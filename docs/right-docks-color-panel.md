# The Color panel

Split from [right-docks.md](right-docks.md): the right column's Color panel, its views and sliders, the hex row, foreground and background picks (the Alt pick in the Foreground Color window included), how a pick is applied, and the drag cost.

## Color panel

`ColorDockPanel` (`src/ui/color_dock_panel.hpp/.cpp`, panel id `colorDock`, GitHub issue 365) holds the foreground/background pair (`ColorWellSwatch` and `ColorWellGlyphButton` from the tool palette, whose Swap Colors and Default Colors actions the glyphs trigger) and one of four views in a `QStackedWidget`: the Hue Cube (a saturation/value field and a hue strip, the default), RGB Sliders, HSB Sliders and CMYK Sliders. The field and strip are the picker window's own widgets (`src/ui/color_field_widgets.hpp`), drawn from an `HsvFieldSource`; the field caches its gradient per hue and size.
- **Views** (GitHub issue 404). The settings gear (`colorPanelSettingsButton`, menu `colorPanelViewMenu`) at the right end of the panel's title row lists the four checkable actions, the only place to switch (Seth, October 25, 2026: no right-click menu). `ColorDockPanel` owns it; `PanelSpec::header_widget` reparents it after the label, 18 px like the collapse toggle, so title rows keep one height. `colorPanel/view` stores the pick (`ColorDockPanel::view_token`: `hueCube`, `rgbSliders`, `hsbSliders`, `cmykSliders`; an unknown value opens the cube; `View` is append-only). Hidden pages are `Ignored`, so the stack's hints are the shown view's. A slider view asks the column for its content height (`PanelSpec::preferred_content_height`, `fitted_height`); a view change while the panel is open and in front refits the section (`PanelColumn::refit_panel_height`), the cube taking its 170 back. No Brightness Cube or Grayscale (Seth, October 25, 2026).
- **Sliders.** Each row is a letter, a `ColorChannelTrack` (the color across that channel with the other two held, a two-tone marker like the hue strip's) and a number box: R, G, B 0..255; H 0..359 degrees, S and B 0..100 percent; C, M, Y, K 0..100 percent ink (`UnitIntSpinBox` with the degree and percent suffixes). A track press or drag, or a number edit (live, including typing), sets the foreground only; Alt does nothing there. The panel keeps the foreground as RGB beside its HSV, so an RGB edit never goes through an 8-bit HSV round trip; a gray keeps the hue shown, and black keeps hue and saturation. Boxes refresh with signals blocked, so a shown color is never a pick. A track drag holds the canvas's answer off like a field drag.
- **CMYK.** The inks are the Color Picker window's numbers: the working CMYK space's `cmyk_from_rgb`, rounded to whole percent, and a set ink gives `rgb_from_cmyk` of the four ([cmyk.md](cmyk.md)). The panel keeps the inks as set (`cmyk_color_` is the color they gave), since RGB cannot hold every ink mix; they are re-derived only when the foreground changes elsewhere or Preferences changes the working space (`working_cmyk_space_changed`). There is no gamut warning in the panel.
- **Hex and RGB row** (issue 577). Under the cube, `colorPanelHexEdit` (`select_all_on_focus`, `parse_panel_color`; bare `RRGGBB` after a `#` label, typed or pasted `#` dropped) and `colorPanelCube{Red,Green,Blue}Spin` show the foreground. A whole value applies at once, short forms and names on Return or focus out; other text restores it. Boxes: Return, arrows, wheel. Each commit is one pick.
- **Picks.** The field shows the foreground; a click or drag sets it. A right press, or Alt (Option on macOS) at a left press, sets the background for the whole drag, as the Pick tool's Alt-click does (GitHub issue 576): `begin_field_pick` reads the press's button and modifiers once and the widget follows only that button (in a color window the right one is accepted only in the Foreground Color window, below). The background takes the color under the pointer (field: the shown hue at the pointer's saturation and value; strip: that hue at full strength); the field keeps showing the foreground.
- **Alt cursor.** Over the field or hue strip, Alt shows the Pick tool's background cursor (`eyedropper_target_cursor(true)`) in place of the widget's own (`BackgroundPickCursor`, src/ui/background_pick_cursor.hpp), following the Alt key itself while hovered (an application key filter, as the field never takes focus) and each mouse move. A press fixes it until its release, as it fixes the target; a right press shows it (`right_picks_background`: the Color panel and the Foreground Color window's field, strip, Wheel and custom colors). The Palette panel's swatches use it for their Alt-click ([palette-mode.md](palette-mode.md)).
- **Foreground Color window.** It has the same Alt pick: `PatchyColorPicker::set_background_pick_handler`, set in `show_color_panel`, routes an Alt press on its palette swatches, custom colors, Square field and hue strip, Wheel, or a Pick Screen Color click to `apply_color_panel_pick(color, true)`; the window keeps showing the foreground, and those surfaces get the background cursor. A right press does the same (GitHub issue 639, `press_picks_background`): a right-click or right-drag on the Square field, hue strip and Wheel, a right-click on custom colors and on read-only palette swatches. An editable palette (Current, or a loaded file) keeps its Set Name / Rename right-click menu, which gains Set as Background Color (`paletteSetBackgroundAction`, first); the grid's cursor follows Alt only, as its right press opens that menu. The Sliders tab has no Alt or right pick (a slider moves one channel). The Background Color window and the request pickers (Layer Style's and the other Choose color buttons) set no handler, so Alt there is a plain click and the right button picks nothing (`ui_color_picker_foreground_window_alt_pick_sets_background`, `ui_color_picker_foreground_window_right_pick_sets_background`, `ui_color_picker_foreground_window_palette_menu_sets_background`, `ui_color_picker_background_window_alt_click_is_a_plain_click`, `ui_color_picker_without_background_pick_ignores_right_click`).
- **Applying.** `MainWindow::apply_color_panel_pick` sets the canvas color (a foreground also recolors an open text session and the shape paint), mirrors it into an open Foreground or Background Color window, and ends in `refresh_color_buttons`, which pushes every change from anywhere back through `set_colors`. During a foreground drag the field ignores the canvas's answer (a palette-snapped color would move the crosshair); a returned color equal to the panel's own keeps the field's hue and saturation.
- **Drag cost** (GitHub issue 464). Every move of a field, strip or track drag is a pick, so per-move work stays small: the field renders its gradient only on a hue or size change (`plane_render_count`); while `picking()` MainWindow defers the pair's settings write (a whole Patchy.ini rewrite) and the gradient preview's restyle to the release (`pick_finished`, `finish_color_panel_drag`; closing the window flushes it). Color windows too (issue 609): `PatchyColorPicker::color_drag_active`, `track_color_window_drag`.
- **32 bits:** a 32-bit document adds the compact `HdrColorControls` row under the view ([high-bit-depth-color.md](high-bit-depth-color.md#color-choice-at-32-bits)).
- **Chips.** A click opens the Foreground or Background Color window, as the tool palette's chips do. With no document the panel is disabled (a document widget).
- `ui_color_panel_*` tests cover the picks, Alt for the whole drag, the sync and the views (`ui_color_panel_view_*`, `ui_color_panel_*sliders*`); `ui_color_panel_field_drag_keeps_per_move_work_small` and `ui_color_picker_window_drag_keeps_per_move_work_small` the drag cost.
