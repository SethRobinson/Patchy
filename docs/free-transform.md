# Free Transform sessions: Skew, Distort, Perspective, steps, and the drag preview

Session-level behavior of Free Transform and Warp beyond the modifier rules in [tools.md](tools.md) ("Free Transform modifiers"), the hit zones in [move-tool.md](move-tool.md), the warp cage in [warp.md](warp.md), and the preview machinery in [interactive-previews.md](interactive-previews.md).

## Steps inside a pending session (GitHub issue 225)

Undo and Redo step through a pending Free Transform or Warp session before it is committed, without touching the document history behind it.

- A step is recorded by `record_transform_session_step(before)` when the session state differs from `before`: a handle or box drag (state captured at press in `transform_session_step_at_press_`, recorded on release), an options-bar numeric edit (`set_transform_controls_state`), a run of arrow-key nudges (a nudge right after a nudge joins that step, so a held arrow is one step), a warp cage handle drag, and a warp style preset. A new step clears the redo stack.
- `TransformSessionStep` holds the mode's whole state: the box (rect, angle, flip signs) in Free Transform, the 4x4 cage plus style and bend in Warp. `restore_transform_session_step` re-renders through the numeric-edit path (full-quality patches over the old-union-new region) or `refresh_warp_preview_cache`.
- `MainWindow::undo` hands a pending session to `undo_transform_session_step`. With no step left, an unchanged session (`transform_session_has_changes` false) is cancelled; a session still holding a stage carried over a Free Transform <-> Warp switch stays open, because the switch starts the step stack over and a cancel would discard that earlier stage. Undo never reaches document history while a session is open. `MainWindow::redo` re-applies session steps and does nothing else while a session is open.
- `update_undo_redo_actions` keeps Undo enabled during a session (there is always a step back or a cancel) and enables Redo from the session's redo stack; the transform-controls callback refreshes both on every change.
- Commit is unchanged: the whole session is one document history entry. Session steps never reach the History panel.

Coverage: `ui_transform_session_undo_steps_back_through_drags` (move, numeric rotate and a nudge run, redo, redo cleared by a new edit, cancel at the start, one history entry on commit, warp cage drag undo and redo).

## Skew, Distort and Perspective (GitHub issue 225)

A Free Transform session is a box (rect, angle, flip signs, as before) plus four corner offsets, `transform_corner_offsets_`, in the ORIGINAL box's frame and units, ordered as the layer's own top left, top right, bottom right, bottom left. Displayed corner k = the box's affine (`transform_affine_delta`, i.e. `free_transform_delta`) applied to original corner k plus offset k, so scaling, rotating or flipping the box carries a distortion with it.

- `transform_session_delta` is the single original-box -> document map every preview, commit and warp hand-off uses: the plain affine while all offsets are zero (so pinned commit bytes and digests cannot move), else `QTransform::quadToQuad` onto the corner quad. `transform_session_source_to_document` maps the source image (which spans the original box) through it; `transform_delta_is_identity` checks the perspective terms too. Never call `free_transform_delta` on the session fields directly.
- Gestures (`transform_drag_kind_for`, decided at press, session only; the passive Move box never distorts): Ctrl+drag a corner distorts it; Ctrl+Alt+Shift+drag a corner applies perspective; Ctrl+drag an edge moves it (both its corners; still a parallelogram), Ctrl+Shift+drag slides it along itself (skew). Alt, read live on every move, mirrors any of these about the center: the diagonally opposite corner, or the opposite side, moves the other way (Ctrl+Alt+drag a side is a symmetric skew). Edit > Transform > Skew / Distort / Perspective (`editTransformMenu`, hotkey ids `edit.transform_skew`, `edit.transform_distort`, `edit.transform_perspective`, no default keys, `QAction::NoRole`) starts or keeps a session in that mode (`begin_free_transform_mode`), where plain corner and edge drags do it: Skew slides edges and moves a corner along one side, Distort moves corners and edges freely, Perspective mirrors the corner across the dragged side (a symmetric trapezoid) and slides edges. Scale, rotate and move drags keep working on the box. Edit > Transform > Scale and Rotate (GitHub issue 299; `edit.transform_scale`, `edit.transform_rotate`) narrow the box instead: `transform_handle_for_session_mode` filters the session hit test (press, cursor, double-click), so in Rotate every corner and side is a rotate grip (the inside still moves) and in Scale the rotate reach outside the box is dead. Ctrl gestures still distort in both. The submenu ends with Warp (`editWarpTransformAction`, `edit.warp_transform`, moved there from the Edit menu itself); Free Transform stays on the Edit menu with Ctrl+T.
- Type buttons (GitHub issue 299): the Move bar carries Skew, Distort, Perspective and Warp (`moveTransformSkewButton`, `moveTransformDistortButton`, `moveTransformPerspectiveButton`, `moveWarpButton`; the menu's entry points), and the session bar leads with the same group as checkable toggles (`transformSkewModeButton`, `transformDistortModeButton`, `transformPerspectiveModeButton`, `transformWarpModeButton`): a click picks the type, a click on the checked one goes back to plain Free Transform. Scale and Rotate stay menu-only: the plain box does both, and with them (and a Free Transform button) the session row was 1252 px and wrapped in the suite's 1180 px window, growing the bar and moving the canvas when a transform started; `ui_free_transform_type_buttons_switch_modes` checks the row keeps one line there. `kTransformTypeButtons` (main_window_actions_options_bar.cpp) is the one table for both bars; `sync_transform_type_buttons` checks the open session's type. Icons are authored SVGs (`transform-skew.svg`, `transform-distort.svg`, `transform-perspective.svg`, `warp.svg`: the dashed original box in icon ink, the result shape in the accent; Warp's is a bowed cage, GitHub issue 350).
- Drags run in the box's frame: the pointer (plus the grab offset to the grabbed corner or edge middle, then snapped) goes through the inverse affine, and the travel lands in the offsets (`update_free_transform_distort`). Handles, hit zones (move-tool.md's EdgesAndCorners rules on the quad: Move core, nearest handle square, segment-distance edge bands, rotate reach), resize cursors (by the handle's on-screen direction) and the rotate stem follow the true quad once it is distorted (`distorted_transform_handle_at`, `draw_distorted_transform_controls`).
- The quad never folds. A drag frame whose quad would be concave, self-crossing, collapsed, or turned inside out (`convex_quad_winding` differs from the drag start's) is skipped and the last good shape stays, so a corner dragged through or past the opposite side stops at the last convex position and follows again when the pointer swings back. A folded quad's homography crosses the horizon and throws pixels far outside the quad and the repaint, which left a smear until commit (Seth's "skew a corner around with vigor"). `set_free_transform_quad` (and so `layer.transform({quad})`) refuses one with "Transform corners must form a convex shape".
- Gesture cursors: over a corner or side, when the held modifiers or the Edit > Transform mode make the drag a skew, distort or perspective, the session cursor is `transform_gesture_cursor` (tool_cursors.cpp: the Move pointer arrow with a parallelogram, irregular quad or trapezoid badge) instead of the resize cursor. `apply_session_transform_cursor` takes the event's modifiers; the canvas key filter re-applies it at the last pointer position when Ctrl, Alt or Shift changes during a session (not mid-drag), and `transform_cursor_modifiers_` keeps the hint for refreshes without an event. A corner on a layer that refuses a non-affine quad keeps the resize cursor.
- Double-click inside the box (off its handles, including a distorted box's Move core) applies the session like Enter (`transform_session_box_contains`, `mouseDoubleClickEvent`); elsewhere it is a second press. Warp keeps its own grid drags.
- Preview: the blit, proxy and multi-snapshot paths draw through `painter.setTransform` with the homography; the composited patches and the commit resample through `resample_transformed_rgba8`, which inverts a projective map per pixel. No supersampling on the far side of a perspective: Photoshop does not area-average there either (the pinball poster's perspective grids match its stored raster within about 2/255 on a 4x reduction this way, and drifted to about 6/255 with a 4 to 8 sample area filter). Masks take the same delta.
- Types: a parallelogram (a skew) is affine, so every layer type takes it. A non-parallelogram quad is refused at the gesture (`begin_transform_distort_drag`, `set_free_transform_quad`; status "Rasterize the layer to distort it") unless `free_transform_accepts_non_affine`: pixel layers and their raster masks take it; shape layers and vector masks take it through `transform_layer_vector_data_projective` (core: every anchor and Bezier handle through the homography, pattern anchors follow, live-shape annotations drop, re-rasterized; curves approximate the exact rational image, as in Photoshop); smart objects take it as a perspective placement (`map_smart_object_placement`, core: the render quad goes through the homography; Photoshop's rule, pinned from both perspective layers of the pinball fixture, stores the corners in nonAffineTransform and their axis-aligned bounding box in Trnf as a TL, TR, BR, BL rectangle; a parallelogram stores the same quad in both; a plain placement under an affine map keeps the old per-corner Trnf map). The content then re-renders onto `smart_object_render_quad` (nonAffineTransform when present). Photoshop-authored perspective placements therefore import editable (no "non_affine" lock) and keep their file raster until edited. Warp refuses a smart object in perspective (Photoshop keeps warped placements' Trnf == nonAffineTransform); type layers never take a non-affine quad (Photoshop grays these commands out for type). The commits pick the vector path by `transform_has_perspective(delta)`, so affine sessions keep `transform_layer_vector_data` byte for byte.
- `free_transform_quad` / `set_free_transform_quad` read and place the corners (document space, the layer's corner order).
- Scripts: `layer.transform({matrix} | {quad}, interpolation?)` (docs/scripting-api-changes.md; with a selection it takes the selected pixels, next section) runs `CanvasWidget::apply_scripted_free_transform` through `ScriptEngineHost::transform_layer`: one session on the layer, corners placed (a matrix maps the session box), committed with the interactive per-type rules, its history entry and the missing-font prompt suppressed (the run's snapshot is the undo step), refusals returned as the thrown error.
- Session steps carry the offsets; `transform_session_has_changes` counts a distortion.
- Options bar W and H (GitHub issue 353): `transform_controls_state` reports the box scale times `transform_distortion_scale_factors`, the mean extent of opposite sides along the box's own axes (offsets included) over the original size, so Distort and Perspective move W and H and the drag readout, while a skew (sides sliding along themselves) keeps them, as in Photoshop. The factors are linear in the box scale: `set_transform_controls_state` divides typed W and H by them, so a typed value round-trips and scales the distorted shape. X, Y and Angle stay the box's (the pivot does not follow the corners).
- The path transform session (Ctrl+T under a path tool) takes the same gestures through the same code: the drag rule, offset update, convex guard, quad handle direction and gesture cursor are `CanvasWidget` statics both sessions call ([vector-commands.md](vector-commands.md#path-free-transform)). Change them in one place.

Coverage: `ui_free_transform_ctrl_drag_corner_distorts`, `ui_free_transform_wild_corner_drag_stays_convex_and_clean` (every frame convex, repainting the previous box, nothing painted outside it), `ui_free_transform_modifier_keys_show_gesture_cursor`, `ui_free_transform_ctrl_alt_drag_is_symmetric` (also the double-click commit on a distorted box), `ui_script_layer_transform_refuses_folded_quad`, `ui_free_transform_perspective_mode_mirrors_the_partner_corner`, `ui_free_transform_skew_mode_slides_an_edge`, `ui_free_transform_distort_refuses_type_layer`, `ui_free_transform_distort_is_a_session_step`, `ui_free_transform_mode_menu_entries`, `ui_free_transform_type_buttons_switch_modes`, `ui_free_transform_scale_and_rotate_modes`, `ui_free_transform_options_bar_follows_distortion`, `ui_free_transform_distort_shape_layer_maps_path`, `ui_free_transform_distort_smart_object_writes_perspective_placement` (also writes `test-artifacts/free_transform_perspective_smart_object.psd`, the Photoshop acceptance file), `ui_pinball_perspective_smart_objects_render_like_photoshop_if_available` (Patchy's first render of the poster's perspective layers against Photoshop's stored raster, and an unedited round trip keeping that raster), core `smart_object_placement_perspective_rule_matches_photoshop` (tests/ui/free_transform_distort_tests.cpp); core `vector_path_projective_transform_maps_control_points`, `vector_layer_projective_transform_drops_live_shape` (tests/core/vector_shape_tests.cpp).

## Transforming the selected pixels (GitHub issue 399)

With a pixel selection on a single pixel layer, Free Transform and the Edit > Transform modes (Scale, Rotate, Skew, Distort, Perspective) take only the selected pixels, as image editors do. Nothing is written to the document until commit.

- Which sessions float (`floating_selection_rect_for_layer`): one non-group target that is a plain pixel layer (not text, shape or smart object), the layer content as the edit target (a mask, channel or Smart Filter mask target keeps the whole-layer session), a selection outside Quick Mask. Text, shape, smart object and adjustment layers, folders and multi-layer selections keep the whole-layer and multi-target sessions above. Warp keeps taking the whole layer: `begin_warp_transform` refuses a floating session ("Warp works on the whole layer. Apply this transform first.") and the session bar's Warp toggle grays out.
- The box is the selection bounds clipped to the layer's opaque rect (the revision-keyed alpha-bounds cache, so the passive Move box can frame it per repaint: with a selection, `move_transform_target_rect` frames what a handle grab would float). An empty box refuses ("The selected area is empty."), as does a layer with locked pixels. The Background's position lock does not refuse: it pins the layer, not its pixels.
- Lift (`lift_selected_pixels`, core/floating_selection.hpp): the floating pixels are the layer's with alpha times the selection coverage (soft edges stay partial); the remainder is the layer with alpha times (1 - coverage). A transparency-locked layer or the Background (`background_layer`) keeps its alpha instead: the hole blends to the background color, like Cut there, and the commit keeps the layer's alpha, format and bounds. The session source is the floating pixels over the box; the selection's whole coverage (the canvas-clipped selection bounds) is kept for the commit.
- Preview: always the composited path. The base renders `floating_selection_preview_document()` (a copy-on-write document copy whose layer holds the remainder; no layer hidden, no preview-scaled base); each patch renders that document with the layer overridden by `composite_floating_pixels` of the remainder and the transformed floating pixels, cropped to the patch plus the layer's effect reach, so a frame costs the patch area, never the layer. The proxy latch blits the floating pixels without mask coverage. The marching ants hide during the session.
- Commit (`commit_free_transform_floating`): one "Free Transform" history entry whose snapshot holds the untouched layer and the starting selection; the layer becomes the remainder with the transformed pixels composited Normal on top (bounds grow to cover them, except under a preserved alpha), and the selection is the stored coverage resampled through `transform_session_delta()` with the session's interpolation. An unchanged box commits nothing. Esc and Undo past the first step change neither layer nor selection; session steps work as above.
- Layer masks stay where they are (only the targeted pixels move, as in Photoshop); a vector mask too.
- Depth: the lift and composite run on straight RGBA rows at the layer's depth (32-bit stays linear), so a whole-pixel move of a hard selection keeps 8 and 16-bit samples exactly.
- Scripts: `layer.transform` runs the same session, so it transforms the selected pixels when the document has a selection.

Coverage: core `floating_selection_*` (tests/core/floating_selection_tests.cpp); UI `ui_free_transform_selection_floats_selected_pixels` (preview hole, commit, one undo step, the selection following, redo), `ui_free_transform_selection_cancel_and_session_steps` (Esc restores bytes and selection, session undo, Warp refusal), `ui_free_transform_without_selection_takes_whole_layer`, `ui_free_transform_selection_keeps_16_bit_samples`, `ui_free_transform_selection_on_background_and_script` (tests/ui/free_transform_selection_tests.cpp), and the "transform selection perspective" row of `ui_deep_documents_match_8_bit_after_every_operation`.

## Free-transform preview: base cache + region patches

The session mirrors the Move tool's structure; never recomposite or convert the whole canvas per mouse-move:

- `transform_base_cache_` (document with the layer hidden) builds once per session via `rebuild_transform_base_cache`, which patches the current render cache over just the layer's effect bounds using hidden-layer overrides (no visibility toggles, no revision churn); the full recomposite is only the stale-cache fallback. `refresh_free_transform_preview_caches` rebuilds it in both preview regimes.
- The composited preview (`transform_preview_needs_compositing`: `layer_needs_composited_transform_preview` layers, plus any layer with visible content above it in composite order) renders `qimage_patches_from_document_region_with_layer_pixels` over `layer_bounds_with_effects(transformed bounds)` only, drawn above the base in paint; simple topmost layers keep the rotated-blit path. Clipping bases blit their clip group ([interactive-previews.md](interactive-previews.md#free-transform-preview)). The blit sits over a base that only hid the layer, so it would cover layers above until commit (GitHub issue 72; `ui_free_transform_keeps_layers_above_visible_mid_drag`). The blit applies the scale-sign flips like the proxy path (mid-drag probe in `ui_point_text_flip_transform_mirrors_and_survives_reedit`). Repaints are bounded to the old-union-new preview rect (`update_transform_preview_region`), and the base has its own display mip chain (`transform_base_display_image_for_zoom`).
- Masked-layer drag cost (GitHub #13 and #15; `patchy_perf_tests maskrotate`, no fixture needed, asserting ceilings): a reveal-all raster mask (`raster_mask_affects_render` false: white pixels, white default, what Add Layer Mask creates) stays on the cheap blit instead of the composited path. For masks that do render, drag frames composite the patch in bands across workers (`qimage_patch_from_document_rect_with_layer_pixels_banded`; a single rect under 4 Mpx otherwise renders on one thread). Banded output is PREVIEW-ONLY (the move-proxy contract), so mouse release re-renders the exact patches once (`transform_preview_patches_banded_`) before the resting preview or commit hold can show them; numeric edits and nudges never band. The resamplers fan out per row block above a small output area (`kResampleParallelMinArea`, `kResampleRowsPerWorker`), so sub-megapixel layers parallelize too.
- Painted-mask frames scan nothing proportional to the stored mask (GitHub #15): `linked_mask_source` crops the mask to its non-default rect once per layer content revision (mask edits and Layer Style live edits bump it; a mouse-move never does) into the session cache `transform_mask_sources_` (`transform_linked_mask_source`, main thread only, cleared with the session), and preview frames resample that crop untrimmed (`transformed_linked_raster_mask(..., trim=false)`: outside its non-default extent the mask holds default_color, which the compositor also reads beyond the bounds, so the render is identical) while commits keep the trimmed, byte-pinned form. The transformed mask still rides a per-frame copy-on-write Document copy (O(layer count), never O(pixels)) because render overrides carry mask bounds only. What remains per frame is the bicubic resample of the layer plus its mask crop and the banded composite, all row-parallel; the proxy gate absorbs the rest (next bullet).
- The proxy area gates scale with the worker count (GitHub #15): `transform_drag_should_use_proxy_preview` multiplies `kTransformProxyAreaThreshold` / `kStyledTransformProxyAreaThreshold` by `min(hardware_worker_threads(), 16) / 16`, since every stage of a composited frame fans out per row and the 4 Mpx figure prices a frame on the 16-worker reference machine. A 4-thread laptop therefore latches at 1 Mpx (250 K styled); the reference machine is unchanged, so step `61_transform_drag_proxy` keeps its counters. `PATCHY_RENDER_THREADS=<n>` (core/worker_budget.hpp, read once) replaces `hardware_concurrency()` for every fan-out so the harness can price that case. The latched proxy of a single masked layer carries its linked raster mask and any vector mask (`source_image_with_mask_coverage`: the source alpha times `build_mask_coverage_plane` over the source's document rect, once per latch), so rotating a painted mask through the proxy shows the masked silhouette; an unlinked mask stays put and keeps the plain approximation. Blend mode and styles still approximate until release.
- `resample_transformed_rgba8` splits destination rows across workers (byte-identical: each output pixel is a pure function of source and inverse transform; commit and preview share the function and pinned transform-commit bytes hold). `PATCHY_RENDER_SINGLE_THREADED=1` forces it sequential; the wasm main-thread fan-out clamp applies.
- Heavy composited-preview drags latch onto a low-res proxy: when the larger of the unclipped transformed-source AABB and the clipped effect-bounds patch rect reaches `kTransformProxyAreaThreshold` (`kStyledTransformProxyAreaThreshold` for styled layers), or a live frame runs over `live_preview_frame_latch_ms`, `refresh_transform_preview_for_drag` stops rendering patches and `draw_free_transform` blits a bounded proxy (`kTransformProxyMaxPixels`, built once per session) with opacity and scale-sign flips applied; blend mode, masks, and styles approximate until release. Sticky per drag, counted once in `RenderCacheDiagnostics::transform_proxy_previews`; release renders the accurate patches through the move-release worker + overlay wait. Only the three `update_free_transform_preview` drag branches can latch; numeric edits, nudges, interpolation changes, and Layer Style live edits always take the full-quality path. At zoom <= 50% the session base comes from the preview-scaled document (`transform_scaled_bases`).
- `pixels_from_image_rgba` (per mouse-move on the resampled image) and `qimage_from_pixel_buffer` (whole layer buffer at session start) are scanline copies, never QColor-per-pixel loops; both are byte-identical by construction, pinned by `ui_edit_conversion_scanline_rewrites_are_byte_identical`.

- Commit hold: a commit whose `document_changed` routes to the full invalidation would flash the layer at its OLD geometry - paint's deferred-async branch keeps the previous frame, which predates the commit (>= 8 Mpx canvas or >= 200 layers; the synchronous region route's wait pump can flash the same way). All three free-transform commits (single, multi, pending-warp) compose the session's final preview once in document space (`compose_transform_commit_hold_image`: base + accurate patches, else the same approximate snapshot/proxy/source blit the live preview drew, at the base's scale level) and arm it just before their `document_changed` call; paint draws the hold instead of the stale cache while the refresh is pending (`render_cache_dirty_ || async_render_cache_in_flight_ || processing_operation_active()`), and a mip-sized hold skips the deep-zoom per-pixel renderer. The arm's fresh flag lets exactly that one notification through `document_changed_impl`; every other document-change entry point (undo/history restores via `set_document_internal` included) clears the hold, and paint drops it once the cache settles. Armed only when the commit changed something. Pinned by `ui_group_transform_commit_deferred_refresh_never_shows_old_geometry`.

Commit-path bytes are untouched by design; the corpus digest tests and the transform-commit suites pin that. Step `61_transform_drag_proxy` drags a handle on the styled CRT screen for real: at standard and above it must report `transform_proxy_previews == 1` (the styled 1 Mpx gate), at quick 0 (live path) - same engages-at-standard convention as the move matrix. Step 34 drives the numeric path and must always report 0.

## Multi-target Free Transform (folders and multi-selections)

Ctrl-T on a selected folder or a multi-layer selection runs a multi-target session (`transform_targets_` in canvas_widget_transform.cpp): the selection normalizes through `root_drop_layer_ids`, folders flatten to transformable leaves the way `movable_layer_ids` does, and exactly one non-group root still takes the single-layer path, whose pixel bytes stay pinned (exception: a lone movable preview-locked smart object takes the multi path; see docs/smart-objects.md). A leaf the transform cannot take along (position lock, vector lock, unsupported Smart Filter stack, smart object without a parsed placement quad) refuses the WHOLE session, unlike the Move tool's skip (scaling the rest around a pinned member would tear the artwork). Preview-locked-but-parsed smart objects (non-affine quads, unsupported warps, external, legacy) transform: their Trnf and stashed nonAffineTransform quads map per corner; a linked one then re-renders from its file, the others keep the resampled pixels. Groups' own masks, adjustment leaves, and empty-pixel leaves with linked masks ride along mask-only.

- Preview: `rebuild_transform_base_cache` hides all target ids; live drags always blit ONE subtree snapshot (`ensure_transform_multi_snapshot`, the `ensure_move_proxy_image` structure: non-target non-adjustment leaves hidden, groups and adjustments keep rendering) mapped through the session delta - no latch heuristics, and the single-path `transform_proxy_previews` counter is never bumped. Release, numeric edits, nudges, interpolation changes, and Layer Style live edits render accurate N-override patches (`refresh_transform_multi_preview_cache` -> `qimage_patches_from_document_region_with_layer_pixel_overrides`). Approximation contract during drags matches the move proxy: blends vs the real backdrop, hidden clipped non-targets, canvas clip, and effect geometry under scale are approximate; commit is always exact. Snapshots above `kTransformProxyMaxPixels` downscale by sqrt; there is no last-resort outline fallback (a huge folder pays the one-time snapshot hitch).
- Commit (`commit_free_transform_multi`): one shared `free_transform_delta` per leaf through the same per-type branches as the single commit (text compose + re-render, `transform_layer_vector_data`, smart-object placement corners + re-render, plain resample), plus linked raster masks via `transformed_linked_raster_mask` (`resample_transformed_gray8`: out-of-source samples read `default_color`, never 0, so reveal-all masks keep their surround; the result is trimmed to its non-default extent, because a rotated mask's AABB is mostly default corners and would double per rotation). The single-layer commit takes its linked mask through the same helper (GitHub #13); unlinked masks stay put and the pending-warp commit still leaves masks alone. Both accurate-patch previews render from a copy-on-write document copy carrying the transformed masks, since render overrides carry mask bounds only. `ui_free_transform_single_layer_rotates_linked_mask` pins preview, commit, trim and undo. One undo entry ("Free Transform"); a required Smart Filter re-render makes the whole set transactional with the same rollback dance. Adjustment layers transform mask-only (their bounds/effect region without a mask stays), matching the Move tool's precedent of not moving adjustment content.
- Warp stays single-layer: `begin_warp_transform` refuses multi sessions before any teardown and the options-bar warp toggle grays out. Suite: tests/ui/group_transform_tests.cpp (pinball fixture end-to-end included).
- The passive Move-tool transform box (`move_transform_controls_rect`) frames folders and multi-layer selections too: a single non-group target keeps the cheap per-layer rect, everything else runs `collect_free_transform_targets` and frames `transform_targets_content_union`, so the box always matches the session a handle grab starts and hides whenever that session would refuse (position/vector locks, unparsed smart objects). The collection walk runs per repaint and per hover move; it is layer-count bounded and the per-leaf alpha rects come from the revision-keyed cache, so no pixel scans. Options-bar X/Y/W/H fields feed from the same rect, so numeric edits on a passive multi selection start the multi session.
