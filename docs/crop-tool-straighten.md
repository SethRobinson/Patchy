# Crop: Straighten

The Crop tool's Straighten button (GitHub issue 702), a child of [crop-tool.md](crop-tool.md). **Read the #702 item of the "Crop interaction" entry in [legal-constraints.md](legal-constraints.md#crop-interaction) before changing any of this: it lists what the gesture must never do.** The claim comparison is in [patent-research-crop.md](patent-research-crop.md#straighten-by-a-drawn-line-github-702).

## Button and gesture

- **Button.** `cropStraightenButton`, a checkable framed push button labeled Straighten with its icon beside the text (`crop-straighten.svg`: a baseline, a tilted line and an arc arrow turning it level, in icon ink; Patchy's own drawing), like the Ruler's Straighten Layer and Straighten Image buttons. It leads the Overlay group of the Crop bar ([options-bar.md](options-bar.md) rule 1: one of the tool's own settings) and shows the bar's checked colors while armed. The first build had an icon-only button, which read as part of the overlay list and was missed (issue 702 follow-up). Its tooltip says to drag along something that should be level or upright; turning it on shows "Drag along something that should be level or upright" in the status bar, cleared when the button goes off. It is a momentary state: nothing is persisted, and there is no command id or default key.
- **The canvas owns the state** (`CanvasWidget::set_crop_straighten_armed`, `crop_straighten_armed`): `refresh_options_bar` mirrors it into the button, so the canvas turns it off. It is off after one line, and every session reset or end turns it off too (`reset_crop_session_state`: Esc's reset, the X, a commit, a tool switch, an edit lock, a document swap).
- **The line.** Armed, a press anywhere (the handles and the inside included) starts a line instead of the usual crop gestures (`begin_crop_straighten_line`); moves only redraw it. Ends are document points read through `view_transform()` (`document_position_f`, unsnapped), so the result is the same at any zoom and view rotation, Move Image Under Crop Box's turned view included. It is drawn like the Ruler's line, in cursor ink with a tick across each end (`draw_crop_straighten_line`, after the Ruler's overlay), exempt from theme roles like every tool overlay. The cursor is the cross while armed, while Ctrl is held over the canvas, and during the line.
- **The turn, once, on release** (`finish_crop_straighten_line`). `crop_straighten_degrees` (ruler_tool.hpp) gives the clockwise box angle that makes the line level or upright, whichever is nearer in the box's own frame: with an unturned box exactly `ruler_straighten_degrees` (the Ruler's Straighten rule), and on a turned box a refinement of its angle, so a box turned a quarter keeps its quarter turn. The box turns about its own center and keeps its rect; it becomes custom (`crop_box_is_default_` false) when the angle is not 0, so Apply, the X and the Info line's angle follow as for the rotate drag. With Move Image Under Crop Box on, `place_crop_box` gives the view the turn, as the mode's rotate drag does: the image turns under the upright box, which keeps its place on screen. Nothing is applied until Enter; the commit is the rotated `crop_document` path, unchanged.
- **Click, Esc, Ctrl.** A click with no real drag (under `QApplication::startDragDistance`) turns nothing and leaves the button on. Esc mid-line drops the line and keeps the box and the button; Esc with the button on and no line turns the button off and keeps the box; the next Esc resets the box as before. Ctrl held at a press draws one line the same way without the button (Ctrl had no meaning in the crop gestures; a held Ctrl shows the cross with a stationary pointer).
- **Overlay and outside.** Show Overlay Only While Dragging counts the line as a gesture, so the guides are the user's choice in this gesture as in every other; the shield and the cropped area are drawn the same during the line as before and after it.

## Limits and differences from Photoshop

The recorded limits, each tested: the turn happens once, on release, never while the line is drawn; it changes neither the zoom nor the box's size; nothing tests whether a canvas edge shows inside the box, so the box does not shrink to fit inside the image (corners that leave the canvas fill by the crop fill rules on commit); no detected horizon, no dial, no automatic leveling. Photoshop's Straighten turns the box and then shrinks it to the largest one that fits inside the turned image; Patchy keeps the box as the user made it.
