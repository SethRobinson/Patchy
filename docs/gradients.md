# Gradients and Photoshop GRD presets

Patchy uses `GradientDefinition` for reusable gradient content and `LayerStyleGradient` for placement. A definition contains the name, Solid or Noise form, Photoshop smoothness (`Intr`, 0-4096), independent color and opacity stops, destination-stop midpoints, and dynamic foreground/background roles. Noise definitions keep the Photoshop seed, roughness, transparency and color-restriction switches, RGB/HSB/Lab model, and four minimum/maximum channel ranges.

Layer-style placement adds Linear, Radial, Angle, Reflected, and Diamond geometry, angle, scale, reverse, dither, interpolation method, Align with Layer, and X/Y percentage offsets. The Stroke effect alone adds Shape Burst (descriptor stringID `shapeburst`), which follows the stroke band's distance field and ignores angle, scale, offsets, and alignment; the calibrated mapping is "Shape Burst render" in [layer-effects-render-stroke.md](layer-effects-render-stroke.md). Preset selection replaces only the definition. It must not overwrite any placement field. Dynamic foreground/background stops stay live in the Gradient tool; layer-style preset selection resolves them from the current Patchy colors before the style is stored in the document.

## Rendering

Imported 8/16-bit CMYK, grayscale and Lab gradients retain their original
descriptors and document mode on eligible layered saves:
[native color preservation](psd-native-color.md). Supported 8-bit CMYK stacks
also regenerate solid/gradient fills from their ink values before composition
and display conversion; see [blend-modes-cmyk.md](blend-modes-cmyk.md). Other non-RGB
previews still interpolate the converted RGB stops.

- Classic applies the stored smoothness as cubic interpolation after destination-stop midpoint remapping.
- Perceptual interpolates in OKLab.
- Linear interpolates in linear-light RGB.
- Gradient Map adjustments pass `ease_every_method`, which applies the Classic smoothness ease to the segment position for Perceptual and Linear too (Photoshop's map behavior; [adjustment-kinds.md](adjustment-kinds.md#gradient-map)). Fills and effects leave it off.
- Dither uses fixed integer hashing and noise uses a clean-room model of Photoshop's noise output (below). Never substitute a standard-library random distribution: output must stay identical across toolchains.
- Noise gradients render Photoshop's colors for a given `RndS`/`Smth`; see "Noise gradients".
- Deep layers: the Gradient tool paints float colors through `EditOptions::deep_primary` (no banding), and gradient fill layers render a deep raster (`deep_gradient_fill_raster`, linear-light interpolation at 32 bits); see [high-bit-depth.md](high-bit-depth.md) and, for the fill layers, [high-bit-depth-compositor.md](high-bit-depth-compositor.md#phase-3-deep-compositor). At 32 bits a tool stop's `intensity_stops` (from the foreground's or background's Intensity, or set in Edit Gradient Stops) scales it above 1.0 ([Color choice at 32 bits](high-bit-depth-color.md#color-choice-at-32-bits)); definitions, GRD and PSD gradients have no Intensity.

`gradient_position` is the shared point-mapped-style geometry function; Shape Burst does not go through it (the stroke renderer derives its position from the band's Euclidean distance field, `stroke_alpha_mask`'s optional plane). Linear and Reflected spans use the layer rectangle projected onto the selected angle, so 90-degree gradients span the layer height rather than its width. For `Align with Layer`, Gradient Overlay and gradient Stroke use the source's nonzero-alpha bounds; PSD channel padding must not compress the visible range. The local alpha bounds are cached by the layer's globally unique pixel revision because finding them is an O(width * height) scan. Transient render pixel overrides bypass that cache. `gradient_color`, `gradient_stop_opacity`, and `gradient_color_dithered` are shared by layer effects and preset thumbnails.

Dynamic Vector Preview passes full canvas/fill/stroke paint bounds separately
from each vector raster clip. Layer-effect paint bounds use its scoped render
context. Tile boundaries never become gradient anchors; ordinary document bakes
keep the original defaults. See [vector-preview.md](vector-preview.md).

## GRD files

`src/psd/grd_io.*` reads and writes Photoshop `8BGR` version 5 files containing a version-16 `GrdL` descriptor. It supports solid `CstS`, noise `ClNs`, dynamic `FrgC`/`BckC` stops, ZString display names, and the trailing `8BIMphry` hierarchy. Imports are limited to 32 MiB, 4096 gradients, and 256 stops per list. A damaged tail may return the valid decoded prefix with warnings; structural damage before the first usable gradient is an error. Stop colors decode through the shared `descriptor_rgb_color` (psd_layer_styles.cpp) with the default converter, so every class Photoshop writes reads correctly: `RGBC`, float RGB (`redFloat`...), `HSBC`, `LbCl`, `CMYC`, and gray `Grsc`, whose `Gry ` is Photoshop's black percentage (100 = black) as in lfx2 gray effect colors (`grd_reads_hsb_lab_cmyk_and_float_stop_colors`). Artboard backgrounds and the Black & White tint use the same decoder.

The application library lives under the settings directory's `gradients/` folder. Each entry is one single-gradient `.grd` plus a JSON sidecar with its fixed storage id, canonical name, and folder path. Default ids and English names in `src/core/gradient_presets.cpp` are persisted and append-only. New defaults need a new `introduced_version` and a `kDefaultGradientsVersion` bump; never rename or reuse an existing id.

The quick picker (`src/ui/gradient_preset_popup.{hpp,cpp}`) and Gradient Manager read the same `GradientLibrary`. The quick picker anchors to the layer-style Preset buttons, the gradient toolbar's Presets button, and the Edit Gradient Stops dialog's Preset button; its Manage Gradients button falls through to the Gradient Manager. The Gradient tool has no definition-backed state: applying a preset there resolves foreground/background stops from the current colors and keeps the preset's own stops (`gradient_tool_stops_from_gradient`, src/core/gradient_fill_drag.cpp; GitHub issue 663 follow-up, where Black to White arrived as 33 sampled stops and crowded the canvas handles). The tool's flat `GradientStop` list merges the color and opacity stop locations (each merged stop takes the color and opacity the preset has there) and keeps each midpoint on its stop (`GradientStop::midpoint`, Photoshop's destination-stop convention, remapped by `gradient_stop_midpoint_remap`); a merged segment that would need two different midpoints is written out in eight straight pieces, Noise is sampled at 65 points, and the tool interpolates straight, so a preset's smoothness is not carried. Every built-in preset keeps its own count and matches its straight ramp within a level (`gradient_tool_stops_keep_a_presets_own_stops`). `tools/gradientStops` writes `midpoint` only when it is not 0.5 (older builds ignore the key); QGradient previews and the options-bar swatch write midpoints out as stops (`gradient_stops_with_explicit_midpoints`), and the Edit Gradient Stops table keeps a row's midpoint on its location cell (no column). The applied result is static. Manager writes are immediate. Restore repairs changed or deleted built-ins without deleting user gradients. Import deduplicates identical name/payload pairs but permits equal names with different definitions. Folder and subtree export includes matching `phry` markers. Previous/Next Preset (, and ., #543) step the Gradient tool through `gradient_preset_popup_order`, the popup's folder-tree order (not `entries()` order), from the preset last applied this session, or the one whose stops equal the current stops, or else from the ends.

## Preset lists

Preset previews (`gradient_thumbnail`) draw alpha over the transparency checkerboard and Foreground/Background stops in the current colors (#581). Library thumbnails are cached per entry: MainWindow's `refresh_color_buttons` hands every color change to `GradientLibrary::set_preview_colors`, which redraws only entries with such stops and nothing when the pair is unchanged; it emits no `changed()`, so lists pick the new thumbnails up when they next open. Shape Appearance draws its rows in the colors it was opened with.

Shape Appearance's fill and stroke Gradient lists open on the preset the layer's gradient came from (`matching_gradient_library_entry`, #578, #579): entries whose definition, Foreground/Background stops resolved in the current colors, draws the same (`gradient_definitions_draw_same`: form, smoothness, stops and alpha stops within PSD/GRD rounding; noise settings exactly; the name ignored). Ties prefer the gradient's own name, then an entry with Foreground/Background stops, so a new Gradient Fill on black and white shows Foreground to Background, not Black to White. No match adds a Custom row (empty item data) at the top that holds the layer's gradient and restores it after a preset is tried. A paint with no gradient yet shows the first preset, which a switch to Gradient seeds from.

A Manage... button beside each of those lists (`shapeFillGradientManageButton`, `shapeStrokeGradientManageButton`; #552 follow-up) opens the Gradient Manager on the paint's gradient, so New from Current saves it as a preset. On close the list is rebuilt from the library and reselected by the same matching (a Custom row it had stays); a Use Gradient pick then applies like a pick in the list.

## Stop editor widget

`GradientStopsEditorWidget` is callback-driven: it never mutates its own stop vectors; hosts copy-and-sort, and must never sort the working vectors in place: an in-flight tag or midpoint drag holds an index into them. Photoshop `Mdpn` belongs to the destination/right stop; the first stop's midpoint is unused.

The layer-style stop-color picker is non-modal, so the editor stays clickable while it is open, and it edits only the stop it opened for (`LayerStyleGradientControls::color_picker_row`). Selecting another stop closes it and keeps its color; a request for that stop reopens the picker there once the open one has unwound; a preset load or stop deletion detaches it first, since stop indices change. GitHub issue 216: the picker kept editing the first stop while the dialog showed the second one selected (`ui_layer_style_gradient_stop_picker_follows_the_selected_stop`).

## PSD layer effects

Gradient Overlay `GrFl` and gradient Stroke `FrFX` share the definition codec but have different required descriptor shapes. Untouched imported `lfx2`/`lmfx` remains byte-preserved. Once edited, writers must retain Photoshop's key order and types documented in [psd-layer-styles.md](psd-layer-styles.md) (GrFl, FrFX), including `Grad`, `Angl`, `Type`, `Rvrs`, `Dthr`, interpolation, `Algn`, `Scl`, and `Ofst`.

Factory reset writes a copied library entry first. In-memory gradients change only
after the save succeeds, so a write failure leaves the current library intact.

## Gradient fill layer geometry

Gradient Fill layers and gradient-filled shapes (`GradientSpanBasis::CenterChord` in `gradient_position`) span the center chord of the aligned bounds ([vector-psd-encodings.md](vector-psd-encodings.md), "GdFl gradient fill geometry"). Photoshop 2026 COM probes (October 2026; 95 fills, 4x4 to 64x64 and non-square canvases, five types, scale and offsets) pinned two further rules for Linear, Reflected and Radial:

- Each pixel samples at its top-left corner (x, y), not its center. On a 4x4 canvas the half pixel is an eighth of the ramp.
- At 100% scale with no offset the ramp runs between the chord ends truncated to whole pixels: Linear between both truncated ends, Reflected and Radial from the truncated center to the truncated far end. The effective angle follows those integer points, so a nominal 30-degree reflected fill runs at 45 degrees on 4x4, 36.87 on 8x8, 32 on 16x16 and 30.7 on 64x64. Every such probe matches within 1/255. Scaled or offset fills keep the continuous ends, which fit those probes better. `gradient_fill_layer_geometry_matches_photoshop_probes` (tests/core/vector_raster_tests.cpp) pins both rules.

A fill layer without a vector mask aligns to the layer's bounds, which in Photoshop are its user mask's visible samples when the mask hides the rest of the canvas (default color 0): psd-tools' 32-bit `gradient-fill.psd` ramps over the mask's rows 6..100, not the 150-pixel canvas (`fill_layer_mask_bounds` in src/core/vector_raster.cpp, pinned by `gradient_fill_layer_aligns_to_its_mask_bounds`; at 32 bits the result matches Photoshop within 2 levels).

Not modeled: Angle and Diamond (they keep center sampling), and offsets on very small canvases (no candidate rule fit a 16x8 probe). With this geometry `photoshop-shape-gradient.psd` sits at mean error 0.29 against Photoshop, and psd-tools' `colormodes/4x4_*` files depend on it.

## Gradient tool Fill Layer mode

The Gradient tool's options bar starts with Mode (`gradientModeCombo`: Pixels, Fill Layer; `tools/gradientMode` token `pixels` or `fillLayer`; GitHub issue 580). In Fill Layer mode a drag on a layer's content never touches pixels (`CanvasWidget::gradient_drag_makes_fill_layer`; mask, channel and Quick Mask targets still paint). On release `MainWindow::handle_gradient_fill_drawn` rewrites only the gradient of the active Gradient Fill layer or single-fill gradient shape (name, masks, path, opacity, blend mode and styles stay; refused while the layer is locked), otherwise it adds a Gradient Fill layer above the active one through `create_fill_layer` (a selection becomes its mask, as with Layer > New Fill Layer, and the bar's Opacity becomes the layer opacity). Each is one undo step; a click without a drag does nothing; the drag preview covers the canvas.

`gradient_fill_from_drag` (src/core/gradient_fill_drag.cpp) inverts the fill-layer geometry above so the layer renders what Pixels mode paints for the same drag: Align with Layer off (the canvas is the bounds, so a mask never moves the ramp), the angle of the drag, center at the drag's midpoint (Linear) or start (other styles; half a pixel on for Angle and Diamond, which sample pixel centers) as X/Y offsets, Scale = drag length over the center chord (twice that for Reflected, Radial and Diamond; Angle ignores it), Classic smoothness 0 with the tool's stops and their midpoints on both lists (straight interpolation like the tool), Reverse as `Rvrs`. They agree within 2 levels, Angle away from its start pixel and seam ray (`gradient_fill_from_drag_renders_the_gradient_tool_drag`); `gradient_fill_from_drag_layers_round_trip_through_psd` pins the PSD fields and leaves `test-artifacts/gradient_fill_from_drag.psd`, which Photoshop 2026 opened clean with its flatten within 2 levels of Patchy's (November 2026; offsets past 200% and Scale 940% included). Limits: Scale clamps to the dialog's 1% to 1000%, so a drag over ten center chords long, or under 1% of one, renders shorter or longer than painted; a 32-bit stop's Intensity is dropped (definitions have none). The PSD round trip and the Photoshop check above covered Linear and Radial drags.

## Gradient Fill handles

With the Gradient tool active (either mode) and a Gradient Fill layer or single-fill gradient shape active, its content targeted and no Quick Mask, the canvas draws the gradient's handles (GitHub issue 663; `src/ui/canvas_widget_gradient_handles.cpp`): the line from the start handle (a light disc) to the end handle (a disc with a dark center), the color stops as squares in their colors on one side of the line, the opacity stops as gray circles (black is opaque) on the other, and each segment's midpoint as a diamond beside its stops (hidden when the stops are under 16 screen pixels apart). Noise gradients show the line and ends only. Colors are the `canvas_gradient_handle_ink`, `_fill` and `_active` theme roles; the overlay maps document points through `view_transform()`, so zoom, pan and view rotation hold.

- Geometry: `gradient_fill_line` (src/core/gradient_fill_drag.cpp) inverts the stored placement over the bounds the bake measures (`gradient_fill_alignment_bounds`: the canvas, or with Align with Layer a pathless fill's visible mask bounds, else the path's coverage bounds). Linear runs through the center; the other styles start at it (Angle and Diamond half a pixel back); Angle keeps the length its Scale records. `place_gradient_fill_line` is the forward step `gradient_fill_from_drag` uses. Stop location 0 is at the start handle, or at the end when Reverse is on. Handle drags keep sub-pixel positions. The bounds are cached by layer id, render and content revision, and canvas size; nothing else touches pixels per repaint.
- Gestures: an end changes angle, scale and offsets (Shift: 15-degree steps about the other end); the line moves the gradient (offsets only); a stop slides along the line (locations clamp to 0..100%, both lists stay sorted and a midpoint travels with its destination stop); a stop dragged more than 48 screen pixels off the line is deleted on release (struck through while held; never below two stops of its kind); a midpoint slides between its stops (5% to 95%, the Edit Gradient Stops dialog's range); a click on the line adds a color stop with the color shown there; a double-click on a color stop opens the color picker (live preview), on an opacity stop the Fill Layer Settings dialog. Ctrl, Alt and Meta presses keep their usual meaning, and a press away from every part draws a new gradient as before.
- History: each gesture previews live through `MainWindow::handle_gradient_fill_handle_edit` (the layer re-renders, no history) and lands as one undo step: Move Gradient Start Point, Move Gradient End Point, Move Gradient, Move/Delete Color Stop, Move/Delete Opacity Stop, Move Gradient Midpoint, Add Color Stop, Change Color Stop. A gesture that ends where it began, Esc, a tool switch or a lost release restores the layer with no step; a document swap mid-drag drops it. A locked layer refuses with a status message. Edits write the same fill descriptor the Gradient Fill dialog does.
- Hints: hovering a part names its gesture in the status bar; its tooltip names the part and its location. The line takes presses within 7 screen pixels (the drawn band is 3); a press and release within the drag distance on it adds the stop, a press that moves on moves the gradient.
- Performance (GitHub issue 663 follow-up): the overlay follows every move, but the layer previews at most every 33 ms (the first change at once). A preview of a pathless 8-bit fill over 1 Mpx bakes a draft (`update_gradient_fill_draft_raster`: exact ramp positions on a 4-pixel grid, interpolated, exact per pixel in cells across an Angle seam or a sharp turn, a 4096-entry color table, no dither) and invalidates with `document_changed_async_preview`, which never cancels the composite in flight; shapes with paths and 16/32-bit documents bake exactly. The release bakes exactly, once. `ui_gradient_fill_handles_drag_timing` prints each gesture's per-move cost (1600x1200 by default; `PATCHY_GRADIENT_HANDLE_TIMING=1` times 4000x3000 and 8000x8000), and `PATCHY_GRADIENT_HANDLE_TRACE=1` prints each preview's bake time. On metroid (i9-11900KF): 4000x3000 went from 110 to 160 ms per move (an exact 92 ms bake plus a cancelled composite) to 22 to 27 ms (an 11 ms draft); 8000x8000 from 580 to 875 ms to about 160 ms, mostly allocating and writing the 256 MB raster.
- Tests: `gradient_fill_line_inverts_the_drag_placement`, `gradient_fill_alignment_bounds_follow_the_bake`, `gradient_fill_stop_edits_keep_stops_sorted` (core); `ui_gradient_fill_handles_edit_a_linear_fill` (its add-a-stop click goes through the window like a real one), `ui_gradient_fill_handles_follow_a_radial_fill_in_a_rotated_view`, `ui_gradient_fill_handles_show_a_presets_own_stops` and `ui_gradient_fill_handles_drag_timing`.

## Gradient tool styles

The options bar's Style list (`gradientMethodCombo`, label "Style", GitHub issue 610) offers the Gradient Fill dialog's five styles in its order: Linear, Radial, Angle, Reflected, Diamond. `GradientMethod` (src/core/pixel_tools.hpp) is append-only and saved by value as `tools/gradientMethod` (0 Linear and 1 Radial keep their meaning; unknown values load as Linear). `gradient_tool_position` is the one ramp function for `draw_gradient`, the mask and channel gradient (`CanvasWidget::draw_mask_gradient`) and the drag preview: Linear projects onto the drag over its length; Reflected is the absolute projection; Radial the distance over the drag length; Diamond the L1 distance in the drag's frame (a square with a corner at the drag end); Angle sweeps one ramp per turn starting on the drag direction, clockwise on screen (the start pixel is position 0.25, like Photoshop's angle fills). These are `gradient_position`'s fill-layer shapes, so Fill Layer mode matches. Qt has no Angle, Reflected or Diamond gradient, so the preview samples `gradient_tool_position` on a grid of at most 160,000 cells over the visible fill rect and draws it smooth-scaled (`sampled_gradient_preview_brush`, canvas_widget_draw_tools.cpp). Both gradient combos use `use_scrolling_list_popup`, so their lists open below the box rather than as a menu with the current row over it. Tests: `tool_gradient_styles_render_angle_reflected_and_diamond`, `ui_gradient_style_combo_lists_five_styles`, and the restore check in `ui_startup_restores_stored_brush_and_gradient_settings`.

## Noise gradients

A clean-room, black-box model (October 2026): fitted only to the rendered output of 16-bit 4096x2 noise Gradient Fills that a licensed Photoshop 2026 drew over COM, with no Photoshop code inspected, decompiled, or disassembled (see [legal-licensing.md](legal-licensing.md#format-copyright-trademarks-and-assets)). The generator family and its constants were identified by matching that output against public algorithms. `build_noise_gradient_table` (src/core/blend_math.cpp) implements it and `noise_gradient_matches_photoshop_samples` pins Photoshop's bytes. Patchy matches within half an 8-bit level up to 50% roughness and about one level at 100%.

- Random stream: Park-Miller minimal standard (`state = state * 16807 mod 2^31-1`, `u = state / (2^31-1)`), seeded with `RndS` (seed 0 stays 0). Seed `k*s` gives draws `k * u(s) mod 1`; that relation is how the stream was identified.
- Each channel (R, G, B, transparency) is `0.5 + sum_k p^k * (0.5 - a_k) * sin(2*pi*(0.12 * 1.18^k * t + b_k))` for k = 0..50, lowest frequency first, `t` in [0, 1). Per component the stream yields four amplitude draws `a` (channel order) then four phase draws `b`.
- Roughness: `p = (0.2 + 0.7 * Smth/4096)^0.15` (fit error 7e-6 over 65 levels).
- Restrict Colors (`VctC`): when the offset from mid gray, taken in the color model's own channels (H, S, B for HSB) plus the transparency channel when Add Transparency is on, is longer than 0.5, scale it to 0.5. Then each channel clamps to [0, 1] (hue clamps, it does not wrap) and maps into `Mnm`/`Mxm` (clamping happens before the range mapping). Without transparency the RGB-only rule is off by up to 82 levels on transparent noise; the 4D rule matches within 0.25.
- Photoshop point-samples a 4096-entry table (a 256-pixel fill reads every 16th entry); Patchy caches the table per setting and samples `floor(t * 4096)`.
- HSB converts with the standard hexcone formula (within 2 levels). Lab (`lab_noise_to_rgb`, blend_math.cpp; issue 263): L = 100v, a and b = 255v - 128, CIELAB with a D65 white straight to sRGB, XYZ and linear RGB clipped. Mean error against full-range Lab probes (seed 43487260, `local-test-fixtures/noise-gradient-probes/lab263-*.png`, jobs-263*.json): 10 to 13 levels. Measured residuals, unexplained (October 21, 2026): achromatic probes (a = b = 0) follow L = 100v only for v >= 0.392 and collapse below it (v = 0.3 reads L 20.8, 0.26 reads 12.7, 0.2 reads 4.3, 0.1 reads 0.8; identical at 8 and 16 bits and across seeds), yet the same toe applied to chromatic probes makes them worse; on unclipped chromatic samples the effective a is about 0.7 times the nominal, b about 0.95 on the blue side and up to 1.3 on the yellow side. Photoshop's own Lab to sRGB document conversion is standard under every rendering intent (checked over COM for issue 263), so the mapping lives in the gradient generator.
- Residual: a small extra term at 0.12 * 1.18^m cycles per pixel with harmonics (under 0.001) is not modeled.
- Grayscale documents (psd-tools' `noise-gradient-grayscale.psd`, Photoshop 2026): Photoshop stores the Lab model's L, or the luma `0.299 R + 0.587 G + 0.114 B` of the RGB or HSB color, as the gray value and shows it through the document's gray profile. The PSD reader sets `GradientNoiseSettings::gray_output` (the document's 256 gray-to-sRGB colors; render-only, it never makes gradients compare different) on every noise gradient it parses there, and `gradient_color` returns that table's entry. The three single-color fills bake as 127, 154 and 153 exactly; 30/59/11 weights fit them equally. `psd_tools_grayscale_noise_gradients_render_gray_if_available` pins the shown 148, 173 and 172. Ranges stay whole percents, so the file's 8.33% hue reads 8% (one level).

## Noise gradients in PSD fill layers

Noise `ClrS` enum values are `RGBC`, `HSBl`, and `LbCl`. The color-object
classes `HSBC` and `LABC` are not the HSB/Lab enum values: Photoshop silently
interprets them as RGB. PSD fills, layer effects, and GRD exports all write
the native enum values; readers still accept older Patchy spellings.

A Gradient Fill layer or shape stroke may carry a noise (`ClNs`) gradient. Photoshop's PSDs store the channel ranges `Mnm `/`Mxm ` as doubles (79.9988 for 80), where GRD files use longs; the reader accepts both. `gradient_object` (src/psd/psd_vector.cpp) writes the noise form with Photoshop's keys and order (`Nm`, `GrdF`, `ShTr`, `VctC`, `ClrS`, `RndS`, `Smth`, `Mnm`, `Mxm`) and no stop lists. A noise gradient is never "healed" for missing transparency stops: writing it as a stop gradient left an empty `Clrs` list and Photoshop dropped the fill layer on open (psd-tools' `gradients/noise-gradient-*.psd`, found by Testy in October 2026; Photoshop 2026 opens the regenerated file clean with all three layers still Gradient Fill).
