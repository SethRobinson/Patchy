# Image tracing to shapes

`Layer > New > Trace Image to Shapes...` (command id `layer.trace_image_to_shapes`, default Ctrl+Alt+Shift+T, object name `layerTraceImageAction`; the same action sits in the Layers panel context menu after Rasterize) turns the active pixel layer into a group of editable shape layers, one solid fill per color, the way Illustrator's Image Trace does. The source layer is hidden, not deleted. Scripts call `layer.traceToShapes(options)` (docs/scripting.md). Legal boundaries live in [legal-constraints.md](legal-constraints.md) ("Vector tracing"); the claim-level record is in [patent-research.md](patent-research.md). Do not widen the feature past those boundaries without a new review.

## Code map

- `src/core/image_trace.{hpp,cpp}`: `ImageTraceOptions`, `trace_image` (the pipeline), `render_image_trace` (solid-fill preview raster), `build_image_trace_group` (the group of shape layers), and the option mappings `image_trace_fit_tolerance` / `image_trace_corner_angle`. Qt-free, deterministic (including its parallel stages).
- `src/core/palette.{hpp,cpp}`: besides the shared median cut and `PaletteLut` (whose behavior is pinned by the GIF and palette-mode byte canaries and never changes for existing callers), the additive `weighted_color_distance` and `refine_palette_weighted` (integer Lloyd) used only by tracing.
- `src/core/mask_outline.{hpp,cpp}`: `trace_mask_outlines`, the pixel-edge boundary walker promoted from the selection outline code (the UI wrapper in `selection_outline.cpp` converts its loops to Qt types without changing a coordinate; the outline stress tests guard that).
- `src/core/path_fit.{hpp,cpp}`: `PathFitOptions` and the options overload of `fit_closed_loop` (corner angle, significant-vertex tangents, snap curves to lines). The two-argument overload keeps Make Work Path's historical output.
- `src/ui/image_trace_dialog.{hpp,cpp}`: the modal dialog (`imageTraceDialog`) with its zoomable preview (`imageTracePreview`), the preset table (`image_trace_presets`), and the latest-wins background tracer.
- `src/ui/main_window_vector.cpp`: `MainWindow::trace_image_to_shapes` (guards, settings, dialog) and `insert_image_trace_layers` (undo entry, group insert, source hidden, the frontmost traced shape activated so the pen and path tools edit the trace at once; the script still returns the group). `src/ui/script_api.cpp`: `ScriptLayerObject::traceToShapes`.
- Tests: `tests/core/image_trace_tests.cpp` (pipeline, fitter options, mask outline), `tests/ui/image_trace_ui_tests.cpp` (dialog flow with undo, scripting).

## Pipeline

Stages after the format normalize run parallel where noted: workers only fill disjoint position-indexed slots, so output is bit-identical to a sequential run (`max_workers` on `trace_image`, 1 forces sequential; the cancel predicate must be thread-safe).

1. **Smoothing (optional).** `smoothing` > 0 blurs an RGBA working copy before quantization: alpha-weighted integer box blur, twice per axis, edge-clamped, with the ORIGINAL alpha carried through so which pixels are traced never changes and background color cannot bleed across the transparency edge. 0 is a byte-for-byte no-op (the untouched flow).
2. **Label map.** 16-bit and float buffers convert to 8-bit first (value/257 rounded; floats clamp to 0..1). With a selection active the command traces `pixels_limited_to_selection` (main_window_shared), an RGBA copy whose alpha is 0 wherever selection coverage is below 128, so the selection is a per-pixel input predicate exactly like the alpha cut, never a per-region parameter (the legal boundary). By default the quantization palette still comes from the WHOLE layer: `trace_image` takes an optional `palette_source` buffer feeding the Color counts and the Grayscale histogram, run through the same 8-bit normalization and smoothing (blurred independently, because the masked copy's alpha-weighted blur diverges near the selection edge), so a selection trace picks bit-identical colors to a whole-layer trace while the masked buffer still decides which pixels are traced. A selection-scoped palette re-optimizes the entries onto anti-aliasing ramps and grain and shatters flat areas into speckle (the August 2026 27k-anchor bug). The dialog's "Pick colors from the whole layer" checkbox (`imageTracePaletteFromLayerCheck`, settings key `imageTrace/paletteFromLayer`, default on; deliberately outside `ImageTraceOptions` and presets) and the script option `paletteFromLayer: false` switch back to selection-scoped colors; either scope keeps every parameter global (the legal boundary). Black and White ignores the palette source (fixed palette). Pixels with alpha below 128 are untraced. Black and White thresholds integer luminance (299/587/114). Grayscale solves exact optimal 1D quantization over the 256-bin histogram (DP over cluster boundaries, integer, smallest-split tie-break; populations halve until sums fit 64 bits). Color seeds with the shared deterministic median cut (`core/palette`), then refines with fixed-iteration integer Lloyd k-means under `weighted_color_distance` (2/4/3-weighted squared RGB; 6-bit cell fold, lowest-index tie-break, empty clusters keep their center); refinement is skipped when the unique colors already fit the palette so exact palettes stay exact. Assignment is exact per unique color (parallel; lowest palette index wins ties), never the old 5-5-5 lookup table whose +-4 per-channel bucket error misassigned close palette entries. Never dithered. Ignore White turns every palette entry with all channels at or above 240 into untraced.
3. **Boundary majority (with smoothing).** When `smoothing` > 0, one 3x3 label majority pass (double-buffered; untraced pixels neither vote nor change; ties keep the center when it is among the best, else lowest palette color key) de-rags the interfaces between similar colors.
4. **Noise.** 4-connected components smaller than `noise` pixels merge into a neighbor, repeated until stable (at most 8 passes, cancellable per pass). A component whose border is at least half untraced merges into untraced (dust inside transparency disappears); otherwise it takes the labeled neighbor with the closest palette color (`weighted_color_distance`) among those with at least a quarter of the longest labeled border, ties to the longer border then the lower label.
5. **Contours.** Each label is traced at once within its bounds (parallel per label); loops attribute to their component through the canonical start vertex (outer loop: the top-left corner of the topmost-leftmost pixel; hole: the top-left corner of the topmost-leftmost inside pixel, whose upper neighbor is the owner). Outer loops read clockwise (positive signed area), holes counterclockwise.
6. **Method.** Abutting: one layer per label, outer loops `Add`, holes `Subtract`, one shape group per subpath in trace order (the Make Work Path convention, which puts every hole after its outer loop and every island after its hole). Overlapping: nesting depths come from the per-hole 8-connected flood (a component's parent owns the smallest hole containing it), then every (depth, label) layer is re-traced from its own mask grown `clamp(ceil(tolerance) + 1, 2, 4)` px into STRICTLY LATER painted pixels: each shape tucks under the shapes above it, which kills the hairline seams where independently fitted edges meet and where antialiased abutting coverage lets the backdrop bleed through. The dilation never enters earlier-painted or untraced pixels, so visible geometry and the silhouette are unchanged. A hole whose interior is later-painted is dropped (the children stack on top); holes over earlier-painted or untraced content stay `Subtract`, so a ring around transparency survives.
7. **Staircase settling.** Before fitting, every vertex between two stair edges (edges no longer than `clamp(3 * tolerance, 1.5, 6)` px whose ends turn in opposite directions) moves to the average of their midpoints. Real corners (longer edges) and the caps of 1 px wide features (same turn at both ends) stay in place. Without this, Douglas-Peucker takes stair corners as chord endpoints and keeps 1 px steps as anchors near 1 px tolerance.
8. **Fit.** `fit_closed_loop` with `PathFitOptions{tolerance, corner angle, smooth_corner_tangents = true, snap_curves_to_lines, refine_iterations = 8}` (parallel per loop; runs stay independent per-run Schneider fits, the legal boundary). Fitted subpaths with fewer than three anchors and collapsed handles are dropped.
9. **Anchor budget (optional).** `max_anchors` > 0 caches each loop's settled polyline and, while the total exceeds the budget, escalates ONE global tolerance (x1.5 per pass, capped at 16 px, at most 12 passes) and refits every loop from its cached polyline, keeping a refit only when it is smaller (Simplify Path's never-worse rule; refits always start from the pixel contour, never from a flattening of an earlier fit). Loops at four anchors or fewer are left alone. A budget the trace already meets changes nothing.
10. **Order.** Layers back to front: ascending depth, then descending pixel area, then palette color key. Layer names are `#RRGGBB`; the group is "Traced <source name>".

## Options

| Option | Range, default | Meaning |
| --- | --- | --- |
| Mode | Color | Color, Grayscale, Black and White. |
| Colors / Grays | 2..256, 16 | Palette size for Color / Grayscale. |
| Threshold | 1..255, 128 | Black and White: luminance below it is black. |
| Paths | 0..100, 50 | Fit tolerance, log scale: 4 px at 0, 1 px at 50, 0.25 px at 100 (`image_trace_fit_tolerance`). |
| Corners | 0..100, 75 | Corner angle threshold: 120 degrees at 0, 30 at 100 (`image_trace_corner_angle`). |
| Noise | 1..100 px, 25 | Minimum region area. |
| Smoothing | 0..10 px, 0 | Denoise blur before quantization plus the boundary majority pass; 0 is a byte-for-byte no-op. |
| Max anchors | 0..20000, 0 (Off) | Anchor budget: the fit tolerance escalates until the result fits; 0 traces without a budget. |
| Method | Abutting | Abutting (cutouts) or Overlapping (stacked, seam-free through underlap). |
| Snap curves to lines | off | Collapse cubics whose handles stay within tolerance of the chord. |
| Ignore white | off | White regions become untraced. |

Presets (`image_trace_presets`) are fixed option sets (ten built-ins; "Photo (Maximum)" is Color 256, Paths 80, Corners 50, Noise 4, Smoothing 2, Overlapping); the combo shows "Custom" whenever the controls match none of them. Save... / Delete beside the combo manage user presets (`ImageTraceUserPreset`; settings key `imageTrace/userPresets`, a compact JSON array using the `imageTrace/*` spellings; names are the identity, case-insensitive, built-in names are refused, malformed elements are skipped one by one). They list after a separator; a built-in wins a tie when the controls match both. The last-used options persist under the `imageTrace/*` settings keys (persisted identifiers; never rename).

## Fitter hardening (August 2026)

`generate_bezier` rejects least-squares handle lengths above the run's polyline length and handles that cross when projected onto the chord (paper.js's order check), and `max_fit_error` also evaluates the curve halfway between neighboring samples against the polyline midpoint. A run with one or two interior samples otherwise fits handles hundreds of pixels long that spike between samples (the first photo trace drew image-spanning hairlines). These apply to every `fit_closed_loop` caller; the path-fit tests and `ui_make_work_path_from_selection_traces_selection` cover the unchanged cases. `PathFitOptions::refine_iterations` (default 4, the historical literal for Make Work Path and Simplify Path) sets the Newton reparametrization attempts before a near-miss run splits; tracing uses 8 so near-circular runs converge instead of splitting.

## Dialog and preview

Controls on the left (each numeric option is a slider plus spin box through `add_dialog_slider_spin_row`; the spin boxes keep their object names), the rendered trace (`render_image_trace` over a checkerboard) on the right with zoom buttons, wheel zoom, drag pan, and double-click fit/100%. While a trace runs the `ActivitySpinner` (`imageTraceBusySpinner`, theme role `dialog_busy_spinner`) shows beside the info label and the preview takes the busy cursor; `imageTraceSizeWarningLabel` appears when `image_trace_result_is_large` (2,000 layers or 20,000 anchors) and `imageTraceSelectionNoteLabel` when the command was limited to a selection. Preview downsampling was evaluated and rejected: OK reuses the preview trace, and Noise/Paths are pixel units. Every control change re-traces the layer's full pixels on a tracked background worker after a 150 ms debounce, latest-wins: stale work aborts through the tracer's cancellation poll. OK waits for the trace of the current settings and hands that result to the caller, so nothing traces twice. The info label reads "N shape layers, M anchors". The Max anchors spin shows "Off" at 0 (`setSpecialValueText`); the size warning names Paths, Noise, and Max anchors as the remedies. The preview shows only the traced result and never the source: no source overlays or outline renditions of the source, no source/trace rendition switches, no per-region controls, no re-trace after the dialog closes (US 7636097 claims the combination of overlapping source/trace display, rendition selectors, and automatic re-tracing). "Show anchors" (`imageTraceShowAnchorsCheck`, settings key `imageTrace/showAnchors`, a view preference outside `ImageTraceOptions` and presets) overlays the traced result's own anchor points as marks in the canvas path overlay's fixed accent-on-dark pair; it displays nothing derived from the source and toggling only repaints (never re-traces), so it sits outside that claim. Note for terminology: "anchor" is the app-wide user-facing term for the fitted Bezier control points; "vertex" names the intermediate pixel-edge polyline points that the fit consumes and discards, and appears in no UI string. Photos trace into tens of thousands of subpaths and exported SVGs of such traces are tens of megabytes; contouring and fitting run parallel on native builds, while single-threaded wasm runs the whole trace inline on the UI thread, so high color counts block longer there.

## Scripting

`layer.traceToShapes({mode, colors, threshold, paths, corners, noise, smoothing, maxAnchors, method, snapCurvesToLines, ignoreWhite, paletteFromLayer})` traces synchronously, inserts the group above the layer, hides the layer, and returns the group (null when nothing traced). With a document selection it traces only the selected area, like the dialog (no option: scripts control the selection through the selection API); the palette comes from the whole layer by default, and `paletteFromLayer: false` restores selection-scoped colors. Unknown option names throw. Text, shape, and Smart Object layers trace their cached pixels without a rasterize prompt (the menu command rasterizes first through the shared prompt).

## Not implemented (later phases)

Centerline (stroke) tracing, automatic palette sizing ("Full Tone"), and tracing into a work path. The centerline patent (US 7876932) expired in 2025, so that phase needs only a skeletonization design, not a new clearance.
