# Right panel column

On a first launch and after Reset Panels the right column holds, top to bottom, Color and Palette (one tab group, expanded, Color in front), Layers, Channels and Paths (one tab group, expanded), then Properties, Info and History (collapsed; Seth, October 2026). `create_docks` adds the Layers group first, so it is the fill section, then the other panels, merges Palette into Color and sets the order. It is Patchy's own `PanelColumn` (`src/ui/panel_column.hpp/.cpp`): a vertical `QSplitter` of sections, each a title row over its panel, never a `QDockWidget`; sections and tabs move within it ([right-docks-reordering.md](right-docks-reordering.md)). The central widget is the `workspaceSplitter` (`QSplitter`): the document tabs (`documentTabs`, stretch 1) and the column (stretch 0). Tests reach the tabs with `findChild<QTabWidget*>("documentTabs")`, never through `centralWidget()`. `create_docks` (`src/ui/main_window_docks.cpp`) builds each panel and hands it over as a `PanelSpec`.

Panel ids are the old dock object names (`layersDock`, `channelsDock`, `pathsDock`, `historyDock`, `propertiesDock`, `infoDock`, `paletteDock`), plus `colorDock` for the Color panel added later. They name the panel's widget, and the saved layout stores them, so they never change. A title row is `<prefix>DockTitle` with `<prefix>DockTitleLabel` and `<prefix>DockCollapseButton` (`dockCollapseButton` property); Window > Show Panel Titles hides the rows of expanded sections ([Hidden title rows](#hidden-title-rows)). The theme, the MCP allowlist and the tests rely on these names. Every tab group's section is `panelTabGroup`, its bar `panelTabGroupTabBar` (groups formed later take the same names; the theme styles the bar by that name) (`drawBase(false)`, so no Fusion base line: GitHub issue 123, `ui_dock_tab_bars_draw_no_native_base`). `MainWindowTestAccess::panel_column`/`panel_section`/`show_panel` reach it from tests.

Related documents:
- [right-docks-color-panel.md](right-docks-color-panel.md): the Color panel (`ColorDockPanel`), its views and sliders, the hex row, foreground and background picks, and the drag cost.
- [right-docks-reordering.md](right-docks-reordering.md): dragging sections and tabs within the column, drop targets, and how tab groups form and dissolve.

## Width

- **The edge.** The column's draggable edge is the workspace splitter's handle, named `rightDockResizeHandle` (theme and MCP selectors). `apply_right_column_width` sets it exactly with `setSizes`. The column's stretch factor is 0, so it keeps its width as the window resizes. Do not reintroduce a fixed-width widget or an overlay handle.
- **Widths.** `update_right_dock_minimum_width` measures two. The content-fit width `right_dock_minimum_width_` takes each wrapping Layers row at its `comfortable_width()` (the footer buttons on one row, or the blend row at its wrapped width; see [layer-panel.md](layer-panel.md)) plus the column chrome, never below `kRightDockMinimumWidth`. The compact width `right_dock_compact_width_` is the panel layout's minimum, every row fully wrapped, plus the chrome (GitHub issue 199): between the two the rows reflow, and only below the compact width does the panel scroll sideways (`ui_layer_panel_compact_width_keeps_controls_whole`). Channels, Paths and the other panels are not measured. The chrome is the column minus the Layers panel's scroll viewport, measured once laid out (on the column's first show, through `handle_right_dock_resize_event`, and lazily). The panel can be wider than the viewport, so never measure against the panel. Never add a competing hardcoded width.
- **Opening width.** Until the user or a script picks a width (`right_dock_width_follows_minimum_`), the column sits at the content-fit width and follows it when it changes (language switch, restyle), so it opens with no dead strip beside the Layers footer in every language (GitHub issue 96, `ui_right_dock_opens_at_content_width_without_gap`).
- **Picked widths.** `patchy.ui.setSidePanelWidth` goes through `set_right_dock_stack_width`, which clamps to `kRightDockFloorWidth` .. window width - 260 and keeps the result, narrower than the content included; it never snaps. A drag of the edge lands in `handle_right_column_moved` (`splitterMoved`). Within `kRightDockSnapDistance` of the content-fit width it snaps onto it and follows that width again. Otherwise the dragged width is kept as picked (`ui_right_dock_drag_snaps_to_content_width`). It stays usable while a non-modal preview dialog is open; modal windows block it, as Qt blocks all main-window input (`ui_right_dock_drag_works_during_preview_dialog`).
- **Overflow.** Every panel but Properties (already a `QScrollArea`) sits in a `RightDockOverflowArea` (`rightDockOverflowScroll`). Below a panel's minimum width the panel keeps that width and scrolls sideways, with the bar at the bottom. It hands the panel the viewport's full height, never less than the panel's minimum, and its minimum height grows by the bar while it shows. Below that minimum (a lowered floor) it scrolls vertically, never clipping (#213 follow-up, `ui_right_dock_short_narrow_column_scrolls_instead_of_clipping`). `place_content` switches both bars (as-needed ones lag a pass); the vertical one waits a pass, so drags never flicker it. It places the panel by hand because `widgetResizable` would size the height-for-width Layers panel to its preferred height and clip the footer. Title labels use an `Ignored` width policy, so a long title clips instead of holding the column wide (`ui_right_dock_drags_below_content_minimum_with_scroll`).
- Tests read the content-fit width with `MainWindowTestAccess::right_dock_content_minimum_width` and the narrowest no-scroll width with `right_dock_compact_width`. Keep staged `setSidePanelWidth` values in tests above it unless the test is about scrolling. A splitter handle moves with its drag, so a test drags it with one move, not several in its own coordinates.

## Narrow Layers panel

Three Layers rows wrap instead of clipping (`WrappingControlRowLayout`, `WrappingButtonRowLayout` in main_window_docks.cpp; GitHub issues 96 and 199):
- **Blend row.** The blend mode box narrows first, down to the room the default mode's name needs (GitHub issue 693, [layer-panel.md](layer-panel-blend-row.md#blend-and-opacity-row)). Then Opacity and Fill drop their "Opacity: " and "Fill: " labels, both together (the 693 follow-up, `ui_layer_blend_row_drops_labels_before_wrapping`). They go under the combo, labels shown, only when even that does not fit one line, then Fill under Opacity (`ui_layer_blend_row_wraps_in_narrow_panel`); no stock language gets there before the panel's compact width. Opacity and Fill widen to end each line at the panel's right edge (issue 680 follow-up 2). With Customize Layers Panel's Show Fill field off the Fill field is hidden and no part of the row, so the combo and Opacity share a line down to a narrower column ([layer-panel-row-options.md](layer-panel-row-options.md)).
- **Lock row.** The name filter leaves the Lock buttons for a line of its own when its share drops under `kLayerNameFilterMinimumWidth`.
- **Footer.** The buttons narrow from their maximum to their minimum width at 3 px spacing (the theme's `layerActionButton` rule sets both, scaled per footer icon size; its widths exclude the border), then wrap one button at a time: each row holds as many minimum-width buttons as fit, the rest flow below in the same columns (#213 follow-up). Every footer button is flat at rest and outlined only on hover or press, the `QPushButton`s through the same theme rule as the menu `QToolButton`s; the Channels and Paths footers (`QToolButton`s) already look the same (#354, `ui_panel_footer_buttons_outline_only_on_hover`).
- **List floor.** `kLayerListMinimumWidth` (256) keeps a top-level row with a mask, its link and two badges whole, so it is the widest item and sets the compact width (268 px offscreen in English, against the 367 px opening width). Narrowing the row itself would lower it.
- **Two widths per row.** `minimumSize()` is the row fully wrapped (it sets the compact width); `comfortable_width()` the row at the opening width (footer on one row, Opacity and Fill on one line under the combo). Nothing changes until the column is narrower than the content-fit width (`ui_layer_panel_compact_width_keeps_controls_whole`).
- **Height.** Wrapped rows raise the panel's minimum height. Every growth refits the floors (`handle_right_dock_resize_event` watches the panel's layout requests): the panel's explicit floor is the larger of its base (240 px, lowered by the screen fit) and the wrapped height, both ways (`refresh_layers_panel_floor`), so the rows never squeeze into each other; the fit lowers other floors only when the window's minimum passes the screen, then undoes the window growth the raise forced.

## Heights and collapse

Panel heights must never pin the window taller.
- **Collapsed.** A collapsed section is exactly its title row, plus the group's tab bar. Its min == max is set by `apply_section_state`, recomputed on a style or font change (`ui_collapsed_right_docks_have_uniform_title_height`). The splitter has stretch 1 over a stretch-0 spacer in the column's layout: while a section is expanded it takes the full height, and once its maximum falls short (every section collapsed, or only capped ones such as Color open) the rows stack from the top with the spare height below (GitHub issue 391, `ui_panel_all_collapsed_stack_at_top`).
- **Freed height.** QSplitter keeps a slot's remembered size after the section's maximum shrinks, which leaves a band under a collapsed header until a divider moves. Every collapse, expand, close and reopen ends in `settle_sizes`, which clamps each slot to its section's limits and gives the difference to the nearest expanded sections, the ones above first (`ui_panel_collapse_and_close_leave_no_gap`).
- **Expanded.** An expanded section has its spec floor, raised to its bodies' minimum until the screen fit lowers it (`section_floor`, `refresh_floors`): Layers group 300, Channels and Paths 190, History 90 (prefers 190), Properties prefers 230 with no cap, Color prefers 170 (at most 280), Palette prefers 320. Expanding hands the section its preferred height through `QSplitter::setSizes`, synchronously, taken from the other expanded sections, tallest first and down to their floors (`grant_preferred_height`). There are no temporary minimums and no deferred releases.
- **Title-row clicks.** A click (press and release on the row, no drag) on a collapsed section's title row or title text expands it; a double click on an expanded one collapses it, and a double click on a collapsed one expands it (the first click expands, `expanded_by_click_` keeps the double click from collapsing it again). A single click on an expanded row does nothing. Both go through the collapse button's `setChecked`, so the toggle, `panel_expanded_changed` and the saved layout see the same change as a button click. A press that turns into a drag toggles nothing; the collapse button keeps its own clicks. The tab bar keeps tab picking and does not toggle (GitHub issue 335, `ui_panel_title_click_expands_and_double_click_collapses`).
- **Tab group.** The group is one section, so it collapses and expands as one: its toggles stay in step, and a background tab's toggle expands the whole group (GitHub issue 101, `ui_tabbed_right_dock_group_collapses_as_one`).
- **First show.** The first show distributes the heights with `apply_preferred_heights`; every section but the Layers group takes its preferred height (the Color group its front tab's 170) and the Layers group takes the rest.
- **The fill section.** The section holding the first panel added (Layers, `fill_panel_id_`, `Section::fills`, refreshed by `update_fill_section` after every regroup) has stretch 1 and takes the column's spare height wherever it has been moved and whatever group it is in; `apply_preferred_heights` gives it the rest and `lower_floors` lowers it last.
- **Dividers.** The column splitter's handles drag (`ui_right_dock_separator_drags_between_docks`). Only Color is capped; the rest grow to their neighbors' floors (local issue 025). Properties' info rows word-wrap, so it scrolls only below its controls' width or its rows' height (`ui_properties_divider_grows_panel_without_scroll_bars`).
- **Screen fit.** The window's minimum must fit `available_window_height()` (GitHub issue 108). `fit_right_dock_floors_to_screen` lowers the expanded sections' floors, bottom up and the group last, never below their title row plus 48 nor below their content's own minimum (`PanelColumn::lower_floors`). Then, if needed, it lowers the Layers list's 120 px and panel's 240 px floors (the list never below 48), walking `updateGeometry` up to the column so the cached minimums follow, and lowers the section floors again to the new content minimum. Only a screen too short for that takes a section under its content (`keep_content` false), where its overflow area scrolls vertically instead of clipping; a section is never given less than its floor, which would paint it over the next title row (local issue 016). Once shown, it activates the layout so a resize right after sees the lower minimum. It runs from the startup clamp, the column's first show, and every expand, visibility or grouping change. The startup clamp runs before the first show, when the Options bar measures its wrapped height at no width (about 390 px for a 30 px row), so the first show restores the section floors (`PanelColumn::restore_floors`) and fits again with real sizes. Panels that can outgrow their share scroll internally; never give a panel an unbounded minimum height (`ui_right_dock_floors_fit_the_screen_height`, `ui_right_dock_panels_expand_within_window_height`; the Wayland side is in [wayland.md](wayland.md)).

## Showing, hiding and the header menu

- **Showing and hiding.** `PanelColumn::set_panel_visible` closes or reopens a panel. In the group it hides the tab, passes the front to the next open tab, and hides the section once no tab is open. A reopened section takes its preferred height back from its neighbors. Every section always spans the column's full width (`ui_panel_close_and_reopen_keeps_full_width`).
- **Header menu.** Right-clicking a title row or a tab emits `header_context_menu_requested`, and `show_panel_header_menu` opens `panelHeaderMenu`. It holds Collapse Panel or Expand Panel, then Close Panel (Close Tab Group on the tab bar, which closes every tab of the group), the panel and toolbar toggles, Show Panel Titles and Reset Panels (`ui_panel_header_right_click_opens_panel_menu`). A right-click on a toolbar or the menu bar opens `toolbarPanelMenu` (`MainWindow::createPopupMenu`): the same panel and toolbar toggles, Show Panel Titles and Reset Panels, without the collapse and close entries (`ui_panel_list_opens_on_toolbar_right_click`). The palette-mode status chip calls `show_panel("paletteDock")`, and `patchy.ui.expandPanel` does the same by script name ([scripting.md](scripting.md)).

## Hidden title rows

Window > Show Panel Titles (`window.show_panel_titles`, `windowShowPanelTitlesAction`, checked by default, no default key; GitHub issue 721) turns the title rows of expanded sections off and on, live, through `MainWindow::set_panel_titles_visible` and `PanelColumn::set_titles_visible`. `shows_title_row` decides per section:
- **Expanded section of its own.** No title row: the panel starts at the section's top edge.
- **Expanded tab group.** The tab bar stays (it picks the tab and carries the header menu) and the title row under it goes.
- **Collapsed section.** Keeps its title row, which is how it expands again (a click on the row or its button); expanded, the row goes.
- **Settings gears.** A `PanelSpec::header_widget` (the Layers and Color gears) never becomes unreachable. In a group, `place_header_widgets` moves the front tab's gear into `panelTabGroupCorner`, a holder at the end of the tab bar's row that takes no room while empty; it follows the front tab and goes back to its title row when the row returns, the panel leaves the group or the group dissolves (before the container is deleted). A section of its own whose panel has a gear keeps its title row: it has no tab bar to move to.
- **Heights.** `header_height` is what sits above the panel now (the tab bar, plus the title row while shown) and replaces `collapsed_height` in the floors, the preferred heights, the screen fit and the drop targets. Sections keep their heights when the option changes, so the panel takes or gives the row's room and nothing shifts; a section sitting at a content-fitted height (the Color panel's slider views) refits. Turning the option back on returns the same layout.
- **What is lost while hidden.** A section of its own has no collapse button, no title-row drag and no header to drop a panel onto, and its header menu is gone. Tab groups keep all of that on their tab bar (Collapse Panel in its right-click menu). Show Panel Titles itself stays in the Window menu, the tab bar menu and the toolbar right-click menu, and Reset Panels brings the rows back too. Panel bodies get no new right-click menu.
- **Reset Panels** turns the option back on (its default) before it restores the layout, so every title row returns and the heights are measured with the rows in place; the layout saved after it holds `window/showPanelTitles` true.

`ui_panel_titles_hide_for_expanded_panels`, `ui_panel_titles_hidden_keep_settings_gears`, `ui_panel_titles_setting_returns_in_the_next_window`.

## Window menu entries

The Window menu lists every panel and both toolbars as checkable entries (`install_window_panel_entries`, GitHub issue 163). `sorted_window_panel_actions` sorts the panel entries by their current text with `QCollator` each time the menu opens. The document-window commands sit under Window > Arrange.
- **Panel entries.** `toggle_window_panel`: a panel that is open and in front closes, collapsed or not (GitHub issue 234; Photoshop expands it); any other opens, comes to the front and expands (`show_panel`), so a tab behind another of its group comes forward. The check mark is `panel_visible`, re-read on every open (`ui_window_menu_hides_collapsed_panel`).
- **Hotkeys** (GitHub issue 469). Each panel entry is a registered command `window.panel_<name>`: F6 Color, F7 Layers and F8 Info by default, Photoshop's panel keys; the rest unbound. F5 stays View > Force Refresh, so **Brush Dynamics and Effects** (`window.brush_settings`) and **Brush Tips** (`window.brush_tips`) ship unbound: floating windows ([brushes-ui.md](brushes-ui.md)). `ui_window_panel_hotkeys_show_and_hide_panels`.
- **Toolbars.** `toggleViewAction`s, Tool Palette then Tool Options (object `Options`), follow the panels between separators, in the right-click menus too (GitHub issue 513).
- **Show Panel Titles** (`window.show_panel_titles`, [Hidden title rows](#hidden-title-rows)) and **Reset Panels** (`window.reset_panels`) end the list, after a separator.
- **During automation.** Panel entries, Show Panel Titles and Reset Panels stay usable while MCP automation runs (`McpActivity::action_allowed`).

`ui_window_menu_lists_panels_and_toolbars` covers the entries.

## Saved panel layout

A consented close (`closeEvent`, beside `save_window_geometry`) writes the layout, and the next launch reads it right after the window geometry, before the first show (`save_panel_layout`, `restore_panel_layout`).

The keys are compatibility contracts:
- `window/panelLayoutVersion` (`kPanelLayoutVersion`, now 4). Bump it when panels are added, renamed or their default groups change; an older record is then ignored unless `read_panel_layout` carries it forward. Version 3 is version 4 without `window/panelGroups` and `window/frontPanels`: it is kept with the column of its time (only the Layers group, Color and Palette apart, and that time's default order when it has no `window/panelOrder`). Version 2 is version 3 without the Color panel: it is kept, and the Color panel joins it collapsed, just above Palette (the old heights are restored with Color last, then it moves; `ui_panel_layout_from_before_color_panel_keeps_its_panels`).
- `window/hiddenPanels` (panel ids and the toolbar names `toolPalette`, `Options`).
- `window/collapsedPanels`.
- `window/frontPanel` (the first group's front tab) and `window/frontPanels` (version 4: every group's front tab; read in preference).
- `window/panelOrder` (`section_order`, applied before the heights, which are by position; a record without it keeps the default order).
- `window/panelGroups` (version 4): one string per tab group, its panel ids in tab order joined by commas (`tab_groups`); a panel in no entry has a section of its own. Read first, through `set_tab_groups`: unknown ids are skipped, a group that already holds the same panels only orders its tabs, every other group comes apart in place, and each saved group forms where its first panel sits.
- `window/panelSplitterState` (the column splitter's `saveState`).
- `window/panelColumnWidth` (present only while the width is picked, not following the content).
- `window/showPanelTitles` (Show Panel Titles; absent means shown). Written with the layout but no part of the versioned record: `read_panel_layout` applies it whatever `window/panelLayoutVersion` says.

Offscreen runs neither read nor write the record (`panel_layout_persists`). A UI test that closes a panel must not leak into the next one, and `--headless` or the MCP connector's own window must not change the user's layout. Tests drive it through `MainWindowTestAccess::write_panel_layout`/`read_panel_layout` (`ui_panel_layout_returns_in_the_next_window`).

Window > Reset Panels (`reset_panels`) does the following:
- turns Show Panel Titles back on ([Hidden title rows](#hidden-title-rows)),
- reopens every panel,
- restores the first-launch groups and tab order (`default_tab_groups_`, through `set_tab_groups`) and section order (`default_panel_order_`),
- applies the collapse states captured right after `create_docks` (`default_collapsed_panels_`),
- brings Layers to the front,
- re-adds a moved toolbar to its first-launch area,
- re-runs `apply_preferred_heights`,
- returns the column to the content-fit width.

The window keeps its size and place. Floors a short screen lowered stay lowered: restoring them would ask for more height than the window has (`ui_reset_panels_restores_first_launch_layout`, `ui_reset_panels_keeps_the_window_geometry`).
