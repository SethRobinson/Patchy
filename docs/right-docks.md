# Right panel column

On a first launch and after Reset Panels the right column holds, top to bottom, Color and Palette (one tab group, expanded, Color in front), Layers, Channels and Paths (one tab group, expanded), then Properties, Info and History (collapsed; Seth, October 2026). `create_docks` adds the Layers group first, so it is the fill section, then the other panels, merges Palette into Color and sets the order. It is a `PanelColumn` (`src/ui/panel_column.hpp/.cpp`) that Patchy owns: a vertical `QSplitter` of sections, each a title row (collapse toggle and title) over its panel. Nothing in it is a `QDockWidget` and nothing floats; sections move up and down within the column, and panels join or leave tab groups there (see "Reordering"). The central widget is the `workspaceSplitter` (`QSplitter`): the document tabs (`documentTabs`, stretch 1) and the column (stretch 0). Tests reach the tabs with `findChild<QTabWidget*>("documentTabs")`, never through `centralWidget()`. `create_docks` (`src/ui/main_window_docks.cpp`) builds each panel and hands it over as a `PanelSpec`.

Panel ids are the old dock object names (`layersDock`, `channelsDock`, `pathsDock`, `historyDock`, `propertiesDock`, `infoDock`, `paletteDock`), plus `colorDock` for the Color panel added later. They name the panel's widget, and the saved layout stores them, so they never change. A title row is `<prefix>DockTitle` with `<prefix>DockTitleLabel` and `<prefix>DockCollapseButton` (`dockCollapseButton` property). The theme, the MCP allowlist and the tests rely on these names. Every tab group's section is `panelTabGroup`, its bar `panelTabGroupTabBar` (groups formed later take the same names; the theme styles the bar by that name) (`drawBase(false)`, so no Fusion base line: GitHub issue 123, `ui_dock_tab_bars_draw_no_native_base`). `MainWindowTestAccess::panel_column`/`panel_section`/`show_panel` reach it from tests.

## Width

- **The edge.** The column's draggable edge is the workspace splitter's handle, named `rightDockResizeHandle` (theme and MCP selectors). `apply_right_column_width` sets it exactly with `setSizes`. The column's stretch factor is 0, so it keeps its width as the window resizes. Do not reintroduce a fixed-width widget or an overlay handle.
- **Widths.** `update_right_dock_minimum_width` measures two. The content-fit width `right_dock_minimum_width_` takes each wrapping Layers row at its `comfortable_width()` (the footer buttons on one row, or the blend row at its wrapped width; see [layer-panel.md](layer-panel.md)) plus the column chrome, never below `kRightDockMinimumWidth`. The compact width `right_dock_compact_width_` is the panel layout's minimum, every row fully wrapped, plus the chrome (GitHub issue 199): between the two the rows reflow, and only below the compact width does the panel scroll sideways (`ui_layer_panel_compact_width_keeps_controls_whole`). Channels, Paths and the other panels are not measured. The chrome is the column minus the Layers panel's scroll viewport, measured once laid out (on the column's first show, through `handle_right_dock_resize_event`, and lazily). The panel can be wider than the viewport, so never measure against the panel. Never add a competing hardcoded width.
- **Opening width.** Until the user or a script picks a width (`right_dock_width_follows_minimum_`), the column sits at the content-fit width and follows it when it changes (language switch, restyle), so it opens with no dead strip beside the Layers footer in every language (GitHub issue 96, `ui_right_dock_opens_at_content_width_without_gap`).
- **Picked widths.** `patchy.ui.setSidePanelWidth` goes through `set_right_dock_stack_width`, which clamps to `kRightDockFloorWidth` (120) .. window width - 260 and keeps the result, narrower than the content included; it never snaps. A drag of the edge lands in `handle_right_column_moved` (`splitterMoved`). Within `kRightDockSnapDistance` (10 px) of the content-fit width it snaps onto it and follows that width again. Otherwise the dragged width is kept as picked (`ui_right_dock_drag_snaps_to_content_width`). It stays usable while a non-modal preview dialog is open; modal windows block it, as Qt blocks all main-window input (`ui_right_dock_drag_works_during_preview_dialog`).
- **Overflow.** Every panel but Properties (already a `QScrollArea`) sits in a `RightDockOverflowArea` (`rightDockOverflowScroll`). Below a panel's minimum width the panel keeps that width and scrolls sideways, with the bar at the bottom. The area never scrolls vertically: it hands the panel the viewport's full height, and its minimum height grows by the bar while it shows. It places the panel by hand because `widgetResizable` would size the height-for-width Layers panel to its preferred height and clip the footer. Title labels use an `Ignored` width policy, so a long title clips instead of holding the column wide (`ui_right_dock_drags_below_content_minimum_with_scroll`).
- Tests read the content-fit width with `MainWindowTestAccess::right_dock_content_minimum_width` and the narrowest no-scroll width with `right_dock_compact_width`. Keep staged `setSidePanelWidth` values in tests above it unless the test is about scrolling. A splitter handle moves with its drag, so a test drags it with one move, not several in its own coordinates.

## Narrow Layers panel

Three Layers rows wrap instead of clipping (`WrappingControlRowLayout`, `WrappingButtonRowLayout` in main_window_docks.cpp; GitHub issues 96 and 199):
- **Blend row.** Opacity and Fill go under the combo when one line does not fit, then Fill under Opacity (`ui_layer_blend_row_wraps_in_narrow_panel`).
- **Lock row.** The name filter leaves the Lock buttons for a line of its own when its share drops under 90 px (`kLayerNameFilterMinimumWidth`).
- **Footer.** The buttons narrow from their maximum to their minimum width at 3 px spacing (the theme's `layerActionButton` rule sets both; its widths exclude the border), then wrap into balanced rows, four over four. Every footer button is flat at rest and outlined only on hover or press, the six `QPushButton`s through the same theme rule as the two menu `QToolButton`s; the Channels and Paths footers (`QToolButton`s) already look the same (#354, `ui_panel_footer_buttons_outline_only_on_hover`).
- **List floor.** `kLayerListMinimumWidth` (256) keeps a top-level row with a mask, its link and two badges whole, so it is the widest item and sets the compact width (268 px offscreen in English, against the 367 px opening width). Narrowing the row itself would lower it.
- **Two widths per row.** `minimumSize()` is the row fully wrapped (it sets the compact width); `comfortable_width()` the row at the opening width (footer on one row, Opacity and Fill on one line under the combo). Nothing changes until the column is narrower than the content-fit width (`ui_layer_panel_compact_width_keeps_controls_whole`).
- **Height.** Wrapped rows raise the panel's minimum height. Every growth refits the floors (`handle_right_dock_resize_event` watches the panel's layout requests): the refit raises the panel's own explicit floor to the wrapped height, or the 240 px floor would win and squeeze the rows into each other once the panels above take the height (an expanded Color panel does), and lowers other floors only when the window's minimum passes the screen.

## Heights and collapse

Panel heights must never pin the window taller.
- **Collapsed.** A collapsed section is exactly its title row, plus the group's tab bar. Its min == max is set by `apply_section_state`, recomputed on a style or font change (`ui_collapsed_right_docks_have_uniform_title_height`). The splitter has stretch 1 over a stretch-0 spacer in the column's layout: while a section is expanded it takes the full height, and once its maximum falls short (every section collapsed, or only capped ones such as Properties open) the rows stack from the top with the spare height below (GitHub issue 391, `ui_panel_all_collapsed_stack_at_top`).
- **Freed height.** QSplitter keeps a slot's remembered size after the section's maximum shrinks, which leaves a band under a collapsed header until a divider moves. Every collapse, expand, close and reopen ends in `settle_sizes`, which clamps each slot to its section's limits and gives the difference to the nearest expanded sections, the ones above first (`ui_panel_collapse_and_close_leave_no_gap`).
- **Expanded.** An expanded section has its spec floor: Layers group 300, Channels and Paths 190, History 90 (prefers 190), Properties at most 230, Color prefers 170 (at most 280), Palette prefers 320. Expanding hands the section its preferred height through `QSplitter::setSizes`, synchronously, taken from the other expanded sections, tallest first and down to their floors (`grant_preferred_height`). There are no temporary minimums and no deferred releases.
- **Title-row clicks.** A click (press and release on the row, no drag) on a collapsed section's title row or title text expands it; a double click on an expanded one collapses it, and a double click on a collapsed one expands it (the first click expands, `expanded_by_click_` keeps the double click from collapsing it again). A single click on an expanded row does nothing. Both go through the collapse button's `setChecked`, so the toggle, `panel_expanded_changed` and the saved layout see the same change as a button click. A press that turns into a drag toggles nothing; the collapse button keeps its own clicks. The tab bar keeps tab picking and does not toggle (GitHub issue 335, `ui_panel_title_click_expands_and_double_click_collapses`).
- **Tab group.** The group is one section, so it collapses and expands as one: its toggles stay in step, and a background tab's toggle expands the whole group (GitHub issue 101, `ui_tabbed_right_dock_group_collapses_as_one`).
- **First show.** The first show distributes the heights with `apply_preferred_heights`; every section but the Layers group takes its preferred height (the Color group its front tab's 170) and the Layers group takes the rest.
- **The fill section.** The section holding the first panel added (Layers, `fill_panel_id_`, `Section::fills`, refreshed by `update_fill_section` after every regroup) has stretch 1 and takes the column's spare height wherever it has been moved and whatever group it is in; `apply_preferred_heights` gives it the rest and `lower_floors` lowers it last.
- **Dividers.** The dividers between sections are the column splitter's handles and drag (`ui_right_dock_separator_drags_between_docks`).
- **Screen fit.** The window's minimum must fit `available_window_height()` (GitHub issue 108). `fit_right_dock_floors_to_screen` lowers the expanded sections' floors, bottom up and the group last, never below their title row plus 48 (`PanelColumn::lower_floors`). Then, if needed, it lowers the Layers list's 120 px and panel's 240 px floors (the list never below 48). Once shown, it activates the layout so a resize right after sees the lower minimum. It runs from the startup clamp, the column's first show, and every expand, visibility or grouping change. The startup clamp runs before the first show, when the Options bar measures its wrapped height at no width (about 390 px for a 30 px row), so the first show restores the section floors (`PanelColumn::restore_floors`) and fits again with real sizes. Panels that can outgrow their share scroll internally; never give a panel an unbounded minimum height (`ui_right_dock_floors_fit_the_screen_height`, `ui_right_dock_panels_expand_within_window_height`; the Wayland side is in [wayland.md](wayland.md)).

## Color panel

`ColorDockPanel` (`src/ui/color_dock_panel.hpp/.cpp`, panel id `colorDock`, GitHub issue 365) holds the foreground/background pair (`ColorWellSwatch` and `ColorWellGlyphButton` from the tool palette, whose Swap Colors and Default Colors actions the glyphs trigger) and one of three views in a `QStackedWidget`: the Hue Cube (a saturation/value field and a hue strip, the default), RGB Sliders and HSB Sliders. The field and strip are the picker window's own widgets (`src/ui/color_field_widgets.hpp`), drawn from an `HsvFieldSource`; the field caches its gradient per hue and size.
- **Views** (GitHub issue 404). The menu button under the pair (`colorPanelViewButton`, `colorPanelViewMenu`) and the panel's header menu list the same three checkable actions. `colorPanel/view` stores the pick (`ColorDockPanel::view_token`: `hueCube`, `rgbSliders`, `hsbSliders`; an unknown value opens the cube). Hidden pages carry an `Ignored` size policy so the stack's hints are the shown view's. A slider view asks the column for its content height (`PanelSpec::preferred_content_height`, `fitted_height`), and a view change while the panel is open and in front refits the section at once (`PanelColumn::refit_panel_height`): shorter hands the height to the nearest expanded sections, the cube takes its 170 back. Brightness Cube, Grayscale and CMYK sliders were left out (Seth, October 25, 2026).
- **Sliders.** Each row is a letter, a `ColorChannelTrack` (the color across that channel with the other two held, a two-tone marker like the hue strip's) and a number box: R, G, B 0..255; H 0..359 degrees, S and B 0..100 percent (`UnitIntSpinBox` with the degree and percent suffixes). A track press or drag, or a number edit (live, including typing), sets the foreground only; Alt has no meaning there, as in the picker window's Sliders tab. The panel keeps the foreground as RGB beside its HSV, so an RGB edit never goes through an 8-bit HSV round trip; a gray keeps the hue shown, and black keeps hue and saturation. The number boxes are refreshed with signals blocked, so a color from elsewhere never comes back as a pick. A track drag holds the canvas's answer off like a field drag.
- **Picks.** The field shows the foreground. A click or drag sets the foreground (the field and strip edit it as the picker window does). Alt (Option on macOS) at the press makes that press set the background for its whole drag, as the Pick tool's Alt-click does: `begin_field_pick` reads the press event's modifiers once. The background takes the color under the pointer (field: the shown hue at the pointer's saturation and value; strip: that hue at full strength), and the field keeps showing the foreground.
- **Alt cursor.** Over the field or the hue strip, holding Alt shows the Pick tool's background cursor (`eyedropper_target_cursor(true)`) in place of the widget's own (`BackgroundPickCursor`, src/ui/background_pick_cursor.hpp). It follows the Alt key itself while the pointer is over the widget (an application key filter installed only while hovered, since the panel never takes focus) as well as each mouse move, and a left press fixes it until the release, as the press fixes the target. The Palette panel's swatches use the same cursor for their Alt-click ([palette-mode.md](palette-mode.md)).
- **Foreground Color window.** The floating picker has the same Alt pick when opened for the foreground: `PatchyColorPicker::set_background_pick_handler`, set in `show_color_panel`, routes an Alt press on its palette swatches, custom colors, Square field and hue strip, Wheel, or a Pick Screen Color click to `apply_color_panel_pick(color, true)`; the window keeps editing and showing the foreground, and those surfaces get the background cursor. The Sliders tab has no Alt pick (a slider moves one channel). The Background Color window and the request pickers set no handler, so Alt there acts like a plain click and the cursor stays (`ui_color_picker_foreground_window_alt_pick_sets_background`, `ui_color_picker_background_window_alt_click_is_a_plain_click`).
- **Applying.** `MainWindow::apply_color_panel_pick` sets the canvas color (the foreground path also recolors an open text session and the shape paint, like the Foreground Color window), mirrors it into an open Foreground or Background Color window, and ends in `refresh_color_buttons`, which pushes every color change from anywhere back through `set_colors`. While a foreground drag runs the field ignores the canvas's answer (a palette-snapped color would move the crosshair); a returned color equal to the one the panel produced keeps the field's own hue and saturation.
- **Chips.** A click opens the Foreground or Background Color window, as the tool palette's chips do. With no document the panel is disabled (a document widget).
- `ui_color_panel_*` tests cover the picks, Alt for the whole drag, and the sync; `ui_color_panel_view_menu_switches_views`, `ui_color_panel_sliders_set_foreground`, `ui_color_panel_sliders_follow_color_changes_elsewhere` and `ui_color_panel_view_persists` the views.

## Showing, hiding and the header menu

- **Showing and hiding.** `PanelColumn::set_panel_visible` closes or reopens a panel. In the group it hides the tab, passes the front to the next open tab, and hides the section once no tab is open. A reopened section takes its preferred height back from its neighbors. Every section always spans the column's full width (`ui_panel_close_and_reopen_keeps_full_width`). The old dock column could re-dock a reopened panel narrower, with the window background beside it.
- **Header menu.** Right-clicking a title row or a tab emits `header_context_menu_requested`, and `show_panel_header_menu` opens `panelHeaderMenu`. It holds Collapse Panel or Expand Panel, then Close Panel (Close Tab Group on the tab bar, which closes every tab of the group), the panel and toolbar toggles, and Reset Panels (`ui_panel_header_right_click_opens_panel_menu`). A right-click on a toolbar or the menu bar opens `toolbarPanelMenu` (`MainWindow::createPopupMenu`): the same panel and toolbar toggles and Reset Panels, without the collapse and close entries (`ui_panel_list_opens_on_toolbar_right_click`). The palette-mode status chip calls `show_panel("paletteDock")`, and `patchy.ui.expandPanel` does the same by script name ([scripting.md](scripting.md)).

## Reordering

Dragging a title row, or a group's tab bar, up or down moves that section. `PanelColumn` filters the title rows and the tab bars (a press on the label reaches the row; the collapse button keeps its press, and a press on a tab still picks it). Past `startDragDistance` the drag starts: a closed-hand override cursor, a ghost, a drop indicator, and an application event filter so Escape or any other press cancels. Nothing floats, nothing leaves the window, `QDrag` is not used, and `QTabBar::setMovable` stays off: the column owns the gesture (`ui_panel_title_drag_reorders_sections`, `ui_panel_tab_drag_reorders_tabs`, `ui_panel_drag_onto_header_merges_into_tabs`).
- **What moves.** A drag from a tab carries that tab, whichever way it goes (so the first tab can be pulled out below its own group); a drag from a title row, or from the tab bar beside the tabs (the bar spans the section for this), carries the section. Offscreen tests press clear of the window's right edge: the custom window chrome takes a press there as a resize. A press still picks the tab first, so a dragged tab is in front.
- **Ghost.** `panelDragGhost`, a child of the window (never a window, transparent to the mouse), paints what the drag carries at half opacity under the pointer, held where it was pressed, so the drop line, the outline and the panels show through it. Its own style sheet makes its background transparent: the theme gives every plain `QWidget` an opaque `@window_bg`, which would paint under the copy (`ui_panel_drag_onto_header_merges_into_tabs` checks the alpha). It carries the tab, or the bar the section was picked up by (its title row, or the tabs of its tab bar), grabbed when the drag starts.
- **Drop targets** (`drop_at`). Beside the column (over the canvas, say) nothing shows and a release changes nothing: the panel stays where it was. Above or below the column, in line with it, a drop lands at its top or bottom, the only way above a group whose tab bar starts at the very top (its bar covers the edge band). A tab over its own bar, or within 6 px above or below it, only changes places. Otherwise a section's header (its tab bar and title row, `collapsed_height`) takes the panel in, except a band at its top and bottom edges (a quarter of the header, 3 to 8 px), which drops between sections; below an expanded section's header a drop lands above or below its middle. A drop onto its own header, or a section dropped where it is, does nothing and shows nothing.
- **Indicators.** Between sections: the Layers list's insertion line (`panelDropIndicator`, `@drop_indicator_bg`) on the divider. Onto a header: `panelMergeIndicator` outlines that header, plus an upright insertion line at the tab edge when the pointer is over its tab bar (before the first shown tab whose middle lies past the pointer, mirrored right to left).
- **Moves.** A section dropped between sections moves with `move_section_index` through `QSplitter::insertWidget`, keeping its height, and emits `section_order_changed`. A tab dropped along its own bar moves with `move_tab_index`, which moves the `pages` entry, the `QStackedWidget` page and the `QTabBar` tab together, so tab, stack and page indexes stay equal everywhere the code assumes it; it keeps the front page and the focus. A drop beside the tab's own place, or with only closed tabs between, changes nothing. The tab bar still gets the release, so it clears its pressed tab.
- **Groups.** A panel dropped on another section's header joins it as a tab (`merge_panel`, at the tab slot or after the last tab) and comes to the front; a section dropped there brings all its tabs, its front one in front (`merge_section`). The section joined keeps its collapse state. A tab dropped between sections becomes a section of its own there, with the group's collapse state (`separate_panel`). A group left with one panel becomes a plain section again (`dissolve_group`: its page takes the group's splitter slot through `QSplitter::replaceWidget`, the container is deleted later); a single section that gains a tab turns into a group in place (`make_group`). A page leaving its own section drops the min and max heights that section had (a collapsed one is pinned to its title row). Regrouping reparents pages and can delete the dragged tab bar, so a drop queues it (`Qt::QueuedConnection`) rather than doing it inside the dragged widget's event. `finish_regroup` refreshes the fill section, every section's state and the sizes, then emits `tab_groups_changed` and `section_order_changed`; the window refits its floors on it.
- **Names.** Sections are named by their first panel's id (`section_order`, `set_section_order`, `move_section`; any member's id names its section), so a group is named by its first tab. `tab_groups`, `set_tab_groups`, `set_tab_order`, `move_tab`, `merge_panel`, `merge_section` and `separate_panel` do the same as the drags without a mouse. The header menu has no grouping commands yet.

## Window menu entries

The Window menu lists every panel and both toolbars as checkable entries (`install_window_panel_entries`, GitHub issue 163). `sorted_window_panel_actions` sorts them by their current text with `QCollator` each time the menu opens. The document-window commands sit under Window > Arrange.
- **Panel entries.** `toggle_window_panel`: a panel that is open and in front closes, collapsed or not (GitHub issue 234; Photoshop expands a collapsed one instead); any other opens, comes to the front and expands (`show_panel`), so a tab behind another of its group comes forward. The check mark is `panel_visible`, re-read on every open (`ui_window_menu_hides_collapsed_panel`).
- **Toolbars.** The toolbars use Qt's own `toggleViewAction`.
- **Reset Panels.** Window > Reset Panels (`window.reset_panels`) ends the list.
- **During automation.** Panel entries and Reset Panels stay usable while MCP automation runs (`McpActivity::action_allowed`).

`ui_window_menu_lists_panels_and_toolbars` covers the entries.

## Saved panel layout

A consented close (`closeEvent`, beside `save_window_geometry`) writes the layout, and the next launch reads it right after the window geometry, before the first show (`save_panel_layout`, `restore_panel_layout`).

The keys are compatibility contracts:
- `window/panelLayoutVersion` (`kPanelLayoutVersion`, now 4). Bump it when panels are added, renamed or their default groups change; an older record is then ignored unless `read_panel_layout` carries it forward. Version 3 is version 4 without `window/panelGroups` and `window/frontPanels`: it is kept with the column of its time (only the Layers group, Color and Palette apart, and that time's default order when it has no `window/panelOrder`). Version 2 is version 3 without the Color panel: it is kept, and the Color panel joins it collapsed, just above Palette (the old heights are restored with Color last, then it moves; `ui_panel_layout_from_before_color_panel_keeps_its_panels`).
- `window/hiddenPanels` (panel ids and the toolbar names `toolPalette`, `Options`).
- `window/collapsedPanels`.
- `window/frontPanel` (the first group's front tab) and `window/frontPanels` (version 4: every group's front tab; read in preference).
- `window/panelOrder` (`section_order`, applied before the heights, which are by position; a record without it keeps the default order).
- `window/panelGroups` (version 4): one string per tab group, its panel ids in tab order joined by commas (`tab_groups`); a panel in no entry has a section of its own. Read first, through `set_tab_groups`: unknown ids are skipped, a group that already holds the same panels only orders its tabs, every other group comes apart in place, and each saved group forms where its first panel sits.
- `window/panelSplitterState` (the column splitter's `saveState`).
- `window/panelColumnWidth` (present only while the width is picked, not following the content).

Offscreen runs neither read nor write the record (`panel_layout_persists`). A UI test that closes a panel must not leak into the next one, and `--headless` or the MCP connector's own window must not change the user's layout. Tests drive it through `MainWindowTestAccess::write_panel_layout`/`read_panel_layout` (`ui_panel_layout_returns_in_the_next_window`).

Window > Reset Panels (`reset_panels`) does the following:
- reopens every panel,
- restores the first-launch groups and tab order (`default_tab_groups_`, through `set_tab_groups`) and section order (`default_panel_order_`),
- applies the collapse states captured right after `create_docks` (`default_collapsed_panels_`),
- brings Layers to the front,
- re-adds a moved toolbar to its first-launch area,
- re-runs `apply_preferred_heights`,
- returns the column to the content-fit width.

The window keeps its size and place. Floors a short screen lowered stay lowered: restoring them would ask for more height than the window has (`ui_reset_panels_restores_first_launch_layout`, `ui_reset_panels_keeps_the_window_geometry`).
