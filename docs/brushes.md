# Bitmap brush tips, dynamics and effects, Flow/Airbrush, Mixer Brush, Pattern Stamp, and .abr import

Brush-tip stamping engine, tip library/UI, brush dynamics, and .abr import. Determinism and append-only identifier rules (`BrushDynamicControl`) are in `AGENTS.md`; UI conventions in [ui-conventions.md](ui-conventions.md); the binding patent summary in [legal-constraints.md](legal-constraints.md). Script automation (`layer.drawStrokes`, `patchy.brushes`): [brush-automation.md](brush-automation.md). Painting and retouch tools write 16/32-bit layers at depth (deep brush compositor; palette snapping is 8-bit only): [high-bit-depth.md](high-bit-depth.md).

Brush, Pattern Stamp, and Eraser can stamp bitmap **brush tips** as well as the procedural brushes. Two procedural footprints exist, `core BrushShape` Round and Square, selected in the tip picker as the reserved ids `builtin.round` and `builtin.square` (script identifiers; never change them). The Square is procedural on purpose: a hard, unrotated square snaps to the pixel grid, so a dab at any sub-pixel position covers exactly (2 x radius + 1)^2 whole pixels and a size-1 square is the one pixel under the pointer, with no partial-alpha fringe. Rotation, roundness (a rectangle) and Soft use the geometric footprint with a Chebyshev feather keeping the corners square (`square_brush_coverage` in `src/core/pixel_tools.cpp`); square strokes take the elliptical brushes' dab-spacing path. Square applies to the Brush and Eraser (`apply_brush_tip_to_options` sets `EditOptions::brush_shape`); Pattern Stamp, Clone, Mixer and the retouch brushes stay round. With session dynamics active the Square stamps through a synthesized solid 256 px square the way Round stamps through its disc. The cursor and the large-brush overlay draw a square outline rotated by the base angle. `tool_square_brush_dabs_are_pixel_snapped_and_solid` (core) pins the footprint math.

## Core stamping engine

- Core stamping: `src/core/brush_tip.hpp/.cpp` (`BrushTip` = 8-bit grayscale coverage mask + default spacing; `BrushTipMipChain` box-filtered halvings built once per tip; `ScaledBrushTip` resampled per brush size) and `src/core/pixel_tools.cpp` (`paint_tip_dab`, `paint_tip_segment`). `EditOptions::brush_tip` (non-owning `const ScaledBrushTip*`, null = procedural) plus `brush_tip_spacing` select the stamp path. Rotation/roundness/subpixel apply per-dab in the inverse map, so the scaled cache depends only on size (pressure size quantizes to 2px steps while a tip is active; an 8-entry LRU caches scaled stamps). The stateful `paint_brush_segment(..., BrushTipStrokeState&)` overload carries dab spacing across the stroke smoother's short segments; state resets in `CanvasWidget::clear_brush_stroke_tracking()`.
- **Soft** applies to bitmap tips as an outward edge feather: `patchy::soften_scaled_brush_tip` (3x separable box blur; pads the stamp and shifts the anchor), via `CanvasWidget::scaled_brush_tip_for(size, softness)` cached by (size, feather). Feather = size x softness% / 400. A soft tip's center coverage can drop below 100% for thin tips, so soft erase leaving residue is correct.
- All brush/eraser strokes (procedural and bitmap-tip) share the per-stroke snapshot compositor (`install_brush_stroke_compositor` + `write_brush_stroke_pixel_from_snapshot`): overlapping dabs accumulate alpha toward the stroke's opacity cap and re-blend against a stroke-start snapshot, so soft overlaps (self-crossings, edge-to-edge stamps) never seam. Flow scales each dab before that accumulation; the default 100% Flow path stays byte-identical. Tips route through it via `EditOptions::stroke_pixel_writer`, honored in `paint_tip_dab` (`ui_brush_tip_soft_stamps_accumulate_without_seams` pins this). The layer-mask brush uses the older max-coverage cap at 100% Flow and the accumulation equation for reduced Flow or Airbrush buildup. Clone and local adjustment brushes keep the max-coverage cap (`capped_stroke_coverage`).
- Brush size maxes at **1024** via `kMaxBrushSize` everywhere (canvas, Alt+drag, options bar); Quick Select has its own 512px cap.
- `[`/`]`, Shift+`[`/`]`, and the pen-button size actions resize **proportionally**: `proportional_brush_step` (main_window_shared.cpp) grows 10% (Shift 30%) with a 1-px floor (2 px Shift); grow = `(1+f)`, shrink = `1/(1+f)`, so `]` then `[` round-trips. Do not revert to a fixed step (large brushes crawl). `ui_photoshop_shortcuts_are_registered` pins the steps (20->22/26, 100->110/130, 5->6); retune factors and test together.

## .abr parsing

`src/psd/abr_reader.*` (`read_abr`): supports v1/v2 and v6/v7/v10 (subversion 1 = 47-byte, 2 = 301-byte samp entry key skip), pairs `samp` bitmaps with the `desc` ActionDescriptor brush list **in order** for names/spacing, decodes per-row PackBits RLE, downconverts 16-bit, crops to content, caps dimensions at 4096, and skips bad entries with warnings, never failing the file. v6 8BIM tagged blocks are padded to 4-byte boundaries with the padding excluded from the length field; the block walk must skip that padding or the next signature read lands mid-pad (surfaces only when a desc length is not already 4-aligned). PSD and ABR share the descriptor parser and `decode_packbits` in `src/psd/psd_descriptor.*`.

## User library and built-in default tips

- The user library is `src/ui/brush_tip_library.*`: `<settings dir>/brushes/` (`%APPDATA%/RTsoft/Patchy/brushes/`) with one grayscale PNG (coverage mask) + one JSON sidecar (`{"name", "spacing", "folder"}`) per tip; ids are the UUID filename stems. Corrupt files skip that tip only. Tests pass a temp dir to the constructor. Tips carry an organizational **folder** (empty = ungrouped, sorted first); `import_abr` files everything into a folder named after the .abr; `remove_tips()` bulk-deletes with one `changed()`.
- **Built-in default tips** (`src/ui/default_brush_tips.*`): 40 parametric tips (16 natural-media, 20 v3 stamps, 4 v4 effect examples), all deterministic seeded noise/SDF math, no binary assets. Seeding into the "Patchy Defaults" folder is gated by the `brushes/defaultTipsVersion` int; each spec carries `since_version` and startup calls `restore_default_tips(stored_version)`, so a version bump seeds only newer tips and deleted older defaults stay deleted. Direction-control stamps author their art with bitmap +X = direction of travel. Tiling stamps (brick road, cobblestone, rope) are square/X-periodic with coverage touching the tile edges, because `add_tip` crops to content and dab advance = brush size x spacing (spacing 1.0 = exact butt joint). UI tests suppress seeding via `clear_brush_tip_test_state()`; `ui_default_brush_tips_seed_once_and_render_sheet` renders every tip.
- Deleted defaults are recoverable: `restore_default_tips()` re-adds missing ones by name within the defaults folder. The manager's "Restore Default Brushes" button pairs it with `reset_default_tips_to_factory()`, which snaps customized default-folder tips (spacing/tip shape/dynamics) back to the shipped spec and rewrites a mask PNG in place (same id) when its pixels differ from the generator output. Only the button does this; startup seeding never resets customizations or masks.

## Picker, manager, cursors

- The options-bar preset combo (`brushPresetCombo`) lists `builtin_brush_presets()` (Round, Hard Round, Square, Pencil, Ink, Airbrush; `src/ui/brush_presets.*`) ahead of the saved automation presets. Round is the soft preset, id `soft_round`; Hard Round (`hard_round`, 25 px) is the startup preset. The retired `round` id (the 25 px hard Round before issue 482) is an alias: `canonical_brush_preset_id` maps it to `hard_round`, so stored `tools/brushPreset` values, `getPreset("round")` and `presetId: "round"` land on Hard Round, and nothing lists it (`ui_brush_preset_list_leads_with_round_and_retired_round_id_resolves`). Every built-in preset selects its procedural tip: `BrushPreset::tip_id` is `builtin.square` for Square and empty (Round) for the rest, so picking any preset while a bitmap tip is active returns to a procedural tip. The bitmap "Square" in the Patchy Defaults folder is unrelated and stays (it is a sampled tip with soft scaled edges). Scripting: `brushes.getPreset("square")` reports `tipId: "builtin.square"`, `listTips()` lists both procedural tips first. `ui_square_brush_preset_paints_square_tip_and_round_presets_restore_round` pins all of it.
- `BrushTipPicker` (options-bar popup; Brush, Mixer, Pattern Stamp, Eraser; a fixed-width field with a chevron, the tip thumbnail and the elided name, full name in the tooltip: GitHub issue 364) and `request_brush_tip_manager` (`src/ui/brush_tip_manager_dialog.*`): QTreeWidget with expandable folder rows, Extended multi-selection, bulk delete (button or Del; a folder row means all its tips), folder line-edit for the selection, live engine-rendered stroke preview. "Define Brush Tip from Selection" (Edit > Define New Preset, hotkey id `edit.define_brush_tip`) captures inverted luminance x alpha x selection coverage (dark pixels paint, Photoshop semantics). The active tip is application-wide (re-applied in `apply_active_brush_settings_to_canvas`) and persists with the rest of the Brush and Eraser bars (`tools/brushTip`, [tool-options.md](tool-options.md)); the Round startup preset is the default for a missing key or a removed tip.
- Dialog spin boxes keeping their - / + buttons must append `dialog_spinbox_button_style()` (src/ui/dialog_utils) to the dialog stylesheet AFTER all children exist (see that header's gotcha note).
- Every Size/Soft footprint tool (`tool_uses_brush_footprint_cursor` in canvas_widget_shared, plus Quick Select via its own path) drops the pixmap cursor past the ~155px display cap and becomes a crosshair plus a canvas-overlay outline (`brush_outline_uses_overlay`/`draw_brush_hover_outline`) (also needed on wasm: browsers reject oversized bitmap cursors). Only tip-stamping tools (`tool_paints_with_brush_tip`: Brush, Mixer, Pattern Stamp, Eraser) trace the active tip's outline (`CanvasWidget::apply_brush_tip_cursor`, base shape only, no per-dab rotation/tilt); the retouch/toning tools always show the procedural circle, matching their procedural strokes. On stationary `[`/`]` resizes, `invalidate_brush_hover_outline(previous)` must erase old union new: `update_tool_cursor()` repaints only the new rect, so shrinking would strand the old rings. A `grab()` test repaints the whole widget and cannot catch this; manual-verify.
- Holding **Alt** over a paint/shape/fill tool (`tool_uses_alt_left_for_color_pick`) turns left-click into a colour pick; `update_tool_cursor` shows the eyedropper cursor, hotspot on the lower-left tip, checked before the brush/overlay branches. The `eventFilter` swaps the cursor the instant Alt toggles, driven by the event's folded modifiers via the transient `alt_color_pick_cursor_override_`, never `QApplication::keyboardModifiers()` (it lags and leaves the eyedropper stuck; Zoom/selection badges fold modifiers for the same reason). The glyph is one shared cached helper, `patchy::ui::eyedropper_cursor()` (ui/tool_cursors), also used by the Eyedropper tool and the colour picker's "Pick Screen Color" overlay so they never drift.
- The center + of every footprint cursor, the tip cursor, Quick Select's Replace cursor and the overlay outline is `paint_brush_center_cross` (canvas_widget_shared): filled whole-pixel bars, a light core in a dark outline, never an antialiased 1 px line, which smeared to half brightness and, drawn after the dashed softness ring, took its faint blue (GitHub issue 425). `ui_brush_cursor_center_cross_is_two_tone`.
- The Alt+right-drag Size/Soft readout is the canvas HUD pill (`paint_canvas_hud_pill`, shared with the drag size readout), centered below the disc and kept clear of the rulers and edges (GitHub issue 422). `ui_brush_adjust_readout_is_a_hud_pill`.
- The tip picker popup resizes via an embedded QSizeGrip (frameless Qt::Popup has no native resize border); size persists as `ui/brushTipPickerPopupSize`, saved in closeEvent (outside-click dismissal goes through close()). The grip is custom-painted (`VisibleSizeGrip`; the native one is nearly invisible on themed chrome).

## Painting tool modifiers

The footprint-cursor tools (`tool_has_ctrl_temporary_move`, the same set as `tool_uses_brush_footprint_cursor`: Brush, Mixer, Pattern Stamp, Eraser, Clone, Healing, Spot Healing, Smudge, Dodge, Burn, Sponge, Blur, Sharpen) share their modifiers (GitHub issues 380, 421, 423):

- **Ctrl** (Command on macOS) is the temporary Move, read from the press's own modifiers and checked before the tool's own press. The four-way arrow shows while it is held (`update_tool_cursor`, before the Alt eyedropper: Ctrl+Alt is not the Move), from the folded modifiers of the key or hover event (`retouch_cursor_modifier_override_`). The press (`begin_paint_temporary_move`) starts the Move drag of the selected layers with Auto-Select off (`begin_move_drag`) and records `paint_ctrl_click_`. A drag clears it and moves; a release that never dragged selects the topmost layer with a visible pixel under the pointer (`select_paint_layer_at`, the first pass of `topmost_move_layer_at`, position locks ignored because the layer is picked for painting) and paints nothing; empty space keeps the selection. With nothing movable the press waits: a drag reports the lock or "Click an editable layer to move", a click still selects. `ui_paint_tools_ctrl_click_selects_layer_ctrl_drag_moves`.
- **Alt+right-drag** sets size and softness; **Shift+click** joins the last stroke with a straight line.
- **Shift held** (alone, no stroke running, pointer over the canvas) previews that line: a light line on a dark halo from `last_stroke_end_document_` to the pointer (GitHub issue 445; `stroke_connect_preview_line`, canvas_widget_brush.cpp). Mouse moves and the folded Shift/Ctrl/Alt key events in `eventFilter` refresh it; leaving the canvas, hiding the tab, a press, a tool switch or a new document clear it. Repaints cover only the old and new line bounds. `ui_paint_shift_line_preview_follows_pointer`.
- Picking one of these tools shows a short status bar hint, `paint_tool_hint_source` (main_window_actions_tool_palette.cpp) with the tool name for `%1`: only what painting does not reveal (the tool's own Alt click, Shift+click line, Alt+right-drag), modifier names resolved per platform. It leaves out "drag to paint" and the Ctrl gestures so it fits a small screen (GitHub issue 421 follow-up). `ui_paint_tool_hints_name_shared_gestures`.

## Deliberate limitations

Layer-**mask** painting and Clone/Healing/Smudge/Dodge/Burn/Sponge/Blur/Sharpen stay procedural. The four effect families apply to Brush strokes only. Dual Brush imports one secondary tip's basic geometry, not its own scatter/dynamics stack or arbitrary blend mode. Brush Texture uses a generated substitute instead of imported pattern pixels, and its depth dynamics are static by design.

## Pattern Stamp

Pattern Stamp paints the selected Pattern Library tile through the common brush footprint. The options bar exposes Pattern, Manage, Aligned, Size, Opacity, Flow, Soft, and Tip; numeric fields use the shared chevron popup slider, not permanent sliders. Manage opens the existing Pattern Manager, so generated defaults, image imports, and imported `.pat` entries work without a second store. The pattern id and Aligned state persist as tool settings; pattern pixels stay in the library.

Aligned anchors the tile grid on the first stroke and keeps that document-space origin across later strokes; unaligned, every stroke centers the tile under the initial pointer. Shift-click stroke connection, number-key Opacity, Shift+number-key Flow, selection coverage, transparent-pixel locking, palette snapping, layer expansion, undo, and bitmap tips reuse the existing brush paths. Brush dynamics are deliberately disabled for Pattern Stamp: a selected bitmap tip is a static mask, and Round stays procedural.

The implementation is a direct modulo lookup into one immutable RGBA tile; the binding boundary (no destination inspection, no content-derived or input-driven texture assembly; US 9864922, US 10902645) lives in [legal-constraints.md](legal-constraints.md). Keep the constraint comment in `CanvasWidget::install_brush_stroke_compositor` in sync with that file.

Pattern Stamp is destructive raster painting matching Adobe's documented basic behavior; PSD/PSB contains only ordinary layer pixels (no private metadata, no live pattern dependency). `ui_pattern_stamp_alignment_palette_and_psd_round_trip` pins both alignment modes, palette snapping, and exact layered PSD reopen.

## Flow and Airbrush

The Brush options bar has separate Opacity and Flow plus an Airbrush toggle. Opacity is the most paint one stroke applies; Flow is the fraction metered by each spatial dab; Transfer Flow dynamics multiply that per-dab fraction before the Opacity-capped accumulator. Reduced-Flow Round strokes use the fixed dab-spacing path even with a hard edge, so output depends on document distance, not mouse-move event density. Shift+number keys set Flow; while Airbrush is on the assignment flips, Photoshop-style (bare numbers set Flow, Shift+numbers set Opacity). Both run 0..100 like Soft and Smooth (issue 253; Photoshop stops both at 1%, a deliberate difference: one minimum for every bar percentage; the Fill tool follows, [tools.md](tools.md)): 0% paints nothing. Opacity 0 turns every writer off in `install_brush_stroke_compositor` (`edit_options` floors the core alpha at 1/255); Flow 0 zeroes the accumulators; shape tools and Smudge return early; scripts accept 0.

Airbrush adds one copy of the current flat 2D stamp every 50 ms while the pointer is held, even stationary. Timer stamps advance Shape and Transfer dynamics (Fade included) but suppress Scattering and Count; pointer movement keeps full dynamics. The same Flow accumulator and Opacity ceiling apply to movement and timer dabs on both pixel and mask targets. The timer stops on release, focus loss, tool change, target change, or Airbrush off. The built-in Airbrush preset: fully soft 56 px Round tip, Round dynamics session reset, 100% Opacity, 12% Flow, timed buildup on. No airbrush-only duplicate defaults: Smoke, Spray, Spatter and Stipple cover those shapes. Flow and Airbrush use the same application-wide per-Brush/Eraser mirrors as Size/Opacity/Softness and persist with them ([tool-options.md](tool-options.md)).

Patent review (July 15, 2026): the classic flat-stamp behavior Adobe documents: Flow accumulates only to Opacity and a held stationary airbrush builds color. The binding boundary (no particles, 3D spray cone, stylus-pose projection, velocity-dependent deposition, bristle or fluid simulation, wet/dirty paint, or bidirectional transfer; US 8854342, US 9600907, US 10489937) lives in [legal-constraints.md](legal-constraints.md). Keep the matching constraint comment in `CanvasWidget::timerEvent` in sync with that file.

`ui_brush_flow_builds_only_to_opacity_cap_and_round_trips_psd` pins the Opacity ceiling and exact layered PSD reopen; `ui_airbrush_fast_strokes_ignore_mouse_event_density` pins the spatial cadence; `ui_brush_opacity_and_flow_accept_zero_and_paint_nothing` pins 0%.

## Brush Mode

The Brush bar's Mode (`brushModeCombo`, setting `tools/brushMode`, script `mode`; ids in `script_paint_mode_id`) offers every layer blend mode except Pass Through plus Behind and Clear, which are `PaintMode` kinds, not `BlendMode` values (`core/paint_mode.hpp`). `install_brush_stroke_compositor` picks the stroke's mode (Normal for every tool but Brush; masks and channels have their own path), and the snapshot writer applies it to the accumulated coverage against the stroke-start pixel, so dabs never compound a mode. Normal keeps the historical byte-exact path. Blend modes use `composite_blended_rgb(_deep)` and paint plainly over transparency; Dissolve uses `DissolveField::Paint`; Behind is destination-over; Clear removes alpha. Without an alpha channel or with Lock Transparent Pixels, Behind and Clear change nothing. Palette mode snaps the blended color. CMYK documents blend in their RGB pixels (cmyk.md). The Eraser has no Mode (Photoshop's Eraser Mode means its tip shape). These are generic compositing operators; nothing in legal-constraints.md touches them. Tests: `paint_mode_*` (core), `ui_brush_mode_*`, `ui_script_brush_mode_strokes_and_validation`.

## Local adjustment brushes

Dodge, Burn, Sponge, Blur, and Sharpen share one stroke-start snapshot engine in `canvas_widget_brush.cpp`. They use the procedural Size/Soft footprint plus a separate Strength cap. Dodge and Burn offer Shadows/Midtones/Highlights and Protect Tones; Sponge offers Saturate/Desaturate and Vibrance. Settings are application-wide and persist under stable `tools/local*` and `tools/sponge*` keys. The Detail flyout holds Smudge/Mixer Brush/Blur/Sharpen; the Toning flyout holds Dodge/Burn/Sponge.

The algorithms are fixed and user-directed: Blur is one alpha-aware 3x3 Gaussian; Sharpen subtracts that blur once from the center sample; Dodge and Burn apply a fixed luminance-range weight through channel screen/multiply or a tone-protecting equal channel offset; Sponge scales chroma around fixed Rec. 709 luma, optionally easing off already-saturated colors. Nothing ranks pixels, detects edges or regions, samples stroke-start color statistics, searches patches, deconvolves, or adapts the footprint to image content (the claim record is in [patent-research.md](patent-research.md); keep the constraint comment at `CanvasWidget::local_adjustment_brush_segment` in sync). The tools preserve the active layer's alpha and never expand its bounds; selections and palette snapping apply before the write, and layered PSD/PSB round-trips are exact (`ui_local_adjustment_brushes_use_fixed_math_and_round_trip_psd` pins the five algorithms and every output byte).
