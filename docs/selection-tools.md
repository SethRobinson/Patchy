## Behavior the selection tools share

**Drag inside to move the outline** (GitHub issue 436). With both marquees, all three lassos and the Magic Wand, a Replace-mode press inside the selection drags the outline, pixels untouched (`can_move_selection_at`, `apply_selection_move`, history "Move Selection", coalesced with nudges); hovering there shows the four-way cursor. Never while a Polygonal or Magnetic trace runs: its clicks place points. A press that never moves does the tool's own click on release: the marquees and the Lasso deselect, the Polygonal and Magnetic Lassos start a trace at the press point, the Wand selects from it. Test: `ui_lasso_tools_and_wand_drag_inside_moves_selection`. Each move only translates the press-time selection (`preview_selection_move`: the regions shift, the soft mask image is shared, cropped only where the canvas edge cuts it, and the ants loops move by `shift_selection_outline` instead of a retrace); release runs `apply_selection_move` once for the committed result. Never rebuild the display region from the mask or retrace per move: that made a big Lasso drag on a 3332 x 4998 image crawl (GitHub issue 603, `ui_selection_drag_of_large_lasso_is_fast`, which counts traces).

**Feather and Anti-alias are per tool and persisted.** `MainWindow` keeps one Feather and one Anti-alias per selection tool (`selection_feather_by_tool_`, `selection_antialias_by_tool_`, indexed by `selection_tool_index` like the combine modes). The canvas and the options-bar controls hold only the active tool's pair: `apply_selection_edge_settings_for_tool` swaps it in on every tool switch and after the startup settings load. The keys are `tools/<tool>Feather` and `tools/<tool>AntiAlias` with `<tool>` one of `marquee`, `ellipticalMarquee`, `lasso`, `polygonalLasso`, `magneticLasso`, `wand`, `objectSelect`, `contentAwareMove`, plus `tools/quickSelectFeather` (compatibility contract; table `kSelectionEdgeSettingKeys` in main_window_tool_options.cpp). The Patch tool has no such controls, so its outline always commits with no feather and anti-aliasing on. The UI suite removes these keys between tests (`cleanup_after_visual_test`). Tests: `ui_selection_feather_and_antialias_are_per_tool`, `ui_selection_edge_settings_persist_across_windows`.

- Every selection tool carries a status-bar activation hint (`tool_activation_hint_source`) that names its Shift / Alt combinations, not the drag, resize and move gestures the cursor already shows (GitHub issue 192, `ui_selection_tool_hints_name_modifier_combinations`). Each hint states only what that tool does: Quick Select and Object Selection have no Intersect.
- Every combine-mode cursor (marquees, lassos, Magic Wand, Quick Select, Object Selection, Patch, Content-Aware Move) is drawn by `apply_selection_cursor_for_mode`, which the canvas's Shift/Alt key filter calls with the event's folded modifiers, so the badge changes on the key itself with the pointer still (GitHub issue 289, `ui_selection_tools_alt_and_shift_swap_cursor_without_motion`). A tool missing from it keeps its old cursor until the pointer moves.
- Growing `kSelectionToolCount` (canvas_types.hpp) means updating BOTH brace-initializers (canvas_widget.hpp `selection_modes_per_tool_`, main_window.hpp `selection_modes_`), the `selection_antialias_by_tool_` initializer beside it, the tools array in `apply_selection_modes_to_canvas`, the `selection_tool_index` switch, and, for a tool with Feather controls, a `kSelectionEdgeSettingKeys` row.

## Quick Mask: temporary selection-alpha editing

Quick Mask is separate from Quick Select. `Select > Edit in Quick Mask Mode` (`select.quick_mask`, default `Q`) turns the active canvas's exact selection alpha into a temporary full-canvas `gray8` buffer. The buffer belongs to `CanvasWidget`, not `Document`, so it is never serialized and never marks the document modified. White is selected, black is protected, and gray is partial selection. With no selection the buffer starts black, producing a fully masked canvas.

- `Q` toggles once per press (GitHub issue 437; a Linux desktop with ibus delivered one tap as two triggers, the second about 40 ms after the canvas showed Quick Mask). The action has `autoRepeat(false)`, so a held key does not flicker. `ShortcutDoubleTriggerGuard` (main_window_actions_menus.cpp) drops a keyboard trigger that comes within 200 ms of the event loop being free again after the previous one (a slow toggle and repaint on a large image do not use up the window), or with no release of the key since the previous one (500 ms fallback for a release lost to another window). The menu and the toolbox button trigger the action directly and are never dropped (`ui_quick_mask_q_toggles_once_per_press`, `ui_quick_mask_q_ignores_a_doubled_press_after_a_slow_toggle`). `PATCHY_QUICK_MASK_TRACE=1` prints every Quick Mask change with its source and the key events of its shortcut on stderr (`src/ui/quick_mask_trace.hpp`).
- The display uses Photoshop's masked-area convention: `(255 - selection alpha) * 50%` red over the normal composite. The cached overlay image is patched only in dirty regions during a gesture. Marching ants are suppressed until Quick Mask exits.
- Brush, Eraser, Fill/Clear, Gradient, Line, Rectangle/Ellipse, and Invert share the grayscale mask renderers. Quick Mask bypasses the original selection clip, allowing white to add selection outside the entry boundary. Move, the selection tools, Crop, the stamp, healing, Smudge, Mixer, and toning/detail brushes, Text, the pen and path tools (`quick_mask_tool_is_unavailable` in canvas_widget_events.cpp), plus adjustments, filters, and transforms are disabled while active.
- Entering saves the canvas's foreground/background colors and installs black/white. Exiting restores the exact prior colors and rebuilds the hard or feathered selection from the current buffer.
- Each completed gesture pushes one selection-only history entry. `SelectionSnapshot` carries the temporary buffer through copy-on-write storage, so Undo/Redo works both while Quick Mask is active and after it exits without copying or dirtying the document.
- The Channels dock presents a temporary, fixed `Quick Mask` row after Composite/Red/Green/Blue. It is neither a `DocumentChannel` nor reorderable. Each document canvas keeps its own mode, mask, and saved colors across tab and floating-window activation.

Quick Mask does not call or modify the Quick Select classifier. In particular, it does not change Quick Select's solve-on-release boundary described below.

## Quick Select: solve-on-release is a patent constraint, not a UX choice

The Quick Select tool (`CanvasTool::QuickSelect`, Shift+W cycles to it from the Magic Wand, flyout shared with the Magic Wand) segments each brush stroke ONCE on mouse-release: the drag only accumulates a seed footprint (`stamp_quick_select_segment`) and draws a translucent capsule overlay, then `finish_quick_select_stroke` runs the cut and commits one undo entry. **Do not add live per-mouse-move classification or selection preview before Nov 3, 2029**: Adobe's US 8050498 ("Live coherent image selection", term-adjusted) claims classify-and-display while brush input is being received. Related design rules, all deliberate: Enhance Edge is purely geometric majority smoothing (US 8013870 claims local-color-model edge opacity until 2028), the solve uses ONE window per stroke (US 8121407 claims overlapping-tile decomposition until 2030), and there is no auto-switching between segmentation algorithms (US 10698588 claims toggling graph cut and level-set refinement from the Add/Remove mode plus whether the click lands inside the selection). The foundations used are expired: Boykov-Jolly seeded min-cut (US 6973212), GrabCut color models (US 7660463), MSR Paint Selection (US 8452087, fee-lapsed). `ui_quick_select_stroke_selects_object_and_is_undoable` asserts the no-mid-drag-selection behavior, so a live-preview change will fail it.

- The algorithm is Qt-free in `src/core/quick_select.hpp/.cpp`: RGB-histogram color models, a from-scratch Boykov-Kolmogorov max-flow on the 8-connected window grid (`detail::GridMaxflow`, validated against an Edmonds-Karp reference in `quick_select_maxflow_matches_reference_on_random_grids`), a seed-connectivity filter, hole filling of delta-enclosed regions (catchlights inside an eye; the flood must travel through ALL unchanged pixels or kept rings around a subtraction get eaten), and windows over ~600k px solved on a downsample.
- The energy was CALIBRATED AGAINST PHOTOSHOP 2026 by replaying identical clicks in both engines on `local-test-fixtures/photos/akiko-birthday.psd` (uncommitted) and scoring IoU; final agreement ~0.88-0.93 on object clicks (eye/tooth), ~0.6-0.8 on flat-area clicks where the residual is a 1-3px rim halo. PS's tool options descriptor (AM `currentToolOptions`: `quickSelectBrushSize`, `quickSelectSpread`, `quickSelectStickiness`, `autoEnhance`) confirmed the model. The load-bearing design decisions, each pinned by the probe data; do not "simplify" them away:
  1. posterior = SYMMETRIC epsilon over raw frequencies (per-model Laplace floors made every unseen color lean foreground and flood);
  2. background sampled from the solve WINDOW, not the whole image;
  3. `kBackgroundPrior` on unbrushed pixels (neutral pixels otherwise join the source side for free);
  4. a SPREAD BUDGET (`QuickSelectParams::spread`, PS-like, growth ~2.5x brush radius at 50) via a chamfer-distance ramp with a steep wall: a click on a featureless area returns roughly the brush disc, PS-verified;
  5. boundary-dominant smoothness (lambda 8) with a THRESHOLDED edge classifier (smoothstep between 2x and 6x the window's mean pair distance, 0.15 floor) instead of the GrabCut exponential: soft shading gradients and noise attract nothing, real contours are cheap, which is why a click inside an eye takes the whole eye opening (including dissimilar catchlights) like PS;
  6. the 3x3-blur denoise feeds ONLY the contrast term; blurring the data term smears hard boundaries and insets the cut ~2px (`quick_select_stroke_grabs_flat_region_and_respects_edges` catches it).
- The comparison harness (a COM+computer-use PS click driver) is not in the repo; to reproduce: fixed PS window, 100% zoom, magenta fiducial calibration, masks exported via fill-and-saveAs with history restore.
- Tune `lambda` / `kBackgroundPrior` / spread constants only with the `quick_select_*` core tests green; they encode the PS-calibrated behaviors (bounded taps, big-seed full coverage, budget-bounded subtract shave vs covering-stroke full removal).
- Alt+right-drag sets the Quick Select Size like the Brush's gesture, horizontally only (the tool has no softness), with a "Size: N px" readout; the options bar follows on release (GitHub issue 428, `ui_quick_select_alt_right_drag_sets_size`).
- Quick Select has no Intersect mode (Photoshop parity): Shift+Alt clamps to Add at press, and the Intersect options-bar button is simply not listed for the tool. A stroke in New mode auto-switches the tool to Add (`set_selection_mode(Add)` in `finish_quick_select_stroke`), and the MainWindow selection-mode callback writes canvas-driven changes back into `selection_modes_` so the mode survives tool/document switches.

## Transform Selection

Select > Transform Selection (`selectTransformSelectionAction`, hotkey id `select.transform_selection`, no default key; GitHub issue 323; also in the canvas menu's selection section) reshapes the selection outline, never pixels. `CanvasWidget::begin_transform_selection` opens a Free Transform session flagged `transform_selection_only_` with no layer and no targets: the box is the selection bounds (canvas-clipped), and drags, Edit > Transform modes, Ctrl distort gestures, the options-bar fields and session steps run as for layers ([free-transform.md](free-transform.md)); `prepare_free_transform_source` and `free_transform_accepts_non_affine` return true for it and every pixel preview path skips it (no base cache, no source image).

- Ants: the regular outline hides; `draw_transform_selection_outline` maps the outline traced at the start through `transform_session_delta()` to the widget (cost: the outline's vertices).
- Commit (`commit_transform_selection`): the coverage over the original box through `resample_transformed_gray8` with the session's interpolation, so feathered edges stay soft, then `set_selection_from_coverage` and one "Transform Selection" selection history entry. Unchanged, Esc, or a selection changed meanwhile (`transform_selection_source_is_current`) record nothing.
- Refused without a selection or in Quick Mask; the Select menu grays it without a selection. Ctrl+T during the session keeps it, Warp refuses it, a layer switch keeps it, a tool switch applies it.

Tests: `ui_transform_selection_scales_and_rotates_outline`, `ui_transform_selection_cancel_ants_and_soft_mask`, `ui_selection_context_menu_offers_transform_entries` (tests/ui/free_transform_selection_tests.cpp).

## Paste deselects

Every Edit > Paste branch (internal layers, raster, SVG shapes) calls `clear_selection()` right after its `push_undo_snapshot`, so the marquee that produced the copy does not stay live over the new layer (Photoshop parity) and Undo of the paste brings it back with no extra history entry. Pinned by `ui_paste_clears_selection_and_undo_restores_it`.

## Selection edits under a filter dialog

While a built-in or GEGL filter's settings dialog is open (`MainWindow::apply_filter`, `request_filter_settings`), the selection stays editable on that dialog's canvas (local-028). The dialog frame sets `MainWindow::PreviewSelectionSession` before taking the preview edit lock; the lock then keeps the canvas `edit_locked` but `CanvasWidget::set_selection_edits_allowed_while_locked` lets through left-button input of the Marquee, Elliptical Marquee, Lasso, Polygonal and Magnetic Lasso, Magic Wand, Quick Selection and Object Selection tools (not on rulers or guides), their Shift/Alt/Ctrl keys, arrow nudges, and the keys of a live polygonal or magnetic lasso. Their palette actions and Select All, Deselect, Reselect, Inverse, Grow, Similar, Expand, Contract, Border, Smooth, Feather and Load Layer Transparency stay enabled (`document_action_enabled_during_preview_lock`); everything else stays locked: other tools, filters, Undo, the History panel, Quick Mask, tabs, digits (layer opacity) and Escape (layer deselection). G'MIC, the Filter Gallery, Liquify, adjustments, Smart Filter dialogs and 8BF plug-ins keep the full lock.

- The canvas preview reads the selection when each render starts (`live_selection`); every `push_selection_history` on the active session restarts a 120 ms refresh that waits until no pointer gesture or lasso is live, re-reads `filter_selection`, and calls `FilterDialogSelectionLink::selection_changed`: the dialog rebuilds its bounded proxy for the new selection and emits the canvas preview again. OK reads the selection again, so it applies inside the selection as it is then.
- The layer shows preview pixels the document does not own, so `push_selection_history` records the session's pristine layer in the entry instead. Pixel-reading tools and commands (Magic Wand, Quick Selection, Magnetic and Object Selection presses; Grow, Similar, Load Layer Transparency) first put the unfiltered pixels back (`selection_sampling_callback`, `prepare_preview_selection_sampling`); the refresh brings the preview back afterward.
- Selection edits are ordinary undo steps before the filter's step; Cancel discards only the filter. The tool the user picked stays picked.

Tests: `ui_filter_dialog_selection_edits_follow_preview_and_apply`, `ui_filter_dialog_select_commands_preview_and_cancel_keeps_selection`.
