# Warp: warped smart objects, warp styles, the Warp Transform tool, and Warp Text

Deep reference for all warp machinery. Smart-object fundamentals (model, I/O, locks) live in docs/smart-objects.md; text-layer fundamentals live in docs/text-tool.md. Both warp consumers share `generate_style_warp_mesh` / `apply_warp_distortion` (core/warp_mesh): a change there affects smart-object warps AND Warp Text.

Related documents:

- [warp-text.md](warp-text.md): Warp Text on text layers (the `TextWarp` model, the warp box Photoshop checks on open, TySh I/O, rendering, the Warp Text dialog and its faux-bold guard, editing a warped layer, coverage).

## Warped smart objects

- **Parsing**: psd_descriptor models 'ObAr' (object array = u32 count + ordinary descriptor body of 'rationalPoint's) and 'UnFl' (unit-float array = unit OSType + u32 count + f64s) byte-identically, so warped SoLds parse. A SUPPORTED warp (customEnvelopeWarp meshPoints present, orders 2..4, count == u*v, zero perspective, no quiltWarp) imports with lock="" plus `patchy.smart_object.warp` metadata and re-renders through Patchy's mesh pipeline; unsupported warps keep lock="warp" and the preserved preview. Mesh points are CONTENT-space (E6: a move translates only Trnf/nonAffine, mesh doubles byte-identical, and `psd_warp_move_matches_photoshop_if_available` byte-pins Patchy's regenerate against PS's own moved file).
- **Warped placement quad = mesh hull, NOT the content rect** (e6 capture, pinned by `ui_warp_render_matches_photoshop_preview_if_available`): for a warped SO, Photoshop stores Trnf AND nonAffineTransform as the warp cage's doc-space bounding box (both identical, snapped to integers; e6: mesh hull [-13.62,53.62]x[-7.49,30] with warp bounds (0,0,40,30) <-> quad (66,78)-(133,115)). There is NO stored pre-warp rect. `build_warp_surface_grid` therefore maps the mesh CONTROL-POINT HULL onto the quad (never the warp bounds rect, which double-applies the cage expansion); warp bounds only anchor the source image in mesh space. Renderer: forward-evaluated lattice (`build_warp_surface_grid`, 4 px cells commit quality) + closed-form inverse bilinear per output pixel (`resample_warped_rgba8` in canvas_widget_transform.cpp, reusing the premultiplied samplers; first-writer-wins on folds). Free transform and Edit Contents need no warp-specific code: both re-render through `refresh_smart_object_layer_preview` (the warp-aware choke point), transforms move the hull quad while the content-space mesh rides along untouched (`ui_warped_smart_object_free_transform_rerenders`, `ui_warped_smart_object_edit_commit_keeps_warp` pin both flows).
- PS snaps a warped placement's stored quad to (round(hull_min), round(hull_min) + round(hull_extent)) per axis; Patchy does not replicate the snap (fixture quads are authoritative, Patchy-authored warps write the exact hull).

## Warp style mesh constructions

- **Preset warp styles** (E9/E9b COM captures, `local-test-fixtures/psd/ps2026_e9/`): COM-applied styles BAKE to `warpCustom` + mesh (warpValue reset to 0; bend 0 normalizes to warpNone), and `generate_style_warp_mesh` reproduces every baked control point (max observed delta 2.4e-6 px across 32 captures; `warp_style_meshes_match_photoshop_if_available` pins it at 1e-4). Constructions over content w x h with theta = |bend|/100 * pi/2, "arc row" = the classic cubic circle-arc approximation (radius R = chord/(2 sin theta), handle length (4/3)tan(theta/4)... expressed as (4/3)tan(theta/2)*R for half-angle theta, endpoint tangents rotated theta off the chord):
  - arc = top corners swing about the BOTTOM corners (radius = h), both edges arc with the same central angle 2*theta (negative bend = vertical mirror, rows swapped);
  - arch = both edges arc the same direction over their own chord w (columns translate rigidly);
  - bulge = arch with the bottom edge arcing the OPPOSITE way;
  - flag = pure y-displacement S-curve, handles -/+d with d = 2h*bend/100 (HEIGHT-based, e9b 60x20 disambiguation), both rows;
  - wave = 4x3 mesh, edge rows pinned FLAT, middle row S-curves +/-d about h/2 (opposite S direction to flag);
  - rise = rigid column ramp [d,d,0,0].
  - warpRotate == Vrtc is the identical construction over (h,w) with x/y swapped and the layout transposed (e9 vrtc capture).
- **All fifteen warp styles + distortion** (e9c/e9d COM captures in the same directory + `so_persp_*` in `ps2026_warptext/`): `generate_style_warp_mesh` also bakes:
  - arcLower/arcUpper (identity edge + arc row bulging away for +bend, into the box for -bend; upper = the lower construction mirrored);
  - fish (flag's S on the top edge, INVERTED S on the bottom);
  - fisheye (4x4; only the four interior points move, each along the line to its nearest corner by bend/50; at +50 they sit exactly on the corners);
  - inflate/squeeze (3x3 QUADRATIC patch; edge midpoints slide (w or h)*bend/200: inflate all outward, squeeze pinches the sides inward);
  - twist (4x4; tangential circulation of the interior ring by (w,h)*|bend|/100, direction = bend sign; orientation-invariant: Vrtc bakes IDENTICAL meshes, so the generator skips the transpose);
  - shellLower/Upper (two identity rows; the 2h/3 row's ENDPOINTS rotate theta about the anchor corners; the shell edge fans out via corner-swing + arc row for +bend or arcs into the box for -bend; upper = mirror).
  - Distortion (warpPerspective/warpPerspectiveOther = the Warp Text dialog's Horizontal/Vertical Distortion) is `apply_warp_distortion`: scale every mesh ROW about the midpoint of its two EDGE points by 1+(2v-1)*vertical%/100 FIRST, then every COLUMN by 1+(2u-1)*horizontal%/100 (order + edge-midpoint rule pinned to ~1e-7 by the so_persp captures; distortion folds INTO the mesh on SO bakes, which is why baked files read persp=0). `warp_style_meshes_match_photoshop_e9c_if_available` pins 58 captures at 1e-4.
- **Style-only SoLds** (style + value, no customEnvelopeWarp: the shape interactive PS writes) unlock for the six generatable styles: parse synthesizes the mesh into the warp metadata with `mesh_generated=true`, which renders through the normal pipeline but keeps the FILE style-only (regenerate never injects meshPoints or rewrites uOrder/vOrder for generated meshes), and size-changing refreshes re-derive the bake at the new bounds instead of scaling linearly (the arc trig is not linear). `psd_style_only_warp_unlocks_and_regenerates_if_available` pins the whole flow against a synthesized style-only fixture.

## Warp Transform tool

Edit > Transform > Warp (the last entry), `editWarpTransformAction`, hotkey id `edit.warp_transform`, no default binding; the Move tool's options bar carries the same entry as `moveWarpButton` (GitHub issue 225). A canvas mode parallel to free transform (`begin/finish/cancel_warp_transform` on CanvasWidget) with a 4x4 Bezier cage of 16 draggable handles, cage curves drawn from the control points (preview cells and resolution: Preview structure below; commit bakes at 4 px). The cage lives in CONTENT space and maps to the document through a fixed homography derived at begin time from the STORED mesh hull -> Trnf quad (identity/content rect for un-warped layers), so an existing warp round-trips exactly; the working mesh is the stored one elevated to 4x4 (elevation keeps the surface, so the hull for the mapping must come from the PRE-elevation mesh). Options bar: style combo + bend spin (Photoshop ja style names), preset baking through `generate_style_warp_mesh`, manual drags flip the combo to Custom. The combo lists all fifteen styles.

Commit: smart objects write warpCustom/value-0 metadata + hull quad + block_dirty and re-render through the callback (non-destructive, exactly what PS's own COM bakes produce); linked (external) smart objects warp the same way, their file decoded through `set_smart_object_source_image_callback` (the host resolves it against the document folder; a missing or unreadable file refuses the cage and names the file); plain pixel layers bake destructively with one undo snapshot; text layers refuse with a convert-or-rasterize message (pointing at Warp Text); a smart object in perspective (nonAffineTransform differing from Trnf, or a pending Distort/Perspective stage) refuses too, since Photoshop's warped placements keep the two quads equal ([free-transform.md](free-transform.md)); clicking off the cage does NOT commit (free transform matches): only Enter/Esc/the options-bar buttons/the right-click menu's Apply and Cancel ([canvas-context-menu.md](canvas-context-menu.md))/a tool or layer switch end either session, and Delete, Delete Layer or removing the session's layer cancels it ([tools-transform-modifiers.md](tools-transform-modifiers.md)). Pinned by `ui_warp_transform_bends_pixel_layer_and_undoes`, `ui_warp_transform_on_smart_object_writes_mesh_and_survives_resave`, and `ui_warp_transform_refuses_text_layer`.

Preview structure (view resolution, GitHub #200: the full-resolution per-move render cost about 3.9 s a frame on a 6000x4000 layer): `prepare_warp_source` converts the source to RGBA8888 once and `ensure_warp_base_cache` builds `warp_base_cache_`, the document with the layer hidden via render overrides, banded, composited from the preview-scaled document at zoom <= 50% (`warp_base_cache_scale_level_`). `refresh_warp_preview_cache` renders `warp_preview_patches_` at the zoom's composite level (`preview_composite_level_for_zoom`): the source comes from `warp_source_for_level` (box-halved mips, built once per session), the grid is built over the quad scaled by 2^-level, and the patch composites from the preview-scaled document; the patch images ARE the mip of their full-res `document_rect` and paint draws them directly (`warp_preview_patches_scale_level_`). Only the document area on screen renders (`warp_preview_view_rect`; `resample_warped_rgba8`'s `clip`, widened by the layer effects' reach so shadows from off-screen pixels still land), recorded in `warp_preview_covered_rect_`. Drag frames use the bare view, bilinear samples (nearest stays nearest) and 16 px cells, and below 100% device zoom render at least at level 1 even where the display level is 0 (GitHub #298: between 50% and 100%, a fit photo on a HiDPI screen, a frame rendered the whole on-screen layer at full resolution). A drag move only moves the mesh and sets `warp_drag_preview_pending_`; `paintEvent` renders the latest mesh once per painted frame, so moves that arrive faster than a render (Wayland's uncompressed motion, high-rate mice) never queue renders, and the options bar refreshes during a drag only when the style flips to Custom. Never render the preview per mouse move. The resting frame (release, presets, `set_warp_handle_document_position` outside a drag) uses the session interpolation and the commit's 4 px / 128-cell grid over the view plus half a view per side, so at 100% it is the commit's own pixels. `notify_view_changed` schedules `refresh_warp_preview_for_view` (0 ms timer, coalesced): it re-renders when the composite level changed or the view left the covered rect, and rebuilds a base coarser than the new level. `resample_warped_rgba8` splits output rows across workers; each worker walks every cell in row-major order inside its band, so folds resolve first-writer-wins exactly as the sequential walk (byte-identical, pinned by `ui_warp_resample_parallel_and_clipped_match_sequential`). Never recomposite the whole document or resample the whole layer per handle move. The release renders the resting frame at once. The samplers read the source through `SampleSource` (pointer, stride and size taken once per resample instead of QImage calls per tap; same arithmetic, so commits are byte-identical). `RenderCacheDiagnostics::warp_scaled_previews` / `warp_preview_last_pixels` / `warp_preview_renders`, `ui_warp_drag_preview_renders_at_view_resolution` and `ui_warp_drag_renders_once_per_frame` pin the bounds and the one-render-per-frame rule; `patchy_perf_tests warpdrag` times a 6000x4000 drag at fit and 100%, and `warpphoto` the reporter's 2560x1440 JPEG (`local-test-fixtures/issue-298/sample-1mb.jpg`, from samplelib.com; [SKIP] when absent) at fit in two window sizes, at 66%, and entered from Free Transform, including a burst of 30 queued moves and a digest of the committed layer. On a 16-thread laptop such a burst renders in 17 to 45 ms. The commit path (`bake_warp_into_layer`) resamples the full-res source at 4 px cells through the same parallel resample, with a bounded `document_changed`.

Far drags (GitHub issue 299): `resample_warped_rgba8` walks, per output row, only the span of each cell's corners' convex hull (`convex_cell_span_on_row`, a pixel of slack each side, so output is unchanged), not the cell's bounding box: a handle dragged far stretches cells into slivers whose boxes covered most of the output. `TransformedImage::cell_pixel_tests` counts the walk and `warp_preview_last_cell_tests` exposes it per preview. A cage entered from a Distort/Perspective stage maps through a homography with a horizon; a handle dragged past it put the surface on both sides, the lattice ran to infinity (screen-wide streaks, every frame crawling). `set_warp_handle_document_position` therefore takes a position only when `warp_mesh_placement_is_sane`: the hull box keeps the map's denominator on the visible side (it is linear, so the box corners settle it) and its document quad stays within the canvas grown by twice its larger side (at least 4096 px), unless the move is no worse than the current mesh; otherwise the handle keeps its last good position. Pinned by `ui_warp_far_dragged_interior_point_resamples_in_bounded_work`, `ui_warp_far_drag_preview_work_stays_bounded` and `ui_warp_after_perspective_handle_stops_at_the_horizon`.

## Free transform <-> warp are ONE session

Photoshop's options-bar warp toggle (`transformWarpModeButton`, the last of the session bar's type buttons since GitHub issue 299): `begin_warp_transform` during a free transform composes the pending affine into the cage's content->document homography (`compose_affine_over_homography`, flagged by `warp_entry_changed_`) instead of cancelling it, and `switch_warp_to_free_transform` stashes the mesh (`pending_warp_*` + `transform_has_pending_warp_`), bakes a 4 px preview as the affine stage's source, and lets free transform edit the hull box (toggling back resumes the cage via `resume_pending_warp_session`). Commit from either mode (shared apply button, Enter, tool switch) bakes ONE resample of the ORIGINAL source through mesh + composed map in ONE undo step (`bake_warp_into_layer`, shared with the plain warp commit); smart objects write the mesh + the composed hull quad. Esc anywhere cancels everything. Refusal guards (text layer, preview-locked/undecodable SO) run BEFORE the free-transform teardown, so a refused toggle keeps the pending transform alive. Known simplification: toggling warp->FT shows the AXIS-ALIGNED hull box (a stage-1 rotation is folded into the map, not re-offered for editing). Pinned by `ui_free_transform_warp_toggle_composes_single_commit`, `ui_warp_toggle_back_to_free_transform_keeps_pending_warp`, `ui_smart_object_transform_then_warp_commits_composed_placement`, and `ui_warp_toggle_refuses_text_layer_and_keeps_transform`.

## E11 acceptance (warp round-trip through Photoshop)

Photoshop 2026 opened both Patchy-authored warp artifacts (a from-scratch warp-tool bake and a PS-authored e6 mesh transformed through Patchy) and resaved them cleanly. The from-scratch 4x4 mesh and its float hull quad came back VALUE-IDENTICAL (PS applies no snapping to foreign float quads); the 4x2 mesh came back elevated to 4x4 by the standard exact Bezier degree elevation, matching `elevate_warp_mesh_to_cubic` output digit-for-digit, so PS normalizes stored meshes to 4x4 on resave and Patchy re-parses that as a supported warp.
