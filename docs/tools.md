# Paste placement, shape and Fill tools, Free Transform modifiers, the Background lock, Merge Down, and the canvas menu

Small tool/command behaviors. See [selection-tools.md](selection-tools.md), [brushes.md](brushes.md), [text-tool.md](text-tool.md), [vector-tools.md](vector-tools.md), and [crop-tool.md](crop-tool.md) for those features; deep (16/32-bit) layer support for these tools is in [high-bit-depth.md](high-bit-depth.md). The legacy Pixels-mode raster behavior here must stay byte-identical.

## Clipboard pixel placement

- File > Open from Clipboard: [behavior, platforms, and legal review](clipboard.md).
- Edit > Paste (`edit.paste`, Ctrl+V) places pixels by the first rule that applies (Photoshop 2026 over COM, `scripts\dev\artboards\ps-artboard-audit.jsx`, plus one Patchy rule): an active selection centers the paste on its bounds, on the artboard under its center or at the root, so the marquee a Copy or Cut leaves behind puts the pixels back; on an artboard (the selected layer's, or the selected artboard) it centers on that artboard ([artboards.md](artboards.md), "Feature interactions"); pixels copied from this document (`ClipboardPayload::source_session_id`) go back to their place while its center is in view (GitHub issue 193; Photoshop centers them); everything else (external images, other documents, a place scrolled out of view) centers on the viewport at the current pan and zoom. Each axis is clamped so the pasted rectangle fits inside the document.
- Edit > Paste in Place (`edit.paste_in_place`, Ctrl+Shift+V) ignores the selection and uses the pixels' original document coordinates, including across documents, with the same bounds clamp; onto another artboard it keeps their place on the artboard. External images have no source coordinates and use the viewport center.
- Pasting preserves pixel dimensions and content. If the pixels exceed the canvas on an axis, that axis is centered with overflow instead of being resized or cropped. Both commands clear the selection in the paste history entry ([selection-tools.md](selection-tools.md), "Paste deselects"); Undo restores it and Redo restores placement.
- Both commands insert directly above the topmost selected layer, preserving the copied stack's order. A selected child keeps the paste in its folder; a selected folder places it above that folder. With no selected rows, paste appends at the document top. This applies to pixels, whole layer trees, and SVG; the topmost pasted layer becomes active and selected (`ui_paste_inserts_above_topmost_selected_layer`, `ui_paste_above_selected_folder_or_at_top_without_selection`).
- Pixel placement lives in `MainWindow::paste_clipboard` (`main_window_layer_ops.cpp`); whole layer trees and SVG use their own preserving clone/import paths, and Palette or color-picker focus keeps its color paste routing. The `paste` UI filter covers viewport placement, all four edges, cross-document coordinates, oversized pixels, the shortcut, document/channel guards, external clipboard replacement, and undo/redo.

## Crop tool

## Shape tools (Rectangle/Ellipse/Line)

- Rectangle/ellipse honor brush Opacity/Soft through the signed-distance renderer in pixel_tools.cpp.
- Options-bar Style/Width/Height are deliberately session-only (mirrored via `current_shape_*`, never persisted). The row is registered pixel-only: the vector modes hide it and show the active shape's W / H instead ([vector-tools.md](vector-tools.md)). With Style Normal the Width/Height spins are greyed out (the marquee's twin row greys the same way); Fixed Ratio and Fixed Size enable them.
- A Pixels-mode click keeps the legacy 1 px commit (its `begin_edit` snapshot is pushed at press); the vector modes open the Create dialog instead. Coverage: `ui_shape_tap_*`, `ui_shape_style_row_is_pixel_only_and_greys_size_at_normal`.
- Alt draws from the center, so Rectangle/Ellipse are exempt from the Alt temporary eyedropper.
- Mode is always the first options-bar item for the shape tools (built before the shared brush controls), so switching to Pixels never shifts it. Coverage: `ui_options_bar_mode_combo_stays_first_for_shape_tools`.
- ALL constraint math lives in `CanvasWidget::shape_drag_rect()`. It intentionally duplicates `marquee_selection_rect()` (selection-only concerns, separately pinned). Do not merge them.
- The Fill command and Fill tool share their OWN persisted Opacity/Soft (see the Fill tool section); tests laying down setup color call `use_solid_fill_settings(canvas)`.
- Coverage: `ui_shape_fill_and_corner_radius_apply_to_new_documents` also pins the `current_*` mirror pattern from [ui-conventions.md](ui-conventions.md).

## Fill tool (Paint Bucket) and the Fill command

The Fill tool click (Shift+G from the Gradient tool, `CanvasWidget::flood_fill` over core `patchy::flood_fill`) floods from the clicked pixel; the Fill command (Alt+Backspace, `fill_rect`) paints the whole selection or layer and never reads existing colors. The Fill tool's options-bar row holds Opacity, Soft, Tol, and Contiguous, persisted as `tools/fillOpacity` / `fillSoftness` / `fillTolerance` / `fillContiguous` (defaults 100 / 0 / 32 / on), mirrored through `current_fill_*`, and turned into `EditOptions` in one place, `apply_fill_settings` (canvas_widget_shared.cpp), which both paths call. Tol and Contiguous only matter to the flood.

- **Tolerance** (0..255) is the Magic Wand's metric through core `color_within_tolerance` (sum of squared per-channel differences within 4 x tolerance^2), so Fill Tol N accepts exactly the pixels Wand Tol N selects (GitHub issue 30). 0 is an exact match. The wand engines in canvas_widget_selection.cpp inline the same formula; `tool_fill_bucket_tolerance_metric_matches_magic_wand` pins the numbers. **Contiguous** off fills every matching pixel of the layer, still clipped by the selection.
- **Membership is decided against the clicked color, never against written pixels:** a first pass builds a region mask (4-connected stack flood, or a full scan when Contiguous is off), otherwise a translucent fill at a wide tolerance spreads through its own output forever. Under the transparency lock, alpha-0 pixels are outside the region.
- **Opacity** runs 0..100 like the Brush bar's Opacity and Flow (issue 253; Photoshop's Paint Bucket stops at 1%, a deliberate difference so every options-bar percentage shares one minimum): at 0% `flood_fill` and the Fill command return before touching the layer or the history, because the core floors a written alpha at 1/255. Mask and channel fills ignore Opacity at every value. `ui_fill_opacity_accepts_zero_and_fills_nothing` pins it. Opacity **blends** through `write_pixel` (palette mode snaps there like every tool) instead of stamping a reduced alpha; **Soft** feathers inward from the region's edge with the Fill command's chamfer transform (`compute_fill_feather`, up to 50 px). Tolerance 0 at 100% opacity must stay byte-identical to the verbatim copy path pinned by the `flood_fill_background` digest in `tool_write_paths_digest_baseline`.
- Mask and channel floods (`flood_fill_mask`) apply Tol and Contiguous over the one gray channel and write the mask value verbatim. Anti-alias is deliberately not offered.
- Both paths test the selection per pixel through `selection_alpha_at`, which rasterizes a many-span hard selection once (GitHub issue 34; see the lookup section of [selection-tools.md](selection-tools.md)).
- Coverage: core `tool_fill_bucket_*`; UI `ui_fill_tool_tolerance_and_contiguous_persist_across_documents`, `ui_fill_tool_click_honors_tolerance_contiguous_and_opacity`, and `ui_fill_of_wand_selection_with_many_spans_is_fast` (both fills on a 1110 x 1388 wand selection).

## Free Transform modifiers

Session steps and undo inside a pending transform: [free-transform.md](free-transform.md).

Corner handles scale proportionally on their own and Shift releases the lock, matching Photoshop CC 2019 and later. The preference `input/shiftKeepsTransformAspect` (default `false`, Preferences > Tools, `preferencesTransformShiftAspectCheck`) restores the older pairing, where a plain corner drag distorts and Shift holds the ratio. It is a persisted identifier and rides the pen-input load/save/apply trio in main_window_preferences.cpp, so `configure_canvas` and the Preferences accept loop both push it onto every canvas. The session start status line reports the active pairing (both sentences are translated).

- Both sessions decide through one predicate, `CanvasWidget::transform_drag_keeps_aspect(modifiers)` (canvas_widget_transform.cpp): `shift == shift_keeps_transform_aspect_`. The pixel session calls it from `update_free_transform_preview`, the path session from `handle_path_transform_move` (canvas_widget_vector_tools.cpp). The shared predicate keeps their modifier semantics from drifting apart: never reintroduce an inline `Qt::ShiftModifier` test for a resize. Only corners consult it; edge handles scale one axis in every mode. Shift on the rotate handle snaps to 15 degrees in both sessions (a separate modifier test in the same functions). Shift on the shape and marquee tools is an unrelated 1:1 shape constraint.
- Aspect-locked corner drags in both sessions share one rule: the shared scale is the pointer's distance from the anchor projected onto the box diagonal, per axis in absolute value (`(|dx| w + |dy| h) / (w^2 + h^2)`), and each axis keeps its own sign from the side of the anchor the pointer is on. Travel along the diagonal scales at one rate in every direction, a pull leaning against the diagonal shrinks, and a straight pull across the anchor mirrors that axis alone (`ui_point_text_flip_transform_mirrors_and_survives_reedit`). Do not go back to following whichever axis the pointer pulled harder: that scales the short side `aspect` times faster and jumps in rate when the winning axis switches. The pixel session writes the corner from the anchor; the path session converts the per-axis scales back into its local delta.
- While a Free Transform, Warp, or path transform session is pending, the Shape Appearance, Layer Style, and adjustment-layer dialogs refuse to open (`refuse_layer_dialog_during_transform`, a status hint to press Enter or Esc first; `ui_layer_dialogs_refuse_during_transform`).
- The options-bar link button (`freeTransformLinkScaleButton`) mirrors the W% and H% spin boxes only, never handle drags. The X/Y/W/H/Angle fields are `UnitSpinBox`es ([ui-conventions.md](ui-conventions.md), [resolution-units.md](resolution-units.md)): X/Y native px with percent relative to the document extent, W/H native percent with pixels relative to `TransformControlsState::original_size`, Angle degrees only. Typing a unit (or right-clicking the field) switches the display; the linked W/H pair switches together. The interpolation combo (Nearest Neighbor, Bilinear, Bicubic default, Bicubic Smoother, Bicubic Sharper, Automatic; `tools/transformInterpolation`, append-only) and its kernels are in [resampling.md](resampling.md).
- A text layer's session rect is its whole raster (`move_layer_transform_local_rect`: a box layer's frame, a point layer's line box), the same rect the passive Move-tool controls draw, like Photoshop's paragraph-text box. Other layers use the opaque pixel rect. The two must agree because a handle drag sets the rect corner to the absolute mouse position; a session on the smaller ink rect stretches the ink to the frame on the first move (`ui_box_text_transform_handle_grab_keeps_ink_size`).
- The rotate handle turns the box about the reference point (the options-bar Pivot combo, `transform_reference_point_`; `set_transform_reference_point` repaints the session box so the marker moves at once): `update_free_transform_preview` measures the drag angle from `transform_reference_position(start rect, start angle)` and moves the center to `pivot + R(delta)(C0 - pivot)`. With `a` the anchor offset, `C0 - pivot = -R(start)a`, so `C1 + R(new)a` is the pivot again and the reference position is invariant. Numeric edits pivot there too (`set_transform_controls_state`). `draw_free_transform` draws the reference marker (circle plus crosshair) during a session only; the passive Move box stays a plain frame, as in Photoshop.
- Scale handles compute in the box's own frame: the snapped pointer is unrotated about the drag-start center, the edge/corner setters and the Shift aspect block run on an axis-aligned local rect, the flip signs read the raw local rect, and the center rotates back out. At angle 0 this is exactly the world-space math, so unrotated drags stay byte-identical. Hit zones and the grab offset: [move-tool.md](move-tool.md).
- Alt on a scale handle scales about the reference point (`transform_drag_scales_about_reference`, the Shift predicate's sibling): per moving axis the factor is `(pointer - r) / (handle - r)` in local coordinates and the center lands at `r(1 - f)`; a reference sitting on the dragged edge keeps the plain result for that axis; corners under the aspect lock share one magnitude by the same projection (per-axis factors weighted by the squared reference-to-handle spans), each axis keeping its sign. Shift or Alt pressed or released mid-drag replays the preview at the last pointer position, and the modifier cursor filter skips `dragging_transform_`.
- Drag readout (`view/showTransformValues`, default on, Preferences > Application `preferencesShowTransformValuesCheck`, pushed to every canvas with the Shift-aspect pairing): `transform_drag_readout()` lists the reference point's X/Y plus the offset while moving (the Move tool uses the moving set's opaque union, `move_readout_base_rect_`), W x H plus the signed percentages while scaling, and the angle plus its delta while rotating. `draw_transform_drag_readout` paints only the change line (`canvas_lines`, no label) below-right of the pointer in the canvas HUD theme roles; the status bar mirrors both lines (`lines`). Its panel rect joins the bounded drag repaints (`update_drag_readout_region`, [interactive-previews.md](interactive-previews.md)); release and cancel clear it. Text comes from `format_pixels`/`format_percent`/`format_degrees` in measurement_units.hpp. Guide drags show the guide's position under the same preference ([guides.md](guides.md)).
- **Pixel-grid snapping** (PS 27.9 COM captures): Photoshop lands every axis-aligned transform on whole pixels by rounding each destination EDGE with halves up (`snap_to_pixel_grid` in core/pixel_grid.hpp: floor(x + 0.5), so 3.5 -> 4 and -3.5 -> -3): a typed X of 3.4 moves the layer by 3 with crisp pixels, 152.5% of 20 px (edges 4.75..35.25) comes out 5..35, and an odd-sized layer under the Center pivot legitimately reads X .50. Photoshop does this for pixel layers with its "Snap Vector Tools and Transforms to Pixel Grid" preference on OR off (`toolsPreferences.transformsSnapToPixels`, settable through Action Manager `setd` on the application); that preference only decides whether a smart object's placement quad is rounded too (off keeps 13.4 in the quad while the raster still lands on 13). Patchy: `set_transform_controls_state` snaps `transform_current_rect_` (`snap_transform_rect_to_pixel_grid`) whenever `input/snapTransformsToPixelGrid` (Preferences > Tools "Snap transforms to the pixel grid", default on, pushed with the other input prefs) is on and the session is not rotated (`|angle| <= 0.01`; a rotated box cannot sit on the grid, and both stress-test numeric transforms are rotated, which keeps `tool_write_paths_digest_baseline` untouched). Snapping in the setter makes preview, options-bar readback and all three commit paths agree, and integer inputs snap to themselves so pinned commit bytes never move. Handle drags already snap the pointer (`snapped_document_point_f`); an aspect-locked drag can still leave a fractional edge and is not snapped here. Off restores the sub-pixel resample (floor origin, one extra column). A whole-pixel move through the default Bicubic (Catmull-Rom, interpolating) is byte-identical, so there is no separate fast path; an entry that snaps back to the start commits as a no-op. The script API's `moveTo`/`x`/`y` round with the same helper (`ui_script_layer_move_to_rounds_like_photoshop`); type layers round their anchor the same way ([text-render-calibration.md](text-render-calibration.md)). Coverage: `ui_transform_numeric_fraction_snaps_to_pixel_grid`, `ui_transform_numeric_odd_layer_keeps_half_pixel_reference`, `ui_transform_snap_preference_off_keeps_fraction`, `ui_transform_snap_skips_rotated_sessions`, `ui_transform_integer_move_is_lossless_through_bicubic`, `ui_transform_snap_preference_persists_and_reaches_canvas`.
- **Move-tool double-click never starts Free Transform; during a session a double-click inside the box applies it** (Seth's decision, GitHub issue 225, like Photoshop and Enter; details in [free-transform.md](free-transform.md)). Off the box, `mouseDoubleClickEvent` hands the event to `QWidget::mouseDoubleClickEvent`, which replays it as a second press, so it never reaches the text-editor or shape-appearance branches. A double-click inside the box of a transforming text layer runs first: it finishes the transform and opens the text editor. A motionless press inside the box must not nudge it: `update_free_transform_preview` rounds the Move drag START to whole pixels like the snapped end (else a half-pixel pan at 100% shifts the box by 1 px), and `free_transform_snap_exclude_ids` keeps the session's own layers (whose pixels stay put until commit) out of the snap targets (`ui_move_double_click_commits_free_transform_inside_box`).
- Coverage: `ui_transform_shift_frees_aspect_ratio_by_default`, `ui_transform_proportional_corner_follows_diagonal_projection`, `ui_transform_shift_aspect_preference_restores_legacy`, `ui_transform_shift_aspect_preference_defaults_to_off`, `ui_transform_shift_aspect_preference_persists_and_reaches_canvas`, `ui_transform_fields_accept_unit_tokens`, `ui_transform_rotate_drag_pivots_on_reference_point`, `ui_transform_alt_drag_scales_about_reference_point`, `ui_transform_handle_drag_on_rotated_box_uses_local_axes`, `ui_transform_drag_readout_shows_values`, `ui_move_drag_readout_reports_reference_and_delta`, `ui_transform_readout_preference_hides_hud`, plus the `unit_spin_box` group. The path session keeps its own center pivot and has no modifier test yet.

## Image and layer rotation and flips

Image > Rotate Right / Left / 180 and Flip Horizontal / Vertical act on the whole document (`rotate_document_*`, `flip_document_*` in core/document_geometry.cpp: every layer's pixels, bounds and mask, the channels, text transforms, smart-object placements, vector data). Layer > Arrange > Rotate Layer Right / Left / 180 turn the selected pixel layers about their own centers (`rotate_layer_*(Document&, LayerId)`: a quarter turn about the canvas plus the translation that restores the center, rounded to whole pixels), with the flip handler's guards (no smart objects, pixel locks, channel targets). Hotkey ids `image.rotate_180`, `image.flip_horizontal`, `image.flip_vertical`, `layer.rotate_cw`, `layer.rotate_ccw`, `layer.rotate_180` (GitHub issue 139). Tests: `document_flips_and_half_turn_mirror_every_layer_and_channel`, `layer_quarter_turns_keep_the_layer_center`, `ui_image_flip_and_layer_rotate_menu_actions_apply`.

## Eyedropper

A click sets the foreground color; with the Eyedropper tool active, Alt+click sets the background color instead (Photoshop's convention, GitHub issue 150; `color_pick_to_background_`, reported through `set_background_color_picked_callback`). The paint tools' temporary Alt eyedropper (`tool_uses_alt_left_for_color_pick`) always sets the foreground. Test: `ui_eyedropper_alt_click_picks_the_background_color`.

Options (GitHub issue 151; the tool is labeled "Pick"): Sample Size (`eyedropperSampleSizeCombo`: Point Sample, 3/5/11/31/51/101 by N Average; `tools/eyedropperSampleSize`, odd sides 1 to 101) and Sample (`eyedropperSampleLayersCombo`: All Layers or Current Layer; `tools/eyedropperSampleAllLayers`, default All Layers). `current_eyedropper_*` mirrors in MainWindow, applied to every canvas; the paint tools' Alt eyedropper uses them too, as in Photoshop. An average is alpha-weighted over the square clipped to the document: All Layers reads the displayed composite (`compose_document_rect`, a fully transparent square gives black like a point pick), Current Layer reads the active pixel layer through `active_layer_sample_region` (mask and opacity in alpha); a transparent spot there leaves the color unchanged, and a non-pixel active layer warns once per gesture. Sets (`eyedropperSetsForegroundButton` / `eyedropperSetsBackgroundButton`, an exclusive pair; `tools/eyedropperPicksBackground`, default Foreground) names the color a click sets, and Alt inverts it for that click (`eyedropper_target_is_background`, the Zoom tool's mode-XOR-Alt rule), so the default keeps Photoshop's Alt+click background pick. The Eyedropper cursor carries a swatch badge for that target (`eyedropper_target_cursor`), refreshed when Alt toggles; the paint tools' Alt eyedropper ignores Sets. Tests: `ui_eyedropper_sample_size_and_current_layer`, `ui_eyedropper_sets_option_and_alt_inverts`, `ui_eyedropper_options_bar_sample_controls`.

## Arrow-key nudging

Canvas arrow nudges ignore `Qt::KeypadModifier` before checking for plain or
Shift input. Physical macOS arrow keys can carry that flag while remote input
may omit it; both move by 1 px, or 10 px with Shift. Ctrl, Alt and Meta still block
ordinary nudges. This applies to layers, pending Free Transform and Crop boxes,
and selection outlines (`ui_layer_and_free_transform_nudges_accept_keypad_modifier`,
`ui_crop_handles_resize_move_and_nudge`, `ui_selection_arrow_keys_nudge`).

Layer nudges refresh the Move hover outline at the stationary pointer after the
document update. The outline follows the new bounds, disappears if the layer
moves away from the pointer, and returns when it moves back beneath it. A pointer
outside the canvas widget does not regain a hover outline. The refresh uses the
existing old/new outline repaint regions, including the pasteboard
(`ui_move_nudge_refreshes_stationary_hover_outline`).

## Background lock, Eraser and Clear under a transparency lock
- File > New (`MainWindow::reset_document`) and Image > Flatten Image ([layer-merging.md](layer-merging.md)) give an opaque Background (RGB, no alpha) both lock position and lock transparent pixels, as Photoshop does. A transparent Background stays unlocked (a transparency lock would make it unpaintable). Opened flat files and `app.newDocument` keep unlocked layers, so scripts and photo erasing still make transparency (GitHub issue 97).
- With transparency locked, the Eraser and Clear (Delete, Cut) paint the background color and keep each pixel's alpha, in the stroke compositor (`render_brush_stroke_pixel_from_snapshot_target`, `render_brush_stroke_pixel_deep`) and in core (`write_pixel_blend*`, `clear_pixel_would_change`, `clear_rect`). Alpha-0 pixels stay empty, and a locked alpha-less layer never gains alpha (`ensure_alpha_for_erase` is skipped). Unlocked layers without alpha still gain alpha and erase to transparency.
- The lock has no effect on what an alpha-less layer can become, so it never blocks a raster merge into one (`layer_merge.cpp`); merges into the Background behave as with the position lock alone. Pinned by `tool_eraser_and_clear_paint_background_color_under_transparency_lock` and `ui_eraser_on_background_paints_background_color_and_size_cursor`.

## Merge Down
- `MainWindow::merge_down` normalizes the selection, includes a single leaf's lower sibling, and routes selections containing vectors through the preserving planner and Merge Layers dialog. Compatible shapes merge immediately. The dialog offers separate vector/bitmap outputs, merges within each group, and separate vector paint categories. [layer-merging.md](layer-merging.md) owns the options, preservation boundaries, transaction, and scripting contracts.
- Bitmap-only selections retain the existing CPU-composited flattening path: hidden items contribute no pixels and are removed; the bottom visible layer keeps its id and name. Groups flatten in place, and pixels land within the canvas-clipped render bounds. Pattern resources accompany the scratch document. The Background's position and transparency locks permit merge; image-pixel locking refuses it.

## Canvas right-click menu

The right mouse button on the canvas is the context-menu button and never pans (Seth's decision); panning is the middle button, the spacebar, the Pan tool, and the pen barrel button, which `dispatch_tablet_as_mouse` synthesizes as a middle-button drag. Alt+Right stays the brush adjust drag, a right-click on a ruler stays the unit menu, and the MCP activity overlay pans only with the middle button or Space.

- A right press records `context_press_pos_` (cleared by tool, lock, document, and focus changes through `close_canvas_context_menu`, and by a drag past `startDragDistance`); a release within that distance calls `CanvasWidget::show_canvas_context_menu`, the one canvas menu builder. Path tools get `canvasPathContextMenu` ([vector-commands.md](vector-commands.md)).
- Everything else gets a popup `canvasContextMenu` built from sections, each the host's own QActions (enable state and hotkeys carry over; nullptr = separator). No section, no menu. In order: the Move tool's layers-under-the-pointer entries ([layer-panel.md](layer-panel.md)); when the click landed on the selection, `set_selection_context_actions_callback` (Remove Object, Fill, Clear, Stroke, Deselect, Inverse); when it landed inside the bounds of the ACTIVE vector shape layer (any tool but the path tools, edit lock off), `set_shape_context_actions_callback` (Shape Appearance..., Free Transform..., Simplify Path..., separator, Define Custom Shape from Path, Rasterize; an inactive shape gets no section, the Move entries activate it first); for any other active leaf layer, Free Transform alone through `set_layer_context_actions_callback`, only with the Move tool, inside the layer's Move outline (`move_layer_rect_contains_document_point`), and with its position not effectively locked (painting tools keep a right-click on a raster layer menu-free).
- A press on the pasteboard starts a tool only from the allowlist in `CanvasWidget::mousePressEvent` (`allows_off_canvas_press`): Move, the selection tools, Patch, Crop, Zoom, the off-canvas brush family, and since 1.12 the shape tools (Rectangle, Ellipse, Line, Polygon, Custom Shape) and Text, as in Photoshop. A shape or text box may then hang partly off the canvas; a pixel-mode shape clips to the document on commit (`ui_shape_and_text_drags_start_off_canvas`). Any other tool's press outside the document does nothing.
- A click outside the document (the pasteboard) appends the backdrop-color section (`add_backdrop_color_menu_entries`, issue 47): Default, Black, Dark Gray, Medium Gray, Light Gray, White, then Select Custom Color... (Patchy's picker, live preview on every window, Cancel restores the previous choice), radio-checked. The host owns it as `view/canvasBackdropColor` (`MainWindow::set_canvas_backdrop_color_preference` pushes it through `apply_canvas_aid_settings` into `CanvasWidget::set_backdrop_color_override`; the key exists only for a user color); `CanvasWidget::backdrop_color()` paints the pasteboard and the overlay-preview base (the theme role when unset). Scroll bars keep their theme roles.
- **Lifetime:** the popup menu must outlive the dispatch of the click that picked an entry (an entry's modal dialog nests an event loop inside that dispatch, and a `deleteLater` posted there frees the menu under Qt's mouse handler). Hiding only retires the menu (`retire_canvas_context_menu`); `QMenu::triggered`, emitted after the handler returns, posts the deferred delete, and dismissed menus are reaped by the next menu at the same `QThread::loopLevel()` (`reap_retired_context_menus`). Never `deleteLater` a canvas menu from a hide path or a nested loop (`ui_stroke_selection_from_context_menu_survives_following_mouse_input`).
- Coverage: `ui_canvas_backdrop_context_menu_sets_color`, `ui_right_drag_does_not_pan_canvas`, `ui_selection_context_menu_offers_remove_object`, `ui_shape_context_menu_offers_shape_commands`, `ui_move_context_menu_offers_free_transform_on_raster_layer`, `ui_move_layer_menu_preserves_pan_and_cancels_stale_clicks`, `ui_path_context_menu_edits_anchors`, `ui_pen_barrel_button_pans_instead_of_painting`.
