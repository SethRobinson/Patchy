# Shape tools, Crop tool, Free Transform modifiers, Merge Down, and tool icons

Small tool/command behaviors that don't have their own doc. Selection tools live in [selection-tools.md](selection-tools.md); brushes in [brushes.md](brushes.md); the text tool in [text-tool.md](text-tool.md). The vector side of the shape tools (Shape/Path modes, pen, path editing, vector masks, Paths panel, shape library) lives in [vector-tools.md](vector-tools.md); this page covers the legacy Pixels-mode raster behavior, which must stay byte-identical.

## Clipboard pixel placement

- Edit > Paste (`edit.paste`, Ctrl+V) centers copied/cut selection pixels and external clipboard images on the active canvas viewport, using the current pan and zoom. Each axis is clamped so the pasted rectangle fits inside the document.
- Edit > Paste in Place (`edit.paste_in_place`, Ctrl+Shift+V) uses the selection's original document coordinates, including across documents, with the same bounds clamp. External images have no source coordinates and use the viewport center.
- Pasting preserves pixel dimensions and content. If the pixels exceed the canvas on an axis, that axis is centered with overflow instead of being resized or cropped. Both commands clear the selection in the paste history entry; Undo restores it and Redo restores placement.
- Both commands insert directly above the topmost selected layer, preserving the copied stack's order. A selected child keeps the paste in its folder; a selected folder places it above that folder. With no selected rows, paste appends at the document top. This applies to pixels, whole layer trees, and SVG; the topmost pasted layer becomes active and selected. The `ui_paste_inserts_above_topmost_selected_layer` and `ui_paste_above_selected_folder_or_at_top_without_selection` tests cover placement and undo/redo.
- The pixel placement code lives in `MainWindow::paste_clipboard` (`main_window_layer_ops.cpp`). Whole editable layer trees and SVG use their separate preserving clone/import paths. Palette and color-picker focus retain their color paste routing.
- Coverage: the `paste` UI filter includes viewport placement, all four edges, cross-document coordinates, oversized pixels, the actual shortcut, document/channel guards, external clipboard replacement, and undo/redo.

## Shape tools (Rectangle/Ellipse/Line)

- Rectangle/ellipse honor brush Opacity/Soft through the signed-distance renderer in pixel_tools.cpp.
- Options-bar Style/Width/Height are deliberately session-only (mirrored via `current_shape_*`, never persisted). The row is registered pixel-only: the vector modes hide it and show the active shape's W / H instead ([vector-tools.md](vector-tools.md)). With Style Normal the Width/Height spins are greyed out (the marquee's twin row greys the same way); Fixed Ratio and Fixed Size enable them.
- A Pixels-mode click keeps the legacy 1 px commit (its `begin_edit` snapshot is pushed at press); the vector modes open the Create dialog instead. Coverage: `ui_shape_tap_*`, `ui_shape_style_row_is_pixel_only_and_greys_size_at_normal`.
- Alt = draw-from-center, so Rectangle/Ellipse are exempt from the Alt temporary-eyedropper (the two meanings fight).
- Mode is always the first options-bar item for the shape tools (built before the shared brush controls), so switching to Pixels never shifts it. Coverage: `ui_options_bar_mode_combo_stays_first_for_shape_tools`.
- ALL constraint math lives in `CanvasWidget::shape_drag_rect()` — it intentionally duplicates `marquee_selection_rect()` (selection-only concerns, separately pinned). Do not merge them.
- The Fill command and Fill tool share their OWN persisted Opacity/Soft (see the Fill tool section); tests laying down setup color call `use_solid_fill_settings(canvas)`.
- Coverage: `ui_shape_fill_and_corner_radius_apply_to_new_documents` also pins the `current_*` mirror pattern from [ui-conventions.md](ui-conventions.md).

## Fill tool (Paint Bucket) and the Fill command

The Fill tool click (G / Shift+G, `CanvasWidget::flood_fill` over core `patchy::flood_fill`) floods from the clicked pixel; the Fill command (Alt+Backspace, `fill_rect`) paints the whole selection or layer and never reads existing colors. The Fill tool's options-bar row holds Opacity, Soft, Tol, and Contiguous, persisted as `tools/fillOpacity` / `fillSoftness` / `fillTolerance` / `fillContiguous` (defaults 100 / 0 / 32 / on), mirrored through `current_fill_*`, and turned into `EditOptions` in one place, `apply_fill_settings` (canvas_widget_shared.cpp), which both paths call. Tol and Contiguous only matter to the flood.

- **Tolerance** (0..255) is the Magic Wand's metric through core `color_within_tolerance` (sum of squared per-channel differences within 4 x tolerance^2), so Fill Tol N accepts exactly the pixels Wand Tol N selects (GitHub issue 30). 0 is an exact match. The wand engines in canvas_widget_selection.cpp inline the same formula; `tool_fill_bucket_tolerance_metric_matches_magic_wand` pins the numbers. **Contiguous** off fills every matching pixel of the layer, still clipped by the selection.
- **Membership is decided against the clicked color, never against written pixels:** a first pass builds a region mask (4-connected stack flood, or a full scan when Contiguous is off), otherwise a translucent fill at a wide tolerance spreads through its own output forever. Under the transparency lock, alpha-0 pixels are outside the region.
- **Opacity blends** through `write_pixel` (palette mode snaps there like every tool) instead of stamping a reduced alpha; **Soft** feathers inward from the region's edge with the Fill command's chamfer transform (`compute_fill_feather`, up to 50 px). Tolerance 0 at 100% opacity is byte-identical to the old verbatim path, which keeps the `flood_fill_background` digest in `tool_write_paths_digest_baseline` unchanged.
- Mask and channel floods (`flood_fill_mask`) apply Tol and Contiguous over the one gray channel and write the mask value verbatim. Anti-alias is deliberately not offered.
- Coverage: core `tool_fill_bucket_*`, UI `ui_fill_tool_tolerance_and_contiguous_persist_across_documents` and `ui_fill_tool_click_honors_tolerance_contiguous_and_opacity`.

## Free Transform modifiers

Corner handles scale proportionally on their own and Shift releases the lock, matching Photoshop CC 2019 and later. The preference `input/shiftKeepsTransformAspect` (default `false`, Preferences > Application, `preferencesTransformShiftAspectCheck`) restores the older pairing, where a plain corner drag distorts and Shift holds the ratio. It is a persisted identifier and rides the pen-input load/save/apply trio in main_window_preferences.cpp, so `configure_canvas` and the Preferences accept loop both push it onto every canvas.

- Both sessions decide through one predicate, `CanvasWidget::transform_drag_keeps_aspect(modifiers)` (canvas_widget_transform.cpp): `shift == shift_keeps_transform_aspect_`. The pixel session calls it from `update_free_transform_preview`, the path session from `handle_path_transform_move` (canvas_widget_vector_tools.cpp). Both aspect-locked corner drags share one rule: the shared scale is the pointer's distance from the anchor projected onto the box diagonal, per axis in absolute value (`(|dx| w + |dy| h) / (w^2 + h^2)`), and each axis keeps its own sign from the side of the anchor the pointer is on. Travel along the diagonal scales at one rate in every direction, a pull leaning against the diagonal shrinks, and a straight pull across the anchor mirrors that axis alone (`ui_point_text_flip_transform_mirrors_and_survives_reedit` drags one). The pixel session writes the corner from the anchor; the path session converts the per-axis scales back into its local delta. Taking whichever axis the pointer pulled harder (the rule before September 2026) scaled the short side `aspect` times faster, jumped in rate when the winning axis switched, and ignored the other axis outright. The shared predicate is what stops their modifier semantics drifting apart. Never reintroduce an inline `Qt::ShiftModifier` test for a resize.
- Edge handles (Top/Right/Bottom/Left) scale one axis in every mode. Only corners consult the predicate.
- While a Free Transform, Warp, or path transform session is pending, the Shape Appearance, Layer Style, and adjustment-layer dialogs refuse to open (`refuse_layer_dialog_during_transform`, a status hint to press Enter or Esc first). Coverage: `ui_layer_dialogs_refuse_during_transform`.
- Shift on the rotate handle still snaps to 15 degrees in both sessions and both modes; it is a separate modifier test in the same functions.
- The options-bar link button (`freeTransformLinkScaleButton`) mirrors the W% and H% spin boxes only. It does not reach handle drags.
- The session start status line reports the active pairing, so both sentences are translated strings.
- Shift on the shape and marquee tools remains a 1:1 square/circle constraint on a new shape (`shape_square_constrained_`, `selection_square_constrained_`); that is unrelated and unchanged.
- A text layer's session rect is its whole raster (`move_layer_transform_local_rect`: a box layer's frame, a point layer's line box), the same rect the passive Move-tool controls draw, like Photoshop's paragraph-text box. Other layers use the opaque pixel rect. The two must agree because a handle drag sets the rect corner to the absolute mouse position; a session on the smaller ink rect stretches the ink to the frame on the first move. `ui_box_text_transform_handle_grab_keeps_ink_size` pins it.
- The rotate handle turns the box about the reference point (the options-bar Pivot combo, `transform_reference_point_`; `set_transform_reference_point` repaints the session box so the marker moves at once), like Photoshop: `update_free_transform_preview` measures the drag angle from `transform_reference_position(start rect, start angle)` and moves the center to `pivot + R(delta)(C0 - pivot)`. With `a` the anchor offset, `C0 - pivot = -R(start)a`, so `C1 + R(new)a` is the pivot again and the reference position is invariant. Numeric edits already pivoted there (`set_transform_controls_state`). `draw_free_transform` draws the reference marker (circle plus crosshair) during a session only; the passive Move box stays a plain frame, as in Photoshop.
- Scale handles compute in the box's own frame: the snapped pointer is unrotated about the drag-start center, the edge/corner setters and the Shift aspect block run on an axis-aligned local rect, the flip signs read the raw local rect, and the center rotates back out. At angle 0 this is the old world-space math exactly, so unrotated drags are byte-identical.
- Alt on a scale handle scales about the reference point (`transform_drag_scales_about_reference`, the Shift predicate's sibling): per moving axis the factor is `(pointer - r) / (handle - r)` in local coordinates and the center lands at `r(1 - f)`; a reference sitting on the dragged edge keeps the plain result for that axis; corners under the aspect lock share one magnitude by the same projection (per-axis factors weighted by the squared reference-to-handle spans), each axis keeping its sign. Shift or Alt pressed or released mid-drag replays the preview at the last pointer position, and the modifier cursor filter skips `dragging_transform_`.
- Drag readout (`view/showTransformValues`, default on, Preferences > Application `preferencesShowTransformValuesCheck`, pushed to every canvas with the Shift-aspect pairing): `transform_drag_readout()` lists the reference point's X/Y plus the offset while moving (the Move tool uses the moving set's opaque union, `move_readout_base_rect_`), W x H plus the signed percentages while scaling, and the angle plus its delta while rotating. `draw_transform_drag_readout` paints only the change line (`canvas_lines`: the offset, the percentages, or the angle delta, no label) below-right of the pointer in the canvas HUD theme roles, while the status bar mirrors both lines (`lines`). Its panel rect joins the bounded drag repaints (`update_drag_readout_region`, [interactive-previews.md](interactive-previews.md)); release and cancel clear it. Text comes from `format_pixels`/`format_percent`/`format_degrees` in measurement_units.hpp.
- The options-bar X/Y/W/H/Angle fields are `UnitSpinBox`es ([ui-conventions.md](ui-conventions.md), [resolution-units.md](resolution-units.md)): X/Y are native px with percent relative to the document extent, W/H native percent with pixels relative to `TransformControlsState::original_size`, Angle degrees only. Typing a unit (or right-clicking the field) switches what the field displays; the linked W/H pair switches together. The link button still mirrors W and H.
- **Pixel-grid snapping** (PS 27.9 COM captures, September 2026): Photoshop lands every axis-aligned transform on whole pixels by rounding each destination EDGE with halves up (`snap_to_pixel_grid` in core/pixel_grid.hpp: floor(x + 0.5), so 3.5 -> 4 and -3.5 -> -3): a typed X of 3.4 moves the layer by 3 with crisp pixels, 152.5% of 20 px (edges 4.75..35.25) comes out 5..35, and an odd-sized layer under the Center pivot legitimately reads X .50. Photoshop does this for pixel layers with its "Snap Vector Tools and Transforms to Pixel Grid" preference on OR off (`toolsPreferences.transformsSnapToPixels`, settable through Action Manager `setd` on the application); that preference only decides whether a smart object's placement quad is rounded too (off keeps 13.4 in the quad while the raster still lands on 13). Patchy: `set_transform_controls_state` snaps `transform_current_rect_` (`snap_transform_rect_to_pixel_grid`) whenever `input/snapTransformsToPixelGrid` (Preferences > Application "Snap transforms to the pixel grid", default on, pushed with the other input prefs) is on and the session is not rotated (`|angle| <= 0.01`; a rotated box cannot sit on the grid, and both stress-test numeric transforms are rotated, which keeps `tool_write_paths_digest_baseline` untouched). Snapping in the setter means preview, options-bar readback and all three commit paths agree, and integer inputs snap to themselves so pinned commit bytes never move. Handle drags already snap the pointer (`snapped_document_point_f`); an aspect-locked drag can still leave a fractional edge and is not snapped here. Off restores the sub-pixel resample (floor origin, one extra column). A whole-pixel move through the default bicubic (Catmull-Rom, interpolating) is byte-identical, so there is no separate fast path. An entry that snaps back to the start commits as the existing no-op. Coverage: `ui_transform_numeric_fraction_snaps_to_pixel_grid`, `ui_transform_numeric_odd_layer_keeps_half_pixel_reference`, `ui_transform_snap_preference_off_keeps_fraction`, `ui_transform_snap_skips_rotated_sessions`, `ui_transform_integer_move_is_lossless_through_bicubic`, `ui_transform_snap_preference_persists_and_reaches_canvas`. The script API's `moveTo`/`x`/`y` round with the same helper (`ui_script_layer_move_to_rounds_like_photoshop`); type layers round their anchor the same way ([text-render-calibration.md](text-render-calibration.md)).
- **Move-tool double-click does nothing special** (Seth, September 2026): it neither starts nor commits Free Transform (both were tried; a hand that slips between the clicks drags the box). Photoshop commits on a double-click inside the box; Patchy deliberately does not. During a session `mouseDoubleClickEvent` hands the event straight to `QWidget::mouseDoubleClickEvent`, which replays it as a second press, so it behaves like two single clicks and never reaches the text-editor or shape-appearance branches. The one exception runs first: a double-click inside the box of a transforming text layer finishes the transform and opens the text editor. A motionless press inside the box must not nudge it: `update_free_transform_preview` rounds the Move drag START to whole pixels like the snapped end (otherwise a half-pixel pan at 100% shifted the box by 1 px), and `free_transform_snap_exclude_ids` keeps the session's own layers (whose pixels stay put until commit) out of the snap targets. Coverage: `ui_move_double_click_leaves_free_transform_alone`.
- Coverage: `ui_transform_shift_frees_aspect_ratio_by_default`, `ui_transform_proportional_corner_follows_diagonal_projection`, `ui_transform_shift_aspect_preference_restores_legacy`, `ui_transform_shift_aspect_preference_defaults_to_off`, `ui_transform_shift_aspect_preference_persists_and_reaches_canvas`, `ui_transform_fields_accept_unit_tokens`, `ui_transform_rotate_drag_pivots_on_reference_point`, `ui_transform_alt_drag_scales_about_reference_point`, `ui_transform_handle_drag_on_rotated_box_uses_local_axes`, `ui_transform_drag_readout_shows_values`, `ui_move_drag_readout_reports_reference_and_delta`, `ui_transform_readout_preference_hides_hud`, plus the `unit_spin_box` group. The path session keeps its own center pivot and has no modifier test yet.

## Merge Down
- `MainWindow::merge_down` normalizes the selection, includes a single leaf's lower sibling, and routes selections containing vectors through the preserving planner and Merge Layers dialog. Compatible shapes merge immediately. The dialog offers separate vector/bitmap outputs, merges within each group, and separate vector paint categories. [layer-merging.md](layer-merging.md) owns the options, preservation boundaries, transaction, and scripting contracts.
- Bitmap-only selections retain the existing CPU-composited flattening path: hidden items contribute no pixels and are removed; the bottom visible layer keeps its id and name. Groups flatten in place, and pixels land within the canvas-clipped render bounds. Pattern resources accompany the scratch document. Position-only Background locking permits merge; image-pixel locking refuses it.

## Canvas right-click menu

The right mouse button on the canvas is the context-menu button and never pans (Seth, September 2026): panning is the middle button, the spacebar, the Pan tool, and the pen barrel button, which `dispatch_tablet_as_mouse` synthesizes as a middle-button drag. A right press records `context_press_pos_` (cleared by tool, lock, document, and focus changes through `close_canvas_context_menu`, and by a drag past `startDragDistance`); a release within that distance calls `CanvasWidget::show_canvas_context_menu`, the one builder for every canvas menu. Path tools get `canvasPathContextMenu` ([vector-commands.md](vector-commands.md)). Everything else gets a popup `canvasContextMenu` whose first section is the Move tool's layers-under-the-pointer entries ([layer-panel.md](layer-panel.md)) whose second, present when the click landed on the selection, is `MainWindow::selection_context_actions_` (Remove Object, Fill, Clear, Stroke, Deselect, Inverse: the menus' own QActions, nullptr = separator, supplied through `set_selection_context_actions_callback`), and whose third, present when the click landed inside the bounds of the ACTIVE vector shape layer (any tool but the path tools, edit lock off), is the shape section supplied through `set_shape_context_actions_callback`: Shape Appearance..., Free Transform..., Simplify Path..., separator, Define Custom Shape from Path, Rasterize (again the Layer > Shape and Edit menus' own QActions, so their enable state and hotkeys carry over). A shape that is not active gets no shape section; the Move section's layer entries activate it first. For any other active leaf layer (pixel, text, smart object) the third section is Free Transform alone, through `set_layer_context_actions_callback`, and only with the Move tool, only inside the layer's Move outline (`move_layer_rect_contains_document_point`), and only when its position is not effectively locked (Free Transform would refuse it); painting tools keep a right-click on a raster layer menu-free. No section, no menu. **Lifetime:** the popup menu must outlive the dispatch of the click that picked an entry (September 2026 crash: Stroke Selection's modal dialog nested an event loop inside that dispatch, a `deleteLater` posted from inside it destroyed the menu, and Qt's window-level mouse handler then read the freed popup window). Hiding only retires the menu (`retire_canvas_context_menu`); `QMenu::triggered`, emitted after the entry's handler returns, posts the deferred delete that Qt processes once the dispatch has unwound, and dismissed menus are reaped by the next menu at the same `QThread::loopLevel()` (`reap_retired_context_menus`). Never `deleteLater` a canvas menu from a hide path or a nested loop. `ui_stroke_selection_from_context_menu_survives_following_mouse_input` pins it. Alt+Right stays the brush adjust drag, a right-click on a ruler stays the unit menu, and the MCP activity overlay pans only with the middle button or Space. Coverage: `ui_right_drag_does_not_pan_canvas`, `ui_selection_context_menu_offers_remove_object`, `ui_shape_context_menu_offers_shape_commands`, `ui_move_context_menu_offers_free_transform_on_raster_layer`, `ui_move_layer_menu_preserves_pan_and_cancels_stale_clicks`, `ui_path_context_menu_edits_anchors`, `ui_pen_barrel_button_pans_instead_of_painting`.

## Tool palette layout

- Built imperatively in `MainWindow::build_tool_palette()` (main_window_actions_tool_palette.cpp, the tool-palette phase of `create_actions()`); order is the construction order, in separator-delimited clusters: select (Move, Marquee, Lasso, Wand, Crop), paint (Brush, Eraser, Gradient+Fill), retouch (Stamp, Healing, Smudge, Dodge), draw/type (Pen Tools, Path Tools, Shapes, Type), view (Pick, Hand, Zoom). The Pen Tools flyout (Pen P as default, then Add Anchor / Delete Anchor / Convert Point, unbound) sits directly before the Path Tools flyout (drawing and adjusting paths alternate constantly, so the two slots stay adjacent). The Pen stays separate from the path-select tools (a flyout hides the tool you switch to most); the anchor tools live under the Pen because Photoshop users look for them there. See [vector-commands.md](vector-commands.md).
- Below the tools, an expanding spacer pins the color cluster to the bottom edge, ordered FG swatch, BG swatch, Default Colors (D), Swap Colors (X), separator, Quick Mask. That order is deliberate for vertical overflow: QToolBar hides items tail-first into the extension button, so a short window loses Quick Mask first, then X and D, and the swatches last. The palette width is a 43 px minimum, never fixed, because clicking the extension arrow expands the bar into extra columns by temporarily widening it; a fixed width clamps that into a clipped sliver (see the standing rule in [ui-conventions.md](ui-conventions.md)). The expansion is a sticky toggle: stock Qt collapses it half a second after the pointer leaves the bar, so `ToolPaletteExpansionLock` swallows Leave while the extension button is checked, and picking a palette item leaves it open (an auto-collapse there ate the first click of the Zoom button's double-click-for-100%). While it is open, `ToolPaletteExpansionReservation` raises the bar's minimum width to the measured expanded width so the main-window layout reserves the extra columns and the canvas shrinks instead of being overlaid; each pass releases the minimum, re-measures, and re-pins so Qt can drop back to fewer columns when the window grows. The bar closes on an arrow re-click, or automatically once the window is tall enough that nothing overflows. Coverage: `ui_tool_palette_overflow_hides_quick_mask_before_swatches`, `ui_tool_palette_extension_button_expands_palette`, `ui_tool_palette_expansion_sticky_after_tool_pick`, `ui_tool_palette_expanded_zoom_double_click_sets_actual_pixels`, `ui_tool_palette_expansion_collapses_when_window_fits_again`.
- Tools sharing a slot go through the shared `create_flyout_tool_action` + `configure_tool_flyout` lambdas (eleven flyouts: marquee, lasso, wand, gradient+fill, stamp, healing [Healing Brush J / Spot Healing Shift+J / Patch unbound, default Healing Brush, see [healing.md](healing.md)], smudge/detail, dodge/tone, pen tools [Pen P / Add Anchor / Delete Anchor / Convert Point, default Pen], shape [Line/Rect/Ellipse/Polygon/Custom Shape, default Rect], path tools [Path Select A / Direct Select Shift+A]). Tools whose gestures the name does not explain also carry a two-line tooltip (`tool_tooltip_source`) and a status-bar activation hint (`tool_activation_hint_source`). The flyout swaps the button's default action on each member action's `triggered`, which also covers hotkey activation.
- Every flyout button sets the `toolFlyout` Qt property; the app stylesheet keys the corner-triangle `::menu-indicator` and its sizing on `QToolButton[toolFlyout="true"]`, so a new flyout only needs the property (via `configure_tool_flyout`), not a new QSS selector. Coverage: `ui_stamp_and_gradient_flyouts_swap_tools`.
- A flyout opens three ways: press-and-hold (`QToolButton::DelayedPopup`; the delay is `SH_ToolButton_PopupDelay` from `InteractionHintsStyle` in `src/app/main.cpp`, 200 ms instead of Qt's 600), a left double-click, or a right-click (`configure_tool_flyout` installs a `ToolFlyoutEventFilter` that calls `showMenu()` for both: Qt otherwise routes the double-click pair's second press back to `mousePressEvent` and restarts the hold timer, and a right press would otherwise reach the toolbar's own context menu). The first click of the pair still selects the default tool. A persistent tool-group bar beside the palette was rejected (Seth, September 2026): the flyout menu is the only group UI. Coverage: `ui_tool_flyout_double_click_opens_menu`, `ui_tool_flyout_right_click_opens_menu`.
- Clone/Pattern Stamp (S / Shift+S) and Gradient/Fill (G / Shift+G) deliberately share slots like the other paired-shortcut groups; Clone and Gradient are the defaults.

## Tool palette icons

- Original SVGs at `src/ui/icons/tool-*.svg` (32x32, `#dce2eb` strokes, at most one non-load-bearing `#74c0ff` accent). Generic metaphors, no Photoshop geometry, so the license stays clean.
- QtSvg renders a Tiny-1.2 subset only, and a typo'd qrc alias renders EMPTY silently — review with `patchy_ui_visual_tests.exe ui_tool_palette_icons` (writes contact-sheet artifacts, checks per-icon coverage + pairwise distinctness).
- Clone keeps the classic rubber-stamp silhouette; Pattern Stamp is deliberately a different silhouette (stamp knob over a large checkerboard tile) because a small in-base detail was indistinguishable from Clone at the palette's 20px render size. Keep any future pair of related tools distinct in SILHOUETTE, not just in accent color. The healing flyout follows the same rule: bandage (Healing Brush), circle with burst ticks (Spot Healing), rotated stitched square (Patch). The pen flyout: nib drop (Pen), a curve with a hollow anchor plus a + or - accent (Add/Delete Anchor), a corner whose anchor sprouts a handle (Convert Point).
