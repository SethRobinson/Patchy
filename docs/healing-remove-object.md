# Remove Object and content-aware fill

Split from [healing.md](healing.md): Edit > Remove Object (its dialog, worker fill job, variations, tone match and edge feather), the content-aware exemplar fill with its Nearest Edge fallback, and the entry points that share the command. The healing family's patent boundary, the healing membrane and the retouch Sample (the snapshot every fill reads) are in healing.md.

## Remove Object

Edit > Remove Object... (also in the Select menu; hotkey id `edit.remove_object`, unbound by default; object name `editRemoveObjectAction`) opens the Remove Object dialog (`MainWindow::remove_object_dialog`, main_window_layer_ops.cpp; objectName `patchyRemoveObjectDialog`, `run_non_modal_dialog`) on the current selection. The dialog shows at once and the first fill runs on a worker thread, so the UI stays live; `removeObjectStatusLabel` reads "Filling... N%" until the result lands. Controls:

- **Reroll** (`removeObjectRerollButton`): fills again with the next variation; `removeObjectVariationLabel` reads "Variation N", where variation 1 is the byte-stable best-match fill and variation N is `ExemplarInpaintOptions::attempt` N - 1 (below). The status label reports the method and patch count.
- **Tone match** 0..100 % (`removeObjectToneMatchSlider` / `removeObjectToneMatchSpin`, key `tools/removeObjectToneMatch`, default 0): the strength of the tone match after the fill; 0, the default, is the raw exemplar fill.
- **Edge feather** 0..50 px (`removeObjectFeatherSlider` / `removeObjectFeatherSpin`, key `tools/removeObjectFeather`, default 0): a gaussian of that sigma over the selection coverage (the mask-feather three-box approximation, `mask_feather_blur`; the padded bounds grow by the boxes' total reach), grown outward on top of the selection's own feather. The fill covers the widened footprint and the skirt blends the edge, so the filled area grows by the blur's reach (about three sigma): a feather larger than the selection's margin to a strong edge makes the fill synthesize that edge, which is why the default is 0 and the tooltip says to keep it small when the selection hugs an edge (the banner fixture at feather 4 shows the failure: `ui_remove_object_banner_feather_4`).
- **Duplicate to New Layer** (`removeObjectDuplicateButton`, enabled once a result is in and no fill is in flight): copies the current result's filled area (coverage > 0 over the job bounds) onto a new transparent pixel layer inserted above the active layer, hidden so the next preview stays visible, named "Remove Object variation N" (`next_duplicate_name`), as its own history entry ("Duplicate Remove Object variation to layer", pushed with the original layer in place so Undo never captures a preview). Several variations can be kept this way and compared afterwards by toggling visibility.
- The wrapped status label grows the dialog (`keep_dialog_tall_enough_for_wrapped_text`, dialog_utils: minimum height = `totalHeightForWidth`), never squeezing the rows (#612).

Every fill is one `CanvasWidget::RemoveObjectJob` in three stages: `prepare_remove_object` on the UI thread (the prechecks, the padded coverage, the retouch snapshot; the previous preview is restored into the layer first, so the snapshot is the document before any fill and the canvas shows the original while the next fill computes), the static `compute_remove_object` on a worker thread through `launch_async` (the exemplar fill and tone match over the job's own copies; `ExemplarInpaintOptions::cancel` is polled per copied patch), and `commit_remove_object` on the UI thread from the dialog's 50 ms poll (the heal write into the layer as the preview, `record_history = false`, under `lock_preview_dialog_edits`). A changed setting or a Reroll cancels the fill in flight (its worker is retired and drained, never abandoned; the waited drain at close goes through `CanvasWidget::wait_for_processing_operation`, never a bare `future.wait()`, because a blocked wasm main thread starves the JS event loop the fill's strip threads start and return through, and the tab freezes on Cancel mid-fill) and starts the new one; OK and Duplicate are disabled while a fill is in flight. A fill runs only on Reroll, on a slider release, or on a settled spin/step value (a 250 ms coalescing timer, skipped while the slider is held and when the settled values equal the applied ones), never per slider move: US 8050498 (live classify-and-display, to Nov 3, 2029) bars a live per-move healing preview ([legal-constraints-filters.md](legal-constraints-filters.md)). OK restores the original, pushes ONE "Remove Object" history entry, puts the last result back, and persists the two settings; Cancel, Esc, the chrome X, and an unwinding call cancel any fill in flight and restore the original with no history entry. The selection stays put. Status: "Removed object with content-aware fill, variation N (M patches)". `remove_object_in_selection(options)` (the script API and the bare-canvas paths) prepares and commits on the calling thread and runs the compute stage on a `launch_async` worker under `wait_for_processing_operation`, whose poll feeds the overlay ("Removing object... N%") from the percent the worker publishes. Never move that compute back on-thread with a pump in the progress callback: on wasm no pump paints, so the tab looks frozen for the whole fill. A dry pre-spawned pool computes inline under the usual `BlockingFanoutBudgetScope` contract (docs/wasm.md).

**Variation continuity.** MainWindow keeps `remove_object_last_selection_hash_` (an FNV-1a hash of the selection region's rects) and `remove_object_last_attempt_`: a dialog opened again on the same selection starts at the variation after the last one it showed; another selection starts at variation 1 (the best match). The nearest-edge repeat cycle on the canvas is separate (Try another, below).

Two methods; only the first has a menu entry (a Nearest Edge entry confused users; it stays the automatic fallback and a script API method):

- **Content-aware (default)**: the exhaustive exemplar fill of `core/exemplar_inpaint.{hpp,cpp}` (Criminisi 2003, whose Microsoft patent expired; the boundary in [legal-constraints-filters.md](legal-constraints-filters.md) "Content-aware fill and exemplar inpainting" and the claim record in [patent-research-inpainting.md](patent-research-inpainting.md)). A copy of the retouch snapshot is filled from the hole boundary inward in priority order (confidence times the strongest known isophote projected on the front normal, integer math; ties go to the cell nearest the original hole edge by a BFS distance transform, then the smaller cell index, so equal priorities peel in from every edge instead of sweeping from the top-left and colliding with the far edge in a seam; priorities are cached per front cell and refreshed only in the neighbourhood of each copied patch, Criminisi's incremental update); each 9x9 target patch takes the best source patch from an exhaustive scan of a window around it, scored by an integer L1 distance over the target's known pixels (SSE2/NEON and scalar paths give the same sums) plus a fixed penalty of 2 per pixel of Manhattan offset between source and target centres (a geometric preference for nearby sources: rows draw from their own row to the left and right, so a grain's phase stays locked to the surroundings instead of drifting until it collides with the far edge, which printed a vertical seam a patch inside the right edge of wide selections), first scan index on ties, with strips sharing the best distance only to prune strictly worse partial sums. The candidates come from up to five full-resolution windows of `radius` = `clamp(max(w, h) / 2 + 32, 48, 96)`: the target's own window, plus, when that window holds fewer than 4096 clean source centres (an integral-image count; the target is deep inside), for each axis ray from the target whose first original known cell lies beyond that window, the half-window on the far side of that edge point (per-cell ray tables), so a target deep in a large hole still sees the band to its left and right at its own height as well as above and below. Do not replace this with a coarse candidate grid (it shifts the grain's phase by a pixel or two deep inside and prints a seam where the zones meet) or a window centred only on the nearest edge (it pulls unrelated content, such as darker wood from below, into the middle); a per-row next-valid-centre table skips the hole in O(1), and a last resort scans the whole window on a stride of 4. Filled pixels never become sources, and each search is independent of every other patch's offset (no offset field, propagation, perturbation, pruning, or coarse-to-fine map, by legal design). The candidate scan fans out over row strips with a (distance, index) reduction, so it is byte-identical single-threaded. When no fully known source patch is in reach (the selection fills its neighbourhood), it falls back to Nearest Edge and says so.
  - **Variations** (`ExemplarInpaintOptions::attempt`; the dialog's Reroll; the script API's `attempt` for this method): attempt 0 is the byte-stable best-match fill above. Attempt N > 0 is Efros-Leung's (1999) epsilon selection: after the same exhaustive scan finds the best distance D, a second full scan of the same windows against the fixed threshold D + max(D / 8, 8 per known target pixel) counts the admissible candidates (partial sums stop at the threshold; strips only count, and their counts sum in row order), and the copy comes from the k-th admissible candidate in scan order, k a splitmix64 draw seeded from `(attempt << 40) ^ target image cell` mapped by multiply-high, found by a serial walk of the window that holds it; the best candidate is always admissible. The admissible set is recomputed per target from that fresh scan, used once, and dropped: no offset is perturbed or propagated, nothing persists between targets or runs, and every variation is reproducible and identical single-threaded vs parallel. Variations of a near-uniform texture may coincide, and a reroll costs about two scans. `exemplar_inpaint_banner_tone_match_stays_dark_and_varies_by_attempt` pins attempts 0, 1, and 2 on the issue #23 fixture (`tests/remove_object_fixture.hpp`, shared with the UI suite).
  - **Tone match** (`exemplar_match_tone`, radius 24, strength = the dialog's Tone match, off at 0, the default): frequency separation through the recorded membrane. The fill's low-pass band, a box blur taken over HOLE cells of the fill only and normalized by their count, for the interior and the one-cell ring alike, is replaced by the harmonic interpolation across the hole of that low-pass read at the ring, keeping the fill's grain; that removes the brightness polygon where fill fronts from differently lit edges meet (no gradients are composited, so US 9058699 stays untouched). Nothing outside the hole is read. Never normalize over the ORIGINAL known pixels: content a radius past the hole edge then takes the weight of the excluded hole cells and lifts the fill toward the surroundings (issue #23's fixture, a 35 px hole running 3 px short of a dark band's edges, band luminance 26: the raw fill is 26, known-pixel normalization gives 82). A smaller radius is worse (94 at radius 8, since the box's far-side fraction grows), so the radius stays 24, which also keeps structure crossing the hole (the banner's stripe) where a small radius flattens it. The strength scales the per-pixel correction with round-half-away-from-zero integer math; 100 is the full replacement, 0 skips the pass.
  - The result is written through the shared `heal_mask_from_surroundings` with an identity source map, whose membrane solves to zero.
- **Nearest Edge** (no QAction or hotkey id; `RemoveObjectMethod::NearestEdge` and `layer.removeObject({method: "nearestEdge"})` only): the selection form of Spot Healing ([healing.md](healing.md#spot-healing)), `spot_heal_source_map` plus the membrane through the same write (the stroke path calls the same routine; areas at or above 262,144 pixels fan out over row strips like the Patch tool). Instant, and the status bar reports "source N of M". Edge feather applies; Tone match does not.

Both refuse (status error, no history entry) without a selection, without unselected pixels around the selection to sample, or when `can_begin_pixel_edit` refuses.

**Try another (Nearest Edge).** Running it again on the same selection (same bounds and an FNV-1a hash of its coverage) advances `remove_object_attempt_`; `spot_heal_source_map`'s `attempt` parameter indexes the geometrically valid candidates in their fixed order (mirror then translate per direction: nearest boundary, opposite, the two perpendiculars) and wraps, so attempt 0 is the pick Spot Healing always uses. The user's repeat count is the only input besides shape; pixel content is never read in that mode. Undo does not reset the cycle, so Undo / Remove Object / Undo / Remove Object also walks the candidates; a different selection restarts at 0. Content-aware runs do not touch the cycle.

Entry points sharing the command: Edit > Fill's Content-Aware, the canvas context menu on the selection ("Canvas right-click menu" in [tools.md](tools.md)), the Patch tool (Enter with an outline and no drag asks the host through `set_remove_object_requested_callback`, which MainWindow points at the dialog; a bare canvas without a callback runs the default fill directly; Enter mid-drag commits the drag like a release; the `patchRemoveObjectButton` options-bar button triggers the action), and the script API `layer.removeObject({method?, attempt?, toneMatch?, feather?})`, dialog-free, which returns `{method, patches, source, sourceCount, attempt}`, requires the layer to be the active layer, and rides the run's single undo snapshot (`record_history = false` runs the prechecks without `begin_edit`). Coverage: `exemplar_inpaint_restores_periodic_stripes_deterministically`, `exemplar_inpaint_banner_tone_match_stays_dark_and_varies_by_attempt`, and `spot_heal_source_map_attempt_cycles_valid_candidates` (core), `ui_remove_object_*` (the dialog, its worker, Duplicate to New Layer, and the continuity in `ui_remove_object_dialog_previews_rerolls_and_is_undoable`; variations, tone, and feather with `ui_remove_object_banner_*` artifacts in `ui_remove_object_banner_variations_tone_and_feather`; `ui_remove_object_parallel_heal_detaches_shared_pixels` for the strip path with shared bytes), `ui_patch_tool_enter_removes_object`, the Remove Object rows of `ui_spot_healing_and_patch_texture_gallery`, `ui_selection_context_menu_offers_remove_object` (tests/ui/layer_context_lifecycle_tests.cpp), and `ui_script_remove_object_heals_selection` plus the local-fixture `ui_script_remove_object_then_reopen_large_document` (tests/ui/scripting_tests.cpp).
