# Pattern presets: bundled textures, the pattern library, Pattern Manager

Split from [style-presets.md](style-presets.md): the bundled photo-texture patterns (the "Textures" folder), the persistent pattern library and Pattern Manager, long picker popups, Photoshop preset pattern names, and the versioned defaults the pattern and style libraries share. How applying a style preset carries its patterns stays in the parent.

## Bundled photo-texture patterns (the "Textures" folder)

20 real photo-scanned seamless tiles (wood-heavy: seven woods plus stone, metal, fabric, and ground surfaces) from Poly Haven under CC0, bundled as 512x512 lossless PNGs in `src/ui/textures/` via `textures.qrc` and described by the Qt-free `PhotoPatternPreset` table in core/pattern_presets.cpp (fixed `f0705a00-…` ids, canonical English names, per-entry `introduced_version`). Pixels load through `ui/photo_pattern_presets.hpp`; `bundled_pattern_resource`/`is_bundled_pattern_id` are the one-stop resolvers every site uses (style apply, New Style capture, seeding, previews, `ensure_patterns_for_style`). Sourcing rules live in [legal-licensing.md](legal-licensing.md); per-asset provenance is in NOTICE-THIRD-PARTY.md. Prep pipeline for adding/replacing a texture: download the 1K PNG diffuse map (resolve the exact URL from `https://api.polyhaven.com/files/<asset id>`, Diffuse -> 1k -> png), center-crop the largest square, tile it 3x3, smooth-scale to 3x512, and crop the center 512 tile (the 3x3 step gives the borders wrap-correct filtering so seamlessness survives the downscale), then save as PNG; never route through JPEG. Decoded bytes are pinned by `ui_photo_pattern_presets_load_stable_tiles` (the failure output prints hashes for deliberate re-pins).

**Static-lib qrc gotcha**: a `.qrc` compiled into the static patchy_ui library dead-strips its self-registering initializer in executables that never reference it. `photo_pattern_presets.cpp` force-registers with `Q_INIT_RESOURCE(textures)` (from outside any namespace) before the first resource read; a new qrc added to a static lib needs the same treatment.

## Pattern library and Pattern Manager

`.pat` imports are capped at 32 MiB compressed, 8 million pixels per pattern, 16,384 pixels per axis, and 16 million decoded pixels per file, with a separate aggregate plane-expansion budget (container parsing lives in [psd-layer-styles.md](psd-layer-styles.md)). The persistent user library is `<settings directory>/patterns/` (`%APPDATA%/RTsoft/Patchy/patterns/` on Windows; `src/ui/pattern_library.*`): PNG plus JSON per entry, valid UTF-8 source Photoshop ids up to 255 bytes preserved when unique (unsafe ids receive a fresh UUID), imports grouped under the PAT filename, and folders editable in Pattern Manager. Layer Style's Pattern Overlay and Bevel Texture pickers present the same folders as expandable tree rows while retaining a flat combo model for the selected value. When an imported id already belongs to different pixels, the sidecar retains that source id so later imports deduplicate the remapped entry. A chosen preset is copied into the active document as `Authored`; later library deletion cannot break that document. If a library tile collides with different document pixels under the same id, the selected copy receives a document-local UUID. Preview-off, cancel, and the pre-undo restore return the document pattern store to its exact original state. The manager's explicit Restore command repairs deleted or changed defaults (defaults seed once under the `patterns/defaultPatternsVersion` settings key; versioning below). The manager's preview pans with any mouse button and wheel-zooms about the cursor, outlining the tile under the viewport center (Seamless-Tile-Preview style), and its "Open as Image" button hands the tile to MainWindow, which must DEFER creating the document until the Layer Style dialog closes: `add_document_session` is forbidden under the preview-dialog edit lock (pinned by `ui_layer_style_open_pattern_as_image_defers_until_dialog_closes`). The manager's combined Import command also accepts plain image files (any QImageReader format, EXIF-rotated, alpha kept, any rectangle, capped at 8 Mpx and 30,000 pixels per axis so authored PSD pattern resources remain writable) via `PatternLibrary::import_image`; image imports land ungrouped with a fresh pattern UUID and no pixel dedup. Full-resolution tiles are cached under both a 16-entry and 64 MiB total limit.

Shape Appearance's Fill and Stroke dropdowns show thumbnails from the document's embedded tiles, followed by library-only entries. When both sources contain the same pattern id, the document entry and its pixels take precedence.

Long pickers must fit the screen (GitHub issue 271). The plain combo-box pickers (Shape Appearance's fill and stroke pattern and gradient lists, Fill Path's pattern, the Pattern Stamp options-bar list) call `use_scrolling_list_popup` (`dialog_utils.hpp`): Fusion and the macOS style otherwise show a combo's list as a menu sized to every row with the current row over the box, which ran off the top of a Wayland screen. They open a scrolling list of at most `kLongListPopupRows` rows on every style. Every blend mode list (`add_blend_mode_items`, `add_paint_mode_items`: options bars, Layers panel, Layer Style, New Layer, filters) uses the same form with `kBlendModeListPopupRows`, so the whole list shows where it fits (GitHub issue 414: the menu form ran off the top of a small screen at 125%). Each time the list opens, `fit_combo_popup_to_screen` moves it into the screen's available geometry (below the box, else above, else the taller side, scrolling; not on Wayland, where the compositor places popups); on Windows QComboBox alone fits it to the whole screen, taskbar included. Layer Style's tree pickers and the gradient preset popup size and place their own popups (`position_popup_below`). Tests: `ui_shape_pattern_list_popup_fits_the_screen`, `ui_blend_mode_lists_fit_a_small_screen`.

Photoshop's own presets are named with a localization key, `$$$/Presets/Patterns/Patterns_pat/TieDye=Tie Dye`. Pickers show the English default (`photoshop_zstring_display_text`, `src/support/string_utils.hpp`; `document_pattern_display_name` for document patterns), while the resource and any paint that picks it keep the raw key, so Photoshop still localizes it after a save. `.pat` imports store the default as the library entry's name.

## Versioned defaults (patterns and styles)

`kDefaultStylesVersion` is 2 and `kDefaultPatternsVersion` 3 (version 3 adds no pattern: it runs the duplicate cleanup below once). Both libraries filter restore/has-all by per-entry `introduced_version` (generated patterns and the Text/Basics styles are version 1; photo patterns and Materials styles are version 2), so a version-1 install's upgrade seeds ONLY the new entries and deliberate deletions of old defaults stay deleted (`ui_version_two_defaults_seed_only_new_entries` pins this). Photo patterns seed into the localized "Textures" folder (`photo_patterns_folder_name`), generated ones stay in "Patchy Defaults".

Duplicate default files (issue 636): seeding before stable storage ids (issue 506) could write a built-in twice under UUID storage ids. The loader keeps the first file per pattern id, so the copy was hidden until the shown one was deleted. Below version 3, startup seeding first runs `remove_duplicate_default_pattern_files()`: among files whose sidecar carries a built-in's pattern id, those with the same name, folder, source id and pixels collapse to one (the file named after the preset id, else the one the library shows, else the oldest) and the library reloads. Edited, renamed or moved copies stay. Documents and tool settings reference patterns by pattern id, never storage id, so nothing needs remapping. Pinned by `ui_default_pattern_duplicate_files_collapse_once_on_upgrade`.
