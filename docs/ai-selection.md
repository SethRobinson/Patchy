# Automatic selection: Select Subject and the Object Selection tool

Photoshop-style automatic selection that runs on the CPU only, so it works on every desktop Patchy supports without a GPU. The binding patent rules are the "Automatic selection" bullet in [legal-constraints.md](legal-constraints.md); the claim record is in [patent-research.md](patent-research.md). Read both before changing how prompts, masks or modes reach a network.

## What ships

| Piece | Where | Notes |
|---|---|---|
| Select > Select Subject (`select.subject`) | `src/ui/main_window_ai_selection.cpp` | BiRefNet_lite, one pass over the merged document at 1024x1024 (stretched), soft matte. Also the "Select Subject" options-bar button on Quick Select and Object Selection, which uses the tool's combine mode. |
| Select > Select Background (`select.background`) | same | The same one pass, inverted (255 outside the matte). |
| Layer > Layer Mask > Remove Background (`layer.remove_background`) | same | The same one pass as the active layer's mask (default 0 outside the matte); an existing mask's painted pixels are multiplied in and its density and feather kept (`apply_subject_matte_to_layer_mask`, shared with `layer.removeBackground()`). One undo step; the selection is untouched. Also a button on the Object Selection options bar. |
| Select Object (`select.object_in_selection`) | `src/ui/canvas_widget_object_select.cpp` | Right-click inside a selection (after Remove Object): the selection's bounding box becomes one Object Selection box prompt and the object replaces the selection (`select_object_in_selection`). |
| Canvas right-click | `src/ui/canvas_widget_move.cpp` | With a selection tool active and the click outside any selection, the menu offers the three commands above (`set_selection_tool_context_actions_callback`). |
| Object Selection tool (`tools.object_select`, `CanvasTool::ObjectSelect`) | `src/ui/canvas_widget_object_select.cpp` | Third member of the Magic Wand flyout (Shift+W cycles). Drag a box, or click; solves on release. Shift adds, Alt subtracts, no Intersect (Shift+Alt is Add, like Quick Select). Options: New/Add/Subtract, Feather, Anti-alias, Sample All Layers, Model (Standard or High Quality, desktop only), Select Subject. Settings keys `tools/objectSelectFeather`, `tools/objectSelectAntiAlias`, `tools/objectSelectSampleAllLayers`, `tools/objectSelectModel` (`standard` or `highQuality`, the default), `automaticSelection/highQualityModelOffered`. |
| Script API | `src/ui/script_ai_selection.cpp` | `doc.selection.selectSubject(opts)`, `doc.selection.objectSelect({rect} or {point}, ...)`, `doc.selection.automaticSelectionAvailable`, `doc.selection.objectSelectionModel`, `app.downloadObjectSelectionModel()`. See patchy.d.ts. |
| Engine | `src/ai/` (`patchy_ai` library, Qt-free) | `ai_selection_math.*` (pre/post-processing, always built), `segmentation_engine.hpp` API, `segmentation_engine_onnx.cpp` (the only ONNX Runtime TU), `segmentation_engine_web.cpp` (the threaded wasm app; see WebAssembly below), `segmentation_engine_stub.cpp` (builds without either), `segmentation_engine_common.cpp` plus `segmentation_engine_internal.hpp` (the prompt construction and output choice both engines share). |

Builds without an engine (wasm-core, the single-threaded wasm app, or a dev tree that never ran the setup script) compile the stub: the menu item, the tool and the button are left out, and scripts get `automaticSelectionAvailable == false` and a clear error from the calls.

**Select Subject is held back.** CMake's `PATCHY_ENABLE_SELECT_SUBJECT` (default OFF) gates the BiRefNet model pending patent review of Adobe US 12051225 claim 16 ([patent-research-selection.md](patent-research-selection.md)). Off, the model is neither required, staged nor packaged (the staging step rebuilds `<build>/ai-models` from the list, so a stale copy disappears), `subject_selection_available()` is false (also compiled in as `PATCHY_SELECT_SUBJECT`, so a stray file cannot re-enable it), Select Subject, Select Background, Remove Background, their options-bar buttons and the selection-tool right-click entries are hidden, and the script calls throw while `doc.selection.subjectSelectionAvailable` reads false. Object Selection and Select Object need only `segmentation_available()` and ship. Setup provisions MobileSAM and EfficientViT-SAM only; it never downloads BiRefNet or deletes existing local copies. An experimental opt-in build needs a manually supplied model. Redistribution requires resolving the legal review before restoring provisioning or packaging.

## Models and runtime

BiRefNet's `ai-models-1` asset has been withdrawn. Installed apps never fetch it; existing local copies still work in opt-in builds. Older source checkouts must omit its setup entry. The original release's license and checksum records remain for prior downloads.

Patchy ships the MobileSAM int8 pair, pinned in `scripts/setup-ai-deps.ps1` / `.sh`, `cmake/patchy_ai.cmake` and the Flatpak manifest (keep all four in sync). The files are assets of the GitHub release **`ai-models-1`** (`https://github.com/SethRobinson/Patchy/releases/download/ai-models-1/<file>`), a release that must never be marked Latest (the README and `latest_version.json` download through `/releases/latest/`) and whose assets are never replaced: a new model set gets a new tag (`ai-models-2`) and new pins. Nothing is committed to git.

| File (in `ai-models/`) | Size | Converted from | License | SHA-256 |
|---|---|---|---|---|
| `mobile_sam_image_encoder_int8.onnx` | 14.4 MB | huggingface.co/Acly/MobileSAM `mobile_sam_image_encoder.onnx` (28.2 MB; preprocessing built in: HWC float 0..255, longest side 1024, the graph normalizes and pads) | MIT export of Apache-2.0 MobileSAM | `6af3f249...930cd7` |
| `sam_mask_decoder_multi_int8.onnx` | 4.8 MB | same repo, `sam_mask_decoder_multi.onnx` (16.5 MB; standard SAM decoder, 4 masks + IoU predictions) | Apache-2.0 (SAM decoder) | `aa1410be...c10a6` |
| `birefnet_lite_general_1024_int8.onnx` (held back; not provisioned or packaged) | 143.2 MB | github.com/ZhengPeng7/BiRefNet release v1 `BiRefNet-general-bb_swin_v1_tiny-epoch_232.onnx` (224 MB) | MIT | `0374fa92...27fed5e` |
| ONNX Runtime 1.30.0 CPU | | github.com/microsoft/onnxruntime releases (win-x64, win-arm64, osx-arm64, linux-x64, linux-aarch64, SHA-256 pinned per package) | MIT (ThirdPartyNotices.txt ships beside it) | per package in the scripts |

`scripts/ai/quantize_models.py` reproduces the three int8 files byte for byte from the pinned upstream fp32 files (it checks their SHA-256): dynamic int8, weights int8 per channel, MatMul/Gemm only. BiRefNet's export routes its MatMul weights through Identity nodes; the script removes those first, otherwise the quantizer keeps every float weight beside its int8 copy and the file grows to 253 MB. The script is dev tooling (Python, `onnxruntime==1.30.0`, `onnx==1.23.2`); builds only download.

Rejected for licensing: EdgeSAM (S-Lab, non-commercial), RMBG-1.4/2.0 (non-commercial), SAM 3 (restricted), CorridorKey (CC BY-NC-SA-based, no redistribution). MobileSAM's decoder graph still has SAM's `mask_input`/`has_mask_input` inputs; the engine always feeds zeros and 0 (a legal rule, not an optimization).

### The High Quality model (desktop download)

Object Selection has two models. **Standard** is MobileSAM, bundled everywhere (and the only one on the web). **High Quality** is EfficientViT-SAM XL0 (MIT Han Lab, Apache-2.0; image encoder replaced, SAM's prompt encoder and decoder kept; legal record in [patent-research-selection.md](patent-research-selection.md)). It is never packaged: desktop users download it once, on request, from the release **`ai-models-2`** into `<AppDataLocation>/ai-models` (`downloaded_models_folder()`). It runs when its files are present and `tools/objectSelectModel` is not `standard`; the choice is the user's, never derived from the image.

| File | Size | Converted from (huggingface.co/mit-han-lab/efficientvit-sam @ a2f0c592) | SHA-256 |
|---|---|---|---|
| `efficientvit_sam_xl0_encoder_fp16.onnx` | 226.1 MB | `onnx/xl0_encoder.onnx` (451.8 MB, `b39add8f...`) | `a28cf697...5bf101` |
| `efficientvit_sam_xl0_decoder_multi_fp16.onnx` | 8.4 MB | `onnx/xl0_decoder.onnx` (16.5 MB, `051bfae9...`) | `632613ec...ba496b` |

- **Why fp16, not int8.** Weights are float16 behind Cast nodes ONNX Runtime folds at load, so it runs in float32. Measured on 14 photo prompts (October 2026): fp16 masks match fp32 at IoU 0.9987 mean (0.995 worst); int8 weight-only per channel collapses to 0.43 (embedding cosine 0.28; 32-weight blocks still 0.84), because the ReLU linear attention amplifies weight rounding. Keeping the 33 most sensitive convolutions fp16 and the rest int8 measured 148 MB compressed at IoU 0.998, but its layer choice was fitted on one photo: unshipped until validated on a wider set.
- **The decoder** export picked the best mask in-graph; `quantize_models.py` exposes all four masks (`low_res_masks`, 256x256 over the padded frame) and `iou_predictions` instead, so the choice follows `best_sam_candidate` like MobileSAM. It has no mask input.
- **Input.** NCHW, ImageNet mean/std, longest side 1024, zero-padded to 1024 square (`padded_sam_encoder_input`). Masks map straight from the low-res grid to document pixels in one bilinear pass (`document_mask_from_low_res_logits`; padding cells never read).
- **Download** (`src/ui/object_selection_model_download.cpp`): pinned URL, size and SHA-256 per file (keep in sync with `setup-ai-deps.*` and `PATCHY_AI_DOWNLOAD_MODEL_FILES`), plus optional `fallback_urls` tried in order when a link fails (unreachable, HTTP error, wrong size or hash), streamed through `QSaveFile` with a running hash and committed only on a match; files already present and matching are skipped. Progress (`ModelDownloadProgress`) names file N of M, its size and the link being fetched, reported before each file's first byte.
- **Progress dialog** (`ModelDownloadDialog`, `src/ui/model_download_dialog.*`): every download the user starts (this model, the watermark models, a one-click update) shows the heading, "File N of M: name (size)", and under "From:" the full link (`modelDownloadLinkLabel`, before redirects, so a GitHub release link and not the storage host's signed one): selectable when it fits, elided in the middle otherwise, the full link always in the tooltip, the context menu and Copy Link. Cancel and Escape reject, which cancels the job. Offer and Preferences texts name the source before anything starts (`model_download_source_text`: "github.com/SethRobinson/Patchy (release ai-models-2)"). Redirects are followed by hand so every host, GitHub's storage host included, resolves on a detached thread first (`host_resolve.hpp`, GitHub issue 48; the update checker uses the same helper). Transfer timeout 60 s without bytes.
- **UI.** The first time the tool is chosen, or right-click Select Object is first used, on a desktop build without the model, one dialog offers the download (never during unattended automation, nor offscreen unless a test opts in through `MainWindowTestAccess`; `automaticSelection/highQualityModelOffered` remembers it, for both). Select Object then solves with whichever model the answer left in place. The options bar's Model combo shows the model that runs; choosing High Quality without the files offers the download again. The download runs under the window-modal progress dialog above. Scripts: `app.downloadObjectSelectionModel()` (status-bar progress) and `doc.selection.objectSelectionModel`.
- **Preferences > Tools** shows whether it is downloaded, with Download (progress dialog modal to Preferences) and Delete. Delete also removes `automaticSelection/highQualityModelOffered` and resets `tools/objectSelectModel` to High Quality, so the tool offers the download again on its next first use and a new download is used at once.
- **Deleting it.** `release_high_quality_model()` (sessions are shared-owned, so a run in flight finishes on its own reference), then `delete_downloaded_high_quality_model` removes exactly the two files by full name and the folder only when it is then empty (plain rmdir; never a wildcard or recursive delete). The Windows uninstaller does the same for `%APPDATA%\RTsoft\Patchy\ai-models` (`packaging/windows/UninstallPatchy.cs` repeats the names). macOS has no uninstaller; the Flatpak's copy lives in its data folder, which `flatpak uninstall --delete-data` removes.
- **Watermark models.** The TrustMark watermark models are a second, separate download into the same folder, through the same `start_model_download` and ONNX translation unit: [watermarks.md](watermarks.md).
- **Lookup.** `high_quality_model_path` tries the download folder, then the bundled `ai-models` folder (a packager may ship it). Build trees stage the files into `<build>/ai-models-download` when `setup-ai-deps` provisioned them; tests point the engine there. That folder is never packaged.

### Why int8, and which int8 (measured October 2026)

Compared with fp32 on real photos (a 3000x1820 photo, the Vermeer IFF fixture, the San Francisco readme photo), same prompts, IoU of the 50% masks against fp32, i9-12900KS:

| Variant | Size (deflate) | IoU vs fp32 | Speed |
|---|---|---|---|
| MobileSAM fp32 | 44.7 MB (36.7) | reference | encode 410 to 450 ms, decode 75 ms |
| **MobileSAM int8, MatMul/Gemm (chosen)** | **19.2 MB (12.4)** | **0.9935 to 0.9998**, mean alpha diff under 1/255 | encode about 10 to 15% faster, decode same |
| MobileSAM int8 including Conv | 16.2 MB | as low as 0.02 (clicks select the wrong region) | encode 3x slower |
| BiRefNet fp32 | 224 MB (165) | reference | 5.5 to 6.1 s |
| **BiRefNet int8, MatMul/Gemm (chosen)** | **143 MB (88)** | **0.997 to 0.9999** | about 5 to 7% faster |
| BiRefNet int8 including Conv | 93 MB (39) | 0.997 to 0.9997 | 2.3x slower (ConvInteger is slow on CPU) |
| BiRefNet static QDQ int8 (MinMax calibration) | 94 MB (41) | 0.94 on the Vermeer (bleeds into the background) | no faster, 8 s load |

Differences in the chosen variants are sub-pixel edge shifts. Not measured: Apple Silicon and pre-VNNI x86 speed (results stay correct; the speedup may differ). About 43 MB of BiRefNet is float Constant nodes (Swin position tables) that dynamic quantization does not touch.

`setup-ai-deps` provisions `<main checkout>/.deps/onnxruntime/<ver>/<platform>/` and `.deps/ai-models/`; worktrees find the main checkout through `git rev-parse --git-common-dir`, and CMake searches both `.deps` folders. Packagers pass `PATCHY_ONNXRUNTIME_DIR` and `PATCHY_AI_MODELS_DIR`. `PATCHY_ENABLE_AI_SELECTION` (default ON) and `PATCHY_REQUIRE_AI_SELECTION` (default OFF; release builds turn it on so a missing model is a configure error) control the build. `patchy_ai_runtime` is the copy-once target staging `ai-models/` and the runtime libraries into the build directory; `patchy_copy_ai_runtime(target)` attaches it.

ONNX Runtime is **loaded at run time, never linked** (`ORT_API_MANUAL_INIT`, `LoadLibraryExW` by full path beside the executable on Windows, since System32 can hold an unrelated older `onnxruntime.dll`; `dlopen` from beside the executable, `../Frameworks`, then by plain name elsewhere). A machine that cannot load it still runs Patchy and reports the feature unavailable. This matters on macOS: the 1.30 dylib requires macOS 14 while Patchy targets 12, so macOS 12 and 13 run without automatic selection.

At run time `configure_automatic_selection_models()` (main_window_ai_selection.cpp) points the engine at `ai-models` beside the executable, `../Resources/ai-models` (macOS bundle) or `../share/patchy/ai-models` (Linux install). Tests set the folder themselves.

## Engine behavior

- Preprocessing composites RGBA over white. SAM: area-averaging resize so the longest side is 1024 (aspect kept, top-left anchored). BiRefNet: stretch to 1024x1024, ImageNet mean/std, NCHW.
- Postprocessing upsamples logits bilinearly to document resolution once and crops to covered bounds (`document_mask_from_logits`). SAM masks map through a fixed narrow ramp around logit 0 (`127.5 + 64 * logit`) to anti-alias the edge; BiRefNet keeps the sigmoid matte.
- Point prompt: one positive point plus SAM's padding point (label -1), the alternative (outputs 1-3) with the highest predicted IoU. Box prompt: two corners (labels 2, 3), the output with the highest predicted IoU among all four, clipped to the box (SAM masks can spill past it). MobileSAM's single-mask output (0), the textbook choice for a box, degrades on a loose box: on a photo of a boy in front of a fridge it took the fridge too at predicted IoU 0.66 while output 3 was the boy at 0.96 (Photoshop's tool handled the same box). A tight box makes all four agree. `ai_object_selection_loose_box_skips_background_if_available` pins it on a local fixture.
- **Zoom-to-box.** A box prompt whose grown region (`sam_box_region`: 15% of the box's longer side per side, at least 64 px, widened to at least 384 px, clamped) covers less than 80% of the image encodes only that region (`sam_encode_region`; `SamTransform::origin_*` keeps prompts and masks in document coordinates). Fixed geometry from the box alone, one encode, one decode (legal rule). It sharpens edges up to the image-to-region ratio, since SAM decoders resolve only a 256-cell grid over the encoded frame. Clicks keep the whole-image embedding. Both engines and the script API share it.
- **Embeddings carry their model** (`SamEmbedding::model`) and decode only with that model's decoder.
- Sessions: `ORT_ENABLE_ALL`, CPU arena disabled (activation memory returns after each run), ONNX Runtime's default thread pool (physical cores; measured fastest) unless `PATCHY_RENDER_THREADS` is set. Encoder and decoder stay loaded; the subject session stays loaded after a run and `MainWindow` frees it after 3 minutes idle (`release_subject_model`; the timer is stopped while a run is in flight).
- Cancellation: `InferenceCancel::request()` terminates the running ONNX Runtime call (`RunOptions::SetTerminate`); the call throws `InferenceCancelled`.
- Out of memory: ONNX Runtime reports a `std::bad_alloc` inside a kernel only as status text ("... Status Message: bad allocation"). `run()` and `open_session()` turn those (`is_out_of_memory_message`) and a direct `std::bad_alloc` into `InferenceOutOfMemory`; every caller checks `is_out_of_memory()` and shows `automatic_selection_out_of_memory_message(command)` (close other programs or documents, try again) instead of the raw diagnostic. The session stays usable; a retry with more free memory succeeds.
- Model outputs are CPU-dependent float math, so this module is exempt from the byte-determinism rule: tests compare masks by IoU, never bytes.

## UI behavior that is load-bearing

- Object Selection computes the image embedding on a tracked worker at the first press (no prompt, nothing displayed), keyed on (Sample All Layers, model, sampled layer id) plus a 64-bit signature of the sampled pixels. A box release with a zoom region re-reads the source, cancels a whole-image encode still running (it would only compete for the CPU) and encodes the region under the same overlay; `object_select_encodes_started()` counts both kinds. `notify_document_changed` and document swaps (undo/redo) only mark it unverified; the next press hashes the source and re-encodes only when the pixels differ, so a selection-only undo keeps it. The worker owns its promise, so dropping never blocks. A release waits for a pending encode under the processing overlay ("Analyzing image..."). A second click on an unchanged document reuses the embedding (`object_select_encodes_started()` counts encodes for tests).
- During a drag the canvas draws only the user's rectangle (black line plus white dashes). A release within 4 widget px of the press is a click. One undo entry per release ("Object Selection").
- `CanvasWidget::apply_automatic_selection_mask` is the shared combine (Feather and Anti-alias of the active tool apply).
- Select Subject runs on a worker under a window-modal, immediately shown progress dialog with Cancel; the dialog keeps the document from changing under the run.
- Sample All Layers: on, every command analyzes the merged document; off, it analyzes the active layer rendered alone (`automatic_selection_layer_image`: any layer kind, shape and text included, with its opacity, mask and effects; other layers hidden except its ancestor groups). A hidden or empty layer (an adjustment layer alone) is refused with a message rather than falling back to anything. Object Selection and Select Object use the Object Selection checkbox; the subject commands use Quick Select's checkbox when Quick Select is the active tool and the Object Selection checkbox otherwise. Scripts take `sampleAllLayers` (default true) on `objectSelect`, `selectSubject`, `selectBackground` and `removeBackground`.
- Percentages are estimates: ONNX Runtime reports no progress inside a run. The subject commands scale elapsed time against the last run's duration on this machine (QSettings `automaticSelection/subjectRunMs`, averaged with each new run, model load included); Object Selection's "Analyzing image... N%" uses the last encode's duration. Both hold at 95% until the run really ends.

## Measured performance (dev box i9-12900KS, 24 threads, Windows)

fp32 numbers come from an idle box; the int8 rows from an fp32/int8 run alternated under the same background load, so compare within a row pair, not across the table.

| Step | fp32 | int8 (chosen) |
|---|---|---|
| MobileSAM encode, 1024x768, session warm | about 200 ms idle (330 ms at 6 threads); 394 ms loaded | 320 ms loaded |
| MobileSAM session load | about 290 ms | about 290 ms |
| SAM decode per click or box (warm) | 30 to 100 ms; the first call loads the decoder (about 400 ms) | same |
| EfficientViT-SAM XL0 encode (fp16 weights, any image: the frame is always 1024 square) | about 1.5 s (1.3 to 2.2 s over 14 photos, Python harness, October 2026); session load about 0.8 s; process peak about 1.3 GB | |
| BiRefNet_lite run, warm | about 4.8 s idle (barely scales with threads); 5.9 s loaded | 5.6 s loaded |
| BiRefNet_lite session load | about 2 to 3 s idle | same as fp32 |
| BiRefNet_lite peak memory (2316x3088 photo, 24 threads) | | about 6.2 GB process working set; failed with "bad allocation" when 6.3 GB was free (October 2026) |

Published numbers for a 6-core Ryzen 5600X: MobileSAM encode 0.8 s, BiRefNet_lite 7 s (ONNX Runtime). About 60% of BiRefNet's time is Transpose/Sum/Mul/GatherND, the export's spelling of deformable convolution and Swin window shuffles.

## Tests

- Core (`patchy_core_tests ai_`): transform and preprocessing math, logit mappings, upsample/crop, IoU, then real runs on a self-authored synthetic scene (shaded disc on mottled noise): box and point IoU >= 0.9, Select Subject IoU >= 0.85, cancel before and during a run, out-of-memory recognition (`ai_out_of_memory_failures_are_recognized`), model load from a Unicode folder. In a build without the engine the model tests print `[SKIP]`; in a build with it, missing models fail.
- UI (`PATCHY_UI_TEST_FILTER=object_select`, `select_subject`, `select_background`, `remove_background`, `context_menu_offers_subject`): no selection change before release, one undo entry, booleans, embedding reuse, the options bar and menu, and the script API. The subject tests skip without the subject model; `ui_select_subject_is_left_out_without_the_subject_model` then checks every surface hides or refuses it while Object Selection still works. Core `ai_select_subject_finds_the_disc` checks the refusal, and the mid-run cancel test cancels the encoder instead.

## WebAssembly

The threaded wasm app (`wasm-release`) runs Object Selection in Microsoft's onnxruntime-web 1.30.0 (npm, MIT), not in `patchy.wasm`. Linking ONNX Runtime statically would add 10+ MB to `patchy.wasm`, put its kernels under Asyncify instrumentation, and share the 4 GB wasm32 heap with documents; onnxruntime-web runs in its own worker and heap and costs visitors nothing until first use. Select Subject is not offered on the web (`subject_selection_available()` is false). wasm-core (no page) and `wasm-release-st` (no worker that can wait) build the stub.

- **Pieces.** `segmentation_engine_web.cpp` implements the same API; `scripts/wasm/ai-host-pre.js` is the page-side host, linked as `--pre-js` by `patchy_copy_ai_runtime`. `setup-ai-deps -Web` (`--web` in the .sh) provisions `.deps/onnxruntime-web/<ver>/`: the npm tarball is SHA-256 pinned, only `ort.wasm.min.mjs` and `ort-wasm-simd-threaded.{mjs,wasm}` are kept, and `LICENSE` plus `ThirdPartyNotices.txt` come from the release tag (the npm package has none). `patchy_ai_runtime` stages `onnxruntime-web-<ver>/` (versioned, so caches never mix releases) and `ai-models/` (the two MobileSAM files plus `MODEL-LICENSES.txt`) beside `patchy.html`, never into `patchy.data`.
- **Transport.** Every engine call runs on a pthread worker; a main-thread call throws `std::logic_error`, because the host runs on the main thread and waiting there would deadlock. The worker fills one of eight slots of a static mailbox (`WebSlot`; the host's `W` table mirrors its word layout), bumps the mailbox sequence and wakes it. The host waits on the sequence with `Atomics.waitAsync` (a 100 ms poll where the browser lacks it), copies the inputs out, runs ONNX Runtime, writes the outputs back and notifies the slot's state word. The host never calls a wasm export (the Asyncify rule in [wasm.md](wasm.md)); the main thread attaches it once through `EM_ASM` from `segmentation_available()`.
- **Slot states.** FREE, PREPARING, PENDING, CLAIMED (host copying inputs), RUNNING, WRITING (host writing outputs), DONE or FAILED, back to FREE. PENDING and RUNNING are left only by compare-exchange: a cancel moves them to ABANDONED, and the host frees an abandoned slot once it lets go, so it never writes into a slot or buffer a newer request owns. A request the host has not claimed after 60 s fails ("the page did not answer").
- **Callers.** `solve_object_select` decodes on a worker on every platform. The script API (`ScriptEngineHost::automatic_select`) runs on a worker and waits in an event loop on wasm only, feeding the watchdog, then refuses if the document closed or changed size meanwhile.
- **Host behavior.** `ort.env.wasm.proxy = true` (ORT in its own worker, so an encode never blocks the page), up to 8 threads, one run at a time (sessions are not reentrant). Proxy mode transfers and detaches input buffers, so every run builds fresh tensors. Models download from `ai-models/` into the Cache API (`patchy-ai-models`; names are content-pinned, so entries under other names are deleted), with progress in permille written to the slot and read through `model_download_permille()` ("Downloading Object Selection model... N%"). Models stay identity-encoded so progress can count against Content-Length; the ORT wasm is precompressed. Failures that look like allocation errors come back prefixed "out of memory" and map to `InferenceOutOfMemory`.
- **Release.** `build-wasm.bat` configures with `PATCHY_REQUIRE_AI_SELECTION=ON` (a build host needs `setup-ai-deps.ps1 -Web` once per pinned version) and copies both folders into the site; the upload scripts send them before the html. `.htaccess` maps `.mjs` to `text/javascript` and caches `.mjs` and `.onnx` as immutable.
- **Measured** (Chrome, i9-12900KS, 8 ORT threads, October 2026, standalone harness on the San Francisco readme photo at 1024x680): session load about 0.6 s, encode 0.85 to 1.3 s (native int8 0.3 to 0.5 s), decode 55 to 90 ms. Against native ONNX Runtime on the same input the embedding differs by at most 0.027 (values up to 0.76) and the four decoder masks score IoU 0.985 to 0.998, the chosen one 0.998. In the app (`wasm-release`, same box), a script `objectSelect` on a 4288x2848 photo with the sessions loaded took 0.88 s including the fresh encode; click, box, Shift-add and Alt-subtract and the first-use download from an empty Cache API were checked by hand.

## Platform packaging

- Windows: `onnxruntime.dll` and `onnxruntime_providers_shared.dll` beside `patchy.exe`, `ai-models\` beside them; the installer and zip pick up the build folder contents.
- macOS: the dylib goes in `Contents/Frameworks` and `ai-models` in `Contents/Resources`, both staged by the bundle step and signed with the app.
- Linux/Flatpak: an `onnxruntime` archive module installs into `/app`; models install to `share/patchy/ai-models`.

## Not done yet

- WebAssembly: onnxruntime-web's WebGPU provider (the int8 MatMulInteger graph would need a float model there); Safari, Firefox and iOS memory headroom are untested.
