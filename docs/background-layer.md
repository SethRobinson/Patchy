# Background layer

Read this before changing the Background layer's rules, its Layers panel row or menu, or how PSD files mark one. Layer row conventions stay in [layer-panel.md](layer-panel.md); the Background's locks and the Eraser under them are in [tools.md](tools.md).

Photoshop's Background (#274) is `background_layer` (core/layer_metadata.hpp): the bottom top-level pixel layer with no alpha, bounds exactly the canvas, position locked. File > New and Flatten Image make one; the PSD reader adopts Photoshop's (`adopt_photoshop_background`: a bottom record with no transparency channel is expanded to the canvas over white whatever the background color and given position and transparency locks; Photoshop also renames it "Background", Patchy keeps the record's name, Photoshop 2026 over COM on ag-psd's float-size sample), and the writer emits it without a transparency channel, so it round-trips. Opened flat images stay unlocked, ordinary layers (issue 97).

A copy of the Background is an ordinary layer (#604): `clear_background_locks` (the position, transparency and auto-nest locks; other locks stay) runs on every copy, through `clear_background_locks_if_copy_of_background` in Duplicate Layer and the Move tool's Alt-drag (`duplicate_layers`), the panel's Alt-drop, Edit > Copy's layer payload, copies to another document (`copy_layers_between_documents`) and a script's `layer.duplicate()`. The one exception is a copy into an empty document (Duplicate Layer to Document > New Document): as its first layer it stays that document's Background. An ordinary layer's duplicate keeps its locks.

Every stack change goes through `refuse_background_stack_change` / `layer_stack_keeps_background` (panel drops and Alt-drop copies, the list reorder, Move Layer Up/Down; grouping it is refused; Bring to Front, Send to Back and Reverse leave it out of the selection and stop above it), and it takes no layer styles (`can_edit_layer_styles`, `edit_active_layer_style`, Paste Layer Style).

## Canvas changes

A Background's bounds are the canvas, so every canvas change either rebuilds it to the new canvas or releases it (GitHub issue 701); none leaves its name and locks on a layer that stopped being one.

- **It stays the Background** when the change cuts the layers (Crop with Delete Cropped Pixels on, a rotated crop, Perspective Crop, Canvas Size with its layer crop, `doc.crop`) or only grows the canvas (Canvas Size, a crop box dragged outward, `doc.resizeCanvas` with options): it is cut to the canvas and new area is filled with the extension color. These paths find it by the `background_layer` rule, read before the change (`document_background_id` in document_geometry.cpp), not by its name: a PSD from a translated Photoshop, Flatten Image in a translated Patchy and a script's `flatten()` name it otherwise. A pixel layer that is only named "Background" (an opened flat image's, unlocked) still fills new area as before, by the name.
- **It becomes "Layer 0"** when the change keeps the layers' pixels and the old canvas reaches beyond the new one on any side: Crop with Delete Cropped Pixels off, Canvas Size made smaller without its layer crop, `doc.resizeCanvas` with options. `resize_canvas_to_frame` runs `release_background` (core/layer_metadata.hpp: `clear_background_locks` plus the name the caller passes, `layer_from_background_name()` in ui/canvas_widget_shared.hpp, the same "Layer 0" Layer from Background gives). The layer is then only translated, like every ordinary layer: it keeps every pixel and its 3-channel buffer, and where the canvas also grew on another side the new area is transparent, not filled. The release is part of the Crop or Canvas size undo step.
- **Other releases.** `doc.resizeCanvas(w, h)` without options moves and fills nothing, so a Background that no longer matches the new canvas is released the same way (script_api.cpp). A core caller that passes no name (the artboard canvas fit and growth, `resize_to` in artboard.cpp) releases the locks and leaves the name, so a layer named "Background" keeps widening with the artboard canvas; that growth fills with transparency, which gives the layer an alpha channel and releases it too.
- **Photoshop 2026** (COM, a 1280 x 720 Background-only document, background color red). The Crop tool with Delete Cropped Pixels off gives "Layer 0" with both locks cleared and every pixel kept, and transparency in area the box added; Patchy matches, except that Photoshop does this even when the box only extends the canvas and cuts nothing, where Patchy keeps the Background and fills. With Delete Cropped Pixels on the Background is cut, filled with the background color where the box extends, and stays the Background, as in Patchy. Image > Canvas Size always keeps the Background: smaller cuts it to the canvas (Patchy releases it instead unless the layer crop is ticked, so the option to keep pixels means the same for every layer), larger fills with the extension color.

## Row and menu

Its row shows one padlock badge (property `layerBackgroundBadge`, tooltip "Background: ...") in place of the transparency, position and auto-nest badges (Seth declined Photoshop's italic name). A left click on that padlock runs `layer_from_background` (#629): the badge is a `LayerBackgroundBadge` QLabel with a pointing-hand cursor that takes the press itself, and `LayerListWidget::eventFilter` leaves a plain click or double-click on it alone, so the selection does not change and no drag starts (Ctrl- and Shift-clicks still select). A right-click on it alone opens `show_background_context_menu`: Layer from Background (`layer_from_background`: `release_background`, which clears those locks and names it "Layer 0", one undo step), Duplicate, Delete (only with another layer), Convert to Smart Object, Merge Visible and Merge Visible to New Layer (Copy) (both only with another visible layer), Flatten Image, then the row menus' Export submenu (#657: Quick Export as PNG, Export As..., Duplicate Layer to Document...; `add_layer_context_export_menu`, shared with the normal row menu). Merge Visible with the Background visible merges into it and keeps it the Background ([layer-merging.md](layer-merging.md#merge-visible)).
