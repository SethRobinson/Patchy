# Brush tip picker, cursors, and painting tool modifiers

Split from [brushes.md](brushes.md): the tip picker and Brush Tips manager, the floating Brush Tips window, footprint cursors and the brush overlay, and the modifiers every footprint-cursor tool shares (Ctrl Move, Shift line, stroke points as pixel indices, tool hints).

## Picker, manager, cursors

- `BrushTipPicker` (options-bar popup; Brush, Mixer, Pattern Stamp, Eraser; a fixed-width field with a chevron, the tip thumbnail and the elided name, full name in the tooltip: GitHub issue 364) and `request_brush_tip_manager` (`src/ui/brush_tip_manager_dialog.*`): a folder tree, multi-selection, bulk delete (button or Del; a folder row means all its tips), a folder field for the selection, a live stroke preview. "Define Brush Tip from Selection" (Edit > Define New Preset, hotkey id `edit.define_brush_tip`) captures inverted luminance x alpha x selection coverage (dark pixels paint, Photoshop semantics). The active tip is application-wide (re-applied in `apply_active_brush_settings_to_canvas`) and persists with the rest of the Brush and Eraser bars (`tools/brushTip`, [tool-options.md](tool-options.md)); the Round startup preset is the default for a missing key or a removed tip.
- Every Size/Soft footprint tool (`tool_uses_brush_footprint_cursor` in canvas_widget_shared, plus Quick Select via its own path) drops the pixmap cursor past the ~155px display cap for a canvas overlay (`brush_outline_uses_overlay`/`draw_brush_hover_outline`; also needed on wasm: browsers reject oversized bitmap cursors). The pointer is then the 17 px `brush_center_cross_cursor`; the overlay skips its own cross while that cursor shows (one cross at any size, GitHub issue 533) and draws it under any other pointer. Only tip-stamping tools (`tool_paints_with_brush_tip`: Brush, Mixer, Pattern Stamp, Eraser) trace the active tip's outline (`CanvasWidget::apply_brush_tip_cursor`, base shape only, no per-dab rotation/tilt); the retouch/toning tools always show the procedural circle, matching their procedural strokes. On stationary `[`/`]` resizes, `invalidate_brush_hover_outline(previous)` must erase old union new: `update_tool_cursor()` repaints only the new rect, so shrinking would strand the old rings. A `grab()` test repaints the whole widget and cannot catch this; manual-verify.
- **Brush overlay (GitHub issue 517).** Show Outline, Show Overlay and Overlay Opacity sit under a separator in the Brush tool's Smoothing gear (the Mixer and Eraser share that menu; `sync_brush_overlay_menu` hides the entries for them). Show Outline is on by default (`tools/brushOutline`); off, the Brush tool's pointer is the small `brush_center_cross_cursor` at every size and no canvas outline is drawn (`brush_outline_hidden`, checked first in `update_tool_cursor` and `brush_outline_uses_overlay`); the other footprint tools keep their outline. The overlay is off at 100% by default (`tools/brushOverlay`, `tools/brushOverlayOpacity`, every canvas). The opacity row is a menu `QWidgetAction`: `install_scrub_label` gives it scrub handles (`install_scrub_labels_in` never reaches a menu), a QSS rule keeps `brushOverlayOpacityRow` and its label transparent, and its left margin is `menu_item_text_indent` (dialog_utils), measured on every show so the label lines up with the item text. While on, the Brush (only) draws one dab under the pointer in the foreground color (its gray on a mask) at the overlay opacity, below the outline: `draw_brush_dab_overlay` samples `patchy::brush_dab_coverage` (core/pixel_tools.hpp), the coverage `paint_brush_dab` stamps at whole pixels (Round, elliptical, Square, or the scaled tip under its angle and roundness; a 1 px dab only at offset 0, since `brush_dab_rect` trims it to one pixel and the radius-0 square has coverage 1 everywhere; `tool_brush_dab_coverage_matches_painted_dab`). Below 100% each of the four supersamples reads the document pixel it falls in, so a 1 or 2 px dab shows as the fraction of the screen pixel it paints. Dynamics, Opacity and Flow are not previewed. The dab is cached in `brush_overlay_image_` per tip, size, Soft, shape, angle, roundness, color and zoom, at document resolution from 100% up (snapped to the pixel under the pointer) and at screen resolution below, capped by `kMaxHalfExtent`; a move repaints only the old and new dab rects. Hidden while painting, panning or on another tool; follows `[`/`]` and centres on the Alt+right-drag disc like the clone overlay. Tests: `ui_brush_overlay_*` (`small_dabs_match_painted_footprint` covers sizes 1 to 4 at 800%, 3200% and 50%).
- Holding **Alt** over a paint/shape/fill tool (`tool_uses_alt_left_for_color_pick`) turns left-click into a colour pick; `update_tool_cursor` shows the eyedropper cursor, hotspot on the lower-left tip, checked before the brush/overlay branches. The `eventFilter` swaps the cursor the instant Alt toggles, driven by the event's folded modifiers via the transient `alt_color_pick_cursor_override_`, never `QApplication::keyboardModifiers()` (it lags and leaves the eyedropper stuck; Zoom/selection badges fold modifiers for the same reason). The glyph is one shared cached helper, `patchy::ui::eyedropper_cursor()` (ui/tool_cursors), also used by the Eyedropper tool and the colour picker's "Pick Screen Color" overlay so they never drift.
- A dialog's canvas picker (`set_transient_read_interaction`: the Levels and Curves point pickers, Curves' on-image drag) owns the pointer while it is on: its cursor wins in `update_tool_cursor`, and the tool's hover overlays (canvas brush outline, brush and clone overlays, Shift line preview, Eyedropper sample square) are off until it ends; set and clear repaint the canvas once (GitHub issue 638).
- The center + of every footprint cursor, the tip cursor, Quick Select's Replace cursor and the overlay outline is `paint_brush_center_cross` (canvas_widget_shared): filled whole-pixel bars, a light core in a dark outline, never an antialiased 1 px line, which smeared to half brightness and, drawn after the dashed softness ring, took its faint blue (GitHub issue 425). `ui_brush_cursor_center_cross_is_two_tone`.
- The Alt+right-drag Size/Soft readout is the canvas HUD pill (`paint_canvas_hud_pill`, shared with the drag size readout), centered below the disc and kept clear of the rulers and edges (GitHub issue 422). `ui_brush_adjust_readout_is_a_hud_pill`.
- **Filter and floating windows (GitHub issue 506 follow-up).** The chooser is one `BrushTipBrowser` (brush_tip_picker.*) in both the popup and the floating Brush Tips window: a Filter field (`brushTipPickerFilterEdit`, name or folder, case-insensitive substring, combined with the folder combo; it has the keyboard when the popup opens, Enter picks the first match, Escape clears the text first and then closes the popup). The folder choice lives in the picker (remembered across openings); the text is never stored. The Brush Tips manager has the same field over its tree (`brushTipManagerFilterEdit`, `PresetTreeWidget::set_filter_text`; the scaffold keeps Delete bound to the tree). The popup's Keep Open button (`brushTipPickerKeepOpenButton`) or Window > Brush Tips (hotkey id `window.brush_tips`, no key; picks the Brush tool when the active tool takes no tip) opens the floating window; while it is open the picker raises it instead of a popup, and it follows the active tool's tip (`select_current`; library changes rebuild it on the next turn, never inside its own click). The window is a `BrushToolWindow` (brush_tool_window.*): a non-modal `Qt::Tool` dialog of the main window, position in the dialog position memory, size and open state in `brushes/tipsWindowSize`/`brushes/tipsWindowOpen` (reopened without activation at the next launch; MainWindow::closeEvent hides it without recording it closed). Its controls take no focus and every key no text field takes goes to the active canvas, so tool letters, `[`/`]` and Space keep working; registered shortcuts are `Qt::ApplicationShortcut` and fire from it anyway. On Wayland the compositor places it (no restored position). A tool without a tip, no document or a preview-dialog lock disables its content under a one-line reason (`refresh_brush_tool_windows`).
- **Grid labels and Import Brushes (GitHub issues 506 follow-up and 520).** Every grid item takes the whole cell (`tip_grid_cell_size`, item size hints; uniform item sizes sized every cell from Round's and cut names to one line). The names are a step under the dialog text (QSS `QListWidget#brushTipPickerList`, 10px, so it follows the interface text size), two lines per cell, then elided; the tooltip holds the full name. Both Import Brushes buttons (picker and manager) go through `get_abr_import_file_name` (brush_tip_library.*): the dialog opens in the folder it showed last, picked or cancelled (`brushes/lastImportDirectory`), or the platform default when that folder is gone. `ui_brush_tip_picker_labels_are_smaller_with_full_name_tooltips`, `ui_brush_tip_import_remembers_last_folder`.
- The tip picker popup resizes via an embedded QSizeGrip (a frameless Qt::Popup has no resize border); size persists as `ui/brushTipPickerPopupSize`, saved in closeEvent (outside-click dismissal goes through close()). The grip is custom-painted (`VisibleSizeGrip`; the native one is nearly invisible on themed chrome).

## Painting tool modifiers

The footprint-cursor tools (`tool_has_ctrl_temporary_move`, the same set as `tool_uses_brush_footprint_cursor`: Brush, Mixer, Pattern Stamp, Eraser, Clone, Healing, Spot Healing, Smudge, Dodge, Burn, Sponge, Blur, Sharpen) share their modifiers (GitHub issues 380, 421, 423):

- **Ctrl** (Command on macOS) is the temporary Move, read from the press's own modifiers and checked before the tool's own press. The four-way arrow shows while it is held (`update_tool_cursor`, before the Alt eyedropper: Ctrl+Alt is not the Move), from the folded modifiers of the key or hover event (`retouch_cursor_modifier_override_`). The press (`begin_paint_temporary_move`) starts the Move drag of the selected layers with Auto-Select off (`begin_move_drag`) and records `paint_ctrl_click_`. A drag clears it and moves; a release that never dragged selects the topmost layer with a visible pixel under the pointer (`select_paint_layer_at`, the first pass of `topmost_move_layer_at`, position locks ignored because the layer is picked for painting) and paints nothing; empty space keeps the selection. With nothing movable the press waits: a drag reports the lock or "Click an editable layer to move", a click still selects. `ui_paint_tools_ctrl_click_selects_layer_ctrl_drag_moves`.
- **Alt+right-drag** sets size and softness; **Shift+click** joins the last stroke with a straight line.
- **Shift held** (alone, no stroke running, pointer over the canvas) previews that line: a light line on a dark halo from `last_stroke_end_document_` to the pointer (GitHub issue 445; `stroke_connect_preview_line`, canvas_widget_brush.cpp). Mouse moves and folded Shift/Ctrl/Alt key events (`eventFilter`) refresh it; leaving the canvas, hiding the tab, a press, a tool switch or a new document clear it. Repaints cover only the old and new line bounds. Both ends map through the painted pixel's center (stroke points are pixel indices; the 1 px brush and the non-Brush tools use whole pixels, larger Brush, Mixer, Pattern Stamp and Eraser strokes the fractional pointer), never a pixel's corner (GitHub issue 505).
- **Stroke points are pixel indices.** The core brushes center a dab at index n on pixel n's center, so the canvas maps the pointer to `stroke_position_f` (its document position less half a pixel) for every fractional stroke point: press, coalesced moves, release, Shift line and the Smoothing leash (`widget_position_for_stroke_point` maps back). Drag dabs then sit on the pointer like the click dab (`ui_brush_drag_dabs_center_on_pointer`). Scripted strokes pass their own coordinates and are unaffected. `ui_paint_shift_line_preview_follows_pointer`, `ui_paint_shift_line_preview_starts_at_pixel_center`.
- Picking one of these tools shows a short status bar hint, `paint_tool_hint_source` (main_window_actions_tool_palette.cpp) with the tool name for `%1`: only what painting does not reveal (the tool's own Alt click, Shift+click line, Alt+right-drag), modifier names per platform; no "drag to paint" or Ctrl gestures, so it fits a small screen (GitHub issue 421 follow-up). `ui_paint_tool_hints_name_shared_gestures`.
