# Platform-specific tests

Split from [platform.md](platform.md): the tests that skip or relax off Windows and why, the font-face gates, and what the macOS and Linux suites need with the fixture corpus present.

## Per-platform test skips (keep this list current)

On macOS/Linux: `ui_bundled_legacy_plugin_action_applies_filter`, `ui_transparency_checkerboard_and_copy_paste_preserve_alpha`, `ui_legacy_plugin_run_respects_selection_and_undoes`, `ui_legacy_plugin_mehdi_filters_run_if_available`, `ui_legacy_plugin_mehdi_dialog_capture_if_available`, `ui_legacy_plugin_menu_opens_folder_and_rescans` and `ui_about_dialog_has_plugins_folder_row` (the legacy 8BF host and its folder UI are Windows-only, docs/plugins.md; `ui_legacy_plugin_ui_absent_off_windows` runs there) plus the core `legacy_host_self_test_filters_fixtures_in_both_bitnesses` (not registered off Windows), and the two `ui_imported_psd_box_text_line_clip_*` tests (pin Windows Arial line metrics; CoreText/fontconfig differ by a few px). On macOS only: the chrome tests that skip without `use_custom_window_chrome()` ([wayland.md](wayland.md)). `ui_main_window_renders_color_controls` asserts frameless/badge/window-buttons **presence on Windows and Linux and absence on macOS**. Local-fixture tests `[SKIP]` on a remote until the corpus is copied ([testing.md](testing.md)).

Text tests additionally gate on the fixture's own face. All three guards live in `tests/ui/ui_test_support.cpp`, for two reasons: a substituted face turns a pinned geometry tolerance into a measurement of the substitute, and a text session without the face raises the Missing Font prompt, which nothing answers under offscreen (the suite HANGS in the nested dialog loop).

- `skip_without_arial_for_psd_text_preview()` gates the Arial-pinned PSD text tests in `psd_text_import_tests.cpp`, the three `ui_af_*` text tests, and three warp tests (`ui_warp_text_render_matches_photoshop_if_available`, `ui_warp_text_box_matches_photoshop_layout`, `ui_warped_text_allows_real_bold_face`). macOS ships Arial (`/System/Library/Fonts/Supplemental`) and runs them all; Linux ships Liberation, not Arial, and skips them.
- `skip_without_font_face(family, role)` gates on a face being reachable at all, matching MainWindow's family-or-`"family style"` split (Qt files Arial Black under family Arial, style Black). Candara (`restaurant-menu-inside.psd`) and Bookman Old Style (`dungeon-scroll-game-screen.psd`) are Windows-only; Georgia is Windows and macOS.
- `skip_without_psd_text_face(layer, family)` covers the other way a machine lands off the Windows baseline: the family the imported layer resolved to. PSD PostScript names go through DirectWrite on Windows and the Qt font database elsewhere (`install_font_database_psd_font_resolver` in `src/ui/psd_font_resolver.hpp`, installed by the app and the UI test main; the suffix-stripping heuristic in `psd_text_read.cpp` is the last resort; wasm stays heuristic-only so bundled alias families never reach imported metadata). The database resolver matches whole-family ("Arial Black") and family + style ("Arial" + "Black") faces with the DirectWrite output rules ([font-resolution.md](font-resolution.md)). The guard fires only when the face was absent at read time: the `snes-box-a3.psd` probes run on Windows and macOS and skip on Linux (no Arial Black). Register a fixture's face BEFORE reading the PSD.

## Remote suites with the fixture corpus present

`local-test-fixtures/` is copied to the mac and linux build hosts, so both remotes run the fixture-gated text tests and every suite must pass there; a `[SKIP]` line reports each thing a machine cannot cover (one per missing `local-test-fixtures` PSD). `composite_corpus_flatten_digests_are_stable` runs against the tracked baselines in `test-fixtures/psd` everywhere: the CPU compositor is byte-identical across Windows, macOS arm64/clang, Linux x86-64/GCC and wasm. Never re-pin those baselines per machine.

Most corpus differences are the face gates listed above; two tests needed something else:

- `ui_duke_psd_text_runs_survive_reedit` reflows `Duke nukem mobile.psd`'s body between the first and second apply. Its face (FuturaLT-ExtraBold) is installed nowhere, so each platform's substitute reflows: 30px on Windows, 102 on macOS, 127 on Linux. Windows keeps the measured 64/32px bound; elsewhere it is a tenth of the block. The fixed point that follows (identical metadata, byte-identical third apply) is platform-independent.
- `ui_font_picker_applies_a_pick_the_control_already_shows` sets the picker to a family the database lacks. CoreText (and fontconfig on its first miss) then fills in aliases lazily, re-emitting the combo's current row, whose handler writes the displayed family back over the missing one; aliases fill once, so the test sets it twice. `ui_text_font_picker_preview_shows_supported_scripts` likewise takes the first Japanese family the PICKER lists, not the database's first: `QFontComboBox`'s model drops families the database still reports.
