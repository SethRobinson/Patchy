# Customize Tool Palette dialog

The dialog of [tool-palette.md](tool-palette.md#customizing-the-palette), which owns the palette's customization, its settings keys and the rule that only what the user hid is stored.

- Customize Tool Palette (GitHub issues 213, 316 and 199): `src/ui/tool_palette_customization.{hpp,cpp}` holds the choice, its settings, the dialog (`toolPaletteCustomizeDialog`, non-modal, one at a time; a second way in raises it on the asked tab) and its painted preview; `src/ui/tool_palette_layout.{hpp,cpp}` (`ToolPaletteLayout`) builds the palette's items. Ways in: Window > Customize Tool Palette... (`window.customize_tool_palette`, no default key), the first entry of the palette's right-click menu, Preferences > Application's Customize Tool Palette... button, on its own line under the tool palette settings (`preferencesCustomizeToolPaletteButton`; the dialog opens as Preferences' child, so it closes with it), the Layers footer menu and Customize Layers Panel... in the Layers panel settings gear's menu (both on the Layers Panel tab; the gear: [layer-thumbnails.md](layer-thumbnails.md#layers-panel-settings-gear)); the title row's right-click menu stays the panel list (Seth, October 29, 2026: other panel headers list no panel options there). Coverage: `ui_layers_panel_gear_opens_layer_button_customize`. The palette has no gear (it starts with Move): the retired setting `toolPalette/showCustomizeButton` is never reused, and `patchy.ui.toolPalette.showGearButton` is accepted and ignored. Rows are at least 26 px tall (`QTreeWidget#toolPaletteCustomizeTree::item` QSS); the shortcut keys end 12 px before the list's right edge, where the scrollbar sits, through `ShortcutColumnDelegate` (an item `padding-right` in QSS only widens the column: right-aligned text still ends flush with the cell, issue 213 follow-up; `ui_tool_palette_footer_items_hide_and_preview` measures the drawn pixels), and the cluster headings take their font height plus 18 px, bottom-aligned; the headings and the keys get `text_secondary` from their column delegates when painted, so a scheme change while the dialog is open recolors them (GitHub issue 499 comment); `ToolPaletteCustomizeTree::drawBranches` draws a heading's expand sign in its text band so the two line up (issue 213 follow-up); the Layers Panel tab's rows 30 px. The Tools tab is three columns: the tree (its key column left aligned, GitHub issue 499), the options (Layout with No tool groups `toolPaletteUngroupToolsCheck`, then Buttons: Toolbar icon size `toolPaletteIconSizeCombo` and Open tool groups on, then Bottom of the palette: `toolPaletteShowColorsCheck`, `toolPaletteShowQuickMaskCheck`, `toolPaletteShowScreenModeCheck`, `toolPaletteShowExpandButtonCheck`, `toolPaletteShowScrollArrowsCheck`, the last two off with a tooltip while wheel scrolling is off), and the preview, which draws the flyout corner arrow on group slots and the footer rows shown (centered under two columns), at the chosen icon size. Every combo in the dialog is at least 90 px wide (as in Preferences) and opens a list as wide as its widest entry (`fit_combo_popup_to_entries`; GitHub issue 537, `ui_tool_palette_customize_combos_show_their_entries` in English, German and Russian). The dialog is resizable (`toolPaletteCustomizeSizeGrip` in the button row; frameless chrome has no native border) and opens at its natural size (about 505 px tall), or the size last dragged to (`toolPalette/customizeDialogSize`, stored only when the size changed), bounded by the screen's available area; the tree's minimum is 340 x 200, so the options column sets the minimum height. The preview takes its column's height (`QSizePolicy::Expanding`, size hint = minimum = one row, the gap and the footer) and draws every row of tools that fits at the real icon size, then the footer; only when rows are left out does it cut the strip at a torn gap, two zigzag edges in `tool_palette_separator` with the gap left unpainted so the dialog shows through (GitHub issue 499 comment). Below the strip the column stays empty. Its `toolRows`, `shownToolRows` and `stripHeight` properties carry the counts and the painted height (`ui_tool_palette_customize_preview_fits_its_height`). The icon size and group opening are Preferences settings under their own keys (`ToolPaletteDialogChoice` carries them beside the customization): OK applies them through `MainWindow::apply_tool_palette_preferences`, which also moves the combos of an open Preferences or customize dialog, so the two never disagree; Preferences' OK goes through the same call. OK applies live and stores (`MainWindow::apply_tool_palette_customization`), Cancel changes nothing, Reset to Default restores both tabs, the footer order included. The Layers Panel tab lists the footer buttons in footer order (GitHub issue 471): `layerFooterOrderUpButton` and `layerFooterOrderDownButton` beside the list move the current row (each off where it would do nothing), and the list drags rows (`InternalMove`; rows have no `ItemIsDropEnabled`, so a drop lands between rows). Coverage: `ui_tool_palette_dialog_reorders_layer_buttons`. Above the list, beside `layerFooterIconSizeCombo` (Icon size:), `layerFooterPresetCombo` (Preset:) offers Patchy (the default order and hidden set), Adobe Photoshop, Affinity Photo, GIMP, Krita and Custom (`LayerFooterPreset`, `apply_layer_footer_preset`): a preset shows its buttons in its order and hides the rest after them, picking Custom changes nothing, and any tick, move or drag re-matches the rows, so the combo says Custom unless they match a preset again. No key stores the preset: `matching_layer_footer_preset` compares the shown buttons in order (hidden ones' places do not count), on open and after every change; Reset to Default is Patchy. **Rule (Seth, October 27, 2026, #471): keep the other editors' presets.** They only order and hide Patchy's own buttons and icons, so they do not reproduce another product's layout under the AGENTS.md interface rule; a preset lists only buttons Patchy has (none for their live filter, anchor or properties buttons; Adobe Photoshop's starts with Link Layers, #656). Names are nominative product names, translators keep them, and README.md's Trademark Notice covers them ([legal-licensing.md](legal-licensing.md#format-copyright-trademarks-and-assets)). Coverage: `ui_layer_footer_presets_set_order_and_shown_buttons`, `ui_tool_palette_dialog_layer_button_presets`. Scripts read and set it through `patchy.ui.toolPalette` ([scripting-api-changes.md](scripting-api-changes.md)). Dragging tool rows to reorder the palette (mockup 1) is not built.
