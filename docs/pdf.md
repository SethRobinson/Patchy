# PDF import and export

PDF has NO registry row: the writer branch lives in `write_flat_image_file` (image_document_io.cpp) and opening intercepts before the registry lookup in `load_document_from_path` (the page picker needs to run first). The `file_format_entries()` row carries both halves; the open half is conditional on `pdf_import_is_available()`. The open-dialog filter contract and the layered-save guard are in [file-formats.md](file-formats.md).

## Export (`ui/pdf_export.{hpp,cpp}` + `ui/pdf_export_editable.cpp`, always built, wasm included)

One page sized `pixels / document PPI` inches per axis via `print_detail::document_{horizontal,vertical}_ppi`, zero margins, `QPageSize::ExactMatch` so a nearly-Letter page cannot snap to Letter, device resolution pinned to the document PPI (`pdf_detail::configure_document_page`, shared by both modes). PDF caps a page at 14400 points; larger shrinks to the cap, pixels untouched. `PdfExportOptions` members, in order: `lossless`, `editable_layers` (decided per save, below), `missing_fonts_as_images` (persists as `saveOptions/pdfMissingFontsAsImages`, the PDF Options checkbox shown only while layers are kept), `jpeg_quality` (from the image-quality presets, below), `auto_grayscale`, `keep_original_image_data` (pass-through, below). Callers aggregate-initialize positionally: new members go last.

Scripts reach every choice through `doc.saveAs`/`doc.exportAs` and `app.exportPdf` with the same option names: `imageQuality` (a preset id), `lossless`, `editableLayers`, `keepOriginalImageData`, `missingFontsAsImages` (`ui/script_save_options.cpp`; `lossless` is applied first so a preset wins regardless of key order).

- **Image pages go through Patchy's own writer, `formats/pdf_image_writer` (Qt-free).** Qt's PDF engine can only write an image as Flate RGB (3 bytes per pixel even for gray content) or as JPEG at a fixed quality 94. `pdf::ImageWriter` streams one page at a time (only object offsets stay in memory), takes ALREADY encoded image streams, writes `%PDF-1.7` with a classic xref (64-bit offsets, a translated error past the ten-digit limit near 9.3 GB), no dates or ids (deterministic bytes), numbers through `format_pdf_number` (never the C locale), and streams into a sibling temporary that `finish()` renames over the destination (`AtomicFileReplacement`, [document-recovery.md](document-recovery.md)), so an unfinished or failed export leaves an existing file untouched and its destructor removes the temporary. The Qt-engine writers (`write_editable_pdf_document_file`, the multi-page Qt path) do the same through `pdf_detail::QtPdfOutput`; the text-merge pass rewrites that temporary, never the destination. `pdf_detail::encode_page_image` makes the stream from the composite: one pass finds gray (R == G == B on every pixel that is not fully transparent) and opaque; gray pages are one channel (`/DeviceGray`); `lossless` is Flate behind the PNG Up predictor (`/Predictor 12`), otherwise JPEG at `jpeg_quality` through `QImageWriter` (`Format_Grayscale8` gives a one-component JPEG); an 8-bit `/SMask` is written only when some pixel is not opaque. `write_image_pages` composites on the calling thread (the compositor already fans out over strips) and encodes on up to 4 `launch_async` workers, written in page order; it runs serially when `kBackgroundWorkRunsInline` or `max_blocking_fanout_workers` answers under 2 (wasm).
- **Image-quality presets** (`pdf_image_quality_presets`, permanent ids): `lossless`, `high` (JPEG 90, the dialog default), `medium` (75), `low` (50). Persisted as `saveOptions/pdfImageQuality`, shared by PDF Options (`pdfImageQualityCombo`) and Export Multi-Page PDF (`multiPagePdfImageQualityCombo`) through `populate_pdf_image_quality_combo`; a missing key means `high`. Never read the older `saveOptions/pdfLossless` bool as a choice (older builds rewrote it to `true` after every flat save of any format); it is still written for those builds. The `PdfExportOptions` and `ImageSaveOptions` struct defaults stay lossless, so scripts and the CLI never degrade pixels unasked. Pages that go through Qt's engine (below) keep Qt's two choices: Flate RGB, or JPEG 94 for every lossy preset. Tests assert the FILTER and colour space in the bytes (`/FlateDecode` vs `/DCTDecode`, `/DeviceGray` vs `/DeviceRGB`), never absolute file sizes, which flip sign with the content.
- **Flat mode (default)**: the page is `flat_export_qimage(document, true)` through the image writer, so doc-alpha exports non-destructively as an `/SMask`.
- **Routing in editable mode**: a page whose visible content is exactly one pixel layer (`pdf_detail::document_is_single_raster_layer`: no shape, text, adjustment, or second visible leaf) could only ever be one image, so it takes the image writer and its codecs; every raster-imported PDF page is this case. Anything else keeps Qt's engine. One `QPdfWriter` makes one file, so in a multi-page export a single page that needs Qt sends every page that way. `write_print_pdf` stays on Qt.
- **Pass-through of an imported page's own image (`keep_original_image_data`).** When the import can prove a page is exactly one image it keeps that image's encoded stream on the document (`DocumentMetadata::pdf_source_page`, `core/pdf_source_page.hpp`: its own field, never in `values`, so no file writer serializes it; `shared_ptr` payloads, so copies and undo snapshots cost nothing). `write_image_pages` composites each page as usual, and when `document_matches_pdf_source` holds it writes `pdf_detail::source_image_page` instead of encoding: the source's bytes, filter, colour space (an `/ICCBased` profile is written once and shared by every page that uses it), `/Decode`, the crop-box page size, `/Rotate`, and the image's own placement matrix (real scans place the image a fraction of a point larger than the page, and the reference file's pages are `/Rotate 270`). "Unchanged" is a fingerprint, not a revision: `pdf_composite_hash` over the size and RGBA bytes of `flat_export_qimage(document, true)`, stamped at import and compared at export, plus the document's pixel size and PPI. Any visible edit re-encodes that page only, an undo back to the imported pixels passes through again, and a hidden layer or a rename changes nothing. The option persists as `saveOptions/pdfKeepOriginalImages` (default on; `pdfKeepOriginalCheck` and `multiPagePdfKeepOriginalCheck`, shown only while some document carries source data, through `ImageSaveOptions::pdf_original_image_data_available`). An image-writer page written this way probes as a source page again, so a second generation passes through too. Tests: `pdf_probe_*`, `pdf_image_writer_repeats_rotation_placement_and_profile`, `ui_pdf_pass_through_*`. Not covered by a test: an ENCRYPTED source (the bytes come from `File::stream_data`, which decrypts; the only encrypted fixture has no image).
- **Editable mode ("Keep layers as editable objects")**: `pdf_detail::write_editable_pdf_document_file` walks the layer stack bottom-up through QPainter on QPdfWriter with `setWindow(document pixel grid)`, so every object draws in document coordinates. The walk, barrier rule, combine classification, gradient geometry/stops, and shape representability are the Qt-free plan in `formats/vector_export_plan.{hpp,cpp}` shared with SVG export ([svg.md](svg.md) "Export" has the representability rules). Per object:
  - Shape layers: `QPainterPath` (even-odd; SeparatePaths combine forms draw one path per Add group), solid/gradient/pattern brushes, `QPen` strokes (dashes and offset in pen widths, so a doubled pen halves them; Qt's miter limit is Patchy's / 2 because Qt measures in whole pen widths). Inside alignment = double width under a self clip; Outside = double width drawn under the opaque fill. A pattern fill is a texture brush transformed by translate(phase), rotate(-angle), scale: the angle is counterclockwise-positive and Qt's `rotate()` is clockwise on the y-down page (`ui_pdf_export_editable_pattern_fill_rotates_like_canvas`). Pattern STROKES rasterize. Vector masks become `setClipPath(IntersectClip)` (inverted via canvas rect + even-odd).
  - Text layers: real text with embedded subset fonts and ToUnicode, drawn by `draw_text_layer_to_painter` (`ui/text_layer_painter.hpp`, implemented in main_window.cpp): the same `TextRenderPlan` the layer's raster came from, drawn through the layer's canonical text transform, so glyphs land exactly on the raster. Refused (and rasterized, the notice naming why) only for warped text and placeholder rasters. An **imported Photoshop type layer** (`patchy.text.raster_status` = `psd_raster_preview`, or a `patchy.psd.text.transform` the Patchy transform still equals, which an import-time regenerated preview also has) is the common case and is re-laid-out by Patchy: its PSD transform is anchored at the first BASELINE while the plan's local origin is the layout top, so `imported_preview_text_plan_transform` places it the way a commit would. Box text: the PSD `boxBounds` top-left is the plan's local (0,0), and the editor's advance calibration (`calibrated_box_text_metric_scale`, run at the raster's scale) keeps the wrapping the raster has. Point text: the re-rendered ink pinned to the source raster's ink (justification fraction along x, top along y, like `anchored_text_transform_for_pixels`); scaled/rotated point text reuses the free-transform alignment (`psd_point_text_local_bounds_transform_for_pixels`, then the document-bounds fallback). **A missing font is substituted** (Qt's fallback face, as an edit does) with a notice naming the font; `missing_fonts_as_images` embeds the layer's pixels instead, and an imported preview with no font name ("PSD Text") counts as missing. **Qt embeds a face only when its `FaceId` carries a file name, which an APPLICATION font never has on Windows**: for those families QPdfEngine draws glyph outlines instead and the page holds no text (it re-imports as shape layers). So Patchy never registers a system font file it does not have to ([fonts.md](fonts.md)); text in a bundled or user-dropped font still exports as outlines.
  - **Post-pass `formats/pdf_text_merge` (Qt-free), run on the written file.** Qt's engine emits every glyph as its own `x y Td <g> Tj` and maps the space glyph to U+0009 in ToUnicode, so importers read one object per LETTER with tabs for spaces. `merge_glyph_runs_in_qt_pdf` reparses the file with `pdf::File`, folds each `BT..ET` block's same-baseline glyphs into one `Td [<g..> k <g..>] TJ` whose kerns come from the font's `/W` (or `/Widths`) so positions are unchanged (a new baseline or any other operator ends the run; a lone glyph stays a `Tj`), rewrites U+0009/0A/0D ToUnicode destinations to U+0020 in place (same length), re-Flates the content, replaces the stream dictionary + data with a direct `/Length` (Qt's indirect length object is left unused), and shifts the classic xref table and `startxref` by the byte delta. Stream extents come from `raw_stream_bytes` (RawStream::data_length is 0 for an indirect /Length). Anything off-pattern (content arrays, non-Flate filters, an xref stream, encryption, parse notices) leaves the file as Qt wrote it. `pdf_text_merge_folds_qt_glyph_runs_into_tj` pins the content, the xref, and the importer's view.
  - Pixel and smart-object layers: the layer flattened alone through the compositor (styles, masks, smart filters bake in), cropped to its alpha bounds, drawn as one image at the layer opacity. Silent: an image is their natural form.
  - Qt's PDF engine writes NO blend modes, transparency groups, or soft masks, so: every non-Normal blend (and every adjustment layer) is a barrier that merges everything below it at that sibling level into one image; a group with opacity, a non-Normal/pass-through blend, a raster mask, or a style rasterizes whole; a raster mask on a vector or text layer sends it through the compositor; clipping-mask runs bake as a unit. Hidden layers (and the clipped run a hidden base owns) are dropped before the walk, so they neither paint nor count as barriers. Each loss is a notice; `write_flat_image_file` forwards them and `export_notes_suffix_for` puts the first one in the status message.
  - **Choosing the mode**: a layered document (`flat_save_discards_layers`) going to .pdf from Save As, Export, or an unconfirmed `save_document_to_path` never sees the generic "Layers Will Be Flattened" prompt; `MainWindow::resolve_pdf_layer_choice` asks "Keep Layers Editable / Flatten to One Image / Cancel" (`pdfLayersMessageBox`, with a Remember checkbox) unless the preference `saveOptions/pdfLayerPolicy` (`ask` default / `flatten` / `editable`, Preferences "Saving layered documents as PDF") answers silently. The answer rides `ImageSaveOptions::pdf_editable_layers` for that save only (never a persisted save default); PDF Options has no checkbox for it; while layers are kept it shows the fidelity banner (`pdfEditableLayersWarning`) and `pdfMissingFontsAsImagesCheck`, and grays the Scale combo (the layered branch runs before `export_stand_in_document`, which would flatten, so no export transform applies). A linked smart-object child and CLI saves keep the flatten path; scripts opt in with `editableLayers`. Save As reports "Saved PDF copy with editable layers".
  - Verification: `ui_pdf_export_editable_*` read the output back through Patchy's own Qt-free `pdf::read_page_as_vectors` (structure: shape/text/image counts, fill colors, text content) and through QPdfDocument/PDFium (pixels: mean RGB delta against the composite over white, < 6), so neither decoder is the writer.
- **Multi-page (File > Export > Multi-Page PDF, `write_multipage_pdf_file`, `app.exportPdf`; issue 19)**: one page per document, each sized by `pdf_detail::document_page_size`. Flat pages and all-raster editable exports go through `write_image_pages`. When some page needs Qt (routing above), one `QPdfWriter` writes every page, started with `setPageSize` + `newPage()`; the device resolution is fixed for the file (page 1's PPI), so every page maps its own pixel grid onto its sheet through `setViewport(paintRectPixels)` + `setWindow(document grid)` and runs `pdf_detail::paint_editable_document` (the single-page walk on an already-begun painter); the text-merge post-pass runs once on the finished file, and only when some layer actually went out as text (`paint_editable_document` reports `text_drawn`). The dialog (`ui/multipage_pdf_export_dialog`, `multiPagePdfExportDialog`) offers two page sources: every selected open document in list order (the shared document-order control, [import.md](import.md) "Folders of images"), or `documents_for_top_level_groups`: one copy of the active document per visible top-level group with the other top-level layers hidden (ungrouped root layers stay when "Draw ungrouped layers on every page" is on), top of the stack first so groups named Page 1, Page 2 come out in reading order; the group source is offered only when the active document has a visible top-level group. Page size in group mode is the whole canvas. Editable is ON by default (`exportOptions/multiPagePdfEditableLayers`), unlike the single-page Save As policy prompt. The writer takes a per-page progress callback (`PdfPageProgress`; false cancels, the partial temporary is removed, an existing destination is kept, and the writer returns false) that the handler feeds from a cancellable `QProgressDialog` (`multiPagePdfProgressDialog`, "Writing page N of M"). Settings: `exportOptions/multiPagePdf{Source,UngroupedLayers,EditableLayers}` plus the shared `saveOptions/pdfImageQuality`; the missing-fonts choice rides `saveOptions/pdfMissingFontsAsImages` unprompted. Tests: `ui_pdf_export_multipage_*`, `ui_multipage_pdf_dialog_lists_documents_and_groups`, `ui_script_export_pdf_writes_pages`. The folder round trip (Export Documents to Folder, Open Folder) is in [import.md](import.md).

## Import

- **Editable import is the dialog's default:** the Qt-free `formats/pdf_{syntax,filters,file,fonts,content,document_io}` family parses files (lenient xref/object-stream/rebuild, all non-image filters, simple + Type0 fonts with /Differences and /ToUnicode) and interprets one page's content stream. Paths become vector shape layers (nonzero via shared `formats/vector_fill_rule`, even-odd in one group; clips become vector masks with `Intersect` groups). Each show-text operator becomes one text layer: a whole `TJ` array is ONE run (its strings concatenate and the kerning numbers fold into `intended_width`; only a jump of >= 1000 thousandths, positioning rather than kerning, ends the run; ToUnicode control characters U+0009/0A/0D read as spaces). `MainWindow::render_pending_pdf_text_layers` finishes each style run, rendering through glyph-space matrix `patchy.pdf.text_xfrm` and clamping an x-scale correction against `patchy.pdf.text_intended_width` so substituted fonts keep run widths; PDF has no paragraphs, so one layer per run is the honest unit. Images become embedded smart objects (DCT bytes verbatim, else `formats/pdf_png_writer`; the quad keeps rotation, `render_pending_pdf_image_layers` bakes pixels). Shadings/tiling patterns/Separation tints/soft masks approximate with a notice; editable failure falls back to raster. Standard RC4/AES user and owner passwords import; custom security handlers refuse. `formats/affine.hpp` is shared with SVG.
- **One `pdf::PageReader` per import.** `read_page_as_vectors(bytes, options)` opens the file on every call (a copy of the whole file plus the cross-reference and page-tree parse, per page). `PageReader` (formats/pdf_document_io.hpp) owns one `pdf::File` for the editable pages, the probe, and the source capture of flattened pages; the span functions are thin wrappers over it. Not for concurrent use (the file's object caches are unlocked): one thread at a time, any thread. A file Patchy's own parser cannot open still imports through PDFium, without those extras.
- **The page probe (`PageReader::probe_page`, `PageProbe`)** walks a page with `ContentOptions::decode_images` off (`probe_page_content`): `on_image` still fires with the transform, size, `PlacedImage::source`, and the codec read from the filter chain, but no image stream is read or decoded. It counts VISIBLE primitives (an opaque image that covers the whole page resets the counts, so a background rectangle under a scan is not content; invisible render-mode-3 text, an OCR layer, is never emitted), measures how much of the page is images the editable reader cannot decode (JPEG 2000, CCITT, JBIG2), reports `/Annots`, and fills `source_page` when the page is exactly one opaque image an export can carry verbatim: DCT or JPX, DeviceGray / DeviceRGB / ICCBased with N 1 or 3 / none (JPX), no `/SMask`, `/Mask`, `/SMaskInData`, stencil, constant alpha, or blend mode, every canvas corner inside the image's quad (slack 1e-3 of the image), and no clip except axis-aligned rectangles that contain the page. CMYK, Indexed, Cal*, Lab and Separation are refused rather than approximated.
- **Scanned pages flatten, once, with one notice.** The Import PDF dialog probes every selected page first. A page that is only undecodable images, or at least half covered by them, goes straight to the raster path: the editable reader would drop the scan and keep only what sits on top (an OCR'd scan would come in as loose text on an empty page), and a pure scan would pay a full parse and a throw before the PDFium render anyway. All pages scans: the whole selection takes the flatten path (with read-ahead, below). The notice is one plural line, not one per page.
- **Rendering is a two-stage pipeline off the UI thread** (`render_pages`): when the caller reports progress on the GUI thread, `render_page_image` (PDFium) runs through `launch_async` with one page of read-ahead, and `finish_rendered_page` (trim, `document_from_qimage`, probe, source stamp) runs on a second worker while the NEXT page renders; results are taken in page order, at most two pages of pixels in flight besides the one rendering, and the UI thread only pumps events. PDFium's global lock means two pages never render at once; the pipeline buys a live progress dialog, a Cancel that answers mid-page, and the conversion hidden behind the next render. The probe takes a mutex because a `PageReader` is one thread at a time and two finishing steps can overlap. The non-interactive load (which may itself be on a worker) renders inline. Separate-documents mode builds each `Document` where the pixels are hot and drops the frame at once.
- **The page picker never renders before it shows.** Rows start with a transparent icon of the right shape and `pdfImportThumbnailTimer` (zero interval) renders one thumbnail per tick, rows on screen first, and stops on `QDialog::finished`: the import renders through the same `QPdfDocument` from a worker, so no thumbnail may start once the dialog is closing. The size label (`pdfImportSizeLabel`) adds "About N GB of memory" once the selection's RGBA pixels pass 0.5 GB, and says so more firmly past half of `total_physical_ram_mb()`.
- **Pages become documents or layers ("Pages become:" combo, `pdfImportPagesTargetCombo`, setting `imports/pdfPagesTarget`; issue 19).** Separate documents is the default and Photoshop's behavior: `PdfImportOptions::separate_documents` makes every selected page its own `Document` at its own size (page 1 in `PdfImportResult::document` with `document_title`, the rest in `extra_documents`), and `MainWindow::open_extra_imported_page_sessions` opens one pathless session per extra page titled "file.pdf - Page N" (page 1 keeps the file path and the same title form) through `add_document_session(..., SessionActivation::Background)`: a tab and a session but no tab switch, panel rebuild, composite, or paint, so page 1 stays active. A background session sets `DocumentSession::fit_view_on_first_activation`; `activate_document_canvas` fits it the first time its tab is selected, and once more from a zero timer after the newly shown page has its real geometry. In this mode the editable reader runs once per selected page (a page it cannot model flattens alone, with a notice, and the rest stay editable). "Layers in one document": raster pages stack as "Page N" layers through `document_from_frames` (only the first visible), and editable import brings in page 1 only, because editable objects from several pages cannot honestly share one canvas. The non-interactive path (CLI, scripts, Reopen, Files as Layers) imports page 1 flattened at the remembered `imports/pdfResolution`. **Progress:** the accepted dialog shows a cancellable `QProgressDialog` (`pdfImportProgressDialog`, "Importing page N of M") driven by `PdfImportOptions::progress` (false = stop, keeping the pages done, with an "Import stopped after N of M pages" notice), and the session pass shows `pdfPagesProgressDialog` ("Opening page N of M") and pumps events after each `add_document_session` so tabs appear one by one.
- **Raster import** (`ui/pdf_import.{hpp,cpp}`, the "Flattened image per page" mode and the non-interactive default) needs the optional Qt PDF add-on, which wraps PDFium. Not in a stock Qt install and absent on wasm, so CMake uses its OWN `find_package` (a missing component in the main QUIET one would silently skip the whole app target), defines `PATCHY_HAVE_QT_PDF`, else builds `pdf_import_stub.cpp`. Stub builds still recognize `.pdf` as openable (`is_supported_open_path`), so a picked or dropped PDF fails with the stub's clear message; on wasm that message carries `kPdfDesktopOnlyMarker` and `show_open_failed_message_box` strips it and adds a "Get the Desktop Version" button linking to the GitHub download section (Store-button pattern). Provisioning: `-m qtpdf` in the mac/linux setup scripts; Windows: `aqt install-qt windows desktop <ver> win64_msvc2022_64 -m qtpdf --noarchives -O .deps\Qt`.
- **PDFium renders onto a TRANSPARENT page**, not white, and "Trim to content" compares full ARGB so vector and scanned borders both trim. **Qt PDF exposes no crop-box selection**: `pagePointSize` is CropBox intersected with MediaBox; Art/Bleed/Trim boxes are unreachable, so Photoshop's Crop To menu cannot be reproduced (the post-render trim plus a notice stands in). Raster pages cap at 20000 px per axis with a notice. The document adopts the chosen PPI, so PDF must never join `kDensitylessFormats`.
- **PDF is a read-only SOURCE** even though the writer exists: `is_read_only_source_extension` lists it explicitly, because an import is a rasterization at one resolution (and even the editable export loses adjustment layers, blend modes, and styles), so Save must never replace a multi-page vector file with a re-render. Save routes to Save As defaulting `.psd`; Save As and Export to `.pdf` still work.
- Fixtures are synthesized byte by byte in-test (xref offsets computed, never hand-counted).

## Performance and profiling

`PATCHY_UI_PROFILE=1` prints per-page stage timings to stderr (`ui/ui_profile.hpp`): `pdf_import.{thumbnails,read_file,vector_page,render,raster_fallback,trim,to_document}`, `open.{add_session,fit_to_view}`, `pdf_pages.{pending_layers,add_session,fit,pump}`, and `pdf_export.{page,composite,encode,write_page,new_page,raster_chunk_flatten,raster_chunk_draw,text_merge,finish}`. `patchy_perf_tests.exe pdfopen [file]` and `pdfsave [file]` time the whole flow (file from the argument, else `PATCHY_PERF_PDF`, else `local-test-fixtures/pdf/C2_Kyoto_House_Plans_Compressed.pdf`; `[SKIP]` when absent; `PATCHY_PERF_PDF_PAGES=<n|all>` caps the pages, default 8; `PATCHY_PERF_PDF_KEEP=1` keeps the written files). Both run with isolated settings and are never part of the default perf run.

Reference file: 86 MB, 85 pages, each one 3496x5019 8-bit gray JPEG 2000 image (about 1 MB per page), imported at 300 ppi. Per page on a 12900KS (September 2026 baseline):

| Step | Time | Note |
|---|---|---|
| PDFium render (`QPdfDocument::render`) | 490 ms on a P-core, to 1100 ms at below-normal priority | about 85% of the open. Decode-bound: smoothing flags change nothing, half size still costs 290 ms. PDFium is single-threaded behind Qt PDF's global lock, and no other JPEG 2000 decoder is linked, so this is the in-process floor |
| Open the `PageReader` + probe all 85 pages | 2 ms + 3 ms | routes scans straight to the flatten path |
| Thumbnail | 14 ms each | PDFium decodes JPX at reduced resolution for small targets; the dialog shows in about 50 ms |
| `document_from_qimage` + source capture (composite + hash) | 32 ms + 60 ms | on a second worker, hidden behind the next page's render |
| Session add + first paint pump | 6 ms | background sessions; the tab still appears as each is made |
| Qt-engine export: flat lossless / flat JPEG 94 / editable lossless | 2000 ms and 8.9 MB (8.8x the source) / 280 ms and 2.9 MB / 3100 ms and 8.9 MB | what a page routed to Qt costs. Composite is 29 ms; the rest is Qt converting and deflating RGB, plus a 1000 ms single-threaded `flatten_document_rgba8` per raster page in editable mode |
| Image-writer export: `lossless` / `high` (the default, editable on or off) / `medium` / `low` | 420 ms and 4.9 MB / 78 ms and 2.1 MB / 74 ms and 1.3 MB / 71 ms and 0.92 MB | gray one-channel data, 4 encode workers; wall time per page over an 8-page run |
| Export, untouched import (pass-through, the default) | 52 ms per page: all 85 pages in 4.5 s, 86,067,370 bytes against the source's 86,074,801 | every JPX stream byte-identical and in order, `/Rotate 270` and the placement matrix repeated; the time is the composite and its hash |
| Text-merge post-pass | 69 ms per 71 MB | skipped unless a layer went out as text |

Timing caveat: `run-throttled.bat` runs at below-normal priority, and on a hybrid CPU Windows moves sustained background-priority work to the E-cores after about 3 s, so the same render reads 490 ms early in a run and 1100 ms later. Judge import changes by the non-render stages, or by one real open with `PATCHY_UI_PROFILE=1`.

Not done, in order of what they would buy on a long scanned PDF:
- **Multi-process rendering.** PDFium's lock is per process, so N render-worker `patchy.exe` processes would cut the 85-page open from about 45 s to under 10 s here. Needs an early `main()` branch ahead of single-instance forwarding, a password channel off the command line, crash/cancel handling, and an in-process fallback.
- **Lazy page documents.** Decode a page's pixels the first time it is shown or edited (pass-through never needs untouched pixels); every reader of a document (thumbnails, scripts, commands) would have to cope with a pixel-less session.
- **Pass-through under edits.** With the imported layer unchanged and everything above it Normal, keep the original image and add the layers above as one cropped `/SMask` image.
- **Flate, CCITT, and JBIG2 pass-through** needs `File` to return a stream decrypted but still filtered (`stream_data` decodes everything except the image codecs). An image-stream replacement post-pass would give Qt-engine pages the same codecs.
