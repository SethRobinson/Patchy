# PDF import and export

PDF has NO registry row: the writer branch lives in `write_flat_image_file` (image_document_io.cpp) and opening intercepts before the registry lookup in `load_document_from_path` (the page picker needs to run first). The `file_format_entries()` row carries both halves; the open half is conditional on `pdf_import_is_available()`. The open-dialog filter contract is in [file-formats.md](file-formats.md), the layered-save guard in [file-formats-saving.md](file-formats-saving.md).

Related documents:

- [pdf-import.md](pdf-import.md): reading pages as editable layers (Patchy's own parser) or flattened images (PDFium), the page probe and scan routing, the Import PDF dialog and its options, and how pages become documents, layers or artboards.
- [pdf-editable-export.md](pdf-editable-export.md): the "Keep layers as editable objects" writer (each layer as a PDF object through Qt's engine), the glyph-run merge post-pass, what flattens, and its tests.
- [pdf-performance.md](pdf-performance.md): stage timings (`PATCHY_UI_PROFILE=1`), the `pdfopen`/`pdfsave` perf tests, the reference-file baseline and the open performance ideas.

## Rules for both directions

- **PDF is a read-only SOURCE** even though the writer exists: `is_read_only_source_extension` lists it explicitly, because an import is a rasterization at one resolution (and even the editable export loses adjustment layers, blend modes, and styles), so Save must never replace a multi-page vector file with a re-render. Save routes to Save As defaulting `.psd`; Save As and Export to `.pdf` still work.
- Fixtures are synthesized byte by byte in-test (xref offsets computed, never hand-counted).

## Export (`ui/pdf_export.{hpp,cpp}` + `ui/pdf_export_editable.cpp`, always built, wasm included)

One page sized `pixels / document PPI` inches per axis via `print_detail::document_{horizontal,vertical}_ppi`, zero margins, `QPageSize::ExactMatch` so a nearly-Letter page cannot snap to Letter, device resolution pinned to the document PPI (`pdf_detail::configure_document_page`, shared by both modes). PDF caps a page at 14400 points; larger shrinks to the cap, pixels untouched. `PdfExportOptions` members include `lossless`, `editable_layers` (decided per save, below), `missing_fonts_as_images` (persists as `saveOptions/pdfMissingFontsAsImages`, the PDF Options checkbox shown only while layers are kept), `jpeg_quality` (from the image-quality presets, below), `auto_grayscale`, `keep_original_image_data` (pass-through, below), and `pages` (`PdfPageSource`, tokens `artboards`/`groups`/`canvas`): one page per artboard (`documents_for_artboards`, [artboards.md](artboards.md)), one per top-level group (`documents_for_top_level_groups`), or the whole canvas. PDF Options (below) picks it. Callers aggregate-initialize positionally: new members go last.

Scripts reach every choice through `doc.saveAs`/`doc.exportAs` and `app.exportPdf` with the same option names: `imageQuality` (a preset id), `lossless`, `editableLayers`, `keepOriginalImageData`, `missingFontsAsImages`, `pages`, `artboardPages` (true = `artboards`, false = `canvas`) (`ui/script_save_options.cpp`; `lossless` is applied first so a preset wins regardless of key order).

- **Image pages go through Patchy's own writer, `formats/pdf_image_writer` (Qt-free).** Qt's PDF engine can only write an image as Flate RGB (3 bytes per pixel even for gray content) or as JPEG at a fixed quality 94. `pdf::ImageWriter` streams one page at a time (only object offsets stay in memory), takes ALREADY encoded image streams, writes `%PDF-1.7` with a classic xref (64-bit offsets, a translated error past the ten-digit limit near 9.3 GB), no dates or ids (deterministic bytes), numbers through `format_pdf_number` (never the C locale), and streams into a sibling temporary that `finish()` renames over the destination (`AtomicFileReplacement`, [document-recovery.md](document-recovery.md)), so an unfinished or failed export leaves an existing file untouched and its destructor removes the temporary. The Qt-engine writers (`write_editable_pdf_document_file`, the multi-page Qt path) do the same through `pdf_detail::QtPdfOutput`; the text-merge pass rewrites that temporary, never the destination. `pdf_detail::encode_page_image` makes the stream from the composite: one pass finds gray (R == G == B on every pixel that is not fully transparent) and opaque; gray pages are one channel (`/DeviceGray`); `lossless` is Flate behind the PNG Up predictor (`/Predictor 12`), otherwise JPEG at `jpeg_quality` through `QImageWriter` (`Format_Grayscale8` gives a one-component JPEG); an 8-bit `/SMask` is written only when some pixel is not opaque. `PdfExportOptions::cmyk_space` writes every page as four-component ICCBased CMYK instead, with an output intent ([cmyk.md](cmyk.md)). `write_image_pages` composites on the calling thread (the compositor already fans out over strips) and encodes on up to 4 `launch_async` workers, written in page order; it runs serially when `kBackgroundWorkRunsInline` or `max_blocking_fanout_workers` answers under 2 (wasm).
- **Image-quality presets** (`pdf_image_quality_presets`, permanent ids): `lossless`, `high` (JPEG 90, the dialog default), `medium` (75), `low` (50). Persisted as `saveOptions/pdfImageQuality`, shared by PDF Options (`pdfImageQualityCombo`) and Export Multi-Page PDF (`multiPagePdfImageQualityCombo`) through `populate_pdf_image_quality_combo`; a missing key means `high`. Never read the older `saveOptions/pdfLossless` bool as a choice (older builds rewrote it to `true` after every flat save of any format); it is still written for those builds. The `PdfExportOptions` and `ImageSaveOptions` struct defaults stay lossless, so scripts and the CLI never degrade pixels unasked. Pages that go through Qt's engine (below) keep Qt's two choices: Flate RGB, or JPEG 94 for every lossy preset. Tests assert the FILTER and colour space in the bytes (`/FlateDecode` vs `/DCTDecode`, `/DeviceGray` vs `/DeviceRGB`), never absolute file sizes, which flip sign with the content.
- **Flat mode (default)**: the page is `flat_export_qimage(document, true)` through the image writer, so doc-alpha exports non-destructively as an `/SMask`.
- **Routing in editable mode**: a page whose visible content is exactly one pixel layer (`pdf_detail::document_is_single_raster_layer`: no shape, text, adjustment, or second visible leaf) could only ever be one image, so it takes the image writer and its codecs; every raster-imported PDF page is this case. Anything else keeps Qt's engine. One `QPdfWriter` makes one file, so in a multi-page export a single page that needs Qt sends every page that way. `write_print_pdf` stays on Qt.
- **Pass-through of an imported page's own image (`keep_original_image_data`).** When the import can prove a page is exactly one image it keeps that image's encoded stream on the document (`DocumentMetadata::pdf_source_page`, `core/pdf_source_page.hpp`: its own field, never in `values`, so no file writer serializes it; `shared_ptr` payloads, so copies and undo snapshots cost nothing). `write_image_pages` composites each page as usual, and when `document_matches_pdf_source` holds it writes `pdf_detail::source_image_page` instead of encoding: the source's bytes, filter, colour space (an `/ICCBased` profile is written once and shared by every page that uses it), `/Decode`, the crop-box page size, `/Rotate`, and the image's own placement matrix (real scans place the image a fraction of a point larger than the page, and the reference file's pages are `/Rotate 270`). "Unchanged" is a fingerprint, not a revision: `pdf_composite_hash` over the size and RGBA bytes of `flat_export_qimage(document, true)`, stamped at import and compared at export, plus the document's pixel size and PPI. Any visible edit re-encodes that page only, an undo back to the imported pixels passes through again, and a hidden layer or a rename changes nothing. The option persists as `saveOptions/pdfKeepOriginalImages` (default on; `pdfKeepOriginalCheck` and `multiPagePdfKeepOriginalCheck`, shown only while some document carries source data, through `ImageSaveOptions::pdf_original_image_data_available`). An image-writer page written this way probes as a source page again, so a second generation passes through too. Tests: `pdf_probe_*`, `pdf_image_writer_repeats_rotation_placement_and_profile`, `ui_pdf_pass_through_*`. Not covered by a test: an ENCRYPTED source (the bytes come from `File::stream_data`, which decrypts; the only encrypted fixture has no image).
- **Editable mode ("Keep layers as editable objects")**: shape layers become PDF paths, text layers real text with embedded fonts, pixel and smart-object layers images, all through Qt's PDF engine; what that engine cannot express flattens into an image with a notice. The per-object rules, the glyph-run merge post-pass and the verification tests are in [pdf-editable-export.md](pdf-editable-export.md).
  - **Choosing the mode**: the editable check in PDF Options (below) decides it per save and rides `ImageSaveOptions::pdf_editable_layers` (never a persisted save default). A save that shows no dialog (Ctrl+S to a .pdf path, an unconfirmed `save_document_to_path`) asks `MainWindow::resolve_pdf_layer_choice`: the preference `saveOptions/pdfLayerPolicy` (`ask` default / `flatten` / `editable`, Preferences "Saving layered documents as PDF"), else "Keep Layers Editable / Flatten to One Image / Cancel" (`pdfLayersMessageBox`, with Remember). The layered branch runs before `export_stand_in_document`, so no export transform applies. A linked smart-object child and CLI saves keep the flatten path; scripts opt in with `editableLayers`. Save As reports "Saved PDF copy with editable layers".
- **Multi-page (File > Export > Multi-Page PDF, `write_multipage_pdf_file`, `app.exportPdf`; issue 19)**: one page per document, each sized by `pdf_detail::document_page_size`. Flat pages and all-raster editable exports go through `write_image_pages`. When some page needs Qt (routing above), one `QPdfWriter` writes every page, started with `setPageSize` + `newPage()`; the device resolution is fixed for the file (page 1's PPI), so every page maps its own pixel grid onto its sheet through `setViewport(paintRectPixels)` + `setWindow(document grid)` and runs `pdf_detail::paint_editable_document` (the single-page walk on an already-begun painter); the text-merge post-pass runs once on the finished file, and only when some layer actually went out as text (`paint_editable_document` reports `text_drawn`). Its page sources are PDF Options' (below); a group carrying `patchy.pdf.page_rect` (a PDF import's page folder) is cropped to that rect and keeps its page image for pass-through, any other group page is the whole canvas, and groups come top of the stack first so Page 1, Page 2 read in order. Editable is ON by default (`exportOptions/multiPagePdfEditableLayers`), unlike the single-page Save As policy prompt. The writer takes a per-page progress callback (`PdfPageProgress`; false cancels, the partial temporary is removed, an existing destination is kept, and the writer returns false) that the handler feeds from a cancellable `QProgressDialog` (`multiPagePdfProgressDialog`, "Writing page N of M"). Settings: `exportOptions/multiPagePdf{Source,UngroupedLayers,HiddenGroups,EditableLayers}` plus the shared `saveOptions/pdfImageQuality`; the missing-fonts choice rides `saveOptions/pdfMissingFontsAsImages` unprompted. Tests: `ui_pdf_export_multipage_*`, `ui_multipage_pdf_dialog_lists_documents_and_groups`, `ui_script_export_pdf_writes_pages`. The folder round trip (Export Documents to Folder, Open Folder) is in [import.md](import.md).
- **PDF Options** (`run_pdf_options_dialog`, `ui/multipage_pdf_export_dialog`, `multiPagePdfExportDialog`, widgets `multiPagePdf*`) is the one dialog every interactive PDF save shows, always after the file name: Save As and Export Flat Image to .pdf (title "PDF Options", button Save, this document's pages only; `MainWindow::prompt_pdf_options`) and Export Multi-Page PDF (button Export, adds one page per open document in the shared order list). Pages: the whole canvas (`multiPagePdfCanvasRadio`), each artboard, each top-level group (`documents_for_top_level_groups`; "Draw ungrouped layers on every page" and "Include hidden groups" become `PdfExportOptions::include_ungrouped_layers`/`include_hidden_groups`), or open documents. Save As starts on artboards, else an imported PDF's page folders, else the canvas; Export starts on the remembered `exportOptions/multiPagePdfSource` (`documents`/`groups`/`artboards`/`canvas`). The editable check (shown for a layered document) starts from `pdfLayerPolicy` when set, else the last answer (`exportOptions/multiPagePdfEditableLayers`); the missing-fonts check sits under it. `apply_pdf_choice_to_save_options` hands Save As the answer, so `save_document_to_path` asks nothing more. Sprite-sheet and image-sequence exports to PDF keep the per-format `pdfSaveOptionsDialog`. Tests: `ui_save_as_pdf_uses_the_pdf_options_dialog`, `ui_multipage_pdf_dialog_lists_documents_and_groups`.
