# PDF import and export

PDF has NO registry row: the writer branch lives in `write_flat_image_file` (image_document_io.cpp) and opening intercepts before the registry lookup in `load_document_from_path` (the page picker needs to run first). The `file_format_entries()` row carries both halves; the open half is conditional on `pdf_import_is_available()`. The open-dialog filter contract and the layered-save guard are in [file-formats.md](file-formats.md).

## Export (`ui/pdf_export.{hpp,cpp}` + `ui/pdf_export_editable.cpp`, always built, wasm included)

One page sized `pixels / document PPI` inches per axis via `print_detail::document_*_ppi`, zero margins, `QPageSize::ExactMatch` so a nearly-Letter page cannot snap to Letter, device resolution pinned to the document PPI (`pdf_detail::configure_document_page`, shared by both modes). PDF caps a page at 14400 points; larger shrinks to the cap, pixels untouched. `PdfExportOptions` is two bools (`lossless` persists as `saveOptions/pdfLossless`; `editable_layers` is decided per save, below):

- **Lossless is the default and the only real image choice.** Qt's PDF engine re-encodes every non-grayscale image as JPEG quality 94 unless the painter sets `QPainter::LosslessImageRendering`, with no quality knob. `write_print_pdf` sets the same hint for PDF output; printer jobs are left alone. Tests assert the FILTER in the bytes (`/FlateDecode` vs `/DCTDecode`), never file sizes, which flip sign with the content.
- **Flat mode (default)**: one `drawImage` of `flat_export_qimage(document, true)`, so doc-alpha exports non-destructively; Qt writes transparency as an `/SMask` (a 1-bit `/ImageMask` when the alpha is two-level).
- **Editable mode ("Keep layers as editable objects", August 2026)**: `pdf_detail::write_editable_pdf_document_file` walks the layer stack bottom-up through QPainter on QPdfWriter with `setWindow(document pixel grid)`, so every object draws in document coordinates. The walk, barrier rule, combine classification, gradient geometry/stops, and shape representability are the shared Qt-free plan in `formats/vector_export_plan.{hpp,cpp}` that SVG export also uses (one policy, two writers; see [svg.md](svg.md) "Export" for the representability rules). Per object:
  - Shape layers: `QPainterPath` (even-odd; SeparatePaths combine forms draw one path per Add group), solid/gradient/pattern brushes, `QPen` strokes (dashes and offset in pen widths, so a doubled pen halves them; Qt's miter limit is Patchy's / 2 because Qt measures in whole pen widths). Inside alignment = double width under a self clip; Outside = double width drawn under the opaque fill. Pattern STROKES rasterize. Vector masks become `setClipPath(IntersectClip)` (inverted via canvas rect + even-odd).
  - Text layers: real text with embedded subset fonts and ToUnicode, drawn by `draw_text_layer_to_painter` (`ui/text_layer_painter.hpp`, implemented in main_window.cpp): the same `TextRenderPlan` the layer's raster came from, drawn through the layer's canonical text transform, so glyphs land exactly on the raster. Refused (and rasterized) for warped text and for rasters Patchy did not render (`patchy.text.raster_status` other than `patchy_raster`: a PSD preview kept for a missing font). **Qt embeds a face only when its `FaceId` carries a file name, which an APPLICATION font never has on Windows**: for those families QPdfEngine draws glyph outlines instead and the page holds no text (it re-imports as shape layers). Patchy therefore never registers a system font file it does not have to (docs/fonts.md); text in a bundled or user-dropped font still exports as outlines.
  - **Post-pass `formats/pdf_text_merge` (Qt-free), run on the written file.** Qt's engine emits every glyph as its own `x y Td <g> Tj`, and its ToUnicode maps the space glyph to U+0009 (lowest code point sharing the glyph), so importers (Patchy, Affinity) read one object per LETTER with tabs for spaces. `merge_glyph_runs_in_qt_pdf` reparses the file with `pdf::File`, folds each `BT..ET` block's same-baseline glyphs into one `Td [<g..> k <g..>] TJ` whose kerns come from the font's `/W` (or `/Widths`) so positions are unchanged (a new baseline or any other operator ends the run; a lone glyph stays a `Tj`), rewrites U+0009/0A/0D ToUnicode destinations to U+0020 in place (same length), re-Flates the content, replaces the stream dictionary + data with a direct `/Length` (Qt's indirect length object is left unused), and shifts the classic xref table and `startxref` by the byte delta. Stream extents come from `raw_stream_bytes` (RawStream::data_length is 0 for an indirect /Length). Anything off-pattern (content arrays, non-Flate filters, an xref stream, encryption, parse notices) leaves the file as Qt wrote it. `pdf_text_merge_folds_qt_glyph_runs_into_tj` pins the content, the xref, and the importer's view.
  - Pixel and smart-object layers: the layer flattened alone through the compositor (styles, masks, smart filters bake in), cropped to its alpha bounds, drawn as one image at the layer opacity. Silent: an image is their natural form.
  - Qt's PDF engine writes NO blend modes, transparency groups, or soft masks, so: every non-Normal blend (and every adjustment layer) is a barrier that merges everything below it at that sibling level into one image; a group with opacity, a non-Normal/pass-through blend, a raster mask, or a style rasterizes whole; a raster mask on a vector or text layer sends it through the compositor; clipping-mask runs bake as a unit. Hidden layers (and the clipped run a hidden base owns) are dropped before the walk, so they neither paint nor count as barriers. Each loss is a notice; `write_flat_image_file` forwards them and `export_notes_suffix_for` puts the first one in the status message.
  - **Choosing the mode**: a layered document (`flat_save_discards_layers`) going to .pdf from Save As, Export, or an unconfirmed `save_document_to_path` never sees the generic "Layers Will Be Flattened" prompt; `MainWindow::resolve_pdf_layer_choice` asks "Keep Layers Editable / Flatten to One Image / Cancel" (`pdfLayersMessageBox`, with a Remember checkbox) unless the preference `saveOptions/pdfLayerPolicy` (`ask` default / `flatten` / `editable`, Preferences "Saving layered documents as PDF") answers silently. The answer rides `ImageSaveOptions::pdf_editable_layers` for that save only (never a persisted save default); the PDF Options dialog has no checkbox for it, only the fidelity warning banner (`pdfEditableLayersWarning`) while layers are kept, and the export Scale combo grays out then (vectors scale with the page; `export_scale` is forced to 1 and the layered writer bypasses `scaled_flat_document`, which would flatten first). A linked smart-object child and CLI saves keep the old flatten path. Save As reports "Saved PDF copy with editable layers".
  - Verification: `ui_pdf_export_editable_*` read the output back through Patchy's own Qt-free `pdf::read_page_as_vectors` (structure: shape/text/image counts, fill colors, text content) and through QPdfDocument/PDFium (pixels: mean RGB delta against the composite over white, < 6), so neither decoder is the writer.

## Import

- **Editable import is the dialog's default:** the Qt-free `formats/pdf_{syntax,filters,file,fonts,content,document_io}` family parses files (lenient xref/object-stream/rebuild, all non-image filters, simple + Type0 fonts with /Differences and /ToUnicode) and interprets one page's content stream. Paths become vector shape layers (nonzero via shared `formats/vector_fill_rule`, even-odd in one group; clips become vector masks with `Intersect` groups); each show-text operator becomes one text layer (a whole `TJ` array is ONE run: its strings concatenate and the kerning numbers fold into `intended_width`; only a jump of >= 1000 thousandths, positioning rather than kerning, ends the run; ToUnicode control characters U+0009/0A/0D read as spaces) (style run, finished by `MainWindow::render_pending_pdf_text_layers`, which renders through glyph-space matrix `patchy.pdf.text_xfrm` and clamps an x-scale correction against `patchy.pdf.text_intended_width` so substituted fonts keep run widths; PDF has no paragraphs, so one layer per run is the honest unit); images become embedded smart objects (DCT bytes verbatim, else `formats/pdf_png_writer`; the quad keeps rotation, `render_pending_pdf_image_layers` bakes pixels). Shadings/tiling patterns/Separation tints/soft masks approximate with a notice; editable failure falls back to raster. Standard RC4/AES user and owner passwords import; custom security handlers refuse. `formats/affine.hpp` is shared with SVG.
- **Raster import** (`ui/pdf_import.{hpp,cpp}`, the "Flattened image per page" mode and the non-interactive default) needs the optional Qt PDF add-on, which wraps PDFium. Not in a stock Qt install and absent on wasm, so CMake uses its OWN `find_package` (a missing component in the main QUIET one would silently skip the whole app target), defines `PATCHY_HAVE_QT_PDF`, else builds `pdf_import_stub.cpp`. Provisioning: `-m qtpdf` in the mac/linux setup scripts; Windows: `aqt install-qt windows desktop <ver> win64_msvc2022_64 -m qtpdf --noarchives -O .deps\Qt`.
- **PDFium renders onto a TRANSPARENT page**, not white, and "Trim to content" compares full ARGB so vector and scanned borders both trim. **Qt PDF exposes no crop-box selection**: `pagePointSize` is CropBox intersected with MediaBox; Art/Bleed/Trim boxes are unreachable, so Photoshop's Crop To menu cannot be reproduced (the post-render trim plus a notice stands in). Raster pages cap at 20000 px per axis with a notice. The document adopts the chosen PPI, so PDF must never join `kDensitylessFormats`.
- **PDF is a read-only SOURCE** even though the writer exists: `is_read_only_source_extension` lists it explicitly, because an import is a rasterization at one resolution (and even the editable export loses adjustment layers, blend modes, and styles), so Save must never replace a multi-page vector file with a re-render. Save routes to Save As defaulting `.psd`; Save As and Export to `.pdf` still work.
- Fixtures are synthesized byte by byte in-test (xref offsets computed, never hand-counted); export verification reads Patchy's output back through decoders that are not the writer.
