# Tool palette: layout, flyouts, cycle hotkeys, and icons

The tool palette toolbar built by `MainWindow::build_tool_palette()`: tool order, the color cluster and overflow behavior, flyout groups and their Shift+letter cycle commands, and the tool icon art rules. Tool behaviors live in [tools.md](tools.md); hotkey registration rules in [ui-conventions.md](ui-conventions.md).

## Layout and overflow

- Built imperatively in `MainWindow::build_tool_palette()` (main_window_actions_tool_palette.cpp, the tool-palette phase of `create_actions()`); order is the construction order, in separator-delimited clusters: select (Move, Marquee, Lasso, Wand, Crop), paint (Brush, Eraser, Gradient+Fill), retouch (Stamp, Healing, Detail, Toning), draw/type (Pen Tools, Path Tools, Shapes, Type), view (Pick, Hand, Zoom). The Pen Tools flyout sits directly before the Path Tools flyout because drawing and adjusting paths alternate constantly. The Pen stays separate from the path-select tools (a flyout hides the tool you switch to most); the anchor tools live under the Pen because Photoshop users look for them there. See [vector-commands.md](vector-commands.md).
- Below the tools sits `ToolPaletteFooter` (`src/ui/tool_palette_footer.hpp`): the 43 x 42 color well (background swatch lower right, foreground swatch over it, the Swap glyph in the free upper-right corner (a double-headed arrow bending around that corner, one head toward each swatch, as in Photoshop; GitHub issue 115 reported the earlier mirror-image glyph as rotated), the Default glyph in the lower-left one; the swatches are `ColorWellSwatch` QPushButtons named `foregroundColorButton`/`backgroundColorButton` that paint their color themselves, the glyphs `ColorWellGlyphButton`s carrying `colorSwapAction`/`colorDefaultAction`) and the Quick Mask button under it, 72 px in all. The footer is a child of the toolbar outside its layout: `ToolPaletteFooterPlacer` reserves the toolbar layout's bottom contents margin for it (re-applied after every style polish, which resets the margins) and places it there on every resize, so Qt lays out only the tools above, and a short window folds tools into the extension while the well and Quick Mask stay pinned at the bottom. Qt seats the extension button at the bar's bottom edge (inside the footer); the placer's `seat_extension` pins it directly above the footer in BOTH directions on every move, because a window growing back after a shorter layout delivers the palette's Resize after Qt has already moved the button, and a lift-only seat left it over the tool the taller column had just revealed (GitHub issue 126; `ui_tool_palette_extension_survives_resize_cycles` cycles short, tall, short and shorter windows) (`ui_tool_palette_overflow_hides_quick_mask_before_swatches` now pins exactly that). The extension chevron keeps Qt's 14 px extent through its own QSS rule; the palette's 24 px tool-button rule used to apply to it and clip it. It points right while collapsed (`AppStyle` answers `SP_ToolBarVerticalExtensionButton` with `chevron-right`: the overflow opens columns to the right) and left while expanded (`apply_extension_chevron`, re-applied after a style change; GitHub issue 122). The palette width is a 43 px minimum (`kToolPaletteCollapsedMinWidth`), never fixed, because clicking the extension arrow expands the bar into extra columns by temporarily widening it; a fixed width clamps that into a clipped sliver (see the standing rule in [ui-conventions.md](ui-conventions.md)). The expansion is a sticky toggle: stock Qt collapses it half a second after the pointer leaves the bar, so `ToolPaletteExpansionLock` swallows Leave while the extension button is checked, and picking a palette item leaves it open (an auto-collapse there eats the first click of the Zoom button's double-click-for-100%). While it is open, `ToolPaletteExpansionReservation` pins the bar's minimum AND maximum width to the columns the layout actually filled (`used_columns_width`: the rightmost visible tool's right edge plus the margin) so the main-window layout reserves exactly those columns and the canvas shrinks instead of being overlaid; Qt's own `expandedSize` guesses the column count from the square root of the tool count and reserved two empty columns beside the two in use (GitHub issue 124). Each pass releases both limits, lets Qt re-lay the bar, re-measures, and re-pins so it can drop back to fewer columns when the window grows. Tool buttons are 35 px wide, the collapsed column's full content width: a narrower button was centered in the collapsed column but left-aligned in an expanded one, a 1 px hop on every expand (issue 121; `ui_tool_palette_expansion_keeps_columns_tight_and_aligned` pins both). The bar closes on an arrow re-click, or automatically once the window is tall enough that nothing overflows. The expansion never runs through the main-window widget animator: the reservation controller turns `QMainWindow::setAnimated` off in the extension button's `toggled` (emitted before the `clicked` Qt's own expand/collapse slot listens to) and back on a turn later. QToolBarLayout skips item layout while it believes the bar is animating, and Qt 6.11 (the Flatpak runtime; native presets are 6.8.3) clears that state only when the animation object is destroyed, which left the collapsed bar's buttons centered for the expanded width (GitHub issue 88). Only Qt 6.11 shows it, which the Linux remote suite runs on ([linux-testing.md](linux-testing.md)). Coverage: `ui_tool_palette_animated_collapse_realigns_buttons`, `ui_tool_palette_overflow_hides_quick_mask_before_swatches`, `ui_tool_palette_extension_button_expands_palette`, `ui_tool_palette_expansion_sticky_after_tool_pick`, `ui_tool_palette_expanded_zoom_double_click_sets_actual_pixels`, `ui_tool_palette_expansion_collapses_when_window_fits_again`.
- Tools sharing a slot go through the shared `create_flyout_tool_action` + `configure_tool_flyout` lambdas. Thirteen flyouts in menu order (the first member is the default unless marked): Move (V) / Artboard ([artboards.md](artboards.md)); Marquee / Elliptical Marquee; Lasso / Polygonal Lasso / Magnetic Lasso; Magic Wand / Quick Select; Crop (C) / Perspective Crop ([crop-tool.md](crop-tool.md), GitHub issue 328); Gradient / Fill; Clone / Pattern Stamp; Healing Brush (J) / Spot Healing / Patch ([healing.md](healing.md)); Smudge / Mixer Brush / Blur / Sharpen; Dodge / Burn / Sponge; Pen (P) / Add Anchor / Delete Anchor / Convert Point; Path Select (A) / Direct Select; Rectangle (U) / Ellipse / Polygon / Line / Custom Shape (Line below Polygon, issue 308). The flyout swaps the button's default action on each member action's `triggered`, which also covers hotkey activation. Tools whose gestures the name does not explain also carry a two-line tooltip (`tool_tooltip_detail_source`) and a status-bar activation hint (`tool_activation_hint_source`).
- Every flyout button sets the `toolFlyout` Qt property; the app stylesheet keys the corner-triangle `::menu-indicator` and its sizing on `QToolButton[toolFlyout="true"]`, so a new flyout only needs the property (via `configure_tool_flyout`), not a new QSS selector. Coverage: `ui_stamp_and_gradient_flyouts_swap_tools`.
- A flyout opens three ways: press-and-hold (`QToolButton::DelayedPopup`; the delay is `SH_ToolButton_PopupDelay` from `AppStyle` in `src/ui/app_style.cpp`, 200 ms instead of Qt's 600), a left double-click, or a right-click (`configure_tool_flyout` installs a `ToolFlyoutEventFilter` that calls `showMenu()` for both: Qt otherwise routes the double-click pair's second press back to `mousePressEvent` and restarts the hold timer, and a right press would otherwise reach the toolbar's own context menu). The filter also swallows the button's `ContextMenu` event, which Qt sends after the right press (with the release on Windows, with the press on macOS and X11) and which would otherwise bubble to `QMainWindow::contextMenuEvent` and open the toolbar menu over the flyout (GitHub issue 356); tool buttons without a flyout still show the toolbar menu. Coverage: `ui_tool_flyout_right_click_opens_only_the_flyout`. The filter opens the menu only while the button is enabled: it sees events before Qt's disabled check, which drops a disabled button's left press. Tool buttons are enabled with no document open ([tool-options.md](tool-options.md), local-008), so click, hold, double-click and right-click all work on the home screen; `ui_tool_flyout_left_hold_opens_menu` and `ui_tools_work_with_no_document_open` cover the hold. The first click of the pair still selects the default tool. Every way in shows the menu, so `ToolFlyoutMenuPlacement` moves it on Show to 2 px past the button's right edge, top edges aligned (QToolButton put it over the button's last column, GitHub issue 284); Qt's placement stays when it would not fit on the right. The menu's own sheet draws the icons at the palette's icon size, centered between the menu edge and the names (item padding-left 24 px, icon offset 14 px). `ToolFlyoutCurrentMarker` paints a 6 px accent square 3 px before the icon on the row of the tool the button shows (`text_on_accent` on a highlighted row; issue 284 follow-up, moved next to the icon at the reporter's request), after the menu paints itself; every row keeps the same geometry, so marked and unmarked rows line up. Coverage: `ui_tool_flyout_opens_beside_its_button_with_palette_size_icons`, `ui_tool_flyout_marks_the_tool_its_button_shows`. The flyout menu is the only group UI: a persistent tool-group bar beside the palette was rejected (Seth's decision). Coverage: `ui_tool_flyout_double_click_opens_menu`, `ui_tool_flyout_right_click_opens_menu`.
- **Shift+letter cycles a flyout** (GitHub issue 45, Photoshop's convention): `configure_tool_flyout` also registers one "Cycle <Group> Tools" command per flyout (`tools.cycle.move`, `.marquee`, `.lasso`, `.wand`, `.crop`, `.gradient`, `.stamp`, `.healing`, `.detail`, `.tone`, `.pen`, `.path_select`, `.shape`; object names `toolCycle...Action`; category `tools`) on Shift plus the group's letter (Shift+V, M, L, W, C, G, S, J, R, O, P, A, U), listed in the flyout menu after a separator. It selects the member after the active tool when the active tool is in the group, otherwise the member after the one the button shows, wrapping, so every member is reachable by key. The members past the first ship unbound because Qt fires neither of two actions sharing a sequence; a saved user override that puts Shift+<letter> back on a member wins the sequence and suppresses the cycle default (`ui_tool_cycle_yields_to_member_override`). The plain letter still selects the primary tool. Coverage: `ui_tool_cycle_hotkeys_walk_each_flyout`, `ui_photoshop_shortcuts_are_registered`.

## Toolbar icon size

- Preferences > Application > Toolbar icon size (`preferencesToolbarIconSizeCombo`, under Interface scale): Smallest, Small, Normal (default), Bigger, Biggest, factors 0.75, 0.875, 1, 1.25 and 1.5 on top of the interface scale. Named steps, not percentages, because the interface scale beside it already is one. Stored as the token (`smallest` ... `biggest`) under `preferences/toolbarIconSize`, a compatibility contract; an unknown token reads as Normal. Helpers in `src/ui/app_settings.hpp`.
- Every palette length is its Normal value times the factor, rounded (`tool_palette_length` in `tool_palette_footer.hpp`): the icon (20 px), the tool button content (31 x 24) and the plain QPushButton rule. The collapsed column is the scaled 31 plus 12 (padding, border and the bar's side margins stay 1, 1 and 4 px), so the 35-px-button-fills-the-column rule of issue 121 holds at every size. The footer (well, glyphs, Quick Mask, its height) scales by column / 43 instead, so the well always fills the column; `ToolPaletteFooter::set_scale` lays it out and the glyphs paint on their 14 px grid through a painter scale. The k* constants stay the Normal sizes.
- The window sheet writes these lengths as `@tp(n)` (factor) and `@tf(n)` (footer factor) in `main_window_theme.cpp`; `photoshop_style(factor)` resolves them before the color tokens, so the Normal sheet is unchanged byte for byte. The flyout menus draw icons at the palette's icon size.
- Applies live on OK (`MainWindow::apply_tool_palette_factor`: closes an open overflow expansion, then icon size, collapsed width property `toolPaletteCollapsedWidth`, footer, flyout menu sheets, window sheet). The options bar keeps its size. Coverage: `ui_toolbar_icon_size_preference_scales_tool_palette`.

## Icons

- Original SVGs at `src/ui/icons/tool-*.svg` (32x32, `#dce2eb` strokes, at most one non-load-bearing `#74c0ff` accent). Generic metaphors, no Photoshop geometry, so the license stays clean. The Gradient tile runs ink to `#242628` (icon surface), so it reads as a light-to-dark ramp in both schemes (issue 129 asked for white-to-black; the old ink-to-accent ramp was two dark tones in Light). Light's `icon_accent` is `#1a73e8`, chosen to stay distinct from the dark ink (issue 129).
- Quick Mask (the footer button and Select > Edit in Quick Mask Mode, GitHub issue 224): a framed window half tinted with the mask red, fully tinted when checked (`quick-mask.svg`, `quick-mask-on.svg`, drawn for `QIcon::On` through the two-stem `themed_svg_icon`). The red `#eb5f6e` is the overlay's own color, exempt from recoloring like the paint swatches; frame and dashed diagonal are icon ink. The footer shows it icon-only at 22 px (its frame fills less of the art than the tool glyphs) in a 36 x 26 button box (QSS content plus padding and border) that `place_controls` centers inside the palette's 1 px right border (the footer spans the palette, so its last column is that border): the box, checked border included, must fit on every side. The same pass keeps the Swap glyph 2 px clear of that border, with equal inked gaps to the foreground swatch on its left and the background swatch below it (GitHub issue 251). Coverage: `ui_tool_palette_quick_mask_button_shows_its_icon` (nothing drawn in the footer's left column or its two right columns, at 100% and 150%).
- Size (GitHub issue 338): every 32-unit icon under `src/ui/icons/` (palette, menus, toolbars, options bar, panels) puts its art's longer side at 29 units, centered, measured on the rendered ink with strokes. Existing art is wrapped in a `translate scale` group rather than redrawn. Exempt, at their own sizes: the 16-unit chrome (chevrons, checkmark, spin buttons, scroll texture, flyout corner), the layer-row badges (`badge-fx`, `badge-vector`, `smart-object*`), the mask link toggle (`link`, `off`), Quick Mask and the paint swatches (`default-colors`, `swap-colors`).
- QtSvg renders a Tiny-1.2 subset only, and a typo'd qrc alias renders EMPTY silently. Review with `patchy_ui_visual_tests.exe ui_tool_palette_icons` (writes contact-sheet artifacts, checks per-icon coverage + pairwise distinctness).
- Magnetic Lasso is the Lasso's own loop and tail with accent-filled, ink-outlined square nodes along the rope (the anchor squares the tool itself drops), as GitHub issue 130 proposed; the earlier magnet glyph did not read. Polygonal Lasso (GitHub issue 287) is the same knot with the loop and tail drawn as straight, round-joined segments, ink only, so the three differ in silhouette. Perspective Crop (GitHub issue 328) is a trapezoid with accent corner handles and a dashed cross inside, not Crop's two crossed brackets.
- Clone keeps the classic rubber-stamp silhouette; Pattern Stamp is deliberately a different silhouette (stamp knob over a large checkerboard tile) because a small in-base detail was indistinguishable from Clone at the palette's 20px render size. Keep any future pair of related tools distinct in SILHOUETTE, not just in accent color. The healing flyout follows the same rule: bandage (Healing Brush), circle with burst ticks (Spot Healing), rotated stitched square (Patch). The pen flyout: nib drop (Pen), a curve with a hollow anchor plus a + or - accent (Add/Delete Anchor), a corner whose anchor sprouts a handle (Convert Point).
