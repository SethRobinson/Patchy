# Tool palette: layout, flyouts, cycle hotkeys, and icons

The tool palette toolbar built by `MainWindow::build_tool_palette()`: tool order, the color cluster and overflow behavior, flyout groups and their Shift+letter cycle commands, Customize Tool Palette, and the tool icon art rules. Tool behaviors live in [tools.md](tools.md); hotkey registration rules in [ui-conventions.md](ui-conventions.md).

## Layout and overflow

- Built imperatively in `MainWindow::build_tool_palette()` (main_window_actions_tool_palette.cpp, the tool-palette phase of `create_actions()`), which registers each slot with `ToolPaletteLayout` (below, "Customizing the palette"); order is the construction order, in separator-delimited clusters: select (Move, Marquee, Lasso, Wand, Crop), paint (Brush, Eraser, Gradient+Fill), retouch (Stamp, Healing, Detail, Toning), draw/type (Pen Tools, Path Tools, Shapes, Type), view (Pick/Ruler, Hand, Zoom). The Pen Tools flyout sits directly before the Path Tools flyout because drawing and adjusting paths alternate constantly. The Pen stays separate from the path-select tools (a flyout hides the tool you switch to most); the anchor tools live under the Pen because Photoshop users look for them there. See [vector-commands.md](vector-commands.md).
- The cluster separators are the `QToolBar#toolPalette::separator` rule in main_window_theme.cpp: a 1 px line in the `tool_palette_separator` role with a 4 px side margin. It must read at a glance yet stay quieter than the icons (GitHub issue 406): Dark and Light keep it at least 56 per channel from `tool_palette_bg` (`ui_theme_adjacent_roles_stay_distinguishable`), and the bundled themes inherit the step through the generator ([theme-files.md](theme-files.md)).
- Below the tools sits `ToolPaletteFooter` (`src/ui/tool_palette_footer.hpp`): the 43 x 42 color well (background swatch lower right, foreground swatch over it, the Swap glyph in the free upper-right corner (a double-headed arrow bending around that corner, one head toward each swatch, as in Photoshop; GitHub issue 115 reported the earlier mirror-image glyph as rotated), the Default glyph in the lower-left one; the swatches are `ColorWellSwatch` QPushButtons named `foregroundColorButton`/`backgroundColorButton` that paint their color themselves, the glyphs `ColorWellGlyphButton`s carrying `colorSwapAction`/`colorDefaultAction`) the Quick Mask button under it, and the screen mode button under that ([screen-modes.md](screen-modes.md#the-tool-palette-button), GitHub issue 212), 97 px in all at Normal. In two columns (GitHub issue 499) its cell is centered under the two tool columns (`ToolPaletteLayout::footer_center_x`, `ToolPaletteFooter::set_center_x`) and, while nothing overflows, scrolls or expands, it sits 8 px under the last tool row (`tools_bottom`) instead of at the bar's bottom; the extension seat is measured from the bottom position (`ui_tool_palette_two_column_footer_sits_centered_under_the_tools`). Customize Tool Palette can hide each of the three rows (`ToolPaletteFooter::set_shown_rows`): a hidden row takes no height, the rows under it move up, and the footer posts a LayoutRequest so the placer shrinks the reserved margin and the tools get the room (0 px with all three hidden). The footer is a child of the toolbar outside its layout: `ToolPaletteFooterPlacer` reserves the toolbar layout's bottom contents margin for it (re-applied after every style polish, which resets the margins) and places it there on every resize, so Qt lays out only the tools above, and a short window folds tools into the extension while the well and Quick Mask stay pinned at the bottom. Qt seats the extension button at the bar's bottom edge (inside the footer); the placer's `seat_extension` pins it directly above the footer in BOTH directions on every move, because a window growing back after a shorter layout delivers the palette's Resize after Qt has already moved the button, and a lift-only seat left it over the tool the taller column had just revealed (GitHub issue 126; `ui_tool_palette_extension_survives_resize_cycles` cycles short, tall, short and shorter windows) (`ui_tool_palette_overflow_hides_quick_mask_before_swatches` now pins exactly that). The extension chevron keeps Qt's 14 px extent through its own QSS rule; the palette's 24 px tool-button rule used to apply to it and clip it. It points right while collapsed (`AppStyle` answers `SP_ToolBarVerticalExtensionButton` with `chevron-right`: the overflow opens columns to the right) and left while expanded (`apply_extension_chevron`, re-applied after a style change; GitHub issue 122). The palette width is a 43 px minimum (`kToolPaletteCollapsedMinWidth`), never fixed, because clicking the extension arrow expands the bar into extra columns by temporarily widening it; a fixed width clamps that into a clipped sliver (see the standing rule in [ui-conventions.md](ui-conventions.md)). The expansion is a sticky toggle: stock Qt collapses it half a second after the pointer leaves the bar, so `ToolPaletteExpansionLock` swallows Leave while the extension button is checked, and picking a palette item leaves it open (an auto-collapse there eats the first click of the Zoom button's double-click-for-100%). While it is open, `ToolPaletteExpansionReservation` pins the bar's minimum AND maximum width to the columns the layout actually filled (`used_columns_width`: the rightmost visible tool's right edge plus the margin) so the main-window layout reserves exactly those columns and the canvas shrinks instead of being overlaid; Qt's own `expandedSize` guesses the column count from the square root of the tool count and reserved two empty columns beside the two in use (GitHub issue 124). Each pass releases both limits, lets Qt re-lay the bar, re-measures, and re-pins so it can drop back to fewer columns when the window grows. Tool buttons are 35 px wide, the collapsed column's full content width: a narrower button was centered in the collapsed column but left-aligned in an expanded one, a 1 px hop on every expand (issue 121; `ui_tool_palette_expansion_keeps_columns_tight_and_aligned` pins both). The bar closes on an arrow re-click, or automatically once the window is tall enough that nothing overflows. The expansion never runs through the main-window widget animator: the reservation controller turns `QMainWindow::setAnimated` off in the extension button's `toggled` (emitted before the `clicked` Qt's own expand/collapse slot listens to) and back on a turn later. QToolBarLayout skips item layout while it believes the bar is animating, and Qt 6.11 (the Flatpak runtime; native presets are 6.8.3) clears that state only when the animation object is destroyed, which left the collapsed bar's buttons centered for the expanded width (GitHub issue 88). Only Qt 6.11 shows it, which the Linux remote suite runs on ([linux-testing.md](linux-testing.md)). Coverage: `ui_tool_palette_animated_collapse_realigns_buttons`, `ui_tool_palette_overflow_hides_quick_mask_before_swatches`, `ui_tool_palette_extension_button_expands_palette`, `ui_tool_palette_expansion_sticky_after_tool_pick`, `ui_tool_palette_expanded_zoom_double_click_sets_actual_pixels`, `ui_tool_palette_expansion_collapses_when_window_fits_again`.
- Tools sharing a slot form a tool group: a flyout button whose menu holds the members. How a group opens, selects, cycles (Shift+letter), shows one tool or none (No tool groups), and draws its menu: [tool-flyouts.md](tool-flyouts.md).

## Customizing the palette

- Customize Tool Palette (GitHub issues 213, 316 and 199): `src/ui/tool_palette_customization.{hpp,cpp}` holds the choice, its settings, the dialog (`toolPaletteCustomizeDialog`, non-modal, one at a time; a second way in raises it on the asked tab) and its painted preview; `src/ui/tool_palette_layout.{hpp,cpp}` (`ToolPaletteLayout`) builds the palette's items. Ways in: Window > Customize Tool Palette... (`window.customize_tool_palette`, no default key), the first entry of the palette's right-click menu, Preferences > Application's Customize Tool Palette... button, on its own line under the tool palette settings (`preferencesCustomizeToolPaletteButton`; the dialog opens as Preferences' child, so it closes with it), the Layers footer menu and Customize Layers Panel... in the Layers panel settings gear's menu (both on the Layers Panel tab; the gear: [layer-thumbnails.md](layer-thumbnails.md#layers-panel-settings-gear)); the title row's right-click menu stays the panel list (Seth, October 29, 2026: other panel headers list no panel options there). Coverage: `ui_layers_panel_gear_opens_layer_button_customize`. The palette has no gear: one was tried above Move and taken out (the palette starts with Move); its setting `toolPalette/showCustomizeButton` stays unused and `patchy.ui.toolPalette.showGearButton` is a no-op. Rows are at least 26 px tall (`QTreeWidget#toolPaletteCustomizeTree::item` QSS); the shortcut keys end 12 px before the list's right edge, where the scrollbar sits, through `ShortcutColumnDelegate` (an item `padding-right` in QSS only widens the column: right-aligned text still ends flush with the cell, issue 213 follow-up; `ui_tool_palette_footer_items_hide_and_preview` measures the drawn pixels), and the cluster headings take their font height plus 18 px, bottom-aligned; the headings and the keys get `text_secondary` from their column delegates when painted, so a scheme change while the dialog is open recolors them (GitHub issue 499 comment); `ToolPaletteCustomizeTree::drawBranches` draws a heading's expand sign in its text band so the two line up (issue 213 follow-up); the Layers Panel tab's rows 30 px. The Tools tab is three columns: the tree (its key column left aligned, GitHub issue 499), the options (Layout with No tool groups `toolPaletteUngroupToolsCheck`, then Buttons: Toolbar icon size `toolPaletteIconSizeCombo` and Open tool groups on, then Bottom of the palette: `toolPaletteShowColorsCheck`, `toolPaletteShowQuickMaskCheck`, `toolPaletteShowScreenModeCheck`), and the preview, which draws the flyout corner arrow on group slots and the footer rows shown (centered under two columns), at the chosen icon size. Every combo in the dialog is at least 90 px wide (as in Preferences) and opens a list as wide as its widest entry (`fit_combo_popup_to_entries`; GitHub issue 537, `ui_tool_palette_customize_combos_show_their_entries` in English, German and Russian). The dialog is resizable (`toolPaletteCustomizeSizeGrip` in the button row; frameless chrome has no native border) and opens at its natural size (about 465 px tall), or the size last dragged to (`toolPalette/customizeDialogSize`, stored only when the size changed), bounded by the screen's available area; the tree's minimum is 340 x 200, so the options column sets the minimum height. The preview takes its column's height (`QSizePolicy::Expanding`, size hint = minimum = one row, the gap and the footer) and draws every row of tools that fits at the real icon size, then the footer; only when rows are left out does it cut the strip at a torn gap, two zigzag edges in `tool_palette_separator` with the gap left unpainted so the dialog shows through (GitHub issue 499 comment). Below the strip the column stays empty. Its `toolRows`, `shownToolRows` and `stripHeight` properties carry the counts and the painted height (`ui_tool_palette_customize_preview_fits_its_height`). The icon size and group opening are Preferences settings under their own keys (`ToolPaletteDialogChoice` carries them beside the customization): OK applies them through `MainWindow::apply_tool_palette_preferences`, which also moves the combos of an open Preferences or customize dialog, so the two never disagree; Preferences' OK goes through the same call. OK applies live and stores (`MainWindow::apply_tool_palette_customization`), Cancel changes nothing, Reset to Default restores both tabs, the footer order included. The Layers Panel tab lists the footer buttons in footer order (GitHub issue 471): `layerFooterOrderUpButton` and `layerFooterOrderDownButton` beside the list move the current row (each off where it would do nothing), and the list drags rows (`InternalMove`; rows have no `ItemIsDropEnabled`, so a drop lands between rows). Coverage: `ui_tool_palette_dialog_reorders_layer_buttons`. Above the list, beside `layerFooterIconSizeCombo` (Icon size:), `layerFooterPresetCombo` (Preset:) offers Patchy (the default order and hidden set), Adobe Photoshop, Affinity Photo, GIMP, Krita and Custom (`LayerFooterPreset`, `apply_layer_footer_preset`): a preset shows its buttons in its order and hides the rest after them, picking Custom changes nothing, and any tick, move or drag re-matches the rows, so the combo says Custom unless they match a preset again. No key stores the preset: `matching_layer_footer_preset` compares the shown buttons in order (hidden ones' places do not count), on open and after every change; Reset to Default is Patchy. **Rule (Seth, October 27, 2026, #471): keep the other editors' presets.** They only order and hide Patchy's own buttons and icons, so they do not reproduce another product's layout under the AGENTS.md interface rule; a preset lists only buttons Patchy has (none for their link, live filter, anchor or properties buttons). Names are nominative product names, translators keep them, and README.md's Trademark Notice covers them ([legal-constraints.md](legal-constraints.md#format-copyright-trademarks-and-assets)). Coverage: `ui_layer_footer_presets_set_order_and_shown_buttons`, `ui_tool_palette_dialog_layer_button_presets`. Scripts read and set it through `patchy.ui.toolPalette` ([scripting-api-changes.md](scripting-api-changes.md)). Dragging tool rows to reorder the palette (mockup 1) is not built.
- Settings, compatibility contracts; a default is removed rather than written: `toolPalette/hiddenTools` (tool hotkey ids), `toolPalette/layout` (`two_columns`, anything else is one column), `toolPalette/wheelScroll` (default true), `toolPalette/ungroupTools` (true when No tool groups is on; [tool-flyouts.md](tool-flyouts.md)), `toolPalette/hiddenFooterItems` (`kToolPaletteFooterItemIds`: `colors`, `quick_mask`, `screen_mode`), `layersPanel/hiddenFooterButtons` (`kLayerFooterButtonIds`: `new_layer`, `new_folder`, `new_adjustment`, `layer_styles`, `add_mask`, `duplicate`, `move_up`, `move_down`, `merge_down`, `merge_visible`, `rasterize`, `animation`, `delete`), `layersPanel/shownFooterButtons` (the optional `move_up`, `move_down`, `merge_down`, GitHub issue 470, and `merge_visible`, `rasterize`, issue 539), `layersPanel/footerButtonOrder` (every known footer id once, hidden ones included, written only when the order differs from `kLayerFooterButtonIds`; GitHub issue 471), `layersPanel/footerIconSize` (toolbar icon size tokens; [layer-panel.md](layer-panel.md)).
- **Rule: a customization stores only what the user hid, never a full visible list or slot list**, so a tool or footer button added in a later version shows on a customized palette. The one exception is a button that starts hidden (`kLayerFooterButtonIdsHiddenByDefault`): its key stores it when shown, so settings that name only hidden buttons keep it hidden. In memory `hidden_layer_buttons` is the whole hidden list, those ids by default; `set_stored_tool_palette_customization` splits it between the two keys. A tool the settings do not name shows; a new tool joining a flyout whose stored members are all hidden brings the slot back with just that tool (the flyout menu and its cycle hold it alone). Ids this build does not know are ignored and kept (the dialog writes them back), so a newer version's settings survive an older one. The footer order is the other exception, a full list: `resolved_layer_footer_order` drops unknown ids and puts a button the stored order leaves out (one added later) right after the button it follows by default, first when none of those is placed (`ui_layer_footer_order_resolves_unknown_and_missing_ids`). The dialog's rows come from the palette's own slots (`MainWindow::tool_palette_catalog` reads `ToolPaletteLayout::entries`), so a new tool gets its row with no list to edit. Tests: `ui_tool_palette_settings_from_an_older_version_show_new_tools`, `ui_tool_palette_dialog_lists_every_palette_tool`.
- Every slot is one persistent QToolButton: the flyout buttons, and `<tool>ToolButton` for a plain tool (`handToolButton`; `palette->widgetForAction(tool action)` no longer finds it). In one column each slot is a toolbar item of its own, a QWidgetAction whose createWidget/deleteWidget move the button in and out (to the hidden `toolPaletteStash`), never deleting it, so filters, menus and the shown tool survive. `apply` rebuilds the items: each cluster's visible slots, a separator between non-empty clusters. Two columns put two slots side by side in a `toolPaletteRow`, left to right within the cluster; a row is one toolbar item, so the overflow folds and expands whole rows, and `used_columns_width` maps row buttons into the bar.
- Hiding never touches a tool's QAction (a hidden QAction loses its shortcut): tool actions carry `kToolPaletteToolIdProperty`, plain ones are also added to the window, and only the slot's item leaves. A flyout member left out leaves the menu (rebuilt: visible members, separator, cycle command) and the Shift+letter cycle (`cycle_members`); its own command still selects it, and the button keeps showing a visible member. A slot with every member hidden leaves the palette, and its cycle walks all members. Hand hidden still pans with H and Space (GitHub issue 304).
- Wheel scrolling (issue 316, on by default, both layouts): in an overflowing palette the wheel (120 per notch; touchpad deltas add up) hides leading items (`scroll_offset`), a separator going with the cluster above it. `toolPaletteScrollUpArrow`, the palette's first toolbar item, shows while scrolled; `toolPaletteScrollDownArrow` covers Qt's extension where Qt seats it, so it shows exactly while the column overflows below. Under it, directly above the footer, `toolPaletteExpandArrow` (a full-width 14 px row) opens the columns whenever any tool is hidden, above or below (GitHub issue 488: a column scrolled to its end no longer overflows, so Qt hides its extension). `bottom_reserve` adds the row to the placer's bottom margin, measured without the row so it never keeps itself; a click scrolls to the top and clicks the extension; open columns drop both rows and the wheel. A click on a scroll arrow scrolls one item; a taller window brings items back from the top (`update_scroll_state`). With the option off the extension works as above. Coverage: `ui_tool_palette_scroll_mode_keeps_expand_button_reachable`.
- Coverage (tests/ui/tool_palette_customize_tests.cpp): `ui_tool_palette_customize_hidden_tools_keep_hotkeys`, `ui_tool_palette_two_columns_place_tools_side_by_side`, `ui_tool_palette_wheel_scrolls_overflowing_column`, `ui_tool_palette_customize_dialog_applies_cancels_and_resets`, `ui_layer_footer_buttons_hide_from_their_menu`, `ui_tool_palette_settings_from_an_older_version_show_new_tools`, `ui_tool_palette_dialog_lists_every_palette_tool`, `ui_preferences_opens_customize_tool_palette` (and the combos kept in step both ways), `ui_tool_palette_footer_items_hide_and_preview`, `ui_tool_palette_customize_preview_fits_its_height`, `ui_tool_palette_customize_tree_text_follows_the_scheme`.

## Toolbar icon size

- Preferences > Application > Toolbar icon size (`preferencesToolbarIconSizeCombo`, its own form row right under Interface scale; beside the scale field it wrapped badly in a narrowed dialog, desk card local-024; `ui_preferences_toolbar_icon_size_row_under_interface_scale`): Smallest, Small, Normal (default), Bigger, Biggest, factors 0.75, 0.875, 1, 1.25 and 1.5 on top of the interface scale. Named steps, not percentages, because the interface scale above it already is one. Stored as the token (`smallest` ... `biggest`) under `preferences/toolbarIconSize`, a compatibility contract; an unknown token reads as Normal. Helpers in `src/ui/app_settings.hpp`.
- Every palette length is its Normal value times the factor, rounded (`tool_palette_length` in `tool_palette_footer.hpp`): the icon (20 px), the tool button content (31 x 24) and the plain QPushButton rule. The collapsed column is the scaled 31 plus 12 (padding, border and the bar's side margins stay 1, 1 and 4 px), so the 35-px-button-fills-the-column rule of issue 121 holds at every size. The footer (well, glyphs, Quick Mask, its height) scales by column / 43 instead, so the well always fills the column; `ToolPaletteFooter::set_scale` lays it out and the glyphs paint on their 14 px grid through a painter scale. The k* constants stay the Normal sizes.
- The window sheet writes these lengths as `@tp(n)` (factor) and `@tf(n)` (footer factor) in `main_window_theme.cpp`; `photoshop_style(factor)` resolves them before the color tokens, so the Normal sheet is unchanged byte for byte. The flyout menus draw icons at the palette's icon size.
- The customize dialog shows the same combo (above). Applies live on OK (`MainWindow::apply_tool_palette_factor`: closes an open overflow expansion, then icon size, collapsed width property `toolPaletteCollapsedWidth`, footer, flyout menu sheets, window sheet). The options bar keeps its size. Coverage: `ui_toolbar_icon_size_preference_scales_tool_palette`.

## Icons

- Original SVGs at `src/ui/icons/tool-*.svg` (32x32, `#dce2eb` strokes, at most one non-load-bearing `#74c0ff` accent). Generic metaphors, no Photoshop geometry, so the license stays clean. The Gradient tile runs ink to `#242628` (icon surface), so it reads as a light-to-dark ramp in both schemes (issue 129 asked for white-to-black; the old ink-to-accent ramp was two dark tones in Light). Light's `icon_accent` is `#1a73e8`, chosen to stay distinct from the dark ink (issue 129).
- Quick Mask (the footer button and Select > Edit in Quick Mask Mode, GitHub issue 224): a framed window half tinted with the mask red, fully tinted when checked (`quick-mask.svg`, `quick-mask-on.svg`, drawn for `QIcon::On` through the two-stem `themed_svg_icon`). The red `#eb5f6e` is the overlay's own color, exempt from recoloring like the paint swatches; frame and dashed diagonal are icon ink. The footer shows it icon-only at 22 px (its frame fills less of the art than the tool glyphs) in a 36 x 26 button box (QSS content plus padding and border) that `place_controls` centers inside the palette's 1 px right border (the footer spans the palette, so its last column is that border): the box, checked border included, must fit on every side. The same pass keeps the Swap glyph 2 px clear of that border, with equal inked gaps to the foreground swatch on its left and the background swatch below it (GitHub issue 251). Coverage: `ui_tool_palette_quick_mask_button_shows_its_icon` (nothing drawn in the footer's left column or its two right columns, at 100% and 150%).
- Size (GitHub issue 338): every 32-unit icon under `src/ui/icons/` (palette, menus, toolbars, options bar, panels) puts its art's longer side at 29 units, centered, measured on the rendered ink with strokes. Existing art is wrapped in a `translate scale` group rather than redrawn. Exempt, at their own sizes: the 16-unit chrome (chevrons, checkmark, spin buttons, scroll texture, flyout corner), the layer-row badges (`badge-fx`, `badge-vector`, `smart-object*`), the mask link toggle (`link`, `off`), Quick Mask and the paint swatches (`default-colors`, `swap-colors`).
- Screen modes (`screen-mode-standard`, `-full-with-menus`, `-full`): our own frame, menu-strip and corner-mark drawings around an accent canvas, one per mode, distinct in silhouette ([screen-modes.md](screen-modes.md#the-tool-palette-button)).
- Crop (`tool-crop.svg`, GitHub issue 390, from a reporter's mockup): the two crop marks leave a clear square about 14 of 32 units wide on the middle row, with the accent diagonal inside it; arms 6 units, the art still 29 units. Perspective Crop keeps its own trapezoid-and-handles drawing. Coverage and shots: `ui_tool_palette_crop_icon_has_large_center`.
- QtSvg renders a Tiny-1.2 subset only, and a typo'd qrc alias renders EMPTY silently. Review with `patchy_ui_visual_tests.exe ui_tool_palette_icons` (writes contact-sheet artifacts, checks per-icon coverage + pairwise distinctness).
- Magnetic Lasso is the Lasso's own loop and tail with accent-filled, ink-outlined square nodes along the rope (the anchor squares the tool itself drops), as GitHub issue 130 proposed; the earlier magnet glyph did not read. Polygonal Lasso (GitHub issue 287) is the same knot with the loop and tail drawn as straight, round-joined segments, ink only, so the three differ in silhouette. Perspective Crop (GitHub issue 328) is a trapezoid with accent corner handles and a dashed cross inside, not Crop's two crossed brackets. Ruler (GitHub issue 331) is a straightedge laid diagonally with tick marks along one side, the middle tick in accent: a wide bar, so it never reads as the Line tool's single stroke.
- Clone keeps the classic rubber-stamp silhouette; Pattern Stamp is deliberately a different silhouette (stamp knob over a large checkerboard tile) because a small in-base detail was indistinguishable from Clone at the palette's 20px render size. Keep any future pair of related tools distinct in SILHOUETTE, not just in accent color. The healing flyout follows the same rule: bandage (Healing Brush), circle with burst ticks (Spot Healing), rotated stitched square (Patch), almond eye with an accent pupil (Red Eye). The pen flyout: nib drop (Pen), a curve with a hollow anchor plus a + or - accent (Add/Delete Anchor), a corner whose anchor sprouts a handle (Convert Point).
