# Crop tool

Read this before changing the Crop tool, its options bar, or `crop_document`. Related tool-wide rules live in [tools.md](tools.md).

Photoshop-style interactive crop (hotkey C; `tools.crop`). Session code in canvas_widget_crop.cpp; commit in `MainWindow::commit_crop_rect` (main_window_layer_ops.cpp). Plain C belongs to the tool: the Image > Crop to Selection command keeps its persisted id (`image.crop_to_selection`) but ships with no default shortcut, like Photoshop's Image menu.

## Session and box

- **Picking the tool frames the canvas** (`begin_default_crop_session`, called from `set_tool`, `set_document_internal` and an unlock in `set_edit_locked`): the box is the whole canvas, fitted to the ratio when one is set, with the 8 handles ready, so dragging a handle inward crops and outward extends the canvas without drawing anything first (GitHub issue 66). The session exists whenever the tool is current and a document is set; `crop_session_has_changes()` (box differs from the unrotated canvas) gates Apply, the no-op Enter ("Nothing to crop"), and the recovery busy check (`any_canvas_interaction_active`), so the idle frame never blocks autosave. The X button and the "Crop cancelled"/"reset" status follow `crop_session_can_reset()` instead (box differs from the ratio-fitted frame, or is selection-derived or rotated): a ratio frame is smaller than the canvas, so Apply is on but the X stays off (GitHub issue 318, `ui_crop_cancel_button_off_for_ratio_frame`).
- **An active selection becomes the box** instead: `selection_.boundingRect()`, overriding the ratio for that box. The marching ants hide while the box descends from it (`crop_box_from_selection_`, cleared by Esc or a new drag-out; `draw_selection_overlay`), a tool switch brings them back, and a commit clears the selection (`ui_crop_tool_adopts_active_selection`). A selection set or cleared under the tool (Select All, Inverse, scripts) re-frames a default or selection-derived box through `follow_selection_into_crop_session` (called from the selection setters; a custom box or an in-flight drag is left alone), so the box never lags the marquee.
- **Default frame vs custom box** (`crop_box_is_default_`): while the box is the automatic frame, a press on the canvas that misses a handle lays out a new rect (the frame has no interior to move; a sub-drag click keeps it), and a press on the pasteboard rotates. Any drag-out, handle drag, nudge, or rotation makes the box custom: then the interior moves it (`snapped_rect_delta`), arrows nudge (Shift = 10 px), and a drag off the box ROTATES it about its center (the straighten gesture; Shift snaps 15 degrees, a mere click changes nothing; hover off the box shows the nearest corner's `corner_rotate_cursor` through `transform_rotate_cursor_at`, by the corner's on-screen direction). The handles reuse `transform_handle_at` (`EdgesAndCorners`: an edge resizes anywhere along it, GitHub issue 176, [move-tool.md](move-tool.md)) with Rotate mapped to None. Enter or the options-bar check commits; Esc and the X put the frame back (`reset_crop_session_to_canvas`), they never end the session.
- Switching tools, locking edits, or swapping documents CANCELS a pending crop (never commits, unlike Free Transform): an accidental switch must not resize the document. Re-clicking the Crop palette button keeps the box (`set_tool` tears down only on an actual tool change). Focus loss ends in-flight drags but keeps the session.

## Commit and `crop_document`

- **Delete Cropped Pixels / Delete Off-Canvas Layers** (`cropDeletePixelsCheck`, `tools/cropDeletePixels`, default on; `cropDeleteLayersCheck`, `tools/cropDeleteLayers`, default off; both persisted) on the options bar are Canvas Size's two layer options, the first named and defaulted like Photoshop's. Pixels on, an unrotated commit is `crop_document` (tight per-layer buffers); off, it is the Canvas Size frame resize (`resize_canvas_to_frame(doc, rect, color, false)`): every layer keeps its pixels beyond the new canvas (a later canvas extension or move brings them back) and Background fills new area with the background color. Layers on, `remove_layers_outside_canvas(doc, rect)` runs against the frame BEFORE the crop (the crop would empty those layers and hide them from the test) and the status line reports the count. A rotated box always goes through the rotated `crop_document` (destructive); the layer delete then uses the axis-aligned rect as a conservative test (`ui_crop_delete_options_crop_and_delete_layers`).
- A rotated box straightens on commit through the 4-arg `crop_document(doc, rect, angle, extension_color)`: result pixels sample the document through the inverse rotation about the box center (`sample_rotated_crop_pixels`: bilinear for 8-bit, bilinear on float samples in the buffer's own domain for 16/32-bit layers that keep their format, nearest otherwise), text/smart-object/vector data ride the same affine, exposed areas follow the crop fill rules (Background fill color; elsewhere transparency, promoting an opaque RGB layer to RGBA at its own depth), and angles under 0.01 degrees take the exact unrotated path. Handle drags on a rotated box run the axis-aligned edge math in the box's own frame; snapping is skipped while rotated (guides assume axis-aligned edges).
- The rect may extend past the canvas; commit expands the document (through the 3-arg `crop_document(doc, rect, extension_color)` in document_geometry.cpp, or `resize_canvas_to_frame` with Delete Cropped Pixels off). A contained rect takes the exact per-layer crop path; an expanding one keeps tight buffers on ordinary layers and rebuilds only a pixel layer literally named "Background" canvas-sized via `resize_layer_to_canvas`, filled with the background color at commit. Channels ride `resize_document_channel_canvas` (Spot new area 255, others 0). The 2-arg `crop_document` still clamps to the canvas: the script API relies on that contract. After a commit `set_document` frames the new canvas afresh and the view recenters at the current zoom.

## Ratio and Size

- **Ratio** (`tools/cropRatioWidth`/`tools/cropRatioHeight`, persisted; both > 0 to constrain): a change reshapes the pending box at once (`set_crop_ratio`). The default frame re-fits from the whole canvas (`ratio_fitted_crop_rect`: the largest rect of the ratio inside the canvas, centered), so Clear grows it back. A custom box keeps its width and center and derives the height, which makes the result independent of the intermediate ratios a field passes through as it is typed (fitting inside itself would shrink cumulatively); Clear leaves it alone. The ratio also constrains drag-outs (over Shift's 1:1 latch, toggleable mid-drag) and always binds corner drags, re-centering the derived axis on edge drags. Shift on a corner with no ratio holds the drag-start aspect. `transform_drag_keeps_aspect` deliberately does not apply: crop is a drag-rect tool, not a transform session.
- **Style** (`cropStyleCombo`, `tools/cropStyle`; 0 Ratio, 1 Size; `crop_option_widget_visible` swaps the two field sets inside `refresh_options_bar`). Ratio shows the preset combo, the unitless W : H pair and Clear. Both ratio pairs (this one and the marquee's Fixed Ratio) are `TrimmedDoubleSpinBox` (unit_spin_box.hpp): two decimals of input, trailing zeros dropped from the display ("0", "2", "1.5"; `ui_crop_ratio_fields_show_trimmed_numbers`). Size shows `UnitIntSpinBox` Width / Height fields built like the marquee's Fixed Size pair (pixel native, typed unit tokens convert at the document PPI through `document_axis_context`, the same quick values, commit on Enter or focus-out): they mirror the pending box after every change and `set_crop_session_size` resizes it about its center, the link button keeping the box's proportion. Size mode runs the canvas unconstrained; the remembered ratio (`current_crop_ratio_*`, what the settings persist) returns with Ratio mode through `effective_crop_ratio_*` (`ui_crop_size_style_fields_mirror_and_resize_box`).
- **Bar groups** ([options-bar.md](options-bar.md) grouping rules): Style | the preset combo, W : H and Clear (Ratio) or Width, link and Height (Size) | the Overlay list (GitHub issue 325) | Delete Cropped Pixels and Delete Off-Canvas Layers | the Crop options "..." button (rule 1: advanced options) | Apply and Cancel. Clear stays beside the pair it clears (rule 2), as GitHub issue 324 settled; `ui_crop_options_bar_groups_its_controls` checks the order and the one row at 1366 px in both styles.
- The Ratio preset combo (`cropRatioPresetCombo`) writes into the W : H fields, which stay the source of truth: index 0 "None" and the last index "Custom" are fixed anchors (`sync_crop_ratio_preset_combo` derives the row from the field values and shows Custom for anything unmatched), "Original Ratio" reads the active document reduced by gcd at selection time, and Clear resets to None. The ratio fields, like every toolbar spin box, select their value on focus (`select_all_on_focus`, [ui-conventions.md](ui-conventions.md)).

## Drag gestures

- `crop_drag_rect` is the third deliberately-unmerged twin of `marquee_selection_rect`/`shape_drag_rect`; unlike the marquee, its anchor is never edge-clamped (the pasteboard is legal). Space repositions a drag-out in flight, and Space during a handle drag slides the whole box with the drag-start rect following, so releasing it resumes the resize in place (the marquee handle rule, same `spacebar_reposition_start_marquee_*` storage; `ui_crop_handle_drag_space_slides_box_then_resumes`). Photoshop has no such gesture; Patchy keeps the two tools consistent.
- **Alt during a drag-out draws from the center** (`crop_from_center_`): the press point is the box center and the box is twice the drag extent, with a set ratio or Shift's square latch still constraining. Both latches are read from every move and from mid-drag Shift/Alt key events, so Alt pressed after the press, or released before the release, takes effect with a stationary pointer (GitHub issue 78, `ui_crop_alt_drag_out_draws_from_center`). On Windows, Alt+Space during any canvas gesture is forwarded as Space by `canvas_alt_space_filter.cpp` rather than opening the window's system menu ([platform.md](platform.md)).
- Alt while dragging a handle resizes about the box's center: the opposite side mirrors the dragged one (`center_anchored_handle_rect` in canvas_widget_shared.cpp, shared with the marquee handles; a set ratio or Shift still constrains). Read per move, so Alt pressed after the grab counts, and Alt over a handle keeps the resize cursor (GitHub issue 66, `ui_crop_alt_handle_drag_resizes_about_center`).
- **Size style's link binds handle drags** (GitHub issue 332): with Size style and `cropLinkSizeButton` down, `crop_size_link_active()` feeds `set_crop_keep_proportions`, and `update_crop_adjust_drag` takes the drag-start width:height as its target ratio for every handle, the same path a set ratio uses (corners scale both sides, edges derive the other axis re-centered, Alt about the center, rotated boxes in their own frame). Link off, or Ratio style, leaves handles free (`ui_crop_size_link_keeps_proportion_on_handle_drags`).
- The marquee resize handles ([selection-tools.md](selection-tools.md)) copy the non-ratio branch of `update_crop_adjust_drag` (exclusive right/bottom edges, 1 px minimum, clean flip) and share `draw_transform_handle_squares` with the transform controls.

## Overlay and hints

- Overlay (`draw_crop_overlay`): a QRegion-with-hole shield outside the box plus composition guides (below) as cosmetic dark+light line pairs, deliberately unthemed like the marching ants; the W x H readout rides `draw_drag_size_readout`. Full-widget repaints during crop drags are accepted (the shield spans the viewport). The idle frame shields only the pasteboard.
- **Crop options popup** (`cropOptionsButton`, the "..." `optionsBarMenuButton` pattern, its own group between the Delete checkboxes and Apply; GitHub issue 326): the overlay's Turn Overlay and Always / While Dragging come first (issue 325, below), then Show Cropped Area (`tools/cropShowCroppedArea`, default on; off fills the outside with `backdrop_color()`, opaque) and the crop shield: Enable Crop Shield (`tools/cropShieldEnabled`, on; off draws nothing outside), Color (`tools/cropShieldColor`, `#rrggbb`, black, chosen in Patchy's picker with live preview) and Opacity (`tools/cropShieldOpacity`, 0 to 100, default 47, which is the original alpha 120). The values live in `CropOverlayOptions` (canvas_types.hpp), mirrored in `current_crop_overlay_options_` and pushed to every canvas by `apply_crop_overlay_options`. The shield color is a user setting like the grid and guide colors, so it stays outside the theme palette (`ui_crop_options_popup_sets_shield_and_cropped_area`). Photoshop's canvas-moves mode and Auto Center Preview are not implemented.
- The activation hint (`tool_activation_hint_source`) names the handle, lay-out, rotate, Enter and Esc gestures; the Crop line in the info panel shows the pending W x H and angle.

- **Overlay choices** (GitHub issue 325): `cropOverlayCombo` (`tools/cropOverlay`, a token: `none` (shown as "No Overlay"), `thirds` default, `grid`, `diagonal`, `triangle`, `goldenRatio`, `goldenSpiral`; an unknown token is `thirds`) sets `CanvasWidget::CropOverlay`, items in enum order. `crop_overlay_guides` builds the lines per paint from the box alone (no image-sized work): axis-aligned lines in groups drawn dark-then-light per group, which keeps Rule of Thirds pixel-identical to the old fixed thirds; Grid is near-square cells, six across the shorter side (long side capped at 48); Golden Ratio is 1/phi^2 and 1/phi of each side; Diagonal the two corner-to-corner lines; Triangle one diagonal plus the perpendiculars from the other two corners; Golden Spiral ten square cuts of a golden rectangle with a quarter arc each, stretched to the box and turned upright for a portrait box. Oblique lines and arcs draw antialiased and clipped to the box; the arcs' dark twin is a 2 px stroke under the light one. The Crop options menu (`cropOptionsMenu`) starts with Turn Overlay (`cropOverlayTurnAction`, enabled for Triangle and Golden Spiral only), which steps `tools/cropOverlayOrientation` 0-3 (bit 0 mirrors horizontally, bit 1 vertically; the Triangle reads bit 0), and Always Show Overlay / Show Overlay Only While Dragging (`tools/cropOverlayShow`, `always` or `dragging`; both disabled under No Overlay): the latter draws guides only during a drag-out, handle drag, move or rotate. The list has no label (its entries name themselves) and a fixed 112 px width, and its settings live in the shared menu, so the bar keeps one row in the 1180 px test window: a wrapped bar can un-wrap mid-drag and shift the canvas under handle-drag tests. No hotkeys: O belongs to the Dodge group. `ui_crop_overlay_choices_draw_their_guides` checks the lines per choice, the turns, While Dragging and the persistence.

## Image menu crop commands

- **Image > Crop to Selection and Crop to Selection (Advanced) use the pending box while the Crop tool is active** once the user has laid one out (`crop_session_active() && crop_session_has_changes()`): the plain command calls `commit_crop_session` (same as Enter), the advanced one takes `crop_session_rect()` as the dialog frame and refuses a rotated box with a status message (its `resize_canvas_to_frame` path has no rotation). While the box is still the automatic canvas frame (after Esc, say) a marquee selection wins, and with neither the commands report "Nothing to crop" (`ui_crop_menu_commands_use_crop_box`).
- Image > Crop to Selection (Advanced) is the Canvas Size dialog prefilled with the selection as its frame (W/H, anchor about the selection, extension color, the layer crop checkbox starting checked and the delete-off-canvas one unchecked), applied through `resize_canvas_to_frame` rather than `crop_document`; see the dialog semantics in [resolution-units.md](resolution-units.md).

## Perspective Crop (GitHub issue 328)

The Crop flyout's second member (`tools.perspective_crop`, `CanvasTool::PerspectiveCrop`, no default key; Shift+C cycles the flyout). It rectifies a skewed area (a photographed page or sign) onto a rectangle. Session code in canvas_widget_perspective_crop.cpp; commit in `MainWindow::commit_perspective_crop_quad` (main_window_layer_ops.cpp); core in `perspective_crop_document` (document_geometry.cpp).

- **Session.** Unlike Crop, picking the tool frames nothing. The first press decides: a drag lays out a box (its four corners), a click places the first corner and three more clicks place the rest (a dashed rubber band follows the pointer). A fourth click that would fold the quad is refused with "The corners must form a convex shape". Each corner handle then moves on its own (a quad, not a rectangle; a drag that would fold it keeps the last convex shape, Free Transform's rule), the inside moves the whole quad, a press elsewhere does nothing. Corners are stored in output order: the one nearest the top left first, then clockwise on screen (`upright_quad`), so click order and direction never mirror or turn the result. Enter or the check button commits, Esc or the X clears the corners. A tool switch, edit lock or document swap cancel (never commit), like Crop; `perspective_crop_session_pending` joins the recovery busy check.
- **Overlay.** The Crop shield options (color, opacity, Show Cropped Area off hides it) shade outside the quad; the outline and handles use the Crop box inks (unthemed: they sit on artwork). Show Grid (`tools/perspectiveCropShowGrid`, default on) draws the rectified grid through `QTransform::squareToQuad`, about one line per 40 widget pixels of the longest side (2 to 12 divisions), dark-under-light like the crop guides.
- **Options bar.** W and H (`UnitIntSpinBox`, pixel native with unit tokens at the document PPI like Crop's Size fields; 0 shows blank) set the result size, blank taking `perspective_crop_auto_size` (the mean of the top and bottom edge lengths by the mean of the left and right ones); a swap button sits between them. Resolution (pixels per inch, blank keeps the document's) only changes the document's print resolution. Front Image fills all three from the active document, Clear empties them (Photoshop's two buttons). None of the three persist.
- **Commit (`perspective_crop_document`).** The result rect maps onto the quad through `homography_from_rect_to_quad` (core/warp_mesh.hpp). Every pixel layer, mask and channel resamples through the rotated crop's sampler (`sample_mapped_crop_pixels`, shared with `sample_rotated_crop_pixels`: bilinear with clamped edges, 16/32-bit layers in their own float domain, nearest across a depth change), so it is deterministic and works at every depth; no area averaging on the far side, Free Transform's perspective rule. A rect quad the size of its output copies pixels exactly. Layer bounds are the projected bounding box clipped to the new canvas (a layer reaching across the quad's horizon takes the whole canvas). Fill rules are the rotated crop's: a "Background" layer is rebuilt canvas-sized with the background color under area the quad takes from beyond the canvas, other layers get transparency there (opaque 8-bit layers gain alpha). Non-pixel layers: a parallelogram quad is affine, so text transforms, smart-object placements and vector data ride it exactly like the other crops (type stays live); a true perspective quad rasterizes text layers (`clear_layer_text_metadata`, now in core; Free Transform refuses perspective on type for the same reason), gives smart objects a perspective placement (`map_smart_object_placement`, Free Transform's rule) and maps shape layers, vector masks and paths through `transform_layer_vector_data_projective`/`transform_vector_path_projective`. Documents with artboards, Smart Filters or unparsed smart objects are refused as for Crop. One undo step ("Perspective Crop").
- **Scripts.** `doc.perspectiveCrop(corners, {width, height, resolution})`: four `[x, y]` or `{x, y}` corners in output order, the commit's rules with white under the Background (the 2-arg `crop` convention).
