# Crop tool

Read this before changing the Crop tool, its options bar, or `crop_document`. Related tool-wide rules live in [tools.md](tools.md).

Related documents:

- [crop-tool-perspective.md](crop-tool-perspective.md): the Perspective Crop tool (the Crop flyout's second member), its session, overlay, options bar, commit and script call.

Photoshop-style interactive crop (hotkey C; `tools.crop`). Session code in canvas_widget_crop.cpp; commit in `MainWindow::commit_crop_rect` (main_window_layer_ops.cpp). Plain C belongs to the tool: the Image > Crop to Selection command keeps its persisted id (`image.crop_to_selection`) but ships with no default shortcut, like Photoshop's Image menu.

## Session and box

- **Picking the tool frames the canvas** (`begin_default_crop_session`, called from `set_tool`, `set_document_internal` and an unlock in `set_edit_locked`): the box is the whole canvas, fitted to the ratio when one is set, with the 8 handles ready, so dragging a handle inward crops and outward extends the canvas without drawing anything first (GitHub issue 66). The session exists whenever the tool is current and a document is set; `crop_session_has_changes()` (box differs from the unrotated canvas) gates Apply, the no-op Enter ("Nothing to crop"), and the recovery busy check (`any_canvas_interaction_active`), so the idle frame never blocks autosave. The X button and the "Crop cancelled"/"reset" status follow `crop_session_can_reset()` instead (box differs from the ratio-fitted frame, or is selection-derived or rotated): a ratio frame is smaller than the canvas, so Apply is on but the X stays off (GitHub issue 318, `ui_crop_cancel_button_off_for_ratio_frame`).
- **An active selection becomes the box** instead: `selection_.boundingRect()`, overriding the ratio for that box. The marching ants hide while the box descends from it (`crop_box_from_selection_`, cleared by Esc or a new drag-out; `draw_selection_overlay`), a tool switch brings them back, and a commit clears the selection (`ui_crop_tool_adopts_active_selection`). A selection set or cleared under the tool (Select All, Inverse, scripts) re-frames a default or selection-derived box through `follow_selection_into_crop_session` (called from the selection setters; a custom box or an in-flight drag is left alone), so the box never lags the marquee.
- **Default frame vs custom box** (`crop_box_is_default_`): while the box is the automatic frame, a press on the canvas that misses a handle lays out a new rect (the frame has no interior to move; a sub-drag click keeps it), and a press on the pasteboard rotates. Any drag-out, handle drag, nudge, or rotation makes the box custom: then the interior moves it (`snapped_rect_delta`), arrows nudge (Shift = 10 px), and a drag off the box ROTATES it about its center (the straighten gesture; Shift snaps 15 degrees, a mere click changes nothing; hover off the box shows the nearest corner's `corner_rotate_cursor` through `transform_rotate_cursor_at`, by the corner's on-screen direction). The handles reuse `transform_handle_at` (`EdgesAndCorners`: an edge resizes anywhere along it, GitHub issue 176, [move-tool.md](move-tool.md)) with Rotate mapped to None. Enter or the options-bar check commits; Esc and the X put the frame back (`reset_crop_session_to_canvas`), they never end the session.
- Switching tools, locking edits, or swapping documents CANCELS a pending crop (never commits, unlike Free Transform): an accidental switch must not resize the document. Re-clicking the Crop palette button keeps the box (`set_tool` tears down only on an actual tool change). Focus loss ends in-flight drags but keeps the session.

## Commit and `crop_document`

- **Delete Cropped Pixels / Delete Off-Canvas Layers** (`cropDeletePixelsCheck`, `tools/cropDeletePixels`, default on; `cropDeleteLayersCheck`, `tools/cropDeleteLayers`, default off; both persisted) on the options bar are Canvas Size's two layer options, the first named and defaulted like Photoshop's. Pixels on, an unrotated commit is `crop_document` (tight per-layer buffers); off, it is the Canvas Size frame resize (`resize_canvas_to_frame(doc, rect, color, false)`): every layer keeps its pixels beyond the new canvas (a later canvas extension or move brings them back) and Background fills new area with the background color. Layers on, `remove_layers_outside_canvas(doc, rect)` runs against the frame BEFORE the crop (the crop would empty those layers and hide them from the test) and the status line reports the count. A rotated box always goes through the rotated `crop_document` (destructive); the layer delete then uses the axis-aligned rect as a conservative test (`ui_crop_delete_options_crop_and_delete_layers`).
- A rotated box straightens on commit through the 4-arg `crop_document(doc, rect, angle, extension_color)`: result pixels sample the document through the inverse rotation about the box center (`sample_rotated_crop_pixels`: bilinear for 8-bit, bilinear on float samples in the buffer's own domain for 16/32-bit layers that keep their format, nearest otherwise), text/smart-object/vector data ride the same affine, exposed areas follow the crop fill rules (Background fill color; elsewhere transparency, promoting an opaque RGB layer to RGBA at its own depth), and angles under 0.01 degrees take the exact unrotated path. Handle drags on a rotated box run the axis-aligned edge math in the box's own frame; snapping is skipped while rotated (guides assume axis-aligned edges).
- The rect may extend past the canvas; commit expands the document (through the 3-arg `crop_document(doc, rect, extension_color)` in document_geometry.cpp, or `resize_canvas_to_frame` with Delete Cropped Pixels off). A contained rect takes the exact per-layer crop path; an expanding one keeps tight buffers on ordinary layers and rebuilds only a pixel layer literally named "Background" canvas-sized via `resize_layer_to_canvas`, filled with the background color at commit. Channels ride `resize_document_channel_canvas` (Spot new area 255, others 0). The 2-arg `crop_document` still clamps to the canvas: the script API relies on that contract. After a commit `set_document` frames the new canvas afresh and the view recenters at the current zoom.

## Ratio and Size

- **Ratio** (`tools/cropRatioWidth`/`tools/cropRatioHeight`, persisted; both > 0 to constrain): a change reshapes the pending box at once (`set_crop_ratio`). The default frame re-fits from the whole canvas (`ratio_fitted_crop_rect`: the largest rect of the ratio inside the canvas, centered), so Clear (both fields to 0, the list back on Ratio) grows it back. A custom box keeps its width and center and derives the height, which makes the result independent of the intermediate ratios a field passes through as it is typed (fitting inside itself would shrink cumulatively); Clear leaves it alone. The ratio also constrains drag-outs (over Shift's 1:1 latch, toggleable mid-drag) and always binds corner drags, re-centering the derived axis on edge drags. Shift on a corner with no ratio holds the drag-start aspect. `transform_drag_keeps_aspect` deliberately does not apply: crop is a drag-rect tool, not a transform session.
- **Preset list** (`cropPresetCombo`, GitHub issue 696; rows and matching in `ui/crop_presets.hpp`, the window's side in main_window_crop_bar.cpp) replaced the Style and Ratio lists. Top to bottom: the free modes Ratio and Size | Original Ratio (the active document reduced by gcd when it is picked) and 1:1, 4:5, 5:7, 2:3, 16:9 | six pixel sizes read by id from the New Document templates (`crop_size_template_ids`: 720p, 1080p, 4K, Social Post, Portrait Post, Social Story; never a second table of sizes) | the saved presets | Save Preset... and Delete Preset. A row sets the style (`tools/cropStyle`: 0 Ratio, 1 Size; `crop_option_widget_visible` swaps the two field sets inside `refresh_options_bar`) and its values in one step (`set_crop_style_and_ratio`): Ratio shows the ratio fields with nothing set (what None was), a ratio row fills them, Size shows the pixel fields, and a size row also sets the box to that many pixels about its center. A size preset never resamples (Photoshop's does): the commit crops or extends the canvas to it. The fields stay the source of truth: `sync_crop_preset_combo` shows the row the style, the ratio fields and the pending box match (`crop_preset_row_for_state`: a saved preset before a built-in one, Original Ratio before the fixed ratios, else the free mode, which is also what a ratio of the user's own shows, the old Custom). Size runs the canvas unconstrained (`effective_crop_ratio_*`); the stored ratio stays in the settings meanwhile, and picking Ratio clears it.
- **Saved presets.** Save Preset... (enabled while the values are not saved yet: a set ratio, or the Size box) asks for a name (`cropSavePresetDialog`, offering "3 : 2" or "1920 x 1080 px") and appends to `tools/cropUserPresets`, a permanent key: a JSON array, oldest first, of `id` ("user-N", one above the highest), `name`, `kind` (`ratio` or `size`), `w` and `h`. Those names and tokens never change; entries without a usable id, name, kind or value are skipped, and the key is removed with the last preset. Delete Preset removes the saved preset the list shows, without a prompt; it is off otherwise, so built-in rows cannot be deleted. The crop context menu lists the rows without the two commands ([canvas-context-menu.md](canvas-context-menu.md)).
- **Fields.** Both ratio pairs (this one and the marquee's Fixed Ratio) are `TrimmedDoubleSpinBox` (unit_spin_box.hpp): two decimals of input, trailing zeros dropped from the display ("0", "2", "1.5"; `ui_crop_ratio_fields_show_trimmed_numbers`). Size shows `UnitIntSpinBox` Width / Height fields built like the marquee's Fixed Size pair (pixel native, typed unit tokens convert at the document PPI through `document_axis_context`, the same quick values, commit on Enter or focus-out): they mirror the pending box after every change and `set_crop_session_size` resizes it about its center, the link button keeping the box's proportion (`ui_crop_size_style_fields_mirror_and_resize_box`). The ratio fields, like every toolbar spin box, select their value on focus (`select_all_on_focus`, [ui-conventions-dialogs.md](ui-conventions-dialogs.md)).
- **Swap buttons** (GitHub issue 697; the shared framed button, [options-bar.md](options-bar.md)). In the ratio pair `cropRatioSwapButton` stands where the ":" was and trades the two values through `swap_crop_ratio`: the automatic frame re-fits, and a custom box trades its width and height about its center (keeping its width, as a typed ratio does, would balloon it). It is off until a value is set. In Size, `cropSizeSwapButton` sits between Width and Height (the link button follows Height) and trades the box's width and height about its center; on the automatic frame that lays a turned box over the canvas (`ui_crop_swap_buttons_turn_ratio_and_size`).
- **Bar groups** ([options-bar.md](options-bar.md) grouping rules): the Preset list | the ratio pair with its swap button and Clear (Ratio) or Width, swap, Height and link (Size) | the Overlay list (GitHub issue 325) | Delete Cropped Pixels and Delete Off-Canvas Layers | the Crop options gear button (rule 1: advanced options) | Apply and Cancel. Clear stays beside the pair it clears (rule 2), as GitHub issue 324 settled; `ui_crop_options_bar_groups_its_controls` checks the order and the one row at 1366 px and in the 1180 px test window, in both modes.

## Drag gestures

- `crop_drag_rect` is the third deliberately-unmerged twin of `marquee_selection_rect`/`shape_drag_rect`; unlike the marquee, its anchor is never edge-clamped (the pasteboard is legal). Space repositions a drag-out in flight, and Space during a handle drag slides the whole box with the drag-start rect following, so releasing it resumes the resize in place (the marquee handle rule, same `spacebar_reposition_start_marquee_*` storage; `ui_crop_handle_drag_space_slides_box_then_resumes`). Photoshop has no such gesture; Patchy keeps the two tools consistent.
- **Alt during a drag-out draws from the center** (`crop_from_center_`): the press point is the box center and the box is twice the drag extent, with a set ratio or Shift's square latch still constraining. Both latches are read from every move and from mid-drag Shift/Alt key events, so Alt pressed after the press, or released before the release, takes effect with a stationary pointer (GitHub issue 78, `ui_crop_alt_drag_out_draws_from_center`). On Windows, Alt+Space during any canvas gesture is forwarded as Space by `canvas_alt_space_filter.cpp` rather than opening the window's system menu ([platform-sites.md](platform-sites.md)).
- Alt while dragging a handle resizes about the box's center: the opposite side mirrors the dragged one (`center_anchored_handle_rect` in canvas_widget_shared.cpp, shared with the marquee handles; a set ratio or Shift still constrains). Read per move, so Alt pressed after the grab counts, and Alt over a handle keeps the resize cursor (GitHub issue 66, `ui_crop_alt_handle_drag_resizes_about_center`).
- **Size style's link binds handle drags** (GitHub issue 332): with Size style and `cropLinkSizeButton` down, `crop_size_link_active()` feeds `set_crop_keep_proportions`, and `update_crop_adjust_drag` takes the drag-start width:height as its target ratio for every handle, the same path a set ratio uses (corners scale both sides, edges derive the other axis re-centered, Alt about the center, rotated boxes in their own frame). Link off, or Ratio style, leaves handles free (`ui_crop_size_link_keeps_proportion_on_handle_drags`).
- The marquee resize handles ([selection-tools-marquee.md](selection-tools-marquee.md)) copy the non-ratio branch of `update_crop_adjust_drag` (exclusive right/bottom edges, 1 px minimum, clean flip) and share `draw_transform_handle_squares` with the transform controls.

## Overlay and hints

- Overlay (`draw_crop_overlay`): a QRegion-with-hole shield outside the box plus composition guides (below) as cosmetic dark+light line pairs, deliberately unthemed like the marching ants; the W x H readout rides `draw_drag_size_readout`. Full-widget repaints during crop drags are accepted (the shield spans the viewport). The idle frame shields only the pasteboard.
- **Crop options popup** (`cropOptionsButton`, a gear menu button, [options-bar.md](options-bar.md) rule 8, its own group between the Delete checkboxes and Apply; GitHub issue 326): the overlay's Turn Overlay and Always / While Dragging come first (issue 325, below), then Show Cropped Area (`tools/cropShowCroppedArea`, default on; off fills the outside with `backdrop_color()`, opaque) and the crop shield: Enable Crop Shield (`tools/cropShieldEnabled`, on; off draws nothing outside), Color (`tools/cropShieldColor`, `#rrggbb`, black, chosen in Patchy's picker with live preview) and Opacity (`tools/cropShieldOpacity`, 0 to 100, default 47, which is the original alpha 120). The values live in `CropOverlayOptions` (canvas_types.hpp), mirrored in `current_crop_overlay_options_` and pushed to every canvas by `apply_crop_overlay_options`. The shield color is a user setting like the grid and guide colors, so it stays outside the theme palette (`ui_crop_options_popup_sets_shield_and_cropped_area`). Photoshop's canvas-moves mode and Auto Center Preview are not implemented.
- The activation hint (`tool_activation_hint_source`) names the handle, lay-out, rotate, Enter and Esc gestures; the Crop line in the info panel shows the pending W x H and angle.

- **Overlay choices** (GitHub issue 325): `cropOverlayCombo` (`tools/cropOverlay`, a token: `none` (shown as "No Overlay"), `thirds` default, `grid`, `diagonal`, `triangle`, `goldenRatio`, `goldenSpiral`; an unknown token is `thirds`) sets `CanvasWidget::CropOverlay`, items in enum order. `crop_overlay_guides` builds the lines per paint from the box alone (no image-sized work): axis-aligned lines in groups drawn dark-then-light per group, which keeps Rule of Thirds pixel-identical to the old fixed thirds; Grid is near-square cells, six across the shorter side (long side capped at 48); Golden Ratio is 1/phi^2 and 1/phi of each side; Diagonal the two corner-to-corner lines; Triangle one diagonal plus the perpendiculars from the other two corners; Golden Spiral ten square cuts of a golden rectangle with a quarter arc each, stretched to the box and turned upright for a portrait box. Oblique lines and arcs draw antialiased and clipped to the box; the arcs' dark twin is a 2 px stroke under the light one. The Crop options menu (`cropOptionsMenu`) starts with Turn Overlay (`cropOverlayTurnAction`, enabled for Triangle and Golden Spiral only), which steps `tools/cropOverlayOrientation` 0-3 (bit 0 mirrors horizontally, bit 1 vertically; the Triangle reads bit 0), and Always Show Overlay / Show Overlay Only While Dragging (`tools/cropOverlayShow`, `always` or `dragging`; both disabled under No Overlay): the latter draws guides only during a drag-out, handle drag, move or rotate. The list has no label (its entries name themselves) and a fixed 112 px width, and its settings live in the shared menu, so the bar keeps one row in the 1180 px test window: a wrapped bar can un-wrap mid-drag and shift the canvas under handle-drag tests. `ui_crop_overlay_choices_draw_their_guides` checks the lines per choice, the turns, While Dragging and the persistence.
- **Crop keys** (GitHub issue 698; `MainWindow::handle_crop_option_key_event`). While `crop_session_can_reset()` holds (a box the user could lose, the X button's rule), O is Next Overlay (`cropOverlayNextAction`, first in the Crop options menu: it steps the six overlays and wraps, No Overlay is not a stop), Shift+O is Turn Overlay (swallowed when the overlay has nothing to turn, never a tool switch) and H toggles Show Cropped Area. With the automatic frame the letters switch tools as on any tool, so a stray O or H no longer throws a box away. The application event filter takes the ShortcutOverride and the key press for whatever in the window holds the keyboard, like the opacity digits; a text field keeps its letters. These are built-in keys, not commands: each is taken only while the key is still on the command Patchy ships it on, or on nothing (`crop_option_key_available`), so a letter the user or a shortcut set gave to another command runs that command ([hotkey-sets.md](hotkey-sets.md#crop-keys)). The menu shows the keys that apply (set when it opens) and the Overlay list's tooltip names O (`refresh_crop_key_hints`). Photoshop's P toggles its canvas-moves mode, which Patchy does not have (GitHub issue 699). `ui_crop_keys_step_overlay_and_cropped_area_while_box_pending`, `ui_crop_keys_yield_to_reassigned_letters`.

## Image menu crop commands

- **Image > Crop to Selection and Crop to Selection (Advanced) use the pending box while the Crop tool is active** once the user has laid one out (`crop_session_active() && crop_session_has_changes()`): the plain command calls `commit_crop_session` (same as Enter), the advanced one takes `crop_session_rect()` as the dialog frame and refuses a rotated box with a status message (its `resize_canvas_to_frame` path has no rotation). While the box is still the automatic canvas frame (after Esc, say) a marquee selection wins, and with neither the commands report "Nothing to crop" (`ui_crop_menu_commands_use_crop_box`).
- Image > Crop to Selection (Advanced) is the Canvas Size dialog prefilled with the selection as its frame (W/H, anchor about the selection, extension color, the layer crop checkbox starting checked and the delete-off-canvas one unchecked), applied through `resize_canvas_to_frame` rather than `crop_document`; see the dialog semantics in [resolution-units.md](resolution-units.md).
- **Image > Trim...** (`image.trim`, no default shortcut; GitHub issue 297; `MainWindow::trim_canvas_dialog`) crops through `crop_document` to the rect `trim_bounds` (formats/document_trim.cpp) finds on the composite of every visible layer at the document's depth (`flatten_document_for_trim`). Based On: Transparent Pixels (alpha exactly 0; offered only when some composite pixel is below full alpha), Top Left or Bottom Right Pixel Color (every channel equal at the composite's depth; a transparent corner matches every transparent pixel). Tolerance (0..255, default 0 = those exact matches) widens them to alpha <= N, or every channel (alpha included) within N of the corner; N is in 8-bit units at every depth, comparing display-encoded values as the Magic Wand does (32-bit composites are sRGB-encoded first). Trim Away: each checked side drops its run of fully matching rows or columns; OK is off with no side checked. No change (nothing matches, or every pixel matches) is a status message and no undo step; with a tolerance above 0, every pixel matching says so and suggests a lower Tolerance. Artboard documents are refused like Crop. Settings `trim/basedOn` (the ids `transparent`, `topLeft`, `bottomRight`, shared with `doc.trim`) `trim/top|bottom|left|right` and `trim/tolerance` are permanent.
