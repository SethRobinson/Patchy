# Crop tool

Read this before changing the Crop tool, its options bar, or `crop_document`. Related tool-wide rules live in [tools.md](tools.md).

Photoshop-style interactive crop (hotkey C; `tools.crop`). Session code in canvas_widget_crop.cpp; commit in `MainWindow::commit_crop_rect` (main_window_layer_ops.cpp): `crop_document` with Delete Cropped Pixels on (the default) or a rotated box, the Canvas Size frame resize with it off (see below).

- **Picking the tool frames the canvas** (`begin_default_crop_session`, called from `set_tool`, `set_document_internal` and an unlock): the box is the whole canvas, fitted to the ratio when one is set, with the 8 handles ready, so dragging a handle inward crops and outward extends the canvas without drawing anything first (GitHub issue 66). The session exists whenever the tool is current and a document is set; `crop_session_has_changes()` (box differs from the unrotated canvas) gates Apply and the X button, the no-op Enter ("Nothing to crop"), the "Crop cancelled" status, and the recovery busy check (`any_canvas_interaction_active`), so the idle frame never blocks autosave.
- **An active selection becomes the box** instead: `selection_.boundingRect()`, overriding the ratio for that box. The marching ants hide while the box descends from it (`crop_box_from_selection_`, cleared by Esc or a new drag-out; `draw_selection_overlay`), a tool switch brings them back, a commit clears the selection as before (`ui_crop_tool_adopts_active_selection`).
- **Default frame vs custom box** (`crop_box_is_default_`): while the box is the automatic frame, a press on the canvas that misses a handle lays out a new rect (the frame has no interior to move; a sub-drag click keeps it), and a press on the pasteboard rotates. Any drag-out, handle drag, nudge, or rotation makes the box custom: then the interior moves it (`snapped_rect_delta`), arrows nudge (Shift = 10 px), and a drag off the box ROTATES it about its center (the straighten gesture; Shift snaps 15 degrees, a mere click changes nothing; hover off the box shows `crop_rotate_cursor()` from tool_cursors.cpp as the hint). The handles reuse `transform_handle_at` with Rotate mapped to None. Enter or the options-bar check commits; Esc and the X put the frame back (`reset_crop_session_to_canvas`), they never end the session.
- A rotated box straightens on commit through the 4-arg `crop_document(doc, rect, angle, extension_color)`: result pixels sample the document through the inverse rotation about the box center (bilinear for 8-bit, nearest otherwise), text/smart-object/vector data ride the same affine, exposed areas follow the crop fill rules (Background fill color, transparency plus rgba8 promotion elsewhere), and angles under 0.01 degrees take the exact unrotated path. Handle drags on a rotated box run the axis-aligned edge math in the box's own frame; snapping is skipped while rotated (guides assume axis-aligned edges).
- The rect may extend past the canvas; commit expands the document (through the 3-arg `crop_document(doc, rect, extension_color)` in document_geometry.cpp, or `resize_canvas_to_frame` with Delete Cropped Pixels off). A contained rect takes the exact legacy per-layer path; an expanding one keeps tight buffers on ordinary layers and rebuilds only a pixel layer literally named "Background" canvas-sized via `resize_layer_to_canvas`, filled with the background color at commit. Channels ride `resize_document_channel_canvas` (Spot new area 255, others 0). The 2-arg `crop_document` still clamps to the canvas: the script API relies on that contract. After a commit `set_document` frames the new canvas afresh.
- Switching tools, locking edits, or swapping documents CANCELS a pending crop (never commits, unlike Free Transform): an accidental switch must not resize the document. Re-clicking the Crop palette button keeps the box (`set_tool` tears down only on an actual tool change). Focus loss ends in-flight drags but keeps the session.
- **Ratio** (`tools/cropRatioWidth`/`tools/cropRatioHeight`, persisted; both > 0 to constrain): a change reshapes the pending box at once (`set_crop_ratio`). The default frame re-fits from the whole canvas (`ratio_fitted_crop_rect`: the largest rect of the ratio inside the canvas, centered), so Clear grows it back. A custom box keeps its width and center and derives the height, which makes the result independent of the intermediate ratios a field passes through as it is typed (fitting inside itself would shrink cumulatively); Clear leaves it alone. The ratio also constrains drag-outs (over Shift's 1:1 latch, toggleable mid-drag) and always binds corner drags, re-centering the derived axis on edge drags. Shift on a corner with no ratio holds the drag-start aspect. `transform_drag_keeps_aspect` deliberately does not apply: crop is a drag-rect tool, not a transform session.
- **Style** (`cropStyleCombo`, `tools/cropStyle`; 0 Ratio, 1 Size; `crop_option_widget_visible` swaps the two field sets inside `refresh_options_bar`). Ratio shows the preset combo, the unitless W : H pair and Clear. Size shows `UnitIntSpinBox` Width / Height fields built like the marquee's Fixed Size pair (pixel native, typed unit tokens convert at the document PPI through `document_axis_context`, the same quick values, commit on Enter or focus-out): they mirror the pending box after every change and `set_crop_session_size` resizes it about its center, the link button keeping the box's proportion. Size mode runs the canvas unconstrained; the remembered ratio (`current_crop_ratio_*`, what the settings persist) returns with Ratio mode through `effective_crop_ratio_*` (`ui_crop_size_style_fields_mirror_and_resize_box`).
- The Ratio preset combo (`cropRatioPresetCombo`) writes into the W : H fields, which stay the source of truth: index 0 "None" and the last index "Custom" are fixed anchors (`sync_crop_ratio_preset_combo` derives the row from the field values and shows Custom for anything unmatched), "Original Ratio" reads the active document reduced by gcd at selection time, and Clear resets to None.
- `crop_drag_rect` is the third deliberately-unmerged twin of `marquee_selection_rect`/`shape_drag_rect`; unlike the marquee, its anchor is never edge-clamped (the pasteboard is legal). Space repositions a drag-out in flight, and Space during a handle drag slides the whole box with the drag-start rect following, so releasing it resumes the resize in place (the marquee handle rule, same `spacebar_reposition_start_marquee_*` storage; `ui_crop_handle_drag_space_slides_box_then_resumes`). Photoshop has no such gesture; Patchy keeps the two tools consistent.
- Alt while dragging a handle resizes about the box's center: the opposite side mirrors the dragged one (`center_anchored_handle_rect` in canvas_widget_shared.cpp, shared with the marquee handles; a set ratio or Shift still constrains). Read per move, so Alt pressed after the grab counts, and Alt over a handle keeps the resize cursor (GitHub issue 66, `ui_crop_alt_handle_drag_resizes_about_center`). The ratio fields, like every toolbar spin box, select their value on focus (`select_all_on_focus`, [ui-conventions.md](ui-conventions.md)).
- The marquee resize handles ([selection-tools.md](selection-tools.md)) copy the non-ratio branch of `update_crop_adjust_drag` (exclusive right/bottom edges, 1 px minimum, clean flip) and share `draw_transform_handle_squares` with the transform controls; the crop code itself is unchanged.
- Overlay (`draw_crop_overlay`): QRegion-with-hole shield at rgba(0,0,0,120) plus rule-of-thirds cosmetic line pairs, deliberately unthemed like the marching ants; the W x H readout rides `draw_drag_size_readout`. Full-widget repaints during crop drags are accepted (the shield spans the viewport). The idle frame shields only the pasteboard.
- The activation hint (`tool_activation_hint_source`) names the handle, lay-out, rotate, Enter and Esc gestures; the Crop line in the info panel shows the pending W x H and angle.
- Plain C moved here from `image.crop_to_selection` (August 2026); that menu command keeps its persisted id but ships with no default shortcut, like Photoshop's Image menu.
- **Image > Crop to Selection and Crop to Selection (Advanced) use the pending box while the Crop tool is active** once the user has laid one out (`crop_session_active() && crop_session_has_changes()`): the plain command calls `commit_crop_session` (same as Enter), the advanced one takes `crop_session_rect()` as the dialog frame and refuses a rotated box with a status message (its `resize_canvas_to_frame` path has no rotation). While the box is still the automatic canvas frame (after Esc, say) a marquee selection wins as before, and with neither the commands report "Nothing to crop". A selection set or cleared under the tool (Select All, Inverse, scripts) re-frames a default or selection-derived box through `follow_selection_into_crop_session` (called from the selection setters; a custom box or an in-flight drag is left alone), so the box never lags the marquee (`ui_crop_menu_commands_use_crop_box`).
- **Delete Cropped Pixels / Delete Off-Canvas Layers** (`cropDeletePixelsCheck` `tools/cropDeletePixels` default on; `cropDeleteLayersCheck` `tools/cropDeleteLayers` default off; both persisted) on the options bar: Canvas Size's two layer options, the first named and defaulted like Photoshop's. Pixels on, an unrotated commit is `crop_document` (tight per-layer buffers, the tool's long-standing behavior); off, it is the Canvas Size frame resize (`resize_canvas_to_frame(doc, rect, color, false)`): every layer keeps its pixels beyond the new canvas (a later canvas extension or move brings them back) and Background fills new area with the background color. Layers on, `remove_layers_outside_canvas(doc, rect)` runs against the frame BEFORE the crop (the crop would empty those layers and hide them from the test) and the status line reports the count. A rotated box always goes through the rotated `crop_document` (destructive); the layer delete then uses the axis-aligned rect as a conservative test. `ui_crop_delete_options_crop_and_delete_layers`.
- Image > Crop to Selection (Advanced) is the Canvas Size dialog prefilled with the selection as its frame (W/H, anchor about the selection, extension color, the crop and delete-off-canvas checkboxes), applied through `resize_canvas_to_frame` rather than `crop_document`; see the dialog semantics in [resolution-units.md](resolution-units.md).
- Coverage: core `crop_document_expanding_*`/`crop_document_mixed_crop_and_expand`/`crop_document_contained_rect_matches_two_arg_overload` (document_ops_filters_tests.cpp); UI `ui_crop_*` (crop_tool_tests.cpp), notably `ui_crop_tool_frames_canvas_and_fits_ratio`, `ui_crop_tool_adopts_active_selection`, `ui_crop_menu_commands_use_crop_box` and `ui_crop_delete_options_crop_and_delete_layers`.
