# Edit > Fill

Edit > Fill... (Shift+Backspace, Shift+F5; action `editFillAction`) opens the Fill dialog (`src/ui/fill_dialog.cpp`, objectName `patchyFillDialog`, issues 530, 575 and 743). `MainWindow::edit_fill_dialog` (main_window_layer_ops.cpp) refuses a read-only channel or an unfillable layer before showing it, as Stroke Selection does. The Fill tool (Paint Bucket) and the plain Fill command are in [tools.md](tools.md#fill-tool-paint-bucket-and-the-fill-command).

## Dialog

Two group boxes, **Fill** and **Blending**, each a `QFormLayout` (`AllNonFixedFieldsGrow`) whose label column `align_form_label_columns` gives one width, so every field starts at one x; the two checkboxes sit in the field column with no label (issue 575's follow-up). OK is as wide as Cancel in every language (`equalize_dialog_button_widths`).

- **Contents:** (`editFillContentsCombo`): Foreground Color, Background Color, Color..., a separator, Black, 50% Gray, White, a separator, Pattern, Content-Aware. Color... (from the list or a click on the swatch `editFillColorSwatch`) opens the color picker at once; cancelling it goes back to the previous choice. The swatch's `fillColor` property holds the Color... choice, so automation can set it without the picker. The swatch hides (keeping its room) while Pattern or Content-Aware is chosen.
- **Pattern:** (`editFillPatternCombo`, the row under Contents; [Pattern](#pattern) below) lists the pattern library. The row keeps its place and is enabled, with its label, only while Pattern is chosen.
- The list and swatch are `FillContentsField` (fill_dialog.hpp), shared with the New Layer dialog's Fill row ([new-layer.md](new-layer.md#new-layer-dialog)): it builds both from a list of `FillContents` (Transparent and Neutral are New Layer's only; `fill_contents_from_token` never reads them, so `tools/editFillContents` cannot hold them; Pattern is Edit > Fill's only, and New Layer's list does not name it) and sizes the combo with `fit_combo_to_entries`, so every entry shows whole in the box and in the open list in every language and style (issues 575, 655: under Fusion, the Linux style, the open list is a menu whose rows need more room than the box, and it elided "Foreground Color").
- **Blending**: Mode: (`editFillModeCombo`, the paint modes including Behind and Clear from `core/paint_mode.hpp`, which change only alpha; this dialog alone adds a separator above Behind, the Brush bar's shared `add_paint_mode_items` list keeps none), Opacity: 1..100 (`editFillOpacitySlider` / `editFillOpacitySpin`, an `add_dialog_slider_spin_row`), Preserve Transparency (`editFillPreserveTransparencyCheck`).
- Color contents go through a `FillCommandBlend` into `fill_active_layer_with_color`; non-Normal Modes use `EditOptions::fill_paint_mode`. The Foreground and Background choices carry the paint intensity of their color. No History contents.

## Settings

Saved on OK, all permanent identifiers: `tools/editFillContents` (tokens `foreground`, `background`, `color`, `black`, `gray50`, `white`, `pattern`, `contentAware`), `tools/editFillColor`, `tools/editFillPatternId` (the chosen pattern's library id, kept while another Contents is chosen, as the color is), `tools/editFillMode` (the script paint-mode id), `tools/editFillOpacity`, `tools/editFillPreserveTransparency`, `tools/editFillContentAwareNewLayer`.

## Pattern

- Pattern (issue 743) fills with one pattern library tile repeated from the document's top-left corner, at 100% size and no rotation. The list is the library as the Pattern Stamp lists it (`add_pattern_library_items`, pattern_library.hpp: thumbnail, display name, a tooltip with folder and size), a scrolling list (`use_scrolling_list_popup`) sized to its entries. It opens on the pattern used last, or the first one when that pattern has left the library.
- Offered when the library has a pattern and the target is a layer's own pixels (`FillPatternSource`): for a mask, a document channel, a Smart Filter mask or Quick Mask the entry is disabled with a tooltip, and a remembered Pattern opens as Foreground Color. An empty library disables it too.
- It honors the selection (coverage included), Mode, Opacity and Preserve Transparency and is one "Fill" history step, like a color. A tile pixel's own alpha scales the fill there; a clear tile pixel leaves the layer as it was.
- `MainWindow::edit_fill_dialog` resolves the tile (`PatternLibrary::resource`) and passes it in `FillCommandBlend::pattern_tile`; `fill_active_layer_with_color` sets `EditOptions::fill_pattern_tile`, and core `fill_rect` reads each pixel's color and alpha from `PatternTileSampler` at 100% (a nearest lookup, anchored at the document origin), then writes it through the color fill's own pixel writers, so depth, palette mode and every Mode behave as for a color. The tile must be 8-bit RGB or RGBA; any other fills nothing.
- The legal boundary is the Pattern Stamp's ([legal-constraints.md](legal-constraints.md#brush-behavior)): a direct lookup into one static tile. The fill never reads the destination to shade, adapt or synthesize the pattern, and there are no scripted or generated arrangements (brick, cross weave, random and the like): each needs its own claim read first.
- The document keeps only the filled pixels: no pattern is added to its pattern store, and a PSD holds nothing but the layer.

## Content-Aware

- Offered only when there is a selection and the target is a layer's own pixels (not a mask, a document channel, a Smart Filter mask or Quick Mask): otherwise the entry is disabled with a tooltip, and a remembered Content-Aware opens as Foreground Color.
- While it is chosen Preserve Transparency is disabled (the fill comes from the surrounding pixels) and Add to New Layer (`editFillContentAwareNewLayerCheck`) is enabled, only then. Mode and Opacity (with their labels) are enabled only while Add to New Layer is ticked, and then offer only layer blend modes: Behind and Clear are disabled, and a chosen one switches to Normal.
- `MainWindow::content_aware_fill_selection` runs Remove Object's dialog-free path (`CanvasWidget::remove_object_in_selection`, [healing-remove-object.md](healing-remove-object.md#remove-object)) at the dialog's defaults: attempt 0 (the best-match fill), tone match 0, feather 0, under a wait cursor and the canvas progress overlay. It runs with `record_history = false`, then puts the original layer back, pushes ONE "Content-Aware Fill" history entry and writes the result. It is the same engine, so the legal boundary of Remove Object applies unchanged ([legal-constraints-filters.md](legal-constraints-filters.md)): never give this entry its own algorithm.
- **Add to New Layer**: the layer keeps its pixels; Layer Via Copy's `copy_pixels_from_layer` copies the filled layer's pixels under the selection (selection coverage as alpha) onto a new pixel layer named "Content-Aware Fill" directly above it, which becomes active. Outside the selection the new layer is transparent. The new layer takes Mode as its blend mode (Normal where `blend_mode_supported_at_depth` refuses it) and Opacity as its layer opacity.
- The selection stays put.
