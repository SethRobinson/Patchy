# Platform-specific sites

Split from [platform.md](platform.md): the inventory of platform-guarded code, each site with why it differs per OS and the rule that keeps it working there.

## Platform-specific site inventory (keep current)

- Windows Explorer branding: `src/app/patchy.rc.in` embeds the display name and
  project version in every app build; the installer registers the same
  `Patchy Image Editor` name. See [Windows packaging](../packaging/windows/README.md#open-with).
- `main_window_chrome.cpp` + the `use_custom_window_chrome()` call sites in `main_window.cpp` (frameless flag, chrome controls; Win32 native frame, Linux `startSystemMove`/`startSystemResize`).
- `psd_text_read.cpp` / `psd_text_write.cpp` DirectWrite font resolution + wide-string helpers (portable heuristic fallback).
- `layer_list_widget.cpp` drag-wheel low-level mouse hook (degrades gracefully).
- `canvas_alt_space_filter.cpp` (Windows only, inert elsewhere): Qt's Windows key mapper never delivers Space while Alt is held and opens the system menu instead, whose modal loop eats the mouse release of an Alt-from-center drag being repositioned with Space (GitHub issue 78). The app-level native filter, installed once from the `CanvasWidget` constructor, runs ahead of the key mapper: while the focused canvas has `pointer_gesture_active()` it consumes the `VK_SPACE` `WM_SYSKEYDOWN`/`WM_SYSCHAR`/key-up and sends the canvas plain Space key events; idle, Alt+Space still opens the menu. `ui_marquee_alt_space_mid_drag_repositions_instead_of_system_menu` feeds it crafted `MSG`s (offscreen has no Win32 loop).
- `dialog_utils.cpp` `use_qt_file_dialog_controls` (Qt dialog widgets only under offscreen; native/portal dialogs otherwise, on every OS).
- The Print dialog's "Print Using System Dialog..." is always `QPrintDialog`, with no offscreen switch, so the UI test checks the button and never clicks it. On Windows 11 22H2+ that is the "unified" `PrintDlgEx` dialog, which shows "This app doesn't support print preview" to every Win32 caller (only WinRT `PrintManager` apps get a preview there). Do not switch to the classic `PrintDlg` + `PD_ENABLEPRINTHOOK` dialog: it only hides the driver's options behind Properties..., and a `0x80070002` error there means a broken Microsoft Print to PDF install, not a Patchy bug.
- `print_dialog.cpp` `ensure_printer_driver_usable` / `windows_printer_device_is_usable` (Windows only): when `CreateDC` fails (a Microsoft Print to PDF with a broken port registration, `ERROR_PATH_NOT_FOUND`), `QWin32PrintEnginePrivate::initialize` nulls the DEVMODE and `QPageSetupDialog::exec` crashes on it, while the spooler still hands out a DEVMODE. The guard therefore tests the device context, not the DEVMODE, and Print, Page Setup, and the system dialog report "Printer unavailable" instead.
- Windows print-color complaints (right on screen, shifted on paper) are not Patchy's: the spooled PCL XL stream is byte-exact (capture it by giving a `NativeFormat` `QPrinter` a non-`.pdf` output name) and RGB-to-CMYK happens in printer firmware. Converting before `drawImage` changes nothing (`QWin32PrintEngine` re-tiles to opaque RGB32).
- `dialog_utils_mac.mm` `keep_dialog_above_parent_window` (macOS child-window anchor, see [macOS non-modal dialog anchoring](platform.md#macos-non-modal-dialog-anchoring); wasm has its own restacking version in dialog_utils.cpp; first Objective-C++ TU, `enable_language(OBJCXX)` is APPLE-gated in CMakeLists).
- `dialog_utils_mac.mm` `move_pointer_to_global_position`: Qt's cocoa `QCursor::setPos` posts a synthetic CGEvent, so macOS asks the user to let Patchy control the computer (Accessibility). The macOS half calls `CGWarpMouseCursorPosition` instead, which needs no permission. Never call `QCursor::setPos` directly in `src/ui`; the one caller is the Alt+Right-drag brush adjust snapping the pointer back to its anchor.
- `dialog_utils.cpp` `screen_color_at_global_position` (the canvas eyedropper outside the document and the color picker's screen eyedropper): `QScreen::grabWindow` raises the macOS Screen Recording permission prompt, so on macOS it first renders the Patchy window under the point (`own_window_color_at_global_position`, a `QWidget::grab`, no permission). Only a pick outside Patchy's windows or on a native title bar reads the screen there; other platforms keep the plain screen read (`ui_own_window_color_sample_reads_widget_without_screen_grab`).
- HDR display info (`app.displayInfo()`, the stress report's `platform.screen`): `display_hdr_info_win.cpp` matches the screen's HMONITOR (`QNativeInterface::QWindowsScreen`) to a DXGI output (`IDXGIOutput6::GetDesc1`: PQ color space means "Use HDR" is on, plus peak, full-frame and minimum nits), reads SDR white from DisplayConfig only while HDR is on, and flags `SM_REMOTESESSION`; a fresh DXGI factory per query, since an old one keeps its first color space. `display_hdr_info_mac.mm` matches NSScreen by flipped frame (then name) and reads the current and potential EDR headroom, no nits. Linux, wasm and offscreen report `hdrQueried=false`. All arithmetic and the presenter eligibility policy (`PATCHY_HDR_DISPLAY=0/1`) live in Qt-free `core/hdr_display.hpp`. Nothing renders in HDR yet.
- Scanner import uses Windows WIA in `scanner_import_win.cpp` and macOS ImageKit/ImageCaptureCore in `scanner_import_mac.mm`; the macOS browser exposes local and network scanners but not cameras, and acquisition remains single-image on both platforms. The AppKit sheet is callback-based so the File menu action returns to the native run loop; never wait for it with a nested `QEventLoop` (its controls stay visible but take no mouse input).
- The app stylesheet's `QCheckBox { border: none }` (macOS Aqua layout-item margin suppression, see [Styled QCheckBox and QMacStyle margins](platform.md#styled-qcheckbox-and-qmacstyle-margins)) and its APPLE-gated `QGroupBox` block + `brush_dynamics_popup.cpp` `compact_group_grid` (QMacStyle's Aqua group-box chrome and layout spacings blow dense panels past the screen; Windows keeps native metrics).
- `dialog_utils.cpp` `suppress_native_tab_bar_base` (macOS document-mode tab bars paint a light native base across their width even though the `::tab` rules still apply, so the document tabs drop the base; no-op elsewhere).
- `app_style.cpp` `AppStyle::styleHint` macOS block (pins SH_FormLayoutFieldGrowthPolicy / LabelAlignment to the Windows behavior; QMacStyle keeps form fields at size-hint and right-aligns labels, shrinking edits to slivers).
- `main_window_files.cpp` `reveal_path_in_file_explorer`: the Windows branch must pass `/select,` and the file path as SEPARATE QProcess arguments. QProcess quotes any space-containing argument whole, and Explorer reads a quoted `"/select,path"` blob as unparseable, silently opening the default folder.
- `network_mounts.cpp` `read_system_mounts` (macOS `getmntinfo(MNT_NOWAIT)`, Linux `/proc/self/mounts`, empty on Windows where `GetDriveTypeW` answers): the recent-history existence check skips paths on non-local mounts and `autofs` triggers, because a stat on a stale share blocks for the whole network timeout and `main()` waits for that worker at quit. Reads cached kernel data only; never replace it with `statfs` on the path, which contacts the server. `ui_network_mount_classification_uses_deepest_mount_point` pins the matcher.
- `main_window_files.cpp` `rebuild_recent_files_menu`: native menu bars (macOS, Linux appmenu desktops) cannot host widget actions, so the recent-files filter row (a QWidgetAction line edit) is skipped when `menuBar()->isNativeMenuBar()`, leaving the plain paged menu. Offscreen reports false, so the UI tests cover the filter row everywhere.
- Optional Qt add-ons get their OWN `find_package(Qt6 QUIET COMPONENTS <X>)` and a `if(TARGET Qt6::X)` source swap, never a slot in `PATCHY_QT_COMPONENTS`: that lookup is QUIET, so one missing component silently skips the entire app target. Qt PDF is the current example (`pdf_import.cpp` vs `pdf_import_stub.cpp`, `PATCHY_HAVE_QT_PDF`); QtPrintSupport uses the same swap shape keyed on EMSCRIPTEN (Qt publishes no wasm build of it). Both stubs must keep every entry point real enough to report the feature as unavailable.
- `update_checker.cpp` platform id (windows/macos/linux manifest keys).
- `appimage_menu_entry.cpp` (Help > Add Patchy to Applications Menu): runs only when `appimage_file_path()` is set (Linux AppImage); the desktop cache tools are `Q_OS_LINUX`-guarded. See [appimage.md](appimage.md#applications-menu-entry).
- `hotkey_registry.hpp` `platform_hotkeys`: per-OS default shortcuts (macOS Clear also takes Backspace, which the Mac delete key sends). Only per-command deltas persist, so saved hotkeys follow the platform default; each OS's defaults must stay conflict-free (`ui_hotkey_defaults_have_no_conflicts`).
- `single_instance.cpp` (Windows only): a relaunch grants `AllowSetForegroundWindow` to the pipe's server process (`GetNamedPipeServerProcessId`) before forwarding; the foreground lock otherwise refuses the running instance's activation and its window only flashes on the taskbar. The receiver comes forward on arrival (`bring_to_front_for_second_instance`, modal dialog first): the grant expires before a deferred file open runs.
- `text_render.cpp` `draw_document_glyph_run`: macOS fills document glyph outlines, because CoreText stem-darkens the cached glyph images Qt draws text up to 64 px with, whatever the `QFont` strategy (Convert to Shape coverage 0.80 at 30 px, 0.99 above 64 px; heavier than Photoshop). About 9 µs a glyph against 1 µs; UI text keeps CoreText's. Pinned by `ui_text_convert_to_shape_matches_small_point_text`.
- `main.cpp` Windows app-font candidates + macOS `Contents/Resources` probes (with `localization.cpp`'s translations probe).
- Tests: `test_harness.hpp`, the paired crash reporters in `tests/ui/main.cpp`, `test_fonts.hpp`.
