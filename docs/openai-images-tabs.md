# OpenAI Image Tools: Expand, Animate and Describe

The Expand, Animate and Describe tabs of the OpenAI Image Tools dialog. The dialog, Edit and Remove, the seams, variations and API facts are in [openai-images.md](openai-images.md); the binding rules are in [legal-constraints.md](legal-constraints.md#prompt-driven-image-generation).

## Expand

A frame view (`OpenAiExpandFrameView`, `openAiImagesExpandView`) shows a thumbnail of the visible image inside the grown canvas, the new area tinted with the accent role; dragging an edge or corner outward adds pixels on that side, and it stops at the image, never inside it (the drag holds its scale, so the frame follows the pointer as it grows). Four fields under it add pixels to the left, top, right and bottom (0 to 10000 each, the new canvas at most 30000 px a side) and stay in step with the view, with a "New canvas: W x H px" readout and an optional prompt (sent with the fixed `kExpandKeepInstructions` after it; empty sends the fixed `kExpandPromptWhenEmpty`). There are no aspect-ratio presets and no crop: the size comes only from the typed margins, and the image is never rotated (docs/legal-constraints.md, "Prompt-driven image generation"). At the click `MainWindow::openai_expand_source` captures the canvas size and the visible image; `openai::expand_frame` places it at (left, top) on a transparent frame of the grown size, scaled down to at most 2048x2048 pixels in area, with coverage 255 in the new area. That goes through `masked_edit_images` for its size and padding, but is sent alone: no mask, `complexity: low`, `background: opaque`, no references. With a mask and the default complexity, 2.6 drew a new strip that did not continue the picture: sharper hair, a different sweater, a hard line at the old edge (Seth's test, 2026-11-06). Probed live on a 2000x1500 photo grown 1100 px at the bottom: mask with default complexity, mask with low, markup with low, and no mask with low. None moved or scaled the picture (best fit at scale 1.0, no shift), and the three low-complexity ones continued it, no mask most closely. When the result arrives, `MainWindow::add_openai_expanded_layers` checks the document is still open at the captured size, pushes one "OpenAI Image Tools" undo step, grows the canvas with Canvas Size's own work (`resize_canvas_without_history`, the old origin at (left, top), the Background extended in white), and adds the image scaled to the new canvas as a layer named "OpenAI Expand" (`expand_layer_image`, no mask), above the original, which stays untouched underneath. The model redraws the original near the new area so the extension flows: on a 512 x 512 photo grown 423 px down, its version differed from the original by 20 to 30 levels in the last quarter next to the seam and about 5 higher up, and that redraw is content, not a shift (aligning it removed little). A fade at the old edge therefore crossfaded two different drawings and ghosted (Seth, 2026-11-06). So the layer is opaque in the new area and over the original to a depth set by Blend (`openAiImagesExpandBlendSlider`, setting `openAiImages/expandBlend`, 0 to 100%, default 25%: that fraction of the deepest an original pixel can lie from new area), then fades to clear over `expand_fade_width` (6% of that depth, at least 8 px), tone matched to the original across the fade (`match_tone`); 0% fades right at the old edge, 100% is OpenAI's whole picture. Blend applies to the current result as it moves (`apply_expand_blend`, the pixels re-prepared and swapped like a variation, no history step). After an Expand is applied the four fields return to 0 and the frame shows the grown canvas alone; kept margins read as a new area left unfilled (Seth, 2026-11-06). A large canvas comes back softer in the new area, since the frame is scaled to about one megapixel for the request.

## Animate

A prompt (required), "Start from" (the prompt only, the active layer, or the visible image; the starting image goes first, then the reference images, and `animation_prompt` says which is which in fixed text), Frames (2 to 16, default 9), Frame delay (20 to 2000 ms, default 200), Frame size (512, 720 or 960 square; sizes above `max_gif_frame_edge` for the frame count are greyed out) and Background (transparent or opaque; GIF transparency is per pixel on or off). The request asks for `output_format: gif` with `frame_count` and `frame_duration_ms`: from the prompt only, a generation; from an image, an edit whose one `image[]` is that image (prepared like a reference) and never a mask. OpenAI draws the frames on one fixed sheet (4x2 for few frames, 3x3 for 9, 4x4 for 16) that must stay within 3840 px a side and its pixel budget: 1024 px frames never fit, 960 px fits up to 9 frames and 720 px up to 16 (derived from refusals; a refusal's message still reaches the status line). The prompt goes inside fixed English sprite-sheet instructions (`openai::animation_prompt`, the form OpenAI's Images 2.6 GIF examples use: exactly N frames, identical panels, fixed camera, same subject, small even steps, a loop, no borders or labels; from an image, also "keep its subject, composition, colors, lighting and style"), so the frames stay consistent; the user's text follows "Motion:". Each returned GIF (`GenerateResult::encoded`) is read with qgif (`openai::gif_frames`, composited frames and their delays) and `MainWindow::add_openai_animation_documents` opens it as a new untitled document "OpenAI Animation", one visible layer per frame, frame 1 on top, each named "Frame N <delay>s" as the GIF import names them (`document_from_frames`, `gif::format_delay_seconds_token`), so File > Export > Layers as Animated GIF and the Animation Preview play it with its timing ([animation.md](animation.md)). Variations open one document each.

Colors (`openAiImagesAnimateColorsCombo`, setting `openAiImages/animateColors`, default GIF, Seth 2026-11-07): OpenAI's GIFs share one 256-color global palette across all frames (measured: 220 to 255 colors a frame), which bands skin and gradients, and the API has no color option. Full color (`sheet`) instead asks for the frames as one ordinary PNG sheet and slices it here: `sheet_layout` picks the grid (fewest spare cells, columns at least rows and at most 3:1; the frame count rounds up to fill it, 5 frames as 6 on 3 x 2, and the status says so), `sheet_animation_prompt` wraps the motion in fixed grid and loop wording, `sheet_request_size` is the grid at the chosen frame size, enlarged to the API's smallest image when below it (two 512 px frames), and `sheet_frames` cuts the reply in reading order and scales each panel to the frame size; `add_openai_animation_frame_documents` builds the document as for a GIF, with the Frame delay for every frame. PNG keeps soft transparency. Probed live 2026-11-07: from a start photo, a clean 3 x 3 grid with neighboring frames 3 to 5 levels apart and about 62,600 colors a frame (the GIF of the same request: 255); from a prompt alone, a clean 3 x 3 grid. GIF stays the default because OpenAI's animation mode is built for it, while the sheet relies on the model keeping the grid.

## Describe

The Describe tab (`DescribeTab`, built 2026-11-06) asks a text model for a written description of an image and shows it in the tab's read-only box (`openAiImagesDescribeText`), selectable and copyable. Source (`openAiImagesDescribeSourceCombo`): the visible image or the active layer, the same captures the reference buttons use; `refresh_describe_preview` shows it on the tab (`openAiImagesDescribePreview`) whenever the tab opens or the source changes, so the user sees what is sent. `Client::describe` posts `describe_request_json` to `/responses`: model `kDescribeModel` (`gpt-6.1-sol`, Seth's pick, 2026-11-06), the fixed instruction `kDescribeInstructions` (scene, people without guessing who they are, objects, readable text, lighting, style; English prose), the image scaled down to at most 1536 px a side as a metadata-free PNG data URL with `detail: high`, and `store: false`. `parse_describe_response` joins the reply's `output_text` parts; a `refusal` part or an empty reply shows as an error. The model, quality and Variations rows hide on this tab. Probed live on a 2000x1500 photo: about 34 s and 3,400 tokens.

The description stays text: Patchy never copies it into a prompt field or sends it with an image request, and describes only the image as it is now, never a comparison of versions or the edit history ([legal entry](legal-constraints.md#prompt-driven-image-generation)).
