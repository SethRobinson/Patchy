# Options bar layout

How the Options bar keeps one height and fits narrow windows (GitHub issue 91). Control conventions (row height, scrub labels, `configure_toolbar_spinbox`, unit fields) stay in [ui-conventions.md](ui-conventions.md).

## Grouping rules

Every tool's bar follows these rules; a new bar or control is placed by them (worked out on GitHub issues 284 to 292 with the reporter and Seth).

1. **Groups, in this order**: tool modes or presets | size fields | blending, strength or edge (Feather, Opacity) | the tool's own settings | checkbox group | model or advanced options | action buttons. A bar uses only the groups it has.
2. **One separator between neighboring groups**, never inside a group: a label and its field, a W/H pair with its swap or link button, and a value and the unit or slider beside it stay together.
3. **Checkboxes form one group** next to each other, after the value fields (issue 292). A checkbox that belongs to one field's meaning stays with that field: Anti-alias sits right after Feather on every selection bar, and checkboxes that follow it with no field between join that group (Object Selection: Feather, Anti-alias, Sample All Layers | Model; issue 292).
4. **Action buttons come last** (Remove Object, Apply/Cancel, Add Artboard).
5. **Never a separator first, last, or right after another one.** Register separators with `add_option_separator` for the tools whose groups they divide, and let hidden groups take care of themselves: `stray_option_separators` drops a separator that a tool, mode or style would leave leading, trailing or doubled.
6. **A label precedes its field** as one scrub zone ([ui-conventions.md](ui-conventions.md)), spelled out ("Tolerance", not "Tol"; issue 290). Short names only for paired size fields (W/H) and the swap or link between them.
7. **Icon buttons between two fields sit evenly**: the glyph is as far from the field before as from the label after (the swap button: 11 px each side, issue 286 follow-up).
8. **A menu of further options is a gear button** (`make_options_menu_button` in main_window_actions_options_bar.cpp: `gear.svg` at 16 px, InstantPopup, the `optionsBarMenuButton` QSS rule's bordered 20 px look with no menu arrow and a 16 px content minimum, 27 px wide; GitHub issue 326 follow-up): Move's align menu, Crop options, Smoothing options and the Clone source settings. Never a "..." text button.
9. **One row at 1366 px.** A separator costs 7 px (a 3 px widget and the flow's 4 px spacing); when a row has no room, drop a separator before a control (the Mixer row has none before Sample All Layers; GitHub issue 364).
10. **Buttons are as tall as the fields, and the row sits on the strip's middle.** The `QToolBar#Options QPushButton` rule has no vertical padding and the `optionsBarButton` icon buttons cap their content at 20 px, so every control is at most 26 px like the combos and spin boxes (GitHub issue 409). The flow's 4 px top and bottom margins make one 26 px row fill the 34 px strip, 4 px above and below; a wrapped bar has 4 px above, between and below its rows. `FlowLayout::set_center_rows` (on for the bar) centers each control on its row, so a 24 px label sits on a 26 px field's line, and splits evenly only height beyond what any tool's rows need at that width. Rows start at the top margin: when the bar keeps a wrapped tool's second-row height (it never shrinks on a tool switch, above), a one-row tool stays on line one with the spare height below, never centered across both lines. A control of odd height breaks the even split. The status bar's zoom group is 19 px for the same reason (10 px each side in the 39 px bar). Coverage: `ui_options_bar_controls_sit_centered_on_the_strip` (every tool, both schemes, plus the zoom group), `ui_options_bar_short_row_stays_on_line_one_after_a_wrapped_tool` (Move wrapped at 1024 px, then Pick), `ui_pick_options_bar_groups_its_controls` (the Foreground/Background pair against the Size combo).

11. **A separator's line sits in the middle of the clear space** between the ink on either side: a field's or framed button's edge, a label's first glyph (after its 5 px padding and QLabel's half-'x' indent), a checkbox's box or last glyph, an icon button's glyph (its frame is transparent until hover or check, and the line stays put when one is checked). `FlowLayout` lays the row out as before, then moves each `OptionsBarSeparator` off its slot to that middle (`set_ink_insets`, fed by `options_bar_ink_insets` in main_window_actions_options_bar.cpp); no other control moves, so the widths in rule 9 hold. A label's ink and a checkbox's last glyph are found by rendering the control over the bar's background (`painted_ink_columns`; the checkbox's scan stays inside its keyboard-focus outline): `tightBoundingRect` misses macOS glyphs by about 2 px, and a font-only render missed Windows labels by 2 px the other way. A new kind of control whose ink sits inside its box (a custom-painted widget, a frameless tool button subclass) gets a case there. Coverage: `ui_options_bar_separators_sit_centered_in_their_gaps` measures every separator on every tool's bar and the Free Transform row in both schemes and allows 1 px between the two sides (GitHub issue 181 follow-up).

Example, the Brush bar: `Preset [combo] Tip [picker][dynamics] | Size [spin][slider] | Mode [combo] Opacity [spin] | Soft [spin] Flow [spin] [Airbrush] | Smooth [spin][gear]` (GitHub issue 364: the Opacity separator, on every brush-family bar with Opacity; the tip leads every bar that has one, in the Preset group, and Pattern Stamp starts with it; `ui_brush_tip_follows_the_preset_menu`). The Dynamics button is an icon toggle (`brush-dynamics.svg`, three sliders), checked while its popup or its floating Brush Dynamics and Effects window is open; it is not a gear because it opens a panel, not a menu. The Tip picker and the Dynamics popup each have a framed Keep Open push button that turns them into floating windows ([brushes.md](brushes.md), "Filter and floating windows"). Example, the Patch bar: `[modes] | Patch [combo] | [Transparent] [Sample All Layers] | [Remove Object]`.

Coverage: `ui_options_bars_follow_the_separator_rules` walks every tool's bar (and the variants its style or mode combo switches to) in both schemes and fails on a leading, trailing or doubled separator or a wrapped row. Rules 1 to 4, 6 and 7 are review rules.

## One height per window width

- The bar never shrinks on a tool switch, because a height change there moves the tool palette, the canvas and the docks. Nor does it grow before it has to: `OptionsFlowContainer` reports the visible controls' wrapped height, kept sticky per width (the tallest any tool needed since the last width change), so a tool that fits one row never shows an empty second row, a tool that needs two grows the bar once and later tools keep it, and a resize resets the reservation to the current tool. (GitHub issue 91.)
- The window's minimum height counts the bar as it is laid out, second row included, so a short window never squeezes the panel column under its content (local issue 016, `ui_panel_column_short_window_keeps_sections_apart`). The bar is Fixed vertically, so the window's layout takes its size hint as its minimum: never give `QToolBar#Options` a QSS `min-height` (an explicit minimum hides the wrapped row), and the one-row floor (34 px strip) lives in `OptionsFlowContainer::height_for`. Until the container is shown at its real width both hints read one row: an unshown child is 100 px wide, and every control wrapped onto its own row there grew the window before its first show.
- `refresh_options_bar` swaps control visibility under `set_updating(true)`: a layout pass in the middle can see the old and new controls together, and the reservation must not learn that transient height.
- Every control gets one `setVisible` with its final state, all hides before any show, the Transform and Warp session rows included: Qt lays the bar out at once when a child is shown, so a tool row shown while the session row was still up wrapped the bar onto two rows for a painted frame when a session ended (GitHub issue 455; `ui_free_transform_delete_layer_ends_the_session`).
- `MainWindow::refresh_options_bar_rows` hands `FlowLayout` (`src/ui/options_flow_layout.hpp`) every tool's row: the widgets `refresh_options_bar` would show for that tool under the current vector mode, live shape layer and crop style. It rebuilds the rows only when that key changes, and records each tool's row index (`options_bar_tool_rows_`); `refresh_options_bar` sets the active tool's (`FlowLayout::set_active_row`). The rows drive the per-tool slider collapse below and the tallest-row height.
- Hidden widgets are measured the way `QWidgetItem` would measure them shown, after `ensurePolished`. A widget added to the flow outside `register_option_action` is invisible to the measure and can still grow the bar.

## Selection tool rows

- Separators group the selection bars (GitHub issues 286, 290, 291, 292): mode buttons | Feather and Anti-alias | the tool's own fields. Quick Select leads with Size (it has no Anti-alias, like Photoshop's Quick Selection bar), the Magic Wand reads mode buttons | Sample and its size combo (GitHub issue 435) | Feather and Anti-alias | Tolerance | its checkboxes, Object Selection reads Feather, Anti-alias, Sample All Layers | Model (as the reporter asked), and the marquees set Radius and Style apart from the Width/Height pair. Order is construction order in `build_options_bar`, so a tool-specific control that must precede a shared one is built before it.
- Fixed Ratio and Fixed Size each have a swap button between Width and Height (`selectionRatioSwapButton`, `selectionFixedSizeSwapButton`); `marquee_fixed_size_option_widgets_` hides the pixel pair's button under Normal, whose fields are greyed. The Artboard bar's `artboardSwapSizeButton` is the same button (`make_swap_dimensions_button`): an 18 px options-bar icon button showing `swap-dimensions.svg`, two opposed arrows in icon ink only; the New Document dialog's `newDocumentSwapDimensionsButton` shows the same glyph. The glyph sits evenly between the Width field's edge and the Height label's text (11 px each side): the button carries a 2 px left margin and the label after it drops its text padding (`label_after_swap_button`). The color well's `swap-colors` glyph carries swatches and is not for this. The marquee style is part of `refresh_options_bar_rows`' key. Coverage: `ui_selection_options_bars_group_their_controls`, `ui_marquee_swap_button_swaps_width_and_height`, `ui_swap_dimension_buttons_show_a_themed_full_size_glyph`, `ui_swap_dimension_buttons_sit_evenly_between_width_and_height`.

## Shape tool rows

- The shape bars (Rectangle, Ellipse, Polygon, Line, Custom Shape; Pen shares them) read, in Shape mode: mode | Fill [swatch] | Stroke [width] [swatch] | W [link] H | Combine | the tool's own settings | Appearance... (GitHub issue 311). The own group is Rectangle's Radius, Polygon's Sides and Star inset, Custom Shape's Shape (a folder-tree picker with search and a Shapes Manager... button, [vector-tools.md](vector-tools.md)), Line's Weight with the two arrowhead toggles, and Pen's Auto Add/Delete; Ellipse has none.
- The Fill and Stroke swatches are framed `QToolButton`s (`optionsBarSwatch` QSS rule: the push-button colors, hover and pressed states) 38x26 with a 28x16 chip, drawn at the button's icon size by `options_bar_swatch_icon`. The Text bar's `textColorButton` is the same button showing a solid chip (GitHub issue 343).
- No Stroke checkbox, here or in the Shape Appearance dialog (Seth, issue 311 follow-up): the width is the switch. The field shows 0 while the stroke is off and accepts 0 to turn it off; any other value turns it on. The model keeps `stroke.enabled` and the last real width (`set_vector_stroke_width_from_field`), so a PSD's vstk never carries a zero width, a PSD stroke that is off reads 0, and the saved `tools/vectorStrokeEnabled`/`vectorStrokeWidth` keys are unchanged. At 0 only `stroke.enabled` is applied to the selection, so each shape keeps its own width. The swatch and width stay enabled.
- The keep-proportions toggle (`vectorShapeLinkSizeButton`, a framed push button) sits evenly: the H label after it (`vectorShapeHeightLabel`) drops its text padding, so the field-to-button gap matches the button-to-text gap (4 and 5 px).
- Coverage: `ui_shape_options_bars_group_their_controls` (grouping, Line order, swatch frame, toggle spacing, one row at 1366 px, shots in both schemes); `ui_shape_stroke_width_zero_means_no_stroke` (render, PSD round trip, a disabled stroke reads 0, a width restores it).

## Duplicate sliders drop first

- An inline slider that repeats the spin box beside it (the spin box already has the popup slider and the scrub label) carries `kOptionsBarCollapsibleProperty`. Today: Brush Size, Gradient Opacity, Quick Select Size, Fill Opacity and Soft. The brush family's Opacity and Soft have no inline slider at all (October 2026), like Flow and Smooth: the popup slider, a drag on the label or inside the field, and the number keys reach them.
- Per tool: the active tool's sliders hide only when its own row would wrap with them (`FlowLayout::measure_rows` decides per row). Other tools' rows never cost it its slider: a global decision hid the Clone Stamp's Size slider at 1330 px with 300 px to spare because the Healing Brush row wrapped (GitHub issue 458 follow-up; `ui_options_bar_sliders_collapse_per_tool`). A resize across a tool's width calls back into `refresh_options_bar`. The bar height is the tallest row after each row's own collapse, and the sticky reservation keeps it across tool switches.
- Mark only true duplicates. Never mark a control that is the only way to reach a setting.
- The decision is rechecked whenever a control changes size without the width changing (`OptionsFlowContainer::event` on `LayoutRequest`), and a change of decision on the same row drops the height reservation; a tool switch never does. (GitHub issue 364.)
- A control whose content changes (a name, a preset) keeps one width: the Brush Tip picker and the Artboard preset picker size from their size hints, elide the name and show it in full in the tooltip (`ui_brush_tip_picker_keeps_a_fixed_width`).

## Popups and the cursor

- A canvas cursor change made while a popup holds the pointer (a slider popup's quick value redraws the brush cursor) is applied by Qt to the whole main window, which then shows it over the options bar until the pointer enters another widget. `MainWindow::eventFilter` calls `refresh_cursor_under_pointer` (dialog_utils) after any `Qt::Popup` hides, so every popup is covered (GitHub issue 293, `ui_slider_popup_close_restores_cursor_under_pointer`).

## Keyboard focus

- Enter in a field (spin box, the font box) commits it; Esc puts back the value from before the edit (spin boxes: `ToolbarSpinboxEscapeReverter`, GitHub issue 186; the editable font box puts back its text from focus-in). Either key then hands the keyboard back to the active canvas, or to a live text session, so tool keys work again; Esc also leaves any other focused bar control. `MainWindow::handle_options_bar_focus_event` (application event filter) does it once for every bar control: the move is queued after the press, so the canvas never sees that Esc (it would deselect the layer), and it is skipped when the control lost focus meanwhile. A click elsewhere moves focus as usual. (GitHub issue 439; `ui_options_bar_enter_and_esc_return_the_keyboard_to_the_canvas`.)
- Tab and Shift+Tab stay in the bar: the same handler moves focus through the visible, enabled controls that take Tab focus, in reading order (row by row, left to right; `options_bar_tab_stops`), and wraps at either end, so the keyboard never walks on into the panels or the document tabs. Esc or Enter leave the bar. Not while a popup (a combo list, the font completer) is open. (Issue 439 follow-up; `ui_options_bar_tab_wraps_within_the_bar`, Brush and Magic Wand.)
- An exclusive button group (the selection modes, Zoom In/Out, the Pick tool's Sets, text alignment; found by `options_bar_exclusive_group`: an exclusive `QActionGroup` behind a tool button's action or an exclusive `QButtonGroup`) is one Tab stop, its checked button, as a radio group is. Left/Up and Right/Down move to the neighbour and select it at once (wrapping); Space and Enter select the focused button. A new group in the bar gets this by being exclusive and taking Tab focus; never give its buttons `Qt::NoFocus`. Qt itself moves `Qt::TabFocus` within a `QButtonGroup` to the button that last had focus, so `options_bar_takes_tab_focus` counts a group's button when any of its buttons takes Tab focus. (Issue 440 follow-up; `ui_options_bar_button_groups_are_one_tab_stop`.)
- A click on a bar control that takes only Tab focus (tool buttons, mode buttons) focuses it, so Tab moves on from there, as from a clicked field or checkbox; not while a text session is live (the keyboard stays in the editor, issue 175). Space reaches a bar control only when it has keyboard focus (`spacebar_canvas_pan_blocked_by_text_input` checks `optionsKeyboardFocus`); after a click Space still pans the canvas. Letters, and Shift/Alt for the canvas (its application-wide key filter), work whatever holds focus. A checked button's focus outline is `@text_bright`, since a checked button already wears the accent border.
- Keyboard focus is shown: a control reached with Tab or Backtab carries `kOptionsBarKeyboardFocusProperty` (`optionsKeyboardFocus`) until it loses focus, and the bar QSS gives it an `@accent_border_bright` border. The bar's checkboxes paint themselves (`CheckGlyphBox`) and draw the same 1 px outline around glyph and text, only for keyboard focus (issue 167: no frame otherwise). A click focuses without the mark, and no control changes size. (GitHub issue 440; `ui_options_bar_tab_focus_shows_a_themed_outline`, shots in both schemes.)

## Text bar

- At 1366 px every tool row must fit on one line: `ui_options_bar_keeps_one_height_across_tools` checks it and prints each row's natural width. A new control on a long row (Text, Brush, Clone) needs that budget. The clone overlay checkbox stays in the Clone Stamp and Healing Brush gear popup, not on the bar: a bar copy (#426) made the Healing Brush row about 1440 px and cost every tool its Size slider at 1366 px (#458). Without it the widest row is Mixer Brush, about 1340 px with its slider, so 1366 px keeps the sliders. Line (Shape mode) has no collapsible slider, so `ui_line_options_bar_fits_one_row_with_room_to_spare` keeps it 100 px under that width for wider desktop fonts; its arrowheads are glyph toggles, not checkboxes (GitHub issue 174).
- Text Size shows Photoshop's precision: at most two decimals, trailing zeros dropped ("12 pt", "14.45 pt"; `UnitSpinBox::set_trim_trailing_zeros`). Sizes are whole pixels underneath (`text_points_to_pixels`), so two decimals round-trip every pixel size below 7200 ppi. The automatic size compares against the value the field holds after rounding (`text_size_auto_points_`).
- A field whose displayed max is narrower than its realistic values sizes itself from `kToolbarSpinboxWidthSampleProperty` (Text Size: 888.88 pt).
- The font family combo's popup sizes itself; the style combo's list opens wider than the closed control. The closed font box always shows a family name from its start (cursor at 0 after any programmatic set and on focus out; typing keeps its cursor), so a long name clips on the right (issue 416).
- Paragraph direction is in the Paragraph panel with a mirror of the Vertical toggle, as in Photoshop; the bar keeps the toggle. The row reads Font and style | Size and Smoothing | color swatch | alignment | Vertical and Warp | Character and Paragraph (GitHub issue 343; `ui_text_options_bar_groups_its_controls`). The color swatch has no "Color:" label, and the align buttons are ragged-line glyphs (`text_alignment_icon`, columns for vertical type) with no "Align:" label. Option labels pad 5 px on the left only, controls sit 4 px apart, and options-bar checkboxes size to their text with a 58 px floor.
