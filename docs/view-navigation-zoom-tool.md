# Zoom tool and drag zoom

Split from [view-navigation.md](view-navigation.md): the Zoom tool (options bar, click direction, view presets, click, marquee, Scrubby Zoom, right-click), the Hand tool's preset row and zoom clicks, and the pen ZoomCanvas drag, which shares Scrubby Zoom's step.

## Zoom tool (Z, `tools.zoom`)

Handled in src/ui/canvas_widget_events.cpp; the tool works while a preview dialog has editing locked (`edit_locked_ && !zooming_` guards).

- **Options bar** (Photoshop's row, built in `build_options_bar`): Zoom In / Zoom Out direction toggle, separator, Scrubby Zoom, separator, 100% / Fit Screen / Fill Screen. Every widget in the row carries the `optionsBarAllowedWhileLocked` property, so `refresh_options_bar` keeps it enabled whenever a document is open even while a preview dialog locks editing (the other tool rows disable then). The persisted options (`tools/zoomToolZoomsOut`, `tools/zoomScrubby`, both default off) follow the Fill tool's Contiguous wiring: a `CanvasWidget` setter, a `current_*` mirror in MainWindow, `load_tool_settings` / `save_tool_settings`, the control re-sync in `refresh_options_bar` and `sync_tool_option_controls_from_canvas`, and the push into every activated canvas in `activate_document_canvas`, so each is one global preference across documents.
- **Direction toggle**: two checkable actions in an exclusive `QActionGroup` (`zoomInModeAction`, `zoomOutModeAction`, the `zoomIn` / `zoomOut` action icons). `CanvasWidget::zoom_tool_zoom_out_active(modifiers)` is the one place that decides a click's direction: the mode XOR Alt, so Alt still inverts whichever mode is active. The release handler, the cursor badge (`apply_zoom_cursor` via `update_tool_cursor` and the `eventFilter` Alt watch) and the marquee preview all read it; `set_zoom_tool_zooms_out` refreshes the cursor when the tool is active. Scrubby drags ignore it (direction comes from travel).
- **View presets**: `zoomActualPixelsButton` ("100%", `set_view_zoom_centered(1.0)`), `zoomFitScreenButton` ("Fit Screen", `fit_to_view`), `zoomFillScreenButton` ("Fill Screen", `fill_to_view`). They are plain QPushButtons that call the canvas directly rather than mirroring the View menu actions, so the row does not depend on the menu build order. View > Fill Screen (`view.fill_screen`, `viewFillScreenAction`, no default shortcut, the `fill` action icon) is the menu twin; View > 200% (`view.zoom_200`, `viewZoom200Action`, no default shortcut, no icon) is `set_view_zoom_centered(2.0)`; `fill_to_view` uses the larger axis ratio over the view area where `fit_to_view` uses the smaller with a 10 px margin a side, and both center the document there ([View area](view-navigation.md#view-area)).
- **Hand tool row** (H, `CanvasTool::Pan`; GitHub issue 303): the same three view-preset buttons, registered for both tools, so the Hand row is 100% / Fit Screen / Fill Screen with no separator before it. They keep `optionsBarAllowedWhileLocked` (the Hand tool is also selectable while a preview dialog locks editing). Photoshop's Scroll All Windows is not offered: Patchy has no multi-window scroll sync.
- **Hand zoom clicks** (GitHub issue 304): with the Hand tool, or Space held over any tool, a left press with Ctrl (Cmd on macOS, Qt's `ControlModifier`) or Alt arms `hand_zoom_pending_` instead of a pan (`hand_click_zooms`); the release is one Zoom-tool click step (`zoom_click_step`, shared with the Zoom tool's click branch) about the release point, in for Ctrl and out for Alt (Alt wins when both are held), fixed at the press and independent of the Zoom tool's direction mode. Travel before the release neither pans nor reaches the tool under a Space hold; there is no marquee or scrub. A middle-button pan ignores the modifiers. `apply_hand_cursor` shows the Zoom tool's magnifier (minus for Alt) while Ctrl or Alt is held, from the folded key in `eventFilter` and the Space press. On Windows, Alt+Space pressed in that order opens the window's system menu unless a gesture is in flight (canvas_alt_space_filter.cpp), so the Space-held Hand zooms out when Space goes down first. Test: `ui_hand_tool_ctrl_alt_click_zooms_and_drag_pans`.
- **Press** sets `zooming_` and records `zoom_start_` / `zoom_current_` clamped to the document frame (`clamped_document_point`), so a marquee begun in the grey margin stays on the canvas edge.
- **Click** (release with less than `kZoomClickSlopPx` of Manhattan travel, or a drag whose rect is at most 1 px on both axes): `zoom_click_step`, one zoom-ladder step ([Zoom model](view-navigation.md#zoom-model)) in, or out when zooming out (Zoom Out mode, or Alt inverting the mode), about `zoom_click_anchor(pos)`. `zoom_click_anchor` clamps the position onto the document frame, so a margin click zooms toward the nearest document edge, never toward empty space.
- **Marquee** (Scrubby Zoom off, a real drag, the click direction is in): `zoom_to_document_rect`, with Fit's 10 px margin a side ([View area](view-navigation.md#view-area)). `draw_zoom_preview` (canvas_widget_view.cpp) paints the rect and skips it when the direction is out. The info panel reports the rect as "Zoom".
- **Scrubby Zoom** (GitHub issue 51, Photoshop's gesture; `tools/zoomScrubby`, checkbox `zoomScrubbyCheck`). Gesture: the press arms `zoom_scrubbing_` (a sub-state of `zooming_`, never the pen flag) with `zoom_drag_anchor_widget_ = zoom_click_anchor(press)` and `zoom_drag_last_pos_ = press`. Movement under the click slop keeps the release a click (exactly the branch above). The first move at or past the slop sets `zoom_scrub_started_` and applies the accumulated horizontal delta at once (no dead zone); every move after that calls `apply_zoom_drag_step(dx)`: `zoom_at_widget_point(anchor, kZoomDragFactorPerPixel ^ dx)` with right = in, left = out, vertical travel ignored. Release after a started scrub does nothing more. Alt only matters to a click (an Alt drag scrubs). While scrubbing there is no marquee preview, no "Zoom" info rect, and the marching-ants timer does not repaint for the gesture. Focus loss and `cancel_pointer_gestures` clear both scrub flags.
- The option leaves the cursor and hotkeys alone: the magnifier stays, Alt still flips the badge.
- **Right-click** opens the canvas context menu with the View menu's zoom actions first (GitHub issue 300; [tools.md](tools.md#canvas-right-click-menu)). It never zooms out: that is Alt+click.

## Pen ZoomCanvas drag

The pen button action `PenButtonAction::ZoomCanvas` (`canvas_widget_pen.cpp` for tablet events, the pen-button-as-mouse path in `canvas_widget_events.cpp`) uses `begin_zoom_drag` / `update_zoom_drag` / `end_zoom_drag` (canvas_widget_view.cpp): vertical delta, up = in, anchored at the press, gated by `pen_zoom_dragging_`. It shares `zoom_drag_anchor_widget_`, `zoom_drag_last_pos_`, and `apply_zoom_drag_step` with Scrubby Zoom; the two gestures cannot overlap because a left press ends a pen-button gesture first.

`kZoomDragFactorPerPixel` (canvas_widget_view.cpp) is the one sensitivity constant for both gestures. Dialog previews have their own copy: `ZoomableImagePreview::set_scrubby_zoom` (the Develop Raw dialog's Scrubby Zoom, GitHub issue 395) repeats it and `kZoomClickSlopPx` in zoomable_image_preview.cpp; keep them in step.
