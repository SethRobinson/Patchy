# Artboards

Photoshop-style artboards: canvases inside one document, each with its own rect and background. The legal boundary (no artboard inferred from edit history, no angular snapping, no cross-artboard propagation or reflow) is binding: [legal-constraints.md](legal-constraints.md) "Artboards", with the claim record in [patent-research-artboards.md](patent-research-artboards.md).

## Model (`core/layer.hpp`, `core/artboard.{hpp,cpp}`, Qt-free)

- An artboard is a **top-level group** carrying `std::optional<LayerArtboard>` (`Layer::artboard()`): `rect` (document pixels), `background` (`ArtboardBackground`: White 1, Black 2, Transparent 3, Custom 4, Photoshop's `artboardBackgroundType` values; never renumber), `color` (Custom only, white otherwise), `preset_name`, `guide_indices`. `set_artboard` throws `logic_error` on a non-group and bumps render and content revisions; `translate_artboard` bumps render only (like `set_bounds`). `clone_with_id`, `copy_layer_state` and document copies carry it.
- `DocumentMetadata::artboard_settings` (`DocumentArtboardSettings`) is the document `artd` block: origin, auto-expand offset and flags, default background. `DocumentMetadata::pdf_page_source_pages` keys a merged PDF import's page images by artboard or page-folder id (pass-through, below). Neither is in `values`, so no other writer serializes them.
- Rules: artboards never nest and never go inside a plain group. `move_layers_for_drop` (`core/layer_tree.cpp`), `create_layer_folder_from_layers` ("An artboard cannot go inside a folder"), `doc.groupLayers` and `doc.moveLayers` all refuse. A new artboard is **Normal** (isolated), not Pass Through, and goes on top of the stack (`new_artboard_insert_index`). Names come from `next_artboard_name` ("Artboard N", one past the highest N).
- Helpers: `document_artboards` (top of the stack first: the Layers panel order and every per-artboard page order), `artboard_at`, `artboard_owning_layer`, `artboard_union_bounds`, `artboard_rect_beside`/`artboard_rect_next_to` (`kArtboardSpacing` 100 px), `put_layers_on_new_artboard` (Artboard from Layers for menu and scripts), `convert_artboards_to_plain_groups`.

## Ground truth (Photoshop 2026 over COM, `test-fixtures/psd/photoshop-artboard-*.psd`)

- Children clip to the rect; the background paints under them inside the group, so the artboard's opacity and blend mode apply to both.
- Layers outside every artboard ("loose") render normally; the composite outside every artboard and loose layer is transparent.
- The canvas grows live as artboards move past it, and Photoshop shrinkwraps the canvas on save to the artboards plus loose content. Patchy grows after each edit (`grow_canvas_to_artboards`, never shrinks mid-drag) and offers the shrinkwrap as Image > Fit Canvas to Artboards (`fit_canvas_to_artboards`, `artboard_document_extent`). Both return the coordinate shift when the canvas grows up or left; callers pan the view by it (`CanvasWidget::shift_view_for_document_offset`) so the artwork stays put on screen.
- Folder records of artboards have a zero rect and four channels, `lsct` Normal, `lyvr` 160.

## Compositor (`render/layer_compositor.hpp`, `core/layer_render_utils.cpp`)

The CPU group branch intersects `clip` with the rect and paints `artboard_background_rgba` (`paint_artboard_paper`) before the children: into the isolated buffer, or for a Pass Through artboard into the destination at the layer's opacity. `layer_render_bounds` of an artboard is its rect plus style padding, so an empty artboard still paints, and per-layer render overrides are ignored for artboards. Documents without artboards take the unchanged path, so the byte and digest canaries are untouched. The native CMYK path composites artboards itself (paper separated to inks, [blend-modes.md](blend-modes.md)); the native duotone path falls back to the CPU compositor when `document_has_artboards`; Dynamic Vector Preview keeps the artboard on its scene copy and composites it the same way ([vector-preview.md](vector-preview.md)). `transform_document_vector_data` maps artboard rects through the canvas transform (Canvas Size, Crop, flips, rotations, Image Size; an arbitrary rotation keeps the bounding box).

## PSD (`psd/psd_artboard.{hpp,cpp}`)

- Per folder: `artb` (older files: `abdd`, `artd`), version 16 + descriptor class `artboard`: `artboardRect` (`classFloatRect`, `Top `/`Left`/`Btom`/`Rght` doubles), `guideIndeces`, `artboardPresetName`, `Clr ` (`RGBC` doubles), `artboardBackgroundType`. Global: `artd`, version 16 + `null` descriptor with `Cnt `, the auto-expand offset and origin points (`Pnt `, `Hrzn`/`Vrtc`), the flags and the default color (`RGBC` integers). `artboard_block_payload` reproduces Photoshop's key order and id forms, so a Photoshop block regenerates byte for byte (`psd_artboard_blocks_regenerate_photoshop_bytes`).
- Read: `build_group_hierarchy` parses the block on top-level folders only; `artd` fills `artboard_settings`.
- Write: a folder whose preserved block still parses to its model keeps the bytes; otherwise the regenerated `artb` goes after `lsct` and stale artboard keys are skipped. The global `artd` is kept verbatim when count and settings match, regenerated otherwise, dropped when no artboards remain, and authored when artboards exist without one. Every written file must open in Photoshop cleanly ([ps-compat.md](ps-compat.md)).

## Other formats

- **Affinity**: top-level artboards import as native artboards (the mask rect; a plain solid "<name> Background" shape becomes the White, Black or Custom background and is removed), [af-format.md](af-format.md).
- **SVG, Aseprite, editable PDF**: `convert_artboards_to_plain_groups` on a copy (Normal group, rectangular vector mask, a bottom "<name> Background" solid shape), which composites the same.
- **PDF export**: `PdfExportOptions::pages` (`PdfPageSource::Artboards` by default, chosen in PDF Options, [pdf.md](pdf.md)) makes Save As, Export and `write_multipage_pdf_file` write one page per visible artboard via `documents_for_artboards` / `document_for_artboard` (`ui/pdf_export.cpp`): a copy holding that artboard only (loose layers dropped unless asked), cropped to the rect over transparency, a background nothing can show through dropped, and a then-plain Transparent artboard unwrapped so a scanned page stays one image and passes through. Multi-Page PDF has an Artboards source ([pdf.md](pdf.md)).
- **PDF import** to "Artboards in one document": one artboard per page, page 1 on top, grid layout; see [pdf.md](pdf.md). `attach_pdf_page_source` stamps each page's source image against the page `document_for_artboard` derives, so an untouched artboard re-exports its original bytes.

## UI

- **Canvas** (`ui/canvas_widget_artboard.cpp`): with artboards the checkerboard paints only inside Transparent artboards (`draw_canvas_backdrop`) and the document-bounds outline (`canvas_document_border`) is not drawn, since the canvas then has no fixed size (#278, `ui_artboard_document_hides_the_canvas_outline`); `draw_artboard_overlay` draws every outline, then every name label over them (a label sits above its own top edge, so a board right above would otherwise cross it with its outline), then the selected artboard's eight handles and its "+" add buttons, in the `canvas_artboard_{outline,label,selected,handle}` theme roles. A label is ink on whatever it sits on (#260): `artboard_label_backing` samples a fixed 6 by 3 grid of the rendered frame under the label (the pasteboard color between artboards, another artboard's paper or content, the checkerboard mean inside a Transparent one; never work proportional to the document), each sample light above a luma of 118; a light majority picks `canvas_artboard_label_on_light` (dark ink), otherwise `canvas_artboard_label` (light ink), and both roles exist in both schemes, so a user pasteboard color moves the ink too. A label straddling the two (a row's worth of minority samples: a name hanging over a neighbouring board's edge, as "custom board" does in ag-psd's sample at small zooms) also gets a one-pixel halo in the other ink, so the part over the pasteboard reads as well as the part over the paper. Pinned by `ui_artboard_label_ink_follows_what_it_sits_on`, `ui_artboard_label_reads_across_a_neighbouring_boards_edge`, `ui_artboard_label_shows_its_full_name_past_a_narrow_board` and, on the reporter's file, `ui_artboard_ag_psd_sample_labels_read_on_their_backing_if_available` (`local-test-fixtures/ag-psd/artboards/src.psd`, ag-psd's artboards sample). A label shows the whole name, past a narrow board if need be (`artboard_label_widget_rect`): it is elided only where another visible artboard's label on the same row starts inside it (clipped to 6 px before that label) or where it would run past the visible canvas edge, and never below 24 px; the Move tool's label hit area is that same rect, so hover and click follow the visible text. A label click selects the artboard with the Move and Artboard tools (and starts a move); a double-click renames it with every tool.
- **Artboard tool** (`CanvasTool::Artboard`, `tools.artboard`, icon `tool-artboard.svg`; a flyout with Move, cycled by `tools.cycle.move`, Shift+V; [tool-palette.md](tool-palette.md)): drag on empty space creates (a plain click inside an artboard selects it; on empty space, the pasteboard or loose content it deselects every layer like the Move tool's blank click, Shift keeps the selection, #279), drag inside or on a label moves the artboard with its content (Alt duplicates), handles resize (Shift keeps the aspect), "+" adds one beside on that side, arrows nudge (a run of nudges is one undo step, `ArtboardNudgeRun`), Esc cancels a drag. Every edit is one undo step and grows the canvas (`MainWindow::finish_artboard_edit`). The tool emits `ArtboardEditRequest`s; `MainWindow::handle_artboard_edit` applies them.
- **Options bar** (#285): the Size preset picker (`ArtboardPresetPicker`, `src/ui/artboard_preset_picker.hpp`; the templates are New Document's, `artboard_size_presets`), a separator, Width, a swap button and Height, a separator, background (`white`, `black`, `transparent`, `other`: permanent `tools/artboardBackground` tokens; Other asks for a color), a separator, Add Artboard, a separator, Auto-Nest Layers. One line at 1366 px; pinned by `ui_artboard_options_bar_separates_size_background_and_add`. Settings: `tools/artboard{Width,Height,Background,BackgroundColor,AutoNest}`. The picker is a field-styled button naming the chosen preset (Custom when the size matches none; one fixed width) over a menu: a search field, Custom, then one submenu per group (Screen, Phone, Tablet, Social, Web, Print, Photo, Icons & Games). Typing replaces the submenus with a flat list of matches (the New Document search rule, `size_preset_matches_search`), the first highlighted; from the field Up/Down move, Enter picks, Right opens a group. It keeps the chosen template's id while the size still matches. Coverage: `ui_artboard_preset_picker_*`.
- **Move tool**: with exactly one artboard selected in the Layers panel the Move tool moves the artboard itself (rect and content). An artboard is a Move target under the pointer too (#259, `move_artboard_target_at`): its label with any setting, and with Auto-Select on or Ctrl held its empty area (no layer under the pointer, locked ones included, and no passive transform-box edge there). Hovering frames the artboard rect with the layer hover outline and turns its label the selected color, the four-way cursor shows, and a press selects it in the Layers panel and drags it with its content (`handle_move_tool_artboard_press`). Layers inside keep their own Auto-Select pick; with Auto-Select off and no Ctrl the empty area still drags the selection. Selecting an artboard with the Move tool (a selecting canvas click on its label or area, or its row in the Layers panel; never a hover) shows the status line "Switch to the Artboard tool (Shift+V) to add, resize or duplicate artboards" with the registry's current binding (`MainWindow::show_artboard_tool_hint_for_move_tool`: the `tools.artboard` shortcut when it has one, else `tools.cycle.move`; no parenthetical when neither is bound), since the "+" buttons, handles and copies belong to the Artboard tool; the Artboard tool itself shows nothing. Pinned by `ui_artboard_move_tool_hover_frames_artboard_and_click_selects_it`. With Auto-Nest on (also shown on the Move tool; `CanvasWidget::set_artboard_auto_nest`), a moved layer whose center lands on an artboard joins it (on top of its children) and one moved off every artboard leaves for the root above the artboard it left. The canvas applies it inside the move's undo step (`artboard_nest_roots`, `artboard_nest_moves`, `apply_artboard_nest_moves` in core); MainWindow only refreshes the panels (`refresh_after_artboard_nesting`). The user's explicit drag decides; nothing is inferred from history. **Prevent Auto-Nesting** (#246, `kLayerLockArtboardAutonest`, PSD `lspf` 0x8) opts out: `artboard_nest_moves` skips a root that has it, and on an artboard nothing nests into or out of it. It applies to canvas moves only; panel drags and Layer > Arrange still re-parent. It is not an editing lock (Lock All, `layer_locks_all` and the effective-lock helpers leave it out, folders do not pass it down) and has no panel button: the row's right-click Lock submenu holds the registered checkable `layerPreventAutoNestingAction` (hotkey id `layer.prevent_auto_nesting`) and Layer > Lock Layers... has a box for it, and the row shows a `tool-artboard` badge. Photoshop's own Background stores it (0xd) but shows one lock icon, so a Background row (the bottom top-level pixel layer named Background) keeps the bit and draws no badge for it. Pinned by `artboard_nest_moves_honor_prevent_auto_nesting`, `ui_artboard_prevent_auto_nesting_keeps_layer_in_place`, `ui_issue_246_sample_prevent_auto_nesting_if_available`, `ui_psd_background_hides_prevent_auto_nesting_badge`.
- **Delete** (#277): Edit's `layer.clear` (Delete; Backspace too on macOS) on a selected artboard deletes it with its layers as one undo step, as a folder is deleted, from any tool (`MainWindow::clear_active_layer`; a selected layer inside it goes with it, a selected loose pixel layer is cleared in the same step). With a pixel selection active it refuses with "Artboards can't be cleared. Deselect first, ...", like text and smart-object layers. Pinned by `ui_artboard_delete_key_deletes_the_selected_artboard`.
- **Layers panel**: an artboard glyph, "Artboard" kind and tooltip, row property `layerRowArtboard` ([layer-panel.md](layer-panel.md)). Duplicating an artboard places the copy right of the rightmost one (`place_duplicated_artboards`).
- **Properties panel**: X, Y, W, H and background for the selected artboard (`build_properties_artboard_panel`). The fields scrub like the options bar's. A scrub of X/Y/W/H (here or the options-bar W/H) only previews on the canvas, as an Artboard-tool drag does (`preview_artboard_field_rect`, `CanvasWidget::preview_artboard_rect`; `kScrubActiveProperty` tells a scrub from typing), and commits one edit at its `editingFinished`: running the whole resize per pixel was slow on large documents. Typed values and arrow steps apply at once; a run of them until `editingFinished` is one undo step (`artboard_field_edit_run_`).
- **Commands**: Layer > New > Artboard... (`layer.new_artboard`), Artboard from Group (`layer.artboard_from_group`), Artboard from Layers (`layer.artboard_from_layers`), Convert Artboard to Group (`layer.artboard_to_group`, keeps the layers, drops the background); Image > Fit Canvas to Artboards (`image.fit_canvas_to_artboards`); File > Export > Artboards to Files (`file.export_artboards`). Every one is a permanent hotkey id.
- **New Document**: the Artboards check (`newDocument/artboards`) starts the document as "Artboard 1" the canvas size, holding "Layer 1".
- **Artboards to Files**: the Documents to Folder dialog in Artboards mode (`ExportDocumentsFolderSource::Artboards`, `exportArtboardsDialog`): the rows are artboards, files are prefix (default "<document> - ") plus the artboard name, Add gives a taken name " 2", " 3". It shares `export_page_documents_to_folder` with Documents to Folder.
- **Print**: "Each Artboard as a Page" (`PrintAreaMode::Artboards`) prints `print_artboard_pages`; "Match each artboard" (`printMatchArtboardCheck`) makes every sheet the artboard's print size with no margins at actual size. Only a PDF can change sheet mid-job (Qt refuses a new layout for an active native print job), so Save PDF honors it per page and a printer keeps the chosen paper.

## Feature interactions

Photoshop 2026's behavior, captured on one scene (A 0,0,300,300 with A1; B 400,0,300x250 with B1; a loose layer) by `scripts\dev\artboards\ps-artboard-audit.ps1`, and pinned for Patchy by `ui_artboard_feature_interactions_match_photoshop`:

| Command | Photoshop | Patchy |
|---|---|---|
| Canvas Size, growing | artboards and content move by the anchor offset | same |
| Canvas Size, shrinking | never clips an artboard: the canvas grows back around them | same (`grow_canvas_to_artboards` after `resize_canvas_to_frame`); Photoshop's regrown size differs, Patchy's is the tight fit |
| Image Size | rects and content scale | same |
| Rotate 90, flip | rects and content transform | same (`transform_document_vector_data`) |
| Crop (Image > Crop, Crop tool) | no effect | refused with a status line (`refuse_crop_with_artboards`); resize artboards with the Artboard tool |
| Trim, Reveal All | trims or reveals to artboards plus loose content | no such commands |
| Flatten Image | artboards composite (with paper) into Background | same |
| Merge Visible | merges everything into one layer, artboards gone | Patchy's command stamps a merged copy and keeps the layers |
| New Layer | inside the selected layer's artboard, or inside the selected artboard on top | same (`insert_layer_after_anchor`) |
| Select All | the active layer's artboard | same (`CanvasWidget::select_all`) |
| Paste | into the target artboard, centered on it | same (pixel paste; [tools.md](tools.md) "Clipboard pixel placement" off artboards) |
| Paste with a marquee active | centered on the marquee, into the artboard under its center (the root when none), whichever layer is selected | same |
| Paste in Place onto another artboard | keeps the place on the artboard | same (`ClipboardPayload::source_artboard_origin`) |
| Duplicate artboard | 100 px right of the original | 100 px right of the rightmost artboard (`place_duplicated_artboards`; the same spot here); canvas growth amounts differ |
| Save As a flat format | shrinkwraps the canvas to artboards plus loose content first | writes the canvas as it is; Image > Fit Canvas to Artboards does the shrinkwrap |
| Painting outside every artboard | refused ("does not overlap the canvas") | allowed on the active layer; a press on another artboard paints there (below) |

## Painting across artboards

A paint press (Brush, Eraser, Mixer Brush, Pattern Stamp, Smudge, Clone, Healing, the local adjustment brushes, Fill) on an artboard that does not own the active layer would paint into that layer, where its own artboard clips the paint away (Photoshop does exactly that). Patchy paints on the clicked artboard instead (`CanvasWidget::retarget_paint_to_clicked_artboard`): its topmost visible, unlocked, non-procedural pixel layer becomes active, with a status line; an artboard with none gets an empty artboard-sized "Layer N" after the stroke's undo snapshot (`add_paint_layer_on_artboard`), so one Undo removes stroke and layer. A press outside every artboard, or on the active layer's own artboard, changes nothing. Test: `ui_artboard_paint_switches_to_the_clicked_artboards_layer`.

## Fast paths (previews and partial renders)

The speed paths must show what the full composite will. Rules, each pinned by `ui_artboard_drag_across_artboards_previews_the_release` unless noted:
- `composite_document_layer` (the 8-bit fast walk) always isolates an artboard, Pass Through or not, so its clip and paper apply in every partial render.
- Preview-scaled documents (zoom 50% or less) scale the artboard rect with the group bounds (`shrink_layer_for_preview`, `retarget_preview_scaled_layer_bounds`).
- Move drag live patches render from a copy re-nested the way the release will (`move_patch_source`, cached while the nest targets stay the same); the release re-parents before its cache patch, and a re-nesting release without reusable patches takes the bounded `document_changed_effect_bounds` path.
- The Move proxy snapshot renders the moving layers' artboards as plain groups (no paper, no clip baked in) and paint clips the blit, and the commit hold, to the artboard the content lands in (`move_proxy_clip_document_rect`). A document with an artboard that blends, fades, masks or styles (`artboard_composites_plainly` false) never latches the proxy.
- Free Transform composites any layer on an artboard (`transform_preview_needs_compositing`); the single-layer blits clip to the artboard, and the multi-target snapshot unclips and clips like the Move proxy.
- The Artboard tool's drag ghost is the artboard rendered alone, over the canvas rendered without it; a canvas growth keeps the old frame, shifted, as the stale frame (`set_document_after_canvas_growth`).

## Scripting

`doc.artboards`, `doc.addArtboard`, `doc.artboardFromLayers`, `doc.fitCanvasToArtboards`, `doc.exportArtboards`, `layer.isArtboard`, `layer.artboard`, `layer.setArtboard`, the `artboardPages` PDF option, and `isArtboard`/`artboard` in the MCP state (`ui/script_artboards.cpp`; [scripting.md](scripting.md), the guide and patchy.d.ts).
