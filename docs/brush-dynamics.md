# Brush dynamics (Photoshop-compatible)

Split from [brushes.md](brushes.md) (stamping engine, tips, picker, Flow/Airbrush, Pattern Stamp). `BrushDynamicControl` is an append-only enum (`AGENTS.md`); the binding boundaries are in [legal-constraints.md](legal-constraints.md) "Brush behavior".

Modeled: per-dab Shape Dynamics (size/angle/roundness jitter with minimum floors, flip X/Y jitter), Scattering (scatter %, both axes, count 1-16, count jitter), Transfer (opacity and Flow jitter with independent minimums), static Tip Shape (base angle/roundness), Brush Texture (generated Fine Grain/Canvas/Speckle masks with scale/depth/invert), Dual Brush (multiplies the primary tip by one repeated computed round mask with size/hardness/spacing), Color Dynamics (foreground/background interpolation plus hue/saturation/brightness jitter and purity, per dab or per stroke), and Wet Edges. Wet Edges builds one max-coverage union mask for the whole stroke, lightens the wash interior, and concentrates paint in its low-coverage boundary; individual dab boundaries inside the stroke are never wet edges. Observed Photoshop behavior: watercolor edge pooling, not canvas smearing (the tooltip points to Smudge).

**Every input-driven dynamic carries a Photoshop-style Control** (Off / Fade with per-dynamic fade steps / Pen Pressure / Pen Tilt / Pen Rotation / Stylus Wheel = tablet tangential pressure; angle adds Initial Direction / Direction). Size/roundness/opacity controls are tri-state against the global pen prefs: the default `GlobalDefault` leaves `input/pen/*` authoritative (pre-dab scaling in `effective_brush_input`); any other value (including Off) makes the brush own that aspect and suppresses the matching global modulation (size<->pressureSize, opacity<->pressureOpacity, roundness<->tiltShape's tilt->roundness), gated by `brush_dynamics_authoritative` (Brush tool only, never the eraser end/tool, Clone/Smudge, or mask painting). Flow has no matching global pen preference, so its default control is Off. Off means the brush ignores the pen for that aspect: `active()` treats Off/GlobalDefault as inactive, so an Off-only Round brush stays on the procedural capsule path (the options-bar badge keys on `brush_dynamics_is_default`, not `active()`). Controls map the input c in 0..1 into [minimum, 1] (count fades toward 1, scatter scales by c, angle maps c to 0..360 deg); a missing pen input reads as 1.0 (a mouse paints at full value). Controls never consume RNG draws; the draw-order contract gates stay keyed on static config (`tool_brush_tip_controls_at_full_value_change_nothing` pins this). Only append to `BrushDynamicControl`: combo indices and casts depend on the existing order.

- Core engine `src/core/brush_dynamics.hpp/.cpp`: `BrushDynamics` carried by value in `EditOptions`; default-constructed = `active()==false` = the historical stamp path bit-for-bit, zero RNG draws. Per-dab variation rides the inverse map (`TipDabTransform`: inverse_scale + flip signs); size jitter only SHRINKS (Photoshop semantics), so the scaled-tip LRU and 2px pressure quantization are untouched. The RNG is splitmix64 with explicit uniform mapping, NEVER std::uniform_*_distribution (implementation-defined output breaks cross-toolchain pixel tests). The draw-order contract lives in brush_dynamics.hpp; tests depend on it. Stroke state (RNG, fade step index, smoothed + initial direction) lives in `BrushTipStrokeState`, seeded from `EditOptions::brush_dynamics.seed` on the first dab; CanvasWidget seeds per stroke in `clear_brush_stroke_tracking()` (`set_brush_dynamics_test_seed` is the UI-test hook).
- Dynamics are Brush-tool only: erase strokes strip `brush_dynamics` in draw_brush_segment / draw_brush_at. The procedural **Round brush supports dynamics too**: its capsule renderer has no dab loop, so while `brush_dynamics_.active()` a Round stroke stamps through a synthesized 256px disc tip (`round_dynamics_tip_mips()`, spacing 25%; Soft feathers it like any bitmap tip; pressure sizes quantize to 2px). Inactive dynamics keep the capsule path bit-for-bit; a Round ERASE stroke always stays procedural. Round and Square dynamics are **session-only** (`MainWindow::round_brush_dynamics_` + base shape, never persisted, reset each launch). `draw_brush_at` routes tip presses through a stateful zero-length `paint_brush_segment` so the press dab is not re-stamped by the first move segment (else it visibly double-jitters).
- Per-tip persistence: `BrushTipEntry` carries dynamics + base angle/roundness; the JSON sidecar has top-level `"baseAngle"`/`"baseRoundness"` and a `"dynamics"` object (camelCase fractions 0..1, scatter 0..10, string enum tokens like `"direction"`), written only when non-default. Texture persists `textureEnabled`/`textureStyle`/`textureScale`/`textureDepth`/`textureInvert`/`textureSeed`; Dual Brush its enabled/size/hardness/spacing fields; Color Dynamics its enabled/jitter/control/fade/purity/per-tip fields; Wet Edges as `wetEdges`. Control tokens: `"global"`/`"off"`/`"fade"`/`"penPressure"`/`"penTilt"`/`"penRotation"`/`"stylusWheel"`. Missing/unknown keys read as defaults (no sidecar migration). Imported ABR tool settings persist as optional top-level `toolFlow`/`toolAirbrush`. Adding a dynamics field means updating BOTH `brush_dynamics_is_default` and `persisted_dynamics_equal`; missing one silently breaks sidecar writes or factory reset.
- The options-bar **Dynamics** button (`BrushDynamicsButton`, Brush tool only; a sliders icon right after the Tip picker, checked while the popup is open, "Dynamics" as its accessible name) edits the active bitmap tip (persisted via `BrushTipLibrary::set_tip_dynamics`, debounced ~200 ms) or the Round brush's session values (`set_round_session` on the builtin round id, never persisted); values reach the canvas via `apply_brush_tip_to_canvas`. The hidden `textureSeed` is retained while the form edits visible texture settings. The manager's stroke preview renders dynamics with a fixed seed.
- `parse_brush_dynamics` (abr_reader.cpp) imports the supported dynamics: Shape/Scatter/Transfer fields, texture `useTexture`/`textureScale`/`textureDepth`/`InvT`/`Txtr`, one `dualBrush.Brsh` secondary tip's diameter/hardness/spacing, Color Dynamics `useColorDynamics`/`clVr`/`H   `/`Strt`/`Brgh`/`purity`/`colorDynamicsPerTip`, and `Wtdg` (Wet Edges). Imported texture artwork is not bundled or copied: the pattern identity is hashed into a stable seed and its name selects the closest generated grain family. Input-driven `textureDepthDynamics` is deliberately reduced to the static `textureDepth`, with a per-brush import notice. Base `Angl`/`Rndn` come from the primary `Brsh` tip object. Options-bar Flow imports from `toolOptions.flow`, Airbrush from preset `Rpt ` (live key `repeat`); both apply only when `toolOptions.brushPreset` is true, and a library-change echo re-applies the tip without resetting tool settings. `bVTy` mapping: 0 Off, 1 Fade, 2 Pen Pressure, 3 Pen Tilt, 4 Stylus Wheel, 5 Rotation, 6 Initial Direction, 7 Direction. Every supported dynamic's control + `fStp` imports; on non-angle dynamics bVTy 0 maps to the slot default (GlobalDefault for size/roundness/opacity, Off for flow/scatter/count/color), and the angle-only 6/7 degrade to Off (`non_angle_control_from_bvty`).
- With `input/pen/tiltShape` on and the tip's angle control PenTilt/PenRotation, the per-dab path owns the angle and effective_brush_input skips its tilt-angle assignment (tilt->roundness still applies unless the roundness control overrides it), avoiding double rotation. Known divergence: dab spacing tracks the base brush size, not the per-dab controlled size.
- **Direction first dab (#221).** A press has no travel, so with a Direction/Initial Direction angle `paint_brush_segment` holds the press dab (and stationary Airbrush ticks) in `BrushTipStrokeState` until the pointer is 3 px away, then stamps it at the press point along that travel. `finish_brush_tip_stroke` stamps a dab still held at stroke end (under 1 px of travel = click: base angle, press pen sample); release, focus loss and `drawStrokes` call it.
- The built-in default tips ship with **curated dynamics** (`DefaultBrushTipSpec::dynamics`); Canvas, Square, Calligraphy, Dotted Line, and RTsoft Logo deliberately stay plain. `brushes/defaultTipsVersion` = **4** (v3 added the 20 stamps, v4 the four effect presets). Upgrades from < 2 also run `BrushTipLibrary::apply_default_tip_dynamics()` once. It must never re-run for stored version >= 2: it cannot tell a deliberate post-v2 reset from "never migrated". It only touches default-folder tips still at untouched defaults; user customizations always win. "Restore Default Brushes" re-adds missing tips with curated dynamics but never re-migrates existing ones.
- The dynamics form is the shared `BrushDynamicsPanel` (brush_dynamics_popup.*): the options-bar popup embeds it; the manager's "Edit Dynamics..." button (single selection) opens it in a child dialog with live debounced apply + preview refresh. Control combos map items via `addItem(text, int(enum))`/`currentData`, so display order is decoupled from enum values, EXCEPT the pre-existing angle combo, whose item indices equal the enum values (a UI test sets index 6 = Direction; append-only). The popup must size from the PANEL's sizeHint, not adjustSize(): QScrollArea::sizeHint caps at ~24 font-heights and would show a needless scrollbar; it clamps to screen height only when the panel cannot fit, widening for the scrollbar. Tips with dynamics or a non-default tip shape get a blue corner badge (`brush_tip_thumbnail_with_badge`) and a " - dynamics" tooltip suffix.
- Patent boundaries (reviewed July 15, 2026): Shape Dynamics and Scattering remain clear. The binding design boundaries for Brush Texture (US 10902645, US 8896579), Color Dynamics (US 10924633), Wet Edges, and Dual Brush live in [legal-constraints.md](legal-constraints.md); keep the implementation comments in sync with that file. Wet Edges' curve was calibrated from observed Photoshop 2026 output using a scripted hard Round stroke (no Adobe code or artwork involved) and sits outside the now-expired US 6198489.
- PSD/PSB compatibility is raster-exact: brush configuration is application/library state; documents store only painted pixels, which other editors reopen identically. ABR import is the compatibility path for brush settings.
