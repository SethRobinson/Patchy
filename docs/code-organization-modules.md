# Render, core, format and UI module splits

Split from [code-organization.md](code-organization.md): the deliberate splits outside MainWindow, CanvasWidget and the PSD codec (preset trees and manager dialogs, layer style mask operations, compositor targets instantiated once each, the Affinity importer, the layer style and adjustment dialogs, core geometry and resampling, single-home helpers, dialog previews, the gradient preset popup and the test suites).

## Other deliberate splits

- `ui/preset_tree_widget.{hpp,cpp}` is the generalized folder-grouped preset tree (reload preserving selection/collapse, folder expansion, click dispatch); `ui/style_browser.{hpp,cpp}` keeps `StyleBrowserWidget` as a thin adapter over it whose public API, signals, and objectNames are load-bearing for `layer_style_dialog.cpp` and UI tests. `ui/preset_manager_scaffold.{hpp,cpp}` owns the shared manager-dialog shell (layout, action rows, delete plumbing, use_selected); each `*_manager_dialog.cpp` keeps its previews, persistence, import/export, extra buttons, and strings local so translation contexts and per-dialog behavior deltas stay put. The gradient manager deliberately shares only the button row: its tree is structurally different (non-modal, nested slash-path folders, expanded-set semantics).
- `render/layer_style_mask_ops.{hpp,cpp}` owns non-template mask preparation, coverage, stroke, blur/expand, bevel, and Satin machinery. `layer_render_types.hpp` holds render override/cache value types; `style_mask_cache.hpp` holds cache helpers; `layer_render_facade` exposes operations needed by UI tools without the compositor implementation; `layer_knockout.hpp` is the PSD knockout mode alone (writers include it, not the templates). Per-pixel `composite_*`/`render_*` templates and arithmetic remain in `layer_compositor.hpp`; its non-template half (per-layer preparation such as `prepare_stroke_render` and `prepare_interior_overlays`, the `fold_*` color folds, the stroke knockout factors) is defined in `layer_compositor.cpp`. Never introduce virtual or type-erased calls in that inner loop. Mask math and iteration order are byte-pinned by the compositor canaries; keep bodies verbatim when reorganizing.
- **Compositor targets are instantiated once each.** `composite_layer<Target>` pulls the whole render tree (every effect renderer, `composite_pixel_layer`, the `GroupMaskedTarget`/`ChannelRestrictedTarget` wrappers and the isolated buffers) into any TU that calls it: 40 to 120 s per TU before October 2026. The target classes therefore live in headers (`render/composite_targets.hpp`: `Rgb8PixelBufferTarget`, `Rgba8PixelBufferTarget`, `Rgb8PerPixelTarget`; `ui/qimage_composite_target.hpp`: `QImageCompositeTarget`; the isolated buffers in `layer_compositor.hpp`), each header ends with `PATCHY_COMPOSITOR_TARGET_INSTANTIATIONS(extern, T)`, and one `layer_compositor_<target>.cpp` per target (`src/render`, `src/ui/layer_compositor_qimage.cpp`) carries the definition. A new target follows the same pattern; a TU-local target class (native_cmyk's `NativeTarget`) still pays the full instantiation itself. Format and UI TUs include the target header, never instantiate the tree, and stay under a few seconds.
- `formats/af_document_io.cpp` assembles imported documents. Private Affinity modules separate container/decompression (`af_container`), raster (`af_raster`), text (`af_text`), and vector (`af_vector`) decoding. Their internal headers belong only to the importer; see [af-format.md](af-format.md).
- `ui/layer_style_dialog.cpp` owns dialog state, preview/apply/cancel, and preset coordination. `layer_style_effect_pages` builds effect pages in enum order; `layer_style_gradient_controls` owns gradient editing; `layer_style_dialog_controls` owns reusable control construction. Dialog-owned context and returned widget aggregates outlive every connected callback. Preserve object names, translation contexts, preview cancellation, and pattern-store restoration.
- `ui/adjustment_dialogs.cpp` owns the per-adjustment dialog half of `filter_workflows.cpp`: Levels widgets, adjustment requests, and Hue/Saturation converters. `filter_workflows.cpp` keeps catalog helpers, generic filter settings, Smart Filter blending, and pixel application. Their shared private helpers live in `ui/filter_workflows_internal.hpp`, which no other TU may include.
- `core/document_geometry.cpp` owns crop, rotate, flip, image/canvas resize, and `DocumentChannel` geometry from `pixel_tools.cpp`. `core/resample.cpp` owns the Image Size resampler and the interpolation kernels Free Transform shares (docs/resampling.md). Painting stays in `pixel_tools.cpp` and is byte-pinned by `tool_write_paths_digest_baseline`. `core/pixel_tools.hpp` remains the umbrella header; cross-half private helpers are declared in `core/pixel_tools_internal.hpp`, which no other directory may include. Both halves use public `core/blend_math.hpp` for `clamp_byte` and `core/rect_utils.hpp` for `normalized_rect`, and callers outside `pixel_tools.cpp` pass `extension_color` explicitly. `brush_coverage` is public in `core/pixel_tools.hpp`: the canvas brush preview and Spot Healing sample the same falloff the brush engine stamps with.
- Single-home helpers, never copied into a TU: `support/byte_order.hpp` (fixed-width big- and little-endian reads, writes and appends; the PSD codec keeps `psd::BigEndianReader/Writer`), `support/random_uuid.hpp` (the one mutex-guarded random id engine behind `generate_pattern_uuid` and `generate_smart_object_uuid`), `core/splitmix64.hpp` (the constexpr hash behind every deterministic random draw), `core/layer_tree.hpp`'s `find_layer_in_tree` (which `Document::find_layer_recursive` forwards to), `color/lcms_intent.hpp` (private to `patchy_color`), and `ui/alpha_row_bands.hpp` (the text re-render row measure MainWindow and the UI tests share).
- `ui/zoomable_image_preview.{hpp,cpp}` is the one zoom, pan and mouse implementation for dialog previews. Dialogs that paint their own pixels (`TracePreviewWidget` in `image_trace_dialog.cpp`, `ConvertPreviewWidget` in `palette_convert_dialog.cpp`) derive from it, set a logical size instead of an image and draw inside the protected `paint_backdrop`/`paint_content` hooks; `interaction_cursor` lets a subclass show a busy cursor. Object names and the `previewZoomPercent`/`previewFitMode` properties are load-bearing for UI tests.
- `ui/gradient_preset_popup.{hpp,cpp}` owns the anchored gradient quick-picker popup shared by the layer-style Preset buttons, the gradient toolbar Presets button, and the Edit Gradient Stops dialog. Its child objectNames are derived from the anchor button's objectName and are load-bearing for `layer_style_dialog.cpp` and UI tests.
- The core test suite uses thematic TUs under `tests/core`; the UI suite uses thematic TUs under `tests/ui`. Their registration and helper rules live in [testing.md](testing.md).
