# Editable PDF export

Split from [pdf.md](pdf.md): how "Keep layers as editable objects" writes each layer as a PDF object through Qt's PDF engine, the glyph-run merge post-pass, what flattens with a notice, and the verification tests (choosing the mode per save and page routing stay in pdf.md).

**Editable mode ("Keep layers as editable objects")**: `pdf_detail::write_editable_pdf_document_file` walks the layer stack bottom-up through QPainter on QPdfWriter with `setWindow(document pixel grid)`, so every object draws in document coordinates. The walk, barrier rule, combine classification, gradient geometry/stops, and shape representability are the Qt-free plan in `formats/vector_export_plan.{hpp,cpp}` shared with SVG export ([svg.md](svg.md) "Export" has the representability rules). Per object:

- Shape layers: `QPainterPath` (even-odd; SeparatePaths combine forms draw one path per Add group), solid/gradient/pattern brushes, `QPen` strokes (dashes and offset in pen widths, so a doubled pen halves them; Qt's miter limit is Patchy's / 2 because Qt measures in whole pen widths). Inside alignment = double width under a self clip; Outside = double width drawn under the opaque fill; either on a path with an open subpath rasterizes (`shape_layer_exportable_as_vector`). A pattern fill is a texture brush transformed by translate(phase), rotate(-angle), scale: the angle is counterclockwise-positive and Qt's `rotate()` is clockwise on the y-down page (`ui_pdf_export_editable_pattern_fill_rotates_like_canvas`). Pattern STROKES rasterize. Vector masks become `setClipPath(IntersectClip)` (inverted via canvas rect + even-odd).
- Text layers: real text with embedded subset fonts and ToUnicode, drawn by `draw_text_layer_to_painter` (`ui/text_layer_painter.hpp`, implemented in main_window.cpp): the same `TextRenderPlan` the layer's raster came from, drawn through the layer's canonical text transform, so glyphs land exactly on the raster. Refused (and rasterized, the notice naming why) only for warped text and placeholder rasters. An **imported Photoshop type layer** (`patchy.text.raster_status` = `psd_raster_preview`, or a `patchy.psd.text.transform` the Patchy transform still equals, which an import-time regenerated preview also has) is the common case and is re-laid-out by Patchy: its PSD transform is anchored at the first BASELINE while the plan's local origin is the layout top, so `imported_preview_text_plan_transform` places it the way a commit would. Box text: the PSD `boxBounds` top-left is the plan's local (0,0), and the editor's advance calibration (`calibrated_box_text_metric_scale`, run at the raster's scale) keeps the wrapping the raster has. Point text: the re-rendered ink pinned to the source raster's ink (justification fraction along x, top along y, like `anchored_text_transform_for_pixels`); scaled/rotated point text reuses the free-transform alignment (`psd_point_text_local_bounds_transform_for_pixels`, then the document-bounds fallback). **A missing font is substituted** (Qt's fallback face, as an edit does) with a notice naming the font; `missing_fonts_as_images` embeds the layer's pixels instead, and an imported preview with no font name ("PSD Text") counts as missing. **Qt embeds a face only when its `FaceId` carries a file name, which an APPLICATION font never has on Windows**: for those families QPdfEngine draws glyph outlines instead and the page holds no text (it re-imports as shape layers). So Patchy never registers a system font file it does not have to ([fonts.md](fonts.md)); text in a bundled or user-dropped font still exports as outlines.
- **Post-pass `formats/pdf_text_merge` (Qt-free), run on the written file.** Qt's engine emits every glyph as its own `x y Td <g> Tj` and maps the space glyph to U+0009 in ToUnicode, so importers read one object per LETTER with tabs for spaces. `merge_glyph_runs_in_qt_pdf` reparses the file with `pdf::File`, folds each `BT..ET` block's same-baseline glyphs into one `Td [<g..> k <g..>] TJ` whose kerns come from the font's `/W` (or `/Widths`) so positions are unchanged (a new baseline or any other operator ends the run; a lone glyph stays a `Tj`), rewrites U+0009/0A/0D ToUnicode destinations to U+0020 in place (same length), re-Flates the content, replaces the stream dictionary + data with a direct `/Length` (Qt's indirect length object is left unused), and shifts the classic xref table and `startxref` by the byte delta. Stream extents come from `raw_stream_bytes` (RawStream::data_length is 0 for an indirect /Length). Anything off-pattern (content arrays, non-Flate filters, an xref stream, encryption, parse notices) leaves the file as Qt wrote it. `pdf_text_merge_folds_qt_glyph_runs_into_tj` pins the content, the xref, and the importer's view.
- Pixel and smart-object layers: the layer flattened alone through the compositor (styles, masks, smart filters bake in), cropped to its alpha bounds, drawn as one image at the layer opacity. Silent: an image is their natural form.
- Qt's PDF engine writes NO blend modes, transparency groups, or soft masks, so: every non-Normal blend (and every adjustment layer) is a barrier that merges everything below it at that sibling level into one image; a group with opacity, a non-Normal/pass-through blend, a raster mask, or a style rasterizes whole; a raster mask on a vector or text layer sends it through the compositor; clipping-mask runs bake as a unit. Hidden layers (and the clipped run a hidden base owns) are dropped before the walk, so they neither paint nor count as barriers. Each loss is a notice; `write_flat_image_file` forwards them and `export_notes_suffix_for` puts the first one in the status message.
- Verification: `ui_pdf_export_editable_*` read the output back through Patchy's own Qt-free `pdf::read_page_as_vectors` (structure: shape/text/image counts, fill colors, text content) and through QPdfDocument/PDFium (pixels: mean RGB delta against the composite over white, < 6), so neither decoder is the writer.
