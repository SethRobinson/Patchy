# Photoshop adjustment kinds (#250)

Codec and calibration record for the Photoshop adjustment kinds added under #250, and for the placeholders that stand in for kinds Patchy cannot apply yet. Shared conventions (PS = Photoshop 2026, the COM probe workflow, fixtures) are in [adjustments-calibration.md](adjustments-calibration.md); the probes use a 64x68 image holding a 256-step gray ramp plus a 16-level RGB cube. Unchanged native blocks are written back byte for byte; new kinds append to `AdjustmentKind`.

## Placeholders

Adjustment blocks Patchy cannot apply import as empty pixel layers marked `patchy.adjustment.placeholder_kind`: the Layers panel draws the kind's symbol on a muted frame and a tooltip says it is kept but not applied, one import notice covers the file, and the native block is written back byte for byte. Every #250 kind now has a real `AdjustmentKind`; `photoshop_placeholder_adjustment_kind` still maps `vibA`, `mixr`, `phfl`, `grdm`, `blwh`, `clrL` and `selc` blocks their parsers cannot read to a placeholder, and a readable `vibA` holding Photoshop's newer Color and Vibrance settings becomes the `color_vibrance` placeholder (see Vibrance).

## Channel Mixer

`AdjustmentKind::ChannelMixer`, Photoshop's `mixr` block (44 bytes: u16 version 1, u16 monochrome, then four rows of int16 red, green, blue, unused, constant for the red, green and blue outputs and a fourth row Photoshop leaves zero; in monochrome the gray mix sits in the first row). An unedited block is written back byte for byte; an edited one drops the preset-name `CgEd` block. Fitted on a Photoshop 2026 COM probe (#250): the gray ramp plus RGB cube through 9 settings (layout markers, a channel swap, mixed and negative weights, constants, +-200 extremes, two monochrome mixes, 33/34% thirds). The model matches every probe value.

- Each percentage, weights and constant alike, becomes `percent * 1024 / 100` truncated toward zero (`channel_mixer_weight`: 20% is 204, -71% is -727). An output channel is `(R*Wr + G*Wg + B*Wb + 255*Wc) / 1024`, rounded half up and clamped. Monochrome sends the gray row to all three channels.
- Refuted: exact percentages with any rounding (hundreds to thousands of off-by-one values per setting: a 20% weight takes 153 to 30, not 31), weights floored instead of truncated (negative weights miss), and the constant as `round(c * 2.55)` or on a 1/256 scale.
- Outputs mix channels, so there is no per-channel LUT; 16/32-bit documents use the same quantized weights without the rounding. Grayscale and CMYK documents keep this RGB math, as Hue/Saturation and Color Balance do: Photoshop's CMYK form (four ink rows) is not modeled.

## Photo Filter

`AdjustmentKind::PhotoFilter`, Photoshop's `phfl` block: version 2, 20 bytes (u16 version, u16 color space 7 = Lab, u16 L in hundredths, int16 a and b in hundredths, u16 0, u32 density percent 1..100, u8 Preserve Luminosity, 3 pad bytes). Patchy keeps the color as that Lab (`PhotoFilterAdjustment::lab_*`), so an unedited block is written back byte for byte; other versions and color spaces stay placeholders. A swatch pick converts sRGB to Lab with the matrices below and matches the Lab Photoshop stores for the probe colors to within 2 hundredths. Fitted on a Photoshop 2026 COM probe (#250): the gray ramp plus RGB cube through 9 settings (warming, cooling, pure red, an odd green, gray and magenta filters; densities 1, 25, 50, 63, 100; both Preserve Luminosity states).

- The filter color is Lab (D50) converted to sRGB bytes. Source and filter go to CIE XYZ (D50) through the Bradford-adapted sRGB matrix; each component becomes `source * (1 - d + d * filter / white)`; the result converts back, is clipped to the sRGB gamut, and rounds half up. Within 1 level of Photoshop on every probe value (about 1 % of values differ by 1).
- Preserve Luminosity: PDF SetLum on that rounded result, with luma `(30R + 59G + 11B)/100` rounded to a whole level for both the source and the filtered color, then ClipColor. Exact on grays and most colors, but Photoshop clips bright colors differently: on the probe 89 % of values match, the rest are within 7 levels, almost all where a channel exceeds 255 after the shift. That clip is unresolved (a single clip center does not explain it).
- Refuted: a multiply or normal blend in encoded or linear RGB (dozens to hundreds of levels off on saturated colors: pure red through a red filter at 100 % gives (194, 0, 10)), Preserve Luminosity as an XYZ Y restore or a Lab L restore, unclamped values carried into SetLum, and Rec. 709 luma weights.
- Outputs mix channels, so there is no LUT; 16/32-bit documents run the same math without the byte stages. Grayscale and CMYK documents keep the RGB math.

## Gradient Map

`AdjustmentKind::GradientMap`, Photoshop's `grdm` block: u16 version (1, or 3 with a 4-byte method key `Gcls`/`Lnr `/`Perc` after the reverse and dither bytes), Unicode name with its trailing null, color stops (u32 location 0..4096, u32 midpoint 0..100, u16 color space, four u16 components, u16 pad), opacity stops (u32, u32, u16 0..255), then u16 2, u16 smoothness 0..4096 and 36 bytes of noise fields, padded to four bytes. Only RGB solid stops are read; other color spaces stay placeholders. The settings are a `LayerStyleGradient` (metadata `patchy.adjustment.gradient_map.*` in Photoshop's integer units); an unedited block is written back byte for byte, and an edit regenerates version 3 with the original's noise fields, which reproduces Photoshop's bytes exactly (pinned). Fitted on a Photoshop 2026 COM probe (#250): 12 maps (black to white and red to blue in all three methods, smoothness 0 and 100 %, reverse, three stops with midpoints, dither, the default method).

- Each pixel's luma, `round((30R + 59G + 11B) / 100)`, indexes the gradient (a 256-entry table per gradient, cached per thread for the compositor). Photoshop's own luma differs by one level on 65 of the 4,352 probe colors, such as (0, 255, 255); no fixed-point form explains it.
- Classic maps follow `gradient_color` with the two-stop endpoint ease of gradient fills. Perceptual and Linear apply the same smoothness ease to the segment position first (`ease_every_method`; fills and layer effects do not), then interpolate in OKLab or linear light. Every probe value is within one level. The ease is verified on two-stop gradients only.
- Opacity stops are kept for the file and ignored, as in Photoshop; Dither is kept but not rendered. 16/32-bit documents use `gradient_color_precise` on the continuous luma. Photoshop's localization-key names (`$$$/DefaultGradient/...=Name`) show only the display part in the Layers panel.
- Refuted: Linear and Perceptual without the ease (15 to 17 levels off at mid grays).

## Black & White

`AdjustmentKind::BlackWhite`, Photoshop's `blwh` block: u32 descriptor version 16 and a descriptor of six weight longs (`Rd  `, `Yllw`, `Grn `, `Cyn `, `Bl  `, `Mgnt`, -200..300), `useTint`, `tintColor` (an `RGBC` object of doubles; Photoshop stores 40.0000027 for 40), `bwPresetKind` and an empty `blackAndWhitePresetFileName`. An unedited block is written back byte for byte; an edit rewrites the modeled values in the original descriptor, and a fresh layer starts from Photoshop 2026's own block (pinned byte for byte). Fitted on a Photoshop 2026 COM probe (#250): 10 settings (defaults, zeros, all 100, single colors, mixed negative weights, extremes, three tints).

- Gray: the smallest channel plus (middle - smallest) times the weight of the secondary color the two largest channels form (yellow, cyan or magenta) plus (largest - middle) times the weight of the largest channel's primary, in hundredths, rounded half up (integer arithmetic on the 8-bit path). Exact on every probe value except one mixed negative-weight set (49 of 4,352 pixels off by one level); no rounding or weight quantization explains those.
- Tint: PDF SetLum of the tint color to the gray, luma `(30R + 59G + 11B) / 100` rounded to a whole level, then ClipColor. Within one level everywhere (about a third of the tinted values differ by one).
- Channels mix, so there is no LUT; 16/32-bit documents run the same math without the rounding. Patchy offers no Auto weights (docs/legal-constraints.md).
- Dialog (`request_black_white_settings`, shared by the layer and Image > Adjustments; #528): each slider row starts with a chip of its hue beside the gray the current weights make of it, and, given the input image, ends with a bar and percentage of how much of the image that weight acts on (`black_white_weight_influence`: each pixel's largest-minus-middle span counts for its primary, middle-minus-smallest for its secondary, times alpha, on an even grid of at most 40,000 samples, read once when the dialog opens). The measurement is display only: no control derives weights from it. The input is the layer's pixels for Image > Adjustments and the composite under the layer for an adjustment layer. Above the sliders, Custom plus nine built-in presets (`builtin_black_white_presets`, permanent ids `black_white.default`, `even_mix`, `soft_skin`, `deep_skies`, `red_lens`, `green_lens`, `blue_lens`, `glowing_foliage`, `bold`; Patchy's own names and weights) show 64x42 thumbnails of that image rendered with each preset and the current tint (a hue sweep without an image). A preset sets the six weights and keeps the tint; the strip follows the sliders back to Custom. The six hue colors are content and stay the same in both schemes; frames, tracks and text use theme roles.

## Color Lookup

`AdjustmentKind::ColorLookup`, Photoshop's `clrL` block: u16 version 1, u32 descriptor version 16 and a descriptor with `lookupType` (`3DLUT`, `abstractProfile` or `deviceLinkProfile`), `Nm  ` (Photoshop stores the LUT's full path; Patchy shows the file name), `Dthr`, and `profile`, the ICC profile Photoshop renders through. A `3DLUT` also keeps the LUT file: `LUTFormat`, `dataOrder`, `tableOrder`, `LUT3DFileData` (the file text) and `LUT3DFileName`. Probed on Photoshop 2026 (#250) with Patchy's own 5- and 17-point `.cube` looks:

- Photoshop renders only the `profile`: a block with the LUT text but no profile opens without warning and renders as identity, so Patchy treats it as identity too. For a loaded `.cube`, Photoshop writes an ICC v4 RGB device link whose A2B0 `mAB ` has identity B and M curves, an identity matrix, the cube as a 16-bit CLUT (red slowest, the cube's own grid) and identity parametric A curves; `photoshop_color_lookup_profile` writes that shape (Patchy's own copyright text, profile ID zero); Photoshop opens it without warning and renders it within one level of its own profile (32 of 4,352 probe pixels differ by one).
- Render: the reader samples the profile with Little CMS at its CLUT grid (`color_lookup_profile_grid`, else 33; abstract profiles run between sRGB ends), with no optimization or white fix-up, into a 16-bit `ColorLookupTable`; the table is applied by tetrahedral interpolation, except a two-point grid, which Photoshop interpolates trilinearly. Probed through profiles at 2, 3, 5, 9, 17 and 33 points, every grid matches Photoshop within one level (17 points: 25 of 13,056 values differ, against 145 for trilinear; 2 points: 112 trilinear against 3,482 tetrahedral).
- Tables are registered by content id (`register_color_lookup_table`), like ink spaces; layer metadata keeps the id and the name. An unedited block is written back byte for byte; a Patchy-made lookup writes `lookupType`, the name, `Dthr` and the generated profile, then, for a table loaded from a file, `LUTFormat` (`LUTFormatCUBE` or `LUTFormat3DL`), `dataOrder` `rgbOrder`, `tableOrder` `bgrOrder`, the file bytes and its name, as Photoshop does. The binding rules are in [legal-constraints.md](legal-constraints.md).
- Layer > New Adjustment Layer > Color Lookup (and editing one) has a Load LUT button for a file the user picks: `.cube` (`LUT_3D_SIZE` 2..256, comments and `TITLE` allowed, only the default 0..1 domain, red fastest; 1D LUTs are refused) and `.3dl` (a first row of input positions, then integer rows with blue fastest, scaled by the smallest of 10, 12, 14 or 16 bits that holds every value). `parse_color_lookup_file` reads both with a locale-free number parser. The `.3dl` row order and depth rule follow the common Autodesk convention and are not probed against Photoshop; `.look` is not read yet. Without a loaded table the layer is identity, as an empty Photoshop Color Lookup is.
- The probes use Patchy's own looks only; the ag-psd sample embeds a look Photoshop bundles, which stays in `local-test-fixtures/` and never enters a committed test.

## Selective Color

`AdjustmentKind::SelectiveColor`, Photoshop's `selc` block: 84 bytes, u16 version 1, u16 method (0 Relative, 1 Absolute), then ten records of four int16 percentages (cyan, magenta, yellow, black, -100..100): an unused first record, then reds, yellows, greens, cyans, blues, magentas, whites, neutrals, blacks. An unedited block is written back byte for byte; an edit rewrites the method and the nine records; a fresh layer writes Photoshop's all-zero Relative block. Fitted on a Photoshop 2026 COM probe (#250): 20 settings (each range, each ink, both methods, a four-range mix). The method is the `Mthd` key; a `CrcM` key is ignored and leaves the layer Relative.

- Weights, on 0..1 channels: reds, greens and blues take largest minus middle when that channel is the largest; cyans, magentas and yellows take middle minus smallest when red, green or blue is the smallest; whites take (smallest - 0.5) * 2 above mid gray, blacks (0.5 - largest) * 2 below it; neutrals take 1 - (|largest - 0.5| + |smallest - 0.5|) for every color but pure black and white.
- Each channel then moves by `((-1 - ink) * black - ink) * m`, with the channel's own ink (cyan for red, magenta for green, yellow for blue), m = 1 in Absolute and 1 - value in Relative, clipped to the channel's room, times the range's weight; the ranges add up, and the result rounds half up. Every single-range probe matches within one level; the four-range mix within two in Absolute.
- Ranges mix channels, so there is no LUT; 16/32-bit documents run the same math without the rounding. The model is implemented from Photoshop's own output; FFmpeg's LGPL filter was not used.

## Vibrance

`AdjustmentKind::Vibrance` (design approved on 2026-10-20), Photoshop's legacy Vibrance in its `vibA` block: u32 descriptor version 16, a one-character empty name, class `null`, and only the non-zero keys: `vibrance` (stringID) and `Strt` (charID) longs, -100..100, padded to four bytes. An unedited block is written back byte for byte; an edit writes exactly the block Photoshop writes for the same values; a fresh layer writes the empty descriptor. Calibrated on two Photoshop 2026 COM probes (#250): the 64x68 grid at 14 settings for the fit, then 4096 seeded random colors at 9 other settings held out for the tolerance.

- **Color and Vibrance.** Photoshop's newer adjustment uses the same `vibA` block. A missing `useLegacy` key means the legacy algorithm (Photoshop drops `useLegacy true` when it writes); its own new-layer default stores `useLegacy false`, which selects the newer algorithm (Vibrance 50 there differs from legacy by up to 101 levels), and Temperature and Tint are `temperature` and `tint` longs in the same descriptor. A block with `useLegacy false` or any key beyond `vibrance`, `Strt` and `useLegacy true` stays a `color_vibrance` placeholder ("Color and Vibrance"). That is why a fresh Patchy layer writes the empty legacy descriptor instead of Photoshop's new-layer block: Photoshop then renders the layer with the algorithm Patchy draws.
- **Saturation** is Photoshop's own math: in sRGB linear light every channel scales by `1 + s/100` around the gray `0.288 R + 0.712 G` (blue weight zero; least squares on the -100 output, which corrects the 0.287/0.708 first estimate), then clips. It matches to one level everywhere (98.3 to 99.6 % of pixels exact).
- **Vibrance** is Patchy's own curve, fitted to Photoshop by least squares. Photoshop's output is a hue-keeping linear-light map per pixel, `out = P + k (c - P)` (median residual under half a level), with the gain k and pivot gray P set by the pixel's largest channel `high`, its saturation `s = 1 - low/high` and, for a boost, its hue. Patchy uses fixed functions of those three values (constants in `vibrance_transfer`, src/core/adjustment_layer.cpp): `P = high (1 - a (1 - high)^b s^c (1 - s)^d)`, one constant set for each direction; `dark = min(1, high/h)^t`; reducing, `k = 1 + v (1 - 0.75 dark s^1.788)`; boosting, `k = 1 + w 0.888 dark v^1.137 (1 - s)^1.012 s^0.597 high^-0.423`, where the hue weight w is 0.83 while red is the largest channel and green sits at most 0.522 of the way from the smallest channel to the largest, eases back to 1 by 0.740 on the yellow side, and eases linearly across the red-magenta sector on the other. Nothing else is consulted: no other pixel, no image statistic, no region or content detection. Vibrance runs first, then clips, then Saturation (the reverse order misses by 5 to 24 levels on average).
- **Tolerance**, in 8-bit levels against Photoshop. Fitted grid: Vibrance +25 / +50 / +100 mean 0.62 / 0.78 / 1.62, p99 3 / 5 / 8, max 4 / 6 / 10; -50 / -100 mean 1.41 / 1.49, p99 5 / 5, max 6 / 7. Held out: +10 / +75 / +100 max 2 / 9 / 11 (mean 0.39 / 1.20 / 1.96); -25 / -75 max 4 / 7 (mean 1.74 / 1.40). Both sliders: mean 0.6 to 2.4 with p99 up to 13; a near-zero channel can miss by up to 32 when a large Saturation follows, because Saturation multiplies Vibrance's small error there. `vibrance_matches_photoshop_2026_calibration` pins 12 colors at 10 settings (221 of 360 values exact, Saturation alone exact on all).
- The gain depends on all three channels, so there is no LUT; 16/32-bit documents run the same math without the rounding.

## Image > Adjustments

Each kind above, and Exposure, is also a destructive Image > Adjustments command (#528): `imageAdjust<Kind>Action` with hotkey id `image.black_white`, `image.vibrance`, `image.exposure`, `image.channel_mixer`, `image.photo_filter`, `image.gradient_map`, `image.selective_color` or `image.color_lookup`; only Black & White has a default key, Ctrl+Shift+Alt+B. The menu runs Brightness/Contrast, Levels, Curves, Exposure | Vibrance, Hue/Saturation, Color Balance, Black & White, Photo Filter, Channel Mixer, Color Lookup | Invert, Posterize, Threshold, Gradient Map, Selective Color | Desaturate and the autos.

- Each opens the kind's adjustment-layer dialog with a live preview on the active pixel layer and applies, as one undo step, what an adjustment layer of the same settings renders: `apply_adjustment_settings_to_pixels` (ui/filter_workflows.cpp) runs the 8-bit LUT or `apply_adjustment_to_color`, and `DeepAdjuster` at 16/32 bits, on the selected pixels (a soft selection blends by coverage); alpha is untouched. The shared flow is `MainWindow::direct_adjustment_dialog`, the Levels flow: a Smart Object is refused, locked pixels refuse, text and shapes ask to rasterize, channel views disable the commands.
- No ink space is attached, so CMYK and Grayscale documents get the RGB math of a new Patchy adjustment layer. Color Lookup's Load LUT works as on the layer; with no table loaded the command changes nothing.
- `ui_image_adjustments_<kind>_matches_adjustment_layer` compares each command with the flattened adjustment layer of the same dialog edits, byte for byte (Black & White also checks a selection and a 16-bit layer).

## Opening a PSD: Photoshop pixels or Patchy's

An imported adjustment layer of any kind renders with Patchy's math from the first frame, not Photoshop's saved pixels: `ReadOptions::retain_flat_composite` (which seeds the first canvas frame from the file's composite, src/ui/canvas_widget.cpp) is off for every app open and set only by a core test. For the fitted kinds (Vibrance above all) a reopened file can therefore differ from Photoshop's composite by the documented tolerance before any edit. Showing Photoshop's pixels until the first edit would need a composite kept per document and dropped on any change.
