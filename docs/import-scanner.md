# Scanner and camera acquisition

Split from [import.md](import.md): how File > Import > From Scanner (or Camera), Photocopy and Divide Scanned Photos acquire an image on each platform. Photocopy and Divide Scanned Photos themselves are in import.md; the platform-guarded files are also inventoried in [platform-sites.md](platform-sites.md).

## Acquisition

- Windows uses WIA (`scanner_import_win.cpp`); macOS uses ImageKit/ImageCaptureCore (`scanner_import_mac.mm`). macOS exposes scanners only (no cameras) and acquisition is single-image.
- Linux (`scanner_import_linux.cpp`) dlopens `libsane.so.1` for scanners and `libgphoto2.so.6` for cameras at run time, like fontconfig and libheif: no headers at build time, nothing bundled in the AppImage (the Flatpak builds both, with `--device=all`). Linux has no system acquisition UI, so Patchy shows its own dialog (`linuxScannerDialog`): one device list for scanners and cameras like the WIA picker, then resolution (300 dpi when offered), mode (Color when offered) and source for a scanner, or the camera's image list (newest last, preselected). It is synchronous like WIA (`acquire_image_from_scanner`), so Scan and Divide Photos loops the same way. Every library call runs on one worker thread at a time; Cancel calls `sane_cancel`, which SANE allows during a blocked read, and the dialog waits for the worker before closing. A failed scan or download stays in the dialog with the error so the user can retry. With neither library installed the command reports what to install; with no device it reports NoDevice.
- SANE frames are assembled by the Qt-free `support::ScanImageAssembler` (`src/support/scan_frame.hpp`, `scan_frame_*` core tests): gray, RGB or three-pass color frames, padded strides, unknown line counts, one-bit samples expanded to 8 bits (SANE's 1 is black in gray line art but full intensity in color frames), 16-bit samples kept in host order. Scans are written as PNG to the temp folder; the device DPI comes from SANE's `resolution` option (`SANE_Fixed` or `SANE_Int`). Camera files are copied byte for byte with their own extension and open through the normal loader, raw included.
- Errors name a cause and a next step, not only the library's text: `support::classify_sane_failure` and `classify_gphoto_failure` map status codes to `AcquireFailureCause` (network scanner unreachable, with the `ip=` address airscan reports; connection lost; busy; permissions; jam; empty feeder; cover open; rejected settings; camera held by the file manager; unsupported model), and the dialog appends the matching explanation under the headline. An I/O error is "unreachable" only for the `airscan:`, `escl:` and `net:` backends.
- The Windows scan dialog is the system UI (`IWiaDevMgr2::GetImageDlg`), so its DPI and file-type defaults come from the selected Windows scan profile, not from Patchy; GetImageDlg offers no way to preseed them. Users who want 600 DPI as the default edit the profile in Windows Fax and Scan (Tools, then Scan Settings).
- Qt's image allocation limit is disabled at startup (`main.cpp`): the 256 MB default rejected large-bed 600 DPI scans with a bare "Unable to read image data".
- `PATCHY_FAKE_SCANNER_FILE=<path>` bypasses native scanner acquisition for offscreen scanner-import tests.
- The macOS AppKit sheet MUST complete asynchronously after returning to the native run loop: a nested `QEventLoop` makes every sheet control ignore mouse input.
- `ui_linux_scanner_dialog_scans_sane_test_backend` (Linux) drives the real dialog against SANE's `test` backend, the fake scanner sane-backends ships: it points `SANE_CONFIG_DIR` at a scratch folder whose `dll.conf` lists only `test` and whose `test.conf` picks the picture, mode, depth and three-pass setting, then scans an 8-bit RGB color pattern, a 16-bit three-pass scan, 1-bit gray line art and a 1-bit color grid at 75 dpi and checks each imported document (the dialog preselects Color, so the gray pass picks Gray). It skips where libsane is not installed, which includes the Flatpak SDK test environment (`-Target linux` default); `remote-build.ps1 -Target linux -NativeQt` runs it on a host with the distribution's libsane.
- Flatpak: the KDE runtime has neither library, so the manifest builds sane-backends and libgphoto2 from pinned release tarballs. The bundled SANE reads its configuration from `/app/etc/sane.d` inside the sandbox, not the host's `/etc/sane.d`. Their source ships with every release as `PatchyLinuxScannerSources.zip` (`scripts/release/make-linux-scanner-sources.ps1`, which reads the modules from the manifest); licensing and the source duty: [legal-licensing.md](legal-licensing.md#scanner-and-camera-libraries-in-the-flatpak).

## Scanner sessions

Scan a Book to PDF ([book-scan.md](book-scan.md)) needs one key press per spread, so it scans through a `ScannerSession` (`src/ui/scanner_session.hpp`) instead of `acquire_image_from_scanner`: open one device, then scan repeatedly with a fixed `ScanRequest` (dpi, Color or Grayscale, area in inches from the bed corner, output path); every scan ends in one `finished(ScanResult)`, with `progress(percent)` on the way.

- Windows (`scanner_session_win.cpp`): WIA 2.0 without a dialog. Devices from `EnumDeviceInfo` (scanners only), `CreateDevice`, the child with `WIA_CATEGORY_FLATBED` (else the first with `WIA_IPS_XRES`). Capabilities: `WIA_IPS_XRES` list or range (standard values inside a range), bed from `WIA_IPS_MAX_HORIZONTAL_SIZE`/`VERTICAL` else `WIA_DPS_*_BED_SIZE` (thousandths of an inch). Per scan: data type and depth, then resolution, then position 0, extents in pixels, position; `WiaImgFmt_BMP` (the format every driver supports) via `IWiaTransfer::Download` into an `SHCreateStreamOnFileEx` stream (`shlwapi`). All COM calls run on one worker thread in the multithreaded apartment that owns the device for the session; `TransferCallback` returning S_FALSE cancels. `WIA_ERROR_WARMING_UP` retries for 60 s. A device with no flatbed fails `open` with a message pointing at the system-dialog option. While the session exists it listens for scanners turning on or off and emits `devices_changed`; lost-device errors set `ScanResult::device_lost` ([book-scan.md](book-scan.md#scanners-turning-on-and-off)).
- System dialog per scan (`create_dialog_scanner_session`, every desktop platform): wraps `acquire_image_from_scanner` (async on macOS); settings are the dialog's, `area_applied` is false. macOS and Linux use it until direct ImageCaptureCore and SANE sessions are written; the SANE session code in `scanner_import_linux.cpp` is the starting point.
- `PATCHY_FAKE_BOOK_SCANNER` (a `QDir::listSeparator()` list of images) makes `create_scanner_session` return the test scanner: each image is a whole-bed scan at the requested dpi, the requested area is cut from it, Grayscale converts; `PATCHY_FAKE_BOOK_SCANNER_BED` (`"8.5x11.7"`, inches) sets the reported bed. `PATCHY_FAKE_BOOK_SCANNER_DEVICES` (`"id=Name;id2=Name2"`, or `none`) sets its scanner list and `PATCHY_FAKE_BOOK_SCANNER_DPIS` (`"150,300"`) the resolutions `open` reports; `notify_test_scanner_devices_changed()` then emits `devices_changed` from every test session and kills its open handle, as a power cycle does.
