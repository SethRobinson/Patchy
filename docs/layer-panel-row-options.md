# Layers panel row options

Part of [layer-panel.md](layer-panel.md).

GitHub issue 680: the Layers Panel tab of Customize Tool Palette ([tool-palette-customize-dialog.md](tool-palette-customize-dialog.md)) has a Rows column. `LayerRowOptions` (`src/ui/layer_row_options.hpp`) holds four of its settings, each stored only when it differs from its default; the keys and tokens are persisted identifiers:

- Compact rows (`layerRowsCompactCheck`, `layersPanel/compactRows`, default off): the `layerRowDetails` line is built hidden (`refresh_layer_thumbnails` still re-syncs it), the main row's vertical margins drop to 2 px (`layer_main_row_vertical_margin`) and `layer_main_row_height(size, true)` is the taller of the 22 px eye and the thumbnail slot (tile + 2) plus 4: 26 px at None and Small, 34 Medium, 54 Large. The eye, thumbnails, name and badges keep their own widgets in the row's layout, so their hit zones stay theirs (`ui_layer_rows_compact_hides_details_and_keeps_hit_zones` checks `childAt` at each center).
- Show row tooltips (`layerRowsTooltipsCheck`, `layersPanel/rowTooltips`, default on; stored as false only): off, `layer_list_item_tooltip` returns nothing, so no row, folder refresh included, carries the name, opacity and locks tip; badge and thumbnail tips stay (`ui_layer_rows_tooltip_option_turns_row_tips_off`).
- Row color (`layerRowColorCombo`, `layersPanel/rowColor`: `strip` default, stored only as `whole_row`): Whole row adds `layerRowColorTint`, a child of the row widget under its controls, transparent to the mouse, following the row's size, that lays the label's `layer_color_*` role at alpha 56 over the row background when painted (so a scheme change recolors it). A selected row paints nothing there, so the selection color shows plain, and the 4 px strip stays in both modes (`ui_layer_rows_whole_row_color_tints_rows`, Dark and Light). QSS keeps the tint widget's own background transparent beside `layerMainRow`.
- Show Fill field (`layerRowsShowFillCheck`, `layersPanel/showFill`, default on; stored as false only; the #680 follow-up): off, `apply_layer_fill_field_visibility` hides `layerFillOpacitySpin`, the Fill field beside Opacity above the list. A hidden widget is an empty item to the wrapping blend row ([right-docks.md](right-docks.md#narrow-layers-panel)), so the row's lines and both column widths are measured without it and the blend mode and Opacity share one line at the width of the footer buttons (293 px in the report) with the blend mode box at its full width. Since #693 the row with Fill holds one line there too, by narrowing that box ([layer-panel.md](layer-panel.md#blend-and-opacity-row)); it wraps a few pixels above the panel's compact width, where the row without Fill still fits. Display only: no layer's fill opacity changes, the hidden field keeps following the active layer, and Layer Styles' and Shape Appearance's Fill Opacity still edit it. `create_docks` applies the stored value (`load_view_settings` runs first), and a change rebuilds no row (`ui_layer_rows_show_fill_option_hides_the_fill_field`).

`MainWindow::apply_layer_row_options` stores and, when a row setting changed, rebuilds the rows on OK. The same column's Thumbnail Size (`layerThumbnailSizeCombo`) and Thumbnail Display (`layerThumbnailDisplayCombo`) combos set `view/layerThumbnailSize` and `view/zoomLayerThumbnailsToContent` through `set_layer_thumbnail_size` and `set_zoom_layer_thumbnails_to_content`, which also move an open dialog's combos (and Preferences' zoom box) when the gear or a thumbnail menu changes them (`ui_layer_rows_thumbnail_combos_follow_the_menus`). Left out on purpose (#680 reply): layout presets and control positions copied from other editors' panels (the AGENTS.md interface rule; legal-constraints.md, "Layers panel filter"), kind icons for thumbnails, a single lock badge, a thumbnail corner icon and another double-click: the badges, the None size and the existing double-clicks already cover them.
