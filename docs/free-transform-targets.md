# Free Transform targets: selected pixels, folders and multi-selections

Split from [free-transform.md](free-transform.md): sessions that take only the selected pixels of a pixel layer (GitHub issue 399), and multi-target sessions on folders and multi-layer selections.

## Transforming the selected pixels (GitHub issue 399)

With a pixel selection on a single pixel layer, Free Transform and the Edit > Transform modes (Scale, Rotate, Skew, Distort, Perspective) take only the selected pixels, as image editors do. Nothing is written to the document until commit.

- Which sessions float (`floating_selection_rect_for_layer`): one non-group target that is a plain pixel layer (not text, shape or smart object), the layer content as the edit target (a mask, channel or Smart Filter mask target keeps the whole-layer session), a selection outside Quick Mask. Text, shape, smart object and adjustment layers, folders and multi-layer selections keep the whole-layer session ([free-transform.md](free-transform.md)) and the multi-target session (next section). Warp keeps taking the whole layer: `begin_warp_transform` refuses a floating session ("Warp works on the whole layer. Apply this transform first.") and the session bar's Warp toggle grays out.
- The box is the selection bounds clipped to the layer's opaque rect (the revision-keyed alpha-bounds cache, so the passive Move box can frame it per repaint: with a selection, `move_transform_target_rect` frames what a handle grab would float). An empty box refuses ("The selected area is empty."), as does a layer with locked pixels. The Background's position lock does not refuse: it pins the layer, not its pixels.
- Lift (`lift_selected_pixels`, core/floating_selection.hpp): the floating pixels are the layer's with alpha times the selection coverage (soft edges stay partial); the remainder is the layer with alpha times (1 - coverage). A transparency-locked layer or the Background (`background_layer`) keeps its alpha instead: the hole blends to the background color, like Cut there, and the commit keeps the layer's alpha, format and bounds. The session source is the floating pixels over the box; the selection's whole coverage (the canvas-clipped selection bounds) is kept for the commit.
- Preview: always the composited path. The base renders `floating_selection_preview_document()` (a copy-on-write document copy whose layer holds the remainder; no layer hidden, no preview-scaled base); each patch renders that document with the layer overridden by `composite_floating_pixels` of the remainder and the transformed floating pixels, cropped to the patch plus the layer's effect reach, so a frame costs the patch area, never the layer. The proxy latch blits the floating pixels without mask coverage. The marching ants hide during the session.
- Commit (`commit_free_transform_floating`): one "Free Transform" history entry whose snapshot holds the untouched layer and the starting selection; the layer becomes the remainder with the transformed pixels composited Normal on top (bounds grow to cover them, except under a preserved alpha), and the selection is the stored coverage resampled through `transform_session_delta()` with the session's interpolation. An unchanged box commits nothing. Esc and Undo past the first step change neither layer nor selection; session steps work as in [free-transform.md](free-transform.md#steps-inside-a-pending-session-github-issue-225).
- Layer masks stay where they are (only the targeted pixels move, as in Photoshop); a vector mask too.
- Depth: the lift and composite run on straight RGBA rows at the layer's depth (32-bit stays linear), so a whole-pixel move of a hard selection keeps 8 and 16-bit samples exactly.
- A script's `layer.transform` and a Move drag inside the selection ([move-tool.md](move-tool.md#dragging-the-selected-pixels)) run this session. Outline only: [Transform Selection](selection-tools.md#transform-selection).

Coverage: core `floating_selection_*` (tests/core/floating_selection_tests.cpp); UI `ui_free_transform_selection_floats_selected_pixels` (preview hole, commit, one undo step, the selection following, redo), `ui_free_transform_selection_cancel_and_session_steps` (Esc restores bytes and selection, session undo, Warp refusal), `ui_free_transform_without_selection_takes_whole_layer`, `ui_free_transform_selection_keeps_16_bit_samples`, `ui_free_transform_selection_on_background_and_script` (tests/ui/free_transform_selection_tests.cpp), and the "transform selection perspective" row of `ui_deep_documents_match_8_bit_after_every_operation`.

## Multi-target Free Transform (folders and multi-selections)

Ctrl-T on a selected folder or a multi-layer selection runs a multi-target session (`transform_targets_` in canvas_widget_transform.cpp): the selection normalizes through `root_drop_layer_ids`, folders flatten to transformable leaves the way `movable_layer_ids` does, and exactly one non-group root still takes the single-layer path, whose pixel bytes stay pinned (exception: a lone movable preview-locked smart object takes the multi path; see docs/smart-objects.md). A leaf the transform cannot take along (position lock, vector lock, unsupported Smart Filter stack, smart object without a parsed placement quad) refuses the WHOLE session, unlike the Move tool's skip (scaling the rest around a pinned member would tear the artwork). Preview-locked-but-parsed smart objects (unsupported warps, external, legacy) transform: their Trnf and stashed nonAffineTransform quads map per corner; a linked one then re-renders from its file, the others keep the resampled pixels. Groups' own masks, adjustment leaves, and empty-pixel leaves with linked masks ride along mask-only.

- Preview: `rebuild_transform_base_cache` hides all target ids; live drags always blit ONE subtree snapshot (`ensure_transform_multi_snapshot`, the `ensure_move_proxy_image` structure: non-target non-adjustment leaves hidden, groups and adjustments keep rendering) mapped through the session delta - no latch heuristics, and the single-path `transform_proxy_previews` counter is never bumped. Release, numeric edits, nudges, interpolation changes, and Layer Style live edits render accurate N-override patches (`refresh_transform_multi_preview_cache` -> `qimage_patches_from_document_region_with_layer_pixel_overrides`). Approximation contract during drags matches the move proxy: blends vs the real backdrop, hidden clipped non-targets, canvas clip, and effect geometry under scale are approximate; commit is always exact. Snapshots above `kTransformProxyMaxPixels` downscale by sqrt; there is no last-resort outline fallback (a huge folder pays the one-time snapshot hitch).
- Commit (`commit_free_transform_multi`): one shared `transform_session_delta()` per leaf through the same per-type branches as the single commit (text compose + re-render, `transform_layer_vector_data`, smart-object placement corners + re-render, plain resample), plus linked raster masks via `transformed_linked_raster_mask` (`resample_transformed_gray8`: out-of-source samples read `default_color`, never 0, so reveal-all masks keep their surround; the result is trimmed to its non-default extent, because a rotated mask's AABB is mostly default corners and would double per rotation). The single-layer commit takes its linked mask through the same helper (GitHub #13); unlinked masks stay put and the pending-warp commit still leaves masks alone. Both accurate-patch previews render from a copy-on-write document copy carrying the transformed masks, since render overrides carry mask bounds only. `ui_free_transform_single_layer_rotates_linked_mask` pins preview, commit, trim and undo. One undo entry ("Free Transform"); a required Smart Filter re-render makes the whole set transactional with the same rollback dance. Adjustment layers transform mask-only (their bounds/effect region without a mask stays), matching the Move tool's precedent of not moving adjustment content.
- Warp stays single-layer: `begin_warp_transform` refuses multi sessions before any teardown and the options-bar warp toggle grays out. Suite: tests/ui/group_transform_tests.cpp (pinball fixture end-to-end included).
- The passive Move-tool transform box (`move_transform_controls_rect`) frames folders and multi-layer selections too: a single non-group target keeps the cheap per-layer rect, everything else runs `collect_free_transform_targets` and frames `transform_targets_content_union`, so the box always matches the session a handle grab starts and hides whenever that session would refuse (position/vector locks, unparsed smart objects). The collection walk runs per repaint and per hover move; it is layer-count bounded and the per-leaf alpha rects come from the revision-keyed cache, so no pixel scans. Options-bar X/Y/W/H fields feed from the same rect, so numeric edits on a passive multi selection start the multi session.
