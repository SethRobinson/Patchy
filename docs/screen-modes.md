# Screen modes

GitHub issue 212. View > Screen Mode: Standard, Full Screen with Menus, Full Screen (`view.screen_mode_standard`, `_full_with_menus`, `_full`), Cycle Screen Mode (`view.screen_mode_cycle`, F). The tool palette footer has one screen mode button (below). Code: `main_window_chrome.cpp` (`set_screen_mode`); the button is built in `build_tool_palette`.

A full-screen or canvas-only switch is a widely shared editor convention (GIMP and Krita have one); nothing in [legal-constraints.md](legal-constraints.md) covers it. The boundary is the interface rule in AGENTS.md: our own icon art and placement, never another editor's toolbox glyph or layout.

- **Modes.** Both full-screen modes call `showFullScreen()` (macOS: its native space). Full Screen also hides the menu bar, every toolbar, the panel column, the document tab bar and the status bar; rulers and floats stay. Leaving Standard records what it showed (`StandardScreenChrome`), so Standard restores exactly that (a bar the user hid stays hidden), with the column's own width and the maximized state.
- **Back to maximized on Windows** (GitHub issue 491). Qt leaves full screen for maximized by first moving the window to its saved normal placement, queued as a restored state, then zooming it. `set_screen_mode` delivers those reports at once with `settling_maximized_return_` set, so `changeEvent` neither strips the zoom nor resizes the window from the stale report; it then gives Windows the window's real normal bounds (`set_windows_normal_placement`) and keeps them in `maximized_return_normal_geometry_`, which `normal_bounds()` reports while Qt's `normalGeometry()` says the maximized size. Offscreen never shows the bug: `ui_screen_modes_return_to_maximized` checks it only on a real window (`PATCHY_UI_TEST_PLATFORM=windows`, [testing.md](testing.md)).
- **Never persisted:** `closeEvent` restores the chrome before saving the layout and Standard's window state.
- **Ways back.** Esc, F, the View shortcuts, the canvas right-click menu's last entry Exit Full Screen (`canvasExitFullScreenAction`), the maximize control, and in Full Screen with Menus a double-click on the menu bar's blank part (the custom title bar on Windows and Linux; `eventFilter`'s title-bar path, where Standard maximizes or restores; menu titles keep their own double-click). Esc is the canvas's last-resort Escape (`set_unused_escape_callback`, before layer deselection), so gestures, transforms, crop and text editing take it first, and never while a popup or modal is up; Esc nothing used reaches `MainWindow::keyPressEvent`. F never fires in a focused text field.
- **Hidden bars.** Qt matches a shortcut only through a visible widget carrying the action, so Full Screen adds every registered command to the window (`set_screen_mode_shortcut_host`, as floats do).
- **Hint.** `screenModeHint` shows for 2.5 s, then fades: "Press Esc to exit full screen", in Full Screen "Press F or Esc ..." with the cycle command's key. Theme roles `menu_bg`, `menu_border`, `text_primary`.
- **System exits.** Full screen left by the window system (macOS's green button) returns to Standard, rechecked 1.5 s after a change (`schedule_screen_mode_window_state_sync`). No title-bar click or drag acts while full screen (Windows skips HTCAPTION there, so the Qt path sees them and drops them); macOS keeps its native frame and menu bar.

## The tool palette button

- `screenModeButton` sits in its own 22 px row under Quick Mask (`ToolPaletteFooter::kScreenModeRowHeight`; the footer is 97 px at Normal), a 36 x 21 box (QSS content 32 x 17, icon 17 px; one row smaller and the box would overflow it at Smallest) centered like Quick Mask; the footer only places it (`set_screen_mode_button`), and it scales with the footer ([tool-palette.md](tool-palette.md#toolbar-icon-size)). One button, not three, so it costs one short row.
- A click cycles like F (`cycle_screen_mode`). A hold (`DelayedPopup`, 200 ms), a double-click or a right-click opens `screenModeFlyoutMenu` beside it: the View > Screen Mode actions themselves (the check marks live in one place) plus Cycle Screen Mode, through the tool flyouts' `ToolButtonPressFilter`, `ToolFlyoutMenuPlacement`, `ToolFlyoutCurrentMarker` (on the current mode) and menu sheet; the `toolFlyout` property draws the corner triangle. Like a tool flyout it shows each mode's icon at the palette's icon size; the menu bar keeps its menus icon-free (`hide_menu_action_icons`), so the shared actions turn `iconVisibleInMenu` on only while this menu is open (`aboutToShow`/`aboutToHide`). Cycle stays text only. A double-click's first click has already cycled.
- The icon is the current mode's action icon (`refresh_screen_mode_button`, run from `refresh_screen_mode_actions`, on the cycle action's `changed` and on retranslation); the tooltip names the mode and the cycle key. In Full Screen the palette is hidden, so only the Standard and Full Screen with Menus icons ever show on it.
- Icons (original, [tool-palette.md](tool-palette.md#icons) rules): `screen-mode-standard.svg` a window frame with a title strip and a side bar around an accent canvas; `screen-mode-full-with-menus.svg` a solid menu strip across the top, two bottom corner marks and a larger accent canvas; `screen-mode-full.svg` four corner marks around the accent canvas alone. Distinct in silhouette, art 29 units.
- Tests: `ui_screen_modes_cycle_hide_chrome_and_restore_standard` (saves `issue_212_full_screen*`), `ui_screen_modes_return_to_maximized`, `ui_screen_modes_escape_and_context_menu_return_to_standard`, `ui_screen_modes_title_bar_double_click_returns_to_standard`, `ui_screen_mode_button_cycles_and_lists_modes` (row, click, icon, tooltip, menu, Biggest; saves `issue_212_palette_footer_*`, `issue_212_screen_mode_menu`, `issue_212_screen_mode_icons`); the icons are on the `ui_tool_palette_icons_render_sheet` sheet and the button in `ui_toolbar_icon_size_preference_scales_tool_palette`.
