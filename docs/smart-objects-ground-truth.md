# Smart objects: Photoshop ground truth and fixtures

Split from [smart-objects.md](smart-objects.md): the Photoshop 2026 COM capture records (Convert, Smart Filters, liFE, Place Linked, Replace Contents) and the committed fixtures that pin them. Capture technique: [photoshop-com.md](photoshop-com.md).

- **Photoshop 2026 ground truth** (COM captures): Convert-to-SO writes BOTH PlLd and SoLd; child doc = "<layer name>.psb" ('8BPB', creator '8BIM'), canvas = layer pixel bounds, Trnf = those corners; Place uses filetype 'png ' etc. with creator four spaces and the E2 placement rule (`generalPreferences.placeRasterSmartObject` gates SO creation and may be off on a given install; capture scripts flip it temporarily and restore it); lnk2 elements are version 8 with ~117 undocumented trailing bytes (parse by element length; Patchy writes v7); duplicates share the Idnt uuid, "New Smart Object via Copy" clones the element under a fresh uuid ('placed' is a per-layer instance uuid, always fresh); **no lnk2 element may be unreferenced**: PS 2026 refuses to open a file whose embedded link block holds an element no layer references ("Could not open ... because of a program error"), whether Patchy authored the element (Convert to SO then Rasterize or Delete) or PS did (its own placed PNG with the layer deleted in Patchy), and PS itself drops the element when it saves after rasterizing (its Convert to SO, Rasterize, Save leaves no lnk2 at all). Patchy's store still keeps orphans so Undo can bring the layer back; the writer leaves them out (`psd_document_io.cpp`, the lnk2/lnkD/lnk3 emission): a block with an orphan regenerates from its remaining elements, each keeping its verbatim bytes, an emptied block is not written, fully referenced blocks stay verbatim, and any placed layer of unknown source (unparsed SoLd, or a placed block that never became metadata) disables the pruning. lnkE (linked) blocks follow the same rule: PS 2026 refuses ("program error") a Patchy-written file whose lnkE holds a liFE element no layer references. Pinned by `psd_writer_omits_unreferenced_smart_object_sources`, `ui_smart_object_orphaned_source_is_not_written`.
- **Smart Filter ground truth**: the complete Photoshop COM capture record (descriptor classes and key orders, FEid cache layout, per-filter kernels and formulas, authoring shape, fixture provenance) lives in [smart-filters-native.md](smart-filters-native.md). Consequences here: `filterFXList` stores filters in execution order while the Layers panel displays them reversed; saving Edit Contents or Replace Contents regenerates the shared `Idnt` and every referencing layer's `placed` uuid, while rasterizing one duplicate leaves the surviving instance IDs unchanged.
- **liFE (linked external file) element layout** (pinned from the 10cm-table-tent PS 2023 capture, v7 elements, and the PS 2026 v8 captures below): uuid pascal string, unicode filename, filetype OSType, creator (four NUL bytes in 2023; PS 2026 writes uninitialized bytes, so the field is noise and Patchy keeps NULs), u64 datasize (0), open descriptor flag + `{null; compInfo{compID:-1, originalCompID:-1}}` for raster contents or an EMPTY descriptor named "Open" of class 'Opn ' for an SVG, then a SECOND u32 descVersion 16 + `ExternalFileLink` descriptor (class strID; keys in order: descVersion(str) long = 2, 'Nm  '(char) TEXT filename, fullPath(str) TEXT file:// URI, originalPath(str) TEXT native path, relPath(str) TEXT), then a 16-byte date struct {u32 year, u8 month, u8 day, u8 hour, u8 minute, f64 seconds}: the file's modification time in **UTC, truncated to whole seconds** (the 13:03:05 UTC stamp of a file modified at 22:03:05.698 JST), then u64 file size (PS compares both for staleness), then the versioned tail every element kind shares: v5+ unicode child doc id, v6+ f64 assetModTime, v7+ u8 lock state, and v8's trailing bytes are a u32 16 + `{null; contentID TEXT uuid}` descriptor. `parse_link_element` models all of it best-effort (unmodeled variants degrade to the verbatim skip) and `serialize_external_element` mirrors it (v7) for dirty external sources; clean elements still re-emit byte-identically. `psb_life_trailer_fields_parse_if_available` + `smart_object_external_element_round_trips_if_available` pin both directions; `stamp_smart_object_link` / `smart_object_link_changed_on_disk` (ui/smart_object_render) own the UTC stamp and its comparison (a local-time stamp from an older Patchy still reads as unchanged).
- **Place Linked ground truth** (PS 2026 COM captures, `scripts\dev\smart-objects\ps-capture-linked.ps1`; local `ps2026_linked/` fixtures pinned by `psd_photoshop_linked_captures_match_authored_blocks_if_available`, `psd_photoshop_linked_elements_parse_if_available` and `ui_smart_object_photoshop_linked_capture_resolves_if_available`): a linked placement writes ONLY a 'SoLE' block (no PlLd) carrying the same 'soLD' v4 descriptor as SoLd, the liFE element goes into 'lnkE', and an EMPTY 'lnk2' block sits beside it (an embedded placement mirrors it: PlLd + SoLd, lnk2, empty lnkE). An SVG placement, linked or embedded, has filetype 'SVG ', Type 1 (vector), Sz = the SVG's own pixel size, Rslt 72, and a 17-key descriptor with NO compInfo; its warp `bounds` are the artwork's unscaled placement rectangle in DOCUMENT space (the E2 rect: physical size centered, fit when larger; 2048 px in a 144 ppi document), which later scales, rotations, duplicates and even a relink to a different-size file leave untouched, while Trnf carries the transform. Raster placements keep Type 2, compInfo and content-rect bounds. `author_placed_layer_sold_payload` reproduces both shapes byte for byte (Type 1 takes the base rect) and `regenerate_placed_layer_payload` never rewrites Type 1 bounds. Paths: fullPath is the undecorated URI `file:///D:/dir/logo ünï 日本.svg` (no percent-encoding, forward slashes; a name holding `#`, `%` or `%20` is stored as typed, so `resolve_smart_object_external_path` tries the text after `file://` as a literal path before any QUrl decode), originalPath the native path, relPath computed against the document's folder at SAVE time ('logo.svg' beside it, '../logo.svg' one folder up), even for a document that had no folder when the file was placed. Every separate placement of one file gets its OWN element and uuid; a duplicated layer shares the element; Update All Modified Content then MERGES every layer linking that file onto ONE fresh element with fresh `placed` ids, so Patchy's shared element on repeated placement is a state Photoshop produces itself. `linkChanged` stays false until Photoshop re-checks the file (it did not notice a rewrite made between two COM calls), and `placedLayerUpdateModified` is refused until it has. Photoshop's stored preview of a linked SVG agrees with Patchy's qsvg render within edge antialiasing (flat and folded logos, userSpaceOnUse gradients inside transformed groups included).
- **Replace Contents ground truth** (E5 COM captures, `ps2026_e5_*` local fixtures): PS creates a NEW element with a fresh uuid and repoints EVERY layer that referenced the old uuid (the replaced-away element is removed, unlike rasterize orphans); each layer's quad is rebuilt about its own quad center preserving the content-inch-to-doc-pixel linear map (`L_new = L_old * dpi_old/dpi_new`; same-dpi replaces degrade to pure pixel scaling), Sz/Rslt become the new content's pixel size and dpi, and layer names swap the old source stem for the new one ("A copy" becomes "B copy"). PS additionally rounds the resulting quad corners to whole pixels while its "Snap Vector Tools and Transforms to Pixel Grid" preference is on (`toolsPreferences.transformsSnapToPixels`, the default; off keeps a Free Transform quad at 13.4 but still renders a pure translation crisply at 13, PS 27.9 captures in docs/tools.md); Patchy keeps full doubles here and snaps only numeric Free Transform rects (a sub-pixel placement difference on OUR edit, not a render divergence). Place also writes an empty 'lnkE' block alongside 'lnk2'.
- **Fixtures**: committed in `test-fixtures/psd/`: `photoshop-place-embedded-png.psd` (real placed SO), `photoshop-basic.psb`, the five original small `photoshop-smart-filter-*.psd` Photoshop 27.8 captures, and Photoshop 2026 per-filter captures `photoshop-smart-filter-<name>.psd` for high-pass, median (radius 7), dust-and-scratches (7/23), surface-blur (the canonical descriptor), unsharp-motion (Unsharp amount/radius/threshold plus Motion angle/distance), plastic-wrap (13/9/7), mosaic (Cell Size 6), emboss (135/3/150), box-blur (radius 5), radial-blur (Spin 10, Good), radial-blur-zoom (Zoom 25, Best), add-noise (Uniform 12.5% seed 123456), add-noise-gaussian (Gaussian 8% monochromatic seed 654321), and the preservation-only tilt-shift (native Blur Gallery descriptor). The matrix also pins integer/fractional Gaussian and High Pass radii, inter-record FEid alignment, entry/stack enable state, Multiply 37%, both Gaussian/Median orders, hard/five-tone (0/64/128/192/255)/disabled filter masks, a coexisting normal layer mask, two transformed instances sharing one source, Edit/Replace Contents, and rasterization. Local-only ps2026_* captures live in `local-test-fixtures/psd/` alongside the eon_spider originals and `local-test-fixtures/psd/PSBtest/` (Seth's manual PSB-in-PSB file: `10cm table tent.psb` embeds `Content.psb`/`Content B.psb`). **NEVER SAVE OVER the PSBtest tent/Content files**: several `_if_available` tests byte-pin their PS-2023 shapes (liFE trailer dates, lnk2-as-8BIM+u64), and a Patchy save re-stamps them. Pristine originals are kept outside the repository (see `agents_local.md`); re-copy them if the suite's liFE trailer checks start failing.
