# PDF import

Split from [pdf.md](pdf.md): reading pages as editable layers (Patchy's own parser) or flattened images (PDFium), the page probe and scan routing, the Import PDF dialog and its options, and how pages become documents, layers or artboards.

## Import

- **Editable import is the dialog's default:** the Qt-free `formats/pdf_{syntax,filters,file,fonts,content,document_io}` family parses files (lenient xref/object-stream/rebuild, all non-image filters, simple + Type0 fonts with /Differences and /ToUnicode) and interprets one page's content stream. Paths become vector shape layers (nonzero via shared `formats/vector_fill_rule`, even-odd in one group; clips become vector masks with `Intersect` groups). Each show-text operator becomes one text layer: a whole `TJ` array is ONE run (its strings concatenate and the kerning numbers fold into `intended_width`; only a jump of >= 1000 thousandths, positioning rather than kerning, ends the run; ToUnicode control characters U+0009/0A/0D read as spaces). `MainWindow::render_pending_pdf_text_layers` finishes each style run, rendering through glyph-space matrix `patchy.pdf.text_xfrm` and clamping an x-scale correction against `patchy.pdf.text_intended_width` so substituted fonts keep run widths; PDF has no paragraphs, so one layer per run is the honest unit. Images become embedded smart objects (DCT bytes verbatim, else `formats/pdf_png_writer`; the quad keeps rotation, `render_pending_pdf_image_layers` bakes pixels). Shadings/tiling patterns/Separation tints/soft masks approximate with a notice; editable failure falls back to raster. Standard RC4/AES user and owner passwords import; custom security handlers refuse. `formats/affine.hpp` is shared with SVG.
- **One `pdf::PageReader` per import.** `read_page_as_vectors(bytes, options)` opens the file on every call (a copy of the whole file plus the cross-reference and page-tree parse, per page). `PageReader` (formats/pdf_document_io.hpp) owns one `pdf::File` for the editable pages, the probe, and the source capture of flattened pages; the span functions are thin wrappers over it. Not for concurrent use (the file's object caches are unlocked): one thread at a time, any thread. A file Patchy's own parser cannot open still imports through PDFium, without those extras.
- **The page probe (`PageReader::probe_page`, `PageProbe`)** walks a page with `ContentOptions::decode_images` off (`probe_page_content`): `on_image` still fires with the transform, size, `PlacedImage::source`, and the codec read from the filter chain, but no image stream is read or decoded. It counts VISIBLE primitives (an opaque image that covers the whole page resets the counts, so a background rectangle under a scan is not content; invisible render-mode-3 text, an OCR layer, is never emitted), measures how much of the page is images the editable reader cannot decode (JPEG 2000, CCITT, JBIG2), reports `/Annots`, and fills `source_page` when the page is exactly one opaque image an export can carry verbatim: DCT or JPX, DeviceGray / DeviceRGB / ICCBased with N 1 or 3 / none (JPX), no `/SMask`, `/Mask`, `/SMaskInData`, stencil, constant alpha, or blend mode, every canvas corner inside the image's quad (slack 1e-3 of the image), and no clip except axis-aligned rectangles that contain the page. CMYK, Indexed, Cal*, Lab and Separation are refused rather than approximated.
- **Scanned pages flatten, once, with one notice.** The Import PDF dialog probes every selected page first. A page that is only undecodable images, or at least half covered by them, goes straight to the raster path: the editable reader would drop the scan and keep only what sits on top (an OCR'd scan would come in as loose text on an empty page), and a pure scan would pay a full parse and a throw before the PDFium render anyway. All pages scans: the whole selection takes the flatten path (with read-ahead, below). The notice is one plural line, not one per page.
- **Rendering is a two-stage pipeline off the UI thread** (`render_pages`): when the caller reports progress on the GUI thread, `render_page_image` (PDFium) runs through `launch_async` with one page of read-ahead, and `finish_rendered_page` (trim, `document_from_qimage`, probe, source stamp) runs on a second worker while the NEXT page renders; results are taken in page order, at most two pages of pixels in flight besides the one rendering, and the UI thread only pumps events. PDFium's global lock means two pages never render at once; the pipeline buys a live progress dialog, a Cancel that answers mid-page, and the conversion hidden behind the next render. The probe takes a mutex because a `PageReader` is one thread at a time and two finishing steps can overlap. The non-interactive load (which may itself be on a worker) renders inline. Separate-documents mode builds each `Document` where the pixels are hot and drops the frame at once.
- **The page picker never renders before it shows.** Rows start with a transparent icon of the right shape and `pdfImportThumbnailTimer` (zero interval) renders one thumbnail per tick, rows on screen first, and stops on `QDialog::finished`: the import renders through the same `QPdfDocument` from a worker, so no thumbnail may start once the dialog is closing. The size label (`pdfImportSizeLabel`) describes what the chosen "Pages become" target builds: for Layers and Artboards with more than one page a "One canvas of W x H px" line (`pdf_merged_canvas_size`, pdf_import.hpp, the function the merge itself sizes its canvas with: the largest page for Layers, the artboard grid with its gaps and any empty cell for Artboards), and "About N GB of memory" once the pages' RGBA pixels plus the one 8-bit RGBA frame the open document keeps of its canvas pass 0.5 GB. Two cases turn the label into a warning (`@console_warning_text`, bold, property `importWarning`): a merged canvas of `kHugeMergedCanvasPixels` (250 Mpx) or more, which says it will be slow to open and edit and names the ways out (fewer pages, a lower resolution, Separate documents), and memory past half of `total_physical_ram_mb()`. It stays a label: the import is never blocked or scaled down. The note can never squeeze the page list (local-050): the list's minimum width is its rows' (`sizeHintForColumn(0)`, the frame and the scroll bar), because a box layout gives its stretch item the bare minimum as soon as the column beside it asks for more than the row has; the label's horizontal size policy is `Ignored`, so its text wraps inside the options column instead of widening it (a wrapped QLabel hints up to 80 characters); and `keep_dialog_tall_enough_for_wrapped_text` (dialog_utils) grows the dialog when the wrapped note needs more lines (`ui_pdf_import_page_list_keeps_its_width_under_the_size_warning`).
- **Pages become documents, layers or artboards ("Pages become:" combo, `pdfImportPagesTargetCombo`, setting `imports/pdfPagesTarget` with tokens `documents`, `layers`, `artboards`; issues 19 and 154).** Separate documents is the default and Photoshop's behavior: `PdfImportOptions::separate_documents` makes every selected page its own `Document` at its own size (page 1 in `PdfImportResult::document` with `document_title`, the rest in `extra_documents`), and `MainWindow::open_extra_imported_page_sessions` opens one pathless session per extra page titled "file.pdf - Page N" (page 1 keeps the file path and the same title form) through `add_document_session(..., SessionActivation::Background)`: a tab and a session but no tab switch, panel rebuild, composite, or paint, so page 1 stays active. A background session sets `DocumentSession::fit_view_on_first_activation`; `activate_document_canvas` fits it the first time its tab is selected, and once more from a zero timer after the newly shown page has its real geometry. In this mode the editable reader runs once per selected page (a page it cannot model flattens alone, with a notice, and the rest stay editable). "Layers in one document": every page, raster or editable, imports as a document and `merge_imported_pdf_pages` (main_window_files.cpp, after `render_imported_pdf_pages`, the pending text and image passes over every page) wraps it in a Pass Through "Page N" folder on a canvas of the largest page: page 1 on top and the only one visible, each folder recording its page as `kLayerMetadataPdfPageRect` and its page image in `pdf_page_source_pages`, so export by groups gives the pages back at their own sizes and passes untouched scans through. "Artboards in one document" merges the same way into one artboard per page, page 1 on top, laid out in a grid (`ceil(sqrt(n))` columns, cells of the largest page, `kArtboardSpacing` apart); each artboard's page background is its artboard background, and a page's source image rides `pdf_page_source_pages` so an untouched artboard page still passes through ([artboards.md](artboards.md)). The non-interactive path (CLI, scripts, Files as Layers) imports page 1 flattened at the remembered `imports/pdfResolution`. Reopen shows the picker; a documents-mode reopen replaces only its own tab with the first chosen page. **Progress:** the accepted dialog shows a cancellable `QProgressDialog` (`pdfImportProgressDialog`, "Importing page N of M") driven by `PdfImportOptions::progress` (false = stop, keeping the pages done, with an "Import stopped after N of M pages" notice). Everything after it reports through ONE dialog, `MainWindow::OpenProgress` (`pdfPageImagesProgressDialog`, under the same "Import PDF - file" title): `open_document_path` and Reopen create it for a PDF import and every later step finds it in `open_progress_` instead of making its own. Its steps, in order: "Preparing page image N of M" (`render_pending_pdf_image_layers` over all the pages at once, so M is every pending image of the import, never "1 of 1" per page, and different pages decode side by side), then for a merge "Building artboard N of M" or "Building page folder N of M" and "Finishing page N of M" (the pass-through fingerprints, below), "Converting the bit depth..." when the depth changes, "Opening file..." (`add_document_session`'s layer rows) and, for separate documents, "Opening page N of M" with an event pump after each `add_document_session` so tabs appear one by one. The dialog shows once the open has waited `open_progress_delay_ms()` (400 ms; at once when the import dialog's own progress was up that long, `PdfImportResult::import_ms`, so one follows the other without a gap) and never under unattended automation; `OpenProgress::pump()` turns the event loop without user input either way. `open_progress_stats_` records the dialogs shown, the image passes and every step label for the tests (`MainWindowTestAccess::open_progress_record`). **Nothing proportional to a page's pixels runs on the UI thread between the reader and the session:** decodes, the per-document fingerprint (`stamped_pdf_source_page`) and the depth conversion run on workers the UI thread waits on while pumping, at most `pdf_page_task_window` at a time (four, half the hardware threads when that is fewer, and fewer for huge pages so the tasks in flight stay within about an eighth of physical memory). A merge fingerprints each page as its exporter derives it (`document_for_imported_page`, then `stamped_pdf_source_page`), which for an artboard whose scan has soft edges means compositing its paper, clip and scan (timings in [pdf-performance.md](pdf-performance.md)), so these run on workers too, read the merged document only, and are filed once all are done. The pages are not fingerprinted before the merge as well (that composited and hashed every page twice). The merge places a page in about a millisecond (pixel storage is shared, `copy_layers_between_documents` skips its extent scan under an exact offset) and drops each page document's layers once placed.
- **Raster import** (`ui/pdf_import.{hpp,cpp}`, the "Flattened image per page" mode and the non-interactive default) needs the optional Qt PDF add-on, which wraps PDFium. Not in a stock Qt install and absent on wasm, so CMake uses its OWN `find_package` (a missing component in the main QUIET one would silently skip the whole app target), defines `PATCHY_HAVE_QT_PDF`, else builds `pdf_import_stub.cpp`. Stub builds still recognize `.pdf` as openable (`is_supported_open_path`), so a picked or dropped PDF fails with the stub's clear message; on wasm that message carries `kPdfDesktopOnlyMarker` and `show_open_failed_message_box` strips it and adds the "Get the Desktop Version" button of the [desktop-only prompt](wasm.md#desktop-only-commands) (`exec_message_box_with_desktop_download`). Provisioning: `-m qtpdf` in the mac/linux setup scripts; Windows: `aqt install-qt windows desktop <ver> win64_msvc2022_64 -m qtpdf --noarchives -O .deps\Qt`.
- **PDFium renders onto a TRANSPARENT page**; `on_white_page` composites it over white when "White page background" (`pdfImportWhiteBackgroundCheck`, `imports/pdfWhiteBackground`, default on, issue 153) is set, and the editable reader adds a bottom white "Background" layer (`VectorReadOptions::white_background`). Artboard merges skip both and use White artboards instead. "Trim to content" compares against the corner pixel, so white and transparent borders both trim.
- **Resolution, Mode, Bit Depth, Reverse Order (issues 147, 152).** Resolution is an editable combo (`pdfImportResolutionCombo`: 72 to 600 presets, any typed 12 to 1200). Mode (`pdfImportColorModeCombo`, `imports/pdfColorMode`): Grayscale makes gray RGB content (raster through `gray_from_rgb`, editable through `VectorReadOptions::grayscale`, which grays paints, shadings and decoded images; a non-gray source image drops its pass-through); CMYK opens every page session in CMYK Proof (a notice when no CMYK profile is set); Palette is Flattened-only and quantizes each page (`convert_imported_document_to_palette`). Bit Depth (`pdfImportBitDepthCombo`, `imports/pdfBitDepth`) converts after the pending passes (`finish_imported_pdf_document`); Palette forces 8. "Open in reverse order" (`imports/pdfReverseOrder`) reverses the page list before anything else.
- **Imported text size (issue 155).** The reader stores the `Tf` size and puts the whole text-space scale in the transform (a `1 Tf` run at 300 ppi is a huge scale), which made the caret and editor box enormous. `render_pending_pdf_text_layers` folds the em height (`hypot` of the glyph matrix's y column) into the font size through `fold_text_transform_scale_into_font_size`, leaving only rotation, aspect and flip in the transform. **Qt PDF exposes no crop-box selection**: `pagePointSize` is CropBox intersected with MediaBox; Art/Bleed/Trim boxes are unreachable, so Photoshop's Crop To menu cannot be reproduced (the post-render trim plus a notice stands in). Raster pages cap at 20000 px per axis with a notice. The document adopts the chosen PPI, so PDF must never join `kDensitylessFormats`.
