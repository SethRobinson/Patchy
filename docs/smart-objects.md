# Smart objects (Photoshop placed layers)

Warp-specific machinery lives in [warp.md](warp.md). This document owns the never-save-over-PSBtest warning; the layer context-menu rule lives in [ui-conventions.md](ui-conventions.md).

A smart object stays a **`LayerKind::Pixel` layer** (the text-layer pattern) whose pixels are Photoshop's rendered preview; identification is the `layer_is_smart_object()` predicate over `patchy.smart_object.*` metadata (core/smart_object.hpp owns the keys and helpers, like adjustment_layer.hpp does).

- **Model**: per-layer placement metadata (source uuid, Trnf quad, size, dpi, lock reason, raster_status, block_dirty) parsed from the 'SoLd' (authoritative; 'SoLE' alias) or legacy 'PlLd' blocks by `src/psd/psd_smart_objects.{hpp,cpp}`; source payloads live in `DocumentMetadata::smart_objects` (a `SmartObjectStore` parsed from the global 'lnk*' blocks, one `SmartObjectSource` per element with **shared_ptr-held bytes so whole-Document undo snapshots share one copy**). Unparseable blocks/elements stay opaque and re-emit verbatim.
- **Native Smart Filter model**: `Layer::smart_filter_stack()` is the per-instance semantic model of SoLd `filterFX`; `src/core/smart_filter.hpp` models stack/entry enable state, native order, blend mode/opacity/colors, settings for the thirteen supported filters (Gaussian Blur, High Pass, Median, Dust & Scratches, Surface Blur, Unsharp Mask, Motion Blur, Plastic Wrap, Mosaic, Emboss, Box Blur, Radial Blur (Spin), Add Noise), and the one shared filter mask separately from the ordinary layer mask. `DocumentMetadata::smart_filter_effects` owns Photoshop's document-global `FEid`/`FXid` render caches, associated by the SoLd `placed` uuid rather than the shared source `Idnt`. Raw record bodies and decoded mask samples are shared across whole-document undo snapshots. A wholly supported stack of those thirteen filters with one unambiguous semantic FEid record is editable; an unsupported entry or cache (including Radial Blur's Zoom method) keeps the whole layer on Photoshop's preserved preview.
- **Editable native rendering**: `src/filters/smart_filter_renderer.{hpp,cpp}` is the deterministic CPU path for supported native Smart Filters; the per-filter kernels and formulas (FEid-canvas embedding, edge repetition, the nearest-visible RGB extension for transparent pixels, alpha trimming) are in [smart-filters-native.md](smart-filters-native.md) "Render semantics". An expanding filter (Gaussian/Motion Blur) followed by a bounds-preserving one uses the expanded result's trimmed bounds; the reverse order can still grow across the FEid canvas. Each entry composites over the previous stack result with its opacity and blend mode (Normal at 100% uses Photoshop's replacement path); the document-space shared mask applies once to the completed stack. The renderer runs only while producing a cached layer raster, never from `paintEvent` or the compositor. Any mutation regenerates from the unfiltered source, never by refiltering the previous preview.
- **Smart Filter preservation**: untouched SoLd and FEid/FXid payloads re-emit byte-for-byte. Parsed version-1 cache records expose 8-bit raw or PackBits filter masks while retaining their raw bodies. An unknown entry, malformed cache, unsupported mask compression/depth, missing association, or duplicate `placed` association marks the whole stack unsupported; one opaque FEid/FXid block makes associations and mutations fail closed across the whole store (a hidden duplicate cannot be ruled out). PackBits row lengths are strict; an invalid cache layout stops before optional-mask decompression. Never execute a supported prefix of an unsupported imported stack. Photoshop writes 0-3 zero alignment bytes after each length-prefixed FEid/FXid record, inside the declared block payload; the codec requires zero padding for the native shape, preserves untouched bytes, accepts the unambiguous unpadded multi-record shape of pre-0.20 Patchy, and reproduces four-byte alignment after a rekey. Patchy-authored filters write a canonical Photoshop-shaped `filterFX` descriptor and a version-3 FEid block (full-document PackBits unfiltered RGB/alpha cache plus the shared mask). Same-size edits patch known leaves in place. Mask painting replaces only the optional FEid mask tail, preserving the unfiltered cache prefix, record order, block dialect, declared-length form, and alignment; an unsafe or ambiguous record rejects the edit. Per-filter opacity/blend-mode edits patch SoLd only. Append, duplicate, reorder, and delete rebuild only `filterFXList`, deep-cloning retained native objects so unknown fields, key order, and ID forms survive without shared descriptor aliases. No private `plSF` fallback exists. An FEid cache makes Photoshop eagerly validate the layer's embedded source file and 'lyid' block at open time; the writer therefore emits even-length merged-composite PackBits rows everywhere, normalizes stored embeds whose composite has odd rows, and synthesizes 'lyid' blocks for id-less smart-object layers (docs/ps-compat.md "Smart Filter documents have two extra open-time requirements").
- **Preserve-unless-edited**: untouched layers re-emit their original SoLd/PlLd blobs byte-identically; a move/transform sets `block_dirty` and the writer REGENERATES the blocks patch-in-place via the generic descriptor writer (psd_descriptor.cpp `write_descriptor`, which preserves key order and each id's charID/stringID form; Photoshop writes the 4-char key "warp" as a stringID, so id form is NOT derivable from length, and `DescriptorObject::key_order`/`KeyEntry::long_form` carry it). `psd_descriptor_writer_round_trips_sold` pins read->write byte-identity.
- **Lock classification** (kLayerMetadataSmartObjectLock): unsupported warp/quiltWarp, non-affine quads, unsupported or ambiguous filterFX/FEid data, external ('liFE') sources, PlLd-only ("legacy"), and parse failures are preview-locked: Patchy shows/preserves Photoshop's raster and refuses pixel edits; rasterize always works. Photoshop Blur Gallery's `blurbTransform` (including native Tilt-Shift) and native Liquify stay in this preservation-only class. A fully supported filterFX/FEid pair containing only the thirteen modeled filters clears the provisional filter lock. Empty lock = editable. (Supported warps unlock; see docs/warp.md.)
- **UI semantics**: the smart-object badge on the layer row's details line (`layerSmartObjectBadgeButton`, embedded vs linked icons, `smartObjectLinked` property) is THE click affordance for opening the contents; the sibling `layerFxBadgeButton` opens layer styles. Row double-click opens layer styles for pixel, text, and smart-object rows (deliberate); group rows: nothing, adjustment rows: the adjustment editor, unlocked shape/fill rows: the shape appearance editor. Filter > Convert for Smart Filters converts the active normal pixel layer to an embedded Smart Object; each of the thirteen supported filters (Radial Blur: default center and tiered samples only; Pixel Mosaic maps to Photoshop's Mosaic) then appends an editable native entry instead of changing source pixels, while staying destructive on ordinary pixel layers. Lens Blur, Iris Blur, and Tilt-Shift Blur are destructive and gallery-capable with no native mapping; Liquify refuses Smart Objects, rasterize first (see docs/liquify.md). A direct action or mixed gallery recipe on a Smart Object takes the all-or-nothing rasterization path, never a partial or private descriptor: both offer the same "Rasterize Smart Object?" prompt (`filterRasterizeMessageBox` / `filterGalleryRasterizeMessageBox`; accept = rasterize + apply destructively as one undo step, cancel = layer untouched), and the Filter Gallery shows the outcome inline before Apply ("SF" badges, tooltips, `filterGalleryOutcomeLabel`, per-entry warnings; see docs/filters.md "Filter Gallery"). Adjustment-only filters (Image > Adjustments) keep the hard refusal status message (native-integrity gates below); `ui_smart_filter_native_integrity_guards_reject_destructive_actions` pins the no-dialog behavior. The routing whitelist is single-sourced: `native_smart_filter_kind_for` / `native_smart_filter_kind_supported` in `src/filters/smart_filter_recipe_mapping.{hpp,cpp}` are the only decision points; never duplicate the ID list. Double-clicking a Smart Filter entry row opens that filter's settings dialog, whose Blending section (blend mode + opacity) also opens via the row's Edit pencil (`patchyFilterDialog`); the layer-styles double-click applies only outside entry rows. Shared-mask thumbnail: click paints, Ctrl-click loads as selection, Shift-click enables/disables, Alt-click shows the grayscale mask-only view; overlay and mask-only commands follow it while it is the active edit target. Unsupported imported stacks show disabled preservation controls. "Convert to Normal Layer (Rasterize)" (`layerSmartObjectToNormalAction`, both Smart Objects menus) just calls the Rasterize path. Painting source pixels raises `paintSmartObjectMessageBox` (Edit Contents / Rasterize / Cancel; press consumed; Edit Contents omitted when contents can't open; automation keeps the status refusal); destructive filters/gallery/adjustments on TEXT and SHAPE layers raise the analogous `rasterizeOrConvertMessageBox`, whose Convert To Smart Object choice (offered only when the smart-filter follow-on can succeed) funnels into `convert_layers_to_smart_object` and then this same routing (see docs/filters.md "Text and shape layer gate"); Delete removes the object (like text); merge targets and rasterize/rasterize-style strip the smart-object data (`strip_layer_smart_object_data`); Export Smart Object Contents... (layer context menu) writes the embedded bytes verbatim. Duplicate, New Smart Object via Copy, and cross-document paste give each clone a fresh `placed` uuid and clone/adopt its FEid/FXid record without copying the large backing bytes; a clone's FEid record must sit immediately after its source record, and its preserved `lyid` block must be rekeyed to a fresh document-wide value (Photoshop 27.8 rejects an appended cache record and aliases layers sharing `lyid`). Rasterize/delete drop the instance cache once no layer references it; undo restores layer and cache together. A missing or ambiguous record blocks the clone.
- **Current Smart Filter editor limits**: Patchy authors and edits ordered stacks of the thirteen supported filters. A new stack uses the exact current selection alpha as Photoshop's shared filter mask (an explicit all-white mask without a selection); later entries retain it. Editable masks are full-document 8-bit grayscale targets: Brush, Eraser, Fill/Clear, Gradient, Line, Rectangle/Ellipse, and Invert edit the temporary mask buffer, unsupported tools are blocked (never touching source pixels), the model and native cache stay unchanged during a gesture, and each completed gesture commits one undo step and regenerates the filtered preview once. Whole-percent opacity (Photoshop normalizes fractional values) and blend mode live in the settings dialog's Blending section with cancellable live preview; Apply is one undo step, and a blending-only accept patches SoLd only. Editable native masks require documents of 64 megapixels or less; larger imported records stay preview-locked. A true `filterMaskLinked` flag is preserved but preview-locked (Photoshop 27.8 ignored attempts to set it; no true-state fixture); linked-mask editing, Density, and Feather are not exposed. The settings dialogs (`editable_smart_filter_dialog_spec`) use the typed and practical ranges, and the renders the formulas, of the destructive catalog entries in [filters.md](filters.md) unless noted; Gaussian Blur and High Pass radii are fractional 0.1 to 1000 px. Mosaic (integer Cell Size 2..200 px, slider to 64) keeps bounds and matches the destructive Pixel Mosaic's alpha-weighted block averages exactly; like Plastic Wrap the descriptor round-trips while the pixels are Patchy's own compatible rendering. Emboss (Angle -360..360 degrees, Height 1..100 px, Amount 1..500 percent; sliders -180..180, 1..24, 1..300) keeps bounds and alpha and matches the destructive Emboss's bilinear-luminance gray relief exactly. Photoshop's Emboss Amount minimum is 1, so a Patchy amount of 0 never maps natively. Box Blur stores a fractional radius 1..2000 px (floored like Median) and renders byte-identically to the destructive Box Blur at every radius (the direct path to 12 px, an exact integer sliding window above), growing inside the FEid canvas and alpha-trimming like Gaussian Blur. Radial Blur models Photoshop's Spin method only and replicates the destructive sweep byte for byte inside the FEid canvas about the content center; amount, quality-tier sample mapping, the default-50/50-center rule, and the Zoom preview-lock live in [smart-filters-native.md](smart-filters-native.md). Add Noise stores Photoshop's verbatim FlRs random seed plus the Uniform/Gaussian and Monochromatic flags; the seeded deterministic renderer (see [filters.md](filters.md)) yields Patchy-compatible pixels rather than Photoshop's noise, and the seed has no dialog control. Preview/Cancel restores the exact cached raster; every mutating action is one undo entry. While previewed values (parameters AND blending) equal the stored ones (even on open with Preview checked) the dialog keeps the current raster, which may be Photoshop's own baked preview; re-rendering identical settings must not visibly change the image (`ui_smart_filter_dialogs_with_preview_keep_unchanged_pixels`). Wrapping a filtered Smart Object inside another is blocked until Patchy can transfer its native cache and document-space mask into the child file.
- **Native-integrity safety gates**: Move-tool drags, keyboard nudges, Free Transform, and Warp rebuild a supported filtered Smart Object from its immutable source and refresh FEid; those commits are transactional (a render/cache failure restores placement, pixels, native cache, and history). Whole-document Image Size, Canvas Size, Crop, and Rotate map every parsed placement quad (Trnf plus any stashed nonAffineTransform) through their document-space matrix and mark the block dirty, so placed content follows like Photoshop's; Image Size also re-renders editable embedded AND resolvable linked placements from source instead of keeping the resampled preview (`rerender_smart_object_previews`, inside `resize_document_image`, so the dialog, `doc.resizeImage` and MCP agree): each linked file is read and decoded once per source element (`SmartObjectSourceRenderCache`), and a linked file that is missing or cannot be decoded keeps the resampled preview and puts "Linked file X was not found" / "Could not decode X" on the status bar. They refuse only what cannot follow: a native Smart Filter stack or non-empty FEid/FXid store (that document-space cache and shared mask are preserved blobs) and an unparsed placement (no quad). Seam offset still refuses every Smart Object: a placed preview ROLLS across the canvas edges instead of translating whole. Layer Flip and Fill likewise refuse Smart Object pixels; use Free Transform or rasterize first. Other destructive Image Adjustments, legacy plug-ins, Cut, Layer via Cut, Apply Layer Mask, Stroke Selection, indexed conversion, palette remapping, and palette snapping require rasterization first. Copy, Layer via Copy, ordinary mask editing, and metadata-only palette changes remain non-destructive and available.
- **Bit depth**: smart objects render their contents, and so their Smart Filters, at 8 bits in every document; the preview widens to the document's depth as layer pixels. The FEid cache Patchy authors is 8-bit (`author_filter_effects_record` refuses deeper input). Deep editing rules: [high-bit-depth.md](high-bit-depth.md).
- Opening a PSD with smart objects emits **import notices** (editable / preview-locked / external / dangling counts) per the status-bar-by-default rule (docs/file-formats.md). UI tests through the window path need the repeating dismisser only when `imports/showPsdWarningsAndInfo` is enabled; direct `DocumentIo::read_file` reads see no dialogs.
- **Editing and authoring**: read [smart-object-editing.md](smart-object-editing.md) for child sessions, format guards, linked files, Replace Contents, Convert, Via Copy, and Place.
- **Locked-but-parsed** external, legacy, unsupported-warp, and non-affine layers translate their quads on Move, regenerate patch-in-place, and ride the multi-target Free Transform: a movable smart object with a parsed placement transforms (Trnf maps per corner through the shared delta). An external (linked) placement then re-renders from its file exactly like an embedded one, Warp included (the canvas decodes the file through `set_smart_object_source_image_callback`, which resolves it against the document folder); the other locks keep the resampled pixels because no re-render exists. A linked file that is missing or unreadable keeps the resampled pixels, the transform still commits, and the status bar names the file; Warp refuses to start without it. A differing nonAffineTransform quad is stashed at parse (`kLayerMetadataSmartObjectNonAffineTransform` / `SmartObjectPlacement::non_affine_transform`), maps per corner with Trnf, translates on Move, and the SoLd writer patches it directly; without a stash (fresh Replace/rescale placements) the fallback is the per-corner Trnf delta, exact only for translations. warpNone warp bounds stay the CONTENT rect (0,0,h,w) like PS writes them. An unsupported Smart Filter stack remains pinned because its baked, document-space masked preview and native FEid cache cannot be moved independently. Truly unparseable SoLds import with lock="unparsed" and an EMPTY uuid (badge + paint/transform/move protection; `layer_has_movable_pixels` pins it because no quad can ride a move); the dangling-uuid cleanup skips that state and the blocks re-emit verbatim forever.
- **Layer context menu**: reorganized into submenus (Layer Style / New / Smart Objects / Layer Mask + the Lock submenu). Standing rule: **Edit Layer Styles... stays the FIRST item, always** (`ui_layer_context_menu_keeps_edit_styles_on_top` pins it). Test helpers search submenus recursively (`find_menu_action_by_text`).
- **Photoshop 2026 ground truth** (COM captures): Convert-to-SO writes BOTH PlLd and SoLd; child doc = "<layer name>.psb" ('8BPB', creator '8BIM'), canvas = layer pixel bounds, Trnf = those corners; Place uses filetype 'png ' etc. with creator four spaces and the E2 placement rule (`generalPreferences.placeRasterSmartObject` gates SO creation and may be off on a given install; capture scripts flip it temporarily and restore it); lnk2 elements are version 8 with ~117 undocumented trailing bytes (parse by element length; Patchy writes v7); duplicates share the Idnt uuid, "New Smart Object via Copy" clones the element under a fresh uuid ('placed' is a per-layer instance uuid, always fresh); **no lnk2 element may be unreferenced**: PS 2026 refuses to open a file whose embedded link block holds an element no layer references ("Could not open ... because of a program error"), whether Patchy authored the element (Convert to SO then Rasterize or Delete) or PS did (its own placed PNG with the layer deleted in Patchy), and PS itself drops the element when it saves after rasterizing (its Convert to SO, Rasterize, Save leaves no lnk2 at all). Patchy's store still keeps orphans so Undo can bring the layer back; the writer leaves them out (`psd_document_io.cpp`, the lnk2/lnkD/lnk3 emission): a block with an orphan regenerates from its remaining elements, each keeping its verbatim bytes, an emptied block is not written, fully referenced blocks stay verbatim, and any placed layer of unknown source (unparsed SoLd, or a placed block that never became metadata) disables the pruning. lnkE (linked) blocks follow the same rule: PS 2026 refuses ("program error") a Patchy-written file whose lnkE holds a liFE element no layer references. Pinned by `psd_writer_omits_unreferenced_smart_object_sources` and `ui_smart_object_orphaned_source_is_not_written`.
- **Smart Filter ground truth**: the complete Photoshop COM capture record (descriptor classes and key orders, FEid cache layout, per-filter kernels and formulas, authoring shape, fixture provenance) lives in [smart-filters-native.md](smart-filters-native.md). Consequences here: `filterFXList` stores filters in execution order while the Layers panel displays them reversed; saving Edit Contents or Replace Contents regenerates the shared `Idnt` and every referencing layer's `placed` uuid, while rasterizing one duplicate leaves the surviving instance IDs unchanged.
- **liFE (linked external file) element layout** (pinned from the 10cm-table-tent PS 2023 capture, v7 elements, and the PS 2026 v8 captures below): uuid pascal string, unicode filename, filetype OSType, creator (four NUL bytes in 2023; PS 2026 writes uninitialized bytes, so the field is noise and Patchy keeps NULs), u64 datasize (0), open descriptor flag + `{null; compInfo{compID:-1, originalCompID:-1}}` for raster contents or an EMPTY descriptor named "Open" of class 'Opn ' for an SVG, then a SECOND u32 descVersion 16 + `ExternalFileLink` descriptor (class strID; keys in order: descVersion(str) long = 2, 'Nm  '(char) TEXT filename, fullPath(str) TEXT file:// URI, originalPath(str) TEXT native path, relPath(str) TEXT), then a 16-byte date struct {u32 year, u8 month, u8 day, u8 hour, u8 minute, f64 seconds}: the file's modification time in **UTC, truncated to whole seconds** (the 13:03:05 UTC stamp of a file modified at 22:03:05.698 JST), then u64 file size (PS compares both for staleness), then the versioned tail every element kind shares: v5+ unicode child doc id, v6+ f64 assetModTime, v7+ u8 lock state, and v8's trailing bytes are a u32 16 + `{null; contentID TEXT uuid}` descriptor. `parse_link_element` models all of it best-effort (unmodeled variants degrade to the verbatim skip) and `serialize_external_element` mirrors it (v7) for dirty external sources; clean elements still re-emit byte-identically. `psb_life_trailer_fields_parse_if_available` + `smart_object_external_element_round_trips_if_available` pin both directions; `stamp_smart_object_link` / `smart_object_link_changed_on_disk` (ui/smart_object_render) own the UTC stamp and its comparison (a local-time stamp from an older Patchy still reads as unchanged).
- **Place Linked ground truth** (PS 2026 COM captures, `scripts\dev\smart-objects\ps-capture-linked.ps1`; local `ps2026_linked/` fixtures pinned by `psd_photoshop_linked_captures_match_authored_blocks_if_available`, `psd_photoshop_linked_elements_parse_if_available` and `ui_smart_object_photoshop_linked_capture_resolves_if_available`): a linked placement writes ONLY a 'SoLE' block (no PlLd) carrying the same 'soLD' v4 descriptor as SoLd, the liFE element goes into 'lnkE', and an EMPTY 'lnk2' block sits beside it (an embedded placement writes the mirror: PlLd + SoLd, lnk2, empty lnkE). An SVG placement, linked or embedded, has filetype 'SVG ', Type 1 (vector), Sz = the SVG's own pixel size, Rslt 72, and a 17-key descriptor with NO compInfo; its warp `bounds` are the artwork's unscaled placement rectangle in DOCUMENT space (the E2 rect: physical size centered, fit when larger; 2048 px in a 144 ppi document), which later scales, rotations, duplicates and even a relink to a different-size file leave untouched, while Trnf carries the transform. Raster placements keep Type 2, compInfo and content-rect bounds. `author_placed_layer_sold_payload` reproduces both shapes byte for byte (Type 1 takes the base rect) and `regenerate_placed_layer_payload` never rewrites Type 1 bounds. Paths: fullPath is the undecorated URI `file:///D:/dir/logo ünï 日本.svg` (no percent-encoding, forward slashes; a name holding `#`, `%` or `%20` is stored as typed, so `resolve_smart_object_external_path` tries the text after `file://` as a literal path before any QUrl decode), originalPath the native path, relPath computed against the document's folder at SAVE time ('logo.svg' beside it, '../logo.svg' one folder up), even for a document that had no folder when the file was placed. Every separate placement of one file gets its OWN element and uuid; a duplicated layer shares the element; Update All Modified Content then MERGES every layer linking that file onto ONE fresh element with fresh `placed` ids, so Patchy's shared element on repeated placement is a state Photoshop produces itself. `linkChanged` stays false until Photoshop re-checks the file (it did not notice a rewrite made between two COM calls), and `placedLayerUpdateModified` is refused until it has. Photoshop's stored preview of a linked SVG agrees with Patchy's qsvg render within edge antialiasing (flat and folded logos, gradients in userSpaceOnUse units inside transformed groups included).
- **Replace Contents ground truth** (E5 COM captures, `ps2026_e5_*` local fixtures): PS creates a NEW element with a fresh uuid and repoints EVERY layer that referenced the old uuid (the replaced-away element is removed, unlike rasterize orphans); each layer's quad is rebuilt about its own quad center preserving the content-inch-to-doc-pixel linear map (`L_new = L_old * dpi_old/dpi_new`; same-dpi replaces degrade to pure pixel scaling), Sz/Rslt become the new content's pixel size and dpi, and layer names swap the old source stem for the new one ("A copy" becomes "B copy"). PS additionally rounds the resulting quad corners to whole pixels while its "Snap Vector Tools and Transforms to Pixel Grid" preference is on (`toolsPreferences.transformsSnapToPixels`, the default; off keeps a Free Transform quad at 13.4 but still renders a pure translation crisply at 13, PS 27.9 captures in docs/tools.md); Patchy keeps full doubles here and snaps only numeric Free Transform rects (a sub-pixel placement difference on OUR edit, not a render divergence). Place also writes an empty 'lnkE' block alongside 'lnk2'.
