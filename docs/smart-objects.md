# Smart objects (Photoshop placed layers)

Warp-specific machinery lives in [warp.md](warp.md). This document owns the never-save-over-PSBtest warning; the layer context-menu rule lives in [ui-conventions.md](ui-conventions.md).

A smart object stays a **`LayerKind::Pixel` layer** (the text-layer pattern) whose pixels are Photoshop's rendered preview; identification is the `layer_is_smart_object()` predicate over `patchy.smart_object.*` metadata (core/smart_object.hpp owns the keys and helpers, like adjustment_layer.hpp does).

- **Model**: per-layer placement metadata (source uuid, Trnf quad, size, dpi, lock reason, raster_status, block_dirty) parsed from the 'SoLd' (authoritative; 'SoLE' alias) or legacy 'PlLd' blocks by `src/psd/psd_smart_objects.{hpp,cpp}`; source payloads live in `DocumentMetadata::smart_objects` (a `SmartObjectStore` parsed from the global 'lnk*' blocks, one `SmartObjectSource` per element with **shared_ptr-held bytes so the 40-deep whole-Document undo snapshots share one copy**). Unparseable blocks/elements stay opaque and re-emit verbatim.
- **Native Smart Filter model**: `Layer::smart_filter_stack()` is the per-instance semantic model of SoLd `filterFX`; `src/core/smart_filter.hpp` models stack/entry enable state, native order, blend mode/opacity/colors, settings for the thirteen supported filters (Gaussian Blur, High Pass, Median, Dust & Scratches, Surface Blur, Unsharp Mask, Motion Blur, Plastic Wrap, Mosaic, Emboss, Box Blur, Radial Blur (Spin), Add Noise), and the one shared filter mask separately from the ordinary layer mask. `DocumentMetadata::smart_filter_effects` owns Photoshop's document-global `FEid`/`FXid` render caches, associated by the SoLd `placed` uuid rather than the shared source `Idnt`. Raw record bodies and decoded mask samples are shared across whole-document undo snapshots. A wholly supported stack of those thirteen filters with one unambiguous semantic FEid record is editable; an unsupported entry or cache (including Radial Blur's Zoom method) keeps the whole layer on Photoshop's preserved preview.
- **Editable native rendering**: `src/filters/smart_filter_renderer.{hpp,cpp}` is the deterministic CPU path for supported native Smart Filters. Gaussian Blur embeds the current stack result in the transparent document-space FEid cache canvas, filters premultiplied RGBA with the canvas edge repeated like Photoshop, and alpha-trims the expanded result. High Pass keeps the current result bounds and alpha exactly, repeats that result's nearest RGB edge, and computes `clamp(source - byte-rounded Gaussian + 128)` per channel, including hidden RGB under transparent pixels. Median keeps exact bounds; each RGBA channel independently takes the upper median over a square edge-clamped window (integer radius = floor of the stored value). Before RGB filtering, transparent source pixels borrow straight color from the nearest nonzero-alpha source (squared Euclidean distance, down-then-right tie breaks) so transparent edges do not pull in black; all-transparent inputs keep their hidden RGB. Dust & Scratches reuses that RGB median and extension, keeps alpha and bounds byte-identical, and replaces the whole RGB triplet only when its maximum channel difference from the extended source strictly exceeds the integer threshold. Surface Blur pads by its rounded effective radius, applies an edge-clamped square weighted filter independently to straight RGB (same nearest-visible extension) and alpha, then alpha-trims; sample `v` around center `c` weighs `max(0, 5 * threshold - 2 * abs(v - c))`, quotient rounded to nearest, ties to even. Unsharp Mask preserves bounds and alpha, subtracts a byte-rounded straight-RGB low-pass from the source, scales the signed detail, and removes Threshold from the scaled magnitude before adding it back. Motion Blur embeds in the FEid canvas, applies one user-directed fixed line kernel through premultiplied RGBA, and alpha-trims. An expanding filter (Gaussian/Motion Blur) followed by a bounds-preserving one uses the expanded result's trimmed bounds; the reverse order can still grow across the FEid canvas. Each entry composites over the previous stack result with its opacity and blend mode (Normal at 100% uses Photoshop's replacement path); the document-space shared mask applies once to the completed stack. The renderer runs only while producing a cached layer raster, never from `paintEvent` or the compositor. Any mutation regenerates from the unfiltered source, never by refiltering the previous preview.
- **Smart Filter preservation**: untouched SoLd and FEid/FXid payloads re-emit byte-for-byte. Parsed version-1 cache records expose 8-bit raw or PackBits filter masks while retaining their raw bodies. An unknown entry, malformed cache, unsupported mask compression/depth, missing association, or duplicate `placed` association marks the whole stack unsupported; one opaque FEid/FXid block makes associations and mutations fail closed across the whole store (a hidden duplicate cannot be ruled out). PackBits row lengths are strict; an invalid cache layout stops before optional-mask decompression. Never execute a supported prefix of an unsupported imported stack. Photoshop writes 0-3 zero alignment bytes after each length-prefixed FEid/FXid record, inside the declared block payload; the codec requires zero padding for the native shape, preserves untouched bytes, accepts the unambiguous unpadded multi-record shape of pre-0.20 Patchy, and reproduces four-byte alignment after a rekey. Patchy-authored filters write a canonical Photoshop-shaped `filterFX` descriptor and a version-3 FEid block (full-document PackBits unfiltered RGB/alpha cache plus the shared mask). Same-size edits patch known leaves in place. Mask painting replaces only the optional FEid mask tail, preserving the unfiltered cache prefix, record order, block dialect, declared-length form, and alignment; an unsafe or ambiguous record rejects the edit. Per-filter opacity/blend-mode edits patch SoLd only. Append, duplicate, reorder, and delete rebuild only `filterFXList`, deep-cloning retained native objects so unknown fields, key order, and ID forms survive without shared descriptor aliases. No private `plSF` fallback exists. An FEid cache makes Photoshop eagerly validate the layer's embedded source file and 'lyid' block at open time; the writer therefore emits even-length merged-composite PackBits rows everywhere, normalizes stored embeds whose composite has odd rows, and synthesizes 'lyid' blocks for id-less smart-object layers (docs/ps-compat.md "Smart Filter documents have two extra open-time requirements").
- **Preserve-unless-edited**: untouched layers re-emit their original SoLd/PlLd blobs byte-identically; a move/transform sets `block_dirty` and the writer REGENERATES the blocks patch-in-place via the generic descriptor writer (psd_descriptor.cpp `write_descriptor`, which preserves key order and each id's charID/stringID form; Photoshop writes the 4-char key "warp" as a stringID, so id form is NOT derivable from length, and `DescriptorObject::key_order`/`KeyEntry::long_form` carry it). `psd_descriptor_writer_round_trips_sold` pins read->write byte-identity.
- **Lock classification** (kLayerMetadataSmartObjectLock): unsupported warp/quiltWarp, non-affine quads, unsupported or ambiguous filterFX/FEid data, external ('liFE') sources, PlLd-only ("legacy"), and parse failures are preview-locked: Patchy shows/preserves Photoshop's raster and refuses pixel edits; rasterize always works. Photoshop Blur Gallery's `blurbTransform` (including native Tilt-Shift) and native Liquify stay in this preservation-only class. A fully supported filterFX/FEid pair containing only the thirteen modeled filters clears the provisional filter lock. Empty lock = editable. (Supported warps unlock; see docs/warp.md.)
- **UI semantics**: the smart-object badge on the layer row's details line (`layerSmartObjectBadgeButton`, embedded vs linked icons, `smartObjectLinked` property) is THE click affordance for opening the contents; the sibling `layerFxBadgeButton` opens layer styles. Row double-click opens layer styles for pixel, text, and smart-object rows (deliberate); group rows: nothing, adjustment rows: the adjustment editor, unlocked shape/fill rows: the shape appearance editor. Filter > Convert for Smart Filters converts the active normal pixel layer to an embedded Smart Object; each of the thirteen supported filters (Radial Blur: default center and tiered samples only; Pixel Mosaic maps to Photoshop's Mosaic) then appends an editable native entry instead of changing source pixels, while staying destructive on ordinary pixel layers. Lens Blur, Iris Blur, and Tilt-Shift Blur are destructive and gallery-capable with no native mapping; Liquify refuses Smart Objects, rasterize first (see docs/liquify.md). A direct action or mixed gallery recipe on a Smart Object takes the all-or-nothing rasterization path, never a partial or private descriptor: both offer the same "Rasterize Smart Object?" prompt (`filterRasterizeMessageBox` / `filterGalleryRasterizeMessageBox`; accept = rasterize + apply destructively as one undo step, cancel = layer untouched), and the Filter Gallery shows the outcome inline before Apply ("SF" badges, tooltips, `filterGalleryOutcomeLabel`, per-entry warnings; see docs/filters.md "Filter Gallery"). Adjustment-only filters (Image > Adjustments) keep the hard refusal status message (native-integrity gates below); `ui_smart_filter_native_integrity_guards_reject_destructive_actions` pins the no-dialog behavior. The routing whitelist is single-sourced: `native_smart_filter_kind_for` / `native_smart_filter_kind_supported` in `src/filters/smart_filter_recipe_mapping.{hpp,cpp}` are the only decision points; never duplicate the ID list. Double-clicking a Smart Filter entry row opens that filter's settings dialog, whose Blending section (blend mode + opacity) also opens via the row's Edit pencil (`patchyFilterDialog`); the layer-styles double-click applies only outside entry rows. Shared-mask thumbnail: click paints, Ctrl-click loads as selection, Shift-click enables/disables, Alt-click shows the grayscale mask-only view; overlay and mask-only commands follow it while it is the active edit target. Unsupported imported stacks show disabled preservation controls. "Convert to Normal Layer (Rasterize)" (`layerSmartObjectToNormalAction`, both Smart Objects menus) just calls the Rasterize path. Painting source pixels raises `paintSmartObjectMessageBox` (Edit Contents / Rasterize / Cancel; press consumed; Edit Contents omitted when contents can't open; automation keeps the status refusal); destructive filters/gallery/adjustments on TEXT and SHAPE layers raise the analogous `rasterizeOrConvertMessageBox`, whose Convert To Smart Object choice (offered only when the smart-filter follow-on can succeed) funnels into `convert_layers_to_smart_object` and then this same routing (see docs/filters.md "Text and shape layer gate"); Delete removes the object (like text); merge targets and rasterize/rasterize-style strip the smart-object data (`strip_layer_smart_object_data`); Export Smart Object Contents... (layer context menu) writes the embedded bytes verbatim. Duplicate, New Smart Object via Copy, and cross-document paste give each clone a fresh `placed` uuid and clone/adopt its FEid/FXid record without copying the large backing bytes; a clone's FEid record must sit immediately after its source record, and its preserved `lyid` block must be rekeyed to a fresh document-wide value (Photoshop 27.8 rejects an appended cache record and aliases layers sharing `lyid`). Rasterize/delete drop the instance cache once no layer references it; undo restores layer and cache together. A missing or ambiguous record blocks the clone.
- **Current Smart Filter editor limits**: Patchy authors and edits ordered stacks of the thirteen supported filters. A new stack uses the exact current selection alpha as Photoshop's shared filter mask (an explicit all-white mask without a selection); later entries retain it. Editable masks are full-document 8-bit grayscale targets: Brush, Eraser, Fill/Clear, Gradient, Line, Rectangle/Ellipse, and Invert edit the temporary mask buffer, unsupported tools are blocked (never touching source pixels), the model and native cache stay unchanged during a gesture, and each completed gesture commits one undo step and regenerates the filtered preview once. Whole-percent opacity (Photoshop normalizes fractional values) and blend mode live in the settings dialog's Blending section with cancellable live preview; Apply is one undo step, and a blending-only accept patches SoLd only. Editable native masks require documents of 64 megapixels or less; larger imported records stay preview-locked. A true `filterMaskLinked` flag is preserved but preview-locked (Photoshop 27.8 ignored attempts to set it; no true-state fixture); linked-mask editing, Density, and Feather are not exposed. Gaussian Blur and High Pass radii are fractional 0.1 to 1000 px; new Gaussian Blur edits use the destructive dialog's practical 0.1 through 12 px range, and an imported value above 12 stays visible and is preserved when accepted unchanged. High Pass, Median, Dust & Scratches, Surface Blur, Unsharp Mask, Motion Blur, and Plastic Wrap use the typed and practical ranges (and rendering formulas) of their destructive catalog entries in [filters.md](filters.md). Mosaic (integer Cell Size 2..200 px, practical slider to 64) keeps bounds and matches the destructive Pixel Mosaic's alpha-weighted block averages exactly; like Plastic Wrap the descriptor round-trips while the pixels are Patchy's own compatible rendering. Emboss (typed Angle -360..360 degrees, Height 1..100 px, Amount 1..500 percent; practical -180..180, 1..24, to 300) keeps bounds and alpha and matches the destructive Emboss's bilinear-luminance gray relief exactly; the destructive catalog shares these typed ranges with its historical practical sliders. Photoshop's Emboss Amount minimum is 1, so a Patchy amount of 0 never maps natively. Box Blur stores a fractional radius 1..2000 px (floored like Median; practical 1..12): radii to 12 render byte-identically to the destructive Box Blur (which keeps its historical 1..12 integer range); larger radii use an exact integer sliding-window path with the same edge-clamped sampling, growing inside the FEid canvas and alpha-trimming like Gaussian Blur. Radial Blur models Photoshop's Spin method only and replicates the destructive sweep byte for byte inside the FEid canvas about the content center; amount, quality-tier sample mapping, the default-50/50-center rule, and the Zoom preview-lock live in [filters.md](filters.md). Add Noise stores Photoshop's verbatim FlRs random seed plus the Uniform/Gaussian and Monochromatic flags; the seeded deterministic renderer (see [filters.md](filters.md)) yields Patchy-compatible pixels rather than Photoshop's noise, and the seed has no dialog control. Preview/Cancel restores the exact cached raster; every mutating action is one undo entry. While previewed values (parameters AND blending) equal the stored ones (even on open with Preview checked) the dialog keeps the current raster, which may be Photoshop's own baked preview; re-rendering identical settings must not visibly change the image (`ui_smart_filter_dialogs_with_preview_keep_unchanged_pixels`). Wrapping a filtered Smart Object inside another is blocked until Patchy can transfer its native cache and document-space mask into the child file.
- **Native-integrity safety gates**: Move-tool drags, keyboard nudges, Free Transform, and Warp rebuild a supported filtered Smart Object from its immutable source and refresh FEid; those commits are transactional (a render/cache failure restores placement, pixels, native cache, and history). Whole-document Image Size, Canvas Size, Crop, and Rotate refuse documents containing any Smart Object (the native placement and document-space mask transforms are not calibrated yet); Layer Flip and Fill likewise refuse Smart Object pixels; use Free Transform or rasterize first. The Filter Gallery maps fully supported recipes to native entries (never partial mappings) and offers to rasterize before applying any mixed recipe. Other destructive Image Adjustments, legacy plug-ins, Cut, Layer via Cut, Apply Layer Mask, Stroke Selection, indexed conversion, palette remapping, and palette snapping require rasterization first. Copy, Layer via Copy, ordinary mask editing, and metadata-only palette changes remain non-destructive and available.- Opening a PSD with smart objects emits **import notices** (editable / preview-locked / external / dangling counts) per the status-bar-by-default rule (docs/file-formats.md). UI tests through the window path need the repeating dismisser only when `imports/showPsdWarningsAndInfo` is enabled; direct `DocumentIo::read_file` reads see no dialogs.
- **Edit Contents**: an editable embedded smart object's badge (or Edit Smart Object Contents in the Smart Objects menus) opens the source as a child tab titled "file.ext (embedded in Parent.psd)": a full `DocumentSession` whose `smart_object_link{parent_session_id, source_uuid}` carries session IDS (never pointers: sessions_ erases on close; `session_id` is the stable identity). Save (Ctrl+S) on the child routes `save_document()` to `commit_smart_object_child_session`: the child serializes in the source's own format (PSB for '8BPB' via `WriteOptions::large_document`, PSD for '8BPS', Qt image formats re-encode a flatten), the element gets fresh shared_ptr bytes (dirty), EVERY layer sharing the uuid re-renders (`smart_object_render.{hpp,cpp}`: quadToQuad + resample_transformed_rgba8, raster_status=patchy_raster), the parent takes ONE undo snapshot ("Edit Smart Object Contents"), and the child marks clean. Size-changing commits rescale quads per the E5 rule below; same-size commits leave SoLd untouched (only the lnk element regenerates). Closing a parent with open child tabs prompts (closeSmartObjectChildrenMessageBox) and resolves the children first; a child whose parent is gone detaches and falls back to Save As. Nesting works by construction (each child is a full session; PSD children keep their own store through DocumentIo). PSD/PSB sources render their preview from the child's own flattened composite (prefer_flat_composite), so untouched children look exactly like Photoshop's stored pixels.
- **Preview decode falls back to the layered render when the stored composite is fully opaque but the layers are not** (`decode_smart_object_source_image`): a 3-channel or opaque composite cannot represent canvas transparency. Older Patchy children (black-matted composites) and Photoshop saves with Maximize Compatibility off (flat white-matted composites) render through the layered fallback; genuinely opaque children keep the PS-exact stored composite. Regression pins: `ui_smart_object_edit_commit_keeps_canvas_transparency`, `ui_smart_object_legacy_black_composite_decodes_transparent` (`test-fixtures/psd/patchy-legacy-black-composite.psb`), and `ui_smart_object_psbtest_repro_decodes_transparent_if_available` (local PSBtest repro). Parents with already-baked-black previews heal on the next commit/transform/update re-render.
- **Edit-format guard**: PSD/PSB (DocumentIo both ways) and png/jpg/jpeg/tif/tiff/bmp/webp (Qt both ways) are editable; GIF and registry-only formats (TGA/PCX/...) decode for preview but refuse Edit/Replace with an explanatory status message (`classify_smart_object_contents`); undecodable/external sources keep Photoshop's preview forever. Content density comes from `smart_object_source_dpi` (PSD resolution or the image's embedded density, 72 fallback); Qt-authored pngs carry a pHYs chunk, so replacing with one honors its dpi like Photoshop does.
- **Replace Contents** follows the E5 semantics exactly: fresh uuid + element, every referencing layer repoints and rebuilds about its own quad center, old element removed, layer names swap the source stem. Accepted replace formats: psd/psb/png/jpg/jpeg/tif/tiff/bmp (webp only round-trips existing sources, its PS filetype OSType is unpinned).
- **Linked-file workflows**: external ('liFE') smart objects are fully workable. Edit Contents resolves the path (relPath against the parent folder, then a bare-filename sibling, then originalPath, then the fullPath URI: `resolve_smart_object_external_path`) and opens the REAL file as a disk-backed session with `SmartObjectLink::external`; its Save writes the file FIRST, then `refresh_external_smart_object_after_save` re-reads the bytes, stamps the liFE date/size, marks the element dirty, and re-renders every uuid-sharing layer as ONE parent undo step. Update Smart Object Content re-reads on demand; document open compares stored date/size and prepends "changed on disk"/"not found" notices (actionable notices go FIRST for the status bar). Relink to File... follows the E14-captured semantics: like Replace Contents but staying external (FRESH element uuid in the lnkE block, referencing layers repoint and rescale about their own centers per E5, layer names swap the source stem, old element pruned). Embed Linked follows E13: ANOTHER fresh uuid, the element moves to lnk2 as liFD, the emptied lnkE stays behind, locks clear, and the per-layer SoLE block key flips to SoLd (block_dirty repoints the Idnt on save). COM note: linked placement needs `putBoolean(charIDToTypeID("Lnkd"), true)` on the 'Plc ' descriptor. No QFileSystemWatcher by design: open-time check + explicit Update + self-save refresh cover the workflows. The shared re-render walk is `refresh_smart_object_layers_for_source`.
- **E4 acceptance**: Photoshop 2026 opened, color-sampled bit-exactly, edited, and resaved the `ui_smart_object_*.psd` artifacts cleanly (no "disk error (-1)"). Re-run the e4_acceptance COM script over those artifacts after any writer-side smart-object change.
- **Authoring**: Convert to Smart Object (layer menu + context submenu) moves the selected layer trees into a child document (canvas = union of render bounds, PSB, '8BPB', named "<top layer>.psb"; nested sources adopt into the child store); the topmost selected layer's slot/id/name become the new smart object, and the preview composites pixel-identically for Normal/100% layers. Place Embedded (File menu) uses the E2 rule dpi-aware (physical size 1:1 centered, fit-to-canvas when larger). Both write a from-scratch SoLd via `psd::author_placed_layer_sold_payload`, which mirrors PS 2026's exact key order/id forms (E1 captures; `smart_object_authored_sold_matches_photoshop_shape` pins the shape) and is pushed into the layer's unknown blocks at author time, so the normal preserve/patch-in-place machinery owns it from then on. Patchy writes NO legacy PlLd companion (PS writes both; it accepts SoLd-only files, E4-gated). New Smart Object via Copy clones the element under a fresh uuid (E8 semantics); free transform composes the delta into the quad and re-renders through `smart_object_transform_render_callback_` (text-layer pattern), with the resampled pixels as fallback.
- **Locked-but-parsed** external, legacy, unsupported-warp, and non-affine layers translate their quads on Move, regenerate patch-in-place, and ride the multi-target Free Transform: a movable smart object with a parsed placement transforms (Trnf maps per corner through the shared delta; resampled pixels stand in for re-render). A differing nonAffineTransform quad is stashed at parse (`kLayerMetadataSmartObjectNonAffineTransform` / `SmartObjectPlacement::non_affine_transform`), maps per corner with Trnf, translates on Move, and the SoLd writer patches it directly; without a stash (fresh Replace/rescale placements) the fallback is the per-corner Trnf delta, exact only for translations. warpNone warp bounds stay the CONTENT rect (0,0,h,w) like PS writes them. An unsupported Smart Filter stack remains pinned because its baked, document-space masked preview and native FEid cache cannot be moved independently. Truly unparseable SoLds import with lock="unparsed" and an EMPTY uuid (badge + paint/transform/move protection; `layer_has_movable_pixels` pins it because no quad can ride a move); the dangling-uuid cleanup skips that state and the blocks re-emit verbatim forever.
- **Layer context menu**: reorganized into submenus (Layer Style / New / Smart Objects / Layer Mask + the Lock submenu). Seth's standing rule: **Edit Layer Styles... stays the FIRST item, always** (`ui_layer_context_menu_keeps_edit_styles_on_top` pins it). Test helpers search submenus recursively (`find_menu_action_by_text`).

- **Smart Filter ground truth**: the complete Photoshop COM capture record (descriptor classes and key orders, FEid cache layout, per-filter kernels and formulas, authoring shape, fixture provenance) lives in [smart-filters-native.md](smart-filters-native.md). Consequences here: `filterFXList` stores filters in execution order while the Layers panel displays them reversed; saving Edit Contents or Replace Contents regenerates the shared `Idnt` and every referencing layer's `placed` uuid, while rasterizing one duplicate leaves the surviving instance IDs unchanged.
- **liFE (linked external file) element layout** (pinned from the 10cm-table-tent PS 2023 capture, v7 elements): uuid pascal string, unicode filename, filetype OSType, creator = four NUL bytes (not "8BIM"/spaces), u64 datasize (0), open descriptor flag + `{null; compInfo{compID:-1, originalCompID:-1}}`, then a SECOND u32 descVersion 16 + `ExternalFileLink` descriptor (class strID; keys in order: descVersion(str) long = 2, 'Nm  '(char) TEXT filename, fullPath(str) TEXT file:// URI, originalPath(str) TEXT native path, relPath(str) TEXT), then a 16-byte date struct {u32 year, u8 month, u8 day, u8 hour, u8 minute, f64 seconds} (the mod time PS compares for staleness), u64 file size, then the versioned tail every element kind shares: v5+ unicode child doc id, v6+ f64 assetModTime, v7+ u8 lock state. `parse_link_element` models all of it best-effort (unmodeled variants degrade to the verbatim skip) and `serialize_external_element` mirrors it for dirty external sources; clean elements still re-emit byte-identically. `psb_life_trailer_fields_parse_if_available` + `smart_object_external_element_round_trips_if_available` pin both directions.
- **Replace Contents ground truth** (E5 COM captures, `ps2026_e5_*` local fixtures): PS creates a NEW element with a fresh uuid and repoints EVERY layer that referenced the old uuid (the replaced-away element is removed, unlike rasterize orphans); each layer's quad is rebuilt about its own quad center preserving the content-inch-to-doc-pixel linear map (`L_new = L_old * dpi_old/dpi_new`; same-dpi replaces degrade to pure pixel scaling), Sz/Rslt become the new content's pixel size and dpi, and layer names swap the old source stem for the new one ("A copy" becomes "B copy"). PS additionally rounds the resulting quad corners to whole pixels; Patchy keeps full doubles (a sub-pixel placement difference on OUR edit, not a render divergence). Place also writes an empty 'lnkE' block alongside 'lnk2'.
