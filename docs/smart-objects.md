# Smart objects (Photoshop placed layers)

Warp-specific machinery lives in [warp.md](warp.md). This document owns the never-save-over-PSBtest warning; the layer context-menu rule lives in [ui-conventions.md](ui-conventions.md).

A smart object stays a **`LayerKind::Pixel` layer** (the text-layer pattern) whose pixels are Photoshop's rendered preview; identification is the `layer_is_smart_object()` predicate over `patchy.smart_object.*` metadata (core/smart_object.hpp owns the keys and helpers, like adjustment_layer.hpp does).

- **Model**: per-layer placement metadata (source uuid, Trnf quad, size, dpi, lock reason, raster_status, block_dirty) parsed from the 'SoLd' (authoritative; 'SoLE' alias) or legacy 'PlLd' blocks by `src/psd/psd_smart_objects.{hpp,cpp}`; source payloads live in `DocumentMetadata::smart_objects` (a `SmartObjectStore` parsed from the global 'lnk*' blocks, one `SmartObjectSource` per element with **shared_ptr-held bytes so whole-Document undo snapshots share one copy**). Unparseable blocks/elements stay opaque and re-emit verbatim.
- **Native Smart Filter model**: `Layer::smart_filter_stack()` is the per-instance semantic model of SoLd `filterFX`; `src/core/smart_filter.hpp` models stack/entry enable state, native order, blend mode/opacity/colors, settings for the modeled filters (listed in [smart-filters-native.md](smart-filters-native.md), which links each family's record), and the one shared filter mask separately from the ordinary layer mask. `DocumentMetadata::smart_filter_effects` owns Photoshop's document-global `FEid`/`FXid` render caches, associated by the SoLd `placed` uuid rather than the shared source `Idnt`. Raw record bodies and decoded mask samples are shared across whole-document undo snapshots. A wholly supported stack of those modeled filters with one unambiguous semantic FEid record is editable; an unsupported cache, or an unsupported entry that runs, keeps the whole layer on Photoshop's preserved preview. `smart_filter_stack_support` (plus `native_shape_supported`: root, entries' `enab`, mask, cache) classifies; hidden entries never run, and only `enab` of an unmodeled entry is written.
- **Editable native rendering**: `src/filters/smart_filter_renderer.{hpp,cpp}` is the deterministic CPU path for supported native Smart Filters; the kernels, edge, transparency and trimming rules are in [smart-filters-native.md](smart-filters-native.md) "Render semantics". An expanding filter (Gaussian/Motion Blur) followed by a bounds-preserving one uses the expanded result's trimmed bounds; the reverse order can still grow across the FEid canvas. Each entry composites over the previous stack result with its opacity and blend mode (Normal at 100% uses Photoshop's replacement path); the document-space shared mask applies once to the completed stack. The renderer runs only while producing a cached layer raster, never from `paintEvent` or the compositor. Any mutation regenerates from the unfiltered source, never by refiltering the previous preview.
- **Smart Filter preservation**: untouched SoLd and FEid/FXid payloads re-emit byte-for-byte. Parsed version-1 cache records expose 8-bit raw, PackBits or zip filter masks while retaining their raw bodies. An unknown entry, malformed cache, unsupported mask compression/depth, missing association, or duplicate `placed` association marks the whole stack unsupported; one opaque FEid/FXid block makes associations and mutations fail closed across the whole store (a hidden duplicate cannot be ruled out). PackBits row lengths are strict; an invalid cache layout stops before optional-mask decompression. Never execute a supported prefix of an unsupported imported stack. Photoshop writes 0-3 zero alignment bytes after each length-prefixed FEid/FXid record, inside the declared block payload; the codec requires zero padding for the native shape, preserves untouched bytes, accepts the unambiguous unpadded multi-record shape of pre-0.20 Patchy, and reproduces four-byte alignment after a rekey. Patchy-authored filters write a canonical Photoshop-shaped `filterFX` descriptor and a version-3 FEid block (PackBits unfiltered RGB/alpha cache over the filter canvas plus the shared mask). Same-size edits patch known leaves in place. Mask painting replaces only the optional FEid mask tail, preserving the unfiltered cache prefix, record order, block dialect, declared-length form, and alignment; an unsafe or ambiguous record rejects the edit. Per-filter opacity/blend-mode edits patch SoLd only. Append, duplicate, reorder, and delete rebuild only `filterFXList`, deep-cloning retained native objects so unknown fields, key order, and ID forms survive without shared descriptor aliases. No private `plSF` fallback exists. An FEid cache makes Photoshop eagerly validate the layer's embedded source file and 'lyid' block at open time; the writer therefore emits even-length merged-composite PackBits rows everywhere, normalizes stored embeds whose composite has odd rows, and synthesizes 'lyid' blocks for id-less smart-object layers (docs/ps-compat.md "Smart Filter documents, two extra open-time requirements").
- **Preserve-unless-edited**: untouched layers re-emit their original SoLd/PlLd blobs byte-identically; a move/transform sets `block_dirty` and the writer REGENERATES the blocks patch-in-place via the generic descriptor writer (psd_descriptor.cpp `write_descriptor`, which preserves key order and each id's charID/stringID form; Photoshop writes the 4-char key "warp" as a stringID, so id form is NOT derivable from length, and `DescriptorObject::key_order`/`KeyEntry::long_form` carry it). `psd_descriptor_writer_round_trips_sold` pins read->write byte-identity.
- **Lock classification** (kLayerMetadataSmartObjectLock): unsupported warp/quiltWarp, non-affine quads, unsupported or ambiguous filterFX/FEid data, external ('liFE') sources, PlLd-only ("legacy"), and parse failures are preview-locked: Patchy shows/preserves Photoshop's raster and refuses pixel edits; rasterize always works. Photoshop Blur Gallery's `blurbTransform` (including native Tilt-Shift) and native Liquify stay in this preservation-only class. A fully supported filterFX/FEid pair containing only the modeled filters clears the provisional filter lock. Empty lock = editable. (Supported warps unlock; see docs/warp.md.)
- **UI semantics**: the smart-object badge on the layer row's details line (`layerSmartObjectBadgeButton`, embedded vs linked icons, `smartObjectLinked` property) is THE click affordance for opening the contents; the sibling `layerFxBadgeButton` opens layer styles. Row double-click opens layer styles for pixel, text, and smart-object rows (deliberate); group rows: nothing, adjustment rows: the adjustment editor, unlocked shape/fill rows: the shape appearance editor. Filter > Convert for Smart Filters is the same conversion as Layer > Smart Objects > Convert to Smart Object, disabled unless the active layer is a normal 8-bit pixel layer; each supported filter with a Filter-menu command (Radial Blur: default center and tiered samples only; Pixel Mosaic maps to Photoshop's Mosaic) then appends an editable native entry instead of changing source pixels, while staying destructive on ordinary pixel layers. Lens Blur, Iris Blur, and Tilt-Shift Blur are destructive and gallery-capable with no native mapping; Liquify refuses Smart Objects, rasterize first (see docs/liquify.md). A direct action or mixed gallery recipe on a Smart Object takes the all-or-nothing rasterization path, never a partial or private descriptor: both offer the same "Rasterize Smart Object?" prompt (`filterRasterizeMessageBox` / `filterGalleryRasterizeMessageBox`; accept = rasterize + apply destructively as one undo step, cancel = layer untouched), and the Filter Gallery shows the outcome inline before Apply ("SF" badges, tooltips, `filterGalleryOutcomeLabel`, per-entry warnings; see docs/filters.md "Filter Gallery"). Adjustment-only filters (Image > Adjustments) keep the hard refusal status message (native-integrity gates below); `ui_smart_filter_native_integrity_guards_reject_destructive_actions` pins the no-dialog behavior. The routing whitelist is single-sourced: `native_smart_filter_kind_for` / `native_smart_filter_kind_supported` in `src/filters/smart_filter_recipe_mapping.{hpp,cpp}` are the only decision points; never duplicate the ID list. Double-clicking a Smart Filter entry row opens that filter's settings dialog, whose Blending section (blend mode + opacity) also opens via the row's Edit pencil (`patchyFilterDialog`); the layer-styles double-click applies only outside entry rows. Shared-mask thumbnail: click paints, Ctrl-click loads as selection, Shift-click enables/disables, Alt-click shows the grayscale mask-only view; overlay and mask-only commands follow it while it is the active edit target. A stack running a filter Patchy does not model (issue 243) can hide or delete that filter, hide the stack, or Delete All Smart Filters (header menu `layerSmartFiltersMoreButton`, also Hide/Show All; own-click row buttons: `layer_row_button_owns_clicks`) whenever Patchy renders what then runs: the commit renders from the source, lifts the "filters" lock, one undo step. Changes that would run it stay disabled with `smart_filter_unmodeled_*_message` tooltips; an unsupported shape disables everything. "Convert to Normal Layer (Rasterize)" (`layerSmartObjectToNormalAction`, both Smart Objects menus) just calls the Rasterize path. Painting source pixels raises `paintSmartObjectMessageBox` (Edit Contents / Rasterize / Cancel; press consumed; Edit Contents omitted when contents can't open; automation keeps the status refusal); destructive filters/gallery/adjustments on TEXT and SHAPE layers raise the analogous `rasterizeOrConvertMessageBox`, whose Convert To Smart Object choice (offered only when the smart-filter follow-on can succeed) funnels into `convert_layers_to_smart_object` and then this same routing (see docs/filters.md "Text and shape layer gate"); Delete removes the object (like text); merge targets and rasterize/rasterize-style strip the smart-object data (`strip_layer_smart_object_data`); Export Smart Object Contents... (layer context menu) writes the embedded bytes verbatim. Duplicate, New Smart Object via Copy, and cross-document paste give each clone a fresh `placed` uuid and clone/adopt its FEid/FXid record without copying the large backing bytes; a clone's FEid record must sit immediately after its source record, and its preserved `lyid` block must be rekeyed to a fresh document-wide value (Photoshop 27.8 rejects an appended cache record and aliases layers sharing `lyid`). Rasterize/delete drop the instance cache once no layer references it; undo restores layer and cache together. A missing or ambiguous record blocks the clone.
- **Current Smart Filter editor limits**: Patchy authors and edits ordered stacks of the supported filters and edits imported table-described ones (no menu entry adds those). A new stack uses the exact current selection alpha as Photoshop's shared filter mask (an explicit all-white mask without a selection); later entries retain it. Editable masks are full-document 8-bit grayscale targets: Brush, Eraser, Fill/Clear, Gradient, Line, Rectangle/Ellipse, and Invert edit the temporary mask buffer, unsupported tools are blocked (never touching source pixels), the model and native cache stay unchanged during a gesture, and each completed gesture commits one undo step and regenerates the filtered preview once. Whole-percent opacity (Photoshop normalizes fractional values) and blend mode live in the settings dialog's Blending section with cancellable live preview; Apply is one undo step, and a blending-only accept patches SoLd only. Editable native masks require documents of 64 megapixels or less; larger imported records stay preview-locked. A true `filterMaskLinked` flag is preserved but preview-locked (Photoshop 27.8 ignored attempts to set it; no true-state fixture); linked-mask editing, Density, and Feather are not exposed. The settings dialogs (`editable_smart_filter_dialog_spec`) use the typed and practical ranges, and the renders the formulas, of the destructive catalog entries in [filters.md](filters.md) unless noted; Gaussian Blur and High Pass radii are fractional 0.1 to 1000 px. Mosaic (integer Cell Size 2..200 px, slider to 64) keeps bounds and matches the destructive Pixel Mosaic's alpha-weighted block averages exactly; like Plastic Wrap the descriptor round-trips while the pixels are Patchy's own compatible rendering. Emboss (Angle -360..360 degrees, Height 1..100 px, Amount 1..500 percent; sliders -180..180, 1..24, 1..300) keeps bounds and alpha and matches the destructive Emboss's bilinear-luminance gray relief exactly. Photoshop's Emboss Amount minimum is 1, so a Patchy amount of 0 never maps natively. Box Blur stores a fractional radius 1..2000 px (floored like Median) and renders byte-identically to the destructive Box Blur at every radius (the direct path to 12 px, an exact integer sliding window above), growing inside the FEid canvas and alpha-trimming like Gaussian Blur. Radial Blur models Photoshop's Spin method only and replicates the destructive sweep byte for byte inside the FEid canvas about the content center; amount, quality-tier sample mapping, the default-50/50-center rule, and the native Zoom method live in [smart-filters-native.md](smart-filters-native.md). Add Noise stores Photoshop's verbatim FlRs random seed plus the Uniform/Gaussian and Monochromatic flags; the seeded deterministic renderer (see [filters.md](filters.md)) yields Patchy-compatible pixels rather than Photoshop's noise, and the seed has no dialog control. Preview/Cancel restores the exact cached raster; every mutating action is one undo entry. While previewed values (parameters AND blending) equal the stored ones (even on open with Preview checked) the dialog keeps the current raster, which may be Photoshop's own baked preview; re-rendering identical settings must not visibly change the image (`ui_smart_filter_dialogs_with_preview_keep_unchanged_pixels`). Wrapping a filtered Smart Object inside another is blocked until Patchy can transfer its native cache and document-space mask into the child file.
- **Native-integrity safety gates**: Move-tool drags, keyboard nudges, Free Transform, and Warp rebuild a supported filtered Smart Object from its immutable source and refresh FEid; those commits are transactional (a render/cache failure restores placement, pixels, native cache, and history). Whole-document Image Size, Canvas Size, Crop, and Rotate map every parsed placement quad (Trnf plus any stashed nonAffineTransform) through their document-space matrix and mark the block dirty, so placed content follows like Photoshop's; Image Size also re-renders editable embedded AND resolvable linked placements from source instead of keeping the resampled preview (`rerender_smart_object_previews`, inside `resize_document_image`, so the dialog, `doc.resizeImage` and MCP agree): each linked file is read and decoded once per source element (`SmartObjectSourceRenderCache`), and a linked file that is missing or cannot be decoded keeps the resampled preview and puts "Linked file X was not found" / "Could not decode X" on the status bar. They refuse only what cannot follow: a native Smart Filter stack or non-empty FEid/FXid store (that document-space cache and shared mask are preserved blobs) and an unparsed placement (no quad). Seam offset still refuses every Smart Object: a placed preview ROLLS across the canvas edges instead of translating whole. Layer Flip and Fill likewise refuse Smart Object pixels; use Free Transform or rasterize first. Other destructive Image Adjustments, legacy plug-ins, Cut, Layer via Cut, Apply Layer Mask, Stroke Selection, indexed conversion, palette remapping, and palette snapping require rasterization first. Copy, Layer via Copy, ordinary mask editing, and metadata-only palette changes remain non-destructive and available.
- **Bit depth**: smart objects render their contents, and so their Smart Filters, at 8 bits in every document; the preview widens to the document's depth as layer pixels. The FEid cache Patchy authors is 8-bit (`author_filter_effects_record` refuses deeper input). Deep editing rules: [high-bit-depth.md](high-bit-depth.md).
- **Grayscale parent previews**: a preserved 8/16-bit grayscale PSD can embed RGB contents. `smart_object_image_for_document` converts the decoded source from sRGB through the parent's gray ICC profile and back to display RGB before resampling or Smart Filters, preserving alpha and the original embedded bytes. An absent/unusable profile uses neutral 30/59/11 luminance. Refresh, Edit/Replace/Relink Contents, Place, Image Size and the hosted Warp source follow this path; the operation's source cache belongs to one parent document. This does not implement native grayscale blend math or CMYK Smart Object gamut conversion. Self-authored Photoshop captures under `test-fixtures/psd/smart-object-gray/` pin Gray Gamma 2.2 and Dot Gain 20% with opaque, half-alpha and transparent colors; `grayscale_smart_object_*` covers both rendering entry points and 8/16-bit parents.
- Opening a PSD with smart objects emits **import notices** (editable / preview-locked / external / dangling counts) per the status-bar-by-default rule (docs/file-formats.md); a linked file that cannot be found also raises the Missing Linked Files dialog ([smart-object-editing.md](smart-object-editing.md), #257). UI tests through the window path need the repeating dismisser only when `imports/showPsdWarningsAndInfo` is enabled; direct `DocumentIo::read_file` reads see no dialogs.
- **Editing and authoring**: read [smart-object-editing.md](smart-object-editing.md) for child sessions, format guards, linked files, Replace Contents, Convert, Via Copy, and Place.
- **Perspective placements** (nonAffineTransform differing from Trnf) are editable, no lock: they render onto that quad, and transforms map it by Photoshop's rule ([free-transform.md](free-transform.md)).
- **Locked-but-parsed** external, legacy, and unsupported-warp layers translate their quads on Move, regenerate patch-in-place, and ride the multi-target Free Transform: a movable smart object with a parsed placement transforms (Trnf maps per corner). An external (linked) placement then re-renders from its file like an embedded one, Warp included (`set_smart_object_source_image_callback` resolves it against the document folder); the other locks keep the resampled pixels because no re-render exists. A missing or unreadable linked file keeps the resampled pixels, the transform commits, and the status bar names the file; Warp refuses without it. A differing nonAffineTransform quad is stashed at parse (`SmartObjectPlacement::non_affine_transform`), translates on Move, and the SoLd writer patches it directly; without a stash (fresh Replace/rescale placements) the fallback is the per-corner Trnf delta, exact only for translations. warpNone warp bounds stay the CONTENT rect (0,0,h,w) like PS writes them. An unsupported Smart Filter stack stays pinned: its baked document-space masked preview and native FEid cache cannot move independently. Truly unparseable SoLds import with lock="unparsed" and an EMPTY uuid (badge + paint/transform/move protection; `layer_has_movable_pixels` pins it because no quad can ride a move); the dangling-uuid cleanup skips that state and the blocks re-emit verbatim forever.
- **Ground truth and fixtures**: the Photoshop COM capture records and the committed fixtures are in [smart-objects-ground-truth.md](smart-objects-ground-truth.md).
- Coverage: `psd_smart_object_*`, `psb_*`, `psd_descriptor_writer_*`, `smart_object_rescaled_placement_*`, `smart_object_store_*`, and `smart_filter_*` in tests/core/; `ui_smart_object_*` in tests/ui/smart_object_tests.cpp plus `ui_smart_filter_*` in tests/ui/smart_filter_tests_flows.cpp, _guards.cpp, and _kinds.cpp.
