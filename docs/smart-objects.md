# Smart objects (Photoshop placed layers)

Deep reference for smart-object work: model, PSD I/O, edit/replace contents, linked files, authoring, and the Photoshop 2026 ground-truth captures. Warp-specific machinery lives in [warp.md](warp.md). This document owns the never-save-over-PSBtest warning; the layer context-menu rule lives in [ui-conventions.md](ui-conventions.md).

A smart object stays a **`LayerKind::Pixel` layer** (the text-layer pattern) whose pixels are Photoshop's rendered preview; identification is the `layer_is_smart_object()` predicate over `patchy.smart_object.*` metadata (core/smart_object.hpp owns the keys and helpers, like adjustment_layer.hpp does).

- **Model**: per-layer placement metadata (source uuid, Trnf quad, size, dpi, lock reason, raster_status, block_dirty) parsed from the 'SoLd' (authoritative; 'SoLE' alias) or legacy 'PlLd' blocks by `src/psd/psd_smart_objects.{hpp,cpp}`; the source payloads live in `DocumentMetadata::smart_objects` (a `SmartObjectStore` parsed from the global 'lnk*' blocks, one `SmartObjectSource` per element with **shared_ptr-held bytes so the 40-deep whole-Document undo snapshots share one copy**). Unparseable blocks/elements stay opaque and re-emit verbatim.
- **Native Smart Filter model**: `Layer::smart_filter_stack()` is the per-instance semantic model of SoLd `filterFX`; `src/core/smart_filter.hpp` models stack/entry enable state, native order, blend mode/opacity/colors, Gaussian Blur, High Pass, Median, Dust & Scratches, Surface Blur, Unsharp Mask, Motion Blur, Plastic Wrap, Mosaic, Emboss, Box Blur, Radial Blur (Spin), and Add Noise settings, and the one shared filter mask separately from the ordinary layer mask. `DocumentMetadata::smart_filter_effects` owns Photoshop's document-global `FEid`/`FXid` render caches, associated by the SoLd `placed` uuid rather than the shared source `Idnt`. Raw record bodies and decoded mask samples are shared across whole-document undo snapshots. A wholly supported stack made from those thirteen filters with one unambiguous semantic FEid record is editable; an unsupported entry or cache (including Radial Blur's Zoom method) keeps the whole layer on Photoshop's preserved preview.
- **Editable native rendering**: `src/filters/smart_filter_renderer.{hpp,cpp}` is the deterministic CPU path for supported native Smart Filters. Gaussian Blur embeds the current stack result in the transparent document-space FEid cache canvas, filters premultiplied RGBA, repeats the canvas edge like Photoshop, and alpha-trims its expanded result. High Pass operates on the exact current result bounds, repeats that result's nearest RGB edge, preserves alpha and bounds exactly, and computes `clamp(source - byte-rounded Gaussian + 128)` per channel, including hidden RGB under transparent pixels. Median also keeps the exact bounds. It independently takes the upper median of each RGBA channel over a square, edge-clamped window whose integer radius is the floor of the stored value. Before filtering RGB, transparent source pixels borrow straight color from the nearest nonzero-alpha source using squared Euclidean distance with down-then-right tie breaks; all-transparent inputs retain their hidden RGB. This keeps transparent edges from pulling black into the result. Dust & Scratches reuses that square RGB median and extension, keeps alpha and bounds byte-identical, and replaces the whole RGB triplet only when its maximum channel difference from the extended source is strictly greater than the integer threshold. Surface Blur pads by its rounded effective radius, applies an edge-clamped square weighted filter independently to straight RGB and alpha, then alpha-trims the result. RGB uses the same nearest-visible extension; each sample `v` around center `c` has weight `max(0, 5 * threshold - 2 * abs(v - c))`, and the quotient rounds to nearest with ties to even. Unsharp Mask preserves bounds and alpha, subtracts a byte-rounded straight-RGB low-pass from the source, scales the signed detail, and then removes Threshold from the scaled magnitude before adding it back. Motion Blur embeds in the FEid canvas, applies one user-directed fixed line kernel through premultiplied RGBA, and alpha-trims the result. Gaussian or Motion Blur followed by any bounds-preserving filter uses the expanded result's trimmed bounds, while a bounds-preserving filter followed by either expanding filter can still grow across the FEid canvas. The renderer composites each entry over the previous stack result using its opacity and blend mode, then applies the document-space shared mask once to the completed stack. Normal at 100% uses Photoshop's replacement path. The renderer is called only while producing a cached layer raster, never from `paintEvent` or the compositor. Setting changes, enable toggles, transforms, warp changes, Edit Contents, linked-source updates, Relink, and Replace Contents all regenerate from the unfiltered source instead of filtering the previous preview.
- **Smart Filter preservation**: untouched SoLd and FEid/FXid payloads re-emit byte-for-byte. Parsed version-1 cache records expose 8-bit raw or PackBits filter masks while retaining their raw bodies; an unknown entry, malformed cache, unsupported mask compression/depth, missing association, or duplicate `placed` association marks the whole stack unsupported. One opaque FEid/FXid block makes associations and mutations fail closed across the whole store because a hidden duplicate cannot be ruled out. PackBits row lengths are strict, and an invalid cache layout stops before optional-mask decompression. Never execute a supported prefix of an unsupported imported stack. Photoshop includes 0-3 zero alignment bytes after each length-prefixed FEid/FXid record, inside the declared block payload; the codec requires zero padding for the native shape, preserves untouched bytes, accepts the unambiguous unpadded multi-record shape written by pre-0.20 Patchy, and reproduces four-byte alignment after a rekey. Patchy-authored filters write a canonical Photoshop-shaped `filterFX` descriptor and a version-3 FEid block containing a full-document, PackBits-compressed unfiltered RGB/alpha cache plus the shared mask. Same-size edits patch known leaves in place. Mask painting replaces only the optional FEid mask tail, preserving the unfiltered cache prefix, record order, block dialect, declared-length form, and alignment; an unsafe or ambiguous record rejects the edit. Per-filter opacity and blend-mode edits patch SoLd only and leave FEid/FXid bytes unchanged. Append, duplicate, reorder, and delete rebuild only `filterFXList`, deep-cloning retained native objects so unknown fields, key order, and ID forms survive without shared descriptor aliases. No private `plSF` fallback exists. An FEid cache also makes Photoshop eagerly validate the layer's embedded source file and its 'lyid' block at open time: the writer therefore emits even-length merged-composite PackBits rows everywhere, normalizes stored embeds whose composite has odd rows, and synthesizes 'lyid' blocks for id-less smart-object layers (July 2026; full pinning in docs/ps-compat.md "Smart Filter documents have two extra open-time requirements").
- **Preserve-unless-edited**: untouched layers re-emit their original SoLd/PlLd blobs byte-identically; a move/transform sets `block_dirty` and the writer REGENERATES the blocks patch-in-place via the generic descriptor writer (psd_descriptor.cpp `write_descriptor`, which preserves key order and each id's charID/stringID form — Photoshop writes the 4-char key "warp" as a stringID, so id form is NOT derivable from length; `DescriptorObject::key_order`/`KeyEntry::long_form` carry it). `psd_descriptor_writer_round_trips_sold` pins read->write byte-identity.
- **Lock classification** (kLayerMetadataSmartObjectLock): unsupported warp/quiltWarp, non-affine quads, unsupported or ambiguous filterFX/FEid data, external ('liFE') sources, PlLd-only ("legacy"), and parse failures are preview-locked: Patchy shows/preserves Photoshop's raster and refuses pixel edits; rasterize always works. Photoshop Blur Gallery's `blurbTransform`, including native Tilt-Shift, and native Liquify remain in this preservation-only class. A fully supported filterFX/FEid pair containing only the thirteen modeled filters clears the provisional filter lock. Empty lock = editable. (Supported warps unlock - see docs/warp.md.)
- **UI semantics**: a smart-object badge button on the layer row's details line (`layerSmartObjectBadgeButton`, embedded vs linked icon variants + `smartObjectLinked` property) is THE click affordance for opening the contents; the sibling `layerFxBadgeButton` opens the layer styles dialog, and row double-click opens layer styles for pixel, text, and smart-object rows (smart objects deliberately included: their contents open via the badge or the Smart Objects menus); group rows do nothing, adjustment rows open the adjustment editor, and unlocked shape/fill rows open the shape appearance editor. The name and details labels yield horizontal space first and elide, so both fixed-size badge buttons stay visible at supported panel widths. Filter > Convert for Smart Filters converts the active normal pixel layer to an embedded Smart Object, after which Gaussian Blur, High Pass, Median, Dust & Scratches, Surface Blur, Unsharp Mask, Motion Blur, Plastic Wrap, Pixel Mosaic (Photoshop's Mosaic), Emboss, Box Blur, Radial Blur (default center and tiered samples only), or Add Noise appends an editable native entry instead of changing its source pixels. All thirteen direct filters remain destructive on ordinary pixel layers. Patchy's Lens Blur, Iris Blur, and Tilt-Shift Blur are destructive and gallery-capable, but have no native Smart Filter mapping. Liquify is a separate destructive brush workspace and refuses Smart Objects until its native Photoshop descriptor and cache behavior are calibrated; rasterize first. A direct action or mixed gallery recipe on a Smart Object follows the existing all-or-nothing rasterization path rather than writing a partial or private Photoshop descriptor: both offer the same "Rasterize Smart Object?" prompt (the direct Filter-menu action's `filterRasterizeMessageBox` and the gallery's `filterGalleryRasterizeMessageBox`; accept rasterizes and applies destructively as one undo step, cancel leaves the Smart Object untouched). Since July 2026 the Filter Gallery also surfaces this outcome inline before Apply (thumbnail "SF" badges, target-aware tooltips, the `filterGalleryOutcomeLabel` line, and per-entry warning marks; see docs/filters.md "Filter Gallery"); the prompt itself is unchanged. Adjustment-only filters (Image > Adjustments) deliberately keep the hard refusal status message — they stay under the native-integrity gates below, and `ui_smart_filter_native_integrity_guards_reject_destructive_actions` pins the no-dialog behavior. The routing whitelist is single-sourced: `native_smart_filter_kind_for` / `native_smart_filter_kind_supported` in `src/filters/smart_filter_recipe_mapping.{hpp,cpp}` are the only decision points, queried by the Filter-menu router, the editable-dialog guard, and the recipe mapper alike — never duplicate the ID list. Smart Filter layer rows show the shared mask, stack and entry visibility controls, settings, Edit, Duplicate, Move Up/Down, and Delete controls; execution order is stored bottom-up and displayed in reverse like Photoshop. Double-clicking a Smart Filter entry row opens that filter's settings dialog (the Photoshop behavior; the row's layer-styles double-click applies only outside the entry rows), and the settings dialog carries a Blending section (blend mode + opacity), reached via the Edit pencil or the entry double-click (`patchyFilterDialog`). Click the shared-mask thumbnail to paint it, Ctrl-click to load it as a selection, Shift-click to enable or disable it, and Alt-click for the grayscale mask-only view. The mask overlay and mask-only commands follow the Smart Filter mask while it is the active edit target. Unsupported imported stacks show disabled preservation controls. "Convert to Normal Layer (Rasterize)" (`layerSmartObjectToNormalAction`, in both Smart Objects menus) is a discoverable alias that just calls the Rasterize path. Painting the Smart Object's source pixels is refused with a status hint; Delete removes the object (like text); merge targets and rasterize/rasterize-style strip the smart-object data (`strip_layer_smart_object_data`); Export Smart Object Contents... (layer context menu) writes the embedded bytes verbatim. Duplicate, New Smart Object via Copy, and cross-document paste give each cloned layer a fresh `placed` uuid and clone/adopt its FEid/FXid record without copying the large backing bytes. A clone's FEid record must sit immediately after its source record, and its preserved Photoshop `lyid` block must be rekeyed to a fresh document-wide value; Photoshop 27.8 rejects an appended cache record and aliases layers that share `lyid`. Rasterize/delete remove the instance cache once no layer references it; undo restores the layer and cache together. A missing or ambiguous record blocks the clone instead of producing a Photoshop-corrupt layer.
- **Current Smart Filter editor limits**: Patchy authors and edits ordered Gaussian Blur, High Pass, Median, Dust & Scratches, Surface Blur, Unsharp Mask, Motion Blur, Plastic Wrap, Mosaic, Emboss, Box Blur, Radial Blur, and Add Noise stacks. A new stack uses the exact current selection alpha as Photoshop's shared filter mask, or an explicit all-white mask when there is no selection; later entries retain that shared mask. Editable masks are full-document 8-bit grayscale targets. Brush, Eraser, Fill/Clear, Gradient, Line, Rectangle/Ellipse, and Invert edit the temporary mask buffer; unsupported tools are blocked rather than touching the Smart Object pixels. The model and native cache remain unchanged during a gesture, and each completed gesture commits one undo step and regenerates the filtered preview once. Whole-percent opacity (Photoshop normalizes fractional values) and blend mode are edited in the settings dialog's Blending section with cancellable live preview; Apply creates one undo step, and a blending-only accept patches SoLd while leaving FEid/FXid bytes unchanged. Editable native masks are limited to documents of 64 megapixels or less; larger imported records remain preserved and preview-locked. A true `filterMaskLinked` flag is also preserved but preview-locked because Photoshop 27.8 did not produce a true-state fixture, so linked-mask editing is not exposed. Density and Feather are not exposed yet. Gaussian Blur and High Pass radii are fractional from 0.1 to 1000 px. New Gaussian Blur edits use the same practical 0.1 through 12 px range as the destructive dialog; an imported native value above 12 remains visible and is preserved when accepted unchanged. High Pass, Median, Dust & Scratches, Surface Blur, Unsharp Mask, Motion Blur, and Plastic Wrap use the typed and practical ranges (and rendering formulas) of their destructive catalog entries in [filters.md](filters.md). Mosaic uses integer Cell Size 2 through 200 px with a practical slider through 64 px; its renderer keeps bounds and matches the destructive Pixel Mosaic's alpha-weighted block averages exactly, so like Plastic Wrap the native descriptor round-trips while the pixels are Patchy's own compatible rendering. Emboss uses integer Angle -360 through 360 degrees (practical -180 through 180), Height 1 through 100 px (practical 1 through 24), and Amount 1 through 500 percent (practical through 300); its renderer keeps bounds and alpha and matches the destructive Emboss's bilinear-luminance gray relief exactly, and the destructive catalog gained the same native typed ranges with the historical practical sliders. Photoshop's Emboss Amount minimum is 1, so a Patchy amount of 0 never maps natively. Box Blur stores a fractional radius from 1 to 2000 px (floored for rendering like Median) with a practical 1 through 12 px slider; radii through 12 render byte-identically to the destructive Box Blur while larger radii use an exact integer sliding-window path with the same edge-clamped sampling, growing inside the FEid canvas and alpha-trimming like Gaussian Blur. The destructive Box Blur catalog deliberately keeps its historical 1 through 12 integer range. Radial Blur models Photoshop's Spin method only and replicates the destructive sweep byte for byte inside the FEid canvas about the content center; amount, quality-tier sample mapping, the default-50/50-center rule, and the Zoom preview-lock live in [filters.md](filters.md). Add Noise stores Photoshop's verbatim FlRs random seed plus the Uniform/Gaussian and Monochromatic flags; the seeded deterministic renderer (see [filters.md](filters.md)) makes the pixels Patchy's own compatible rendering rather than Photoshop's noise, and the seed has no dialog control (the imported value persists through edits). Preview/Cancel restores the exact cached raster, and each Apply, visibility, mask toggle, duplicate, reorder, or delete action produces one undo entry. The settings dialog also keeps the current raster while the previewed values (parameters AND blending) equal the stored ones (including on open with Preview checked): the raster may be Photoshop's own baked preview, and a Patchy re-render of identical settings must not visibly change the image (`ui_smart_filter_dialogs_with_preview_keep_unchanged_pixels`). The Filter Gallery applies recipes containing only the thirteen supported filters non-destructively to a Smart Object; a recipe containing Lens Blur, Iris Blur, Tilt-Shift Blur, or any other Patchy-only filter asks for rasterization and is never partially mapped. Wrapping a filtered Smart Object inside another Smart Object is blocked until Patchy can transfer its native cache and document-space mask into the child file. Unsupported imported stacks remain byte-preserved and preview-locked.
- **Native-integrity safety gates**: Move-tool drags, keyboard nudges, Free Transform, and Warp rebuild a supported filtered Smart Object from its immutable source and refresh FEid. Those commits are transactional: a render/cache failure restores placement, pixels, native cache, and history. Whole-document Image Size, Canvas Size, Crop, and Rotate currently refuse documents containing any Smart Object because the native placement and document-space mask transforms are not calibrated yet. Layer Flip and Fill similarly refuse Smart Object pixels; use Free Transform or rasterize first. The Filter Gallery maps fully supported recipes to native entries and offers to rasterize before applying any mixed recipe. Other destructive Image Adjustments, legacy plug-ins, Cut, Layer via Cut, Apply Layer Mask, Stroke Selection, indexed conversion, palette remapping, and palette snapping require rasterization before they can rewrite Smart Object preview pixels. Copy, Layer via Copy, ordinary mask editing, and metadata-only palette changes remain non-destructive and available. These gates also protect unsupported imported stacks whose Photoshop preview must remain byte-preserved.
- Opening a PSD with smart objects emits **import notices** (editable / preview-locked / external / dangling counts). These follow the status-bar-by-default rule (see docs/file-formats.md); UI tests opening such files through the window path only need the repeating dismisser when they enable `imports/showPsdWarningsAndInfo`. Tests reading via `DocumentIo::read_file` directly are unaffected (no dialogs).
- **Edit Contents**: clicking an editable embedded smart object's badge button (or Edit Smart Object Contents in the Smart Objects menus) opens the source as a child tab titled "file.ext (embedded in Parent.psd)". The child is a full `DocumentSession` whose `smart_object_link{parent_session_id, source_uuid}` carries session IDS (never pointers: sessions_ erases on close; `session_id` is the stable identity). Save (Ctrl+S) on the child routes `save_document()` to `commit_smart_object_child_session`: the child serializes in the source's own format (PSB for '8BPB' via `WriteOptions::large_document`, PSD for '8BPS', Qt image formats re-encode a flatten), the element gets fresh shared_ptr bytes (dirty), EVERY layer sharing the uuid re-renders (`smart_object_render.{hpp,cpp}`: quadToQuad + resample_transformed_rgba8, raster_status=patchy_raster), and the parent takes ONE undo snapshot ("Edit Smart Object Contents"); the child marks clean. Size-changing commits rescale quads per the E5 rule below; same-size commits leave SoLd untouched (only the lnk element regenerates). Closing a parent with open child tabs prompts (closeSmartObjectChildrenMessageBox) and resolves the children first; a child whose parent is gone detaches and falls back to Save As. Nested smart objects work by construction (each child is a full session; PSD children keep their own store through DocumentIo). Decode fidelity: PSD/PSB sources render their preview from the child's own flattened composite (prefer_flat_composite), so untouched children look exactly like Photoshop's stored pixels.
- **Preview decode falls back to the layered render when the stored composite is fully opaque but the layers are not** (`decode_smart_object_source_image`): a 3-channel or opaque composite cannot represent canvas transparency. Older Patchy children (black-matted composites) and Photoshop saves with Maximize Compatibility off (flat white-matted composites) both render through the layered fallback, while genuinely opaque children keep the PS-exact stored composite. Regression pins: `ui_smart_object_edit_commit_keeps_canvas_transparency` (end-to-end convert/edit/commit), `ui_smart_object_legacy_black_composite_decodes_transparent` (committed pre-fix fixture `test-fixtures/psd/patchy-legacy-black-composite.psb`), and `ui_smart_object_psbtest_repro_decodes_transparent_if_available` (the original local repro file in `local-test-fixtures/psd/PSBtest/`). Parent files whose previews were already baked black heal on the next commit/transform/update re-render.
- **Edit-format guard**: PSD/PSB (DocumentIo both ways) and png/jpg/jpeg/tif/tiff/bmp/webp (Qt both ways) are editable; GIF and registry-only formats (TGA/PCX/...) decode for preview but refuse Edit/Replace with an explanatory status message (`classify_smart_object_contents`); undecodable/external sources keep Photoshop's preview forever. Content density comes from `smart_object_source_dpi` (PSD resolution or the image's embedded density, 72 fallback) — note Qt-authored pngs carry a pHYs chunk, so replacing with one honors its dpi like Photoshop does.
- **Replace Contents** follows the E5 semantics exactly: fresh uuid + element, every referencing layer repoints and rebuilds about its own quad center, old element removed, layer names swap the source stem. Accepted replace formats: psd/psb/png/jpg/jpeg/tif/tiff/bmp (webp only round-trips existing sources, its PS filetype OSType is unpinned).
- **Linked-file workflows**: external ('liFE') smart objects are fully workable. Edit Contents resolves the path (relPath against the parent folder, then a bare-filename sibling, then originalPath, then the fullPath URI: `resolve_smart_object_external_path`) and opens the REAL file as a disk-backed session with `SmartObjectLink::external`; its Save writes the file FIRST, then `refresh_external_smart_object_after_save` re-reads the bytes, stamps the liFE date/size, marks the element dirty, and re-renders every uuid-sharing layer as ONE parent undo step. Update Smart Object Content re-reads on demand; document open compares stored date/size and prepends "changed on disk"/"not found" notices (actionable notices go FIRST so the status bar shows them). Relink to File... follows PS's E14-captured semantics: like Replace Contents but staying external (a FRESH element uuid in the lnkE block, referencing layers repoint and rescale about their own centers per E5, layer names swap the source stem, old element pruned). Embed Linked follows E13: ANOTHER fresh uuid, the element moves to lnk2 as liFD, the emptied lnkE stays behind, locks clear, and the per-layer SoLE block key flips to SoLd (block_dirty repoints the Idnt on save). COM note: linked placement needs `putBoolean(charIDToTypeID("Lnkd"), true)` on the 'Plc ' descriptor. No QFileSystemWatcher by design (open-time check + explicit Update + self-save refresh cover the workflows). The shared re-render walk is `refresh_smart_object_layers_for_source`.
- **E4 acceptance**: Photoshop 2026 opened Patchy's committed, replaced, and nested-edit outputs (the `ui_smart_object_*.psd` test artifacts), color-sampled the re-rendered previews bit-exactly, opened each embedded contents, and resaved cleanly (no "disk error (-1)"). Re-run the e4_acceptance COM script over those artifacts after any writer-side smart-object change.
- **Authoring**: Convert to Smart Object (layer menu + context submenu) moves the selected layer trees into a child document (canvas = union of render bounds, PSB, '8BPB', named "<top layer>.psb"; nested sources adopt into the child store), the topmost selected layer's slot/id/name become the new smart object, and the preview composites pixel-identically for Normal/100% layers. Place Embedded (File menu) uses the E2 rule dpi-aware (physical size 1:1 centered, fit-to-canvas when larger). Both write a from-scratch SoLd via `psd::author_placed_layer_sold_payload`, which mirrors PS 2026's exact key order/id forms (E1 captures; `smart_object_authored_sold_matches_photoshop_shape` pins the shape against the committed fixture) and is pushed into the layer's unknown blocks at author time, so the normal preserve/patch-in-place machinery owns it from then on. Patchy writes NO legacy PlLd companion (PS writes both; it accepts SoLd-only files, E4-gated). New Smart Object via Copy clones the element under a fresh uuid (E8 semantics); free transform composes the delta into the quad and re-renders through `smart_object_transform_render_callback_` (text-layer pattern), with the resampled pixels as fallback.
- **Locked-but-parsed** external, legacy, and unsupported-warp layers still translate their quads on Move and regenerate patch-in-place; nonAffineTransform moves by the per-corner DELTA (never overwritten with the affine quad, which would flatten a perspective placement), and warpNone warp bounds stay the CONTENT rect (0,0,h,w) like PS writes them. An unsupported Smart Filter stack is pinned because its baked, document-space masked preview and native FEid cache cannot be moved independently. Truly unparseable SoLds import with lock="unparsed" and an EMPTY uuid (badge + paint/transform/move protection; `layer_has_movable_pixels` pins the layer because no quad can ride a move); the dangling-uuid cleanup skips that state and blocks re-emit verbatim forever.

- **Photoshop 2026 ground truth** (COM captures): Convert-to-SO writes BOTH PlLd and SoLd; child doc = "<layer name>.psb" ('8BPB', creator '8BIM'), canvas = layer pixel bounds, Trnf = those corners; Place uses filetype 'png ' etc. with creator four spaces, smaller-than-canvas places 1:1 centered, larger fits-to-canvas centered (`generalPreferences.placeRasterSmartObject` gates SO creation — it is FALSE on this machine, flip it temporarily in scripts and restore); lnk2 elements are version 8 with ~117 undocumented trailing bytes (parse by element length; Patchy writes v7); duplicates share the Idnt uuid, "New Smart Object via Copy" clones the element under a fresh uuid ('placed' is a per-layer instance uuid, always fresh); rasterizing in PS KEEPS the orphaned lnk2 element, so Patchy never prunes unreferenced sources either.
- **Smart Filter ground truth**: the complete Photoshop COM capture record (descriptor classes and key orders, FEid cache layout, per-filter kernels and formulas, authoring shape, fixture provenance) lives in the Native Smart Filters section of [ps-compat.md](ps-compat.md). Smart-object-side consequences: `filterFXList` stores filters in application/execution order while the Layers panel displays them reversed; each duplicate shares `Idnt` but has a distinct `placed` uuid and FEid record; Saving Edit Contents and Replace Contents regenerate the shared `Idnt` and every referencing layer's `placed` uuid, while rasterizing one duplicate leaves the surviving instance IDs unchanged; Photoshop 27.8 ignored attempts to set `filterMaskLinked=true`, so a true flag is preserved but keeps the imported layer preview-locked.
- **liFE (linked external file) element layout** (pinned from the 10cm-table-tent PS 2023 capture, v7 elements): uuid pascal string, unicode filename, filetype OSType, creator = four NUL bytes (not "8BIM"/spaces), u64 datasize (0), open descriptor flag + `{null; compInfo{compID:-1, originalCompID:-1}}`, then a SECOND u32 descVersion 16 + `ExternalFileLink` descriptor (class strID; keys in order: descVersion(str) long = 2, 'Nm  '(char) TEXT filename, fullPath(str) TEXT file:// URI, originalPath(str) TEXT native path, relPath(str) TEXT), then a 16-byte date struct {u32 year, u8 month, u8 day, u8 hour, u8 minute, f64 seconds} (the mod time PS compares for staleness), u64 file size, then the versioned tail every element kind shares: v5+ unicode child doc id, v6+ f64 assetModTime, v7+ u8 lock state. `parse_link_element` models all of it (best-effort try/catch: unmodeled variants degrade to the verbatim skip) and `serialize_external_element` mirrors it for dirty external sources; clean elements still re-emit byte-identically. `psb_life_trailer_fields_parse_if_available` + `smart_object_external_element_round_trips_if_available` pin both directions.
- **Replace Contents ground truth** (E5 COM captures, `ps2026_e5_*` local fixtures): PS creates a NEW element with a fresh uuid and repoints EVERY layer that referenced the old uuid (the replaced-away element is removed, unlike rasterize orphans); each layer's quad is rebuilt about its own quad center preserving the content-inch-to-doc-pixel linear map (`L_new = L_old * dpi_old/dpi_new`; same-dpi replaces degrade to pure pixel scaling), Sz/Rslt become the new content's pixel size and dpi, and layer names swap the old source stem for the new one ("A copy" becomes "B copy"). PS additionally rounds the resulting quad corners to whole pixels; Patchy keeps full doubles (a sub-pixel placement difference on OUR edit, not a render divergence). Place also writes an empty 'lnkE' block alongside 'lnk2'.
