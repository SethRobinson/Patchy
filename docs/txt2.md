# Photoshop's Txt2 text engine block

The document-level `Txt2` tagged block (global section, after the layer info and the global
layer mask) holds one text object per type layer, addressed by the layer's TySh `TextIndex`.
Photoshop trusts it over the per-layer TySh EngineData ([ps-compat.md](ps-compat.md)). This
document records what the September 26, 2026 COM probe established about its format and
what Photoshop 2026 accepts, so an authoring pass can be built on facts rather than guesses.
Probe files live in `local-test-fixtures/psd/txt2-probes/` (gitignored). The tooling is in
`scripts/dev/txt2/`: `txt2tool.py` (PSD section walker, byte-exact EngineData tokenizer and
serializer, `dump`/`roundtrip`/`diff`/`variant` commands), `variants.py` (the V1 to V6 edits),
`ps-probe.ps1` (opens files in Photoshop over COM, selects each type layer, reads
`textKey` back through Action Manager, renders a PNG, resaves; logs any `PSDialogBox` text)
and `ps-capture-p2b.ps1` (single-setting captures through Action Manager, list styles
included).

Status: Patchy authors the block on every save that has type layers (September 27, 2026).
`src/psd/engine_data.{hpp,cpp}` is the byte-exact tokenizer, AST and serializer for the syntax;
`src/psd/psd_text_engine_block.{hpp,cpp}` parses a block, authors objects and frames from
`TextEngineInputs` (the same text, runs, fonts and box the TySh gets,
`text_engine_inputs_for_layer` in psd_text_write.cpp), and `build_text_engine_block` in
psd_document_io.cpp rebuilds the block for the write: the preserved block (or the Photoshop
2026 template in `psd_text_engine_template.cpp`, generated by `scripts/dev/txt2/make_template.py`)
with every layout cache stripped, an authored object for each regenerated type layer at the
index its TySh will carry (its imported `patchy.psd.text.index` when that object exists, else
appended), the objects of untouched imported layers kept, and the block appended to the global
section when the document never had one. Exception: a document that keeps a verbatim Photoshop
5.x `tySh` record gets no block at all unless it already had one, because the block's presence
alone makes Photoshop open every such layer as pixels ([psd-legacy-text.md](psd-legacy-text.md)).
A block that fails to parse is kept verbatim and the
regenerated layers fall back to indices no object has (`kRegeneratedTextIndexBase`), the
old-text path. Objects a deleted layer leaves behind stay (Photoshop drops them on resave).
Tests: `tests/core/text_engine_block_tests.cpp`.

Acceptance (Photoshop 2026 over COM, `ps-probe.ps1`): a Patchy-born 300 ppi document with
point, indented box, three-run (Arial, Arial Bold, 40 px) and vertical layers, and the tracking
fixture with one layer retyped, all opened clean, with no `oldText`, `textWarningLevel 0`, and
contents, fonts, sizes, indents, run splits, box kind and orientation read back exactly.

## Syntax

The block is the same PostScript-like text syntax as TySh EngineData: `<< /k v >>`
dictionaries, `[ ]` arrays, `(\xfe\xff...)` UTF-16BE strings with only `(`, `)` and `\`
escaped, `/name` enums, `true`/`false`, `/nil`, integers and floats. Differences from TySh:

- Every dictionary key is a small integer (`/0`, `/1`, ... `/98`); `/99` holds a class tag
  (`/CoolTypeFont`, `/SimplePaint`, `/SimpleBlender`, `/SimpleCustomFeature`, and the
  layout classes `/PC` `/F` `/R` `/L` `/S` `/G`).
- The body is a bare key/value sequence (no outer `<< >>`), one line of single-space
  separated tokens starting `" /98 << /0 14 >>"`; the only newlines are inside strings.
- Numbers use Photoshop's short spelling: `.583`, `.8`, `1.0`, `0.0`, `-20.5957`,
  `216.52031` (at most 5 decimals, trailing zeros stripped, `.0` kept, no leading `0`
  before the point).

A lexeme-preserving tokenizer round-trips every Photoshop-authored block byte-exact (22 of
22 fixtures with a document-level block; the pinball poster's only Txt2 is inside an
embedded smart-object PSD in its `lnk2` block, not at document level).

## Structure

| Path | Meaning | Notes |
|---|---|---|
| `/98 << /0 14 >>` | format version | Photoshop 2026 writes 14 |
| `/0` | DocumentResources | |
| `/0/1/0[]` | FontSet | `/99 /CoolTypeFont`, `/0` PostScript name, `/2` type (0 default/Myriad, 1 ordinary), `/5` version string; entry 0 is `AdobeInvisFont` |
| `/0/2`, `/0/3`, `/0/4` | MojiKumi / MojiKumiSet (9) / KinsokuSet (6) | boilerplate, identical across captures |
| `/0/5/0[]` | StyleSheetSet | `/0` name ("Normal RGB", "None"), `/6` the 93-key style sheet |
| `/0/6/0[]` | ParagraphSheetSet | `/0` name ("Normal RGB", "Basic Paragraph"), `/5` the 44-key paragraph sheet, `/6` default style sheet index |
| `/0/8/0[]` | text frame set | one entry per text object |
| `/0/9/0[]` | ListStyleSet | 11 predefined list styles, `/0` name, `/6` numbering kind; index is what a paragraph's `/36` references |
| `/1` | DocumentObjects | |
| `/1/4` | engine version | `/0 7 /1 11 /2 0 /3 (Photoshop)` |
| `/1/0` | document settings | quote table (`/9`, 46 entries), superscript/subscript ratios, boilerplate |
| `/1/5[]` | story list | one entry in every capture, bit-string fields `/2`, `/3`, font versions `/4` |
| `/1/1[i]` | text objects, index = TySh TextIndex | see below |
| `/1/2`, `/1/3` | default style and paragraph sheets | full 93 / 44 key copies |

Text object `/1/1[i]`:

- `/0` model: `/0` the text (Photoshop appends `\r`; runs count it), `/5/0[]` ParagraphRun
  entries (`/0/0/5` sparse paragraph sheet, `/0/0/6` unit flag, `/1` length), `/6/0[]`
  StyleRun entries (`/0/0/6` sparse style sheet, `/0/0/5` unit flag, `/1` length),
  `/10 << /0 1 /2 true >>` (`/0 4` for Standard Vertical Roman Alignment). **The unit flags
  select what the sheet values mean: 0 = document pixels, 1 = points at the document PPI.**
  Photoshop wrote 1 in the 72 ppi captures and 0 for its own objects of a Patchy layer in a
  300 ppi document; an authored object with 1 read a 28 px layer back as 116.67 px. Patchy
  writes 0 (TySh engine units).
- `/1` view: `/4` engine version, `/5`, `/0` frame index list, `/1`, `/2` the cached
  composed layout (`/PC > /F > /R > /R > /L > /S > /G`: glyph ids, cumulative advances,
  line bounds, about 1 KB per line).

Per-object sheets are sparse (about 30 of 44 paragraph keys, 47 of 93 style keys).

## What Photoshop 2026 accepts (probe results, all opened clean, no dialog, correct readback)

- **The cached layout tree is optional.** Object `/1/2` replaced by `[ ]`, removed, or the
  whole view reduced to `/4` and `/0`: Photoshop recomposes from the model, reads the text,
  font, size and tracking back correctly, renders identically, and writes a fresh cache on
  resave.
- **A stale cache is harmful.** Changing the text and run lengths while leaving the old
  cache set `textWarningLevel 1` and re-rendered the layer from the stale glyphs. Never
  write a cache; omit `/2`.
- **Objects can be appended.** A third object (copy of an existing one with new text) with a
  TySh pointing at its index read back as the new text; Photoshop's resave dropped the
  object no layer referenced and renumbered.
- **A Patchy-born document can be given a block.** Grafting Photoshop's objects for the same
  layers (from a Photoshop resave), caches stripped, into the original Patchy file with
  TextIndex 0 and 1 made both layers read as new text: no `oldText`, `textWarningLevel 0`,
  contents and fonts correct.
- Photoshop's untouched resave of a Patchy file writes no Txt2 and TextIndex -1; after a
  DOM `contents = contents` re-layout it writes a block whose objects mirror our TySh
  (fonts get `/2 1` plus a version string, Myriad Pro `/2 0`, a `TimesNewRomanPSMT` entry
  appears unreferenced), but it also stamps `oldText true /oldTextAge ate1` into those TySh
  descriptors, so that file still reads as old text. Do not copy those keys.
- Old-text detection: `oldText` in the Action Manager `textKey` descriptor and
  `textWarningLevel` on the layer descriptor (1 for old or mismatched, 0 for native).

## Lists

Photoshop 25.11+ bulleted and numbered lists live only here (`/36`, `/37`); the TySh
EngineData has no list keys, so a layer read through the old-text path can never carry a
list. Setting them over COM: `set` on the `textLayer` `paragraphStyle` property with a
`listStyle` object of class `listStyleDetails` holding `listStylePredefinedTag`
(`predefinedBulletListStyleTag`, `predefinedNumericListStyleTag`,
`predefinedUppercaseAlphaListStyleTag`, ...) and `bulletListStyleTag`, plus integer
`listTier`. The DOM `textItem` indent setters did not reach the file; the Action Manager
`paragraphStyle` set with `pixelsUnit` values did. Render: the marker sits at the box's left
edge and the text hangs at a fixed offset (a 24 px Arial bullet: text starts 25 px in; "A."
numbering: 58 px), the text itself is unchanged, and the tier changes the bullet glyph
(0 disc, 1 filled square, 2 empty circle) or numbering scheme (numeric tier 1 renders "A.").

## Not yet known

- Whether `/1/5` must grow with the object count (Patchy keeps the template's one story with
  no font versions and Photoshop accepted it); FontSet entries without `/5` version strings
  are accepted too.
- Warp Text, PSD-frame transforms and RTL paragraphs on authored objects: the TySh carries them
  and Photoshop read the probes' horizontal, vertical and boxed layers back, but a warped or
  transformed Patchy-born layer has not been read back yet.
- Older Photoshop versions: only Photoshop 2026 (`/98 /0 14`) is on this machine.
