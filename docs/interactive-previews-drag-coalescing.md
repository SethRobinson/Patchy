# Drag move coalescing

Split from [interactive-previews.md](interactive-previews.md): which canvas drags apply only the newest pointer move of an event-loop pass, how presses, releases and keys flush the recorded move, the tests that pin it and the live Wayland timings.

## How it works

Wayland delivers every pointer motion uncompressed (X11, Windows and macOS merge them), and each Move-tool or Free Transform drag move recomposites its preview, so a fast pointer queued seconds of moves and the canvas repainted about once a second (GitHub #207, #443, #444; the Path Select twin is #314). `defer_coalesced_drag_move` (canvas_widget_events.cpp) applies the first move of an event-loop pass at once and only records later ones while `moving_layer_` or `dragging_transform_` holds; a queued call at the pass end applies the latest recorded position and opens the next pass. Presses, releases and key events call `flush_pending_drag_move` first, so a drop, Shift constraint or Escape acts where the pointer really is; `cancel_pointer_gestures` drops the record. Only spontaneous (window-system) moves coalesce, so tests that send moves one by one see each applied; `set_drag_move_coalescing_for_testing` lets posted moves coalesce. A held pick (`color_picking_`, GitHub #478), Path and Direct Select drags (#678, [vector-commands.md](vector-commands.md)) and Gradient Fill handles (#705, [gradients-fill-handles.md](gradients-fill-handles.md)) coalesce the same way, and so do Clone, Healing, Smudge, toning, Brush and Eraser strokes (GitHub #597, #660, #677), which keep every recorded position as a folded sample instead of only the latest ([performance-strokes.md](performance-strokes.md)); `coalescing_drag_active` names the drags ([pick-tool.md](pick-tool.md#drag-cost)). Scrubs: [ui-conventions-dialogs.md](ui-conventions-dialogs.md#scrub-move-coalescing). Counted in `drag_moves_coalesced`; pinned by `ui_move_drag_coalesces_queued_moves`, `ui_free_transform_drag_coalesces_queued_moves`, `ui_pick_drag_coalesces_queued_moves` and the two drags' own tests; `patchy_perf_tests textdrag` times a 120-move burst both ways. `textdrag_live` (`live-drag.sh`) and `canvasdrag_live` (`live-canvas-drag.sh`, in `scripts/dev/wayland-popups/`) time a real Wayland drag on the headless sway rig (move queueing delay, repaint lag and gaps against the moves' compositor timestamps). Qt 6.11 (the Flatpak) merges moves there, so it keeps up either way; Qt 6.8.3 (the AppImage, `NATIVE=1`) delivers every move and reproduces the lag on a quarter core; on an i7-1360P laptop a 120-move burst on a pixel layer takes 187 ms applied one by one and 20 ms coalesced (October 2026).

## Path Select and Gradient Fill handles (GitHub #678, #705)

Both drags joined `coalescing_drag_active` in November 2026 (`path_edit_drag_moves_points`: Path Select and Direct Select point, handle and whole-shape drags, a shape tool's Ctrl drag and the Pen's Ctrl latch; `gradient_handle_drag_`). Path Select already queued one apply per event-loop pass (#314); the canvas coalescing also skips the rest of `mouseMoveEvent` for a recorded move, and the replayed move feeds that queued apply. A Path Select step also refreshes its region on the UI thread even past half the canvas (`document_changed_drag_region`; [vector-commands.md](vector-commands.md)). Pinned by `ui_path_select_drag_coalesces_moves_and_keeps_the_fill_current` and `ui_gradient_fill_handle_drag_coalesces_queued_moves`.

`patchy_perf_tests canvasdrag_live` (`PATCHY_PERF_CANVASDRAG_KIND=shape|gradient`) with `scripts/dev/wayland-popups/live-canvas-drag.sh <shape|gradient> <on|off> [pace] [hogs]` drags on the sway rig: a Path Select drag of a pentagon over a 3600x5400 noisy photo (its corner past the canvas edge, like the reporter's), or a 1280x720 Gradient Fill's end handle. It also reports `stale_paints` (repaints while the composite was older than the document) and `lag_px` (the dragged point's distance from the pointer at each repaint). Measured on glados (24 threads) with 2554 moves in 3.4 s, `hogs 3` pinning the app to a quarter of a core:

| Case | Before | After |
| --- | --- | --- |
| Gradient handle, Qt 6.8.3, quarter core | the release handled 102 s late, 3 repaints | 22 ms late, 29 repaints (116 ms apart) |
| Gradient handle, Qt 6.8.3, full speed | 15 ms late, 636 repaints | 15 ms late, 372 repaints |
| Gradient handle, Qt 6.11, quarter core | 374 ms late, 19 repaints (191 ms apart) | 26 ms late, 26 repaints (104 ms apart) |
| Path Select, Qt 6.8.3, full speed | 56 of 73 repaints showed a stale fill | 0 of 472 stale |
| Path Select, Qt 6.8.3, quarter core | 5 of 40 stale, release 155 ms late | 0 of 58 stale, release 74 ms late |
| Path Select, Qt 6.11, full speed | 27 of 149 stale | 0 of 484 stale |

Qt 6.11 (the Flatpak) merges motion before Patchy sees it (1351 of the 3000 moves sent at full speed, 39 on a quarter core), so its lag stayed mild; the AppImage's Qt 6.8.3 delivers all of them.
