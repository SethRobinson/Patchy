## Row styling

Layer rows use dynamic properties and application rules such as `QWidget#layerRowWidget[layerRowSelected="true"]`; repolish after property changes (`layerTargetActive` is the reference). `ui_layer_row_selected_highlight_paints` pins the rendered colors. Never give a row widget with a tooltip its own selector-less sheet: Qt cascades it into the tip and `background: transparent` cleared its panel (#347).

Main row (`make_layer_row_widget`): eye, tree indent, folder arrow, clip badge, thumbnail, 4 px apart. Columns (#386 follow-up): once the document has a folder (`layer_list_needs_arrow_column`), every row reserves the arrow slot (a non-folder's `layerTreeIndent` takes it), so content thumbnails, masks and plain rows' names sit in one column per depth, each level `kLayerChildIndent` (16 px) right of its folder's, at every Thumbnail Size; a document without folders reserves nothing. Duplicate's partial insert (#402) rebuilds when that changes. The folder, Layer Styles and Smart Filters arrows are 10 px plus the QSS border (`kLayerDisclosureSlotWidth`, 12 px) by 20 px. The clip badge takes the thumbnail's width in its depth's thumbnail column, so its `clip` glyph (`action_icons.cpp`, also the clip cursor and action icon; from the right, pointing down) centers on the base row's thumbnail and the clipped thumbnail takes the next column (#397; `ui_layer_rows_line_up_thumbnails_by_depth`, `ui_layer_row_spacing_keeps_eye_clip_and_thumbnail_close`, `ui_layer_clip_badge_arrow_points_down`).

Hidden rows disable name, details, mask link and clip badge; other badges stay clickable, dimmed (`layerRowBadgeDimmed`, issue 230).

Blending badge (#494, `layerBlendingBadgeButton`): shown while `layer_advanced_blending_differences` lists non-default Blending Options (channels, Knockout, effect switches, 'tsly' off, Blend If), named in its tooltip; a click opens them. Adjustment thumbnail tooltips name the kind (#492). Crowded rows: badges stay 20 px after QSS polish (`restore_layer_row_button_size`), the name keeps "Www…", then `LayerRowLockStrip` folds the locks into one padlock; `refresh_row_widths` sizes rows to it, then scrolls (`ui_layer_rows_with_every_badge_*`).

Locks: panel buttons, the row's Lock submenu and Layer > Lock Layers... ([layer-shortcuts.md](layer-shortcuts.md)); the last two add Prevent Auto-Nesting (`layer.prevent_auto_nesting`; #246, [artboards.md](artboards.md)). Badges (`make_layer_lock_badge`) show each set lock; a Background shows one padlock instead ([background-layer.md](background-layer.md)); folders pass on editing locks only. Buttons and badges share `layer_lock_icon` (action_icons.cpp, #484): glyphs 14 of 16 px in the buttons, 11 of 14 in badges, pixel art with no partly inked pixel at any scale, inked from a theme role at paint time (`ui_layer_lock_buttons_share_one_icon_height`, `ui_layer_lock_icons_land_on_whole_pixels`). The row tooltip names the effective locks on one line (`layer_list_item_tooltip`, #483): "Locked: All", else the partial ones joined ("Locked: Transparent, Position"), then "Auto-nesting"; the Background reads "Locked: Background", plus Image (`ui_layer_row_tooltip_names_every_lock`).

## Rebuilds and absent rows

`MainWindow::refresh_layer_list` (main_window_layer_panel.cpp) rebuilds in
passes: configure every `QListWidgetItem` while parentless, insert ALL items, then
attach row widgets. The order is load-bearing: `setData`/`setToolTip` on an inserted
item emits `dataChanged` and layout work, and each `setItemWidget` editor index makes
every LATER insert pay an update walk (interleaving goes quadratic). Never mutate an
inserted item mid-rebuild or attach a row widget before the last item is in.
Duplicate Layer adds only its copies' rows (`insert_duplicated_layer_rows`, #402).
Profiling: [performance.md](performance.md) (`layerpanel`, `manylayers`, `duplicate`).

New sessions build rows once; row attachment pumps paints/timers with input excluded
and the preview edit lock held, refusing recursive rebuilds. Slow setup shows an opening
dialog while the spinner animates; hide the welcome panel before inserting the tab. `ui_large_document_session_keeps_loading_responsive`
pins spinner frames during row construction; the recent-file open test pins one rebuild.

Layer Style CANCEL skips `refresh_layer_list`: it restores the pre-dialog state, so
only the previewed thumbnail moved (`refresh_layer_thumbnails` + `refresh_layer_controls`).
Committing rebuilds. Artboard edits that keep every layer in place (resize, plain move,
background) restamp thumbnails the same way (`finish_artboard_edit`'s `rows_unchanged`).

During guarded automation, script rebuilds call `refresh_layer_list(true)`: old row widgets are captured before clearing and deleted after detachment. Manual callbacks and editable pauses use ordinary deferred deletion so the input receiver outlives the event. `ui_mcp_layer_rows_stay_bounded_during_long_script` pins the live-widget bound during execution.

Canvas-driven selection never rebuilds existing rows. `reveal_layer_in_layer_list` (Move-tool auto-select, `active_layer_changed_callback`) and `select_layers_in_layer_list` (rectangle and modifier selection) rebuild only when a collapsed ancestor must open, the name filter must clear, or a target has no row; else they select the existing row (`layer_row_item`) for the ordinary selection handler. Pinned by `ui_move_auto_select_click_keeps_existing_layer_rows`. Both scroll through `scroll_layer_row_into_view`: a row already wholly on screen keeps the scroll position, an off-screen row is centered, and the badge buttons pass `clicked_in_panel` so a partly visible row under the pointer stays put too (#266, `ui_layer_smart_object_badge_click_keeps_panel_scroll`).

Row masks: `LayerListWidget::update_row_viewport_masks` (on scroll, resize, range, value and focus changes) masks the rows under the raised scroll bars. Scroll-bar rects map through global coordinates: the bars live in QAbstractScrollArea's containers, siblings of the viewport. Only rows in view are touched; rows scrolled in get theirs on that pass. Pinned by `ui_layer_list_row_masks_map_scroll_bars_without_warnings`.

The list may omit rows: collapsed folders and the name filter (`layerNameFilterEdit`) rebuild without rows for excluded layers. Never assume every layer has a row, and never add a "row exists but hidden" state: absent rows are the one not-shown state consumers handle. While the name filter is active, `LayerListWidget::set_drag_blocked` refuses drag reordering because a reorder would silently move filtered-out layers; each refused attempt reports through `show_status_error` and leftover held-button moves are swallowed so the base view cannot start a drag-selection sweep.

## Blend and opacity row

Dragging the "Opacity:" or "Fill:" prefix scrubs the value (`install_prefix_scrub`, [ui-conventions.md](ui-conventions.md) Options bar): the drag ends with `editingFinished`, so `finish_pending_layer_opacity_edit` closes it as one undo entry; a click on the prefix focuses the field with the number selected. Combos from `add_blend_mode_items` also step with Left/Right. Panel blend changes merge into one undo entry until a pause or another history change (`ui_layer_blend_mode_steps_coalesce_into_one_undo_entry`). Pass Through is offered first, for folders only (`set_blend_mode_pass_through_offered` per active layer, `BlendModeMenu::Folder` in Blending Options), and never lands on a selected non-folder (#235). `refresh_layer_thumbnails` re-syncs each row's mode and opacity line (`layer_row_details_text`, #236). The blend row, the lock/filter row and the footer wrap in a narrow column (#96, #199; [right-docks.md](right-docks.md)).

While the list is open (#367, `PopupAwareComboBox`), the highlighted mode shows on every selected layer (`preview_layer_blend`, coalesced, async render) with no history entry, session revision or row refresh. Closing restores the modes before Qt reports a choice, which commits one entry; a history change, edit snapshot, or another document or selection closes the list and reverts (`ui_layer_blend_list_*`).

## Click selection

Layer-row click selection (`LayerListWidget::eventFilter` for row widgets, `viewportEvent` for bare viewport; keep the two branches in step): plain click selects one layer (collapse from a multi-selection is deferred to release so drags work), Ctrl-click toggles the row, Shift-click selects `currentRow()`..target replacing the selection, and Ctrl+Shift-click adds that range (`select_range_to_item`'s `additive` flag). The Ctrl branch is tested first, so a Ctrl-click on a thumbnail loads it as a selection instead (next section).

### Thumbnail menus and selection loads

A Ctrl-click (Cmd on macOS) on a content, mask, vector-mask or Smart Filter mask thumbnail loads that part as a selection and leaves the rows alone; Shift adds, Alt subtracts, Shift+Alt intersects (`thumbnail_click_selection_operation`, #433). `MainWindow::load_layer_part_selection` (main_window_layer_thumbnails.cpp) runs the canvas load, then `combine_selection_coverage` against the selection before it, in one history step. While Ctrl (Cmd) is held over any of those thumbnails, it shows `load_selection_pointer_cursor` (tool_cursors.cpp: an arrow with a dashed box holding a plus, minus or cross for Shift, Alt, Shift+Alt; #480, #525). `SelectionLoadCursor` (shared with Channels rows) sets it from mouse moves and Ctrl, Shift and Alt presses and releases (the key folded into the event's modifiers, `QCursor::pos()` for the place); the Alt clip cursor wins (`ui_layer_thumbnail_ctrl_hover_shows_selection_cursor`). A right-click on a pixel layer's content thumbnail opens `layerThumbnailMenu` (Select Pixels, Add, Subtract, Intersect, `layerThumbnailExportMenu`, Thumbnail Size, Thumbnail Display; #432, #462, #481); on a raster or vector mask thumbnail, `layerMaskThumbnailMenu` or `layerVectorMaskThumbnailMenu` (Disable/Enable, the Layer menu's Delete and Apply or Rasterize actions, the four mask loads, `layerThumbnailExportMenu`, Thumbnail Size, Thumbnail Display; #431, #462, #481), after making the row the active layer. Folder, adjustment and Smart Filter mask thumbnails keep the full menu. The fx badge opens `layerFxBadgeMenu` (Copy, Paste, Delete Layer Style, the master eye's switch; #473), the smart object badge `layerSmartObjectBadgeMenu` ([smart-objects.md](smart-objects.md); #474), for the row its left click picks. Tests: `ui_layer_thumbnail_*`, `ui_layer_mask_thumbnail_right_click_opens_mask_menu`, `ui_ctrl_click_layer_*`, `ui_layer_*_badge_right_click_*`.

### Move tool on the canvas

The Move tool's canvas-side layer selection (Ctrl/Shift/Alt clicks, Auto-Select, the selection rectangle, off-canvas drags) is in [move-tool.md](move-tool.md#layer-selection-from-the-canvas); the panel-side rules follow.

The canvas requests panel selection changes through `CanvasWidget::set_layer_selection_requested_callback` -> `MainWindow::select_layers_in_layer_list` (the panel stays the source of truth and pushes the result back via `set_selected_layer_ids`); `activate_layer`'s single-id path still collapses to one row by design. The host reveals selected children of collapsed folders and clears a name filter that would hide selected layers. Rectangle drawing and pending modifier clicks live in `canvas_widget_move.cpp` (tests: the `ui_move_` filter).

### Deselected state

"No selected rows and no active layer" is a resting state. `MainWindow::deselect_all_layers` (Select > Deselect Layers, `select.deselect_layers`, no default key) clears the selection model under a `QSignalBlocker` (`clear()` emits `selectionChanged` first), calls `Document::clear_active_layer`, resets the canvas edit target to Content and pushes an empty selection to the canvas; `refresh_layer_list` keeps the state since a null active layer selects no row. A plain Escape reaches it from the canvas (the last branch of `CanvasWidget::keyPressEvent`: every cancel above it keeps priority and a live drag keeps the selection) and from the focused layer list (`LayerListWidget::set_escape_callback`). An empty id list from the canvas is deselect-all in `select_layers_in_layer_list`. Deselect writes no history entry; undo restores the earlier active layer. A blank-area click empties the list selection (Qt keeps the current row): `set_active_layer_from_selection` deselects all, transform box included. Tests: `ui_move_escape_deselects_layers_without_gesture`, `ui_move_empty_click_and_rectangle_deselect_layers`, `ui_move_deselect_layers_clears_panel_rows_and_active_layer`, `ui_layer_panel_blank_click_deselects_and_hides_transform_box`. Select > All Layers (`select_all_layers`, `select.all_layers`, Ctrl+Alt+A; #479) selects every row but the Background, keeping the active layer if selected (`ui_select_all_layers_*`).

One-layer documents: with no active layer, a command or tool that needs one selects the only layer (`only_layer_id`). Commands call `MainWindow::select_only_layer_if_none_active` right before reading their target (after any Quick Mask or channel-view refusal), new layer commands too; canvas tools get it from `begin_edit`, the reporting `can_begin_pixel_edit`, Magic Wand, Quick Select and the Auto-Select-off Move drag. Delete Layer and the panel's opacity, blend and lock controls are deliberately left alone. Test: `ui_move_deselected_only_layer_is_selected_on_demand`.

### Range selection and the selected count

Range selection normalizes selected ancestors in one const traversal (`root_drop_layer_ids`),
keeping the requested order, rejecting missing ids. Target styles repolish only on change;
slow selection shows the delayed **Selecting layers...** message. The selection handler
and single-layer reveal path show the selected layer count on the status bar, one const
traversal touching neither selection nor history: a selected folder counts itself and every
descendant (hidden, locked, collapsed, or filtered-out included), a selected parent and child
never count a layer twice (`ui_layer_selection_count`).

## New adjustment layers

Clipping controls and row badges use `effective_clip_base`: pixel layers and
folders can host a clipped run. Adjustments clipped above a folder affect its
merged content. The folder itself cannot be a clipped member.

Every New Adjustment Layer entry inserts directly above the topmost selected row, so
inside a selected child's folder or above a selected folder. With no selected rows, the active layer is the anchor, else the document
top. Live previews use the same placement and keep the original active layer. Accepting
selects the new adjustment and records one undo step; cancelling removes the preview
without changing the selection or history.

New adjustments always carry an enabled raster mask: an active pixel selection
supplies its coverage (black outside), else the mask is white across the canvas and
outside it. Previews and committed layers share it in `main_window_adjustments.cpp`.
Tests: `ui_adjustment_layer_inserts_above_selection_with_white_mask`,
`ui_adjustment_layer_preview_uses_topmost_selection_and_cancels_cleanly`, and
`ui_hue_saturation_creates_masked_adjustment_layer` (selection masks).

## Color labels

A layer's color label (#244) is `Layer::color_label()`, Photoshop's `lclr` index (0 none, 1 to 7 the colors; constants and permanent ids in `core/layer.hpp`). It is not an edit to pixels, so it moves no revision, and locked layers take one. The row shows it as `layerRowColorStrip`, a 4 px strip at x 0 of `layerMainRow` inside the base indent, off the layout and transparent to the mouse, created only for a known nonzero label; QSS paints it from the `layer_color_*` theme roles through its `layerColor` property. Layer > Color (`layerColorMenu`) and the row's context menu (`layerContextColorMenu`) share the `layerColor*Action` actions (hotkey ids `layer.color_<id>`), built by `populate_layer_color_actions`; `set_selected_layers_color` labels the selected rows, groups included, as one undo step, and `refresh_layer_color_action_states` checks the common label (none for a mixed selection). Scripts: `layer.colorLabel`. PSD rules in [ps-compat.md](ps-compat.md). A right-click in the main row's eye column (the eye and the strip left of it) opens `layerEyeColorMenu` (`show_layer_eye_color_menu`): Hide/Show This Layer, Show/Hide All Other Layers (the Alt-click `isolate_layer_visibility`), Show All and Hide All Layers (`set_all_layers_visible`, every depth), outside history (#407), then the color actions (#276). Pinned by `ui_layer_color_labels_menu_undo_and_row_strip`, `ui_layer_eye_right_click_opens_color_menu` and `ui_layer_eye_menu_*`.

## Disclosure arrow, double-click, visibility eye

The folder disclosure arrow (`layerFolderDisclosureButton`) toggles one folder, Alt-click also its nested folders, and Ctrl+Alt-click sets every folder to the clicked folder's new state (`MainWindow::toggle_all_layer_folders_expanded`). Empty folders toggle too (#229), empty artboards included (`ui_artboard_empty_artboard_disclosure_toggles_and_saves`). A `ClickModifierRecorder` filter (`click_modifier_recorder.hpp`) records the modifiers (`clicked` carries none); the handler defers (`QTimer::singleShot(0)`): the toggle rebuilds the rows. Runtime expand state is the session's `collapsed_layer_groups`: metadata seeds it at open; saves, recovery and smart-object commits write it back (`DocumentSession::document_for_write`). A toggle is not an edit.

Double-clicking a row opens its editor (layer styles, or an adjustment's settings; shape rows open layer styles too; the vector badge opens Shape Appearance), except on the name label and the thumbnails: a layer mask or vector mask thumbnail targets that mask and opens Mask Properties, Density and Feather (`set_mask_thumbnail_double_click_callback`, deferred past the event; [vector-tools.md](vector-tools.md#vector-mask-ui)). Every row button (eye, mask link, vector mask link, the fx, smart-object, vector and clipping badges, the Smart Filter and effect-row buttons) must be listed in `layer_row_button_owns_clicks` in `layer_list_widget.cpp`, or the list eats the press as a row drag start and routes the double-click to the row's editor (`ui_layer_vector_badge_double_click_opens_shape_appearance`). The name's text extent edits in place (Photoshop; empty space right of a short name opens the editor): `LayerListWidget::begin_inline_rename` swaps `layerRowName` for a `QLineEdit` (`layerRowNameEdit`) in the label's slot at its height and font. Return and focus loss commit, keyed by layer id so a click on another row still renames the edited one; Escape cancels before the list's Escape-to-deselect; the commit runs deferred through `MainWindow::apply_layer_rename` (one undo step; empty or unchanged names record nothing). `refresh_layer_list` cancels an open editor before clearing rows; a queued commit is dropped when the list's session stamp changed (ids restart per document). Rename Layer (menu, context menu, F2) enters the same editor when the active layer's row exists and is the only selected one, else the rename dialog (`ui_layer_row_name_double_click_renames_inline`, `ui_layer_rename_hotkey_enters_inline_edit`, `ui_layer_inline_rename_*`; dialog-opening tests double-click `layerRowDetails`). The content thumbnail routes to `MainWindow::zoom_canvas_to_layer_content`, which fits the view to the layer's alpha-trimmed bounds (`move_layer_outline_bounds`, else `layer_render_bounds`, a folder's descendant union) via `CanvasWidget::zoom_to_document_rect`. Text thumbnails enter inline editing with all text selected, keeping zoom and pan (the callback defers past the thumbnail event and checks the session); adjustment thumbnails open their settings (`ui_layer_thumbnail_double_click_zooms_canvas_to_layer`).

The visibility eye (`layerVisibilityCheck`) does not toggle through its QToolButton on real mouse input: `LayerListWidget::eventFilter` eats the press first. A plain press toggles on press and starts a visibility sweep (dragging along the eye column paints the first toggle's state across crossed rows, skipping disabled eyes; `setSelection` is suppressed while sweeping so the drag cannot rubber-band the selection). The sweep grabs the mouse on the persistent viewport (toggling a folder rebuilds every row and destroys the pressed eye, losing Qt's implicit grab). A pointer at or past the top or bottom edge sweeps to that edge (no column test) and autoscrolls; each step moves the last swept point with the rows and sweeps again (#407, `ui_layer_eye_sweep_autoscrolls_past_the_list_edge`). Release, even outside the list, ends the grab and the scrolling; losing capture, hiding, disabling or deactivating the viewport cancels the sweep. `ui_layer_eye_sweep_survives_folder_row_rebuild` must route input through Qt's window system (direct viewport moves miss the lost-capture bug). An Alt press calls `MainWindow::isolate_layer_visibility` (named in the eye's tooltip, #549): every other layer hides, the second Alt-click restores the per-session snapshot, and any other visibility change drops it. Both handlers defer (`QTimer::singleShot(0)`; folder toggles rebuild rows); the button's `toggled` serves programmatic `click()`. Visibility is not undoable. The G'MIC preview sets `set_visibility_only` (eyes and scrolling; [gmic.md](gmic.md)). Plain eye changes queue a coalesced immutable-snapshot render and keep the previous canvas frame visible, so rendering cannot interrupt the sweep. Inherited folder-control states rebuild through the normal row path. See [interactive-previews.md](interactive-previews.md#visibility-render-waits).

## Effect rows

A layer with any effect instance, hidden ones included, lists them under its row like Smart Filters (#256): a "Layer Styles" header (`layerEffectsRow`) with a disclosure arrow (`layerEffectsDisclosureButton`) and the master eye (`layerEffectsVisibilityButton`, `LayerStyle::effects_visible`), then, while open, one `layerEffectEntryRow` per instance in the dialog's category order (`layer_effect_rows`, main_window_shared.cpp) with its eye (the instance's `enabled`), name and Edit pencil (`layerEffectEditButton`); a row double-click does the same without turning it on (`edit_layer_effect`). The Smart Filters header leads with its own arrow (`layerSmartFiltersDisclosureButton`, #361). Effects start closed (`DocumentSession::expanded_layer_effects`; an effect added by the dialog or Paste Layer Style opens them, `reveal_layer_effects`), Smart Filters open (`collapsed_smart_filters`; an added filter opens them in `commit_smart_filter_stack_edit`). A toggle is no edit. Both save the folder way: `collect_initial_layer_fx_disclosure` seeds them from `patchy.layer_fx_expanded`, `document_for_write` writes them back; PSD has one bit per layer for both lists ([ps-compat.md](ps-compat.md)), so a layer reopens with both open when either was. Master eye off: effect eyes keep their state, draw dimmed (`layerEffectEyeDimmed`) and still toggle. Right-click: `layerEffectContextMenu` (Edit, Hide/Show, Delete via `delete_layer_effect`; routed by `show_layer_context_menu`). Each change is one undo step through `apply_layer_effect_row_edit`, which drops the preserved lfx2 bytes; a locked layer shows the rows read-only. Effect and Smart Filter rows are indented by the arrow's drawn width and the row spacing (`kNestedEyeIndent`), so every nested eye shares the headers' eye column and every nested name starts under "Layer Styles" (#349; `ui_layer_effect_rows_align_under_the_layer_styles_eye`). Hidden instances keep the fx badge and survive a PSD save (the `present` rule in [layer-effects-render.md](layer-effects-render.md)). Tests: tests/ui/layer_effect_rows_tests.cpp, `psd_layer_style_hidden_effects_round_trip`, `psd_layer_fx_expanded_flag_round_trips`.

## Layer commands: delete, duplicate, drags to other documents

Delete Layer (menu, footer button, Delete key, trash drop) runs `MainWindow::delete_layers`: it activates the sibling below the lowest deleted root, else the one above, else its group (issue 249). The footer button goes through `delete_from_layers_panel`: with one layer selected and its raster or vector mask the edit target, it deletes that mask instead; a raster mask on a pixel layer that Apply Layer Mask accepts asks first (`deleteLayerMaskPrompt`: Apply, Delete, Cancel; #441, `ui_layer_footer_delete_removes_targeted_mask`).
