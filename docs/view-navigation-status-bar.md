# Status-bar zoom and info fields

Split from [view-navigation.md](view-navigation.md): the status-bar zoom box (`ZoomPercentEdit`, src/ui/zoom_status_bar.hpp) with its presets menu and Fit button, the document info field, and the selection readout.

## Zoom box, presets and Fit

Status-bar zoom controls (GitHub issue 159): `statusZoomControls` groups the box, whose trailing chevron (`statusZoomPresetsAction`, a QLineEdit trailing action like an options-bar field's) opens `statusZoomPresetsMenu` upward (800% down to 12.5%, the current zoom checked, actions marked `kViewNavigationActionProperty`), with `statusZoomFitButton` (Fit), positioned by `ZoomStatusBar` as one left widget and disabled with no document. Over the box the wheel and Up/Down step the zoom ladder (`next_zoom_ladder_step`); a horizontal drag that starts on the unfocused box scrubs (`kScrubFactorPerPixel` per pixel, right = in, SizeHor cursor), while a click without travel focuses it for typing (IBeam). The MCP input guard lets the group through as navigation. Tests: `ui_status_bar_zoom_percent_box_edits_zoom` (typed values, the 12800% clamp, Escape), `ui_status_bar_zoom_box_wheel_scrub_and_buttons`. The box shows two decimals below 100%, one below 1000% and none from there up (`format_zoom_text`, GitHub issue 237); that is display only, and Enter or focus loss on the unchanged text commits nothing, so the view keeps its exact zoom. `refit_to_font` sizes the box on polish, font, style and action changes: the widest five-digit or fractional value spelled with the font's widest digit, plus the frame and the chevron's reservation (QLineEdit's `PM_LineEditIconSize` + 6 + `PM_LineEditIconMargin`), with a negative right text margin so the text runs up to the chevron's button instead of stopping at the frame padding. Test: `ui_status_bar_zoom_box_fits_large_values`.

## Document info

Status-bar document info (GitHub issues 202 and 206): `statusDocumentInfoLabel` (`StatusDocumentInfoLabel`, src/ui/status_document_info.{hpp,cpp}) follows Fit inside `statusZoomControls` and shows one line for the active document, hidden with none open: dimensions, resolution (px/cm when resource 1005 says so, both axes when they differ), then color mode and depth (`1920 × 1080 px · 72 ppi · RGB 8-bit`; CMYK Proof or Indexed as they apply). It is Patchy's own design: no click-to-choose readout menu and no setting. A `statusInfoSeparator` line (a 7 px `QFrame::VLine` in `@status_field_border`) sits on each side and shows and hides with the field. The field has one fixed width for every document (GitHub issue 206 follow-up), so the status message after it starts at the same x across tab switches: `reserved_text_width` measures a sample line built from the same translated strings (`10000 × 10000 px · 300 ppi · CMYK Proof 16-bit`) in the field's font, plus the 2 px QSS padding a side, recomputed on font, style and language changes. The line is centered in that width (GitHub issue 502), so a shorter one leaves equal room before each separator. A longer line is elided at its end (the tooltip has it all). The field may reach a third of the way across the bar; when even the sample does not fit, the field narrows, trailing parts drop off whole and the dimensions always stay (it refits on `ZoomStatusBar::resized`). The tooltip holds the whole line, the color profile (the kept ICC description, the working CMYK profile in CMYK Proof, or None) and memory use, the byte sizes of every layer pixel buffer, raster mask and document channel (never a flatten). `MainWindow::refresh_status_document_info` runs from `refresh_document_info`, the image mode and bit-depth action refreshes, File Info and Strip Metadata. Fit's padding is 1 px a side, so Fit's text sits evenly between the box and the separator, and Fit's text and a full-width info line sit the same 8 px from the separator between them. Tests: `ui_status_bar_document_info_*` (facts per mode and depth, tooltip, narrow bar, active document and Image Size, fit at 1366 px, one width across documents with separators and the line centered).

## Selection readout

Status-bar selection readout (GitHub issue 355): `statusSelectionInfoLabel` (`StatusSelectionInfoLabel`, same files) follows the document info field and shows the selection's bounding box as `X: 40  Y: 30  W: 200  H: 100 px`, in the ruler unit (`view/rulerUnits`; physical units per axis through the document resolution, Percent against the document's extent, the unit once after H). It is shown only while there is something to measure: `CanvasWidget::selection_readout_rect` gives the live shape's bounds during a marquee, Lasso, Polygonal or Magnetic Lasso gesture, else the selection region's bounding rect (live during a selection move). That reads `QRegion`'s stored extents and the gesture's points, never the selection mask, so `MainWindow::refresh_status_selection_info` runs from every canvas info emit (`update_canvas_info`) and from `refresh_status_document_info` (tab switches, closing, ruler-unit changes). While shown the field only grows, so the status message beside it holds still during a drag; hiding resets it. Test: `ui_status_bar_selection_info_follows_selection`.
