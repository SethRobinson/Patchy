# Patent research: prompt-driven image generation (OpenAI Image Tools)

Engineering record behind the "Prompt-driven image generation" entry in [legal-constraints.md](legal-constraints.md#prompt-driven-image-generation) (review dated 2026-11-06; claims read on the USPTO page scans and Google Patents; expiry dates are Google's adjusted estimates or filing date plus term adjustment). Design: [openai-images.md](openai-images.md). Conventions follow [patent-research.md](patent-research.md).

## What Patchy does

The OpenAI Image Tools dialog sends a text prompt, and optionally up to 16 reference images, to OpenAI's hosted Images API and inserts what comes back as ordinary pixel layers. The image generation network runs on OpenAI's servers; Patchy builds the request (prompt text the user typed, PNG-encoded pixels, size, quality, background, frame count) and places the result. Patchy keeps no generative layer type: results are plain pixel layers with no stored prompt, seed, variants or input reference that could regenerate them. The layer name holds the prompt's first words as a label, which nothing reads back.

Built: Create (a prompt, optional reference images, no mask, no selection input; transparent or opaque background), Edit (named Fill until 2026-11-06) and Remove (re-checked 2026-11-06, below: the user's selection is the only region input; the visible image around it goes with background opaque; Remove sends no reference images and Edit may (Seth's decision, 2026-11-06, under US 12573004 above); Remove sends a mask from the selection and a fixed instruction; Edit sends a markup overlay instead, a red outline drawn just outside the selection, and the user's prompt with fixed instructions appended, or a fixed instruction when it is empty; the result is a pixel layer with a layer mask made from the selection, and nothing is detected in it). Expand (re-checked 2026-11-06 against US 12626423, US 2025/0124626, US 12579606 and US 12608858 below: the new canvas comes only from the pixels the user types for each side, with no list of aspect ratios; it only grows, never crops part of the image in the same operation, and never rotates; the prompt is the user's or a fixed instruction; the user picks the tab). Animate (re-searched 2026-11-06, below): a prompt, optionally with one still image and no mask, returns an animated GIF from OpenAI, whose frames become plain layers of a new document. Expand's frame can also be dragged outward; it never goes inside the image. Describe (2026-11-06, below): the visible image or active layer goes to a text model and the description is shown as text only.

## Active patents and what each independent claim needs

- **US 12462456 B2** (Adobe, "Non-destructive generative image editing", filed 2023-06-05, granted 2025-11-04, 273 days PTA, to about 2044-03; also AU 2024201638 B2). Claims 1 and 13 (methods) and 17 (apparatus) all need: a selection input identifying a portion of a first image on a first layer of a multilayer document; a second image generated from the first image and an input mask from that selection (claim 1 adds the text prompt, claim 13 a contextual taskbar generate button); **generating a subject mask by detecting an object in the second image**; and a layers window showing the first layer and a second layer element presenting the second image and that subject mask. Dependent claims add storing the prompt, input mask, seeds or variants as properties of the second layer and a generative layer window. Patchy's Generate has no selection input and no input mask, so its transparent background option is outside every one of these claims. A future Edit takes the layer mask only from the user's own selection and Patchy never detects an object in the result. Decision for Edit and Remove as built (2026-11-06): a selection-masked request does not ask for a transparent background; it asks for `opaque`. Open for later: whether it may. OpenAI would then return the generated content with alpha around it, the closest Patchy comes to the subject-mask element. The differences: the alpha arrives inside the returned pixels, not as a separate mask element; any detection runs on OpenAI's servers, not in Patchy; and OpenAI does not publish whether it makes the alpha by detecting an object after generation or generates it directly.
- **US 12573004 B2** (Adobe, "Generative image filling using a reference image", filed 2023-11-21, granted 2026-03-10, 150 days PTA, to about 2044-04). Claim 1: an input image, a mask indicating a region of it, a reference image and a text prompt; encoding the reference and the prompt; a composite image with input-image content outside the mask and reference content inside it. Claim 11: the reference inserted into the input image by the mask before generation. Claims 1 and 11 both need the mask together with the reference. **Claim 15 (apparatus) has no mask element**: an image encoder that encodes a reference image, a text encoder that encodes the prompt, and an image generation model that makes a composite image from an input image and both encodings. In Patchy's design the encoders and the generation model are OpenAI's hosted service; Patchy's code contains none of them and sends PNG images and prompt text. A reference added from the active layer works in effect as an input image, so the difference from claim 15 is where the claimed components run, not the shape of the request. Built: reference images never go with a mask (Remove sends none). Decision (Seth, 2026-11-06): Edit sends reference images with its markup outline, the claim 1 and 11 combination of input image, region indication, reference and prompt. The reasoning recorded with it: Patchy sends an image, an outline overlay (not a mask) and text; the encoding of the reference and the prompt and the generation of the composite (every step after receiving) run on OpenAI's servers, as claim 15's encoders and model do; Patchy contains none of them.
- **US 12530821 B2** (Adobe, "Neural compositing by embedding generative technologies into non-destructive document editing", granted 2026-01-20). Claims 1, 12 and 17: an original image, a scene graph describing its elements and a description of a modification; updating the scene graph from the description; generating the modified image from the updated scene graph. Patchy builds no scene graph or element description of the document; the request carries only the user's prompt and pixels. Never derive a description of the layer stack or document elements and send it with a request.
- **US 12626423 B2** (Adobe, "One-click image extension with quick mask adjustment", granted 2026-05-12, to about 2044-09). Claims 1, 9 and 17: a target aspect ratio chosen from **a plurality of candidate aspect ratios corresponding to a fixed set of output aspect ratios of a generative neural network**, the image positioned in a frame of that ratio, a mask created automatically from the ratio and position, and an extended image generated. Expand as built takes the new canvas size only from the pixels the user types for each side, offers no list of aspect ratios, and derives the request size from that canvas (`fit_request_size`), never offering it as a choice.
- **US 12579606 B2** (Adobe, "Generative AI inferred prompt outpainting", granted 2026-03-17, to about 2044-02). Claims 1, 12 and 19: a prompt generated from the image by a prompt generation network, including a term from the camera-setting metadata, then an expanded image. Patchy never generates or completes a prompt from image content or metadata, and request images are PNGs encoded from pixels with no camera metadata.
- **US 12608858 B2** (Adobe, "Image generation with multiple image editing modes", granted 2026-04-21, to about 2043-12). Claims 1, 10, 14: identifying a mask type from predetermined types and selecting an inpainting or outpainting mode of a multi-mode network by that type. Patchy never chooses a command or mode from the mask's shape; the user picks the command.

## Published applications (watch items)

- **US 2025/0124626 A1** (Adobe, "Generative expand in image editing applications", pending). Claims 1 and 13: a frame including a region inside the image and a region outside it **and excluding a third region inside the image** (crop and extend in one operation); claim 18: the image at an oblique angle to the frame. ## Edit and Remove re-check (2026-11-06)

Adobe-assignee searches for generative remove, object removal with diffusion and user selection, and generative fill with an empty prompt, plus the claims of the closest results:

- **US 12333691 B2** (Adobe, infill semantic map, to about 2043-07). Claims 1, 7 and 13: a semantic map of the image's pixel classes, a generative semantic model making an infill semantic map for the region, and an image model generating from that map. Patchy builds no semantic map and sends none; the request carries pixels, a mask from the user's selection and prompt text.
- **US 12333692 B2** (Adobe, multi-layered scene completion, to about 2043-01; claims read on the USPTO scan). Claims 1, 5 and 12: a segmentation network's object or occluder masks, which object occludes which, completing the occluded object with a diffusion model, then moving or deleting the front object. Patchy segments nothing and works out no occlusion; Remove fills the user's selection.
- **US 12260530 B2** (Adobe, human inpainting, to about 2043-02; USPTO scan). Claim 1: a structure guidance map of a detected human, encoders and a parameter network producing local appearance tensors, a human inpainting GAN. Patchy detects no person and builds no structure map.
- US 12462456 (above): Edit and Remove have the selection input and input mask; the result layer's mask is the selection captured at the click, grown and feathered by the user's Edge blend amount (a fixed dilation and feather, never computed from the result), and Patchy detects no object in the result. That layer mask is the claims' input mask carried onto the layer, not their subject mask, which is generated by detecting an object in the second image. Edit's markup overlay (2026-11-06) is the same selection input drawn as an outline instead of sent as a mask: it carries no information beyond the user's selection, Patchy runs no model on it, and the reading above holds for it. A limited search for annotation- or markup-guided generative editing (web search; Espacenet full text for annotation with overlay, text prompt and generative edit, and Adobe-assignee annotation with generative prompt and region) found no claim on a user drawing an outline that guides a hosted model's edit; the hits were model-internal training and generation methods Patchy does not perform. Re-check if OpenAI's markup feature becomes the subject of a patent notice. AU 2023233182 B2 ("Image and object inpainting with diffusion models") was found but its claims were not read (Google Patents refused fetches); its US family was not identified.

## Describe check (2026-11-06)

Describe sends a metadata-free PNG of the visible image or the active layer to an OpenAI text model with a fixed instruction and shows the reply in a read-only box. Seth chose text only (2026-11-06): Patchy never copies the description into a prompt or sends it with an image request. Against the record: US 12579606 needs a prompt generated from the image (with a camera-metadata term) that then drives outpainting; Describe produces no prompt and drives no generation, and sends no metadata. AU 2023206192 (prompt expansion by language models) needs phrases generated from the user's query; Describe has no query. US 12530821 describes document elements as a scene graph; Describe sends flattened pixels. A limited Espacenet search (Adobe; "description of the image", "language model", "image editing", 2022 on) found difference captioning between two images or a series of edited versions (US 12579831 B2, US 2026/0024304 A1, claims not read): Describe captions one image as it is now and never compares versions or sends the edit history. Re-check before adding a way to send the description to a generation request.

## Animate full color (2026-11-07)

Animate's Full color asks OpenAI for the frames as one PNG sheet (a prompt, optionally one still image and references, never a mask) and cuts it into equal panels that become layers. A limited search (web search for generating animation frames as a sprite-sheet grid and splitting it; Espacenet now answers with a bot check) found product documentation and research on sheet-then-split workflows, and US 12639876 B2 (Fusion Holdings, "Graphical animation with image generation enhancements", granted 2026-05-26; claims read from a non-verbatim Google Patents listing, the USPTO scan has no text layer): its independent claims 1, 13 and 20 need invertible mappings of an avatar's parts into an image atlas, inverted to build a second avatar's atlas; Patchy has no parts, no stored mappings and no inversion, only a fixed grid cut of one generated image. US 12573124 (above) still holds: the sheet starts from a still image or a prompt, never from frames of an existing animation. Re-check if the sheet route ever generates from an existing animation's frames.

## Animate re-search (2026-11-06)

Google Patents refused fetches, so the search ran on Espacenet (full text: "animated image" with "text prompt" and "frames"; "animated GIF" with generative or diffusion and "still image"):

- **US 12573124 B2** (Figma, "Progressive real-time diffusion of layered content files with animated features", granted 2026-03-10). Claims 1, 17 and 19: layers of a content file; animation metadata describing how an animating element in a child layer moves; a parent layer holding an image-guided content generation modifier; animation frames generated from that metadata; the modifier applied to those frames in parallel; the results shown as an animation in a preview beside the canvas. Patchy keeps no animation metadata and no generation modifier on a layer, and applies no generation to frames it made; one request returns the frames, which become plain layers. Never add a feature that runs generation over each frame of an existing animation without a new review.
- US 2026/0051101 A1 (Adobe, garment animation with attention map correction) and US 2026/0112104 A1 (Huawei, photorealistic frames by radiance-field diffusion): model-internal methods for specific content; Patchy runs no model.
- No claim was found on asking a hosted service for an animated GIF and placing its frames on layers. The sheet layout and frame slicing happen on OpenAI's servers.

## Seam handling, variations and the Animate wrapper (2026-11-06)

What changed: Expand (2026-11-06) sends its frame with no mask; its layer covers the original to a depth the user's Blend slider sets and then fades over a fixed width, with the same per-channel mean tone offset; nothing in that geometry is computed from the image content. Edit and Remove dilate the selection mask (the request's by 3 bands; the result layer's mask by 0 to 2 bands with a Feather of 0 to 1 band, set by the user's Edge blend slider), and shift the result's color channels by their mean difference from the original on a ring outside the changed area; an Active layer target writes the same composite into the active pixel layer. Variations stay in the dialog and swap the result layer's pixels; nothing about them is stored in the document. Animate wraps the user's motion text in fixed English sprite-sheet instructions.

- **US 2026/0253186 A1** (Adobe, "Advanced framework for simulating and correcting generative inpainting artifacts", pending, priority 2025-02-27; read on Espacenet). Claims 1, 9 and 16: a generative inpainting model's result, then a neural network-based refiner model that corrects artifacts around the inpainted border (claim 16 adds training it with a color space transformation model). Patchy runs no network on the result: a fixed dilation, a fixed gaussian-like feather and one mean offset per color channel. Watch item: re-read if granted, and never add a learned border refiner without a new review.
- Espacenet full-text searches for color matching or harmonization of inpainted or generated regions at their boundary found model-based harmonization (diffusion networks) and nothing claiming a fixed statistic, dilation or feather. Gradient-domain (Poisson) blending of the result stays out without a new review, as the content-aware fill entry keeps it out of Patchy's own inpainting.
- **AU 2023206192 B2** (Adobe, generative prompt expansion; claims read on Espacenet). Claims 1, 8 and 14: a causal language model generating additional phrases from tokens of the user's query and a masked language model inserting a phrase at a target location. Animate's wrapper is constant text with the user's words appended, generated by no language model; Edit's and Remove's fixed instructions likewise.
- US 12462456 (above): the variation picker is in the dialog, not a contextual taskbar over a generative layer, and every independent claim there needs a subject mask detected in the result, which Patchy never makes.

## Other filings looked at

- US 12387402 B2 (Bosch and Carnegie Mellon, localized text-to-image via cross attention): model-internal attention; Patchy sends no per-region prompts or location masks.
- US 12437456 B2 (IKIN, personalized advertising images): not related to editing.
- OpenAI's own `revised_prompt` is server-side and not shown back as a new prompt.

## Limits and watch items

- Adobe-assignee keyword searches on Google Patents (priority 2020 on) plus the citations of the filings above; other holders were not searched, and applications under 18 months old are unpublished. Google Patents, Justia and FreePatentsOnline refused automated fetches part way through; US 12573004, US 12530821 and US 12462456 were read from the USPTO page scans.
- A change to any tab needs a design re-check against this list. A new review comes before: any mask derived from result content, a transparent background in a selection-masked request, reference images combined with a mask, a generative layer that stores its prompt or variants for regeneration, or an aspect-ratio list taken from model output sizes.
