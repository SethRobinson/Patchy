# Canvas right-click menu

How the canvas context menus are built and which commands each one offers. Tool behavior lives in [tools.md](tools.md); the transform sessions in [free-transform.md](free-transform.md), the Crop tool in [crop-tool.md](crop-tool.md), text editing in [text-tool.md](text-tool.md).

**Design rule (GitHub issue 323, decided November 3, 2026):** every entry is a command Patchy already has, under its existing name and in an order that follows Patchy's own menus and options bars. Another editor's menus (screenshots in issues included) are never a spec: no copied set, order or grouping, nothing that only exists there. Each new menu must stand on its own usability merits ([legal-constraints.md](legal-constraints.md#canvas-context-menus)).

The right mouse button on the canvas is the context-menu button and never pans (Seth's decision); panning is the middle button, the spacebar, the Pan tool, and the pen barrel button, which `dispatch_tablet_as_mouse` synthesizes as a middle-button drag. Alt+Right stays the brush adjust drag, a right-click on a ruler stays the unit menu, and the MCP activity overlay pans only with the middle button or Space.

- A right press records `context_press_pos_` (also during a transform session, not during a drag) (cleared by tool, lock, document, and focus changes through `close_canvas_context_menu`, and by a drag past `startDragDistance`); a release within that distance calls `CanvasWidget::show_canvas_context_menu`, the one canvas menu builder. Path tools get `canvasPathContextMenu` ([vector-commands.md](vector-commands.md)).
- Everything else gets a popup `canvasContextMenu` built from sections, each the host's own QActions (enable state and hotkeys carry over; nullptr = separator). No section, no menu. In order: the Move tool's layers-under-the-pointer entries ([move-tool.md](move-tool.md#move-tool-layer-menu)); with the Zoom or Hand tool, anywhere on the canvas, `set_zoom_tool_context_actions_callback` (the View menu's Zoom In, Zoom Out, separator, Fit on Screen, Actual Pixels, 200%; GitHub issues 300 and 323; a right-click never zooms out, Alt+click does); with the Crop tool, `set_crop_context_actions_callback` (next section); on the selection, `set_selection_context_actions_callback` (Remove Object, Select Object where Object Selection ships, Fill, Clear, Stroke, Free Transform, Transform Selection, Deselect, Inverse; an action an earlier section holds is listed once); with a selection tool other than Patch and Content-Aware Move on the document but off the selection, the selection-tool section (`set_selection_tool_context_actions_callback`: Select Subject, Select Background, Remove Background, skipped while hidden, as in builds without the subject model; [ai-selection.md](ai-selection.md)) and, while a selection exists, the selection section without its first group (Remove Object, Select Object; GitHub issue 105); when it landed inside the bounds of the ACTIVE vector shape layer (any tool but the path tools, edit lock off), `set_shape_context_actions_callback` (Shape Appearance..., Free Transform..., Simplify Path..., separator, Define Custom Shape from Path, Rasterize; an inactive shape gets no section, the Move entries activate it first); for any other active leaf layer, Free Transform (a text layer adds a separator and the Type menu's Convert to Shape and Create Work Path, GitHub issue 598) through `set_layer_context_actions_callback`, only with the Move tool, inside the layer's Move outline (`move_layer_rect_contains_document_point`), and with its position not effectively locked (painting tools keep a right-click on a raster layer menu-free). Last, after the pasteboard section below, a full-screen mode adds Exit Full Screen anywhere on the canvas (`set_screen_mode_context_actions_callback`, `canvasExitFullScreenAction`; [screen-modes.md](screen-modes.md)).
- A press on the pasteboard starts a tool only from the allowlist in `CanvasWidget::mousePressEvent` (`allows_off_canvas_press`): Move, the selection tools, Patch, Crop, Zoom, the off-canvas brush family, and since 1.12 the shape tools (Rectangle, Ellipse, Line, Polygon, Custom Shape) and Text, as in Photoshop. A shape or text box may then hang partly off the canvas; a pixel-mode shape clips to the document on commit (`ui_shape_and_text_drags_start_off_canvas`). Any other tool's press outside the document does nothing.
- A click outside the document (the pasteboard) appends the backdrop-color section (`add_backdrop_color_menu_entries`, issue 47): Default, Black, Dark Gray, Medium Gray, Light Gray, White, then Select Custom Color... (Patchy's picker, live preview on every window, Cancel restores the previous choice), radio-checked. The host owns it as `view/canvasBackdropColor` (`MainWindow::set_canvas_backdrop_color_preference` pushes it through `apply_canvas_aid_settings` into `CanvasWidget::set_backdrop_color_override`; the key exists only for a user color); `CanvasWidget::backdrop_color()` paints the pasteboard and the overlay-preview base (the theme role when unset). Scroll bars keep their theme roles.
- **Lifetime:** the popup menu must outlive the dispatch of the click that picked an entry (an entry's modal dialog nests an event loop inside that dispatch, and a `deleteLater` posted there frees the menu under Qt's mouse handler). Hiding only retires the menu (`retire_canvas_context_menu`); `QMenu::triggered`, emitted after the handler returns, posts the deferred delete, and dismissed menus are reaped by the next menu at the same `QThread::loopLevel()` (`reap_retired_context_menus`). Never `deleteLater` a canvas menu from a hide path or a nested loop (`ui_stroke_selection_from_context_menu_survives_following_mouse_input`).
- Coverage: `ui_canvas_backdrop_context_menu_sets_color`, `ui_zoom_tool_context_menu_offers_view_zoom_commands`, `ui_right_drag_does_not_pan_canvas`, `ui_selection_context_menu_offers_remove_object`, `ui_selection_tool_context_menu_offers_subject_commands`, `ui_shape_context_menu_offers_shape_commands`, `ui_move_context_menu_offers_free_transform_on_raster_layer`, `ui_move_layer_menu_preserves_pan_and_cancels_stale_clicks`, `ui_path_context_menu_edits_anchors`, `ui_pen_barrel_button_pans_instead_of_painting`.

## Session menus (GitHub issue 323)

- **Transform session** (Free Transform, Transform Selection, Warp, path transform): a right-click opens a menu with this section alone (`set_transform_session_context_actions_callback`, `MainWindow::transform_session_context_actions`); the right-click itself neither applies nor cancels. Apply and Cancel (`transformContextApplyAction`, `transformContextCancelAction`: the options bar's check and X, or commit/cancel of the path transform), then Edit > Transform's Scale, Rotate, Skew, Distort, Perspective and Warp (Warp left out where it would refuse: selected pixels, Transform Selection, several layers), then for Free Transform the box's own Rotate 180, Rotate Right, Rotate Left, Flip Horizontal and Flip Vertical (`rotate_free_transform_session`, `flip_free_transform_session`: a session step through `set_transform_controls_state` about the reference point, never the layer commands). A path transform offers Apply and Cancel only.
- **Crop session** (`MainWindow::crop_context_actions`): Apply (`commit_crop_session`, enabled by `crop_session_has_changes`) and Cancel (`reset_crop_session_to_canvas`, enabled by `crop_session_can_reset`; Patchy's Cancel is the Esc reset, so there is no separate Reset), then in Ratio style the Ratio preset list (`cropContextRatioAction<index>`, radio-checked to the combo; picking one sets the combo; Custom shows only while current, disabled). Other sections (selection, pasteboard color) follow as usual.
- **Text editing:** the inline editor (`InlineTextEdit::contextMenuEvent`) keeps Qt's own text menu (Undo, Redo, Cut, Copy, Paste, Delete, Select All, translated by the qtbase catalogs) and appends the Type menu's Convert to Shape and Create Work Path. Both finish the edit, which deletes the editor, so the menu (`inlineTextEditorContextMenu`) is reparented to the window and deletes on close.
- The context-only actions have no hotkey ids and no menu-bar place, so Search Commands does not list them; their texts are existing strings (Apply, Cancel, Image > Rotate & Flip's names).

Coverage: `ui_transform_session_context_menu_applies_and_cancels`, `ui_crop_context_menu_offers_apply_cancel_and_ratios`, `ui_hand_tool_context_menu_offers_view_zoom_commands`, `ui_text_editor_context_menu_offers_outline_commands` (tests/ui/layer_context_lifecycle_tests.cpp).
