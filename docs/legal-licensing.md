# Binding licensing, format, trademark and asset constraints

Split from [legal-constraints.md](legal-constraints.md) (feature boundaries from the patent records). Read before touching a file format, codec, dependency, bundled asset, trademark use or the GEGL bundle. Format and codec records: [patent-research-formats.md](patent-research-formats.md).

## Format, copyright, trademarks, and assets

- The root [LICENSE](../LICENSE) covers Patchy's own application code. [Third-Party Notices](../NOTICE-THIRD-PARTY.md) identifies vendored code and assets, including local changes to upstream components. When a binary distribution requires a notice, include the full text in that file or ship it with the component. Keep each copyright holder's own notice even when two components use the same license.
- **Open from Clipboard** makes only an unsaved in-memory raster document ([clipboard.md](clipboard.md)); never extend it to automatic clipboard-to-file/cloud storage or shortcut-bound destinations.
- PSD interoperability comes from observed output of a licensed Photoshop, never decompilation. Never copy verbatim Adobe specification text into the repository; link to it. Use self-authored fixtures only and never support the undocumented PSDC cloud format.
- "Smart Object(s)", "Smart Filter(s)", "Filter Gallery", and "PSD" are not Adobe trademarks in the reviewed record. PHOTOSHOP is registered and policed. Use referential language ("compatible with Adobe Photoshop"); never put Adobe marks in Patchy's name, icons or branding, and keep README.md's Trademark Notice.
- **Shortcut sets** (Preferences > Hotkeys; decided 2026-11-04; [hotkey-sets.md](hotkey-sets.md)): which key runs which command is a functional fact (Lotus v. Borland, 1st Cir. 1995: a command hierarchy and its keystrokes are a method of operation; in the EU, SAS Institute v World Programming, CJEU 2012). Each built-in set is Patchy's own command-id-to-key table (and, for GIMP-style and Krita-style, which tool gestures use Ctrl) taken from the other program's published user documentation or from the running program's UI and output, with the pages used listed in hotkey-sets.md. Never copy or read GIMP's `menurc`/`shortcutsrc`, Krita's shipped `.shortcuts` files, either program's source, or Adobe `.kys` files, and never copy documentation text. Set names are referential only ("Photoshop-style"): no logos, and no other program's marks in Patchy's name, icons or branding.
- Bundled art never comes from AI image generation. Acceptable sources: code generation, or real photography/human artwork under a commercially compatible license, preferably CC0. Each third-party asset gets a `NOTICE-THIRD-PARTY.md` entry, shipped losslessly. Poly Haven textures and [game-icons shapes](vector-tools-custom-shapes.md#bundled-game-iconsnet-shapes) are human-made.
- HEIC/HEIF decoding must use a platform or browser-provided HEVC decoder. Native builds keep their platform-codec paths; Linux dlopens the distro's libheif and its HEVC plug-in at run time and ships nothing (never bundle libheif in the AppImage). The browser build may statically link the vendored libheif container parser and its WebCodecs adapter, but every software HEVC codec backend and HEVC encoder must remain disabled. Never vendor or link libde265, x265 or another HEVC decoder/encoder, and never add HEIC encoding. The WASM CMake option block, the runtime `VideoDecoder.isConfigSupported()` check, and the distribution obligations in `NOTICE-THIRD-PARTY.md` are binding. See [heif.md](heif.md).
- JPEG XR decoding and encoding must use Windows' in-box Imaging Component codec. Never vendor or link jxrlib, libjxr, or another JPEG XR codec, and never add a JPEG XR path to a non-Windows build, without a new review ([jxr.md](jxr.md)).
- PQ and HLG are decode-only: no PQ/HLG encoding, HDR10+ or Dolby Vision metadata, adaptive display tone mapping, or gain maps without a new review.
- AVIF may ship in-process AV1 codecs: libavif 1.4.2 over dav1d 1.5.4 (decode) and libaom 3.15.2 (encode), BSD-2; libaom's AOM Patent License 1.0 text is in `NOTICE-THIRD-PARTY.md`. Conditions: no other AV1 encoder (SVT-AV1, rav1e) or AV2/avm code without a new review; pinned, unmodified releases with LICENSE files. Design: [avif.md](avif.md).
- JPEG 2000 (ISO/IEC 15444-1), OpenEXR and Radiance HDR may ship in-process codecs: OpenJPEG (BSD-2) for JPEG 2000 Part 1 only, tinyexr (BSD-3) for OpenEXR, Patchy's own RGBE for HDR. Conditions: Part 1 only (no Part 2 extensions, no HTJ2K beyond what OpenJPEG's decoder carries, no JPIP), library sources only with LICENSE files beside them and `NOTICE-THIRD-PARTY.md` entries, no deep or multi-part EXR. Upgrades need a new licence read.
- JPEG XL may vendor libjxl (engineering read). Conditions, all binding: (1) a pinned upstream release with no algorithmic changes (Google's `PATENTS` grant covers only "this implementation"); build and symbol-namespace changes are fine, and the libjxl `LICENSE` and `PATENTS` text plus Highway (BSD-3 election), Brotli and skcms/lcms2 notices go in `NOTICE-THIRD-PARTY.md`. (2) Libraries only: no tools, plug-ins, or system codec discovery. (3) The encoder runs with patches and dots off (`JXL_ENC_FRAME_SETTING_PATCHES` and `_DOTS` = 0), and Patchy must not enable any path that classifies image regions as photographic or not to pick lossy versus lossless coding per region (Cloudinary US 12,243,274, to about 2043, outside Google's grant). (4) Never restructure the ANS decoder so symbol output is conditional on a state sufficiency test or the state update is deferred to the next iteration, and never add a per-stream flush/re-initialize flag (Microsoft US 11,234,023 and its pending continuation US 2022/0109891). (5) A libjxl upgrade that changes `PATENTS`, or a newly exposed encoder feature, needs a new review. Use "JPEG XL" only as the format name; no JPEG committee logos.
- Shipping dependencies must allow commercial distribution. GPL tools may make fixtures if never linked or shipped. OpenRaster (.ora) and GIMP .xcf come from their published descriptions (linked, never copied) and the apps' output; Krita's .kra (read only) only from files Krita writes ([kra.md](kra.md)). For file formats, never read or copy Krita, GIMP, GEGL, libkra or other XCF readers' source; names only, no logos. Patchy's own GEGL has its own rule ([below](#gegl-operations-through-a-helper)).
- No Photoshop SDK code or Adobe-created assets may enter this repository or a Patchy binary. The only exception is the self-authored, non-Adobe regression material in `test-fixtures/psd/`. The classic filter plug-in ABI that the legacy `.8bf` host speaks (`src/plugins/host/legacy_filter_abi.hpp`, `src/plugins/pipl.cpp`) is Patchy's own declaration, written from the public plug-in documentation and real plug-ins' observed behaviour: layouts, selector numbers and callback signatures are interoperability facts, but no SDK header, sample, resource template or documentation text may be copied into it or any later addition. The `.8bf` files under `local-test-fixtures/photoshop-plugins/` are third-party test data, never committed, linked into or shipped.

## GEGL operations through a helper

Decided 2026-11-02. Design: [gegl-filters.md](gegl-filters.md); every source consulted, with dates and what was taken from it: [gegl-provenance.md](gegl-provenance.md), kept current with each change. This rule replaces, for GEGL only, the format rule's "never read GEGL source" clause above with the narrower one below. Patchy hosts no GIMP plug-ins and never loads an installed GIMP's libraries (a GIMP 3 plug-in bridge was built on the GEGL branch and removed the same day; its rule is in the branch history).

- **Only the helper loads GEGL.** `patchy-gegl-host`, a separate process Patchy starts, loads Patchy's own GEGL, babl and GLib libraries (the package's bundle) at run time and runs one operation per call. Patchy itself, and every other Patchy binary, loads none of them; Patchy talks to the helper over pipes (pixels and plain settings only).
- **GPL-3 operations are opt-in, and Patchy opts in.** GEGL loads its GPL-3 operations only when the program sets GeglConfig's documented `application-license` to "GPL3", as GIMP does. The helper sets it when Patchy passes `--gpl3` (always, today); dropping that flag limits Patchy to GEGL's LGPL operations.
- **Patchy's own GEGL ships with its GPL-3 module, and with its source** (decided November 2, 2026; replaces the LGPL-only rule of that night). Packages may bundle GEGL and babl (LGPL-3+, GEGL's `gegl-common-gpl3` module GPL-3+), GLib and json-glib (LGPL-2.1+), libiconv and libintl (LGPL-2.1+), libffi, PCRE2 and zlib (permissive), built from upstream release tarballs and MSYS2 packages by `scripts/dev/gegl/`, as separate libraries the helper loads (no technical measure stops a user replacing them), with every license and `licenses/SOURCES.txt` in the package. The one modification: the operations `PATCHY_GEGL_DROPPED` names (`scripts/dev/gegl/common.sh`) are removed from GEGL's build lists by file name before the build, so their code never ships ([gegl-filters.md](gegl-filters.md#legal-review)); the edit may match a build list line by file name but never opens or reads an operation source, and `SOURCES.txt` states it. Every release publishes the complete corresponding source next to its binaries on GitHub, wherever else they are offered too: `PatchyGeglSources.zip`, built from `sources.lock` ([gegl-filters.md](gegl-filters.md#sources)), and the rtsoft.com Flatpak repository serves the same zip beside it ([below](#scanner-and-camera-libraries-in-the-flatpak)); a release without it must not ship a GEGL bundle. Why Patchy stays MIT: Patchy and the helper are separate programs talking over a pipe in Patchy's own small protocol (pixels and plain setting values, no shared internal structures), which the FSF treats as two programs, not one; the helper, which does load the GPL-3 module into its own process, is MIT, a GPL-compatible license, and its source is public in the release tag.
- **Allowed sources: interface facts.** GEGL's, babl's and GLib's installed public headers (function signatures, struct layouts, enumeration and type constants: what the helper declares for itself), their published API documentation, and what the operations report about themselves at run time (`gegl_operation_list_properties`, `gegl_operation_get_key`). **Never read** GEGL or babl source (`.c` files, operation sources), GIMP's or a GIMP plug-in's; no function body is copied, translated or paraphrased. Header use is noted in `NOTICE-THIRD-PARTY.md`.
- **Operations are offered from an allowlist by rule** (`gegl_operation_offered` in `src/ui/gegl_filters.cpp`): image filters with one input and one output, minus the excluded names there. Before an operation is promoted or ships in a release, check it against [legal-constraints.md](legal-constraints.md) like any filter; the excluded names cover the healing, inpainting and red-eye records.
- **Names.** Describe the feature as GEGL filters (nominative use); no GIMP or GEGL artwork, and nothing of GIMP in Patchy's name, icons or branding.

## Scanner and camera libraries in the Flatpak

Decision of 2026-11-05 (PR #648): keep the Flatpak libraries bundled and publish their source. Design: [import-scanner.md](import-scanner.md).

- **What ships.** Only the Flatpak we publish (`PatchyLinux.flatpak`, `PatchyLinuxArm64.flatpak` and the rtsoft.com Flatpak repository) builds sane-backends and libgphoto2 from the pinned release tarballs its manifest names, unmodified (configure options only). The AppImage and native builds use the system's copies and ship neither; never bundle them there without a new decision.
- **Licenses.** sane-backends is GNU GPL version 2 or later. Most of its backends, and `libsane` itself (the `dll` backend), add SANE's exception that permits linking without affecting the program's license; its `LICENSE` file says not every backend applies it, so treat the backends as plain GPL-2+. libgphoto2 is GNU LGPL version 2.1 or later. Both texts ship in `share/licenses/com.rtsoft.patchy/` (`sane-backends-COPYING.txt`, `sane-backends-LICENSE.txt`, `libgphoto2-COPYING.txt`).
- **In Patchy's own process.** Patchy loads both with `dlopen` (unlike GEGL, which only its helper loads). Whether run-time loading of a GPL backend makes Patchy and the backend one combined work is not settled; the terms hold either way, since Patchy's MIT license is GPL-compatible and Patchy's complete source is public under the release tag. Never add a license or term to Patchy that is incompatible with the GPL while the Flatpak carries SANE.
- **Source with every Flatpak release.** GPL-2 section 3 and LGPL-2.1 section 4 require the corresponding source with the binaries. `scripts/release/make-linux-scanner-sources.ps1` (run by `release-linux.ps1`) packs the exact tarballs the manifest names, checked against its SHA-256, with any file or patch the modules use, the manifest, and a README naming the Patchy version, into `PatchyLinuxScannerSources.zip`; `publish-github-release.ps1` uploads it beside the bundles and links it in the notes, and refuses a release without it, with one older than the bundles, or with one whose archives differ from the manifest's. The Flatpak carries a pointer to the source (`scanner-SOURCES.txt`).
- **The rtsoft.com repository offers the source from the same place** (GPL-2 section 3). `scripts/release/upload-flatpak-repo-to-rtsoft.bat` uploads `PatchyGeglSources.zip` and `PatchyLinuxScannerSources.zip` to `rtsoft.com/flatpak/sources/` before it swaps in the new repository, and refuses to update the repository without both. The repository keeps only the latest commit, so only that release's zips stay there. A release that cannot publish the zips must not ship a Flatpak with these modules.
- **Keep the source as long as the binaries.** Never delete a GitHub release's source zips while its bundles stay downloadable there.
- **Version bumps.** A new sane-backends or libgphoto2 version is a manifest edit; the zip follows it, since the script reads the modules from the manifest. A patch added to either module must be a `type: patch` or `type: file` source in the manifest so the script packs it.

## Text recognition models

License facts read at the source on 2026-11-16 (design: [ocr.md](ocr.md); binding entry: [legal-constraints-scanning.md](legal-constraints-scanning.md#text-recognition)).

- **PP-OCR (the one downloadable engine, decided 2026-11-16).** PaddleOCR's code is Apache-2.0 (`LICENSE` in `github.com/PaddlePaddle/PaddleOCR`, "Copyright (c) 2016 PaddlePaddle Authors"; no NOTICE file). Each official ONNX model repository (`huggingface.co/PaddlePaddle/<name>_onnx`) declares `license: apache-2.0` in its metadata and holds `inference.onnx` plus `inference.yml` (preprocessing config and character dictionary); none holds a LICENSE file, and neither the repositories nor the PP-OCRv6 paper describe the training data. Terms for shipping: rehost the files unchanged, pinned by repository commit and SHA-256 (the commit is the record of the license declaration); save the Apache-2.0 text beside the downloaded models; name PaddlePaddle and the source repositories in `NOTICE-THIRD-PARTY.md` and `third_party/ai-models/MODEL-LICENSES.txt`; state any modification (none planned: `inference.yml` is parsed as shipped). **Pinned 2026-11-17**, each repository declaring `license: apache-2.0` at that commit: `PP-OCRv6_small_det_onnx` `28fe5895`, `PP-OCRv6_small_rec_onnx` `b8f84f0b`, and the `<script>_PP-OCRv5_mobile_rec_onnx` repositories `korean` `5c6f574b`, `cyrillic` `2cef8814`, `eslav` `9a32171f`, `el` `8152b89d`, `th` `1d4adbba`, `devanagari` `251aec19`, `ta` `0db89798`, `te` `f1197c83`. The full commits and every file's SHA-256 are in `scripts/setup-ai-deps.ps1` and `.sh`, which fetch them into development trees under Patchy's file names (`ppocr_*.onnx`, and each recognizer's `inference.yml` as `ppocr_*.yml`); the bytes are unchanged. Not fetched: the two orientation classifiers and the Arabic recognizer. The in-app download (2026-11-17) fetches the same files from the `ai-models-4` release, or from those repositories at those commits, with `ppocr_LICENSE.txt` beside them: the Apache License 2.0 text from `github.com/PaddlePaddle/PaddleOCR` at commit `b9da97be` (11376 bytes). Every offer of the download names PaddlePaddle and the license; `NOTICE-THIRD-PARTY.md` carries the notice.
- **National Diet Library recognizer (not shipped; evaluated 2026-11-17 at commit `a25d4564`, where it read vertical Japanese far better than PP-OCR: [ocr-benchmark.md](ocr-benchmark.md)).** `github.com/ndl-lab/ndlocr-lite` states "this program" is published under CC BY 4.0; its PARSeq recognizer code is Apache-2.0; its dependency file places the layout detector's weights under Meta's DINOv3 License, and the README asks users of the bundled models to follow it. The README does not address the recognizer weights or commercial use separately. Before any use: a written confirmation from the library that the recognizer weights alone are CC BY 4.0, credit to the National Diet Library, and a dated decision. The layout detector is never used.
- **manga-ocr (not shipped; same condition).** The model card (`huggingface.co/kha-white/manga-ocr-base`) declares Apache-2.0 and the dataset Manga109-s. Manga109-s permits commercial use of machine learning results and requires that its use "be indicated clearly" when a pre-trained model is published; redistributing the dataset is forbidden. The synthetic training data's fonts and backgrounds are not named, and the author has made no statement on commercial use of the weights. Before any use: a note to the author, the Manga109-s line in the notices, a separate optional download, and a dated decision.
- **Not used**: EasyOCR's pretrained weights (no license stated for them), YomiToku (CC BY-NC-SA).
- **The operating system's engine** (Windows.Media.Ocr) is called through its public API; nothing of it is redistributed.
- **The font behind invisible PDF text** (`/PatchyHiddenText`, [pdf-searchable-text.md](pdf-searchable-text.md)) is built by Patchy's own code from the TrueType table layouts (`src/formats/pdf_hidden_text_font.cpp`, 276 bytes, one square glyph). No other project's font file, glyphless or otherwise, is read, copied or adapted, so it carries no third-party license.
