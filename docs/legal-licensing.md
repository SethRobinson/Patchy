# Binding licensing, format, trademark and asset constraints

Split from [legal-constraints.md](legal-constraints.md) (feature boundaries from the patent records). Read before touching a file format, codec, dependency, bundled asset, trademark use or the GIMP 3 plug-in host. Format and codec records: [patent-research-formats.md](patent-research-formats.md).

## Format, copyright, trademarks, and assets

- **Open from Clipboard** makes only an unsaved in-memory raster document ([clipboard.md](clipboard.md)); never extend it to automatic clipboard-to-file/cloud storage or shortcut-bound destinations.
- PSD interoperability comes from observed output of a licensed Photoshop, never decompilation. Never copy verbatim Adobe specification text into the repository; link to it. Use self-authored fixtures only and never support the undocumented PSDC cloud format.
- "Smart Object(s)", "Smart Filter(s)", "Filter Gallery", and "PSD" are not Adobe trademarks in the reviewed record. PHOTOSHOP is registered and policed. Use referential language ("compatible with Adobe Photoshop"); never put Adobe marks in Patchy's name, icons or branding, and keep README.md's Trademark Notice.
- Bundled art never comes from AI image generation. Acceptable sources: code generation, or real photography/human artwork under a commercially compatible license, preferably CC0. Each third-party asset gets a `NOTICE-THIRD-PARTY.md` entry, shipped losslessly. Poly Haven textures and [game-icons shapes](vector-tools.md#bundled-game-iconsnet-shapes) are human-made.
- HEIC/HEIF decoding must use a platform or browser-provided HEVC decoder. Native builds keep their platform-codec paths; Linux dlopens the distro's libheif and its HEVC plug-in at run time and ships nothing (never bundle libheif in the AppImage). The browser build may statically link the vendored libheif container parser and its WebCodecs adapter, but every software HEVC codec backend and HEVC encoder must remain disabled. Never vendor or link libde265, x265 or another HEVC decoder/encoder, and never add HEIC encoding. The WASM CMake option block, the runtime `VideoDecoder.isConfigSupported()` check, and the distribution obligations in `NOTICE-THIRD-PARTY.md` are binding. See [heif.md](heif.md).
- JPEG XR decoding and encoding must use Windows' in-box Imaging Component codec. Never vendor or link jxrlib, libjxr, or another JPEG XR codec, and never add a JPEG XR path to a non-Windows build, without a new review ([jxr.md](jxr.md)).
- PQ and HLG are decode-only: no PQ/HLG encoding, HDR10+ or Dolby Vision metadata, adaptive display tone mapping, or gain maps without a new review.
- AVIF may ship in-process AV1 codecs: libavif 1.4.2 over dav1d 1.5.4 (decode) and libaom 3.15.2 (encode), BSD-2; libaom's AOM Patent License 1.0 text is in `NOTICE-THIRD-PARTY.md`. Conditions: no other AV1 encoder (SVT-AV1, rav1e) or AV2/avm code without a new review; pinned, unmodified releases with LICENSE files. Design: [avif.md](avif.md).
- JPEG 2000 (ISO/IEC 15444-1), OpenEXR and Radiance HDR may ship in-process codecs: OpenJPEG (BSD-2) for JPEG 2000 Part 1 only, tinyexr (BSD-3) for OpenEXR, Patchy's own RGBE for HDR. Conditions: Part 1 only (no Part 2 extensions, no HTJ2K beyond what OpenJPEG's decoder carries, no JPIP), library sources only with LICENSE files beside them and `NOTICE-THIRD-PARTY.md` entries, no deep or multi-part EXR. Upgrades need a new licence read.
- JPEG XL may vendor libjxl (engineering read). Conditions, all binding: (1) a pinned upstream release with no algorithmic changes (Google's `PATENTS` grant covers only "this implementation"); build and symbol-namespace changes are fine, and the libjxl `LICENSE` and `PATENTS` text plus Highway (BSD-3 election), Brotli and skcms/lcms2 notices go in `NOTICE-THIRD-PARTY.md`. (2) Libraries only: no tools, plug-ins, or system codec discovery. (3) The encoder runs with patches and dots off (`JXL_ENC_FRAME_SETTING_PATCHES` and `_DOTS` = 0), and Patchy must not enable any path that classifies image regions as photographic or not to pick lossy versus lossless coding per region (Cloudinary US 12,243,274, to about 2043, outside Google's grant). (4) Never restructure the ANS decoder so symbol output is conditional on a state sufficiency test or the state update is deferred to the next iteration, and never add a per-stream flush/re-initialize flag (Microsoft US 11,234,023 and its pending continuation US 2022/0109891). (5) A libjxl upgrade that changes `PATENTS`, or a newly exposed encoder feature, needs a new review. Use "JPEG XL" only as the format name; no JPEG committee logos.
- Shipping dependencies must allow commercial distribution. GPL tools may make fixtures if never linked or shipped. OpenRaster (.ora) and GIMP .xcf come from their published descriptions (linked, never copied) and the apps' output; Krita's .kra (read only) only from files Krita writes ([kra.md](kra.md)). For file formats, never read or copy Krita, GIMP, GEGL, libkra or other XCF readers' source; names only, no logos. Hosting GIMP 3 plug-ins has its own rule ([below](#gimp-3-plug-in-hosting)).
- No Photoshop SDK code or Adobe-created assets may enter this repository or a Patchy binary. The only exception is the self-authored, non-Adobe regression material in `test-fixtures/psd/`. The classic filter plug-in ABI that the legacy `.8bf` host speaks (`src/plugins/host/legacy_filter_abi.hpp`, `src/plugins/pipl.cpp`) is Patchy's own declaration, written from the public plug-in documentation and real plug-ins' observed behaviour: layouts, selector numbers and callback signatures are interoperability facts, but no SDK header, sample, resource template or documentation text may be copied into it or any later addition. The `.8bf` files under `local-test-fixtures/photoshop-plugins/` are third-party test data, never committed, linked into or shipped.

## GIMP 3 plug-in hosting

Decided 2026-11-01. Design: [gimp-plugins.md](gimp-plugins.md); every source consulted, with dates and what was taken from it: [gimp-plugins-provenance.md](gimp-plugins-provenance.md), kept current with each change. Code: `src/plugins/gimp/`. This rule replaces, for plug-in hosting only, the "never read GIMP source" clause above; the file-format rule there is unchanged.

- **Allowed sources: interface facts only.** (1) GIMP's installed public headers and the developer.gimp.org API documentation (libgimp, libgimpui, libgimpbase and siblings, LGPL-3). (2) The message layouts, enumerations and constants of libgimpbase's `gimpprotocol.h` and `gimpwire.h` (LGPL-3; section 3 allows a work to use a header's numerical parameters, data structure layouts and small macros in its object code, with notice: `NOTICE-THIRD-PARTY.md`). (3) Procedure names, argument lists and blurbs from GIMP's own Procedure Browser or PDB dump. (4) Files GIMP installs: `interpreters/*.interp`, `environ/*.env`, `gimprc`, the plug-in folder layout. (5) Traffic observed between GIMP's own programs or libraries and real plug-ins, including byte output of GIMP's LGPL libraries called at run time by a development tool that never ships.
- **Never read** GIMP's GPL application code (`app/`, including `app/plug-in` and `app/pdb`), any plug-in's source (GIMP's own and third-party GPL plug-ins alike), GEGL or babl source, or any libgimp/libgimpbase `.c` file. No function body is copied, translated or paraphrased; the codec, PDB table and tile server are Patchy's own code written from the facts above.
- **Nothing of GIMP ships or loads.** No Patchy binary loads a GIMP, GLib, GTK, GEGL or babl library, and no package bundles a GIMP library, plug-in, interpreter, Python, typelib or data file. Patchy finds the user's own GIMP 3 install and starts its plug-ins as separate programs that talk over the PDB pipe protocol; GIMP's LICENSE describes plug-ins that communicate through libgimp or another implementation of that protocol as mere aggregation, not a combined work. GPL plug-ins are installed by the user and run on the user's machine; Patchy distributes none.
- **Names and promotion.** Describe the feature as "GIMP 3 plug-ins" (nominative use of the GIMP name); no Wilber or other GIMP artwork, and nothing of GIMP in Patchy's name, icons or branding. Never advertise a named third-party plug-in in Patchy's UI, README, feature list or release notes (some synthesize patches, near the PatchMatch record in [legal-constraints.md](legal-constraints.md#filters-and-smart-objects)); the test results in [gimp-plugins.md](gimp-plugins.md) list what was tested, by GIMP's procedure names.
- A new source type, or reading anything outside the allowed list, needs a new decision recorded here first.
