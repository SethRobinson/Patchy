# OpenAI Image Tools

Plugins > Companions > OpenAI Image Tools via API Key (built-in) (`pluginsOpenAiImagesAction`, command `plugins.openai_images`, unbound; on wasm a [desktop-only command](wasm.md#desktop-only-commands)) opens a non-modal dialog that sends the user's prompt, and optional reference images, to OpenAI's Images API with the user's own API key. Each returned picture becomes a new pixel layer. The action belongs to MainWindow; `CompanionMenu::set_builtin_action` puts it at the top of the Companions submenu, above a separator, on every rebuild ([companions.md](companions.md#companions-menu)). Binding rules: [legal-constraints.md](legal-constraints.md#prompt-driven-image-generation) and its [record](patent-research-generative.md); read both before changing Edit, Remove, Expand or Animate. Naming follows OpenAI's brand page (openai.com/brand, "API Developers": identify the OpenAI technology truthfully, no OpenAI logo, no implied endorsement); no non-affiliation line is shown (Seth, 2026-11-06).

Code: `src/ui/openai_images.{hpp,cpp}` (request sizing, request and response bodies, key store, `openai::Client`), `src/ui/openai_images_dialog.{hpp,cpp}` (`OpenAiImagesDialog`), `src/ui/main_window_openai_images.cpp` (references from the document, layer insertion). Tests: `tests/ui/openai_images_tests.cpp`.

## Dialog

- **Config tab** (`ConfigTab`, the last tab, Seth's layout, 2026-11-06): the API key, Model and Quality, with a note that they apply to every image tab and that Describe always uses its own model. It has no action button; an action started with no key switches to it and says so (`take_api_key`).
- **API key** (on Config): a password field, Check Key (GET `/models`; a GPT Image 2.6 model the key cannot use is greyed out in the model list), "Remember the key on this computer", an info mark (`info_mark_icon`, shared with Clone Source) whose click shows `key_storage_note()` for the platform, and a "Create an API key" link. A remembered key lives in Windows Credential Manager (generic credential `com.rtsoft.patchy.openai`, user `api-key`) or the macOS keychain (generic password, service `com.rtsoft.patchy.openai`, account `api-key`); these names are persisted identifiers. Elsewhere (Linux, the Flatpak) the store is a plain file, `openai::key_file_path()` (`<per-user app data>/openai-api-key`, a persisted name; in the Flatpak under `~/.var/app/com.rtsoft.patchy/data`), written through `QSaveFile` with owner-only permission set before the key is written, deleted on untick. It is not encrypted: ticking Remember there shows the full path and that warning in the status line, and the info note says the same. `OPENAI_API_KEY` is read when nothing is remembered, on every platform. The key never goes into QSettings, logs or status text. Unticking Remember deletes the stored key at once.
- **Operation tabs** (`openAiImagesModeTabs`, `OpenAiImagesDialog::Tab`): Create, Edit, Remove, Expand, Animate, Describe, Config. The selected tab is filled with the accent, like the checked Variations button. The action button below is named after the tab. The prompt fields (Create, Edit, Animate) are five lines tall and Describe's text box eight (`size_prompt_edit`); they scroll past that.
- **Height** (Seth, 2026-11-06): the dialog stays shorter than the main window's smallest height (about 690 px), so it never covers more than the window it belongs to. Hidden pages ask for no height (`fit_tabs_to_current_page`: QTabWidget otherwise sizes to its tallest page), and on each tab switch the dialog takes the current tab's minimum height, at least 480 px (`fit_height_to_current_tab`, deferred one event-loop turn so the shown and hidden widgets settle). Paired controls share rows (Size and Background, Target and Edge blend, Animate's options in two columns, the reference buttons on the reference label's row with an Add menu). The theme's list rule sets a minimum height at polish time, so `ReferenceList` puts its fixed height back after each polish. At a text size other than 100%, `DialogPositionMemoryFilter` (dialog_utils.cpp, issue 495) grows a dialog to its layout's height for width after each layout change; QTabWidget counts every page there, so every tab grew to the tallest and fought the per-tab fit, leaving stale duplicated controls on screen (Seth, 2026-11-06). `CurrentPageTabWidget` reports the current page's height and no height for width, and the fit aims at the same height the growth computes. The dialog test runs at 115% text size and checks every tab against the main window's minimum height and that the height holds still afterwards.
- **Create tab**: the prompt (required, sent as typed; Patchy never completes or rewrites a prompt, and Animate's fixed wrapper below is the only added text), the reference images, size (Match the canvas, 1024x1024, 1536x1024, 1024x1536, chosen by the model) and background (transparent by default, opaque, auto).
- **Reference images** (`openAiImagesReferencesBox`, below the tabs, shown on Create, Edit and Animate): up to 16 thumbnails, each labeled with the number the prompt uses for it, in the order the request sends them (`number_references`): from 1 on Create, from 2 on Edit (the picture being edited is image 1) and on Animate when it starts from an image. The prompt placeholder gives an example ("the cat from image 1 wearing the hat from image 2"), following OpenAI's prompting guide, which names inputs by number. A small X in each thumbnail's top-right corner removes it (`ReferenceDelegate`); Remove removes the selected ones. Image files or image data dragged from outside (a file manager, a browser) onto the list are added like Paste adds them (`ReferenceList`, `add_references_from_mime`); `QListView::setMovement(Static)` turns the viewport's drop flag off, so it is set after. The Add menu's Add Layer renders the active layer alone (`render_layer_isolated`) cropped to its drawn pixels; Add Visible is the flattened canvas; Add File... reads any Qt-decodable file; Paste adds the clipboard's image, or the image files a file manager copied. Paste is greyed out while the clipboard offers neither (`QClipboard::dataChanged`). The platform's Paste keys (Ctrl+V, Cmd+V) do the same anywhere in the dialog except the text fields; in the prompt field, a clipboard with an image and no text goes to the references and text pastes as text. Patchy's hotkeys are application-wide, so `OpenAiImagesDialog::eventFilter` (on qApp) also accepts the ShortcutOverride for Select All, Copy, Cut, Paste, Undo and Redo in the dialog's text fields; otherwise Ctrl+A and Ctrl+C in the read-only Describe box selected and copied the canvas, and the next paste brought that image (Seth, 2026-11-06). The Describe box is selectable by keyboard as well as mouse. Each image is scaled so its long edge is at most 2048 px and re-encoded as a plain PNG with no metadata (`png_bytes`). With references the request goes to `/images/edits` as `image[]` parts; it has no `mask` part.
- **Shared options** (every request also sends `moderation: low`; settings `openAiImages/model`, `/size`, `/quality`, `/background`, `/count`; persisted keys): model and quality on the Config tab (GPT Image 2.6 only: `gpt-image-2.6-sunburst`, the default, and `gpt-image-2.6-flare`; a saved model the list lacks falls back to the default), quality (auto, low, medium, high), Variations 1 to 4 (one button per count, `openAiImagesCount<N>`), and for Edit and Remove a Target (`openAiImagesTargetCombo`, setting `openAiImages/target`: New layer or Active layer) and Edge blend (`openAiImagesEdgeBlendSlider`, setting `openAiImages/edgeBlend`, 0 to 100%, default 80%, Seth 2026-11-06; [Seams](#seams)).
- **The action button** (Create, Edit, Remove, Expand, Animate, Describe Image) shows the request while it runs: its text becomes "Creating...", "Editing...", "Removing...", "Expanding...", "Building animation..." or "Describing..." with a spinning arc icon drawn each 70 ms in the text role (`advance_spinner`), and a click on it does nothing until the request ends. The click paints that state at once with a "Preparing the request..." status (`generate` then `start_request`), since capturing the document and preparing the images come first, and the button returns if the action stops before sending (no selection, no key). The request body is built on a worker thread (`Client::post_prepared`, a `QThread::create` worker that deletes itself): encoding a 2000x1500 picture as PNG took about 0.6 s of the roughly 0.9 s before a request left (measured 2026-11-07). A request stopped or replaced while its body is built is never sent (`generation_`). Stop aborts the request (OpenAI may still bill one it started); closing the dialog stops it too (`done`). The status line counts the seconds, then reports the layers added and the tokens OpenAI used.
- **Notice** under the options: "Your prompt and any reference images are sent to OpenAI, and generations use your API key, so be careful as they cost real money."

### Errors

`openai::api_error_message` turns an API error into a plain line and `api_error_help` adds a link (shown after it in the status line, `show_error`) where an OpenAI page fixes it: a rejected key (401 or `invalid_api_key`; Manage API keys), an account out of credit (`insufficient_quota`; Add credit, the billing page), the spending limit (`billing_hard_limit_reached`; spending limits), a rate limit (other 429s), a safety refusal (`moderation_blocked`), organization verification (403 mentioning verification; organization settings), a model the key cannot use (404 or `model_not_found`) and OpenAI's own failures (5xx). Anything else shows OpenAI's message. Network failures and timeouts have their own lines. The client's messages are translated in the dialog's context; each call spells it literally so lupdate extracts them.
- Clipboard reads are user-invoked and land in the in-memory reference list. Against the two clipboard patents in [clipboard.md](clipboard.md#legal-review-2026-10-04): no file format or content-management item is created from the clipboard (US12099886B2), and no destination locations are stored against key sequences (US9396176B2); the upload to OpenAI happens only when the user clicks Create.

## Edit and Remove

Both work on the active document's selection (Marquee, Lasso, Object Selection, anything that selects). Without one, Remove says so and sends nothing, and Edit takes the whole canvas (`openai_masked_source(..., whole_when_none)`, Seth, 2026-11-06). `MainWindow::openai_masked_source` captures, at the click: the context region (`openai::context_region`: for Edit the selection's bounds grown by its longer side, at least 160 px, each way ([Edit lab](#edit-lab)); for Remove the whole canvas when it is at most 2560x1440's area (`kMaskedMaxPixels`), else the bounds grown by the larger of their longer side and a quarter of the canvas's; either clipped, grown toward 3:1, and the whole canvas once it covers half of it), the visible composite over it (`flatten_document_rgba8_rect`) and the selection's coverage over it. The model needs the scene: with only a small crop around a selected TV it painted a new apple picture over the TV instead of putting an apple on its screen (Seth, 2026-11-06). `openai::masked_edit_images` pads a region still outside 1:3..3:1 with transparent pixels, scales it to `fit_request_size` of the padded frame (the region's own resolution up to `kMaskedMaxPixels`, at least one megapixel), and makes a mask transparent wherever the coverage it is given covers any part of a pixel (padding stays opaque: kept). The request goes to `/images/edits` with the image as `image[]`, `background: opaque`, `complexity: low` (`kMaskedEditComplexity`: OpenAI's advice for focused edits; the default, high, plans more and changes more). Edit sends the reference images after the picture, as image 2 onward, and appends the fixed `kEditReferencesNote` to the prompt (Seth allowed them, 2026-11-06); Remove sends none (a mask never goes with references).

- **Edit** (named Fill before 2026-11-06) uses OpenAI's markup-guided edit, its documented way to change part of a picture with GPT Image 2.5 and 2.6: no mask, a `markup` part instead (`markup_overlay`: a transparent PNG at the request size with a solid red ring, 1/250 of the longer edge wide, just outside the selection), and the Edit tab's prompt followed by the fixed `kEditOutlineInstructions` (change only inside the red outline, keep the rest, remove the outline), or the fixed `kEditPromptWhenEmpty` alone. Where the selection reaches the context's edge, `masked_edit_images(..., markup_edge_pad)` adds transparent padding on that side (2% of the longer side, at least 8 px) so the ring lies off the picture, and the padding is cropped away with whatever red the model leaves there (red border lines at the canvas edges, Seth, 2026-11-06; probed live, the padded edit came back aligned). An Edit of the whole picture (nothing selected, or everything: `coverage_is_full`) sends no outline at all, the user's prompt (required then) with the fixed `kEditWholeInstructions`, and makes a plain layer with no mask and no Edge blend (a feathered mask would fade the canvas edges). With a mask instead, 2.6 repaints the masked area as a new picture (the TV test, probed live: markup kept the TV and showed an apple on it, a mask over the whole photo replaced the TV with an apple picture). The API refuses markup and mask together.
- **Remove** has no prompt field and sends the fixed `kRemovePrompt` with a mask: the selection dilated by 3 bands ([Seams](#seams)). Probed live with markup too: both removed the person; the mask kept an object that crossed the outline, which suits Remove. All three constants are English text in `openai_images.hpp`, never built from the image.
- Each returned image is scaled back to the padded frame, the padding cut away (`result_for_region`), tone matched (below), and cropped to `keep`, three bands past the selection, the most Edge blend can show. Target New layer: `MainWindow::add_openai_masked_layers` adds the result as a pixel layer over that area, above the selection's layer, with a raster layer mask (default color 0) and a render-time Feather as Edge blend sets them, as one undo step "OpenAI Image Tools"; the original stays underneath. Target Active layer: `openai_active_layer_region` captures the active layer's pixels over that area at the click (an unlocked pixel layer in an 8-bit document, else the dialog says to choose New layer), and `openai_write_into_layer` writes `blend_with_weight(original, result, weight)` into it as one undo step, the weight being the Edge blend mask feathered (`feather_coverage`); a layer with transparency grows to cover the region, an opaque one (a Background) stays opaque. Names: "OpenAI Edit", "OpenAI Edit: <prompt>", "OpenAI Remove". If that document or layer changed or closed meanwhile, nothing is written and the dialog says so.

### Edit lab

Measured live on 2026-11-07 (a scratch harness that rebuilt Patchy's Edit request and composite): three selections on 2000x1500 photos (a TV, a shirt, part of a woman's hair), each sent as the whole picture at low complexity, as a crop of the selection grown by its longer side at low complexity, and as the whole picture at medium complexity. The crop changed less around the selection (8 to 32 px outside: 5 to 7 levels against 7 to 12 for the whole picture) and came back sharper inside a small selection (the TV: 1.6 times the original's detail against 0.6), so Edit sends that crop (`context_region(..., tight)`) unless it would cover half the canvas. Medium complexity changed more outside every time and resized the TV. No run left red outline pixels. When the selection covers only part of an object (the hair), the model changes the whole object and the result stops at the selection's edge: select the whole object.

### Seams

The model redraws the whole frame it is sent, slightly shifted in tone and texture, so a hard mask at the selection edge shows a seam (a marquee's rectangle, Seth's apple test, 2026-11-06). With the band `seam_band` (4% of the selection's longer side, 4 to 32 px): Remove's request mask opens the selection dilated by 3 bands (`dilate_coverage`), so the model may change a margin around it (Edit's markup ring sits just outside the selection, and the model may change anything); the result shows through a mask that Edge blend sets (amount `a` from 0 to 1: `edge_coverage`, the selection dilated by `round(2 * band * a)`, with Feather `edge_feather`, `band * a`), so at 50% and above the transition lies inside the area the model was allowed to change and at 0% the result stops hard at the selection; and `match_tone` shifts the result's color channels by their mean difference from the original over `tone_ring`, a ring just outside the 3-band area where the model was told to keep the image. Edge blend applies to the current result as the slider moves (coalesced every 40 ms, `apply_edge_blend`): `openai_set_layer_mask` replaces the new layer's mask and Feather, or the Active layer target is composed again over the captured original, with no history step and the same revision check as a variation swap. It lets the user pull a wide feather back when the model's redraw past the selection does not match (Seth, 2026-11-06). Only these three: no network, no gradient-domain (Poisson) blending (docs/legal-constraints.md, "Prompt-driven image generation").

## Variations

Create, Edit, Remove and Expand make one result layer per request whatever the Variations count. Every image that came back stays in the dialog (`OpenAiImagesDialog::ResultSet`, never in the document) and the Results row (`openAiImagesResultsRow`, buttons `openAiImagesResult<N>` with thumbnails, shown for two or more) swaps another into the layer: `openai_replace_layer_pixels` for a new layer (same size, place and mask: `Layer::set_pixels` moves a layer to (0, 0), so the bounds are put back; no history step; Undo removes the layer), `openai_write_into_layer` for the Active layer target (composed over the captured original again). Picking one leaves the Variations count alone. The set ends at the next request, when the dialog closes, or when the layer's `content_revision` no longer matches the last write (an edit, an Undo, a closed document); the shown variation stays. Animate opens one document per variation instead.

## Results

For Create, `MainWindow::add_openai_generated_layers` inserts the first returned image into the document that was active when Create was clicked, above the selected layer, as one undo step ("OpenAI Image Tools"), and makes it active. "Match the canvas" scales each image to fit the canvas (aspect kept, smooth, premultiplied); the other sizes keep pixel size. Both center the layer (floor division, as Paste does). Pixels convert to the document's depth. Its name is "OpenAI: <prompt>", the prompt simplified and cut at 48 characters. `openai::placed_image` is the placement, shared with variation swaps. If that document closed meanwhile, or none was open, a new untitled 72 ppi document the first image's size holds them. Layers carry nothing else from the request: no generative layer type, no stored prompt, seed or variants (variations live only in the dialog).

## API facts this code relies on (probed 2026-11-06)

- Sizes for the GPT image models: edges divisible by 16, aspect 1:3 to 3:1, long edge at most 3840, area at most 3840x2160 (above 2560x1440 is experimental). A minimum pixel budget exists but is unpublished: 1024x512 was refused, 1024x640 accepted, so `kMinRequestPixels` is 1024x640. `fit_request_size` aims at the canvas's aspect with an area between 1024x1024 and 1536x1024.
- Schema checks (format, quality, background, n) run before the size check, so a bad size cannot be found without a real request.
- `gpt-image-2.6-flare` takes quality low, medium, high and auto only.
- `background: transparent` returns PNG with soft alpha. Masks on edits are a hint: the model redraws the whole frame, and on 2.6 it fills a mask with the prompt's subject as a new picture. `markup` (2.5 and 2.6 only) is a transparent PNG the size of the first image; not with `mask` or `prompt_rewriter`.
- `complexity` (low, medium, high; default high) is accepted by both endpoints. `moderation` is `low` or `auto` (the default); there is no off. Patchy sends `low` on every request (`kModeration`, Seth, 2026-11-06); multipart edits accept it although the spec lists it only for the JSON form (probed). Requests for well-known characters (Superman) are refused either way, as ChatGPT also does.
- GIF output (`output_format: gif`, `frame_count` 2 to 16, `frame_duration_ms` 20 to 2000) is drawn as one sprite sheet that must fit 3840 px, so frame size limits frame count (2 frames at 1024 needs a 4096x2048 sheet and is refused; 9 at 1024 is 3072x3072, over the pixel budget; 16 at 768 likewise). GIF frames have 1-bit transparency; GIF requests take no mask and no output compression.
- The Responses API takes `input` as one user message with `input_text` and `input_image` (`image_url` may be a base64 data URL) parts; the reply's `output` holds `reasoning` and `message` items, the text in `message` content parts of type `output_text` (there is no top-level `output_text` in the raw JSON). The key's Sol models (2026-11-06): `gpt-5.6-sol`, `gpt-6-sol`, `gpt-6.1-sol`.
- `PATCHY_OPENAI_BASE_URL` replaces `https://api.openai.com/v1` (tests use a local server; `Client::set_base_url` does the same in-process).
