# Options bar: shape tool rows

Split from [options-bar.md](options-bar.md), whose grouping rules these rows follow: the shape tools' bars, which share one Fill / Stroke row in Shape and Pixels modes and one Style row in every mode, and the path selection tools' bars.

## Shape tool rows

- The shape bars (Rectangle, Ellipse, Polygon, Custom Shape) read, in Shape mode: mode | [Fill only][Stroke only][Both] | Fill [swatch] | Stroke [width] [swatch] [dashes] [align] | Combine | the tool's own settings | Style and its size pair | [gear]. Line and Pen keep the older row: no draw-mode buttons, alignment list or Style, and W [link] H before Combine (GitHub issues 311 and 716; `vectorAppearanceButton`, an icon button whose tooltip and accessible name are Shape Appearance..., since the issue 556 follow-up gave its text width to the dash combo). The own group is Rectangle's Radius, Polygon's Sides and Star inset, Custom Shape's Shape (a folder-tree picker with search and a Shapes Manager... button, [vector-tools-custom-shapes.md](vector-tools-custom-shapes.md)), Line's Weight with the two arrowhead toggles (they also edit a selected line, GitHub #622), and Pen's Auto Add/Delete; Ellipse has none.
- Path Select and Direct Select share those groups and separators (GitHub issue 689). With an editable shape layer active: Fill [swatch] | Stroke [width] [swatch] [dashes] | W [link] H | Combine | Merge Shapes, Split Shapes | [gear]. With none the appearance and size groups hide, `stray_option_separators` drops their separators, and the bar reads Combine | Merge Shapes, Split Shapes (`ui_path_select_options_bar_groups_its_controls`).
- The Fill and Stroke swatches are framed `QToolButton`s (`optionsBarSwatch` QSS rule: the push-button colors, hover and pressed states) 38x26 with a 28x16 chip, drawn at the button's icon size by `options_bar_swatch_icon`. The Text bar's `textColorButton` is the same button showing a solid chip (GitHub issue 343).
- The dash combo (`vectorStrokeDashCombo`, GitHub issues 556 and 557; `ui_text_length(104)` wide, which still shows every built-in name in full: it gave 36 px to the draw-mode buttons and the alignment list, issue 716; only the popup widens to longer names) is the one stroke list, in Shape and Pixels modes, rebuilt by `rebuild_vector_stroke_dash_combo` when the saved list can have changed (Shape Appearance or the manager closing, a language switch): the built-in dash presets ([vector-tools-appearance.md](vector-tools-appearance.md)), a separator and the saved stroke presets ([style-presets-strokes.md](style-presets-strokes.md#shape-appearance-stroke-presets); item data `kSavedStrokePresetRow` + index), Custom, a separator and Manage Presets..., which puts the combo back on its entry and opens the Stroke Presets manager. A built-in applies to the selected shape layers at once, one undo step, with its caps and corners (`apply_stroke_dash_preset`, the dialog's rule), and seeds new shapes (`tools/vectorStrokeDashes`, a `stroke_dash_preset_token`). A saved preset (`apply_vector_stroke_style_preset`) sets Align, Caps, Corners, the dashes and the offset the same way and for new shapes (`current_vector_stroke_style_`, saved as `tools/vectorStrokeStyle`, a one-entry preset array); width and paint stay. Until one is picked, new shapes keep the dash preset and Inside alignment (a line: Center, [vector-tools-lines.md](vector-tools-lines.md#a-lines-stroke)); a later built-in pick changes only the dashes and the caps and corners it sets, and resets the offset. The combo shows the entry the selected shape (or the new-shape settings) matches, a saved preset (all fields) before a built-in, and that built-in becomes the one for new shapes; a pattern nothing matches shows Custom, which is hidden otherwise and cannot be picked (Shape Appearance edits it). Coverage: `ui_options_bar_dash_combo_applies_presets`, `ui_options_bar_dash_combo_lists_saved_stroke_presets`.
- No Stroke checkbox, here or in the Shape Appearance dialog (Seth, issue 311 follow-up): the width is the switch. The field shows 0 while the stroke is off and accepts 0 to turn it off; any other value turns it on. The model keeps `stroke.enabled` and the last real width (`set_vector_stroke_width_from_field`), so a PSD's vstk never carries a zero width, a PSD stroke that is off reads 0, and the saved `tools/vectorStrokeEnabled`/`vectorStrokeWidth` keys are unchanged. At 0 only `stroke.enabled` is applied to the selection, so each shape keeps its own width. On the tools with the draw-mode buttons a stroke that is off takes its whole group off the bar (below); on Line, Pen and the path selection tools the group stays, usable.
- Fill layers (Color, Gradient or Pattern fill: no path, or a disabled one; `shape_has_stroke_path`) draw no stroke (GitHub #583). With one selected the stroke controls set up the next shape: `commit_shape_appearance_edit` drops the stroke operations for such a layer (no edit, no undo step), the stroke color and pattern pickers skip it (`stroke_target_shape_layer_ids`), and selecting it never syncs its stroke into the controls; a shape in the same selection still takes the edit. Coverage: `ui_options_bar_stroke_skips_fill_layers`.
- The keep-proportions toggle (`vectorShapeLinkSizeButton`, a framed push button), on the Line, Pen and path selection bars and in the Properties panel, sits evenly: the H label after it (`vectorShapeHeightLabel`) drops its text padding, so the field-to-button gap matches the button-to-text gap (4 and 5 px). The other four bars have the Style row in its place: Fixed Ratio covers new shapes, Shift on a corner handle a resize.
- Coverage: `ui_shape_options_bars_group_their_controls` (grouping, the draw-mode and alignment groups, Line order, swatch frame, toggle spacing, one row at 1366 px, shots in both schemes); `ui_shape_stroke_width_zero_means_no_stroke` (render, PSD round trip, a disabled stroke reads 0, a width restores it).

## One row for Shape and Pixels modes

Rectangle, Ellipse, Polygon and Custom Shape (`shape_tool_has_draw_modes`) show the same draw-mode buttons, Fill group and Stroke group in Shape and Pixels modes: the same widgets and the same saved values (GitHub issue 716). The mode only decides what a drag makes: a shape layer, a path, or pixels ([tools.md](tools.md#shapes-in-pixels-mode)). Path mode hides them. Line keeps its two bars and the Pen is vector only.

- **Widgets.** The groups are registered once, in `vector_shape_mode_option_widgets_` and in `ShapePixelOptions::appearance_widgets`; `VectorOptionModeRules::pixel_style` (Pixels mode on a draw-mode tool) shows that second list too. There is no Pixels-only copy of any of them.
- **Values.** MainWindow's paint mirrors (`current_vector_fill_`, `current_vector_stroke_paint_`, the stroke switch, width, dash preset and saved-preset line), with `ShapePixelOptions` (ui/shape_pixel_options.hpp) for what the mirrors do not hold: the alignment and the fill kind Stroke only took away. One fill paint and one stroke paint, whatever the mode: `current_shape_appearance_content` is the next shape layer and `shape_pixel_style_for_canvas` the next pixel shape, from the same values.
- **Draw-mode buttons** (`shapeDrawFillButton`, `shapeDrawStrokeButton`, `shapeDrawBothButton`: `shape-draw-*.svg`, one exclusive `QButtonGroup`, so one Tab stop) store nothing of their own. They wear the swap buttons' frame (`optionsBarFramedButton`, with a `:checked` rule): a frameless group put the separator beside a checked end button off center, since only the checked one fills its box. They show the fill's none and the stroke's switch: Stroke only sets the fill to none (remembering its kind in `fill_restore_kind`), Fill only turns the stroke off and keeps its width, Both brings both back. Shape Appearance's No Fill and a width of 0 do the same and the buttons follow (`refresh_shape_draw_controls`): a shape with no fill reads Stroke only, and Both or Fill only brings its fill back; with no fill and no stroke none is checked. In Shape mode a click applies `fill.kind` or `stroke.enabled` to the selected shape layers as one undo step, and selecting a shape shows its state.
- **A part that is not drawn leaves the bar** (Seth, 2026-11-13; it greyed before). `ShapePixelOptions::widget_visible`: Stroke only hides the Fill label and swatch; Fill only hides the whole Stroke group (label, width, swatch, dash list, alignment list). The buttons are then the switch that brings a group back. `MainWindow::sync_shape_bar_state` holds what shows (`shown_fill`, `shown_stroke`, part of `refresh_options_bar_rows`' key); `stray_option_separators` closes the gap, and nothing before the groups moves. A width being typed keeps its field (0 on the way to 0.5); leaving the field settles it. The bar is laid out again by `queue_shape_bar_refresh`, never at once: the change is noticed in the middle of an edit (a click sets the bar's values, then applies them to the selected shapes), and `refresh_options_bar` reads the selected shape back into the bar, which undid the click. On Line, Pen and the path selection tools, which have no buttons, nothing hides.
- **Alignment** (`vectorStrokeAlignCombo`: Inside, Center, Outside) shows and edits the selected shapes' `stroke.alignment` as one undo step, the value Shape Appearance's Align edits, and is what new shapes and pixel shapes get: Inside until it is changed, saved as `tools/vectorStrokeAlign`. A saved stroke preset sets it too. A line's stroke stays centered ([vector-tools-lines.md](vector-tools-lines.md#a-lines-stroke)), so Line has no list.
- **The Fill swatch menu has no No Fill on these four bars** (Seth, November 13, 2026: picked with the stroke off it left a shape that draws nothing and no button checked). It reads Foreground Color, Solid Color..., Gradient... and Pattern...; Stroke only is the bar's way to turn the fill off, and Shape Appearance keeps No Fill in its Fill list. The Pen, Line, Path Select and Direct Select bars have no draw-mode buttons, so their Fill menu still leads with No Fill (`show_vector_paint_menu`, `shape_tool_has_draw_modes`). The Stroke menu has no "none" entry (a width of 0 and Fill only turn the stroke off) and starts with Foreground Color. Both modes show the same menus (`ui_shape_fill_menu_has_no_fill_only_without_draw_mode_buttons`). **Foreground Color** is a one-time pick: the paint becomes a solid color, the foreground color as it is now (in the selected shapes too, one undo step), and does not follow the foreground color afterwards. A paint that followed it was tried twice: in Shape mode it fought the bar showing the selected shape, and as a Pixels-only entry it gave the two modes different paints.
- **Pixels mode adds** the tool's own settings with Opacity and Soft (`shapePixelOpacitySpin`, `shapePixelSoftSpin`, mirrors of the brush's opacity and softness; the brush fields do not show on these bars). The Ellipse, which has no Radius, gets its own separator before Opacity. The stroke's width in Pixels mode is the Stroke field (`[` and `]` step it there), not the brush size. A drawn shape stays pending and the bar keeps editing it ([tools.md](tools.md#pending-pixel-shapes)).
- **Settings written before the shared paints.** No key was renamed. A profile left in Shape mode keeps its shape paints, and pixel shapes now paint with them. A profile left in Pixels mode keeps the look of its last pixel shape, moved into the shared values once: from 1.34, or the first build with the draw-mode buttons (`shape_settings_predate_shared_style`: no `tools/vectorFillFollowsForeground`), `legacy_shape_pixel_style` reads `tools/shapeDrawMode` or the older `tools/shapeFill` checkbox, `tools/shapePixelFillColor` and `tools/shapePixelStrokeColor` (absent: the foreground color, taken once), the brush size as the stroke's width, `tools/shapePixelStrokeDashes`, and `tools/shapePixelStrokeAlign` (Center when absent, where the outline always sat); from the one build that let Pixels mode paint a part in the foreground color (`tools/vectorFillFollowsForeground` or `tools/vectorStrokeFollowsForeground` true), that part becomes the foreground color, once. Both keys are written false from then on, and `tools/shapeFill` is still written.
- Coverage: `ui_shape_draw_mode_buttons_follow_and_set_fill_and_stroke` (the hidden groups and their separators), `ui_shape_mode_draw_buttons_edit_selected_shapes`, `ui_shape_mode_alignment_list_edits_and_seeds`, `ui_shape_pixels_mode_paints_gradient_pattern_and_foreground` (Foreground Color), `ui_shape_fill_and_stroke_settings_migrate`.

## The Style row

Style (`shapeStyleCombo`: Normal, Fixed Ratio, Fixed Size; the marquee's, GitHub issue 602) ends the Rectangle, Ellipse and Custom Shape bars in Shape, Path and Pixels modes, before the gear in Shape mode (GitHub issue 716; it was Pixels-only on Rectangle and Ellipse). One set of values, session only, for every mode: a drag makes a shape layer, a path or pixels of that ratio or size. No separator sits between Style and its pair (the row has no room for one, rule 9).

- **Pairs.** Normal shows no size fields, Fixed Ratio the unitless `shapeRatio*Spin` pair with its own values and Fixed Size the pixel `shapeFixed*Spin` pair (`UnitIntSpinBox`, so it follows the ruler unit), each with a swap button (`shapeRatioSwapButton`, `shapeFixedSizeSwapButton`; GitHub issue 697 follow-up) that trades that pair's values. `ShapePixelOptions::widget_visible` picks the pair, and the Style is part of `refresh_options_bar_rows`' key.
- **The pixel pair is also the size of the shape being worked on** (`size_live`: an editable selected shape layer or path component in the vector modes, the pending shape in Pixels mode). It then shows that shape's size in whole pixels, also with Style on Normal, and a typed size resizes it: a shape layer through the W / H fields' own debounced path (`vectorShapeWidthSpin` / `vectorShapeHeightSpin` stay behind the pair as the value: one "Shape size" undo step, live shapes stay live, the Properties panel's link still applies), the pending pixel shape through `set_pending_pixel_shape_size`. A typed size is the next Fixed Size too; a size only shown is not (`ShapePixelOptions::width` / `height` change on an edit alone). The swap button swaps the shape's width and height. Fixed Ratio keeps showing the ratio: there the canvas handles and the Properties panel resize the shape.
- **Polygon** has no Style list (its drag is a center and a radius, not a box). In Shape mode its bar shows the pixel pair while a polygon is selected, as the W / H fields did; in Pixels mode it has none (the row has no room at 1366 px) and the pending polygon is sized by its handles.
- **Line and Pen** keep W [link] H: a line is sized by its ends and Weight, and the Pen's paths have no drag box for a Style to size.
- The W [link] H group left these four bars with the keep-proportions toggle: Fixed Ratio covers new shapes, Shift on a corner handle a resize, and the Properties panel keeps the link.
- Coverage: `ui_shape_style_row_shows_in_every_mode_and_hides_size_at_normal` (every mode, a Fixed Size click and a Fixed Ratio drag in Shape mode, the pair resizing and swapping a selected shape), `ui_shape_pixel_options_bar_follows_the_shape_mode_bar` (the row in the three modes on the four tools at 1600 and 1366 px, both schemes), `ui_shape_pixel_swap_button_swaps_ratio_and_size`, `ui_shape_size_row_shows_in_shape_mode_only` (which bars keep W / H), `ui_pending_pixel_shape_is_edited_from_the_bar_and_committed`.

## Widths

Every shape row stays one line at 1366 px (1352 px of bar) in every mode. Natural widths on Windows with a fill and a stroke both drawn (a hidden group makes a row shorter), measured by `ui_shape_pixel_options_bar_follows_the_shape_mode_bar` and `ui_shape_options_bars_group_their_controls`; "compact" is the row at 1366 px, without its droppable labels:

| Row | Shape mode | Path mode | Pixels mode |
| --- | --- | --- | --- |
| Rectangle, Style Normal | 1150 | 561 | 1169 |
| Rectangle, Fixed Ratio | 1429 (1235 compact) | 840 | 1448 (1319 compact) |
| Rectangle, Fixed Size | 1441 (1247 compact) | 852 | 1460 (1331 compact) |
| Ellipse, Normal / Ratio / Size | 1020 / 1299 / 1311 | 431 / 710 / 722 | 1046 / 1325 / 1337 |
| Polygon | 1117 | | 1136 |
| Custom Shape, Normal | 1202 | 613 | 1221 |
| Custom Shape, Fixed Ratio | 1481 (1236 compact) | 892 | 1500 (1320 compact) |
| Custom Shape, Fixed Size | 1493 (1248 compact) | 904 | 1512 (1332 compact) |
| Line | 1195 | | its brush-like bar |
| Pen | 1110 | | none |

The droppable labels (`kOptionsBarCollapsibleProperty`, [options-bar.md](options-bar.md#duplicate-sliders-drop-first)) are Style, Width and Height on the Style row, Combine on every shape bar and Shape on Custom Shape's. A row that would wrap drops all of its own at once, and wider windows show them. A Normal row with a live size shows the pixel pair and is as wide as its Fixed Size row. Linux and macOS measure 3 to 10 px narrower. The Custom Shape picker is 120 px (150 before the Style row joined its bar), which is what keeps its Pixels rows on one line. A new control on these rows needs its width found first: the Pixels rows with a Fixed Size pair have about 20 px left.
