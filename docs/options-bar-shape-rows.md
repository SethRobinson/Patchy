# Options bar: shape tool rows

Split from [options-bar.md](options-bar.md), whose grouping rules these rows follow: the shape tools' bars in Shape and Pixels modes, which share one Fill / Stroke row, and the path selection tools' bars.

## Shape tool rows

- The shape bars (Rectangle, Ellipse, Polygon, Custom Shape) read, in Shape mode: mode | [Fill only][Stroke only][Both] | Fill [swatch] | Stroke [width] [swatch] [dashes] [align] | W [link] H | Combine | the tool's own settings | [gear]. Line and Pen share the row without the draw-mode buttons and the alignment list (GitHub issues 311 and 716; `vectorAppearanceButton`, an icon button whose tooltip and accessible name are Shape Appearance..., since the issue 556 follow-up gave its text width to the dash combo). The own group is Rectangle's Radius, Polygon's Sides and Star inset, Custom Shape's Shape (a folder-tree picker with search and a Shapes Manager... button, [vector-tools-custom-shapes.md](vector-tools-custom-shapes.md)), Line's Weight with the two arrowhead toggles (they also edit a selected line, GitHub #622), and Pen's Auto Add/Delete; Ellipse has none.
- Path Select and Direct Select share those groups and separators (GitHub issue 689). With an editable shape layer active: Fill [swatch] | Stroke [width] [swatch] [dashes] | W [link] H | Combine | Merge Shapes, Split Shapes | [gear]. With none the appearance and size groups hide, `stray_option_separators` drops their separators, and the bar reads Combine | Merge Shapes, Split Shapes (`ui_path_select_options_bar_groups_its_controls`).
- The Fill and Stroke swatches are framed `QToolButton`s (`optionsBarSwatch` QSS rule: the push-button colors, hover and pressed states) 38x26 with a 28x16 chip, drawn at the button's icon size by `options_bar_swatch_icon`. The Text bar's `textColorButton` is the same button showing a solid chip (GitHub issue 343).
- The dash combo (`vectorStrokeDashCombo`, GitHub issues 556 and 557; `ui_text_length(104)` wide, which still shows every built-in name in full: it gave 36 px to the draw-mode buttons and the alignment list, issue 716; only the popup widens to longer names) is the one stroke list, in Shape and Pixels modes, rebuilt by `rebuild_vector_stroke_dash_combo` when the saved list can have changed (Shape Appearance or the manager closing, a language switch): the built-in dash presets ([vector-tools-appearance.md](vector-tools-appearance.md)), a separator and the saved stroke presets ([style-presets-strokes.md](style-presets-strokes.md#shape-appearance-stroke-presets); item data `kSavedStrokePresetRow` + index), Custom, a separator and Manage Presets..., which puts the combo back on its entry and opens the Stroke Presets manager. A built-in applies to the selected shape layers at once, one undo step, with its caps and corners (`apply_stroke_dash_preset`, the dialog's rule), and seeds new shapes (`tools/vectorStrokeDashes`, a `stroke_dash_preset_token`). A saved preset (`apply_vector_stroke_style_preset`) sets Align, Caps, Corners, the dashes and the offset the same way and for new shapes (`current_vector_stroke_style_`, saved as `tools/vectorStrokeStyle`, a one-entry preset array); width and paint stay. Until one is picked, new shapes keep the dash preset and Inside alignment (a line: Center, [vector-tools-lines.md](vector-tools-lines.md#a-lines-stroke)); a later built-in pick changes only the dashes and the caps and corners it sets, and resets the offset. The combo shows the entry the selected shape (or the new-shape settings) matches, a saved preset (all fields) before a built-in, and that built-in becomes the one for new shapes; a pattern nothing matches shows Custom, which is hidden otherwise and cannot be picked (Shape Appearance edits it). Coverage: `ui_options_bar_dash_combo_applies_presets`, `ui_options_bar_dash_combo_lists_saved_stroke_presets`.
- No Stroke checkbox, here or in the Shape Appearance dialog (Seth, issue 311 follow-up): the width is the switch. The field shows 0 while the stroke is off and accepts 0 to turn it off; any other value turns it on. The model keeps `stroke.enabled` and the last real width (`set_vector_stroke_width_from_field`), so a PSD's vstk never carries a zero width, a PSD stroke that is off reads 0, and the saved `tools/vectorStrokeEnabled`/`vectorStrokeWidth` keys are unchanged. At 0 only `stroke.enabled` is applied to the selection, so each shape keeps its own width. The width field always stays enabled; on the tools with the draw-mode buttons the rest of the Stroke group greys while the stroke is off (below).
- Fill layers (Color, Gradient or Pattern fill: no path, or a disabled one; `shape_has_stroke_path`) draw no stroke (GitHub #583). With one selected the stroke controls set up the next shape: `commit_shape_appearance_edit` drops the stroke operations for such a layer (no edit, no undo step), the stroke color and pattern pickers skip it (`stroke_target_shape_layer_ids`), and selecting it never syncs its stroke into the controls; a shape in the same selection still takes the edit. Coverage: `ui_options_bar_stroke_skips_fill_layers`.
- The keep-proportions toggle (`vectorShapeLinkSizeButton`, a framed push button) sits evenly: the H label after it (`vectorShapeHeightLabel`) drops its text padding, so the field-to-button gap matches the button-to-text gap (4 and 5 px).
- Coverage: `ui_shape_options_bars_group_their_controls` (grouping, the draw-mode and alignment groups, Line order, swatch frame, toggle spacing, one row at 1366 px, shots in both schemes); `ui_shape_stroke_width_zero_means_no_stroke` (render, PSD round trip, a disabled stroke reads 0, a width restores it).

## One row for Shape and Pixels modes

Rectangle, Ellipse, Polygon and Custom Shape (`shape_tool_has_draw_modes`) show the same draw-mode buttons, Fill group and Stroke group in Shape and Pixels modes: the same widgets and the same saved values (GitHub issue 716). The mode only decides what a drag makes: a shape layer, a path, or pixels ([tools.md](tools.md#shapes-in-pixels-mode)). Path mode hides them. Line keeps its two bars and the Pen is vector only.

- **Widgets.** The groups are registered once, in `vector_shape_mode_option_widgets_` and in `ShapePixelOptions::appearance_widgets`; `VectorOptionModeRules::pixel_style` (Pixels mode on a draw-mode tool) shows that second list too. There is no Pixels-only copy of any of them.
- **Values.** MainWindow's paint mirrors (`current_vector_fill_`, `current_vector_stroke_paint_`, the stroke switch, width, dash preset and saved-preset line), with `ShapePixelOptions` (ui/shape_pixel_options.hpp) for what the mirrors do not hold: the alignment, the fill kind Stroke only took away, and Pixels mode's Foreground Color per paint. `current_shape_appearance_content` is the next shape layer and `shape_pixel_style_for_canvas` the next pixel shape, from the same values.
- **Draw-mode buttons** (`shapeDrawFillButton`, `shapeDrawStrokeButton`, `shapeDrawBothButton`: `shape-draw-*.svg`, one exclusive `QButtonGroup`, so one Tab stop) store nothing of their own. They show the fill's none and the stroke's switch: Stroke only sets the fill to none (remembering its kind in `fill_restore_kind`), Fill only turns the stroke off and keeps its width, Both brings both back. The swatch's No Fill and a width of 0 do the same and the buttons follow (`refresh_shape_draw_controls`); with no fill and no stroke none is checked. In Shape mode a click applies `fill.kind` or `stroke.enabled` to the selected shape layers as one undo step, and selecting a shape shows its state.
- **Greying.** `ShapePixelOptions::widget_enabled`: Stroke only greys the Fill label and swatch; Fill only greys the stroke's swatch, dash list and alignment list. The Stroke label and width field never grey: the width is the stroke's switch, and a field that greyed at 0 could not be typed back. On Line, Pen and the path selection tools, which have no buttons, nothing greys.
- **Alignment** (`vectorStrokeAlignCombo`: Inside, Center, Outside) shows and edits the selected shapes' `stroke.alignment` as one undo step, the value Shape Appearance's Align edits, and is what new shapes and pixel shapes get: Inside until it is changed, saved as `tools/vectorStrokeAlign`. A saved stroke preset sets it too. A line's stroke stays centered ([vector-tools-lines.md](vector-tools-lines.md#a-lines-stroke)), so Line has no list.
- **Foreground Color** heads the Fill and Stroke swatch menus in Pixels mode only, above No Fill, Solid Color..., Gradient... and Pattern.... While it is on (`ShapePixelOptions::fill_follows_foreground`, `stroke_follows_foreground`; `tools/vectorFillFollowsForeground`, `tools/vectorStrokeFollowsForeground`) pixel shapes paint that part in the foreground color, as every pixel tool does, and the swatch shows it (`update_vector_swatch_icons`); the bar's own paint stays underneath for Shape mode. Another entry picked from either mode's menu ends it (`end_pixel_foreground_paint`): that paint is then the one both modes use. Selecting a shape, which only shows its paints, does not. Shape mode has no such entry: there the bar shows the selected shape's paints and hands them to the next shape, and a paint that follows the foreground cannot do both (the two fought in a first version: selecting a shape silently ended it). Both are on until a paint is picked.
- **Pixels mode adds** the tool's own settings with Opacity and Soft (`shapePixelOpacitySpin`, `shapePixelSoftSpin`, mirrors of the brush's opacity and softness; the brush fields do not show on these bars), and on Rectangle and Ellipse the marquee's Style (GitHub issue 602; no separator between Style and its pair: the row has no room for one, rule 9): Normal shows no size fields, Fixed Ratio the unitless `shapeRatio*Spin` pair with its own values and Fixed Size the pixel `shapeFixed*Spin` pair, each with a swap button (`shapeRatioSwapButton`, `shapeFixedSizeSwapButton`; GitHub issue 697 follow-up) that trades that pair's values. `ShapePixelOptions::widget_visible` picks the pair, and its Style is part of `refresh_options_bar_rows`' key. The Ellipse, which has no Radius, gets its own separator before Opacity. The stroke's width in Pixels mode is the Stroke field (`[` and `]` step it there), not the brush size.
- **Settings written before the shared row** (`shape_settings_predate_shared_style`: no `tools/vectorFillFollowsForeground`) start with Foreground Color on for both paints, so pixel shapes keep the foreground color they always had and Shape mode keeps its saved paints. When the tools were left in Pixels mode, `legacy_shape_pixel_style` also moves the Pixels look into the shared values once: `tools/shapeDrawMode` or the older `tools/shapeFill` checkbox, `tools/shapePixelFillColor` and `tools/shapePixelStrokeColor` (each becomes the bar's paint and ends Foreground Color for it), the brush size as the stroke's width, `tools/shapePixelStrokeDashes`, and `tools/shapePixelStrokeAlign` (Center when absent, where the outline always sat). Those keys are read only then; `tools/shapeFill` is still written.
- Coverage: `ui_shape_draw_mode_buttons_follow_and_set_fill_and_stroke`, `ui_shape_mode_draw_buttons_edit_selected_shapes`, `ui_shape_mode_alignment_list_edits_and_seeds`, `ui_shape_pixel_options_bar_follows_the_shape_mode_bar` (both modes' order on the four tools at 1600 px, one row at 1366 px with or without the droppable labels, units, mirrors, shots in both schemes), `ui_shape_pixel_swap_button_swaps_ratio_and_size`, `ui_shape_pixels_mode_paints_gradient_pattern_and_foreground` (Foreground Color), `ui_shape_fill_and_stroke_settings_migrate`.

## Widths

Every shape row stays one line at 1366 px (1352 px of bar). Natural widths on Windows, measured by the tests above and `ui_shape_options_bars_group_their_controls`:

| Row | Shape mode | Pixels mode |
| --- | --- | --- |
| Rectangle | 1279 | 1166; Fixed Ratio 1445 (1316 compact); Fixed Size 1457 (1328 compact) |
| Ellipse | 1149 | 1043; Fixed Ratio 1322; Fixed Size 1334 |
| Polygon | 1385 (1320 compact) | 1133 |
| Custom Shape | 1361 (1245 compact) | 1109 |
| Line | 1195 | its brush-like bar |
| Pen | 1110 | none |

Compact is the row without its droppable labels (`kOptionsBarCollapsibleProperty`, [options-bar.md](options-bar.md#duplicate-sliders-drop-first)): Style, Width and Height on the Pixels rows, Combine on every shape bar and Shape on Custom Shape's. A row that would wrap drops all of its own at once, so at 1366 px the Polygon and Custom Shape rows in Shape mode and the Rectangle's Fixed rows in Pixels mode are compact, and wider windows show the labels. Linux and macOS measure 3 to 10 px narrower. A new control on these rows needs its width found first: the Rectangle's Fixed Size row has about 24 px left.
