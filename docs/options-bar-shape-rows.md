# Options bar: shape tool rows

Split from [options-bar.md](options-bar.md), whose grouping rules these rows follow: the shape tools' bars in Shape mode, the path selection tools' bars, and the Rectangle and Ellipse Pixels row.

## Shape tool rows

- The shape bars (Rectangle, Ellipse, Polygon, Line, Custom Shape; Pen shares them) read, in Shape mode: mode | Fill [swatch] | Stroke [width] [swatch] [dashes] | W [link] H | Combine | the tool's own settings | [gear] (GitHub issue 311; `vectorAppearanceButton`, an icon button whose tooltip and accessible name are Shape Appearance..., since the issue 556 follow-up gave its text width to the dash combo). The own group is Rectangle's Radius, Polygon's Sides and Star inset, Custom Shape's Shape (a folder-tree picker with search and a Shapes Manager... button, [vector-tools-custom-shapes.md](vector-tools-custom-shapes.md)), Line's Weight with the two arrowhead toggles (they also edit a selected line, GitHub #622), and Pen's Auto Add/Delete; Ellipse has none.
- Path Select and Direct Select share those groups and separators (GitHub issue 689). With an editable shape layer active: Fill [swatch] | Stroke [width] [swatch] [dashes] | W [link] H | Combine | Merge Shapes, Split Shapes | [gear]. With none the appearance and size groups hide, `stray_option_separators` drops their separators, and the bar reads Combine | Merge Shapes, Split Shapes (`ui_path_select_options_bar_groups_its_controls`).
- The Fill and Stroke swatches are framed `QToolButton`s (`optionsBarSwatch` QSS rule: the push-button colors, hover and pressed states) 38x26 with a 28x16 chip, drawn at the button's icon size by `options_bar_swatch_icon`. The Text bar's `textColorButton` is the same button showing a solid chip (GitHub issue 343).
- The dash combo (`vectorStrokeDashCombo`, GitHub issues 556 and 557; `ui_text_length(140)` wide so every built-in name shows in full; 160 pushed the Line row past its 100 px slack under 1366 px; only the popup widens to longer names) is the one stroke list, rebuilt by `rebuild_vector_stroke_dash_combo` when the saved list can have changed (Shape Appearance or the manager closing, a language switch): the built-in dash presets ([vector-tools-appearance.md](vector-tools-appearance.md)), a separator and the saved stroke presets ([style-presets-strokes.md](style-presets-strokes.md#shape-appearance-stroke-presets); item data `kSavedStrokePresetRow` + index), Custom, a separator and Manage Presets..., which puts the combo back on its entry and opens the Stroke Presets manager. A built-in applies to the selected shape layers at once, one undo step, with its caps and corners (`apply_stroke_dash_preset`, the dialog's rule), and seeds new shapes (`tools/vectorStrokeDashes`, a `stroke_dash_preset_token`). A saved preset (`apply_vector_stroke_style_preset`) sets Align, Caps, Corners, the dashes and the offset the same way and for new shapes (`current_vector_stroke_style_`, saved as `tools/vectorStrokeStyle`, a one-entry preset array); width and paint stay. Until one is picked, new shapes keep the dash preset and Inside alignment (a line: Center, [vector-tools-lines.md](vector-tools-lines.md#a-lines-stroke)); a later built-in pick changes only the dashes and the caps and corners it sets, and resets the offset. The combo shows the entry the selected shape (or the new-shape settings) matches, a saved preset (all fields) before a built-in, and that built-in becomes the one for new shapes; a pattern nothing matches shows Custom, which is hidden otherwise and cannot be picked (Shape Appearance edits it). Coverage: `ui_options_bar_dash_combo_applies_presets`, `ui_options_bar_dash_combo_lists_saved_stroke_presets`.
- No Stroke checkbox, here or in the Shape Appearance dialog (Seth, issue 311 follow-up): the width is the switch. The field shows 0 while the stroke is off and accepts 0 to turn it off; any other value turns it on. The model keeps `stroke.enabled` and the last real width (`set_vector_stroke_width_from_field`), so a PSD's vstk never carries a zero width, a PSD stroke that is off reads 0, and the saved `tools/vectorStrokeEnabled`/`vectorStrokeWidth` keys are unchanged. At 0 only `stroke.enabled` is applied to the selection, so each shape keeps its own width. The swatch and width stay enabled.
- Fill layers (Color, Gradient or Pattern fill: no path, or a disabled one; `shape_has_stroke_path`) draw no stroke (GitHub #583). With one selected the stroke width, swatch and dash combo stay enabled and set up the next shape: `commit_shape_appearance_edit` drops the stroke operations for such a layer (no edit, no undo step), the stroke color and pattern pickers skip it (`stroke_target_shape_layer_ids`), and selecting it never syncs its stroke into the controls; a shape in the same selection still takes the edit. Coverage: `ui_options_bar_stroke_skips_fill_layers`.
- The keep-proportions toggle (`vectorShapeLinkSizeButton`, a framed push button) sits evenly: the H label after it (`vectorShapeHeightLabel`) drops its text padding, so the field-to-button gap matches the button-to-text gap (4 and 5 px).
- Pixels mode on Rectangle and Ellipse follows the same order (GitHub issue 716): mode | [Fill only][Stroke only][Both] | Fill [swatch] | Stroke [width] [swatch] [dashes] [align] | Radius, Opacity, Soft | Style, Width [swap] Height (no separator between Style and its pair: the row has no room for one, rule 9). The three draw-mode buttons (`shapeDrawFillButton`, `shapeDrawStrokeButton`, `shapeDrawBothButton`: `shape-draw-*.svg`, one exclusive `QButtonGroup`, so one Tab stop) replaced the Fill checkbox; Stroke only greys the Fill group and Fill only the Stroke group (`ShapePixelOptions::widget_enabled`). The swatches (`shapePixelFillSwatchButton`, `shapePixelStrokeSwatchButton`) are the Shape-mode swatch button and open Foreground Color / Solid Color...; the dash list (`shapePixelStrokeDashCombo`) holds the built-in presets only (saved stroke presets belong to shape layers) and `shapePixelStrokeAlignCombo` is Inside, Center, Outside. Stroke width, Opacity and Soft (`shapePixelStrokeWidthSpin`, `shapePixelOpacitySpin`, `shapePixelSoftSpin`) mirror the brush fields, which no longer show on these two bars (Line keeps them); the Size slider is gone with them. The Ellipse, which has no Radius, gets its own separator before Opacity. Style is the marquee's (GitHub issue 602): Normal shows no size fields, Fixed Ratio the unitless `shapeRatio*Spin` pair with its own values and Fixed Size the pixel `shapeFixed*Spin` pair, each with a swap button (`shapeRatioSwapButton`, `shapeFixedSizeSwapButton`; GitHub issue 697 follow-up) that trades that pair's values. `ShapePixelOptions::widget_visible` picks the pair, and its Style is part of `refresh_options_bar_rows`' key. State, rules and settings live in `ShapePixelOptions` (ui/shape_pixel_options.hpp); what the style paints is in [tools.md](tools.md#shapes-in-pixels-mode). This is the bar's longest row (the Rectangle's Fixed Size variant is about 1440 px with every label and about 1310 px without the three), so its Style, Width and Height labels carry `kOptionsBarCollapsibleProperty` and drop before the row wraps ([options-bar.md](options-bar.md#duplicate-sliders-drop-first)): at 1366 px the Rectangle's Fixed rows are compact, wider windows show the labels. Coverage: `ui_shape_pixel_options_bar_follows_the_shape_mode_bar` (order at 1600 px, one row at 1366 px with or without the labels, units, mirrors, shots in both schemes), `ui_shape_pixel_draw_mode_buttons_replace_the_fill_checkbox`, `ui_shape_pixel_swap_button_swaps_ratio_and_size`.
- Coverage: `ui_shape_options_bars_group_their_controls` (grouping, Line order, swatch frame, toggle spacing, one row at 1366 px, shots in both schemes); `ui_shape_stroke_width_zero_means_no_stroke` (render, PSD round trip, a disabled stroke reads 0, a width restores it).
