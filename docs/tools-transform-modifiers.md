# Transform modifiers, drag readout, and pixel-grid snapping

Split from [tools.md](tools.md): the Free Transform and path transform modifier rules (corner aspect lock and its Shift preference, the reference point, Alt scaling, scale handles on a rotated box, the options-bar fields), what a pending session refuses or cancels, the drag readout, pixel-grid snapping, and the Move-tool double-click.

## Free Transform modifiers

Session steps and undo inside a pending transform: [free-transform.md](free-transform.md).

Corner handles scale proportionally on their own and Shift releases the lock, matching Photoshop CC 2019 and later. The preference `input/shiftKeepsTransformAspect` (default `false`, Preferences > Tools, `preferencesTransformShiftAspectCheck`) restores the older pairing, where a plain corner drag distorts and Shift holds the ratio. It is a persisted identifier and rides the pen-input load/save/apply trio in main_window_preferences.cpp, so `configure_canvas` and the Preferences accept loop both push it onto every canvas. The session start status line reports the active pairing (both sentences are translated).

- Both sessions decide through one predicate, `CanvasWidget::transform_drag_keeps_aspect(modifiers)` (canvas_widget_transform.cpp): `shift == shift_keeps_transform_aspect_`. The pixel session calls it from `update_free_transform_preview`, the path session from `handle_path_transform_move` (canvas_widget_vector_tools.cpp). The shared predicate keeps their modifier semantics from drifting apart: never reintroduce an inline `Qt::ShiftModifier` test for a resize. Only corners consult it; edge handles scale one axis in every mode. Shift on the rotate handle snaps to 15 degrees in both sessions (a separate modifier test in the same functions). Shift on the shape and marquee tools is an unrelated 1:1 shape constraint.
- Aspect-locked corner drags in both sessions share one rule: the shared scale is the pointer's distance from the anchor projected onto the box diagonal, per axis in absolute value (`(|dx| w + |dy| h) / (w^2 + h^2)`), and each axis keeps its own sign from the side of the anchor the pointer is on. Travel along the diagonal scales at one rate in every direction, a pull leaning against the diagonal shrinks, and a straight pull across the anchor mirrors that axis alone (`ui_point_text_flip_transform_mirrors_and_survives_reedit`). Do not go back to following whichever axis the pointer pulled harder: that scales the short side `aspect` times faster and jumps in rate when the winning axis switches. The pixel session writes the corner from the anchor; the path session converts the per-axis scales back into its local delta.
- While a Free Transform, Warp, or path transform session is pending, the Shape Appearance, Layer Style, and adjustment-layer dialogs refuse to open (`refuse_layer_dialog_during_transform`, a status hint to press Enter or Esc first; `ui_layer_dialogs_refuse_during_transform`).
- Delete (Layer > Fill > Clear Layer / Selection) and Delete Layer during a Free Transform or Warp session cancel it, then act on the untransformed layer; a document change removing a session's layer (the Layers panel, a script) ends the session in `cancel_transform_sessions_on_removed_layers`, so the options bar drops the transform row (GitHub issue 455; `ui_free_transform_delete_layer_ends_the_session`).
- The options-bar link button (`freeTransformLinkScaleButton`) mirrors the W% and H% spin boxes only, never handle drags. The X/Y/W/H/Angle fields are `UnitSpinBox`es ([ui-conventions-dialogs.md](ui-conventions-dialogs.md#options-bar), [resolution-units.md](resolution-units.md)): X/Y native px with percent relative to the document extent, W/H native percent with pixels relative to `TransformControlsState::original_size`, Angle degrees only. Typing a unit (or right-clicking the field) switches the display; the linked W/H pair switches together. The interpolation combo (Nearest Neighbor, Bilinear, Bicubic default, Bicubic Smoother, Bicubic Sharper, Automatic; `tools/transformInterpolation`, append-only) and its kernels are in [resampling.md](resampling.md).
- A text layer's session rect is its whole raster (`move_layer_transform_local_rect`: a box layer's frame, a point layer's line box), the same rect the passive Move-tool controls draw, like Photoshop's paragraph-text box. Other layers use the opaque pixel rect. The two must agree because a handle drag sets the rect corner to the absolute mouse position; a session on the smaller ink rect stretches the ink to the frame on the first move (`ui_box_text_transform_handle_grab_keeps_ink_size`).
- The rotate handle turns the box about the reference point (the options-bar Pivot combo, `transform_reference_point_`; `set_transform_reference_point` repaints the session box so the marker moves at once): `update_free_transform_preview` measures the drag angle from `transform_reference_position(start rect, start angle)` and moves the center to `pivot + R(delta)(C0 - pivot)`. With `a` the anchor offset, `C0 - pivot = -R(start)a`, so `C1 + R(new)a` is the pivot again and the reference position is invariant. Numeric edits pivot there too (`set_transform_controls_state`). `draw_free_transform` draws the reference marker (circle plus crosshair) during a session only; the passive Move box stays a plain frame, as in Photoshop.
- Scale handles compute in the box's own frame: the snapped pointer is unrotated about the drag-start center, the edge/corner setters and the Shift aspect block run on an axis-aligned local rect, the flip signs read the raw local rect, and the center rotates back out. At angle 0 this is exactly the world-space math, so unrotated drags stay byte-identical. Hit zones and the grab offset: [move-tool.md](move-tool.md).
- Alt on a scale handle scales about the reference point (`transform_drag_scales_about_reference`, the Shift predicate's sibling): per moving axis the factor is `(pointer - r) / (handle - r)` in local coordinates and the center lands at `r(1 - f)`; a reference sitting on the dragged edge keeps the plain result for that axis; corners under the aspect lock share one magnitude by the same projection (per-axis factors weighted by the squared reference-to-handle spans), each axis keeping its sign. Shift or Alt pressed or released mid-drag replays the preview at the last pointer position, and the modifier cursor filter skips `dragging_transform_`.
- Drag readout (`view/showTransformValues`, default on, Preferences > Tools `preferencesShowTransformValuesCheck`, pushed to every canvas with the Shift-aspect pairing): `transform_drag_readout()` lists the reference point's X/Y plus the offset while moving (the Move tool uses the moving set's opaque union, `move_readout_base_rect_`), W x H plus the signed percentages while scaling, and the angle plus its delta while rotating. `draw_transform_drag_readout` paints only the change line (`canvas_lines`, no label) below-right of the pointer in the canvas HUD theme roles; the status bar mirrors both lines (`lines`). Its panel rect joins the bounded drag repaints (`update_drag_readout_region`, [interactive-previews.md](interactive-previews.md)); release and cancel clear it. Text comes from `format_pixels`/`format_percent`/`format_degrees` in measurement_units.hpp. Guide drags show the guide's position under the same preference ([guides.md](guides.md)).
- **Pixel-grid snapping** (PS 27.9 COM captures): Photoshop lands every axis-aligned transform on whole pixels by rounding each destination EDGE with halves up (`snap_to_pixel_grid` in core/pixel_grid.hpp: floor(x + 0.5), so 3.5 -> 4 and -3.5 -> -3): a typed X of 3.4 moves the layer by 3 with crisp pixels, 152.5% of 20 px (edges 4.75..35.25) comes out 5..35, and an odd-sized layer under the Center pivot legitimately reads X .50. Photoshop does this for pixel layers with its "Snap Vector Tools and Transforms to Pixel Grid" preference on OR off (`toolsPreferences.transformsSnapToPixels`, settable through Action Manager `setd` on the application); that preference only decides whether a smart object's placement quad is rounded too (off keeps 13.4 in the quad while the raster still lands on 13). Patchy: `set_transform_controls_state` snaps `transform_current_rect_` (`snap_transform_rect_to_pixel_grid`) whenever `input/snapTransformsToPixelGrid` (Preferences > Tools "Snap transforms to the pixel grid", default on, pushed with the other input prefs) is on and the session is not rotated (`|angle| <= 0.01`; a rotated box cannot sit on the grid, and both stress-test numeric transforms are rotated, which keeps `tool_write_paths_digest_baseline` untouched). Snapping in the setter makes preview, options-bar readback and all three commit paths agree, and integer inputs snap to themselves so pinned commit bytes never move. Handle drags already snap the pointer (`snapped_document_point_f`); an aspect-locked drag can still leave a fractional edge and is not snapped here. Off restores the sub-pixel resample (floor origin, one extra column). A whole-pixel move through the default Bicubic (Catmull-Rom, interpolating) is byte-identical, so there is no separate fast path; an entry that snaps back to the start commits as a no-op. The script API's `moveTo`/`x`/`y` round with the same helper (`ui_script_layer_move_to_rounds_like_photoshop`); type layers keep their fractional anchor and round each line start (the anchor minus the justification offset) and each glyph's x with it ([text-render-calibration-pixel-grid.md](text-render-calibration-pixel-grid.md)). Coverage: `ui_transform_numeric_fraction_snaps_to_pixel_grid`, `ui_transform_numeric_odd_layer_keeps_half_pixel_reference`, `ui_transform_snap_preference_off_keeps_fraction`, `ui_transform_snap_skips_rotated_sessions`, `ui_transform_integer_move_is_lossless_through_bicubic`, `ui_transform_snap_preference_persists_and_reaches_canvas`.
- **Move-tool double-click never starts Free Transform; during a session a double-click inside the box applies it** (Seth's decision, GitHub issue 225, like Photoshop and Enter; details in [free-transform.md](free-transform.md)). Off the box, `mouseDoubleClickEvent` hands the event to `QWidget::mouseDoubleClickEvent`, which replays it as a second press, so it never reaches the text-editor or shape-appearance branches. A double-click inside the box of a transforming text layer runs first: it finishes the transform and opens the text editor. A motionless press inside the box must not nudge it: `update_free_transform_preview` rounds the Move drag START to whole pixels like the snapped end (else a half-pixel pan at 100% shifts the box by 1 px), and `free_transform_snap_exclude_ids` keeps the session's own layers (whose pixels stay put until commit) out of the snap targets (`ui_move_double_click_commits_free_transform_inside_box`).
- Coverage: `ui_transform_shift_frees_aspect_ratio_by_default`, `ui_transform_proportional_corner_follows_diagonal_projection`, `ui_transform_shift_aspect_preference_restores_legacy`, `ui_transform_shift_aspect_preference_defaults_to_off`, `ui_transform_shift_aspect_preference_persists_and_reaches_canvas`, `ui_transform_fields_accept_unit_tokens`, `ui_transform_rotate_drag_pivots_on_reference_point`, `ui_transform_alt_drag_scales_about_reference_point`, `ui_transform_handle_drag_on_rotated_box_uses_local_axes`, `ui_transform_drag_readout_shows_values`, `ui_move_drag_readout_reports_reference_and_delta`, `ui_transform_readout_preference_hides_hud`, plus the `unit_spin_box` group. The path session keeps its own center pivot; its Ctrl gestures are tested (`ui_path_transform_ctrl_*`), its Shift aspect pairing not yet.
