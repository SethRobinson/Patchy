# Smart object editing and authoring

The model and preservation rules remain in [smart-objects.md](smart-objects.md).

- **Edit Contents**: an editable embedded smart object's badge (or Edit Smart Object Contents in the Smart Objects menus) opens the source as a child tab titled "file.ext (embedded in Parent.psd)": a full `DocumentSession` whose `smart_object_link{parent_session_id, source_uuid}` carries session IDS (never pointers: sessions_ erases on close; `session_id` is the stable identity). Save (Ctrl+S) on the child routes `save_document()` to `commit_smart_object_child_session`: the child serializes in the source's own format (PSB for '8BPB' via `WriteOptions::large_document`, PSD for '8BPS', Qt image formats re-encode a flatten), the element gets fresh shared_ptr bytes (dirty), EVERY layer sharing the uuid re-renders (`smart_object_render.{hpp,cpp}`: quadToQuad + resample_transformed_rgba8, raster_status=patchy_raster), the parent takes ONE undo snapshot ("Edit Smart Object Contents"), and the child marks clean. Size-changing commits rescale quads per the E5 rule below; same-size commits leave SoLd untouched (only the lnk element regenerates). Closing a parent with open child tabs prompts (closeSmartObjectChildrenMessageBox) and resolves the children first; a child whose parent is gone detaches and falls back to Save As. Nesting works by construction (each child is a full session; PSD children keep their own store through DocumentIo). PSD/PSB sources render their preview from the child's own flattened composite (prefer_flat_composite), so untouched children look exactly like Photoshop's stored pixels.

- **Preview decode falls back to the layered render when the stored composite is fully opaque but the layers are not** (`decode_smart_object_source_image`): a 3-channel or opaque composite cannot represent canvas transparency. Older Patchy children (black-matted composites) and Photoshop saves with Maximize Compatibility off (flat white-matted composites) render through the layered fallback; genuinely opaque children keep the PS-exact stored composite. Regression pins: `ui_smart_object_edit_commit_keeps_canvas_transparency`, `ui_smart_object_legacy_black_composite_decodes_transparent` (`test-fixtures/psd/patchy-legacy-black-composite.psb`), and `ui_smart_object_psbtest_repro_decodes_transparent_if_available` (local PSBtest repro). Parents with already-baked-black previews heal on the next commit/transform/update re-render.

- **Edit-format guard**: PSD/PSB (DocumentIo both ways) and png/jpg/jpeg/tif/tiff/bmp/webp (Qt both ways) are editable; GIF and registry-only formats (TGA/PCX/...) decode for preview but refuse Edit/Replace with an explanatory status message (`classify_smart_object_contents`); undecodable/external sources keep Photoshop's preview forever. Content density comes from `smart_object_source_dpi` (PSD resolution or the image's embedded density, 72 fallback); Qt-authored pngs carry a pHYs chunk, so replacing with one honors its dpi like Photoshop does.

- **Replace Contents** follows the E5 semantics exactly: fresh uuid + element, every referencing layer repoints and rebuilds about its own quad center, old element removed, layer names swap the source stem. Accepted replace formats: psd/psb/png/jpg/jpeg/tif/tiff/bmp (webp only round-trips existing sources, its PS filetype OSType is unpinned).

- **Linked-file workflows**: external ('liFE') smart objects are fully workable. Edit Contents resolves the path (relPath against the parent folder, then a bare-filename sibling, then originalPath, then the fullPath URI: `resolve_smart_object_external_path`) and opens the REAL file as a disk-backed session with `SmartObjectLink::external`; its Save writes the file FIRST, then `refresh_external_smart_object_after_save` re-reads the bytes, stamps the liFE date/size, marks the element dirty, and re-renders every uuid-sharing layer as ONE parent undo step. Update Smart Object Content re-reads on demand; document open compares stored date/size and prepends "changed on disk"/"not found" notices (actionable notices go FIRST for the status bar). Relink to File... follows the E14-captured semantics: like Replace Contents but staying external (FRESH element uuid in the lnkE block, referencing layers repoint and rescale about their own centers per E5, layer names swap the source stem, old element pruned). Embed Linked follows E13: ANOTHER fresh uuid, the element moves to lnk2 as liFD, the emptied lnkE stays behind, locks clear, and the per-layer SoLE block key flips to SoLd (block_dirty repoints the Idnt on save). COM note: linked placement needs `putBoolean(charIDToTypeID("Lnkd"), true)` on the 'Plc ' descriptor. No QFileSystemWatcher by design: open-time check + explicit Update + self-save refresh cover the workflows. The shared re-render walk is `refresh_smart_object_layers_for_source`.

- **Place Linked** (File > Place Linked..., `filePlaceLinkedAction`, `file.place_linked`, hidden on wasm; `MainWindow::place_linked_file_with_path` for tests): the same formats as Place Embedded, SVG included, but the layer references the file. Both commands and `doc.addSmartObject` share `place_file_as_smart_object(session, path, SmartObjectPlaceOptions, before_mutation, error)`: E2 placement by default, or `x`/`y`/`width`/`height`/`scale` (sizes 1..30000 px), the file's base name (or `name`) as the layer name, the new layer on top and active. A linked placement stores an ExternalFile source in 'lnkE' (`SmartObjectStore::add_external`, `set_smart_object_link_target`: filetype, undecorated file URI, native path, relative path, UTC whole-second stamp and size), the layer's block under the 'SoLE' key with lock "external" (exactly how a Photoshop-written one reads back), and its rendered preview as the pixels. **A document with no folder yet** stores the bare file name as the relative path and resolves through the absolute path; `refresh_smart_object_link_relative_paths` recomputes every resolvable link's relative path against the target folder whenever the document is saved as PSD/PSB (Save and Save As alike), which is when Photoshop computes it too, so a PSD saved next to its files stays portable and one saved elsewhere still finds them. **One element per file**: placing a file the document already links (resolved to the same file on disk, `find_smart_object_link_for_file`) joins the existing element, so one Update refreshes every layer placed from it; if the file changed since those layers rendered, they refresh in the same placement step. Embedded placements always get their own copy. Update Smart Object Content runs through `update_linked_smart_object(session, layer, before_mutation, error)` (the menu command and `layer.updateSmartObject()`), which re-stamps the element and re-renders every layer sharing it as one undo step. Relink to File accepts SVG (a raster-to-vector relink flips Type; `regenerate_placed_layer_payload` patches it). **Vector contents** (SVG, `smart_object_contents_are_vector`) rasterize at the placement's own scale (`render_smart_object_vector_contents`, the quad's edge lengths as the pixel size, up to 16384 per side, a whole-pixel placement landing with no resampling): Place, Update, Relink, the external child save, and the editable transform re-render all use it; warped placements keep the natural-size image. The open-time staleness notice, `getSmartObject().changed` and Update compare the UTC stamp and size (`smart_object_link_changed_on_disk`), so a rewrite that keeps the byte size within one second is invisible, as it is to Photoshop. A missing file keeps the stored preview, is reported on open and by Update, saves back unchanged, and Relink repairs it. **Geometry re-renders**: Image Size, Free Transform and Warp re-render a linked placement from its file the way they re-render an embedded one (Photoshop does too), so a linked SVG scaled up stays crisp; Move never re-renders. Image Size reads each file once per source element. A file that is missing or cannot be decoded keeps the resampled preview the operation produced and is named on the status bar ("Linked file X was not found"); Warp refuses to start on it. Pinned by `ui_script_smart_object_image_size_rerenders_linked_and_embedded`, `ui_script_smart_object_linked_raster_rerenders_from_full_resolution`, `ui_script_smart_object_missing_linked_file_keeps_preview_on_image_size` and `ui_smart_object_free_transform_and_warp_rerender_linked_svg`. `getSmartObject().changed` compares the file's UTC mtime and size with the stored stamp, so a copy of a PSD folder made without preserving file times reads every link as changed until Update; geometry operations never touch the stamp. Script API: `doc.addSmartObject`, `layer.isSmartObject`, `layer.getSmartObject()`, `layer.updateSmartObject()` ([scripting-api-changes.md](scripting-api-changes.md)). Tests: `ui_smart_object_place_linked_links_the_file`, `ui_smart_object_placed_svg_is_vector_contents`, `ui_script_smart_object_linked_round_trip_and_update` (the acceptance scenario: three linked placements plus text, saved beside the SVG, reopened, updated after an edit), `ui_script_smart_object_options_and_errors`, `ui_smart_object_missing_linked_file_is_reported_and_relinks`, `ui_unicode_place_linked_smart_object_resolves`, and the core `psd_smart_object_authored_link_round_trips` / `smart_object_authored_vector_sold_matches_photoshop_shape`. Photoshop ground truth: [smart-objects.md](smart-objects.md), "Place Linked ground truth".

- **E4 acceptance**: Photoshop 2026 opened, color-sampled bit-exactly, edited, and resaved the `ui_smart_object_*.psd` artifacts cleanly (no "disk error (-1)"). After any writer-side smart-object change, re-open those artifacts in Photoshop over COM (`scripts\dev\photoshop-open-check.ps1` for the open prompt, `scripts\dev\smart-objects\ps-accept-linked.ps1` for linked placements; [photoshop-com.md](photoshop-com.md)).

- **Authoring**: Convert to Smart Object (layer menu + context submenu) moves the selected layer trees into a child document (canvas = union of render bounds, PSB, '8BPB', named "<top layer>.psb"; nested sources adopt into the child store; the trees shift to the child origin through `offset_copied_layer_tree`, the cross-document copy's helper, so linked and unlinked masks move exactly once, pinned by `ui_smart_object_convert_keeps_masks_in_place`); the topmost selected layer's slot/id/name become the new smart object, and the preview composites pixel-identically for Normal/100% layers. Place Embedded (File menu) uses the E2 rule dpi-aware (physical size 1:1 centered, fit-to-canvas when larger). Both write a from-scratch SoLd via `psd::author_placed_layer_sold_payload`, which mirrors PS 2026's exact key order/id forms (E1 captures; `smart_object_authored_sold_matches_photoshop_shape` pins the shape) and is pushed into the layer's unknown blocks at author time, so the normal preserve/patch-in-place machinery owns it from then on. Patchy writes NO legacy PlLd companion (PS writes both; it accepts SoLd-only files, E4-gated). New Smart Object via Copy clones the element under a fresh uuid (E8 semantics); free transform composes the delta into the quad and re-renders through `smart_object_transform_render_callback_` (text-layer pattern), with the resampled pixels as fallback.

- **Convert to Layers** (Layer > Smart Objects and the layer context submenu, `layerSmartObjectToLayersAction`, `MainWindow::convert_smart_object_to_layers`; GitHub issue 35): decodes the embedded contents like Edit Contents (`decode_smart_object_source_document`: a PSD/PSB keeps its stack, a Qt image is one layer) and copies the roots in through `copy_layers_between_documents` with `CrossDocumentLayerPlacement::exact_offset` and `keep_names`, so nested sources, patterns, and FEid records adopt the usual way and names never gain " copy". A folder named after the Smart Object replaces it in its slot and carries its visibility, clipping, opacity, fill, locks, raster and vector masks, and layer style, with the Smart Object's blend mode (Normal, never Pass Through), so the result composites like the Smart Object did. The mapping is the preview's own (contents canvas quadToQuad the Trnf quad): a linear-identity placement translates exactly, rounded to whole pixels; a scaled, rotated, or flipped one runs `map_unpacked_layer_tree`, the multi-target Free Transform rules (pixels and raster masks resample, text re-renders through its composed transform, vector data transforms exactly, nested placements map and re-render). Refused: linked sources (embed first), Smart Filters on the layer, warp or perspective placements, preserve-only locks, and contents holding Smart Filters when the layers would move. One undo step. The source element stays in the store like every orphan; the writer leaves unreferenced elements out of the file, which Photoshop requires ([smart-objects.md](smart-objects.md), Photoshop 2026 ground truth). Pinned by `ui_smart_object_convert_to_layers_restores_layers_in_place` and `ui_smart_object_convert_to_layers_follows_scaled_placement`.

Save As on an external child refreshes the parent's filename, format, absolute and
relative link paths, timestamps, and rendered preview. Embedded child links retain
their source UUID lineage so parent Undo/Redo reconnects an open child to the
restored source. Convert, Via Copy, and Place prepare changes in a scratch document
and add history only when the complete result can be installed.
