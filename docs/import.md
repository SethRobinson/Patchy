# Import menu: scanner, photocopy, divide photos, sprite sheets, image sequences, folders of images; seamless tiling

The File > Import features, the folder open/export pair, plus the seamless-tiling tooling (preview window, in-canvas tiling mode, seam shifting). File-format readers live in [file-formats.md](file-formats.md); the platform-specific scanner backends are also inventoried in [platform.md](platform.md).

## Scanner import

- Windows uses WIA (`scanner_import_win.cpp`); macOS uses ImageKit/ImageCaptureCore (`scanner_import_mac.mm`). macOS exposes scanners only (no cameras) and acquisition is single-image.
- The Windows scan dialog is the system UI (`IWiaDevMgr2::GetImageDlg`), so its DPI and file-type defaults come from the selected Windows scan profile, not from Patchy; GetImageDlg offers no way to preseed them. Users who want 600 DPI as the default edit the profile in Windows Fax and Scan (Tools, then Scan Settings).
- Qt's image allocation limit is disabled at startup (`main.cpp`): the 256 MB default rejected large-bed 600 DPI scans with a bare "Unable to read image data".
- `PATCHY_FAKE_SCANNER_FILE=<path>` bypasses native scanner acquisition for offscreen scanner-import tests.
- The macOS AppKit sheet MUST complete asynchronously after returning to the native run loop: a nested `QEventLoop` makes every sheet control ignore mouse input.

## Photocopy (scanner to printer)

File > Import > Photocopy runs the same native acquisition as scanner import, then prints the scan through `run_photocopy_dialog` (print_dialog.cpp; wasm stubs it) without ever creating a document session: the scan is a throwaway, like the machine it is named after. The contract is exact physical size, so there is deliberately NO scale control anywhere in the flow:

- Placement is always `PrintScaleMode::ActualSize` at the per-axis scan PPI. The DPI source is the device, not the file: the Windows backend reads WIA_IPS_XRES/YRES off the WIA item after the dialog (`read_scan_resolution`, scanner_import_win.cpp) into `ScannerAcquireResult::horizontal_dpi/vertical_dpi`, and `apply_scanned_document_ppi` (main_window_files.cpp, shared with scanner import) lets those override the file density, because real drivers write 72 or nothing into scanned JPEGs (a 300 DPI scan then "printed" at 4x size). Both sources are clamped to [10, 4800] else 300. macOS reports no device DPI yet (0 = unknown, file density is used).
- The scan anchors its top-right corner to the printable area's top-right corner, mirroring the platen's document registration corner, so the part the user aligned on the glass prints by default. Dragging the preview slides the scan to choose the printed part (clamped so half an inch always stays on the paper); switching printers re-anchors.
- The preview's crop rect (settings.selection_bounds, `PrintAreaMode::Selection`, default whole scan) prints only part of the scan, still at actual size (e.g. just a card on the platen). Its eight handles resize (quarter-inch minimum; the scan holds still on screen, the offsets follow the crop origin); dragging elsewhere moves everything; cropped-away areas dim dark, and the "Print" size row reports the crop's physical size live.
- Paper comes from the selected printer's own default page layout with margins clamped to the driver's minimum, floored at zero (`photocopy_page_layout`): borderless photo drivers (Epson SC-PX1V) report NEGATIVE minimums for overspray, which would put the printable rect and the anchor corner outside the paper. There is no page-setup step. Orientation auto-rotates like a copier: with anchored placement, the orientation losing the least scan area wins, portrait on ties.
- The preview freezes its fit-to-content view transform for the duration of a drag or resize (`frozen_view_` in `PhotocopyPreviewPane`) and refits on release: refitting per frame made the crop appear stationary while the page slid the opposite way, so drags felt reversed.
- Whatever falls outside the printable area is shaded red in the preview pane (`PhotocopyPreviewPane` fits page plus overflow into the widget, so cut-off parts hang visibly off the paper) with a warning label (containment-based, so dragging a small scan off the edge warns too); it prints clipped, never scaled down.
- The only options are the printer (remembered in the `photocopy/printerName` settings key) and the copy count, sent through the shared `paint_printer_page`. Size labels follow the ruler-unit preference (metric rulers read cm/mm, everything else inches).
- `ui_photocopy_dialog_previews_clipping_at_actual_size` drives the dialog through `PATCHY_FAKE_SCANNER_FILE` and pins the clip warning, auto-rotation, top-right anchoring, preview dragging, and the no-session rule.

## Divide Scanned Photos

Two entry points share one flow: File > Import > Scan and Divide Photos (Windows/macOS, same native acquisition as scanner import; the scan is a throwaway like the photocopy, never a session) and Image > Divide Scanned Photos (runs on the current document's flattened composite, the phone-photo-of-prints case; the source document is never modified and gets no undo entry). Detection and extraction are the Qt-free `src/core/photo_divide.{hpp,cpp}` (its header carries the constraint comment; the binding boundary is "Scanned-photo division" in [legal-constraints.md](legal-constraints.md)); the editable preview is `src/ui/divide_photos_dialog.{hpp,cpp}`; the MainWindow flow lives in main_window_files.cpp.

- Detection (3x3 median prefilter on the analysis copy, border-seeded 8-connected flood fill against a median/MAD border background model, radius-1 opening then close/open morphology, union-find components, convex hulls, min-area rects, optional per-side quad fit) runs on a downscaled analysis copy (max edge 1024) once at open and, debounced, on sensitivity changes. The median prefilter and the small opening absorb impulse noise and thin shadow rings next to photo edges, so high sensitivity stays usable on noisy scans; heavy contiguous shadows still need a lower sensitivity. The minimum photo edge is half an inch when the source PPI is known, else 1.5% of the longer edge, floored at 24 px. Photos need a gap of roughly 3 mm on the platen; closer photos merge into one region (fixable by hand in the dialog).
- Region editing: drag inside moves, the eight handles resize; in perspective mode corner handles move individual quad corners; Alt+corner drag rotates in straighten mode; dragging empty background (or Add Region) adds a region; Delete removes. Regions the user added or edited become user-owned: re-detection replaces auto regions (a deleted auto region comes back) but keeps user-owned ones and drops fresh detections overlapping them (bounding-box IoU above 0.5).
- Checkboxes: Straighten (min-area-rect rotation, default on) and Fix Perspective (edge-fit quad, homography rectify, aspect recovered with the Zhang closed form and trusted only within 1.5x of the measured quad side ratio, near-affine quads use the affine form and distrusted recoveries fall back to the measured ratio, then snapped to 1:1, 5:4, 4:3, 7:5, 3:2, or 16:9 within 3%; checking it forces and disables Straighten). Both off cuts plain axis-aligned bounding boxes. Detected angles under 0.3 degrees snap to 0 and extraction of axis-aligned integer quads is an exact byte copy.
- Up direction: four arrow buttons say which way the photos' top edge points in the scan (Up default, Right, Down, Left; one choice for the whole batch). Every extracted photo is rotated by the compensating quarter turn through `rotated_quarter_turns`, a lossless index permutation.
- Output radios (the save choices are hidden on wasm, the one-download-per-file rule): open each photo as an untitled modified document (tab "Photo N", reading order rows top to bottom then left to right); save numbered files to a folder; or save and open, where each opened session carries the saved file's path and starts unmodified, so closing never prompts. The folder (full path edit box plus a browse button), filename prefix (default `photo_`, sanitized like image-sequence names), format combo (flat-image export formats minus SVG and icon/cursor; PNG default), and an If-files-exist choice all live in the dialog and persist. Add (default) gives each file the next free index so a batch lands after whatever the folder already holds and never prompts; Overwrite numbers from 001 and, only when something actually collides, asks once naming the first colliding file before anything is written (No cancels the save). OK creates the folder if missing and keeps the dialog open on failure. Saves use per-format remembered defaults silently with the export scale pinned to 1x (never the shared `saveOptions/exportScale`), run under a progress dialog, and finish with a status-bar line plus, in save-only mode, a "Saved N photos" message box (in save-and-open mode the opened tabs are the confirmation). Photos inherit the source PPI; the scanner path applies device DPI via the shared `apply_scanned_document_ppi`.
- After a completed scanner-driven batch (any output mode), a "Scan another batch of photos?" Yes/No prompt (default Yes) loops straight back into acquisition, so a stack of photos never needs the menu between batches. It never appears after a cancel or failure, and the Image-menu entry point does not prompt.
- Settings keys (permanent): `dividePhotos/sensitivity`, `dividePhotos/straighten`, `dividePhotos/fixPerspective`, `dividePhotos/output` (0 open, 1 folder, 2 save and open), `dividePhotos/upDirection` (0 up, 1 right, 2 down, 3 left), `dividePhotos/folder`, `dividePhotos/prefix`, `dividePhotos/format` (extension token), `dividePhotos/existingFiles` (0 add, 1 overwrite).
- Pinned by the `photo_divide_*` core tests (detection geometry, determinism, rectification RMS, aspect recovery and its near-affine noise guard, high-sensitivity noise robustness, quarter-turn rotation) and the `ui_divide_*` / `ui_scan_and_divide_opens_document_per_photo` / `ui_unicode_divide_photos_folder_save` UI tests, all driven offscreen through `PATCHY_FAKE_SCANNER_FILE`.

## Image sequences

The sibling of the sprite-sheet pair: File > Import > Image Sequence to Layers imports one file per layer, and File > Export > Layers as Image Sequence writes one file per top-level layer (bottom to top, matching the sprite-sheet frame semantics; the options dialog's scope radios pick visible-only, the default, or all layers). Testable helpers live in `src/ui/image_sequence_dialog.{hpp,cpp}`; the file-dialog flows are `MainWindow::import_image_sequence`/`export_image_sequence` in `main_window_files.cpp`.

- Ordering is a natural sort (numeric-aware, case-insensitive: crap2.bmp before crap10.bmp) via `sorted_sequence_paths`. Selecting a single file whose base name ends in digits expands to the whole sibling run (`expand_numbered_sequence`: same prefix + digits + extension); the import confirmation dialog lists the ordered files so the expansion is visible before anything imports.
- Mixed sizes: canvas is the max width x max height and smaller frames top-left align (registration stays at the (0,0) origin). Layer names come from file base names; only the first (bottom) layer starts visible, like sprite-sheet slicing.
- Export naming: the save dialog picks the first file (trailing digits in the typed name set prefix/start/padding via `naming_from_save_base_name`), then the options dialog chooses Numbered vs Layer names (sanitized + case-insensitively deduped, `image_sequence_file_names`) with a live name preview. Files besides the one the save dialog confirmed get one overwrite prompt. Each frame renders through the shared `render_layer_isolated` (image_document_io, also used by the sprite-sheet composer) and routes through `write_flat_image_file` with the format's usual save options.

## Files as layers

Image files added to an open document as new layers, one root per file (GitHub issue 25). Three entry points share `MainWindow::add_files_as_layers` (main_window_files.cpp):

- **File > Import > Files as Layers...** (`fileImportFilesAsLayersAction`, `file.import_files_as_layers`, a document action, hidden on wasm): the `importFilesAsLayersFileDialog` multi-select picker, then `import_files_as_layers_with_paths` (the test entry).
- **A file drop on the Layers panel** ([layer-panel.md](layer-panel.md), "File drops onto the panel"): the drop position picks the insertion point the way a row drag does (above or below a row, onto a folder to add inside it). Drops on the window, canvas, or tabs still open tabs, as does a panel drop with no document open.
- **Edit > Paste** with files copied in a file manager (URLs, no bitmap): the null-image branch of `paste_clipboard` adds the supported files above the topmost selected row; a clipboard that also carries an image keeps the image paste, and unsupported files keep the "Clipboard does not contain an image" status.
- **Scripts:** `doc.importFilesAsLayers(paths)`, all or nothing: an unreadable file throws and adds nothing, and the run's single snapshot covers the mutation.

Rules: every path decodes first through `load_document_from_path` (the non-interactive decoder Open uses: PSD trees, SVG vectors, RAW defaults, PDF page 1, GIF frames, flat alpha promoted to a mask) plus the pending text and image post-open passes. A file whose document has one top-level layer becomes that layer named after the file's base name; two or more become a pass-through folder named after the file with the layers inside, so one file is always one root, one selected row, one undo unit. The roots go into a staged copy of the target through `copy_layers_between_documents` (the Document-level core of the cross-document layer copy) with keep-position placement: a file the target's size lands exactly (a same-size PSD keeps its layout), any other size is centered on the canvas, never scaled, and names take the copy suffix only on collision. The staged stack is repositioned to the drop target with `move_layers_for_drop`, then swapped in under one "Add files as layers" snapshot, so a refusal part-way leaves the live document untouched. Interactive entries skip unreadable files and report them in the status suffix and `filesAsLayersFailedMessageBox` (never under `unattended_automation()`), select every new root with the topmost active, and say "Added N layer(s)". These are pixel and vector layers, not smart objects; Place Embedded stays the smart-object path.

Tests: `ui_layer_panel_file_drop_*` and `ui_import_files_as_layers_action_registered_and_inserts_above_selection` (layer_panel_organization_tests_files_as_layers.cpp), `ui_paste_file_urls_adds_layers` (clipboard_free_transform_tests.cpp), `ui_script_import_files_as_layers` (scripting_tests.cpp), `ui_unicode_files_as_layers_reads_unicode_names` (unicode_path_tests.cpp).

## Folders of images

The document-level pair beside the image-sequence pair, and the half of the PDF round trip that goes through files: a multi-page PDF opens as one tab per page, File > Export > Documents to Folder writes those tabs as numbered page images, and File > Open Folder brings such a folder back as tabs that File > Export > Multi-Page PDF can bind again (docs/pdf.md). Both live in `main_window_files.cpp`; the export dialog is `src/ui/export_documents_folder_dialog.{hpp,cpp}`.

- **Open Folder** (`fileOpenFolderAction`, `file.open_folder`; also a directory dropped on the window or passed on the command line, via `open_command_line_files`): `supported_image_paths_in_folder` lists the folder's direct children that `is_supported_open_path` accepts, minus `.pdf` (each would raise the Import PDF page picker), in natural name order through `sorted_sequence_paths` (page-2 before page-10); subfolders are never entered. `open_folder_path` opens the first image through `open_document_path` (activation, fit, recent file, import notes, exactly like a single open) and the rest as `SessionActivation::Background` sessions with their file paths kept, under `openFolderProgressDialog` ("Opening image N of M", cancellable, an event pump per file so tabs appear one by one), the same shape as the PDF page loop. One unreadable file never stops the rest: failures collect into a status suffix and one `openFolderFailedMessageBox` (interactive runs only). The folder goes into Open Recent Folder once (`add_recent_folder`); the images do not each enter Open Recent File. An empty folder is a `show_status_error` ("No supported images in ..."), and a dropped directory is accepted at drag time by `isDir()` alone (its listing is read only on the drop). Hidden on wasm.
- **Export Documents to Folder** (`fileExportDocumentsToFolderAction`, `file.export_documents_to_folder`, a document action, hidden on wasm like the image-sequence export): `exportDocumentsFolderDialog` lists every open document in the shared document-order control (below; all selected to start), plus Folder (edit + browse), Prefix (sanitized like image-sequence names, default `page_`), Start at, Digits (padding 1-6), Format (`export_documents_format_choices`: the divide-photos rows, flat export formats minus SVG and icon/cursor, plus Photoshop Document and Aseprite; PNG default), and If files exist: Add (default) or Overwrite, with a live name preview and count. Export creates the folder (`mkpath`) and stays open on failure. `export_document_sessions_to_folder` writes each selected session: `.psd` and `.aseprite` go through the layered writers Save As uses (`psd::DocumentIo::write_layered_rgb8_file`, `aseprite::DocumentIo::write_file`, no Fill Opacity prompt since the batch is unattended), every other format writes the flattened composite through `write_flat_image_file` with per-format remembered defaults and the export scale pinned to 1x; `.pdf` with any layered page (`flat_save_discards_layers`) first runs `resolve_pdf_layer_choice` once for the batch (the `saveOptions/pdfLayerPolicy` preference, else the `pdfLayersMessageBox` question; Cancel aborts before anything is written) and rides the answer on `pdf_editable_layers`; names from `image_sequence_file_names` (prefix + zero-padded number + extension): Add takes the next free number per file and never prompts; Overwrite numbers from the start value and, only when something collides, asks once naming the first colliding file (`exportDocumentsOverwriteMessageBox`; No cancels). It runs on the UI thread under a cancellable `exportDocumentsProgressDialog` ("Writing image N of M"); cancelling keeps the files already written. Sessions are untouched (no path, no saved state, no activation change). Settings keys (permanent): `exportDocumentsFolder/folder`, `/prefix`, `/start`, `/padding`, `/format` (extension token), `/existingFiles` (0 add, 1 overwrite).
- **Document-order control** (`src/ui/document_order_list.{hpp,cpp}`, `build_document_order_controls`): the orderable, multi-selectable list shared by this dialog (`exportDocuments*` object names) and Export Multi-Page PDF (`multiPagePdf*`). Documents are picked by selection, like the Import PDF page list (`ExtendedSelection`: click, Shift-click, Ctrl-click), never by check boxes (the application sheet zeroes `QListWidget::indicator` for the Layers panel, and the standard gestures are what people expect); every row starts selected and Select All brings them all back (September 2026). Move Up / Move Down shift every selected row by one, a run already against the edge staying put (`move_selected_list_items`; the current item is restored with `QItemSelectionModel::NoUpdate` because the plain `setCurrentItem` would collapse the selection to one row); Auto Sort is a stable natural sort of the titles (`natural_name_collator`: numeric-aware, case-insensitive, the collator `sorted_sequence_paths` uses too), so "Page 2" lands before "Page 10"; Reverse flips the whole list. Rows move as whole items, so selection and session ids travel with them and the current item stays on the same document.
- Tests: `ui_open_folder_*`, `ui_folder_actions_and_commands_registered`, `ui_export_documents_*`, `ui_document_order_auto_sort_and_reverse` (folder_open_export_tests.cpp), plus `ui_unicode_open_folder_reads_unicode_names` and `ui_unicode_export_documents_to_folder`.

## Animated GIFs

Opening a .gif with 2+ frames automatically imports every frame as a layer in a new session (the gif branch inside `load_via_qt`, main_window_files.cpp; qgif returns fully composited full-canvas frames). Frame 1 becomes the TOP layer and every layer starts visible, deliberately opposite of the sequence/sprite-sheet bottom-first single-visible convention, so a straight Save As GIF animation round-trips. Layer names are "Frame N" plus the frame's delay as a trailing seconds token ("Frame 3 0.4s"); the animated GIF save parses that token back, so a rename that keeps the token keeps the timing. `document_from_frames` grows `FramesToLayersOptions{first_frame_on_top, all_layers_visible}` for this; the image-sequence and PDF callers keep the defaults. Single-frame GIFs, animated WebP, and the pattern-library import keep first-frame-only behavior. Export details live in [file-formats.md](file-formats.md).

## PDF pages

Opening a `.pdf` raises the Import PDF page picker (`pdfImportDialog`, `src/ui/pdf_import.{hpp,cpp}`) before anything renders, the way camera raw raises the develop dialog: the interception sits in `load_document_interactive`. Selected pages become layers through the same `document_from_frames` helper the image-sequence import uses, so the canvas, top-left registration, and first-layer-only visibility rules are shared. Layers are named "Page N" after the real page number, and the chosen resolution becomes the document's PPI. The dialog defaults to editable import (shapes, text layers, smart-object images, one page per document) with "Flattened image per page" as the raster fallback; the reader architecture, approximation rules, and export details live in [file-formats.md](file-formats.md).

## Seamless tiling: preview window, in-canvas mode, seam shifting

Three cooperating features for tile art (July 2026 expansion):

- **Seamless Tile Preview** (View menu): a Qt::Tool window polling a CONST-only revision probe (mutable Layer accessors bump revisions; see [performance.md](performance.md)) and closing via a `done(int)` override (see [ui-conventions.md](ui-conventions.md); `ui_tile_preview_window_tracks_document_edits` pins it). The tick has three content bands: probe changes re-render immediately at or below 1 Mpx, after the probe holds still for one tick up to 16 Mpx (so brush drags are not recomposited per tick), and via the manual Refresh button beyond that. A document IDENTITY change (tab switch/open/close; separate pointer+dims probe) re-renders immediately at any size — `tick()` must never early-return before probing, that was the bug that froze the window on >1 Mpx documents (`ui_tile_preview_follows_document_switches_and_large_edits` pins it).
- **Seamless Tiling in Window** (View menu, per-document check synced in `activate_document_tab`): CanvasWidget paints wrap copies of the committed composite around the document — `draw_tiling_preview` in canvas_widget_render.cpp draws from `render_cache_`/display mips (session previews and all overlays stay on the center tile), with a textured-fill fallback above ~24 visible ghost tiles from a pixmap cache cleared in `invalidate_display_mip_cache()`. Partial updates in `document_changed_impl` replicate dirty rects across visible wrap offsets (or widen to a full update on the textured path); `ui_canvas_tiling_mode_paints_ghost_tiles_live` pins ghost pixels, live stroke replication (via PaintRegionRecorder), and the per-tab check sync. The action handler is on `triggered`, not `toggled`, so the tab-switch setChecked sync cannot re-apply it.
- **Shift Seams to Center** (Image menu + a button in the preview window): `wrap_offset_document` (core/document_geometry.cpp) wrap-rolls raster layers (normalized to the canvas rect first), layer masks (expanded over default_color), and document channels; object-like layers (text, shape layers, placed records) translate whole without wrapping and shape layers re-raster via the `transform_document_vector_data` translate pass. The applied offset is recorded in document metadata (`kTileSeamOffsetMetadataKey` in tile_preview_window.hpp, "dx,dy") so the second press applies the exact inverse even for odd dimensions and undo/redo (whole-Document snapshots) can never desync the parity. The MainWindow toggle follows the rotate-canvas template including the smart-object guard. Rolling only permutes pixels, so palette-mode docs need no snap.
