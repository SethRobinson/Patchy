# Layers panel row controls

Split from [layer-panel.md](layer-panel.md): the folder disclosure arrow, row and thumbnail double-clicks with inline rename, the visibility eye and its sweep, and the Layer Styles and Smart Filters rows listed under a layer.

## Disclosure arrow, double-click, visibility eye

The folder disclosure arrow (`layerFolderDisclosureButton`) toggles one folder, Alt-click also its nested folders, and Ctrl+Alt-click sets every folder to the clicked folder's new state (`MainWindow::toggle_all_layer_folders_expanded`). Empty folders toggle too (#229), empty artboards included (`ui_artboard_empty_artboard_disclosure_toggles_and_saves`). A `ClickModifierRecorder` filter (`click_modifier_recorder.hpp`) records the modifiers (`clicked` carries none); the handler defers (`QTimer::singleShot(0)`): the toggle rebuilds the rows. Runtime expand state is the session's `collapsed_layer_groups`: metadata seeds it at open; saves, recovery and smart-object commits write it back (`DocumentSession::document_for_write`). A toggle is not an edit.

Double-clicking a row opens its editor (layer styles, or an adjustment's or fill layer's settings; the vector badge, on shapes, opens Shape Appearance, a fill layer's fill badge its settings, #607), except on the name label and the thumbnails: a layer mask or vector mask thumbnail targets that mask and opens Mask Properties, Density and Feather (`set_mask_thumbnail_double_click_callback`, deferred past the event; [vector-tools.md](vector-tools.md#vector-mask-ui)). Every row button (eye, mask links, the fx, smart-object, vector, fill and clipping badges, the Smart Filter and effect-row buttons) must be listed in `layer_row_button_owns_clicks` in `layer_list_widget.cpp`, or the list eats the press as a row drag start and routes the double-click to the row's editor (`ui_layer_vector_badge_double_click_opens_shape_appearance`). The name's text edits in place (space right of a short name opens the editor): `LayerListWidget::begin_inline_rename` swaps `layerRowName` for a `QLineEdit` (`layerRowNameEdit`) in the label's slot at its height and font. Return and focus loss commit, keyed by layer id so a click on another row still renames the edited one; Escape cancels before the list's Escape-to-deselect; the commit runs deferred through `MainWindow::apply_layer_rename` (one undo step; empty or unchanged names record nothing). `refresh_layer_list` cancels an open editor before clearing rows; a queued commit is dropped when the list's session stamp changed (ids restart per document). Rename Layer (menu, context menu, F2) enters the same editor when the active layer's row exists and is the only selected one, else the rename dialog (`ui_layer_row_name_double_click_renames_inline`, `ui_layer_rename_hotkey_enters_inline_edit`, `ui_layer_inline_rename_*`; dialog-opening tests double-click `layerRowDetails`). The content thumbnail routes to `MainWindow::zoom_canvas_to_layer_content`, which fits the view to the layer's alpha-trimmed bounds (`move_layer_outline_bounds`, else `layer_render_bounds`, a folder's descendant union) via `CanvasWidget::zoom_to_document_rect`. Text thumbnails enter inline editing with all text selected, keeping zoom and pan (deferred, session checked); adjustment and fill layer thumbnails open their settings (`ui_layer_thumbnail_double_click_zooms_canvas_to_layer`, `ui_fill_layer_row_*`).

The visibility eye (`layerVisibilityCheck`) does not toggle through its QToolButton on real mouse input: `LayerListWidget::eventFilter` eats the press first. A plain press toggles on press and starts a visibility sweep (dragging along the eye column paints the first toggle's state across crossed rows, skipping disabled eyes; `setSelection` is suppressed while sweeping so the drag cannot rubber-band the selection). The sweep grabs the mouse on the persistent viewport (toggling a folder rebuilds every row and destroys the pressed eye, losing Qt's implicit grab). A pointer at or past the top or bottom edge sweeps to that edge (no column test) and autoscrolls; each step moves the last swept point with the rows and sweeps again (#407, `ui_layer_eye_sweep_autoscrolls_past_the_list_edge`). Release, even outside the list, ends the grab and the scrolling; losing capture, hiding, disabling or deactivating the viewport cancels the sweep. `ui_layer_eye_sweep_survives_folder_row_rebuild` must route input through Qt's window system (direct viewport moves miss the lost-capture bug). An Alt press calls `MainWindow::isolate_layer_visibility` (named in the eye's tooltip, #549): every other layer hides, the second Alt-click restores the per-session snapshot, and any other visibility change drops it. Both handlers defer (`QTimer::singleShot(0)`; folder toggles rebuild rows); the button's `toggled` serves programmatic `click()`. Visibility is not undoable. The G'MIC preview sets `set_visibility_only` (eyes and scrolling; [gmic.md](gmic.md)). Plain eye changes queue a coalesced immutable-snapshot render and keep the previous canvas frame visible, so rendering cannot interrupt the sweep. Inherited folder-control states rebuild through the normal row path. See [interactive-previews.md](interactive-previews.md#visibility-render-waits).

The eye's two states differ by shape, then by color (#715): `eye` is an open almond with a solid pupil and clear space round it, `eyeOff` a closed lid with lashes in a thinner line (`paint_simple_icon_glyph`, action_icons.cpp), tinted `layer_eye_on` and `layer_eye_off`. The row button keeps its box (24 px: the QSS gives it 22 px inside a 1 px border, so hit zone and row height are unchanged) and draws the glyph at 20 px; the nested Smart Filter and effect eyes draw it at 16 px in their 22 px button, the Channels panel at 18 px. At each of those sizes a clear pixel separates lid and pupil at 100%. Every palette keeps the visible eye at 6:1 or more on `layer_row_bg`, at least three times the hidden eye's contrast, and the hidden eye visible on a plain and a selected row: Light's pair is hand-picked in `light_palette()`, a bundled theme's through the generator's `ROLE_OVERRIDES` ([bundled-themes.md](bundled-themes.md)). Tests: `ui_layer_eye_hidden_reads_weaker_in_every_theme`, `ui_layer_eye_icons_read_as_open_and_closed`, `ui_layer_eye_fills_its_button`; `ui_layer_eye_issue_715_shots` saves the rows, the Layer Styles rows and the Channels list at 100% and 200%.

## Effect rows

A layer with any effect instance, hidden ones included, lists them under its row like Smart Filters (#256): a "Layer Styles" header (`layerEffectsRow`) with a disclosure arrow (`layerEffectsDisclosureButton`) and the master eye (`layerEffectsVisibilityButton`, `LayerStyle::effects_visible`), then, while open, one `layerEffectEntryRow` per instance in the dialog's category order (`layer_effect_rows`, main_window_shared.cpp) with its eye (the instance's `enabled`), name and Edit pencil (`layerEffectEditButton`); a row double-click does the same without turning it on (`edit_layer_effect`). The Smart Filters header leads with its own arrow (`layerSmartFiltersDisclosureButton`, #361). Effects start closed (`DocumentSession::expanded_layer_effects`; an effect added by the dialog or Paste Layer Style opens them, `reveal_layer_effects`), Smart Filters open (`collapsed_smart_filters`; an added filter opens them in `commit_smart_filter_stack_edit`). A toggle is no edit. Both save the folder way: `collect_initial_layer_fx_disclosure` seeds them from `patchy.layer_fx_expanded`, `document_for_write` writes them back; PSD has one bit per layer for both lists ([ps-compat.md](ps-compat.md)), so a layer reopens with both open when either was. Master eye off: effect eyes keep their state, draw dimmed (`layerEffectEyeDimmed`) and still toggle. Right-click: `layerEffectContextMenu` (Edit, Hide/Show, Delete via `delete_layer_effect`; routed by `show_layer_context_menu`). Each change is one undo step through `apply_layer_effect_row_edit`, which drops the preserved lfx2 bytes; a locked layer shows the rows read-only. Effect and Smart Filter rows are indented by the arrow's drawn width and the row spacing (`kNestedEyeIndent`), so every nested eye shares the headers' eye column and every nested name starts under "Layer Styles" (#349; `ui_layer_effect_rows_align_under_the_layer_styles_eye`). Hidden instances keep the fx badge and survive a PSD save (the `present` rule in [layer-effects-render.md](layer-effects-render.md)). Tests: tests/ui/layer_effect_rows_tests.cpp, `psd_layer_style_hidden_effects_round_trip`, `psd_layer_fx_expanded_flag_round_trips`.
